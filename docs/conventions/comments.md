# 주석 규약

주석은 **코드를 읽어도 알 수 없는 것**만 적습니다. 나머지는 코드가 말하게 두고 지웁니다.

이 문서의 예시는 전부 이 저장소의 실제 코드에서 뽑았고, 어느 파일에서 왔는지 함께 적습니다.
「이렇게 씁니다」로 표시한 블록은 규약을 적용한 **뒤**의 형태라, 지금 그 파일을 열면 아직
고치기 전 모습일 수 있습니다.

## 조문 ① 남기는 주석 — 왜·함정·제약

셋만 남깁니다.

1. **왜 이렇게 했는가** — 다른 선택지를 버린 이유입니다.
2. **함정** — 이렇게 안 하면 무엇이 조용히 깨지는지입니다. 특히 **테스트가 못 잡는 것**입니다.
3. **제약** — 플랫폼·런타임·도구가 강제해서 바꿀 수 없는 것입니다.

기기에서 직접 확인한 사실은 날짜와 함께 적습니다. 그 자체가 남길 이유가 됩니다.

`packages/ui-lynx/src/text-field/TextField.tsx`의 주석을 옮긴 형태입니다.

```ts
// Counter가 없으면 maxlength를 아예 넘기지 않습니다. undefined로 넘기면 iOS native
// input이 포커스 뒤 다시 그릴 때 그것을 0으로 받아 아무것도 입력되지 않습니다
// (2026-09-21 시뮬레이터 실측). 테스트 환경은 undefined 속성을 지워 버려 이 차이를
// 재현하지 못합니다 — 이 주석이 없으면 초록을 근거로 되돌리게 됩니다.
```

## 조문 ② 지우는 주석 — 코드가 말하는 '무엇'

다섯을 지웁니다.

1. **코드를 다시 읽은 주석** — 바로 아래 한 줄이 이미 말하는 것입니다.
2. **작업 이력** — 이슈 번호(`LIB-###`), 작업 단계 이름(`logic` · `ui-implementation` ·
   `logic-scaffold` 등), 회차 표기(`r0.1`)입니다.
3. **저장소 밖 경로** — `.agent-harness/…` · `scratchpad/…`처럼 저장소를 받은 사람이 열 수
   없는 파일을 가리키는 주석입니다.
4. **번호만 남은 인용** — 조문 ④가 다룹니다.
5. **주석 처리된 코드** — 되살릴 근거는 git에 있습니다.

`apps/mobile/src/app/App.tsx`에 지금 있는 주석입니다.

```tsx
// 지웁니다 — prop 이름이 이미 같은 말을 합니다.
// LIB-257 (integration): 여정 맵 머리 알림 버튼 결선(계약 §2.9 5번).
onOpenNotifications={wiring.onOpenNotifications}
```

## 조문 ③ 문체 — 한국어 설명체(`~합니다`)

모든 주석 문장을 설명체로 씁니다. `~한다` · `~이다` · `~없다` · `~않는다` · `~아니다`로
끝내지 않습니다. 강조는 **굵게**로 하고 어미로 하지 않습니다.

한 주석 안에서 어미를 섞지 않습니다. 목록 항목도 문장이면 설명체로 끝냅니다. 명사로 끝나는
항목(`— 갈리는 자리`)은 문장이 아니므로 그대로 둡니다.

```ts
// 이렇게 씁니다.
// `entry`가 비어 있지 않으면 진입 구간입니다. 같은 사실을 `phase` 필드로 한 번 더
// 들면 둘이 어긋날 수 있어 필드를 두지 않습니다.
```

화면에 나가는 한국어 문구(UI 문자열)는 이 규칙 밖입니다. **이 규약이 거는 대상은 코드
주석입니다** — `docs/` 아래 문서의 문체는 각 문서를 따릅니다. 그래서 이 문서를 가리키는
[code.md](code.md)의 절은 그 문서의 평서체로 쓰여 있습니다.

위 예시는 `apps/mobile/src/app/navigation.ts`의 주석을 옮긴 형태입니다.

## 조문 ④ ADR·계약 인용 기준

번호는 **이유를 실제로 설명할 때만**, 그리고 **이유 문장 뒤에만** 붙입니다.

1. 주석은 먼저 이유를 한국어 문장으로 적습니다. 번호는 그 문장 뒤 괄호에 둡니다.
2. **번호를 지워도 문장이 성립해야 합니다.** 성립하지 않으면 그 주석은 이유가 아니라 번호를
   적은 것입니다.
3. **인용하는 번호는 `ADR-####`뿐입니다.** `계약 §…` · `LIB-###` · `r0.N` ·
   `.agent-harness/…` · `scratchpad/…`는 인용하지 않습니다. 저장소를 받은 사람이 열 수 없는
   문서를 가리키기 때문이고, [workflow.md](workflow.md)가 문서에 대해 이미 같은 선을 그어
   두었습니다.
4. `docs/` 안의 문서는 상대 경로로 인용해도 됩니다. 저장소에 실제로 있는 파일이면 됩니다.

```tsx
// 남습니다 — 번호를 가려도 두 문장이 그대로 섭니다.
// 루트 구성이 여기 모입니다 — 화면 전환·에러 경계·프로바이더. 폴더마다 책임을 하나만
// 주기로 한 결정에서 왔습니다(ADR-0003 D5).
```

```tsx
// 지웁니다 — 번호를 가리면 남는 사실이 없습니다.
// LIB-261 (ui-implementation): 계약(.agent-harness/work/lib-261/spec.md §2.4 ·
// §4.2~§4.5)과 design.md §4의 값을 채운다.
```

## 조문 ⑤ 파일 머리 주석의 형태

파일 머리 주석은 **최대 다섯 줄**이고 세 가지만 적습니다.

1. **이 파일이 무엇을 소유하는가** — 한 줄입니다. 반드시 적습니다.
2. **왜 경계가 여기인가** — 다른 자리에 둘 수 있었는데 안 둔 이유가 있을 때만 적습니다.
3. **소비자가 지켜야 할 제약** — 이 파일을 import하는 쪽이 어길 수 있는 것만 적습니다.

작업 이력·계약 절 번호·단계 이름은 넣지 않습니다. 파일 이름과 export 목록으로 소유 대상이
이미 분명하면 파일 머리 주석을 쓰지 않아도 됩니다.

`apps/mobile/src/lib/entry-flow.ts`의 파일 머리 주석을 6줄에서 3줄로 줄인 형태입니다.

```ts
// 진입 흐름 화면 여섯이 공유하는 어휘를 여기 모읍니다. 화면 폴더 사이 값 import를
// 만들지 않으려고 `lib/`으로 올렸습니다(`docs/conventions/code.md` 「import」의 승격 규칙).
// 이 모듈은 `screens/`를 import하지 않습니다.
```

## 조문 ⑥ 주석의 형태 — 공개는 JSDoc, 내부는 `//`

**읽는 사람이 이 파일을 여는지**로 가릅니다.

- **`/** */`(JSDoc)** — 다른 파일에서 쓰는 것을 설명할 때 씁니다. export하는 함수·타입·prop이
  여기 해당합니다. 에디터가 호출하는 쪽에서 툴팁으로 띄워 주므로, 그 파일을 열지 않아도
  읽힙니다.
- **`//`** — 그 파일 안에서만 의미 있는 것에 씁니다. 함수 본문의 함정, 왜 이 순서인지, 왜
  이 값인지가 여기 해당합니다.

형태가 달라도 조문 ①~⑤는 똑같이 적용합니다. JSDoc이라고 해서 「무엇을 한다」를 다시 적지
않습니다.

```ts
/** `phone`으로 진행할 때만 번호를 실어, 코드 검증 화면이 그 번호를 보여 줍니다. */
export function entryScreenAfterLogin(method: EntryLoginMethod, phoneNumber?: string): Screen {
  switch (method) {
    case "phone": {
      // `default`를 두지 않습니다. 로그인 수단이 늘면 이 switch가 TS2366으로 서서, 새 수단이
      // 코드 검증을 거치는지 정하지 않고 지나가는 일을 막습니다.
```

`@param` · `@returns` 태그는 이름과 타입이 이미 말하는 것을 반복하게 되므로 쓰지 않습니다.
설명이 필요하면 문장으로 적습니다.

## 조문 ⑦ 테스트 주석 — 케이스 id와 의도

테스트 주석은 **이 테스트가 빨개지면 무엇이 깨진 것인가**를 남깁니다. 제품 코드가 「왜 이렇게
했는가」를 남기는 자리와 짝입니다.

1. **케이스 id는 남깁니다.** 테스트 계획과 잇는 끈이 그것뿐입니다.
2. **id 뒤에 의도를 한 줄 붙입니다.** id만 있는 주석은 이 자리를 비워 둔 것입니다.
3. **테스트 이름이 이미 말하는 것을 다시 적지 않습니다.**
4. **지우는 것은 제품 코드와 같습니다** — 이슈 번호, 작업 단계 이름, 계약 절 번호.
5. **공허하게 통과할 수 있는 단언에는 그 사실을 적습니다.** 대상이 비어도 초록이 되는 테스트가
   여기 해당합니다.

```ts
// NV5 — 기대 화면을 리터럴로 적습니다. 구현이 쓰는 `tabRootActions`를 테스트도 불러
// 기대값을 만들면, 그 함수가 틀렸을 때 둘이 같이 틀려 통과합니다.
```

기존 테스트 145개의 정리는 제품 코드 정리가 끝난 뒤 따로 엽니다. **새로 쓰는 테스트부터**
이 조문을 지킵니다.

## 스스로 확인하기

리뷰 전에 자기 diff에 대해 아래를 돌립니다. `$AREA`는 바꾼 폴더입니다.

```sh
find $AREA -type f \( -name '*.ts' -o -name '*.tsx' -o -name '*.css' \) \
  ! -name '*.test.ts' ! -name '*.test.tsx' -print0 > /tmp/files.z

# 조문 ②·④ — 이력·저장소 밖 경로·절 번호 인용
xargs -0 grep -nE 'LIB-[0-9]{3}' < /tmp/files.z
xargs -0 grep -nE '\.agent-harness|scratchpad/' < /tmp/files.z
xargs -0 grep -nE '계약 *§|§ ?[0-9]' < /tmp/files.z

# 조문 ③ — 설명체가 아닌 종결
xargs -0 perl -Mutf8 -CSD -ne 'print "$ARGV:$.: $_" if /(?<!니)다(?=[.,)]|\s*[(—]|\s*$)/' < /tmp/files.z
xargs -0 perl -Mutf8 -CSD -ne 'print "$ARGV:$.: $_" if /아니다/' < /tmp/files.z
```

문장이 `다 —`나 `다(…)`로 이어지는 평서체까지 잡으려고 뒤에 오는 글자를 함께 봅니다. 공백만
뒤따르는 경우는 넣지 않습니다 — 「상태마다 」처럼 문장 끝이 아닌 자리가 걸리기 때문입니다.

전부 0줄이면 통과입니다. 남은 줄이 주석이 아니라 화면에 나가는 문구면 그대로 둡니다.

⚠ **문체 검사에 `grep`을 쓰지 마십시오.** macOS 기본 `grep`은 부정 문자 클래스와 `-o`에서
한글을 바이트 단위로 다뤄 **없는 건수를 만들어 냅니다**(실측: 8줄짜리가 36건으로 나왔습니다).
`perl`을 쓰되 `-Mutf8`을 빠뜨리면 반대로 **0건이 나와** 통과한 것처럼 보입니다.

파일 목록도 변수에 담아 넘기지 마십시오. zsh는 따옴표 없는 변수를 낱말로 나누지 않아 경로
전부가 인자 하나로 묶이고, `File name too long`과 함께 **0건에 exit 0**이 납니다. 위처럼
`-print0`과 `xargs -0`으로 넘깁니다.

## 파일 길이

제품 `.ts`·`.tsx` 파일은 **300줄을 넘지 않습니다.** 넘으면 책임이 둘 이상 섞인 신호로 보고
쪼갭니다. `.css`는 이 규칙 밖입니다.

지금은 7개 파일이 이 줄 수를 넘습니다. 기존 파일을 줄이는 작업이 따로 진행 중이고, **새로
만드는 파일부터** 이 상한을 지킵니다.

```sh
find apps/mobile/src packages/ui-lynx/src -type f \( -name '*.ts' -o -name '*.tsx' \) \
  ! -name '*.test.ts' ! -name '*.test.tsx' -exec wc -l {} + | awk '$1 > 300 && $2 != "total"'
```

## 강제 수단

패턴으로 잡히는 것은 `oxlint`가 막고, 나머지는 PR diff를 읽을 때 봅니다.

| 조문 | 무엇이 잡나 |
|---|---|
| ②-2 이슈 번호, ②-3 저장소 밖 경로, ④ `계약 §…` 인용 | `no-warning-comments` 규칙 |
| 파일 길이 300줄 | `max-lines` 규칙(테스트 파일은 제외) |
| ③ 문체 | 위 `perl` 검사와 리뷰 |
| ①·⑤·⑥·⑦ 내용 | 리뷰 |

문체는 규칙으로 막지 않습니다. 한국어 어미를 판정하려면 커스텀 규칙이 필요하고, 화면에
나가는 문자열과 주석을 가려야 합니다.

두 규칙은 지금 `warn`입니다. 기존 코드에 위반이 많이 남아 있어 `error`로 두면 CI가 바로
막히기 때문입니다. 영역별 정리가 끝나면 `error`로 올립니다.
