# 번들 천장을 바꾸는 절차 (첫 실행 시간 기준)

[ADR-0149](../adr/0149-bundle-size-ceiling-and-report.md). `pnpm size:check`가 천장 초과로 실패했을 때 따른다.

## 1. 먼저 줄인다
- **원인 찾기:** PR의 「번들 크기」 댓글에서 무엇이 얼마나 늘었는지 보고, `rspeedy-bundle-size` 스킬의 순서대로 원인을 찾는다. 확인할 것:
  - 메인 스레드로 샌 백그라운드 전용 코드
  - 중복 패키지
  - 번들에 들어간 그림·데이터
  - 문구표와 번역표
- **고칠 수단:** 지연 로드(lazy), 버킷으로 옮기기(그림·콘텐츠), `background-only` 경계

## 2. 줄일 수 없으면 근거를 모은다
- **실사용자 데이터:** Sentry 앱 시작 측정이 켜지면, 기기 등급(`device.class` low / medium / high)별로 첫 실행 시간 p50과 p90을 버전마다 본다.
- **비교:** 천장을 넘는 빌드와 지금 빌드의 차이를 같은 등급끼리 비교한다.
- **그 전에는 저사양 실기 한 대로 잰다.** 같은 기기에서 같은 조건으로 각 3회 이상, 새로 설치한 첫 실행에서 첫 화면이 그려질 때까지의 시간을 잰다.

## 3. 사용자 결정
- **올릴 때 낼 것:** 늘어난 크기, 첫 실행 시간 차이, 줄이지 못한 이유
- **결정 뒤 기록:**
  - 정해지면 `budget.json`의 `maxBytes`와 `note`를 고친다.
  - ADR-0149 적용 기록에 한 줄을 남긴다.
