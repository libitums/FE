## 시나리오

민서 전화 3턴, 다시 듣기, 완료 후 응답, 화면 이탈 및 새 음원 번들 반영을 확인합니다. 주문·카페·최종 복습의 표현 일치와 두 조각 조합은 자동 테스트로 확인합니다.

## 분석 결과

- 사용자가 제공한 Mina / v4 MP3의 첫 파일을 1.13초에서 분리합니다. 10ms RMS가 -42 dBFS 아래인 문장 사이 구간은 1.05–1.22초입니다. 두 문장의 원본 PCM을 빠짐없이 분할하고, mono 44.1 kHz AAC / 요청 비트레이트 96 kbps로 변환합니다.
- 전화 세 파일은 1.130 / 1.717 / 1.489초입니다. 세 파일 합계 60,272 bytes로 이전 28,945 bytes보다 31,327 bytes 증가합니다. JS/이미지 자산이 아닌 네이티브 앱 번들입니다.
- 세 audioSource를 유지하므로 튜토리얼 듣기의 인사도 동일한 ElevenLabs 음원으로 바뀝니다. 네이티브 코드·권한·외부 API 호출 변경은 없습니다.
- ‘물 좀 주세요’를 ‘물’과 ‘좀 주세요’ 두 조각으로 만들어 초급 조합 부담을 유지합니다.

## 제한 사항

사용자가 네 원본의 대사를 확인했습니다. 모델은 음원의 발음·연기를 직접 청취해 판정하지 않았습니다. 문장 분리는 신호의 무음 분석에 근거하며 최종 청취는 사용자가 할 수 있습니다. 성능 수치·Android·VoiceOver 낭독은 미측정입니다.

## 결론과 후속

- `pnpm verify` 전체 통과: 포맷·타입·린트·단위/UI/통합·정책·프로덕션 빌드·크기 검사.
- 메인 번들 1347.9 / 1353.0 kB, 이미지 8588.3 / 11520.0 kB, UI 패키지 465.3 / 481.0 kB로 예산 안입니다.
- iOS Debug Host 빌드 성공. 설치한 Host.app의 세 음원 SHA-256은 저장소 파일과 각각 일치합니다.
- AAC 세 파일의 PCM 재디코딩 성공. 클리핑 샘플 0개, peak는 인사 -3.32 / 소개 -7.81 / 작별 -3.61 dBFS입니다. 원본 발화의 상대적인 강약은 유지했습니다.

- iPhone 17 Pro에서 세 전화 턴 모두 Speaking → Your turn to reply 전환, 첫 인사 다시 듣기, 마지막 응답 후 Call ended, Start over를 직접 확인했습니다. 전화에서 카페로 이탈한 뒤 ‘물 좀 주세요 / mul jom juseyo’ 표시를 스크린샷으로 확인했습니다.
- 공유 듣기 audioSource와 주문 두 조각 조합, 최종 복습 정답은 기존 실제 데이터 통합 테스트가 통과했습니다. 재생 중 이탈의 네이티브 중단 호출은 기존 자동 테스트 범위이며, 소리가 실제로 멎는지 청취 판정은 하지 않았습니다.
