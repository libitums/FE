# 분석 이벤트의 environment 속성 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 렌더링 · 메모리 캡처(`performance:capture`)를 돌리지 않았습니다. 번들
  크기만 재었습니다.
- 기능 PR: 모든 분석 이벤트에 `environment` 속성을 붙이는 변경(이 보고서와 같은 PR)
- 대상 commit: PostHog 전송 브랜치(`454f048`, main `242b7cb`를 합친 뒤) 위의 작업 트리
- 기기: 실행하지 않았습니다. 시뮬레이터 · 실기에서 앱을 띄우지 않았습니다.
- OS: iOS 26.5
- Lynx SDK: 4.0.1
- 빌드: 번들 크기는 `pnpm build`의 `main.lynx.bundle`입니다. Release Host는 빌드하지 않았습니다.

## 시나리오

- 번들 크기: 기준 commit(`454f048`)과 이 작업 트리를 같은 자리 · 같은 환경 변수로 각각 `pnpm build`해
  `apps/mobile/dist/main.lynx.bundle` 크기를 비교했습니다.

## 이 변경이 무엇을 건드렸나

- 설정 판정(`lib/analytics-config.ts`)이 `PUBLIC_ANALYTICS_ENVIRONMENT`를 읽어 `production` ·
  `development` 중 하나로 정합니다.
- 분석 클라이언트가 만들어질 때 그 값을 SDK 공통 속성으로 **한 번** 등록합니다. 이벤트마다 더
  하는 일은 없습니다 — SDK가 이미 하던 공통 속성 병합에 키가 하나 늡니다.
- 화면 · 이벤트 매핑 · 전송 횟수는 바꾸지 않았습니다.

## 해석

- **미측정 기록입니다.** 화면 전환 · 전송 비용은 판정할 수 없습니다.
- 요청 본문은 이벤트마다 `environment` 키와 값만큼(수십 바이트) 늡니다.

## 결론과 후속

- 번들 +110 bytes, 상한 안. 렌더링 · 메모리는 미측정이며 이 기록은 성능 판정이 아닙니다.
- 후속: 기기에서 실제 수신(`environment = development`)을 확인해야 합니다
  (`docs/e2e/analytics.md` B1).
