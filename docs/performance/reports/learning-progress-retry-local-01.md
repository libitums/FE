## 시나리오
진행 저장 실패 뒤 앱을 종료하고 같은 계정으로 다시 시작합니다. 초기 불러오기 실패 중 진행한 뒤 서버가 빈 기록을 반환하는 경우, 저장 응답 중 추가 학습, 계정 전환, 늦은 응답, 손상된 서버 JSON, 삭제 성공·실패를 확인합니다. 네트워크 거부와 타임아웃도 경계 대역에서 재현합니다.

## 분석 결과
- 수정 전 복구 회귀 테스트 12건이 실패했습니다. 미전송 스냅숏을 사용자별 네이티브 저장소에 먼저 기록하고 서버 확인 뒤에만 제거하도록 수정했습니다.
- 기존 사용자로 복귀하면 로컬 미전송 기록을 먼저 적용한 뒤 서버와 합칩니다. 다른 계정의 기록을 읽거나 전송하지 않습니다.
- 한 컨트롤러에 저장 요청 하나를 허용하고, 응답 대기 중 추가된 진행을 다음 요청으로 보냅니다. 실패한 요청은 서버를 다시 읽은 뒤 재전송합니다.
- 실패 시 1·5·15·30·60초로 간격을 늘리고 이후 60초를 유지합니다. 성공 시 재시도 타이머를 없애며, 언마운트와 계정 전환은 이전 작업을 폐기합니다.
- 미전송 기록은 계정당 스냅숏 하나입니다. 이벤트 목록을 무한히 쌓지 않습니다. 로그아웃 시 유지하고 계정 삭제 성공 시 해당 기록을 지웁니다.
- 네이티브 저장소와 HTTP 전송만 대역으로 바꾸고 실제 훅·학습 API·인증·계정 삭제 결선을 실행했습니다.

## 비교
- 기준 번들: PR #188의 main.lynx.bundle 1,383,726 bytes.
- 최종 번들: 1,383,096 bytes(−630). 기존 1,384,000 bytes 예산을 유지합니다. 저장 관련 background 경계를 명시했으며 이미지·음원·의존성을 추가하지 않았습니다.
- 복구 회귀 15건·계정 정리 3건을 포함한 관련 테스트 58건 통과. 전체 포맷·타입·린트·단위/UI/통합 테스트·빌드·번들 크기 검사와 보고서 정책 검사 통과.
- 렌더·fluency·memory·NativeModule 타이밍은 미측정이며, 이 기록으로 성능을 판정할 수 없습니다.

## 해석
측정 한계: 실제 기기를 강제 종료하거나 운영 서버의 네트워크를 차단하지 않았습니다. 테스트의 저장소는 재시작을 모사하는 Map이며, iOS UserDefaults의 디스크 기록 시점·실기 성능을 측정한 결과가 아닙니다. [ReactLynx 생명주기 문서](https://lynxjs.org/react/lifecycle.html)에 따라 저장과 타이머는 background 콜백과 effect 경계 안에서 실행합니다.

## 결론과 후속
통신 실패 때문에 미전송 학습 진행을 잃는 경로를 복구합니다. 여러 기기의 동시 저장과 타임아웃된 이전 요청의 서버 도착 순서는 서버 RPC의 원자적 합치기를 다루는 다음 PR의 범위입니다. 연속 학습 날짜 기록의 오프라인 재전송과 iOS 실기 네트워크 복구 확인은 별도 검증이 필요합니다.
