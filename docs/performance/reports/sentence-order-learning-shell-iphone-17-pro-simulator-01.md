- 상태: 미측정 — 렌더링 · 메모리 캡처(`performance:capture`)를 돌리지 않았습니다. 번들
  크기만 재었습니다.
- 기능 PR: 문장 만들기를 `LearningShell` 위로 옮기고 디자인(Figma 65-14)대로 대화 카드 · 낱말
  창고를 그리며, 첫 인사 스텝에 배정한 변경(이 보고서와 같은 PR)
- 대상 commit: `0daacc2` 위의 작업 트리
- 기기: iPhone 17 Pro 시뮬레이터 — 화면 확인만 했습니다(Lynx Explorer, dev 서버 번들)
- OS: iOS 26.5
- Lynx SDK: 4.0.1 — Explorer 릴리스 기준
- 빌드: 번들 크기는 `pnpm build`의 `main.lynx.bundle`, 화면 확인은 `pnpm dev` 번들입니다.
  Release Host는 빌드하지 않았습니다.

## 시나리오

- 번들 크기: `main`(`0daacc2`)과 이 작업 트리를 각각 `pnpm build`로 빌드해
  `apps/mobile/dist/main.lynx.bundle` 크기를 비교했습니다.
- 화면 확인: 부팅 상태를 잠시 바꿔 문장 만들기를 바로 띄우고, 조각 셋을 놓아 확인 · 판정 ·
  내 말풍선 문장을 눈으로 확인했습니다. 수치를 남기지 않았습니다.

## 이 변경이 무엇을 건드렸나

- 문장 만들기의 머리 · 스크롤 · 액션 행을 걷고 `LearningShell`을 씁니다(듣기와 같은 뼈대).
- 카드 안에 말풍선 둘 · 답 칸 줄, 작업 영역에 낱말 창고(빈칸 포함)가 섭니다.
- 첫 인사 스텝이 듣기 뒤에 문장 만들기를 잇습니다 — 그 스텝의 학습 구간이 길어집니다.

## 해석

- **미측정 기록입니다.** 문장 만들기 진입 비용과 조각을 누를 때의 다시 그리기 비용을 판정할 수
  없습니다.
- 번들이 줄어든 것은 화면이 자기 머리 · 액션 행 · 표식을 걷고 껍데기를 함께 쓰게 된 몫으로
  보이지만, 나눠 재지 않아 근거는 없습니다.
