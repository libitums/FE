## 실행 조건

- 상태: 측정 — 입력 누락 수만(렌더 · 프레임 · 메모리는 미측정)
- 기능 PR: 한국어 자판 빠른 입력 — 번들 page config에 여러 손가락 터치를 켬([ADR-0112 개정 ⟨여러 손가락⟩](../../adr/0112-keyboard-touch-input.md))
- 대상 commit: `main`(`93860d25`) 위의 작업 브랜치 `fix/hangul-keyboard-fast-input`
- 기기: Android AVD R6_API30(2GB, `-read-only`)
- OS: Android 11(API 30)
- Lynx SDK: 4.0.1
- 빌드: `assembleBundled`(release 설정 + 디버그 서명) + 측정용 번들(진입점만 자판 화면으로 바꿈)

## 시나리오

- 「안녕하세요」 12자모 × 5 = 60키를 `sendevent`(다중 터치 프로토콜 B, 손가락 변화 하나 = 쓰기 하나)로 누르고, 자판이 올린 입력 수를 logcat에서 센다. 각 3회.
- 모양 셋: 한 손가락(누름 → 뗌 → 다음) · 두 엄지 짝(앞 키를 누른 채 다음 키) · 굴리기(다음 키가 닿은 뒤 앞 키를 뗌). 간격 100 · 50ms.

- 번들: 바뀐 것은 page config 두 키(수십 바이트)뿐이다 — 앱 코드 · 의존성 변경 없음.

## 해석

- 누락은 시간 간격이 아니라 **손가락이 겹쳤는지**로만 갈렸다 — 한 손가락은 50ms에서도 0, 겹친 둘째 손가락은 간격과 상관없이 모두 빠졌다. 호스트가 한 손가락 모드에서 둘째 손가락 이벤트를 JS에 보내지 않기 때문이다.
- 제한: 에뮬레이터 한 대 · 합성 이벤트다. 실제 손 · iOS · 저사양 실기의 체감 지연은 미측정이고, 측정 중 호스트 부하로 한 회 걸린 시간이 크게 흔들려(이벤트 순서는 같음) 지연 수치는 근거로 쓰지 않는다.

## 결론과 후속

- 결론: 여러 손가락을 켠 뒤 겹친 누름 누락이 0이 됐다. 한 손가락 연타는 고치기 전에도 빠지지 않았다.
- 후속: 사람 손 두 엄지 실기(iOS · Android) — [e2e](../../e2e/keyboard-touch.md) KT-E4 · KT-E12.
