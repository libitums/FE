# Android 로그인 후 탐색 접근성 속성

## 실행 조건

- 상태: 렌더링 시간·프레임·메모리 미측정.
- 대상 commit: `feat/android-signed-in-screen-e2e` 변경.
- 기기: Android 15 API 35 AOSP ARM 에뮬레이터, 320×640·160 dpi.
- OS: Android 15.
- Lynx SDK: 4.0.1.
- 빌드: 모의 인증 설정의 Debug APK와 로컬 미리보기 번들.

## 시나리오

모의 로그인 세션으로 여정 화면을 띄운 뒤 하단 탐색에서 설정으로 이동하고,
글자 배율 1.0·1.3에서 설정 항목과 법률 문서 링크를 Maestro로 확인했다.
하단 탐색·설정 셀의 네이티브 접근성 View와 탭 동작, 설정 제목의 헤딩을 추가했다.

## 분석 결과

- 두 배율의 Maestro 흐름과 기준 이미지 비교가 통과했다. 각 흐름에서 법률 문서를
  브라우저로 열고 앱으로 복귀했다.
- 단위·UI 테스트에서 활성 항목의 접근성 탭과 비활성 항목의 탭 부재를 확인했다.
- 모의 인증 설정의 모바일 Lynx 번들은 1,408,893 bytes였다. 서로 다른 설정으로
  빌드한 운영 번들과 정확한 증분 비교에는 쓰지 않는다.
- 렌더링 시간·프레임·메모리 수치는 수집하지 않았다.

## 해석

접근성 노드를 네이티브 View로 유지해야 Maestro가 하단 탐색과 설정 항목을 찾았다.
이 변경을 뺀 독립 실행에서는 첫 `Journey, selected` 선택부터 실패했고,
변경을 넣은 뒤 두 배율 모두 통과했다. 실제 TalkBack 음성 낭독과 초점 순서는
이 테스트의 범위가 아니다. 추가 View의 렌더링 비용은 측정하지 않아 판정할 수 없다.

## 결론과 후속

로그인 후 작은 화면의 탐색·설정 링크는 모의 세션에서 통과했다. 실제 제공자 로그인과
TalkBack 음성 탐색은 각각 별도 검증이 필요하다.
