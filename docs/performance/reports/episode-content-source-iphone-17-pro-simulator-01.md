## 이 변경이 무엇을 건드렸나

- 내장 데이터: `apps/mobile/content/manifest.json`(새 파일)과 기존 에피소드 JSON 셋(79,346 ·
  121,744 · 98,347 bytes, 합 299,437 bytes 원문)을 `src/lib/episode-bundled.ts`가 JSON 모듈로
  import합니다. PR #235까지 이 셋은 `src/` 밖이라 번들에 없었습니다.
- 디코더 첫 소비: 카탈로그가 `decodeEpisode`를 부르므로 PR #235가 탐침으로 잰 `zod/mini` + 디코더
  (+25,679 bytes)가 처음 산출물에 들어왔습니다.
- 3a 모듈 아홉(`episode-manifest.schema` · `episode-manifest` · `sha256` · `episode-catalog` ·
  `episode-bundled` · `episode-remote` · `episode-cache` · `episode-refresh` · `placeholder-fill`)과
  결선 훅 하나. 런타임 모듈은 전부 `background-only`입니다.
- 새 이미지 · 음원 · 의존성은 없습니다.

## 결론과 후속

- 번들 증가의 대부분은 사용자가 고른 「초반 에피소드 내장」의 데이터 자체입니다. 다음 내장
  에피소드마다 약 +80 ~ 120 KB가 더해질 것으로 예상하며, 그때마다 실측으로 상한을 다시 올립니다.
  10개 정도 내장하면 지금보다 약 +0.6 ~ 0.8 MB입니다 — 그 시점에 번들 압축 · 지연 로드 여부를 다시
  봅니다.
- 런타임 비용(앱 시작 뒤 백그라운드에서 매니페스트 요청 · SHA-256 · 에피소드 디코드)은 재지
  않았습니다. 카탈로그가 맵에 드러나는 3b에서 `performance:capture`로 잽니다 — 특히 에피소드 하나
  (약 100 KB)의 순수 JS SHA-256 시간과 디코드 시간.
- 지금은 버킷이 없어 매 실행 매니페스트 요청이 404로 끝나므로, 에피소드 다운로드 · 해시 계산은 실제
  기기에서 한 번도 돌지 않았습니다.
