# Android 제목 헤딩 노출 — API 35 에뮬레이터 — 01

## 실행 조건

- 측정 일시: 2026-10-01 KST.
- 상태: 미측정 — 렌더링 시간·프레임·메모리 캡처를 수행하지 않았다.
- 기능 PR: https://github.com/libitums/FE/pull/199.
- 대상 commit: `657cde9c` 이후 Android 제목 헤딩 변경.
- 기기: Android 15 API 35 ARM 에뮬레이터, 390×844·160 dpi.
- OS: Android 15.
- Lynx SDK: 4.0.1.
- 빌드: Debug APK와 로컬 미리보기 번들, 번들 포함 APK.
- 실행 회차: 01.

## 시나리오

- 전제: 앱 상태를 지우고 온보딩 첫 화면을 연다.
- 단계: 접근성 클릭으로 온보딩 세 단계를 지난 뒤 로그인 화면을 연다. 네 제목의 Android `isHeading()` 값을 검사한다.
- 관찰 구간: 온보딩 첫 화면부터 로그인 화면까지.

## 분석 결과

- Lynx의 `accessibility-traits="header"`만으로는 Android 접근성 노드의 `isHeading()`이 참이 되지 않았다.
- 실제 제목 텍스트에 `accessibility-heading={true}`를 지정하자 온보딩 세 제목과 로그인 제목에서 `isHeading()`이 참이었다. API 35 계측 1건이 통과했다.
- Maestro 호스트 1건·모의 소셜 로그인 3건·작은 화면 2건이 통과했다. 일반 번들 APK에서도 호스트·작은 화면 흐름을 다시 확인했다.
- Java 호스트의 접근성 브리지는 변경하지 않았다.
- 운영 설정의 모바일 Lynx 번들은 1,408,482 bytes로 1,409,000 bytes 예산 안에 있다.
- 렌더링 시간·프레임·메모리 수치는 수집하지 않았다.

## 해석

Android 접근성 트리의 헤딩 속성은 확인됐다. 성능 수치가 미측정이므로 속성 추가의
렌더링 비용은 판정하지 않는다. 실제 TalkBack의 제목 단위 탐색은 이 계측으로
확인할 수 없다.

## 결론과 후속

TalkBack이 설치된 기기에서 온보딩과 로그인 화면의 제목 단위 탐색과 음성 낭독을
확인한다. 현재 AOSP 에뮬레이터에는 TalkBack이 없고 Google Play 이미지 설치에는
SDK 라이선스 동의가 필요하다.
