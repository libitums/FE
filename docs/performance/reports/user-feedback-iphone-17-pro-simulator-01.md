# 사용자 피드백 · 에피소드 설문 · 평점 요청 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 렌더링 · 메모리 캡처(`performance:capture`)를 돌리지 않았습니다. 번들
  크기만 재었습니다.
- 기능 PR: 설정의 피드백 보내기 화면 · 에피소드 끝 설문 시트 · 앱스토어 평점 요청(이 보고서와 같은 PR, ADR-0036).
- 대상 commit: `feat/feedback`(`feat/progress-streak` 위 — PR #180 뒤에 쌓임).
- 기기: iPhone 17 Pro 시뮬레이터 — 이 회차에서는 앱을 띄우지 않았습니다.
- OS: iOS 26.5
- Lynx SDK: 4.0.1
- 빌드: 번들 크기는 `pnpm build`의 `main.lynx.bundle`입니다. Release Host는 빌드하지 않았습니다.

## 시나리오

- 번들 크기: 루트 `pnpm build`로 빌드해 `apps/mobile/dist/main.lynx.bundle` 크기를 비교했습니다. 기준은 PR #180의 같은 방식
  측정값(main `2fd87611` 합친 뒤)입니다. dev 서버는 띄우지 않았습니다.

## 이 변경이 무엇을 건드렸나

- 새 화면 하나(설정 스택의 피드백) · 시트 하나(에피소드 설문) — 기존 ui-lynx 컴포넌트(OptionSelector · TextField · Button ·
  BottomSheet)만 씁니다.
- 활동을 끝낼 때마다 끝낸 에피소드를 한 번 셉니다(구획 × 항목, 작습니다).
- 보내기 · 설문 답마다 RPC 1회(기다리지 않음). 평점 요청은 설치당 1회.

## 해석

- **미측정 기록입니다.** 늘어난 크기는 화면 · 시트 · 문구 · 결선 코드로 보이지만 소스맵으로 나눠 보지는 않았습니다.
- 새 서드파티 의존은 0건입니다. `StoreKit`은 iOS 시스템 프레임워크입니다.

## 결론과 후속

- 번들 +15,149 bytes, 상한 안(여유 약 2.2 kB). 렌더링 · 메모리는 미측정이며 이 기록은 성능 판정이 아닙니다.
- 후속: **다음 기능은 상한을 넘습니다.** 튜토리얼 콘텐츠(데이터)를 번들 밖으로 빼는 구성을 먼저 검토해야 합니다.

## PR #184 리뷰 후속

- 최신 main을 통합하고 피드백 제출 콜백의 예외를 실패 상태로 처리했습니다. 입력과 별점을 유지하며 재시도할 수 있고 실패 문구를 낭독합니다.
- TextField는 네이티브 이벤트에서 문자열을 추출해 bindinput 콜백에 전달하므로 기존 setMessage 연결이 맞습니다. 실제 입력 이벤트부터 전송·예외·재시도까지 회귀 테스트로 확인했습니다.
- 통합 후 `pnpm verify` 전체 통과. 메인 번들 1,374,816 / 1,375,000 bytes(여유 184 bytes), 이미지 8688.2 / 11520.0 kB, UI 패키지 465.3 / 481.0 kB입니다.
- 이 후속 작업에서는 네이티브 Host 테스트·실기 검증을 반복하거나 운영 마이그레이션을 적용하지 않았습니다. 개인정보 처리방침 갱신과 운영 마이그레이션은 기존 PR의 배포 전제입니다.
