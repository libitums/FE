# Android 접근성 버튼 실행 — API 35 에뮬레이터 — 01

## 실행 조건

- 측정 일시: 2026-10-01 KST.
- 상태: 미측정 — 렌더링 시간·프레임·메모리 캡처를 수행하지 않았다.
- 기능 PR: https://github.com/libitums/FE/pull/199.
- 대상 commit: `19bdbd78` 이후 접근성 클릭 변경.
- 기기: Android 15 API 35 ARM 에뮬레이터, 390×844·160 dpi.
- OS: Android 15.
- Lynx SDK: 4.0.1.
- 빌드: Debug APK와 로컬 미리보기 번들, 번들 포함 APK.
- 실행 회차: 01.

## 시나리오

- 전제: 앱 상태를 지우고 온보딩 첫 화면을 연다.
- 단계: Android 접근성 `ACTION_CLICK`으로 `Next`·`Back`·`Next`·`Next`·`Get started`를 실행하고 세 소셜 버튼의 동작 노출을 검사한다.
- 관찰 구간: 첫 화면 표시부터 로그인 화면의 소셜 버튼 표시까지.

## 분석 결과

- 수정 전 `Next`의 접근성 이름은 있었으나 `isClickable=false`이며 `ACTION_CLICK`이 없었다.
- 수정 후 계측 1건에서 온보딩 왕복·로그인 진입과 세 소셜 버튼의 클릭 동작 노출을 확인했다.
- 호스트는 Lynx 페이지 갱신 때 UI 트리를 순회하고, 접근성 탭이 켜진 네이티브 View에 delegate를 설치한다. 같은 View의 후속 갱신은 기존 delegate를 재사용한다.
- 운영 설정의 모바일 Lynx 번들은 1,408,029 bytes로 직전 1,408,000 bytes 상한을 29 bytes 초과했다. 접근성 속성 추가를 반영해 상한을 1,409,000 bytes로 조정했다.
- 순회 시간·프레임·메모리 수치는 수집하지 않았다.

## 해석

접근성 서비스가 사용할 수 있는 클릭 동작은 확인됐다. 성능 수치가 미측정이므로
페이지 갱신 때의 UI 트리 순회 비용은 판정하지 않는다. TalkBack의 실제 낭독과
순차 탐색도 이 계측으로 확인할 수 없다.

## 결론과 후속

실제 TalkBack을 갖춘 기기에서 낭독·초점 순서를 확인하고, 같은 시나리오의 페이지
갱신 비용을 별도로 측정한다.
