# 공통 타이핑과 통화 UI — 시뮬레이터 검토 — 01

## 실행 조건

- 기록 일시: 2026-09-30
- 상태: 미측정 — 화면과 동작을 검토했으나 PerformanceEntry, 메모리 스냅샷, Trace는 수집하지 않았다.
- 대상 commit: `04cecf48` 위 `codex/shared-typing-call-ui`의 작업 트리. 시각 검토는 병합 전 동일한 화면 구현으로 진행했으며 최신 main에 이식한 뒤에는 자동 검증을 수행한다.
- 기기: iPhone 17 Pro, Apple Silicon iOS Simulator
- OS: iOS 26.5
- Lynx SDK: 4.0.1 (`apps/ios/Podfile.lock`)
- 빌드: Rspeedy 개발 서버의 playground 번들을 기존 Debug Host에서 실행했다. Release Host는 재빌드하지 않았다.

## 시나리오

1. 내레이션, 메신저, 학습 통화, 도입부 통화를 각각 미리보기로 열어 타이핑과 자막 배치를 검토한다.
2. 수신 상태에서는 시계와 자막을 숨기고 초록색 Accept를 표시한다. 받기 이후 통화 타이머와 자막을 표시한다.
3. 도입부 통화는 자막을 자동 진행하고 종료 후 Continue를 표시한다. 도입부 통화에는 음원이 없다.
4. 학습 통화는 답장을 선택하면 다음 음원을 재생한다. 재생 종료·화면 이탈 시 정리와 완료 콜백은 UI 및 통합 테스트로 확인한다.
5. 자막 전체 문장으로 공간을 먼저 확보하고 공개 텍스트만 바꾼다. 기내 안내는 차임 구간 이후 음성 길이에 맞추어 공개한다.

## 분석 결과

타이핑 중 말풍선의 크기와 위치가 움직이던 문제를 전체 텍스트 측정 영역과 공개 영역의 분리로 수정했다. 두 통화는 CallScreen과 CallControls를 공유하며, 도입부 수신 화면과 종료 후 자막·Continue 배치를 시뮬레이터에서 확인했다.

렌더 시간, 프레임 유창성, 메모리와 NativeModule 지연 수치는 미측정이다. 화면 검토와 자동 기능 검증을 성능 측정값으로 대신하지 않는다.

## 해석

개발 모드의 시뮬레이터 시각 검토이므로 실기 성능이나 Release 빌드 성능을 판정할 수 없다. 글자별 업데이트가 렌더 빈도를 높이므로 긴 문장, 반복 재생, 화면 전환 시 부하와 메모리를 추가 측정할 필요가 있다. 타이머 정리 테스트는 메모리 누수 측정을 대체하지 않는다.

## 결론과 후속

공통 컴포넌트와 타이핑 동작의 기능 검증을 PR에 기록한다. 성능 개선 또는 회귀 여부는 아직 판단하지 않는다. 같은 Release Host에서 변경 전후 내레이션과 통화 재생을 반복하고 render·fluency·memory trace를 수집하는 것이 후속이다.
