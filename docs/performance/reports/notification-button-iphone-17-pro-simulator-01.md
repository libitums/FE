## 해석

- 부팅 · 맵 · 학습 화면의 경로에 더해진 계산은 `TopBar` 렌더마다의 `useMotion()` 조회 하나와 순수 함수 둘(클래스 문자열 · 막 유무)뿐입니다 [코드]. 칩의 클래스 계산은 지금의 인라인 배열을 순수 함수로 옮긴 것입니다.
- 눌림 축소는 CSS `transform` 전환이라 레이아웃을 다시 계산하지 않고, 동작 줄이기의 막은 `opacity` 전환입니다 — 어느 쪽도 다시 그림 비용이 늘었다고 볼 근거는 없지만 [추론], 재지 않았습니다.
- 상단 줄이 40 → 44로 4 높아졌지만 탭 루트의 위 여백 값은 그대로라 맵 · 목록의 스크롤 요소 수와 배치 계산은 같습니다. 학습 화면은 카드 영역이 4 줄어듭니다.
- 측정 한계: 런타임은 미측정이라 버튼을 반복해 누를 때의 프레임 · 다시 그림 비용과 메모리는 아직 판정할 수 없습니다. 번들 수치도 설정별 단일 빌드이고, 예측과의 차이를 항목별로 나눈 자료가 없어 위 두 이유는 추론입니다.
