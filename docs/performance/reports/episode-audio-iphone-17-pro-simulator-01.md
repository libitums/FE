## 이 변경이 무엇을 건드렸나

- 메인 · 백그라운드 두 스레드에 실리는 것: 음성 id → 주소 순수 모듈(import 없음), 재생 훅 하나, 컷 표시 모델의 소리 필드와 소리 단서 함수, 최종 테스트의 소리 단서 함수,
  두 화면의 훅 호출과 나가기 앞 정지, 콘텐츠 스키마 · 정규화의 컷 키 한 줄씩.
- 백그라운드에만 실리는 것: 최종 테스트 계획의 대화 줄 찾기와 턴 소리 합치기, 내장 JSON 셋에 더한 음성 id(u01 7 · u02 5 · u03 5자리)와 매니페스트의 version · 해시 · 바이트.
- 네이티브(번들 밖): iOS 재생 모듈의 원격 분기와 번들 id 거부 규칙, Android 원격 판정 클래스와 컨트롤러 분기.
- 새 이미지 · 음원 · 의존성은 없습니다. 음성 14개는 번들이 아니라 Supabase 공개 버킷에 있고 재생할 때 스트리밍합니다.

## 결론과 후속

- 번들 증가는 음성 순수 모듈 · 재생 훅 · 두 화면의 결선 · 최종 테스트 계획의 대화 줄 찾기 · 내장 JSON의 음성 id가 실린 몫입니다. 음원 자체는 번들에 들어오지 않았습니다.
- 런타임에서 재야 할 것(미측정): 컷 진입 → 첫 소리까지의 지연(네트워크 스트리밍 — 프리로드가 없으므로 컷의 첫 프레임보다 늦을 수 있습니다), 소리가 나는 동안 타자기 · 페이드의 프레임,
  최종 테스트에서 정답 효과음과 내 줄이 겹칠 때의 프레임. `performance:capture`와 실기 청음으로 잽니다.
- 병합 직전에 main이 앞서 있으면 그 위에서 번들을 다시 재야 합니다 — 직전 값 1,913,545는 이 브랜치가 갈라진 시점의 main입니다.
