# 여정 맵 지표 모달(연속 학습 · 트로피) — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 렌더링 · 메모리 캡처(`performance:capture`)를 돌리지 않았습니다. 번들
  크기만 재었습니다.
- 기능 PR: 여정 맵 상단 지표 칩(연속 학습 · 트로피)을 누르면 뜨는 전체 화면 모달(Figma
  47-14057 · 74-419)을 더한 변경(이 보고서와 같은 PR)
- 대상 commit: `d88f5c5` 위의 작업 트리
- 기기: iPhone 17 Pro 시뮬레이터 — 화면 확인만 했습니다(Lynx Explorer, dev 서버 번들)
- OS: iOS 26.5
- Lynx SDK: 4.0.1 — Explorer 릴리스 기준
- 빌드: 번들 크기는 `pnpm build`의 `main.lynx.bundle`, 화면 확인은 `pnpm dev` 번들입니다.
  Release Host는 빌드하지 않았습니다.

## 시나리오

- 번들 크기: `main`(`d88f5c5`)과 이 작업 트리를 각각 `pnpm build`로 빌드해
  `apps/mobile/dist/main.lynx.bundle` 크기를 비교했습니다.
- 화면 확인: 여정 맵에서 연속 학습 칩 → 모달 → 뒤로, 트로피 칩 → 모달 → Continue 순으로
  눌러 모달이 뜨고 닫히는 것을 눈으로 확인했습니다. 수치를 남기지 않았습니다.

## 이 변경이 무엇을 건드렸나

- 모달은 **닫혀 있으면 한 노드도 그리지 않습니다** — 열림 상태가 `null`이면 컴포넌트를
  렌더하지 않습니다. 그래서 여정 맵 첫 렌더와 탭 전환 구간에 더해지는 요소는 0이어야
  합니다. 다만 이것은 코드에서 읽은 것이지 캡처로 확인한 값이 아닙니다.
- 칩 둘에 `bindtap`이 붙었습니다. 노드 수는 바뀌지 않습니다.
- 모달이 열리면 요소 약 30개(버튼 둘, 아이콘 최대 11개, 칸 7 · 요일 7)가 한 번에 생깁니다.

렌더링(`pipeline` · `layout`)과 메모리(`elementNodeCount` 등) 값은 **없습니다** — 재지
않았습니다.

## 해석

- **미측정 기록입니다.** 렌더링 · 메모리 수치가 없으므로 이 변경이 여정 맵 전환이나 모달
  열림 비용에 무엇을 더했는지 판정할 수 없습니다.
- 번들 +21.5 kB는 단일 빌드의 비교이고, 무엇이 그 크기를 차지하는지(JSX 스냅샷 · CSS ·
  아이콘 문자열) 나눠 재지 않았습니다. 새 서드파티 의존은 0건입니다 —
  `package.json`과 `pnpm-lock.yaml`이 바뀌지 않았습니다.
- 「닫힌 동안 요소 0」은 코드 구조에서 나온 예상일 뿐 실측 근거가 없습니다.

## 결론과 후속

- 번들 +21,534 bytes, 상한 조정. 렌더링 · 메모리는 미측정이며 이 기록은 성능 판정이 아닙니다.
- 후속: Release Host에서 `performance:capture`로 (1) 여정 탭 재진입 — 앞 보고서
  「여정 맵 상단 바 · 에피소드 헤더」와 같은 절차 — 과 (2) 모달 열림 구간을 재야 합니다.
