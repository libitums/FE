## 시나리오

튜토리얼 말하기에서 Skip과 Speak를 같은 고정 행에 둔다. 문장 카드와 안내는 하나의 스크롤 영역이다. 카드의 파형을 누르면 하단 Speak와 같은 권한 요청·녹음 시작 경로로 들어간다. UI 테스트는 시작·중지, 기존 Skip·거부·완료 동작을 확인한다.

## 분석 결과

| element nodes / memory completion | 73 / completed, 1 of 1 instance |
| 첫 수정분 전체 제품 번들, 운영 공개 설정 포함 | 1,406,322 bytes |

같은 운영 설정의 main 번들 1,404,046 bytes 대비 +2,276 bytes다. CI와 같은 공개 환경변수 없는 빌드는 1,406,133 bytes로, main 1,403,857 bytes 대비 +2,276 bytes다. 상한을 1,405,000 → 1,407,000 bytes로 증가분만 반영한다. fixture 번들 크기를 제품 크기로 사용하지 않았다. 새 자산·의존성은 없다.

375×812에서 두 버튼이 나란히 보였다. 320×568에서는 overflow만 지정하면 z-index를 가진 카드가 스크롤 밖에 그려지는 문제를 확인했고, 스크롤에 독립 z-index를 지정한 뒤 버튼 영역 침범이 사라졌다. 아이콘 탭으로 iOS 마이크 권한 요청까지 도달했다. 실제 음성 인식은 이 검증에 포함하지 않았다.

받아쓰기 설정 안내·재시도 추가 후 최종 운영 설정 제품 번들은 1,407,199 bytes다. 첫 수정분 대비 +877 bytes, 같은 운영 설정의 main 대비 +3,153 bytes다. 이 추가분으로 상한을 1,407,000 → 1,408,000 bytes로 조정했다.

받아쓰기 오류 상태의 375×812와 320×568 시뮬레이터 fixture를 추가 확인했다. 설정 안내를 카드 아래에 두면 첫 화면에서 가려져, 스크롤 밖의 상단 지시문으로 옮겼다. 최종 화면에서 설정 경로 전체와 Try again·Skip이 처음부터 보이고 서로 겹치지 않았다. fixture는 오류 상태를 주입한 레이아웃 확인이며 실제 권한·인식 성공을 대신하지 않는다.

## 제한 사항

단일 시뮬레이터 fixture 최초 로드 관측이며 실기기 출시 성능 기준선이 아니다. 전체 앱 부팅, 스크롤 프레임, 녹음 중 메모리, 실제 음성 인식은 미측정이다. 이전 구현과 동일 조건 성능 비교가 없으므로 개선·퇴행을 판정하지 않는다.

## 결론과 후속

녹음 아이콘의 탭 결선과 버튼 배치를 수정했다. 실제 iPhone에서는 사용자가 Skip 겹침 해소를 확인했다. 후속 진단에서 Siri·받아쓰기 비활성화 오류(`kLSRErrorDomain/201`)가 확인됐으며, 사용자가 받아쓰기를 켠 뒤 실제 인식 결과가 나온다고 확인했다. 후속 수정은 이 오류의 설정 안내와 같은 문항의 Try again 동작을 추가한다. 진단용 로그는 제품 코드에서 제거했다. 진단 로그를 제거한 최종 수정본 설치 후, 사용자가 녹음 후 음원 재생과 홈 화면 왕복 후 재생·녹음 모두 정상이라고 확인했다. Release/App Store 서명 및 TestFlight 검증은 별도다.
