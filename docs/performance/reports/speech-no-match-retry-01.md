# 말하기 못 알아들음 → 다시 말하기 — 01

## 실행 조건

- 측정 일시: 2026-11-24T12:00:00+09:00
- 상태: 미측정 — 런타임 성능(Rendering · Memory · Trace)은 수집하지 않았다. 인식 실패 하나의 결말 분류와 그 국면의 버튼 · 안내를 바꾼 변경의 영향 범위를 적은 기록이다
- 기능 PR: 브랜치 `fix/speech-no-match`([ADR-0179](../../adr/0179-speech-no-match-retry.md))
- 대상 commit: `e80aeb96` 위의 변경
- 기기: Android `Pixel_8` 에뮬레이터 · iOS 26.5 시뮬레이터(동작 확인만, 측정 아님)
- OS: 해당 없음
- Lynx SDK: 4.0.1
- 빌드: `pnpm verify`의 `pnpm build` · `pnpm size:check`(.env.local 없는 설정)
- 실행 회차: 01

## 시나리오

- 단계: 말하기 문항에서 인식 1회가 못 알아들음으로 끝남 → 안내 · `Try again` · `Skip`이 선다 → `Try again`으로 같은 문항을 다시 듣는다.
- 하지 않은 것: 결말이 서는 순간의 프레임 측정, 저사양 기기 실행.

## 이 변경이 무엇을 건드렸나

- 인식 결과 하나에 도메인 · 코드 비교가 몇 번 늘었다(배열 `includes` 셋, 인식 1회당 한 번, 렌더 경로 밖).
- 국면이 하나 늘어 안내 줄 · 버튼 행이 그 국면에서 기존 불가 국면과 같은 수의 요소로 선다. 롤플레이는 버튼 하나(기존 `Button`)가 더 선다.
- 이벤트 수는 그대로다(문항당 첫 판정 · 건너뜀 한 번). `skipReason`의 값이 둘 늘었다.

## 분석 결과

```text
pnpm verify  테스트 · 빌드 · size:check 통과(천장 5,850,000 그대로)
이벤트 수    변화 없음
```

## 해석

- 측정 한계: 결말이 서는 순간의 비용은 재지 않았다. 늘어난 일은 정수 비교 몇 번과 이미 있던 버튼 · 글자 요소 하나다.

## 결론과 후속

- 미측정이며 이 기록은 성능 판정이 아니다.
- 후속: 배포 뒤 `skipReason`의 `missed:*` 분포와 다시 말해 판정된 비율을 본다.
