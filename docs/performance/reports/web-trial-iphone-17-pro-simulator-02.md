## 해석

- 앱 번들이 바이트 단위로 같다 — 패키지 `sideEffects: false`와 쓰이지 않는 export 제거로 새 모듈이 앱 산출물에 들지 않는다(산출물에서 새 판정의 상수 · 군말 표 검색 0 — 자모 열 문자열은 앱의 기존 한글 자판 것이다).
- 체험판 +6,075 B 중 발음 판정(자모 표 · 규칙 · 편집 거리)이 약 3.3 kB(압축 전 산출물을 읽어 어림 — 한글 자모가 UTF-8 3바이트라 표가 크다), 나머지는 수집 · 측정 · UA 분류 결선이다(추정 — 모듈별로 나누어 재지 않았다).
- 압축 전 산출물 바이트이고 실제 전송량 · 실행 시간(편집 거리는 문장당 수백 단위 × 수십 단위, 판정 한 번에 정답 · 대안 쌍 최대 3)은 재지 않았다.
- 측정 한계: 번들 크기만 잰 단일 회차이고 렌더 · 메모리 · 판정 실행 시간은 미측정이다 — 이 수치는 성능 통과의 근거가 아니다. 휴대폰에서 판정이 체감될 만큼 느린지는 이 자료로 판정할 수 없다(EU12에서 볼 것).

## 결론과 후속

- 앱 번들 변화 0, 상한 그대로. 체험판 스크립트 상한을 45,900으로 올렸다(evidence · ADR-0083 대가 11).
- 더 줄여야 하면 자모 표를 문자열 색인으로 바꾸는 것이 첫 후보다(수백 바이트 규모 — 추정).
- 실기 확인(실제 인식기의 받아쓰기 · 수집 요청)은 [웹 체험판 e2e](../../e2e/web-trial.md) EU12 — 미실행.
