## 실행 조건

- 상태: 미측정 — 렌더링 · 메모리 캡처(`performance:capture`)를 돌리지 않았습니다. 번들
  크기만 재었습니다.
- 기능 PR: Lynx `fetch`의 연결 실패 응답(status 0 · 499)을 로그인 클라이언트가 네트워크 실패로
  다루는 변경(이 보고서와 같은 PR)
- 대상 commit: `main`(`50f051e`) 위의 작업 트리
- 기기: 실행하지 않았습니다. 시뮬레이터 · 실기에서 앱을 띄우지 않았습니다.

- Lynx SDK: 4.0.1
- 빌드: 번들 크기는 `pnpm build`의 `main.lynx.bundle`입니다. Release Host는 빌드하지 않았습니다.

## 시나리오

- 번들 크기: `main`(`50f051e`)과 이 작업 트리를 같은 자리 · 같은 환경 변수로 각각 `pnpm build`해
  `apps/mobile/dist/main.lynx.bundle` 크기를 비교했습니다.

## 이 변경이 무엇을 건드렸나

- `lib/api-client.ts`의 전송 한 곳에 status 비교 하나가 늘었습니다.
- 요청 수 · 화면 · 저장은 바뀌지 않았습니다. 바뀌는 것은 연결 실패 때의 분류뿐입니다.
