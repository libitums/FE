## 해석

- **체감 지연 — 로그인 뒤 최대 3초 대기가 생겼습니다.** 소셜 교환 · 코드 검증이 성공한 뒤 결선이 판정 RPC 둘(`load_learning_progress` · `load_learner_profile`)의 응답을 기다리고, 그동안 누른 버튼은 로딩인 채 서 있습니다.
  기존 회원은 첫 `present` 응답이 오는 즉시, 신규 사용자는 두 응답이 다 오는 즉시 넘어가므로 정상 망에서는 RPC 왕복 한 번(두 요청은 같은 틱에 나갑니다)만큼 늦어진다고 봅니다 [추론]. 망이 느리거나 끊기면 **3,000 ms를 다 기다린 뒤** 언어 선택이 섭니다.
  이 대기는 지금까지 없던 것이고 화면에 따로 안내하지 않습니다(소셜 교환 대기와 같은 표시).
- 그 대신 기존 회원은 언어 선택 · 여정 입장 두 화면과 두 번의 탭을 건너뜁니다 — 맵에 닿기까지의 전체 시간은 줄어들 것으로 보지만 [추론], 재지 않았습니다.
- 로그인마다 읽기 RPC가 2건 늘었습니다(진행 동기화의 조회와 같은 순간에 같은 RPC가 한 번 더). 판정이 끝난 뒤 학습자 프로필 업로드가 최대 3초 늦게 시작합니다.
- 부팅 · 맵 · 레슨 경로에는 새 계산이 없습니다 — 세션 갱신 부팅은 판정을 거치지 않습니다 [코드].
- 측정 한계: 런타임은 미측정이라 실제 판정 대기 시간의 분포, 바로 맵 진입의 첫 렌더, 메모리에 대해서는 아직 판정할 수 없습니다. 번들 수치도 설정별 단일 빌드입니다. 판정 실패 · 시간 초과의 빈도는 이 변경이 재지 않기로 했습니다(ADR-0069 Q3).

## 결론과 후속

- 결론: 이 commit의 `main.lynx.bundle`은 CI 설정 2,173,255 · 로컬 설정 2,173,444 bytes이고, main 대비 +4,036 bytes(CI 설정)는 전부 판정 · 배선 · 언어 규칙 코드입니다. 상한은 2,175,000 bytes입니다.
- 후속: 실제 소셜 로그인이 열리면 RUE1 · RUE2의 화면 녹화로 판정 대기(인증 창 닫힘 → 맵 또는 언어 선택)를 프레임 단위로 적습니다. 3초가 짧다는 관측이 나오면 ADR-0069 재검토 조건대로 대기 시간과 판정 결과 측정을 다시 정합니다. 병합 직전에 main이 앞서 있으면 그 위에서 번들을 다시 잽니다.
