- 상태: 미측정 — 번들만. 받기 중 렌더링 · 메모리 · 배터리 · 데이터 사용량을 캡처하지 않았다.
- 기능 PR: 에피소드 백그라운드 받기 — 호스트 `ContentFileModule` · 신호 `contentSyncOpportunity`, JS가 에피소드를 하나씩(본문 → 그림 · 음성) 받고 다 갖춘 원격 에피소드만 연다(ADR-0071). 사용자 결정 2026-10-19.
- 대상 commit: 이 보고서와 같은 PR의 `feat/episode-background-download` 브랜치 HEAD
- 기기: 측정 기기 없음(번들 크기만) — 받기 · 오프라인 재생은 실기 iPhone · Android에서 확인한다
- OS: 해당 없음(번들 산출물)
- Lynx SDK: 4.0.1
- 빌드: `pnpm build` 산출 `apps/mobile/dist/main.lynx.bundle`(CI 설정, `.env.local` 없음), 판정은 `pnpm size:check`
- 측정 일시: 2026-10-19

## 시나리오

- 번들 크기: 이 변경의 CI 설정 빌드를 `pnpm size:check`로 판정했다.

## 이 변경이 무엇을 건드렸나

- JS: 자산 목록 순수 함수 · 에피소드 하나의 자산 받기 · 완료 표시 · 받기 실행기 · 호스트 파일 접점, 갱신 루프 재구성, 카탈로그 게이트, 주소의 로컬 우선.
- 호스트: iOS · Android 파일 저장 모듈과 연결 · 포그라운드 신호, 재생기의 `file://` 허용. 앱 번들(JS)에는 들어가지 않는다.
- 런타임 비용의 새 축: 실행 시작과 신호마다 매니페스트 GET 한 번, 받을 것이 있으면 에피소드당 본문 하나 + 그림 · 음성 수십 개의 순차 다운로드(호스트 스레드). 카탈로그 다시 읽기는 에피소드가 갖춰질 때마다 한 번.

## 제한 사항

- 번들만 쟀고 받기 중 프레임 · 메모리 · 데이터 사용량은 미측정이다 — 이 수치는 성능 통과의 근거가 아니다.
- 순차 다운로드가 학습 화면의 음성 스트리밍과 대역폭을 다투는지는 판정할 수 없는 상태로 남았다.
