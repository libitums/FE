## 해석

- 세션 헤더는 상태 표시줄과 겹치지 않고, 탭 루트 상단 줄과 같은 위쪽 여백(12 dp)에서 시작한다. 빠진 줄 자리에 빈 띠가 남지 않고 아래 내용이 그대로 올라왔다.
- 학습 화면은 세로로 60.4 dp를 더 쓴다. 큰 글자에서 무대 · 작업 영역이 한 스크롤로 합쳐지는 경계(학습 껍데기 큰 글꼴 e2e)가 이만큼 늦게 오는지는 이번 회차에서 보지 않았다.
- 결과 화면은 칩을 다시 세우므로 학습 → 결과로 넘어갈 때 상단 줄이 나타난다. 그 전환이 어색한지는 체감으로 판정하지 않았다.
- 한계: 단일 회차 · 에뮬레이터 한 대 · 글자 배율 1.0 · 학습 폼 둘(문장 만들기 · 대화 순서)만 봤다. 다른 폼(메신저 · 전화 · 듣기 등), 큰 글자, 작은 화면, iOS, TalkBack은 판정할 수 없다. 런타임 성능 값이 없으므로 이 기록은 성능 기준선이나 회귀 통과의 증거가 아니다.

## Trace 후속 확인

- render: 해당 없음 — 상단 줄 노드가 빠져 첫 렌더 비용이 줄 수 있지만 Trace를 수집하지 않았다.
- fluency: 해당 없음 — 문항 전환의 프레임은 측정하지 않았다(눈으로 정상).
- memory: 해당 없음 — 수집하지 않았다.
- NativeModule: 해당 없음 — 관찰 구간에서 이 변경과 관련된 호출이 없다.

## 결론과 후속

- 결론: AVD `R6_API30`의 Debug 빌드에서 학습 화면(튜토리얼 · 카탈로그 첫 문항, 완료 카드)에 칩 · 알림 버튼이 서지 않고 세션 헤더가 상태 표시줄 아래 12 dp에서 시작하며(변경 전보다 60.4 dp 위), 결과 화면과 탭 루트에서는 칩이 그대로 선다.
- 후속: 큰 글자 · 작은 화면에서 학습 껍데기 배치가 어떻게 바뀌는지, iOS 같은 화면의 헤더 위치는 별도 회차에서 본다.
