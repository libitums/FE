# UI 언어 문구표 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 렌더링 · 메모리 캡처(`performance:capture`)를 돌리지 않았습니다. 번들
  크기만 재었습니다.
- 기능 PR: UI 문구를 언어별 문구표(`lib/ui-copy*.ts`)에서 읽게 바꾸고 고른 UI 언어를 저장하는
  변경(이 보고서와 같은 PR, ADR-0031).
- 대상 commit: `feat/ui-language-catalog`(main `c46ce62` 위).
- 기기: iPhone 시뮬레이터(393×852pt) — e2e 회차(`docs/e2e/ui-language.md`)에서 화면 확인만
  했습니다(Debug 호스트 앱 내장 번들).
- OS: iOS 26.5
- Lynx SDK: 4.0.1
- 빌드: 번들 크기는 `pnpm build`의 `main.lynx.bundle`입니다. Release Host는 빌드하지 않았습니다.

## 시나리오

- 번들 크기: 루트 `pnpm build`(ui-lynx → mobile → storybook)로 빌드해
  `apps/mobile/dist/main.lynx.bundle` 크기를 비교했습니다. 기준 main(`c46ce62`)은 임시 worktree에서,
  이 브랜치는 작업 트리에서 `dist`를 지우고 빌드했습니다. dev 서버는 띄우지 않았습니다.
- 화면 확인: 언어 선택 → 맵 · 알림 · 롤플레이 · 설정 · 프로필 · 약관을 돌며 접근성 트리의 한글
  수를 셌고, 재실행 뒤 영어가 유지되는 것을 봤습니다. 시간 수치는 남기지 않았습니다.

## 이 변경이 무엇을 건드렸나

- 새 모듈: 문구표 계약 · 영어 섹션 파일(`lib/ui-copy-en-*.ts`) · `lib/ui-copy.ts`(`uiCopyFor` ·
  `UiCopyContext` · `useUiCopy`) · `lib/ui-language.ts`(저장 키 `libitum.ui.language` 읽기 · 쓰기).
- App 경계에서 문구표를 context로 한 번 내려 주고, 화면 약 70 파일이 리터럴 대신 문구표를 읽는다.
- 부팅 때 저장소 읽기 1회(`loadUiLanguage`), 언어 선택 「Continue」 때 쓰기 1회.
- `packages/ui-lynx` 컴포넌트의 접근성 기본 문구를 영어로 바꿨다(구조 변화 없음).

## 해석

- **미측정 기록입니다.** 늘어난 크기의 대부분은 영어 문구 문자열과 섹션 함수(복수형 등)로
  보이지만 소스맵으로 나눠 보지는 않았습니다.
- 문구표는 언어가 바뀔 때만 새로 고르며(`uiCopyFor`는 상수 객체를 돌려준다), 화면은 context에서
  읽기만 합니다 — 렌더 비용이 체감될 만큼 늘지 않을 것으로 보지만 근거는 없습니다.
- 새 서드파티 의존은 0건입니다.

## 결론과 후속

- 번들 main 대비 +16,950 bytes, 상한 안(여유 약 44.2 kB). 렌더링 · 메모리는 미측정이며 이 기록은
  성능 판정이 아닙니다.
- 후속: 영어 외 언어를 열 때(문구표가 언어 수만큼 커질 때) 번들을 다시 재고, 언어별 지연 로딩이
  필요한지 판단합니다.
