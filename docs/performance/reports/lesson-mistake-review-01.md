# 레슨 틀린 문제 다시 풀기 — 미측정 — 01

## 이 변경이 무엇을 건드렸나

- 순수 함수: 틀린 문항 고르기(결과 → 문항 자리, 건너뛴 말하기 자리 비움) · 줄 넘기기(맞힘 빠짐 · 틀림 뒤로) · 카운터(`Review i / k`) — `catalog-review.ts`.
- 결선: 마지막 활동 뒤 판정 대신 다시 풀기 route(`catalog-lesson`의 `review` 필드)로 갈아타고, 줄이 비면 첫 시도 결과로 지금과 같은 판정 · 기록 · 이벤트를 낸다(`catalog-lesson-finish.ts`). 세션 상태에 틀린 문항 목록 하나가 더해졌다.
- 화면: 다시 풀기 화면은 기존 학습형 컴포넌트에 문항 하나를 넘겨 그대로 다시 쓰고, 껍데기가 context로 헤더 변형(면 색 · 순번 글 · 이름표 꼬리) · 고침 판 · 시작 배지를 그린다. 시작 배지는 새 컴포넌트 하나 · CSS 키프레임 넷(들어옴 · 떠남 · 줄이기 페이드 둘)이고 타이머 둘이 국면을 바꾼 뒤 걷힌다.
- 의존성 · 이미지 · 음원 · 네이티브는 바뀌지 않았다. 아이콘은 이미 있는 `@libitums/icons` 패키지의 `refresh` 하나를 더 가져왔다.

## 해석

- 번들만 쟀고 렌더는 미측정이다 — 이 수치는 성능 통과의 근거가 아니고, main 기준을 같은 회차에 재지 않아 이 변경의 증가분도 말할 수 없다.
- 다시 풀기 화면은 줄을 넘길 때마다 활동 컴포넌트를 새 열쇠로 다시 마운트한다. 문항 하나짜리라 마운트 비용은 레슨 안 활동 전환과 같은 갈래로 보지만, 실기에서 잰 자료가 없다.
- 시작 배지는 재생하는 동안만 DOM에 서고 터치를 받지 않는다. 겹친 동안 아래 문항의 첫 렌더 · 첫 탭 지연이 늘어나는지는 판정할 수 없다 — 프레임 Trace가 필요하다.

## 결론과 후속

- 결론: 번들은 상한 안이다. 런타임 성능은 미측정으로 남긴다.
- 후속: 실기(iPhone · Android)에서 시작 배지 재생 구간의 프레임과 다시 풀기 화면 전환을 Trace로 잰다. Android에서 고침 판의 Continue · 다시 풀기 화면 탭이 취소되지 않는지(누름 상태가 요소를 움직이지 않음) 함께 본다.
