# Android 푸시 서버 전송 성능 기록

## 실행 조건

- 상태: 부분 검증 — 서버 로직·SQL 테스트만 실행. 실제 FCM 왕복 지연·기기 수신 지연은 미측정.
- 대상 commit: `c49a8209` (`origin/main`) 기준 `feat/push-fcm-transport` 작업 트리.
- 기기: 사용하지 않음 — 서버 전송 계약 테스트.
- OS: macOS 로컬 테스트 호스트. Android 기기 수신은 미측정.
- Lynx SDK: 적용 대상 아님 — 호스트 화면을 실행하지 않음.
- 빌드: Node 22 단위·통합 테스트와 일회용 PostgreSQL 17.9. 외부 Firebase 프로젝트와 Android 호스트는 연결되지 않음.
- 실행 회차: 01.

## 시나리오

APNs와 FCM 기기를 같은 조회 결과에 넣고 공지 한 건을 보낸다. OAuth 응답과 FCM HTTP v1 응답은 테스트 대역으로 고정한다. 별도 SQL 테스트는 기존 APNs 행과 FCM 행의 등록·해제를 검증한다.

## 분석 결과

- 혼합 전송 테스트에서 FCM access token 교환은 발송 회차당 한 번이었다.
- FCM 시크릿이 없는 경우 APNs 발송은 계속되고 FCM 기기는 실패 수에만 들어갔다.
- `UNREGISTERED`는 삭제하고 `INVALID_ARGUMENT`는 보존하는 분기를 확인했다.
- 실서비스 호출 지연, CPU, 메모리, 네트워크 사용량은 측정하지 않았다.

## 해석

발송 동시성 상한은 기존 20개를 두 전송에 공통으로 적용한다. 실제 부하와 기기 수신 시간은 미측정이며, Firebase 설정 및 Android 호스트 연결 후 계측한다.

## 결론과 후속

로컬 계약과 SQL 경로는 통과했다. 실제 기기 수신과 전송 지연은 후속 Android 호스트 검증에 남긴다.
