# Android 접근성 텍스트 노출 — API 35 에뮬레이터 — 01

## 실행 조건

- 측정 일시: 2026-10-01 KST.
- 상태: 미측정 — 렌더링 시간·프레임·메모리 캡처를 수행하지 않았다.
- 기능 PR: https://github.com/libitums/FE/pull/199.
- 대상 commit: `7d9e739f` 이후 접근성 텍스트 변경.
- 기기: Android 15 API 35 ARM 에뮬레이터, 390×844·160 dpi 및 320×640·160 dpi.
- OS: Android 15.
- Lynx SDK: 4.0.1.
- 빌드: Debug APK와 로컬 미리보기 번들, 번들 포함 APK.
- 실행 회차: 01.

## 시나리오

- 전제: 앱 상태를 지우고 온보딩 첫 화면을 연다.
- 단계: 접근성 클릭으로 온보딩을 지나 로그인 화면의 텍스트·약관 링크 노드를 읽고, 모의 소셜 콜백 뒤 오류 문구 노드를 확인한다.
- 관찰 구간: 첫 화면부터 로그인 오류 화면까지.

## 분석 결과

- 수정 전 로그인 제목·설명·약관 문구 및 링크는 Android 접근성 트리에 없었다.
- 수정 후 API 35 계측 1건에서 온보딩 진행 상태·제목, 로그인 제목·설명·소셜 버튼·약관 문구·링크의 노출 순서를 확인했다. 약관 링크에는 `ACTION_CLICK`이 있다.
- Maestro 호스트 1건, 소셜 로그인 3건, 작은 화면 2건이 통과했다. 모의 소셜 콜백 뒤 오류 문구도 접근성 노드로 확인했다.
- 텍스트 노드 분리로 사라진 약관 링크 사이 시각적 간격을 CSS로 복구하고 기준 이미지와 비교했다.
- 운영 설정의 모바일 Lynx 번들은 1,408,428 bytes로 1,409,000 bytes 예산 안에 있다.
- 렌더링 시간·프레임·메모리 수치는 수집하지 않았다.

## 해석

Android 접근성 트리의 이름·순서·클릭 동작은 확인됐다. 성능 수치가 미측정이므로
추가된 네이티브 텍스트 노드의 렌더링 비용은 판정하지 않는다. 실제 TalkBack의
낭독과 초점 이동도 이 계측으로 확인할 수 없다.

## 결론과 후속

TalkBack이 설치된 기기에서 온보딩과 로그인 화면의 낭독·초점 이동·약관 링크 실행을
확인한다. 현재 AOSP 에뮬레이터에는 TalkBack이 없고 Google Play 이미지 설치에는
SDK 라이선스 동의가 필요하다.
