# iOS 호스트 루트 뷰 배경을 브랜드 주황으로 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 호스트 한 줄. 렌더링 · 메모리 캡처를 돌리지 않았다. iOS 호스트 `ViewController.viewDidLoad`의 루트 뷰 배경색 한 줄(`.white` → `#F46B18`)만 바뀌고 JS 번들 · 이미지 · 음원 · 의존성은 손대지 않았다.
- 기능 PR: 콜드 스타트에서 런치 스토리보드(주황)와 Lynx 스플래시(주황) 사이에 끼던 흰 프레임을 없앤다([ADR-0049](../../adr/0049-android-launch-appearance.md) 적용 기록 ⟨2026-10-28 — iOS⟩)
- 대상 commit: `7ce9c0ee`(main, Android versionCode 8) 위의 작업 트리 — 이 보고서와 같은 PR
- 비교 기준 commit: `7ce9c0ee` — JS 쪽 변경이 없어 번들 산출물이 같다
- 기기: 측정 기기 없음 — 화면 확인은 iPhone 실기에서 사용자가 한다
- OS: 해당 없음(호스트 코드 변경, 미실행)
- Lynx SDK: 4.0.1
- 빌드: `pnpm build` 산출 `apps/mobile/dist/main.lynx.bundle`(CI 설정, `.env.local` 없음)은 바뀌지 않는다. iOS 호스트는 `xcrun swiftc -parse`로 구문만 확인했다
- 측정 일시: 2026-10-28

## 시나리오

- 콜드 스타트: 앱 아이콘을 눌러 런치 스토리보드 → 호스트 루트 뷰 → Lynx 스플래시 첫 프레임까지의 구간. 변경 전에는 가운데 구간이 흰색이었다.

## 이 변경이 무엇을 건드렸나

- `apps/ios/Host/ViewController.swift`: 루트 뷰 배경색을 `.white`에서 브랜드 주황 `#F46B18`(디자인 토큰 `--libitum-color-brand-primary`의 사본, Android 창 배경과 같은 값)로 바꿨다. LynxView는 그 위에 전체 화면으로 서므로 Lynx가 그린 뒤에는 이 색이 보이지 않는다.
- 번들 로드 시점 · 모듈 등록 · 레이아웃 · globalProps 전송은 바뀌지 않았다.

## 분석 결과

| 번들 | 크기 |
| --- | ---: |
| 기준 commit `7ce9c0ee` — CI 설정 | 변경 없음(JS 미변경) |
| 이 변경 — CI 설정 | 같음 |

- 번들 상한(3,080,000)과 산출물은 그대로다.
- 호스트가 Lynx 첫 프레임 전에 보이는 색만 바뀌었고, 첫 프레임까지의 시간은 재지 않았다 — 이 변경이 그 시간을 바꾼다고 볼 근거는 없다.

## 제한 사항

- 미측정이다 — 실기 · 시뮬레이터에서 콜드 스타트 영상을 찍어 흰 프레임이 사라졌는지 확인하지 않았고, 이 보고서는 성능 통과의 증거가 아니다. 첫 프레임까지의 시간은 실기 측정이 필요하다.
- 번들을 읽지 못하는 실패 경로(Debug 빌드가 `localhost:3000`을 못 찾을 때)는 이제 흰 화면이 아니라 글자 없는 주황 한 면이 남는다 — Android(ADR-0049 D6)와 같은 대가이고, 확인하지 않았다.

## 결론과 후속

- 콜드 스타트의 흰 프레임이 사라졌는지는 실기에서 사용자가 확인한다.
