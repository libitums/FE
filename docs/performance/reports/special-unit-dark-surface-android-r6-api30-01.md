## 이 변경이 무엇을 건드렸나

- 바뀌지 않은 것: 레이아웃 · 상자 수 · 이미지 · 애니메이션. CSS 색 값과 클래스 하나만 바뀌어 렌더 트리의 노드 수와 그리기 단계는 같다고 본다(측정하지 않았다).

## 해석

- 두 화자의 패널은 기기에서 같은 어두운 반투명 면과 같은 글자 색으로 그려지고, 내 대사는 위치(오른쪽으로 24 dp)와 화자 줄 오른쪽의 `Me` · 이니셜로만 갈린다 — 계약대로다.
- 렌더된 면이 토큰으로 계산한 합성색보다 밝다(비주얼 노벨 95% rgb(64,64,62), 전화 rgb(62,65,69) — 이론값은 흰 배경 위에서도 약 rgb(49,51,54)). 실효 불투명도로 치면 약 0.84다. 원인(에뮬레이터 합성 · 색 공간 · Lynx의 알파 처리)은 이 회차로 가를 수 없어서, 대비는 렌더값과 이론값을 둘 다 적었다.
- 큰 글자(대사 · 이름 · 답장 문장)는 렌더값으로도 모두 9:1 이상이다. 전화의 보조 줄(gray-400)도 8:1 이상이다.
- **비주얼 노벨의 로마자 · 번역 줄은 렌더 중앙값 4.52, 사진이 밝은 자리(95%)에서 3.76이다** — 본문 크기 글자의 AA 4.5:1 경계에 걸리거나 그 밑이다. 이 색은 상대 대사가 원래 쓰던 색이고 이번 변경은 내 대사를 그쪽에 맞췄을 뿐이다(전에는 흰 면 위 gray-700). 이 변경의 결함이라기보다 상대 대사부터 있던 대비 한계가 내 대사로 넓어진 것이다.
- 한계: 단일 회차 · 에뮬레이터 한 대 · 글자 배율 1.0 · 배경 사진의 한 장면(카페 앞)만 봤다. 다른 장면 · 다른 밝기의 배경, 큰 글자, 실제 기기 화면, TalkBack은 판정할 수 없다. 런타임 성능 값이 없으므로 이 기록은 성능 기준선이나 회귀 통과의 증거가 아니다.

## Trace 후속 확인

- fluency: 해당 없음 — 장면 전환 · 타자기 효과의 프레임은 측정하지 않았다(화면 전환은 눈으로 정상).
- memory: 해당 없음 — 수집하지 않았다.
- NativeModule: 해당 없음 — 관찰 구간에서 이 변경과 관련된 호출이 없다.

## 결론과 후속

- 결론: AVD `R6_API30`의 Debug 빌드에서 비주얼 노벨 내 대사 패널과 전화 답장 버튼이 어두운 반투명 면 · 흰 글자로 그려지고, 내 대사는 오른쪽 배치 · 이름 오른쪽 정렬을 유지하며, 답장 버튼을 누르면 다음 대사로 넘어간다. 큰 글자 대비는 렌더값으로 9:1 이상이다.
- 후속: 비주얼 노벨 로마자 · 번역 줄(#979CA4)의 대비가 밝은 배경 자리에서 4.5:1 밑으로 내려간다 — 두 화자 공통의 색이라 별도로 판단할 일이다(이번 변경 범위 밖). 렌더된 면이 토큰 합성보다 밝은 원인은 iOS 시뮬레이터 같은 장면과 견주면 갈린다.
