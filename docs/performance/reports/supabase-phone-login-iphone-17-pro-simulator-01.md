## 이 변경이 무엇을 건드렸나

- 새 모듈 넷(`lib/api-client.ts` · `auth-session.ts` · `auth-failure.ts` · `supabase-config.ts`) —
  Supabase Auth REST 세 호출, 세션 직렬화, 실패 문구.
- 로그인 · 코드 검증 화면의 요청 중 · 실패 상태, 코드 칸 넷에서 여섯으로.
- 스플래시 뒤 한 번의 네트워크 왕복(세션 갱신) — 전화번호로 로그인한 설치에서만.

## 해석

- **미측정 기록입니다.** 화면 전환 비용은 판정할 수 없습니다.
- 재실행 시 스플래시가 세션 갱신 응답까지 서 있습니다. 그 왕복 시간(네트워크 · 서버)은 이 기록의
  범위 밖이고, 제한 시간은 10초(`authRequestTimeoutMs`)입니다.
- 새 서드파티 의존은 0건입니다(`supabase-js`를 쓰지 않았습니다).
