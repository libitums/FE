# Android 오디오 재생 호스트 성능 기록

## 실행 조건

- 상태: 부분 측정 — APK 크기와 자산 크기를 기록했고 CPU·메모리·재생 지연은 미측정.
- 대상 commit: `28cf4ea0` (`origin/main`) 기준 `feat/android-audio-playback` 작업 트리.
- 기기: Android 15 API 35 ARM 에뮬레이터, 390×844·160 dpi.
- OS: Android 15.
- Lynx SDK: 4.0.1.
- 빌드: Debug APK, 로컬 미리보기 Lynx 번들.
- 실행 회차: 01.

## 시나리오

모의 로그인 후 튜토리얼 듣기 화면에 진입해 자동 재생을 기다리고, 다시듣기를 두 번
누른 다음 학습을 떠난다. 계측 테스트는 자산을 직접 열고 실제 `MediaPlayer`의
완료·대체·일시정지·중단을 확인한다.

## 분석 결과

- Android APK에 포함한 `.m4a` 자산은 21개, 압축 전 파일 합계 377,002 bytes다.
- Debug APK 크기는 62,729,363 bytes다. 이전 APK의 동일 조건 크기는 확보하지
  못해 증가분은 계산하지 않았다.
- Bundled APK는 61,316,362 bytes이고 21개 자산이 모두 압축 없이 포함됐다.
- API 35 계측 7건과 Maestro 1건이 통과했다. Maestro 로그에 자동 재생 1회,
  다시듣기 2회, 화면 이탈 중단 1회가 남았다.

## 해석

이 기록은 APK 자산과 기능 경로의 크기·동작에 한정된다. CPU·메모리·재생 시작
지연·배터리는 미측정이므로 성능 영향의 일반화나 iOS와의 속도 비교는 할 수 없다.

## 결론과 후속

번들 자산 21개가 앱에 포함되고 네이티브 재생 경로가 동작한다. 배포 후보 빌드에서
재생 시작 지연과 실제 기기 오디오 출력을 측정한다.
