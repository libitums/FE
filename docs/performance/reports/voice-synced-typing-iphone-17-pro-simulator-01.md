# 음성 길이 맞춤 타이핑 (카탈로그 컷) — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 번들만. 렌더링 · 메모리 · 네트워크 캡처를 돌리지 않았다. 받기 한 차례의 요청 수 · 다시 읽기 횟수는 통합 테스트의 관찰이고 기기 측정이 아니다.
- 기능 PR: 카탈로그 컷의 대사 타자기를 음성 길이에 맞춘다 — 버킷의 음성 정보 파일 `audio/manifest.json`(`audio-manifest-1`)을 받기 실행기 한 차례 끝에 받아 기기에 두고, 컷 뷰가 그 길이를 싣고, 화면이 글자 간격을 [35, 300] ms로 고른다. 근거 [ADR-0074](../../adr/0074-voice-synced-typing.md). 사용자 결정 2026-10-19.
- 대상 commit: 이 보고서와 같은 PR의 `feat/voice-synced-typing` 브랜치 HEAD
- 기기: 측정 기기 없음(번들 크기만) — 글 끝과 말소리 끝의 대조는 iPhone 17 Pro 시뮬레이터에서 [e2e](../../e2e/voice-synced-typing.md)로 한다
- OS: 해당 없음(번들 산출물)
- Lynx SDK: 4.0.1
- 빌드: `pnpm build` 산출 `apps/mobile/dist/main.lynx.bundle`(CI 설정 `.env.local` 없음 · 로컬 설정 두 가지), 판정은 `pnpm size:check`
- 측정 일시: 2026-10-19

## 시나리오

- 번들 크기: 이 변경과 기준선(main dac4fe6f)을 같은 설정(CI · 로컬)으로 빌드해 바이트를 비교하고 `pnpm size:check`로 판정했다.
- 런타임: 받기 한 차례에 요청이 하나 늘고(작은 JSON — 16항목 약 1.3 kB), 정보 파일이 바뀐 차례에만 콘텐츠 다시 읽기가 한 번 생긴다. 화면 쪽은 렌더마다 순수 함수 하나(글자 수 세기 · 나눗셈)가 늘 뿐이다. 이 값들은 기기에서 재지 않았다.

## 이 변경이 무엇을 건드렸나

- 새 순수 모듈 둘: 음성 정보 파일 해석 · 맞출 길이 계산(`lib/audio-manifest.ts`), 글자 간격 계산(`screens/catalog-cover/voice-reveal.ts`).
- 새 백그라운드 모듈 하나: 정보 파일 받기 한 차례와 결과 판정(`lib/audio-manifest-refresh.ts`, `background-only`).
- 결선: 콘텐츠 로더의 표 메모 · `audioTimingOf` 포트 · 컷 뷰의 `voiceSyncMs` · 받기 실행기 task 세 줄 · 컷 화면의 `intervalMs` 한 줄. 「서버에 없음」 상수를 하나로 열었다(동작 불변).
- 새 컴포넌트 · prop · 훅 · 의존성 · 미디어 · 네이티브 코드는 없다. ui-lynx `useTypewriter`는 바뀌지 않았다.

## 제한 사항

- 번들만 쟀고 렌더 · 메모리 · 네트워크는 미측정이다 — 이 수치는 성능 판정의 근거가 아니다.
- 정보 파일이 아직 버킷에 없어(공개 주소 HTTP 400) 실제 응답 크기 · 받는 시간 · 저장소 쓰기 비용은 어떤 경로로도 재지 않았다.
- 원격 스트리밍의 재생 시작 지연이 글과 소리의 어긋남에 주는 영향은 기기에서만 판정할 수 있다.

## 결론과 후속

- 정보 파일을 버킷에 올린 뒤(사용자 확인) 시뮬레이터에서 [e2e](../../e2e/voice-synced-typing.md) VTE1 ~ VTE7을 돌고, 그 회차의 요청 수 · 다시 읽기 · 컷 첫 프레임을 위 런타임 표에 채우거나 이 보고서의 02로 잰다.
