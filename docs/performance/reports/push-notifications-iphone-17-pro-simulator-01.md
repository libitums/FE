# 서버 푸시 알림 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 렌더링 · 메모리 캡처(`performance:capture`)를 돌리지 않았습니다. 번들
  크기만 재었습니다.
- 기능 PR: 서버 푸시의 권한 · 기기 등록 · 누른 알림의 목적지 이동과 발송 함수(`send-push`)를 더하는
  변경(이 보고서와 같은 PR, ADR-0034).
- 대상 commit: `feat/push-notifications`(main `609a7bc9` 위).
- 기기: iPhone 17 Pro 시뮬레이터 — 이 회차에서는 앱을 띄우지 않았습니다.
- OS: iOS 26.5
- Lynx SDK: 4.0.1
- 빌드: 번들 크기는 `pnpm build`의 `main.lynx.bundle`입니다. Release Host는 빌드하지 않았습니다.

## 시나리오

- 번들 크기: 루트 `pnpm build`로 빌드해 `apps/mobile/dist/main.lynx.bundle` 크기를 비교했습니다.
  기준 main(`609a7bc9`)은 임시 worktree에서, 이 브랜치는 작업 트리에서 `dist`를 지우고 빌드했습니다.
  dev 서버는 띄우지 않았습니다.

## 이 변경이 무엇을 건드렸나

- 부팅: 세션 갱신이 끝난 뒤 권한 조회 1회, 이미 허용이면 토큰 요청 1회와 등록 요청 1회(기다리지 않음).
- 앱 구간에 들어설 때 누른 알림 조회 1회, 전역 이벤트 구독 하나.
- 설정 항목 하나 · 여정 입장 시작에 권한 요청 1회.
- 서버 쪽(`send-push` · 마이그레이션)은 앱 번들에 들어가지 않습니다.

모바일 번들 상한(1,336,000 bytes) 안입니다. 렌더링 · 메모리 값은 **없습니다** — 재지 않았습니다.

## 해석

- **미측정 기록입니다.** 늘어난 크기는 호스트 접점 · 목적지 검증 · 결선 코드로 보이지만 소스맵으로
  나눠 보지는 않았습니다.
- 부팅의 추가 호출은 모두 화면 전환 뒤에 비동기로 돌고 기다리지 않습니다 — 첫 화면에 닿는 시간에
  들어오지 않을 것으로 보지만 근거는 없습니다.
- 새 서드파티 의존은 0건입니다. `UserNotifications`는 iOS 시스템 프레임워크입니다.

## 결론과 후속

- 번들 main 대비 +7,184 bytes, 상한 안(여유 약 12.9 kB). 렌더링 · 메모리는 미측정이며 이 기록은 성능
  판정이 아닙니다.
- 후속: 상한 여유가 12.9 kB로 줄었습니다 — 다음 기능 전에 번들 구성을 나눠 볼 필요가 있습니다.
