# B 기내 안내방송 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 기능·자산 확인, 성능 추적 없음.
- 대상 commit: `9d3ae16` 위 codex/tutorial-cabin-announcement 작업 트리.
- 기기: iPhone 17 Pro 시뮬레이터.
- OS: iOS 26.5.
- Lynx SDK: 4.0.1.
- 빌드: Rspeedy 개발 playground / Debug Host.
- 일시: 2026-09-30.

## 시나리오

상상 속 전화 후 승무원 장면에 도달하여 딩동·방송이 시작되고, 대사를 넘기거나 나갈 때 재생을 멈춥니다. 음원 종료 후 화면은 그대로 유지합니다.

## 분석 결과

- B 비교본은 5.676초이며 딩동 2초, 무음 0.22초, 처리된 방송 3.456초입니다. mono 44.1 kHz AAC 한 파일로 번들에 넣었습니다.
- 방송의 420–2600 Hz 대역 제한·약한 압축·짧은 반사는 사전 처리됐습니다. 런타임 DSP·믹싱·시퀀스 타이머는 없습니다.
- 배경 스레드 effect에서 장면 음원을 재생하고 장면 변경·언마운트에 cleanup합니다. 마지막 대사 완료와 나가기에서도 즉시 중단합니다. 완료 콜백은 진행을 바꾸지 않습니다.
- 수명주기 UI 테스트 8개와 실제 전체 여정 통합 테스트가 통과했습니다. 재생·동일 음원의 다른 장면·재렌더·종료 콜백·중단·모듈 없음 경로를 확인했습니다.

## 제한 사항

B 효과의 선택은 사용자가 했습니다. 모델은 음질·발음을 직접 청취 판정하지 않았습니다. 자동 테스트의 네이티브 모듈은 테스트 대역입니다. Android·실기·VoiceOver 낭독·성능 수치는 미측정입니다.

## 결론과 후속

- B 음원 변경만 분리한 체크아웃에서 `pnpm verify` 전체 통과: 포맷·타입·린트·전체 테스트·빌드·크기·보고서 정책.
- 프로덕션 main 번들 1348.0 kB / 1353.0 kB, 이미지 8588.3 kB / 11520.0 kB, UI 패키지 465.3 kB / 481.0 kB. 예산 변경 없음.
- Debug iOS Host 빌드 성공. 앱 안 `audio/tutorial-cabin-announcement.m4a`의 SHA-256이 원본 번들 자산과 일치합니다: `9b439e1942b24a3c677bad383a1e60aeb039b58a458c513d064ecea86a85291d`.
- AAC 디코더 메타데이터: 1채널, 44100 Hz, 5.675918초. 파일 58,165 bytes.
- iPhone 17 Pro / iOS 26.5에서 승무원 장면(1/2), 방송 길이가 지난 뒤에도 장면 유지, 탭으로 마지막 독백(2/2), 다음 탭으로 학습 맵 이동을 확인했습니다.
- 시뮬레이터 장면 표시와 자동 테스트의 재생·중단 호출을 검증했습니다. 실제 출력 음질의 청취 판정은 하지 않았습니다.

## PR #181 리뷰·충돌 해결 후속

- 최신 main의 진행 저장 기능과 이전 리뷰 수정을 통합했습니다. 기본 미리보기는 전체 여정으로 유지하고 안내방송 전용 미리보기도 보존합니다.
- 전용 미리보기는 배열 순번 대신 안내방송 audioSource가 있는 세그먼트를 찾습니다. 해당 장면이 없으면 설명이 있는 개발용 오류를 내며 타입 단언으로 검색 실패를 숨기지 않습니다.
- 음원 SHA-256과 크기가 제작 기록과 일치합니다.
- 통합 후 `pnpm verify` 전체 통과. 메인 번들 1357.8 / 1375.0 kB, 이미지 8588.3 / 11520.0 kB, UI 패키지 465.3 / 481.0 kB입니다. 크기 예산은 최신 main의 값을 사용합니다.
- 이번 후속 작업에서는 iOS Host 빌드와 네이티브 재생을 다시 확인하지 않았습니다. 위 시뮬레이터 기록은 최초 구현 당시 검증입니다.
