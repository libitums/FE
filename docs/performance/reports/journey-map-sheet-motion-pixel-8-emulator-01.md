# 여정 맵 유닛 탭 띠 · 말풍선 등장 모션 — Pixel 8 에뮬레이터 — 01

## 실행 조건

- 상태: 측정 — Android 프레임(`dumpsys gfxinfo`)과 번들 크기만. 렌더링 · 메모리 캡처(`performance:capture`)는 돌리지 않았습니다. 바뀐 구간(유닛 탭 뒤 스크롤 · 등장 · 숨쉬기)은 그 수집기가 잡지 못하는 구간입니다.
- 기능 PR: 유닛을 누르면 스크롤이 멈춘 뒤 띠 · 말풍선이 등장하고, 누른 유닛이 튀며 반짝이고, 진행 막대가 차오르며 백분율이 오르고, 시작 버튼이 세 번 숨 쉬는 변경([ADR-0070](../../adr/0070-journey-map-sheet-entrance-motion.md))
- 대상 commit: 프레임 측정은 `journey-map-scroll-unify` 브랜치 `d94ea84b`(호스트 · 번들 모두)입니다. 번들 크기는 상한 반영 commit `38cf8683`과 이 보고서를 쓴 HEAD `c55ae393`(뒤의 대기 중 탭 수정 `51b61ce6` · `2f7c3968` · `b524ef74` 포함)에서 쟀습니다. 기준은 같은 브랜치의 `98d45ac7`(번들은 자리 통일 보고서의 `b9f5c3bc`와 같습니다 — 사이 commit은 문서뿐)입니다.

## 시나리오

- 프레임(SM10 — [보상 모션 e2e](../../e2e/motion-reward.md#유닛-탭-등장-모션-2026-10-19-adr-0070)): 동작 줄이기 끔 · 튜토리얼 진행 중 계정 · 입장 뒤 맵을 손으로 270 css px 내려 화면 아래쪽(y ≈ 713)에 선 왼쪽 유닛(`Asking for directions`, 100 %)을 탭 — 스크롤 → 띠 · 말풍선 등장 → 카운트업 → 숨쉬기 세 번. 같은 조건 5회 연속.
- 회차마다 탭 약 0.3초 전에 앱 패키지에 `dumpsys gfxinfo … reset`, 탭 약 7초 뒤 `dumpsys gfxinfo`. 창은 스크롤 · 등장 · 숨쉬기 끝(띠 시작 약 5.6초 뒤)까지 담습니다.
- 참고 회차: 같은 기능 확인 중의 SM1(왼쪽 · 오른쪽 각 1회) · SM3(스크롤 없이 바로 등장) · SM7(동작 줄이기 켬)에서도 같은 방식으로 받았습니다.
- 번들 크기: 기준과 이 브랜치의 산출물을 비교했습니다.

## 이 변경이 무엇을 건드렸나

- 백그라운드: 순수 상태 기계(`journey-map-sheet-entrance.ts`) · 모션 클래스 계산(`journey-map-sheet-motion.ts`) · 훅 `useSheetEntrance`(조용함 `d4` · 상한 `d9` 타이머). 스크롤 이벤트마다 리듀서 한 번이 더 돕니다(말풍선이 열린 동안만).
- 렌더: 잎 컴포넌트 `StepSheetPercent`가 `d1`(50 ms) 간격 타이머로 12번 다시 그려집니다 — 프레임마다 setState나 main thread 스크립트는 쓰지 않았습니다. 그 밖의 움직임은 전부 CSS keyframe(transform · opacity)입니다.
- DOM: 등장 동안 view가 잠깐 는다 — 노드 후광 1 · 조각 8, 띠 빛 1, 숨쉬기 층 1. 래퍼 다섯이 모든 노드 · 말풍선에 늘 섭니다.
- 새 이미지 · 음원 · 의존성은 없습니다.

## 해석

- 이 기록은 **기능 PR의 관찰 한 번**이며 기준값이 아닙니다. 변경 전(등장 모션 없음) 같은 시나리오의 `gfxinfo`를 받지 않아, Janky 1 ~ 2 %가 이 모션 몫인지 스크롤 · 에뮬레이터 몫인지 가를 근거가 없습니다.
- 에뮬레이터의 프레임은 실기와 다릅니다. 실기 · iOS의 프레임은 미측정이고, 이 값을 일반화하지 않습니다.
- `gfxinfo` 창은 탭 앞 약 0.3초부터 7초 남짓이라 등장(약 1.2초)보다 넓습니다 — 숨쉬기 · 정지 구간이 비율을 낮춥니다. 등장 구간만의 비율은 따로 재지 않았습니다.
- 메모리 · 렌더링 entry · 카운트업 12번 렌더의 스레드 비용은 미측정입니다. SM3의 200 ms 프레임 하나는 한 번뿐이라 원인을 판정할 수 없습니다.
- 「눈에 띄는 끊김 없음」은 에이전트가 녹화를 프레임 단위로 본 판정이고 사람의 체감 확인은 아직 필요합니다.

## 결론과 후속

- Android 에뮬레이터에서 등장 동안 녹화 공백 > 50 ms 없음, `gfxinfo` Janky 0.93 ~ 1.85 %(5회)를 기록했습니다. 성능 판정이 아니라 관찰 기록입니다.
- main 번들이 약 23.0 kB 늘었습니다(새 순수 모듈 둘 · 훅 · 컴포넌트 둘 · 모션 CSS 둘 · 결선). 상한은 실측만큼 올렸습니다.
- 후속: (1) 변경 전 commit에서 같은 SM10 시나리오의 `gfxinfo`를 받아 비교, (2) iOS 시뮬레이터 · 실기 회차, (3) 수집기가 탭 뒤 구간을 잡게 되면 렌더링 · 메모리를 다시 잽니다.
