  `JourneyMapItemNode` 추출(이동 — 순증 작음), 머리 카드 슬롯의 줄 자리 · 카드 높이 재기, 트로피 칩 숨김, 문구 넷.

- ui-lynx: `LearningUnit` 「확인 중」(계약 행 · 면 규칙 · 눌림 제외) · `EpisodeHeader` 「진행 모름」(자리 막대 · 진행 줄 최소 높이 · 숫자 색).
- 새 이미지 · 음원 · 의존성은 없습니다(`package.json` · 잠금 파일 변화 0).

- 중간 단계의 항목별 몫(로딩 줄 컴포넌트 약 +5.4 kB · 그 CSS 약 +3.8 kB 등)은 그 시점의 기록이다 — 최종 상태를 항목별로 다시 나누지 않았다.
- 이미지: `static/image` 8,688,181 bytes — 기준과 같습니다.
- 상한 변경은 **사용자 사전 승인**(실측 기능 증가면 실측으로 올리고 사후 보고) 범위다.

## 결론과 후속

- 번들 증가는 로딩 줄과 그 CSS가 두 스레드에 실린 몫이 가장 크고, 저장본 · 동기화 · 상태 기계는 백그라운드에 실렸습니다. 상한은 사용자 사전 승인으로 실측만큼 올렸습니다.
- 런타임에서 재야 할 것(미측정): 켤 때 저장본을 읽어 적용하는 비용(저장소 동기 읽기 한 번 + JSON 해석 + 합치기)과 첫 맵 그림까지의 시간, 응답 뒤 합치기로 노드가 다시 그려지는 비용,
  로딩 줄 등장 · 회전의 프레임. `performance:capture`로 잽니다.
- 회전 고리가 Button 안 스피너와 두 벌입니다. 셋째 사용처가 생기면 ui-lynx로 올려 한 벌을 걷습니다(ADR-0062 재검토 조건 3).

## 제한 사항

- 빌드 표본은 2회(구현 단계 · 문서 단계, 서로 다른 commit)이고 렌더링 · 메모리 · 첫 그림 시간 · 프레임은 미측정입니다. 이 기록은 기준값이 아니며 성능 판정을 하지 못합니다.
- 항목별 몫은 구현 단계가 나눠 잰 근사치이고 문서 단계는 다시 나누지 않았습니다.
- 시뮬레이터 확인 회차는 상태를 강제로 돌린 임시 빌드라 실제 망 지연 · 실제 저장소 읽기의 체감은 보지 못했습니다.
