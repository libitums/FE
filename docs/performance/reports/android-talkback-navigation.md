# Android TalkBack 탐색 접근성 속성

## 실행 조건

- 상태: 미측정 — 렌더링 시간·프레임·메모리 수치는 수집하지 않았다.
- 대상 commit: `feat/android-talkback-accessibility` 변경.
- 기기: Android 15 API 35 Google Play ARM 에뮬레이터, 390×844·160 dpi.
- OS: Android 15.
- Lynx SDK: 4.0.1.
- 빌드: 모의 인증 설정의 Debug APK와 로컬 미리보기 번들.

## 시나리오

TalkBack을 켜고 온보딩 첫 화면에서 초점·진행 표시를 살폈다. 하단 탐색 항목과
설정 셀에 네이티브 접근성 View 및 클릭 동작을 추가하고 계약·UI 테스트를 실행했다.

## 분석 결과

- 온보딩의 중복 진행 이름을 없애 `Step 1 of 3`이 Android 접근성 트리에 나타났다.
- UI 단위 테스트에서 활성 하단 탐색·설정 항목에는 접근성 탭이 있고 비활성 항목에는
  없음을 확인했다. 설정 제목에는 Android 헤딩 속성을 추가했다.
- 모의 인증 설정의 모바일 Lynx 번들은 1,409,025 bytes였다. 직전 보고된 운영 설정
  번들 1,408,482 bytes와 설정이 달라 정확한 증분 비교로 쓰지 않는다.
- TalkBack 활성 Maestro 흐름은 첫 대사까지 진행한 뒤 `Next` 노드를 찾지 못했다.
- 렌더링 시간·프레임·메모리 수치는 미측정이다.

## 해석

접근성 속성과 중복 이름 수정의 정적 동작은 확인됐다. TalkBack 활성 상태에서
온보딩 전체 흐름이 실패했으므로 사용자 음성 경험은 판정할 수 없다. 성능 수치도
미측정이므로 추가 네이티브 View의 렌더링 비용을 판단할 근거가 없다.

## 결론과 후속

TalkBack 사용 중 Lynx `Next` 노드가 접근성 계층에서 사라지는 원인을 해결하고
동일 Maestro 흐름을 다시 통과시킨다. 실제 음성 낭독과 로그인 후 탐색도 기기에서
확인한다.
