# 메인 스레드에는 영어 문구표만(ADR-0031 D8) — 01

## 실행 조건

- 상태: 미측정 — 렌더링 · 메모리 · 시작 시간 캡처를 돌리지 않았습니다. 번들 크기와 문자열 잔존만 셌습니다.
- 기능 PR: 브랜치 `perf/main-thread-english-copy`
- 대상 commit: origin/main `ff680faf` 위의 변경
- 기기: 동작 확인만 — iPhone 17 Pro 시뮬레이터 · Pixel 8 에뮬레이터
- OS: iOS 26.5 시뮬레이터 · Android 에뮬레이터
- Lynx SDK: 4.0.1
- 빌드: `.env.local` 없는 `pnpm build`. 스레드별 값은 같은 소스의 `DEBUG=rspeedy` 중간 산출물

## 시나리오

- 변경 전후 release 번들을 같은 설정으로 짓고, 크기와 일곱 언어 문구표의 문자열이 어느 스레드에 남는지 셌습니다.
- 저장 언어 vi · ja · th · my의 화면은 [UI 언어 e2e](../../e2e/ui-language.md) ME1~ME5로 봤습니다.

## 이 변경이 무엇을 건드렸나

- `uiCopyFor`가 메인 스레드에서 영어 표만 돌려주고, 표 만들기 호출에 PURE 표시가 붙었습니다. 문구 값은 그대로입니다.

main에 남은 영어 밖 문구의 글자는 함수 문구 조각까지 합쳐 최대 24,404 B(UTF-8)입니다. 영어 표가 참조하는 다국어
객체(요금제 · 상점 등)와, 다른 데이터에 같은 글자가 있어 우연히 맞은 것을 함께 센 상한입니다. 객체의 키 · 코드 몫은
들어 있지 않습니다.

## 해석

- **미측정 기록입니다.** 측정 한계: 시작 시간 · 메모리를 재지 않아 빨라졌는지는 판정하지 않습니다.
- 함수 문구는 소스에서 뽑은 글자 조각으로 세어, 중첩 템플릿 몇 개는 전후 모두 찾지 못했습니다. background의 파일
  내용이 전후 같아 빠진 문구는 없습니다.

## 결론과 후속

- 번들이 400,891 B 줄었습니다. 천장은 바꾸지 않았습니다.
- 후속 후보(이번 범위 밖): 영어 표가 끌고 오는 다국어 객체를 언어별로 나누기, 저사양 Android 첫 실행 시간 측정.
