# 이야기형 최종 복습 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건

- 상태: 미측정 — 화면 검토 및 자동 동작 검증.
- 대상 commit: `3f441f8` 위 codex/tutorial-final-story 작업 트리.
- 기기: iPhone 17 Pro 시뮬레이터.
- OS: iOS 26.5.
- Lynx SDK: 4.0.1.
- 빌드: Rspeedy 개발 playground / 기존 Debug Host.
- 일시: 2026-09-30.

## 시나리오

기내 도입 → 상상 속 카페의 3문항 → 통과 후 공항 도착 엔딩 → 결과 확인을 검증합니다. 실패 시 도움말·재도전, 엔딩 중 이탈, 누락 결과, 연속 탭도 검증합니다.

## 분석 결과

- 실제 대본으로 도입·2/3 통과·재도전·엔딩 완료 경계를 자동 검증했습니다.
- 지정된 iPhone 17 Pro 시뮬레이터에서 기내 도입 첫 화면을 확인했습니다. Almost There 제목, 새 기내 배경, 기존 반투명 다이얼로그, 한영 대사와 하단 safe area가 정상 표시됩니다. 캡처: `final-story-introduction.png`(로컬 임시 캡처).
- 문제 첫 화면과 공항 도착 장면을 각각 직접 진입시켜 시각 검토했습니다. 상황 안내·세 선택지·로마자·대화창이 겹치거나 잘리지 않고, 도착 배경은 하단 safe area까지 이어집니다. 검토용 시작 상태 변경은 복원했으며 사용자가 여는 미리보기는 기내 도입부터 시작합니다. 캡처: `final-story-test-screen.png`, `final-story-arrival-screen.png`(로컬 임시 캡처).
- 기존 범용 최종 시험·통화 시험 회귀를 유지합니다.
- 후속 수정: 미리보기에서도 엔딩 뒤 LessonCompleteScreen을 표시하고 Check 이후에만 맵으로 돌아가도록 연결했습니다. 만점·2개 정답 흐름을 별도 미리보기 테스트로 검증했고, 시뮬레이터에 만점 결과를 직접 띄워 제목·보상·Check 배치를 확인했습니다(`tutorial-perfect-result.png`, 로컬 임시 캡처). 검토용 초기 결과는 복원했습니다.
- 워크스페이스 Vitest 3,204개, 별도 Node 정책 테스트, 포맷·타입·린트·빌드·용량·성능 보고서 정책 검사를 통과했습니다.
- 이미지 3장을 810×1440 JPEG로 저장했습니다. 합계 712,473 bytes이며 최종 빌드의 정적 이미지 전체는 11,404,576 bytes입니다. 기존 상한에 추가 자산 용량만 반영해 11,520,000 bytes로 조정했습니다.
- 프로덕션 main.lynx.bundle 1,328,005 bytes, ui-lynx dist 464,871 bytes로 기존 JS/UI 예산을 통과합니다.
- 성능 수치는 미측정이며 프레임·메모리 개선 근거가 아닙니다.
- 리뷰 반영: JSX에 쓰지 않고 엔딩 완료 콜백으로 전달하는 시험 결과를 state 대신 ref에 보관합니다. 재도전 후 현재 시도 결과 전달·연속 완료 방지·엔딩 중 이탈·결과 화면 연결은 기존 UI/App 테스트로 검증합니다. 기존 코드의 레이스나 렌더 횟수 감소를 실측한 변경은 아닙니다.

## 제한 사항

성능은 미측정입니다. Android·실제 VoiceOver 낭독은 확인하지 않았습니다. 시뮬레이터에서 전체 경로를 수동 탭으로 진행하지 않았으며, 시험·재도전·엔딩 완료는 자동 App/UI 테스트로 검증했습니다. 시뮬레이터의 시각 검토와 자동 App 테스트는 서로 다른 검증 범위입니다.

## 결론과 후속
