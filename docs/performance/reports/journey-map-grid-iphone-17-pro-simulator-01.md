  훅 둘(자동 스크롤 · 열 수), globalProps 읽기, 말풍선 꼬리 치우침과 머리 카드 회피 배치, 선택 측정 함수, 줄 CSS 한 파일과 기존 CSS 몇 줄.

## 결론과 후속

- 번들 증가는 순수 모듈 넷 · 줄/칸 · 튜토리얼 구획 컴포넌트 · 훅 둘 · CSS가 두 스레드에 실린 몫입니다. 상한은 사용자 결정으로 실측에 맞춰 올렸고, 여유가 약 1.1 kB라 다음 화면 기능은
  다시 상한을 넘을 가능성이 큽니다.
- 런타임에서 재야 할 것(미측정): 맵 진입 → 자동 스크롤 시작까지의 시간(진행이 먼저 있을 때 · 늦게 닿을 때), 긴 맵(카탈로그 셋을 지나 에피소드 3)에서 이동 중 머리 카드 다시
  그리기 횟수와 프레임, 도착 뒤 측정 · 보정이 더하는 한 번의 그리기 비용. iOS 시뮬레이터에서 로그인한 뒤 `performance:capture`로 잽니다.
- Android 에뮬레이터 관찰(성능 측정이 아니라 e2e 기록): 부드러운 이동은 거리와 무관하게 약 0.23 ~ 0.27초였고(1,575dp에 스크롤 이벤트 15개, 3,673dp에 14개), 머리 카드는 에피소드 3까지
  가는 동안 0 → 2 → 3으로 바뀌는 것이 녹화 프레임에 잡혔습니다. 프레임 시간 · 떨어진 프레임은 재지 않았습니다.
- 병합 직전에 main이 앞서 있으면 그 위에서 번들을 다시 재야 합니다.
