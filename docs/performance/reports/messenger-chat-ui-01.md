## 시나리오

- 번들 크기: 키보드 PR 기준(`4557a770`)과 같은 설정으로 비교했다. 통합 단계(기기 회차 전) 실측도 함께 적는다.
- 런타임: 미측정. 메신저 탭을 열 때 목록 한 장, 방을 열 때 로그 · 독 · 학습 키보드가 서고, 가짜 출처가 보내기마다 타이머 둘(입력 중 · 답장), 사진 · 음성 요청마다 하나를 건다. 네트워크 요청 · 네이티브 호출 · 저장은 늘지 않는다.

## 이 변경이 무엇을 건드렸나

- 새 폴더 둘: `components/chat/`(공용 부품 일곱 — 학습 메신저가 함께 쓴다) · `screens/messenger-chat/`(목록 · 방 · 겹침 · 순수 모듈 · 픽스처). 새 결선 `app/messenger-chat-wiring.ts` · `app/render-messenger-chat.tsx`, 5개 언어 `ui-copy-*-chat.ts`.
- 바뀐 것: nav(`Tab` · `Screen`) · 셸 모드 · 바 항목 넷과 앱 CSS 덮어쓰기 · `MessengerKeyboard`의 선택 prop `height`.
- 의존성 · 이미지 · 음원 · ui-lynx · 호스트 · 권한 변경 없음. 아바타는 번들에 이미 있는 그림만 재사용한다.

## 제한 사항

- 번들만 쟀고 렌더 성능은 미측정이다 — 이 수치는 성능 통과의 근거가 아니다. 특히 저사양 기기에서 방을 열 때 · 키보드를 바꿀 때 · 메시지 20개 이상 쌓인 로그의 스크롤은 [기기 확인](../../e2e/messenger-chat-ui.md) MC-E3 · E4에서 눈으로만 본다.
- 1단계 데이터는 가짜 출처라 서버 왕복 지연이 없다. 2단계(서버)의 지연 예산은 ADR-0102 쪽 측정이 진다.

## 결론과 후속

- 픽스처(약 36 kB)는 2단계에서 서버 출처로 바뀌면 빠진다.
