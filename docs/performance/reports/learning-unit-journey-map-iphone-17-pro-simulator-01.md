## 시나리오

- 전제: 저장된 로그인 토큰이 없어 스플래시 뒤 온보딩으로 갑니다.
- 단계: `performance:capture -- start`로 Host를 실행하고, 온보딩 세 스텝 → 구글 로그인 →
  언어 선택 Continue → 여정 입장 Start로 여정 맵에 닿습니다. `report`로 보고하고 `stop`으로
  종료한 뒤, 같은 절차를 두 번 더 반복합니다.
- 관찰 구간: native `loadBundle` 시작부터 첫 paint까지, 그리고 `libitum:navigation:journey`
  timing flag가 붙은 update pipeline입니다. **여정 맵이 서는 전환이므로 이 PR이 바꾼 화면을
  지납니다.**

## 이 변경이 무엇을 건드렸나

여정 맵 스텝의 표식을 앱이 직접 그리던 원·아이콘에서 ui-lynx `LearningUnit`으로 옮겼습니다.

- 상태 어휘를 옮깁니다 — `done` → `clear`, `current` → `active`, `locked` → `default`.
- 표식이 커졌습니다. 64px 원 하나에서 100px 링 + 72px 면 + 48px 아이콘이 됐습니다. 노드마다 링 SVG가
  하나씩 더 생깁니다.
- 접근성 요소와 탭 대상이 바깥 상자에서 `LearningUnit`으로 내려갔습니다. 앱 쪽 상자는 표식과
  제목을 세로로 묶기만 합니다.
- `LearningUnit` 계약도 함께 고쳤습니다 — 상태를 `accessibility-value`가 아니라 이름 뒤
  접미사로 내고(ADR-0016 D3), 한 화면에 유닛이 여럿 설 때 가려낼 `id`를 받습니다.

## 분석 결과

여정 맵 전환(`libitum:navigation:journey`)의 `pipeline`입니다. 직전 PR(#114)의 같은 절차
측정을 나란히 둡니다 — 표식을 옮기기 전 값입니다.

| 조건                  | 1회차(빌드 직후) | 2회차     | 3회차     |
| --------------------- | ---------------- | --------- | --------- |
| 이 PR (LearningUnit)  | 101.553 ms       | 48.032 ms | 46.668 ms |
| 직전 (앱이 직접 그림) | 85.778 ms        | 45.714 ms | 46.897 ms |

**안정 구간이 겹칩니다** — 46.7~~48.0 ms 대 45.7~~46.9 ms. 노드마다 링 SVG가 하나씩 늘고
표식이 커졌는데도 전환 비용이 자리를 지켰습니다.

1회차는 101.6 ms로 직전(85.8 ms)보다 큽니다. 다만 **빌드 직후 첫 회차가 두 배 느린 것은 이미
두 조건에서 재현된 패턴이고**(직전 보고서의 절대 배치 비교), 그 회차의 흔들림 폭을 우리는
아직 모릅니다. 이 한 값으로 느려졌다고 말할 수 없습니다.

## 해석

**표식을 옮긴 것이 전환을 느리게 했다고 말할 수 없습니다.** 안정 구간 두 회차가 직전과 겹치고,
1회차 차이는 그 회차의 알려진 흔들림 안에 있는지조차 가릴 자료가 없습니다.

**반대로 빨라졌다고도 말할 수 없습니다.** 회차가 셋뿐이고, 전환 pipeline의 흔들림 폭을 재 둔
적이 없다는 것은 직전 보고서가 적은 그대로입니다.

`layout` 몫이 19.4~~21.4 ms로 직전(19.4~~20.2 ms)과 같은 자리입니다. 링 SVG가 스텝마다
하나씩 늘었으므로 layout이 커질 자리였는데 그러지 않았습니다 — 다만 **왜 그런지는 이 자료가
말해 주지 않습니다.** 절대값이 같다는 관측뿐입니다.

메모리는 이번 회차에서 따로 견주지 않았습니다. 앞선 보고서가 적은 `after-initial-load`의
`viewBytes` 이상이 아직 설명되지 않은 채라, 같은 화면끼리의 비교가 아니면 증거가 되지
않는다는 제약도 그대로입니다.

## 결론과 후속

- 여정 맵 전환 비용은 표식을 ui-lynx로 옮긴 뒤에도 같은 자리입니다. 이 PR이 전환을 눈에 띄게
  무겁게 만들지 않았습니다.
- `libitum:navigation:journey` 수집이 그대로 돕니다 — 스텝 표식이 바뀌어도 timing flag가 붙는
  자리(바텀 네비게이션)는 건드리지 않았습니다.
- **전환 pipeline의 흔들림 폭은 여전히 재야 할 자리입니다.** 직전 보고서가 남긴 후속이 그대로
  남아 있고, 이 보고서도 같은 이유로 1회차를 판정하지 못했습니다.
