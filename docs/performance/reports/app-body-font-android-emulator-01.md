# 본문 글꼴 Duru Sans · 로마자 Duru Roman — Android 첫 화면 시간 — 01

## 실행 조건

- 상태: 부분 측정 — Android 에뮬레이터의 첫 화면 시간(`am start -W`)만 쟀습니다. 렌더링 · 메모리 캡처(`performance:capture`)와 실기 측정은 돌리지 않았습니다.
- 기능 PR: 본문 글꼴(Pretendard JP 서브셋 `Duru Sans`, 4,028,140 bytes)과 로마자 글꼴(Inter Italic 서브셋 `Duru Roman`, 89,916 bytes)을 호스트에 넣고, Android 배포 빌드가 앱 글꼴을 그리도록 일반 자원 가져오기를 등록하는 변경(ADR-0107, 이 보고서와 같은 PR)
- 대상 commit: `main`(c3afcf8a) 위의 `feat/app-font-pretendard`
- 기기: Android 에뮬레이터 `R6_API30`(API 30) — 시간 측정, `Pixel_8`(API 37) — 화면 확인
- OS: Android 11 · Android 17(에뮬레이터)
- Lynx SDK: 4.0.1
- 빌드: `assembleBundled`(배포 설정 + 디버그 서명). 비교 빌드는 같은 소스에서 `DuruSans.ttf` · `DuruRoman.ttf` 두 자산만 뺀 것

## 시나리오

- 첫 실행: 앱을 지우고 설치한 직후 `am start -W` — `AppFonts.install`이 글꼴을 `files/fonts/`로 복사하는 비용이 들어갑니다.
- 두 번째 실행: `force-stop` 뒤 `am start -W` — 크기가 같아 복사하지 않습니다.
- 각 5회.

## 해석

- 첫 실행의 복사 비용은 에뮬레이터에서 중앙값 약 5 ms로, 실행마다의 흔들림(±40 ms) 안입니다. 두 번째 실행부터는 차이가 없습니다.
- 에뮬레이터는 Mac 디스크 위라 빠릅니다 — 저장 장치가 느린 저사양 실기에서는 첫 실행 복사가 더 걸릴 수 있습니다. 재지 않았습니다.
- 측정 한계: 에뮬레이터 한 대 · 5회라 실기로 일반화할 수 없고, 렌더링 비용(글꼴 해석 · 첫 그리기)은 재지 않아 판정할 수 없습니다.

## 결론과 후속

- 이 기록은 첫 화면 시간에 한정한 측정이며 렌더링 · 메모리 판정이 아닙니다.
- 후속: 저사양 실기(기기 성능 목록의 Android 하단)에서 설치 직후 첫 실행 시간, iOS 첫 화면 시간.
