## 시나리오
첫 유닛에서 기내→상상 골목으로 진입하고, 민서 통화 이후 상상 카페→기내로 복귀합니다. 같은 배경의 독백을 넘길 때 전환이 재시작되지 않고 타이핑 완성·다음 진행·방송 중단이 기존대로 동작하는지 확인합니다.

## 분석 결과
- 상상 진입 1900ms: 기내 확대 → 따뜻한 빛 → 골목 정착. 현실 복귀 1600ms: 카페가 물러나고 빛이 걷히며 기내가 정지합니다. 기존 이미지와 한 개의 그라디언트 장식을 사용합니다.
- opacity/transform만 추가합니다. 필터, 레이아웃 애니메이션, JS 프레임 루프, 네이티브 의존성은 추가하지 않습니다.
- 완료 이벤트는 Lynx의 비버블링 이벤트에 맞춰 실제 베일에서 받고 animation_name을 확인합니다. 전환과 출발 배경은 이미지 key 단위로 고정하고 애니메이션은 대사 진행을 변경하지 않습니다.
- main #185의 타이핑과 방송 revealTiming(2220ms 대기/3456ms 출력)을 보존했습니다. 첫 탭은 대사 완성, 다음 탭은 장면 진행입니다.
- 프로덕션 main 번들: main #185의 1,378,744 → 1,383,452 bytes(+4,708). 상한은 실측 증가분을 반영해 1,380,000 → 1,384,000 bytes로 조정했습니다. 이미지 8688.2 / 11520.0 kB, UI 패키지 477.2 / 481.0 kB입니다. 개발 서버를 중단한 상태에서 측정했습니다.

## 제한 사항
Android·실기·VoiceOver·렌더링 성능 수치는 미측정입니다. reducedMotion은 호출자가 명시하는 옵션이며 OS 자동 감지는 추가하지 않습니다. 방송은 장면 mount, 전환은 이미지 load 후 시작하므로 둘의 프레임 단위 동기화를 보장하지 않습니다. 소리의 직접 청취 품질 평가는 하지 않았습니다.

## 결론과 후속
- 배경 UI 11개, 서사 화면·음원 UI 25개, 실제 튜토리얼 전체 여정 통합 테스트 통과.
- 최신 main 병합 후 전체 verify의 포맷·타입·린트·전체 테스트·빌드 통과. 실측 예산 반영 후 크기·보고서 게이트도 통과했습니다.
- 독립 코드 리뷰에서 수정할 문제 없음.
