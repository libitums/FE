# 상상 진입 전환 — iPhone 17 Pro 시뮬레이터 — 01

## 실행 조건
- 상태: 미측정 — 기능·시각 확인, 성능 추적 없음.
- 대상 commit: 0801512f 위 codex/tutorial-imagination-transition 작업 트리.
- 기기: iPhone 17 Pro 시뮬레이터.
- OS: iOS 26.5.
- Lynx SDK: 4.0.1.
- 빌드: Rspeedy 개발 playground / Debug Host.
- 일시: 2026-09-30.

## 시나리오
첫 유닛에서 두 기내 독백을 읽고, 상상 속 골목으로 들어갑니다. 같은 기내 그림의 재사용, 새 그림 로드 전 이전 그림 유지, 1.9초 진입 효과, 사용자 탭 진행을 확인합니다.

## 분석 결과
기존 이미지 두 장과 단일 그라디언트 장식을 겹칩니다. opacity/transform 애니메이션만 추가하며 필터, 레이아웃 애니메이션, JS 프레임 루프, 네이티브 의존성은 추가하지 않습니다. 완료 이벤트는 Lynx의 비버블링 이벤트에 맞춰 실제 베일 요소에서 받고 animation_name을 확인합니다. 애니메이션은 대사 진행을 변경하지 않습니다.

## 제한 사항
Android·실기·VoiceOver·성능 수치는 미측정입니다. reducedMotion은 호출자가 명시하는 컴포넌트 옵션이며 운영체제 설정 자동 감지는 추가하지 않습니다. 기존 동시 진행 중인 타이핑·음성 대사 연출은 이 브랜치의 범위에 포함하지 않습니다.

## 결론과 후속
- 상상 진입 배경 및 실제 첫 유닛 연결 UI 테스트 18개 통과.
- 코드 독립 리뷰에서 수정할 문제 없음.
- 시뮬레이터에서 기내 1/3 → 기내 2/3 → 골목 3/3을 확인했고, 전환 후에도 마지막 대사를 유지합니다.
- 전환 녹화의 0.2초 간격 프레임을 확인했습니다. 기내 확대 → 크림색 빛 → 골목 등장 → 빛 제거 순서가 보이고, 위·아래 안전 영역도 배경으로 이어집니다. 이후 탭으로 민서 메신저에 진입하는 것까지 확인했습니다.
- 전체 verify에서 포맷·타입·린트·전체 테스트·빌드는 통과했으나 번들 상한만 초과했습니다. #184의 main 기준 1,374,816 → 1,379,049 bytes(+4,233)이며 기존 여유는 184 bytes였습니다. 전환 코드의 실측 증가분을 반영해 상한을 1,380,000 bytes로 최소 조정했습니다. 이미지 8688.2 / 11520.0 kB, UI 패키지 465.3 / 481.0 kB로 추가 자산·의존성은 없습니다.

- 예산 조정 후 포맷·크기·성능 보고서 게이트 모두 통과했습니다. 전체 verify의 모든 검사 항목을 완료했습니다.

## 상상에서 기내로 복귀하는 전환 후속
- 민서 통화 이후 첫 기내 독백은 상상 카페를 출발 배경으로 지정합니다. 카페가 물러나고 따뜻한 베일이 걷히며 기내가 정지하는 1600ms 전환을 추가했습니다. 새 이미지·음원·의존성은 없습니다.
- 같은 배경의 다음 독백으로 빠르게 넘길 때 출발 배경과 전환 종류를 유지해 재시작/중간 소실을 막았습니다.
- 안내방송의 기존 mount 재생 및 다음 대사/나가기 때 중단을 유지합니다. 전환은 이미지 load 후 시작하므로 방송 차임과의 프레임 단위 동기화를 보장하지 않습니다.
- 실제 튜토리얼 전체 여정 통합 테스트와 음원 수명주기 테스트 10개, 배경 UI 테스트 11개 통과.
- 시뮬레이터의 기내 복귀 전용 미리보기를 녹화하고 0.2초 간격 프레임으로 카페·따뜻한 베일이 사라져 기내가 자리잡는 것을 확인했습니다. 이후 안내방송 독백이 유지됩니다. 실제 통화 화면부터의 연결은 위 전체 여정 통합 테스트로 검증했습니다.
- 전체 verify의 포맷·타입·린트·테스트·빌드 통과. 복귀 연출은 이전 커밋 대비 +1,134 bytes(1,379,049 → 1,380,183)이며 main 기준 전체 증가분은 +5,367 bytes입니다. 실제 비용을 반영해 최종 상한을 1,381,000 bytes로 조정했습니다. 이미지·UI 패키지 크기는 동일합니다.
