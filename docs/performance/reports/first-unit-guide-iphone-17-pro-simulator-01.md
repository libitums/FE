- 대상 commit: `e08f6f88` 위 첫 유닛 가이드와 알림 목업 제거 작업 트리. 네이티브 화면 확인은 `0801512f` 기반에서 수행했으며, 최신 main의 타이핑·통화 받기·장면 전환 통합은 자동 테스트로 재검증했습니다.

## 시나리오

진척 0의 여정에서 첫 유닛 강조 → 표지 Next → 스토리 안내 닫기 → 대사 세 번 진행 → 채팅 안내 닫기 → 답장 보내기 → 카페 장면 → 통화 안내 순서로 확인했습니다. 앱 통합 테스트에서는 첫 유닛 재진입·완료 후 재생과 안내 중 채팅 타이머·통화 음원의 정지를 확인했습니다.

## 분석 결과

- 기존 화면의 배치와 자산을 유지한 채 첫 유닛에 주황 툴팁과 어두운 안내 오버레이를 추가했습니다.
- 네이티브에서 안내 문구가 scrim 뒤에 가려지던 현상을 전면 레이어 순서로 수정하고 밝은 문구와 주황 화살표를 확인했습니다.
- 안내를 닫는 탭은 첫 대사를 넘기지 않으며, 같은 세션의 같은 안내는 다시 표시하지 않습니다. 첫 유닛 완료 기록이 있으면 안내를 생략합니다.
- 안내 중에는 채팅 메시지와 통화 음원·타이머가 진행되지 않습니다.
- 제품 알림 초기 목록은 비어 있습니다. 기존 알림 데이터는 이동·삭제·분석 이벤트 검증용 테스트 픽스처로만 남겼습니다.
- 프로덕션 모바일 번들은 1,400,606 bytes로 main(#186)의 1,383,452 bytes보다 17,154 bytes 증가했습니다. 가이드 상태·오버레이·툴팁·문구·진행 정지를 포함하며 이미지·음원·의존성 추가는 없습니다. 번들 상한은 1,384,000에서 1,401,000 bytes로 조정했습니다.

- 리뷰 보완: Provider의 context 값을 메모이제이션해 가이드 상태가 그대로인 경우 참조를 유지합니다.
- CI 보완: Overlay·Tooltip을 타입 검사와 Vitest에서 워크스페이스 소스로 직접 연결합니다. 기존 UI package dist가 없는 상태에서 전체 `pnpm verify`를 통과했습니다. 최종 모바일 번들은 1,402,542 bytes이며 현재 1,403,000 bytes 상한 이내입니다.

## 제한 사항

성능 수치는 미측정입니다. 개발 시뮬레이터 확인이므로 실제 기기나 Release 성능으로 일반화할 수 없습니다. Android와 VoiceOver 실제 낭독은 미확인입니다. 최신 main 통합 후 네이티브 화면 전체 흐름은 재확인하지 않았습니다. 알림 빈 상태는 자동 테스트로 확인했으며 알림 서버 공급원은 이 변경에서 추가하지 않았습니다.
