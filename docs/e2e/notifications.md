# 여정 맵 머리의 알림에서 특별 유닛과 롤플레이 목록으로 간다 — iOS Release 수동 e2e

## 판정 채널과 범위

이 문서는 여정 맵 머리의 알림 버튼에서 알림 화면을 열고, 임시 항목 넷(메신저 ·
전화 · 비주얼 노벨 · 롤플레이 목록) 각각으로 이동해 되돌아오는 흐름을 iOS Release
Host와 실기기에서 확인하는 수동 functional · Dynamic Type · VoiceOver e2e 절차다.
저장소 profile에는 `test.e2e` 명령과 runner가 없다 — **자동 E2E: not
applicable(runner/command 없음)**이며, 이 계층의 「테스트를 쓰는 행위」는 이 흐름
문서를 세우는 것 자체다(LIB-247 §6.4(d)). 아래 표는
`.agent-harness/work/lib-257/spec.md` §12.1이 정본이고 이 문서가 사본이다 — 표
항목을 여기서 더하거나 빼지 않는다.

N1–N9·D1은 시뮬레이터에서 먼저 돌 수 있다. 그러나 그 결과만으로 `e2e-red`의
`moot` 값을 주장하지 않는다. **V1–V3은 iPhone 실기 · Release · VoiceOver로 사람만
판정한다**(V4도 같은 채널로 실행하되 관찰 기록형이다 — 아래 「VoiceOver 여정
V1–V4」참고) — Simulator나 정적/UI/integration 결과로 대체하지 않는다. V가 돌지
않으면 `e2e-implementation` → `e2e-green` → `documentation` → `review`가 전부
서지 않는다(spec §12.2, [롤플레이 목록 e2e](roleplay-list.md)와 같은 사슬).

**이벤트는 이 문서의 판정 항목이 아니다**(spec §7.5, 아래 「이벤트 운영 범위」).

정확한 제품 문자열과 testid는 다음을 정본으로 삼는다. 이 문서에 없는 이름이나 ID를
현장에서 새로 만들지 않는다. 기능 계약의 요약은
[알림 스펙](../specs/notifications.md)에 있다(문서 단계가 신설한다 — 아직 없다면
`.agent-harness/work/lib-257/spec.md` §0.3 D-d · §2 · §4를 대신 참고한다).

- `apps/mobile/src/screens/notifications/notifications.contract.ts`
- `apps/mobile/src/screens/notifications/notification-items.ts`(임시 항목 넷의 정본)
- `apps/mobile/src/screens/messenger/messenger.contract.ts`
- `apps/mobile/src/screens/phone-call/phone-call.contract.ts`
- `apps/mobile/src/screens/visual-novel/visual-novel.contract.ts`
- `apps/mobile/src/screens/roleplay-list/roleplay-list.contract.ts`
- `apps/mobile/src/lib/special-unit-entry-source.ts`(나가기 라벨 `맵으로`/`목록으로`의 어휘 정본)
- `apps/mobile/src/app/navigation.ts`(`tabRootActions` — 롤플레이 알림의 `switchTab` → `backToRoot`)

## 전제

공통 전제([docs/e2e/README.md](README.md)) + **Release Host** + **완료 기록이 없는
새 앱 세션**. 각 행의 결과에는 `통과` 또는 `실패: <관찰>`만 기록하고, 추정이나
인상은 넣지 않는다 — **V4만 예외**로 `기록: <관찰 · 숫자>`를 쓴다(아래 「VoiceOver
여정 V1–V4」의 V4 지위 문단 참고, spec §12.1). 아직 돌지 않은 행은 `미실행`, 아직 채우지 않은 증거는 `미기록`으로
둔다 — 결과 값이 아니라 결과가 아직 없다는 표시다([롤플레이 목록](roleplay-list.md) ·
[전화](phone-call.md) · [메신저](messenger.md) · [비주얼 노벨](visual-novel.md)
흐름과 같은 표기).

## 실행 전 증거 고정

한 회차는 아래 값이 모두 채워진 **동일한 Release 산출물**로만 판정한다. 값이 비었거나
서로 다른 빌드에서 왔다면 N1을 시작하지 않는다. 이 흐름은 작성 시점까지 한 번도 실행된
적이 없으므로, 아래 표는 실행자가 회차마다 채운다.

| 증거 | 실행 회차 기록 |
|---|---|
| 소스 identity(커밋과 작업 트리 상태 또는 동등한 재현 식별자) | 미기록 — 실행 시 입력 |
| iOS Host.app SHA-256 | 미기록 — 실행 시 입력 |
| `main.lynx.bundle` SHA-256 | 미기록 — 실행 시 입력 |
| 실기기 모델 · iOS 버전 | 미기록 — 실행 시 입력 |
| 빌드 종류 | 미기록 — 실행 시 입력(Release여야 한다) |
| 확인자 · 확인 시각(시간대 포함) | 미기록 — 실행 시 입력 |

## 기능 · Dynamic Type 여정 N1–N9 · D1

완료 기록이 없는 새 앱 세션에서 시작한다. 아래 표는 spec §12.1 표의 사본이다 — ID ·
단계 · 관찰 · 답하는 수단 열의 문구를 여기서 고치지 않는다. `결과` 열만 이 문서가
더한다.

| ID | 단계 | 관찰(식별 가능한 요소) | 답하는 수단 | 결과 |
|---|---|---|---|---|
| N1 | 앱을 새로 띄운다 | 첫 화면 `journey-map-screen-title` = `여정 맵`. 바텀 탭이 **셋** — 좌→우 `여정` · `롤플레이` · `설정`, `여정` 선택. `홈` 탭 · 홈 화면 **0건** | 시뮬레이터 또는 실기 | 미실행 |
| N2 | 여정 맵 머리의 알림 버튼(종 아이콘 + `알림`)을 누른다 | `notifications-screen-title` = `알림`, 머리 첫 자리 나가기 `맵으로`. 바텀 탭 `여정` 선택 유지. 항목 **넷**, 순서와 문구가 §0.3 D-d 표(메시지 / 행선지). 읽음 표식 · 배지 · 새 알림 점 · 흐린 항목 **0건**(여정 맵의 알림 버튼에도 0건) | 〃 | 미실행 |
| N3 | `맵으로`를 누른다 | `여정 맵`. 알림 화면 없음 | 〃 | 미실행 |
| N4 | 알림 → `약속 확인 메시지` 알림(메신저 열기) → 나가기 | 메신저 화면, `여정` 선택 유지, 나가기 텍스트 `맵으로`. 나가기 뒤 **여정 맵**(알림 화면이 아니다) | 〃 | 미실행 |
| N5 | 알림 → 전화 알림 → 나가기 | 전화 화면(`통화 준비`), 나가기 `맵으로` → 여정 맵 | 〃 | 미실행 |
| N6 | 알림 → 비주얼 노벨 알림 → 나가기 | 비주얼 노벨 화면, 나가기 `맵으로` → 여정 맵 | 〃 | 미실행 |
| N7 | 알림 → 메신저 알림 → 끝까지(둘째 답장) → `맵으로` | 여정 맵의 메신저 항목이 **완료 상태**(여정 모드 — D-a) | 〃 | 미실행 |
| N8 | 알림 → 롤플레이 알림(롤플레이 목록 보기) → 여정 탭 | 누른 뒤 `롤플레이` 선택 · `roleplay-list-screen-title` = `롤플레이`. 여정 탭을 누르면 **알림 화면**이 서 있다(D-c) → `맵으로` → 여정 맵 | 〃 | 미실행 |
| N9 | 롤플레이 탭 → 메신저 항목(연습) → 여정 탭 → 알림 → 롤플레이 알림 | 롤플레이 **목록**이 보이고 연습 메신저 화면이 아니다(D-c `backToRoot`) | 〃 | 미실행 |
| D1 | Dynamic Type을 기본에서 최대(AX5)까지 올리며 N1 · N2를 본다 | 여정 맵 머리의 제목 글자와 알림 버튼이 **겹침 0**, 버튼이 눌린다. 알림 화면 머리의 `맵으로`와 `알림` **겹침 0**. 항목이 세로로 자라고 흐름 영역만 스크롤, 머리는 고정. 항목 오른쪽 경계 **잘림 0**(카드 폭 `100%` + 안쪽 여백 + 테두리 — `box-sizing` 기본값 미확인, 접근성 R-9). 결과는 `통과` 또는 `실패: <배율 · 관찰>` | 시뮬레이터 또는 실기 | 미실행 |

한 항목이라도 어긋나면 `실패: <관찰>`로 적는다 — 무엇이 어긋났는지, 어느 단계에서
처음 보였는지 그대로 적는다. N · D 실패는 `e2e-red`의 `confirmed` 근거다(spec §12.2).

## VoiceOver 여정 V1–V4 — 실기 · 사람만

동일한 Release Host를 **실제 iPhone**에서 실행하고 VoiceOver를 켠다. **Simulator나
정적/UI/integration 테스트는 이 판정을 대체하지 않는다.** 자동 announcement나 임의
focus 이동은 기대하지 않는다.

| ID | 단계 | 관찰(식별 가능한 요소) | 답하는 수단 | 결과 |
|---|---|---|---|---|
| V1 | VoiceOver로 여정 맵 머리를 훑고, 스텝을 눌러 시트를 연 채 다시 훑는다 | 닫힘: 기본 · 최대 배율 모두 `여정 맵, 머리말` → `알림, 버튼` 순(프레임 top 동률 — design §2.3 · §9 Q-1. **역전되면 design 대체안 L로 계약을 보정한다**). 버튼 안 낱말 `알림`이 따로 정지하지 않는다. 시트 열림: 알림 버튼에 **닿지 않는다**(맵 항목도), 제목 · 시트 · 탭은 닿는다. 닫으면 다시 닿는다 | **실기 · 사람만** | 미실행 |
| V2 | VoiceOver로 알림 화면을 훑는다 | `맵으로, 버튼` → `알림, 머리말` → 항목마다 **정지 하나** `<메시지>, <행선지>, 버튼`. 항목 안 메시지 · 행선지가 따로 정지하지 않는다. 읽음 · 배지 낭독 0. **최대 배율(AX5)에서** 흐름 영역을 스크롤하지 않은 초기 상태로 한 손가락 순회만으로 **넷째 항목**(`배운 대화를 롤플레이로 연습해 보세요, 롤플레이 목록 보기, 버튼`)에 **닿는다** — 닿지 못하면 실패(접근성 R-9 · 선례 `listening.md` E-S1). 닿는 순간 **자동 스크롤되는지는 통과/실패가 아니라 적는다**(같은 선례). 넷째가 처음부터 화면 안이면 그 사실을 적는다(그때 이 줄은 순회 도달을 시험하지 못한 것이다). 어긋나면 §4.7로 되돌아온다 — 스크롤 컨테이너 prop을 추측으로 붙이지 않는다 | **실기 · 사람만** | 미실행 |
| V3 | VoiceOver로 탭 바를 훑는다 | 정지 **셋** — `여정, 선택됨, 버튼` · `롤플레이, 버튼` · `설정, 버튼` | **실기 · 사람만** | 미실행 |
| V4 | **관찰 기록형 — 통과/실패가 없다.** 기본 배율 · VoiceOver로 이 변경이 만든 전이 직후를 잰다(활성화 = 두 번 탭). 순서: (a) 여정 맵에서 `알림, 버튼` 활성화 → (b) 알림 화면에서 `맵으로, 버튼` 활성화 → 다시 알림을 연다 → (c) `배운 대화를 롤플레이로 연습해 보세요, 롤플레이 목록 보기, 버튼` 활성화 → (d) 탭 바의 `여정` 탭 활성화 | **적는다**(`기록: …`). (a) 활성화 직후 **처음 읽힌 것**, 이어서 오른쪽 스와이프 **한 번 뒤** 읽힌 것. (b) 활성화 직후 처음 읽힌 것. (c) 활성화 직후 처음 읽힌 것, 그리고 `롤플레이, 선택됨, 버튼`에 닿기까지 **스와이프 수**(정수 — D8 보류 행의 숫자, 방향을 바꿨으면 그것도). (d) 활성화 직후 처음 읽힌 것, 네 손가락으로 화면 위쪽을 한 번 탭(첫 요소로)한 뒤 **첫 두 정지**가 `맵으로, 버튼` → `알림, 머리말`인지(예/아니오 + 들린 그대로), 그 문맥이 **이해되는지**(자유 기술 한 문장 이상). 들린 것이 없으면 `무음`, 닿지 못하고 멈추면 `닿지 못함 · <멈춘 수>` — 둘 다 유효한 기록값이다 | **실기 · 사람만** | 미실행 |

**V4의 지위 — 판정 대상이 아니다.** ADR-0016 D8(전환 통지)이 열리기 전에는 V4가
드러낼 불편을 고칠 경로가 없어 실패 조건을 두지 않는다(`journey-map.md` E2 ·
`assessment.md` M1과 같은 관찰 기록형). V4는 `e2e-red`의 `moot`과 `e2e-green`의
`manual-result`(`passed`·`failed` 둘 다) 판정에는 **실행 의무**로 세어지지만
(기록이 비면 그 값을 낼 수 없다), `confirmed`의 성립이나 `passed`/`failed`의
갈림에는 세어지지 않는다 — `confirmed`는 N·D·V1~V3 판정 항목의 실패 관측 하나로
선다. **기록 완비** = 네 칸이 전부 찬다: (a) 낭독 둘 · (b) 낭독 하나 · (c) 낭독
하나 + 정수 하나(또는 `닿지 못함 · <수>`) · (d) 낭독 하나 + 예/아니오와 들린 두
정지 + 자유 기술. 빈칸 · `미실행` · 「확인함」 같은 요약어는 완비가 아니다(spec
§12.2).

V가 돌지 않으면(실기가 없으면) `e2e-red`에 참인 값이 없다 — N · D만, 또는
V1~V3까지만 돈 결과로 `moot`를 주장하지 않는다(spec §12.2). 열리는 문은
**사람(사용자)이 iPhone · Release · VoiceOver로 이 흐름을 도는 것**뿐이다.

표를 그 회차의 값으로 채운다.

## 이벤트 운영 범위

`notificationEventSink`의 현재 제품 진입점은 명시적 `null`이다(spec §7.5). 따라서 이
문서의 어떤 관찰도 이벤트(`notifications_opened` · `notification_item_tapped`)가
실제 운영 집계로 전송되었다는 증거로 쓰지 않는다. 운영 sink 연결과 서버 집계는 별도
후속 범위다.
