# LIB-254 약속 확인 메신저 — iOS 수동 e2e

## 판정 채널과 범위

이 문서는 자동 e2e가 아니라 iOS Release Host에서 수행하는 수동 판정 절차다.
브라우저·테스트 라이브러리·가짜 host로 대체하지 않는다. 정식 M1–M7과 M8 전체 판정은
아직 완료되지 않았다. 아래 692366… Release의 사용자 관찰만 M8 일부 증거이며, 남은
판정은 [GitHub #44](https://github.com/libitums/FE/issues/44#issuecomment-5594887444)가
추적한다. LIB-253 실기 기록은 재사용하지 않는다.

## 실행 준비

1. iOS Release Host와 승인된 기존 앱 host 프로젝트를 준비한다. 새 자동화 명령은 만들지 않는다.
2. 구현 결선 후 생성된 동일 revision의 앱 번들과 SHA-256을 기록한다.
3. iPhone 실기기 1대와 iOS Simulator 1대를 준비하고, 각각 OS·기기·빌드 종류를 기록한다.
   실기기 VoiceOver 판정은 Simulator 결과로 대체하지 않는다.
4. 기본 글자 크기와 최대 Dynamic Type을 각각 준비한다. VoiceOver는 실기기에서 켠다.

## 증거 기록표

| 환경 | 빌드/번들 SHA-256 | M1–M6 | M7 Dynamic Type | M8 VoiceOver | 비고 |
|---|---|---|---|---|---|
| iPhone 13 mini · iOS 26.6.1 | `6923661bbce0c2e0b5fc29631cae5cf0d36e0c9f85a8cbd9f89ba0431a8614c6` · Release | 미실행 | 미실행 | 부분 확인 | 전체 판정은 GitHub #44에서 추적 |
| iOS Simulator | 미기록 | 미실행 | 미실행 | 미실행 | VoiceOver 결과 대체 불가 |

> **부분 관찰 (692366…, 2026-09-09, iPhone 13 mini · iOS 26.6.1 · Release).** 사용자가 `처음부터 보기`·답장·`맵으로`를 VoiceOver에서 버튼으로 읽히는 것을 확인했다. 이 관찰은 해당 컨트롤의 이름·button 역할 범위만 닫으며, 자동 메시지 발화·중복 발화·포커스 순서·Dynamic Type 및 M1–M7 완료를 뜻하지 않는다.

> **추가 부분 관찰 (동일 692366…).** 사용자가 VoiceOver에서 두 답장 후 마지막 메시지와 `대화 완료`까지 읽히는 것을 확인했다. 중복·끊김이 없었다고 확대하지 않으며, 전체 포커스 세부·Dynamic Type·나머지 M1–M7은 미검증이다.

> **최신 a7ce…의 경계.** `a7ce525783870495462eb4b4c137ef74ff8a40eefe5aed3791589a75fdd43598`
> Release는 build·install·launch와 Simulator 초기-load 성능 수집까지만 확인됐다. 이 SHA의
> M1–M8 실기관찰 응답은 없으며 692366… 또는 초기 f9af42… 관찰을 승계하지 않는다.

## 이벤트 운영 범위

`MessengerEventSink`의 현재 제품 진입점은 명시적 `null`이다. 따라서 이벤트가 실제 운영
집계로 전송되었다고 판정하지 않는다. 운영 sink 연결과 서버 집계는 별도 후속 범위다.
