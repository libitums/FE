# 새 에피소드 콘텐츠 형식 (내장본 교체 · 문화 단계 · 완료 키 · 새 유형 · 대화 조립 화자)

내장 에피소드 셋이 새 형식으로 바뀐 뒤 카탈로그 에피소드가 기기에서 **처음부터 끝까지 막히지 않는지**를 확인하는 **수동 절차**다 — 단계가 `S1` ~ `S8` · 문화 단계 `CULT` · 최종 테스트로 서는지,
문항이 전부 건너뛰어지는 `CULT`가 곧장 결과로 끝나는지, 에피소드 완료(완료 키가 모두 끝남)가 트로피와 다음 표지에 걸리는지, 새 유형이 단어 선택으로 서는지, 대화 조립 칸이 콘텐츠의 화자를 따르는지.
결정은 [ADR-0061](../adr/0061-episode-format-additions.md), 매핑 · 화면은 [ADR-0058](../adr/0058-catalog-learning-session.md) 적용 기록 ⟨2026-10-16⟩, 파일 모양은
[콘텐츠 계약](../specs/episode-content-json-contract.md)이 진다. 레슨 사슬 · 타자 입력 · 최종 테스트 화면 자체는 [카탈로그 레슨 e2e](catalog-lessons.md), 컷 · 최종 테스트의 소리는
[에피소드 음성 e2e](episode-audio.md)가 지고 여기서 되풀이하지 않는다.

| 이미 지는 층 | 무엇을 |
|---|---|
| unit | 새 형식 디코드(새 11종 · 공통 필드 · 완료 조건 검사 · 옛 형식 그대로) · 완료 판정 · 표지 열림 · 트로피 · 유형별 매핑 표(24종) · 대화 조립 칸 화자 · 0문항 단계 결선 · 새 내장본의 해시 · version · 음성 id 배치 · 단계별 표시 수 |
| ui | 대화 조립 칸이 `speakers`대로 서는 것(나 먼저 · 같은 화자 연속 · 채점은 순서 기준) · `CULT` 노드가 `Lesson 9`로 세 상태 · 단어 선택 빈칸 제시문의 낭독 이름 |
| integration | 새 내장본 그대로 앱을 띄워 — 노드 10개 · `CULT` 곧장 결과와 기록 · 이벤트 · 옛 키 모양 진행의 완료 판정과 트로피 · 건너뜀이 섞인 단계를 끝까지 · 대화 조립 첫 칸 화자 · 옛 키 `S9`가 섞인 진행 |

**이 문서만 보는 것**: 실제 데이터가 기기에서 그려지는 모습 — 새 유형의 단어 선택 · 대화 조립 말풍선의 좌우 · 그림 문항 · `CULT` 탭의 흐름 · 재실행 유지 · 낭독.

> ⟨2026-10-16 — 새 에피소드 형식 ②⟩ **문화 · 조립 화면이 섰다**([ADR-0063](../adr/0063-episode-format-screens.md)). 이 문서의 절차 가운데 셋이 PR ① 빌드의 것이다 —
> **S1**의 「`Lesson 9` 탭 → 곧장 결과」(이제 노드는 `Culture`이고 문화 카드 셋 → 문화 확인 셋을 연다 · 머리 카드 분모 `11`은 그대로), **S4**의 건너뛰는 유형 목록(문화 카드 · 문화 확인 · 음절 조립은 이제 선다 — 건너뛰는 것은 말하기 둘 · 소리 조립 · 짝 소리 고르기 · 듣기),
> **S6**(0문항 단계의 낭독 — 경로가 사라졌다). 이 셋과 문화 · 조립 화면의 절차 · 회차는 [문화 · 조립 화면 e2e](episode-format-screens.md)가 진다. 아래 표와 회차 기록은 고치지 않았다(S6 행만 걷었다) — 회차는 그 빌드의 관찰이다.
>
> ⟨2026-10-16 — 새 에피소드 형식 ③⟩ **말하기 둘도 섰다**([ADR-0064](../adr/0064-episode-format-speaking.md)). **S4**의 건너뛰는 유형 목록에서 말하기가 빠진다 — 이제 건너뛰는 것은 소리 조립 · 짝 소리 고르기 · 듣기뿐이다.
> 아래 회차 S4의 `Lesson 5` 분모 **6**은 PR ① 빌드의 값이고, 이제 따라 읽기 셋이 서서 **9**다(`Lesson 6` · `Lesson 8`도 그림 보고 말하기 하나씩 +1). 말하기 화면과 권한 흐름의 절차 · 회차는 [말하기 화면 e2e](episode-format-speaking.md)가 진다.

## 전제

- [공통 전제](README.md#공통-전제) — 자체 호스트 앱, 로그인된 상태.
- iOS: iPhone 17 Pro 시뮬레이터, 이 브랜치의 번들. 다른 작업 트리의 개발 서버를 읽지 않게 한다([README 「자동화」](README.md#ios)).
- `apps/mobile/.env.local`에 Supabase 값이 있어야 원격 그림 · 음성 요청이 나간다. 값은 기록에 적지 않는다.
- 버킷의 매니페스트가 아직 옛 version이면 앱은 **내장본**을 쓴다(이 절차의 대상이다).
- 계정 둘: **새 설치(진행 없음 — 튜토리얼 최종 테스트를 끝낸 뒤)**와 **옛 빌드로 u01을 끝낸 계정**(진행 `intro · S1 · S3 ~ S9 · RP`). 옛 계정에서는 u01이 **완료가 아니다**(`S2` · `CULT`가 없다 — ADR-0061 「대가」 2).
- 콘텐츠: 내장 `u01-water`. 레슨 번호와 단계 id — `Lesson 1` = `S1` … `Lesson 8` = `S8`, **`Lesson 9` = `CULT`**, 그 뒤 `Final test` = `RP`. 머리 카드 분모는 `11`(표지 + 레슨 9 + 최종).

## 관찰 항목 (S1 ~ S7)

통과·실패는 `통과` / `실패: <관찰>` / `판정 불가: <이유>` / `미확인`으로만 적는다.

> **S6 · S7은 계약의 e2e 표에 없다** — 접근성 감사(2026-10-16)가 「기기에서만 닫힌다」로 지목한 두 자리를 받았다(S6은 [ADR-0016](../adr/0016-assistive-technology-semantics.md) D8 적용 기록 ⟨2026-10-16⟩, S7은 단어 선택 빈칸 낭독의 수정).

| id | 단계 | 관찰(통과 조건) |
|---|---|---|
| S1 | (새 설치) 맵 u01 표지 → 표지 화면 · 컷 → `Episode start!` → `Lesson 1` ~ `Lesson 8`을 차례로 끝까지(각 결과 화면) → `Lesson 9` 탭 → 최종 테스트 세 턴 → 결과 → 통과 뒤 컷 → `Episode clear!` → 맵 | `Lesson 9`(`ui-lynx-learning-unit-catalog-unit-u01-water-CULT`)를 누르면 **레슨 화면 없이 곧장 결과**(`PERFECT LESSON!`)가 선다. 맵에서 u01 노드 전부 완료 · 머리 카드 `11 / 11` · **머리 트로피 +1** · **`Episode 2.` 표지 열림** |
| S2 | S1을 지나며 | `Lesson 1`의 빈칸 고르기(`CLOZE_CHOICE` — 「___ 할게요.」, 보기 셋 콘텐츠 순서) · `Lesson 2`의 대답 고르기(`REPLY_SELECT` — 상대 말이 제시문 + 로마자 · 번역 줄, 지시문 `How do you reply?`) · `Lesson 5`의 조사 채우기 · 고치기(`PARTICLE_FILL` · `PARTICLE_SWAP`)가 **단어 선택**으로 선다. **그림 문항**(봉투 · 영수증)이 그림 틀로 서고 그림이 오면 보기가 열린다 |
| S3 | `Lesson 2`의 대화 조립 `S2-07` | 첫 빈 말풍선이 **오른쪽(나, 주황)** 이다 — 콘텐츠가 플레이어 줄부터 시작하는 문항. 정답 순서로 놓으면 정답 |
| S4 | S1을 지나며 | 건너뛰는 유형(말하기 · 소리 조립 · 음절 조립 · 짝 소리 고르기 · 듣기)이 화면에 한 번도 서지 않고, 머리 카운터의 분모가 **표시 문항 수**다 |
| S5 | 앱을 끄고 다시 켠다 | 진행 · 트로피가 남는다. 서버 진행(`learning_progress`)의 u01 키에 `CULT`가 있다 |
| S6 | ~~VoiceOver를 켜고 `Lesson 9`를 두 번 탭~~ **걷힘(⟨2026-10-16 — PR ②⟩)** | ~~결과 화면 낭독(`Lesson complete, no mistakes`)이 노드 활성 피드백에 잘리지 않고 들린다~~ — 0문항 경로가 실데이터에서 사라졌다([ADR-0016](../adr/0016-assistive-technology-semantics.md) D8 적용 기록 닫힘). VoiceOver로 `Culture` 노드 → 문화 카드를 도는 절차는 [문화 · 조립 화면 e2e](episode-format-screens.md) SS5 |
| S7 | VoiceOver(구두점 「일부」 · 「모두」 둘 다)로 빈칸 문장의 단어 선택(`Lesson 1` 빈칸 채우기 · `Lesson 5` 조사 채우기) | 제시문 · 로마자 줄이 밑줄 자리에서 `blank`라고 읽힌다(「카드 blank 할게요」). 1음절 조사 보기(「가」 · 「이」)가 한국어 음성으로 구별돼 들리는지도 적는다 |

Android: 네이티브 변경이 없어 절차를 따로 두지 않는다(단위 · 통합 테스트가 덮는다). 기기 확인이 반쪽인 자리(타자 입력 등)는 [카탈로그 레슨 e2e](catalog-lessons.md) 「미확인」 그대로다.

## 회차 — 2026-10-16, iOS 시뮬레이터, 옛 진행 계정 — 부분 확인

- 기기: 시뮬레이터 `FE-catalog-e2e`(iOS 26.5). **Debug 빌드**. 확인자: 개발 에이전트(시뮬레이터 자동 조작 — `idb` 탭 · 접근성 트리 덤프 · 스크린샷).
- ⚠ **레슨 통과 기준을 0으로 바꾼 커밋하지 않은 테스트 패치를 번들을 만들 때만 얹었다** — 레슨을 정답으로 다 풀지 않고 지나가려고 했다. 그래서 이 회차의 결과 화면 판정(통과 · `PERFECT`)은 **실제 기준의 확인이 아니다.** 패치는 저장소에 없다.
- 빌드 commit은 기록에 없다. 접근성 수정(`36ccdfaf` — 빈칸 낭독)보다 **앞선 빌드다** [추론 — 아래 서버 진행 갱신 시각 02:38Z가 그 commit 시각보다 이르다]. S7의 대상이 아니다.
- 계정: **옛 진행**(`intro · S1 · S3 ~ S9 · RP`)이 남은 로그인 계정. 새 설치 회차는 없다.

| id | 결과 | 관찰 |
|---|---|---|
| S1 | **통과(부분)** | 옛 진행에서 `Lesson 2`(`S2`)를 끝내고 `Lesson 9`(`CULT`)를 누르자 **레슨 화면 없이 곧장 `PERFECT` 결과**가 섰다. 맵으로 돌아오자 머리 트로피가 **1 → 2**, u01 노드가 전부 완료로 섰다 — 옛 진행이 완료가 아니었다가 `S2` · `CULT`로 완료가 되는 것(ADR-0061 Q1 · integration EF3과 같은 경로)을 기기에서 봤다. **보지 못한 것**: 새 설치의 처음부터 끝까지 · 표지 컷과 최종 테스트 · 통과 뒤 컷 · `Episode clear!` · `Episode 2.` 표지가 이 순간에 열리는지 |
| S2 | **통과(부분)** | 대답 고르기(상대 말 글 + 로마자 + 번역) · 조사 채우기 · 조사 고치기가 단어 선택으로 섰다. **빈칸 고르기(`CLOZE_CHOICE`)와 그림 문항은 보지 못했다**(둘 다 `Lesson 1`에 있다 — 빈칸 고르기는 그 끝 문항이다) |
| S3 | 통과 | `S2-07` 첫 칸이 `You`(오른쪽 · 주황). 정답 순서로 놓자 정답 판정. 낭독은 실기로 듣지 않았다(시뮬레이터에 VoiceOver가 없다) |
| S4 | 통과(본 범위) | u01 `Lesson 2` 분모 **8**(14문항 − 듣기 5 · 소리 조립 1), `Lesson 5` 분모 **6**(12문항 − 짝 소리 고르기 2 · 말하기 3 · 소리 조립 1). 건너뛰는 유형의 화면은 서지 않았다. 본 단계는 이 둘이다 |
| S5 | 통과 | 앱을 다시 켠 뒤 진행 · 트로피가 남았다. 서버 `learning_progress`가 02:38Z에 갱신됐고 u01 키에 `CULT`가 들었다 |
| S6 · S7 | 미확인 | VoiceOver 회차가 없다 |

그 밖의 관찰(항목 판정이 아니다): ① 대화 조립에서 칩이 세 줄로 늘면 마지막 칩이 첫 화면 아래(y ≈ 844)에 가려 스크롤해야 보였다 — 화면이 스크롤되므로 막히지는 않는다. [카탈로그 레슨 e2e](catalog-lessons.md) 2차 회차의 E3-D 「남은 보기가 스크롤 없이 보인다」는 그때 데이터의 관찰이고, 이번 것은 새 데이터의 긴 대화에서 난 것이다 — 결함인지는 별도 확인이 필요하다.
② 전환 직후의 탭이 다른 칩에 닿은 일이 있었다 — 도구(좌표 탭)의 타이밍이었고 한 번씩 누르면 정확했다.

## 미확인

- **새 설치의 처음부터 끝까지(S1 전체)** — 표지 컷 · `Lesson 1` · 최종 테스트 · 통과 뒤 컷 · `Episode clear!` · `Episode 2.` 표지 열림. 실제 통과 기준(60 %)으로 푼 회차가 없다.
- **빈칸 고르기(`CLOZE_CHOICE`) · 그림 문항(S2)** — 그림 문항은 실데이터에 그림이 들어온 첫 회차인데 아직 기기에서 본 적이 없다(로딩 중 보기 잠금 · 실패 대체 글자 · 6초 — [카탈로그 새 문항 e2e](catalog-items.md)).
- **최종 테스트의 소리** — 새 내장본에 다시 붙인 음성 id로 소리가 나는지([에피소드 음성 e2e](episode-audio.md) S6 ~ S8).
- **VoiceOver(S7)** · **Android**. (S6은 걷혔다 — 위 머리 메모.) ⟨2026-10-16 — PR ②⟩ S7의 **이름 쪽**은 PR ② 회차가 접근성 트리에서 `삼천 blank`로 봤다 — 실청취는 아직이다([문화 · 조립 화면 e2e](episode-format-screens.md) SS5).
- **u02 · u03** — 이 회차는 u01만 봤다.

⟨2026-10-16 — 사용자 결정⟩ 수용 기준 7(u01을 표지부터 최종 테스트까지 완료)은 이 부분 확인으로 병합한다. 위 미확인 항목은 병합을 막지 않고 다음 기기 회차로 넘긴다.

미확인 항목을 누가 언제 보는지는 [ADR-0061](../adr/0061-episode-format-additions.md) 「미확인 · 후속」 1이 진다.
