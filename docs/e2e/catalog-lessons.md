# 카탈로그 레슨 · 타자 입력 · 최종 테스트 · 통과 뒤 컷 (3c)

카탈로그 에피소드의 레슨 노드가 사슬로 열리고, 레슨이 콘텐츠 문항을 학습 화면(단어 선택 · 대화 조립 · 타자 입력 — ⟨3d-1⟩ 단어 카드 · 짝 맞추기는 [카탈로그 새 문항 e2e](catalog-items.md))으로 세우며, 최종 테스트와 통과 뒤 컷을
지나 다음 에피소드가 열리는 것을 기기에서 확인하는 **수동 절차**다. 결정은 [ADR-0058](../adr/0058-catalog-learning-session.md), 화면은
[화면 명세](../screens.md) 「여정 탭」의 카탈로그 레슨 · 타자 입력 · 카탈로그 최종 테스트 · 통과 뒤 컷 행, 맵 구획과 표지 컷은
[카탈로그 맵 e2e](catalog-map.md), 측정 이벤트는 [ADR-0029](../adr/0029-product-analytics-posthog.md) D14 적용 기록 ⟨2026-10-13⟩이 진다.

| 이미 지는 층 | 무엇을                                                                                                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| unit         | 문항 매핑 · 건너뜀 사유 · 결정적 섞기 · 활동 구간 · 통과 기준(60 %) · 타자 채점 · 최종 테스트 판정 · 노드 사슬 상태 · 세션 고정 · 이벤트 만들기                                       |
| ui           | 학습 화면 셋의 문항 prop 활동 · 학습형 사이 완료 카드 없음 · 레슨 전체 카운터 · 대화 조립 말풍선 · 타자 입력 · 최종 테스트 화면 · 유닛 노드 · 그림 실패 시 이전 층 걷기 · 접근성 이름 |
| integration  | 앱을 띄워 레슨 시작 → 활동 전환 → 결과 → 진행 저장 요청 본문 · 실패 뒤 다시 하기 · 최종 테스트 → 통과 뒤 컷 → 다음 표지 열림 · 이벤트 순서 · 그림 실패                                |

**이 문서만 보는 것**: 기기에서 실제로 그려지는 모습과 조작감 — 칩 안 글자 잘림 · 말풍선 배치 · 자판 반응 · 원격 그림 실패 · 낭독 · 재실행 유지.

## 전제

- [공통 전제](README.md#공통-전제) — 자체 호스트 앱, 로그인된 상태.
- iOS: iPhone 17 Pro 시뮬레이터, 이 브랜치의 번들. 다른 작업 트리의 개발 서버를 읽지 않게 한다([README 「자동화」](README.md#ios)).
- `apps/mobile/.env.local`에 Supabase 값이 있어야 원격 그림 요청이 나간다. 값은 기록에 적지 않는다.
- 계정: **튜토리얼 최종 테스트를 끝낸** 계정(카탈로그 에피소드 1 표지가 열려 있어야 한다). 진행은 서버에 남는다.
- **순차 잠금이라 뒤 항목은 앞 레슨을 모두 통과해야 닿는다** — E5(다섯째 레슨)는 앞 넷을, E7(최종 테스트)은 레슨 여덟을 통과해야 열린다.
  한 회차에 끝까지 가려면 시간이 든다.
- 콘텐츠: 내장 `u01-water`. 레슨 번호와 스텝 id — `Lesson 1` = `S1`, `Lesson 2` = `S3`, `Lesson 3` = `S4`, `Lesson 4` = `S5`, `Lesson 5` = `S6` … `Lesson 8` = `S9`.

## 관찰 항목

통과·실패는 `통과` / `실패: <관찰>` / `판정 불가: <이유>` / `미확인`으로만 적는다.

> 계약 단계의 e2e 표에서 둘이 바뀌었다 — 그 뒤의 사용자 결정 때문이다. **E2**는 「곧바로 PERFECT LESSON」이었는데 빈칸 채우기(`CLOZE`)가 단어 선택으로
> 들어와 3문항을 푼다. **E3 · E4**는 듣기 문항이 섞여 서고 「대본 + 꺼진 재생」을 보는 항목이었는데 오디오 없는 듣기는 건너뛰게 됐다 — E4는
> 「듣기가 서지 않는다」를 보는 항목이 됐다. 아래 표는 바뀐 기대다.
>
> ⟨2026-10-13 — 3d-1⟩ **E2의 기대가 한 번 더 바뀌었다.** 단어 카드가 화면을 얻어 `Lesson 1`(`S1`)은 카드 셋으로 시작하고 카운터가 `1 / 6`이다
> (`Lesson 3` = `S4`도 카드 다섯으로 시작한다). 표의 E2는 지금 기대로 고쳤고, 아래 1차 · 2차 회차의 E2 기록(「단어 선택 3문항」)은 **3c 빌드의 관찰**이라 그대로 둔다.
> 카드 · 짝 맞추기 · 그림 고르기 자체의 관찰 항목은 [카탈로그 새 문항 e2e](catalog-items.md)가 진다.
>
> ⟨2026-10-14⟩ **E8의 기대가 바뀌었다** — 통과 뒤 컷의 마지막 버튼 뒤에 「Episode clear!」 배너가 서고, 그 닫힘이 맵으로 간다. 표의 E8은 지금 기대로 고쳤다.
> 표지 유닛도 이제 컷 앞에 표지 화면이 선다 — E1(「표지를 끝낸다」) · E9(「`Episode 2.` 표지 … 컷까지 넘긴다」)는 표지 화면의 `Next`를 한 번 누르고 진행한다([카탈로그 맵 e2e](catalog-map.md) 「표지 화면 · 시작 배너」).
> 배너 자체의 관찰 항목(C7 · C8)은 아래 「통과 뒤 컷 끝의 클리어 배너」 절이 진다.

## 통과 뒤 컷 끝의 클리어 배너 ⟨2026-10-14⟩

통과 뒤 컷을 끝까지 봤을 때 서는 「Episode clear!」 배너의 절차다. 배너 화면은 표지 컷 뒤의 「Episode start!」와 같은 화면이고 글자만 다르다 —
모습 · 유지 시간 · 동작 줄이기 · 낭독의 관찰 항목은 [카탈로그 맵 e2e](catalog-map.md) 「표지 화면 · 시작 배너」의 C4 ~ C6 · C11 · C12를 글자만 바꿔 그대로 쓴다.
결정은 [ADR-0058](../adr/0058-catalog-learning-session.md) 적용 기록 ⟨2026-10-14⟩이 진다. ui(흐름 컴포넌트의 `clear` 변형 · 나가기에는 배너 없음)와 integration(최종 테스트 → 통과 뒤 컷 → 배너 → 맵 · 다음 표지 열림)은 통과했다.

| id | 단계 | 관찰(통과 조건) |
| --- | --- | --- |
| C7 | 레슨을 모두 끝낸 에피소드에서 최종 테스트 통과 → 결과 나가기 → 통과 뒤 컷을 끝까지 | 마지막 버튼 뒤 검은 면에 주황 **「Episode clear!」** → 약 1.6초 뒤(또는 누르면 바로) 맵. `Final test` 완료 · 다음 에피소드 표지 열림 |
| C8 | 통과 뒤 컷 도중 나가기 · 시스템 뒤로 | **배너 없이** 맵. 다음 에피소드 표지는 열려 있다 |

**실행한 회차가 없다** ⟨2026-10-14⟩. 「Episode clear!」는 최종 테스트를 통과한 직후에만 닿는데, 2026-10-14의 시뮬레이터 회차는 에피소드 셋을 이미 통과한 계정이라 최종 테스트를 다시 통과하지 않았다
(같은 회차에서 「Episode start!」는 봤다 — [카탈로그 맵 e2e](catalog-map.md) 3차 회차). C7 · C8은 **미확인**이다.

## 미확인

- ⟨2026-10-14⟩ **「Episode clear!」 배너(C7 · C8)** — 기기에서 본 적이 없다(위 절).
- **타자 입력(E5)** — 화면 · 자판 반응 · 채점 · 정답 공개를 기기에서 본 적이 없다.
- **최종 테스트(E7) · 통과 뒤 컷과 다음 에피소드 열림(E8)** — 기기에서 본 적이 없다.
- **그림 실패 처리(E9)** — 미확인. 그림 없는 컷은 에피소드 2 · 3에만 있다(위 「E9 결과」).
- **실패 뒤 다시 하기(E6) · 재실행 유지(E10) · 동작 줄이기(E12) · 튜토리얼 회귀의 기기 관찰(E13) · PostHog 이벤트 도착(E14).**
- **VoiceOver 실기(E11 · E11-D)** — 특히 최종 테스트의 놓인 타일에 초점이 가는지.
- **Android(A1 ~ A3)** — 절차만 있고 실행한 회차가 없다.
- **E4의 나머지 레슨** — 듣기가 서지 않는 것을 기기에서 본 범위는 `Lesson 2`까지다(실데이터의 듣기 문항이 건너뛰어지는 것은 unit이 고정한다).
- **성능** — 레슨 진입 시간 · 자판 입력 지연은 재지 않았다([성능 보고서](../performance/reports/episode-catalog-lessons-iphone-17-pro-simulator-01.md)).

미확인 항목을 누가 언제 보는지는 [ADR README 보류 표](../adr/README.md#보류-표) 「3c 카탈로그 레슨의 기기 미확인 항목」이 진다.

## 알려진 제약

- **학습 문항에는 오디오가 없다.** 듣기 문항은 전부 빠지고 받아쓰기의 재생 조작은 꺼져 있다(ADR-0058 D3). ⟨2026-10-14⟩ 최종 테스트 · 통과 뒤 컷에는 소리가 있다 — 확인은 [에피소드 음성 e2e](episode-audio.md)가 진다([ADR-0060](../adr/0060-episode-voice-remote-audio.md)).
- **대화 조립의 화자는 앱의 가정이다**(짝수 칸 상대 · 홀수 칸 나). 콘텐츠에 화자 표기가 없다 — 콘텐츠 계약 Q25.
- **타자 화면의 자판 testid가 `messenger-key-*`다** — 메신저 자판을 그대로 쓴다.
