# 메신저 자유 대화 UI(1단계) — 기기 확인

계약은 `messenger-chat-ui` spec이 정하고 결정은 [ADR-0113](../adr/0113-messenger-chat-ui.md)이 진다(데이터는 가짜 출처 · 서버 없음, ADR-0102 6판의 UI 부분). 자동 테스트(MC-U · MC-UI · MC-I)는 키보드 규칙 · 높이 계산 · 자모 되감기 · 방 리듀서 · 목록 정렬 · 탭 넷 · 셸 모드 · 겹침 열림 닫힘 · 학습 메신저 회귀를 지킨다.
**휴대폰 키보드의 실제 높이 · focus/blur · setValue · 스크린리더 초점 · 큰 글자 · 작은 화면 · 스토어와 같은 빌드**는 테스트 환경에 없으므로 기기에서만 판정한다.

## 준비

- 메신저 탭은 일반 빌드(스토어 구성 포함)에서 바로 보인다 — 측정용 번들 · 진입점 교체가 필요 없다. 로그인(또는 「Continue without an account」) 뒤 하단 바의 **세 번째 항목(말풍선 아이콘 「Chats」)**을 누른다.
- 가짜 데이터: 열린 방 둘 이상 · 잠긴 방 하나 이상이 기본으로 있다. 젬 잔액은 앱의 실제 값(대개 0)이라 **사진 · 음성 요청은 항상 「Get gems」로 간다** — 요청 흐름(스켈레톤 → 도착)을 보려면 잔액을 30 이상으로 만든 개발 구성이나 잔액 시드가 필요하다. 시드가 없으면 MC-E8은 「부분」으로 기록한다.
- 기기: iOS 시뮬레이터(iPhone SE 3세대 375 × 667 · iPhone 17 Pro 402pt · iPad mini) · Android AVD(Pixel_8 412dp · 같은 AVD를 `wm density 480`으로 360dp · R6_API30 API 30 · 2GB 저사양) · 가능하면 실기 한 대씩. MC-E10은 스토어와 같은 빌드(Android `assembleBundled` · iOS Release 구성)로 본다.
- 지켜볼 것: 눈(배치 · 점프 · 잘림) · 입력창 글자 · logcat `FATAL EXCEPTION` · iOS 콘솔 오류 · 스크린리더(VoiceOver · TalkBack) · 큰 글자(iOS 접근성 최대 · Android 글꼴 크기 최대).
- 끝나면 에뮬레이터 `emu kill` · `wm density reset` · 임시 번들이 `apps/ios/main.lynx.bundle` · `apps/android/app/src/main/assets/`에 남지 않았는지 확인한다.

### 알려진 한계(phase 1 — 실패가 아니라 수치를 남길 것)

1. **한국어 키보드 감지는 항상 `unknown`** — 1단계는 학습 키보드 + 토글을 늘 보여 준다. 휴대폰 한국어 키보드가 있는지에 따라 달라지는 모습은 보지 않는다.
2. **키보드 높이는 화면 높이 표(667 → 260 · 844 → 300 · 932 → 320)** 다. 저장된 실제 높이가 없으므로 휴대폰 키보드로 바꿀 때 실제 키보드 높이와 표 값의 차이만큼 **입력 줄 · 토글이 위아래로 튈 수 있다**. 튄 양을 pt/dp로 기록한다(MC-E4).
3. **젬 잔액은 앱의 실제 값** — 사진 · 음성 요청은 잔액이 모자라면 「Get gems」로 간다.
4. **스토어 빌드에도 가짜 데이터**가 보인다(1단계 결정, 2026-11-09). 오류 · 크래시가 없는지만 본다.
5. **스크린리더 초점 복귀는 기기에서 본 적이 없다** — 겹침을 연 일곱 단추(「…」 · 「☰」 · Snapshot · Snap voice · 사이드바의 Get gems · 이야기 시점 · Delete chat) 모두 접근성 요소 자체에 id가 있고(⟨2026-11-09⟩ 접근성 C1 반영 — 예전의 「☰만 예외」는 없어졌다), 복귀는 뒤 화면 숨김이 풀린 다음 프레임에 부른다. `requestAccessibilityFocus` 네이티브 메서드가 iOS · Android에서 실제로 초점을 옮기는지는 MC-E7에서 단추별로 기록한다.

## 접근성 확인

- 모든 단추는 라벨이 있고 눌림 영역이 24 × 24 이상(알약 · 전구 · 「…」 · 보내기 · 토글 · 재생 · Type myself는 보이는 크기가 작아도 `hit-slop`으로 터치 44 이상 — 이웃 단추를 잘못 누르지 않는지 함께 본다). 큰 글자 최대에서 머리 · 토글 · 기능 줄이 잘리지 않는다.
- 상태는 색만으로 전하지 않는다 — 토글 선택 · 신고 사유 체크 · 자동 보기는 글자 · 아이콘 · 낭독으로도 보인다.
- 움직임 줄이기에서 스켈레톤 반짝임 · 입력 중 점 · 사이드바 미는 움직임이 멈추고, 정보는 그대로 전달된다.
- 진동 · 소리만으로 전하는 정보가 없다.
