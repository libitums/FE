# 카탈로그 새 문항 — 단어 카드 · 짝 맞추기 · 그림 고르기 (3d-1)

카탈로그 레슨이 건너뛰던 세 문항 유형이 화면에 서는 것을 기기에서 확인하는 **수동 절차**다 — 단어 카드가 레슨 앞에 한 장씩 서고 채점 없이 넘어가는지,
짝 맞추기가 두 열의 타일을 이어 한 번에 판정되는지, 그림 고르기가 (그림이 있을 때) 단어 선택의 그림 문항으로 서는지. 결정은
[ADR-0058](../adr/0058-catalog-learning-session.md) 「적용 기록」 ⟨2026-10-13 — 3d-1⟩, 화면은 [화면 명세](../screens.md) 「여정 탭」의 단어 카드 · 짝 맞추기 ·
카탈로그 레슨 행, 측정 이벤트는 [ADR-0029](../adr/0029-product-analytics-posthog.md) D14 적용 기록 ⟨2026-10-13 — 3d-1⟩이 진다. 레슨 노드 사슬 · 학습형 연속 ·
타자 입력 · 최종 테스트는 [카탈로그 레슨 e2e](catalog-lessons.md)가 지고 여기서 되풀이하지 않는다.

| 이미 지는 층 | 무엇을                                                                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| unit         | 세 유형의 매핑과 건너뜀 사유(`image-missing` · `no-gloss`) · 낱말 뜻 조회 · 계획의 채점 수 / 표시 수 · 통과 기준과의 맞물림 · 카드의 걸음 판정 · 짝 리듀서와 판정 · 낭독 문자열 · 그림 로드 상태 전이 |
| ui           | 카드 · 짝 보드 · 타일 · 그림 틀의 렌더와 접근성 속성 · 버튼 유무 · 그림 `load` / `error` / 6초 시간 제한에 따른 대체 글자와 보기 잠금 · 레슨 안 위치에서의 이어 가기 · 동작 줄이기                    |
| integration  | 앱을 띄워 맵 → 카드 활동(결과 없음) → 채점 활동 → 판정(채점 수 기준) → 기록 → 이벤트. 그림 문항은 그림 주소가 든 픽스처로 계획 · 화면 · 판정을 지난다                                                  |

**이 문서만 보는 것**: 기기에서 실제로 그려지는 모습과 조작감 — 카드의 배치 · 타일 탭 반응과 번호 · 낭독 · 재실행 유지.
⚠ **그림 고르기는 이 문서로 볼 수 없다** — 실데이터의 그림 문항 10개는 그림 주소가 전부 비어 있어 레슨에 서지 않는다. 그 화면은 ui · integration 테스트(픽스처)가 대신 판정한다.

## 전제

- [공통 전제](README.md#공통-전제) — 자체 호스트 앱, 로그인된 상태.
- iOS: iPhone 17 Pro 시뮬레이터, 이 브랜치의 번들. 다른 작업 트리의 개발 서버를 읽지 않게 한다([README 「자동화」](README.md#ios)).
- 계정: **튜토리얼 최종 테스트를 끝낸** 계정(카탈로그 에피소드 1 표지가 열려 있어야 한다). 진행은 서버에 남는다.
- **순차 잠금이라 짝 맞추기는 멀다.** 짝 맞추기는 내장 `u03-mina`의 `Lesson 8`(`S9`)에만 있다 — 에피소드 1 · 2의 최종 테스트와 에피소드 3의 `Lesson 1` ~ `Lesson 7`을
  통과한 계정이어야 닿는다. 한 회차에 거기까지 가려면 시간이 든다.
- 콘텐츠: 내장 `u01-water` `Lesson 1`(`S1`) = 단어 카드 셋(「물」 · 「괜찮아요.」 · 「봉투」) + 빈칸 채우기 셋. 그 사이의 그림 문항 둘은 건너뛴다 — 표시 문항 6, 채점 문항 3.
  `Lesson 3`(`S4`)도 단어 카드 다섯으로 시작한다.

## 미확인

- **짝 맞추기(E5 · E6)** — 화면 전부. 타일 고르기 · 번호 · 풀기 · `Check` · 정오 표시 · 정답 공개 · 탭 반응을 기기에서 본 적이 없다.
- **그림 고르기(E9)** — 화면 전부. 실데이터에 그림이 0장이라 **그림이 올 때까지 기기에서 볼 방법이 없다.** Lynx iOS가 실패한 그림에 `binderror`를 쏘는지도
  [카탈로그 레슨 e2e](catalog-lessons.md) E9와 함께 열려 있다 — 그림 문항은 이벤트가 안 와도 6초 뒤 뜻 글자로 넘어가게 돼 있으나 그것도 jsdom 테스트로만 참이다.
- **VoiceOver 실기(E7)** — 카드의 이름은 속성 값으로만 봤고, 짝 맞추기의 이음 · 풀림 · 판정 낭독은 한 번도 듣지 못했다.
- **Android(A1 ~ A2)** — 실행한 회차가 없다.
- **카드를 뺀 통과 기준(E4) · 레슨 끝의 결과와 맵 반영(E3) · 재실행 유지(E10) · 동작 줄이기(E8) · 튜토리얼 회귀의 기기 관찰(E11) · PostHog의 `shownItemCount` 도착(E12).**
- **보기 칩 여백 수정(E13)의 튜토리얼 쪽 관찰** — 튜토리얼 낱말 고르기 칩의 폭이 바뀌는데 기기에서 본 기록이 없다.
- **성능** — 레슨 진입 시간 · 타일 탭 반응은 재지 않았다([성능 보고서](../performance/reports/episode-catalog-items-iphone-17-pro-simulator-01.md) — 번들만).
- [카탈로그 레슨 e2e](catalog-lessons.md) 「미확인」의 3c 항목(타자 입력 · 최종 테스트 · 통과 뒤 컷 등)도 그대로 열려 있다.

미확인 항목을 누가 언제 보는지는 [ADR README 보류 표](../adr/README.md#보류-표) 「3d-1 카탈로그 새 문항의 기기 미확인 항목」이 진다.

## 알려진 제약

- **그림 문항이 하나도 서지 않는다.** 그림 주소가 채워지면 앱 변경 없이 선다 — [콘텐츠 계약](../specs/episode-content-json-contract.md) 부록 D.
- **「봉투」의 뜻이 카드에서는 `envelope`이다.** 그림 문항(지금은 서지 않는다)에서는 `bag`이 된다 — 데이터가 그렇다(콘텐츠 계약 Q27).
- **카드뿐인 레슨의 결과 제목은 `PERFECT LESSON!`이다**(사용자 결정 — 그대로 둔다). 실데이터에 그런 레슨은 없다.
- **짝 맞추기 낱말 타일에 로마자가 없다** — 한글을 못 읽으면 어렵다(문장 순서 칩 · 단어 선택 보기와 같다).
- **u03 `Lesson 1`의 카드 예문에 이름 「은지」가 그대로 보인다** — 치환 대상이 아니다(콘텐츠 계약 Q28).
