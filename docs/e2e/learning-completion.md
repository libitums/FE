# 일반 활동 진행률과 완료 화면

2026-09-30 기준 공통 흐름입니다. 듣기·문장 순서·단어 선택·말하기·쓰기에 적용합니다.

## 확인 절차

1. 문항 3개인 활동을 엽니다. Lesson 1 / 3과 막대 약 33%를 확인합니다.
2. 답하고 Next로 이동할 때 Lesson 2 / 3, 약 67%를 확인합니다.
3. 마지막 문항에서는 답변 전부터 Lesson 3 / 3, 100%입니다.
4. 마지막 답변 후 Next를 누릅니다. N/N과 100%가 유지되고 문제 지시문이 사라집니다.
5. 체크 아이콘, All questions done, 다음 단계 안내, 3 of 3 questions completed가 보입니다. 이전 문제의 정답·오답 배지는 없어야 합니다.
6. See results를 누르면 기존 결과 전달이 한 번만 발생합니다. 제품에서는 기존 활동/평가 라우팅을 유지합니다.
7. 첫 일반 유닛 Your First Hello도 확인합니다. 문항과 완료 화면 모두 1/1, 100%이며 완료 요약은 1 of 1 question completed입니다.
8. 빈 활동 픽스처에서는 순번과 문항 수 요약 없이 0%입니다. 완료 카드와 결과 보기 동작은 유지됩니다.

## 실행 기록

iPhone 17 Pro / iOS 26.5 개발 playground에서 7번과 완료 후 맵 복귀를 확인했습니다. 체크 아이콘·카드·하단 버튼이 겹치지 않고 하단 safe area가 유지됩니다. playground의 See results는 맵으로 직접 돌아갑니다.
3문항의 비율과 빈 활동, 다섯 활동의 완료 전이는 자동 unit/UI 테스트로 확인했습니다. VoiceOver 실제 낭독과 Android 렌더링은 이번 실행에서 확인하지 않았습니다.


## 오프라인 날짜 복구 (ADR-0035 D6)

운영 배포 전 `20261001010000_replay_learning_days.sql` 적용 여부를 먼저 확인한다. 테스트용 계정과 실기기에서 다음을 수행하고 실제 실행 결과를 출시 기록에 남긴다.

1. 로그인 후 네트워크를 끊고 학습 활동 하나를 완료한다. 화면 진행은 유지돼야 한다.
2. 앱을 완전히 종료한 뒤 다시 열어 진행이 보존되는지 확인한다.
3. 연결을 복구하면 추가 활동 없이 진행과 완료 날짜가 서버에 반영돼야 한다. 오프라인 학습이 여러 날이면 원래 날짜 각각을 보존한다.
4. 같은 완료를 다시 보내도 서버 날짜 행이 중복되지 않아야 한다. 현재 날짜 기준 연속만 표시하고 과거 기록 복구만으로 축하 모달을 띄우지 않는다.
5. 전송 실패 상태에서 로그아웃 후 다른 계정으로 로그인한다. 이전 계정의 날짜가 새 계정에 저장되면 안 된다. 원래 계정으로 다시 로그인하면 재전송한다.
6. 폐기 가능한 테스트 계정을 삭제하면 서버 진행/날짜 및 기기 미전송 기록이 함께 없어져야 한다. 실제 사용자 계정으로 삭제 테스트를 하지 않는다.

앱 시간을 임의로 바꾸는 대신 날짜 이동은 자동 통합 테스트에서 검증한다. 실기기에서 여러 날짜의 실제 오프라인 사용을 검증하지 않았다면 그 항목을 통과로 적지 않는다.


## 말하기 녹음 조작과 작은 화면

1. 튜토리얼 말하기를 375×812 화면과 더 작은 콘텐츠 영역에서 연다. Skip과 Speak는 하단의 같은 행에서 각각 보여야 한다.
2. 카드가 길면 카드와 안내만 스크롤되고 하단 버튼을 덮지 않아야 한다. 끝까지 내려 파형 아이콘에도 닿을 수 있어야 한다.
3. 카드 파형 아이콘 또는 Speak를 누르면 미요청인 권한만 요청한다. 권한 허용 후 실제 입력을 확인하고, 같은 아이콘 또는 Stop speaking으로 중지해 결과를 받는다.
4. 권한 거부·인식 실패에서는 오답을 만들지 않고 기존 안내와 Skip을 제공한다. Skip이 두 개 나오면 안 된다.
5. 준비 상태의 Skip은 녹음을 시작하지 않고 다음 문항으로 간다. 마지막 문항 뒤에는 완료 화면과 See results가 나온다.
6. 녹음을 마친 뒤 음원 재생, 홈으로 이동 후 복귀해 다시 재생·녹음한다. 실제 마이크·음성 인식 성공은 시뮬레이터의 버튼 상태 변화만으로 판정하지 않는다.

7. iPhone의 받아쓰기를 끈 상태에서 말하기를 시도한다. `kLSRErrorDomain/201`을 받으면 Siri·받아쓰기 설정 안내와 Try again, Skip이 함께 보여야 한다. 설정 → 일반 → 키보드 → 받아쓰기 활성화를 켜고 돌아와 Try again을 누르면 같은 문항을 다시 인식한다. 실패·재시도 자체가 채점이나 건너뛴 횟수를 추가하면 안 된다.

2026-10-01 iPhone 13 mini / iOS 26.6.2 확인: 사용자 확인으로 Skip 겹침이 해소됐다. 마이크·음성 인식 권한과 한국어 인식기 가용 상태는 정상이었지만, 시작 186ms 뒤 입력 버퍼 0개로 `kLSRErrorDomain/201`이 반환됐다. [Apple 문서](https://developer.apple.com/documentation/speech/sfspeechrecognitiontask/error)는 이 값을 Siri 또는 받아쓰기 비활성화로 정의한다. 사용자가 받아쓰기 활성화 후 실제 인식 결과가 나오는 것을 확인했다. 이 확인은 수정 전의 오류 안내를 사용하는 진단 Host에서 이뤄졌으며, 새 안내·같은 문항 재시도는 자동 UI 테스트로 따로 검증한다.

같은 날 최종 수정본(진단 로그 제거, production Lynx 번들을 포함한 Debug Host)을 iPhone에 다시 설치한 뒤, 사용자가 녹음 직후 음원 재생 및 홈 화면 왕복 후 재생·녹음 모두 정상이라고 확인했다.

## 레슨 성공 보상 표시

레슨 통과·만점 화면의 젬 보상은 `+ 0 REWARD`, 맵으로 돌아가는 버튼은 `Back to map`이다. 일반 레슨·서사·메신저·에피소드 최종 복습이 공유하는 기본 보상은 0이며 실제 잔액을 증가시키지 않는다. 미통과의 Try again·나가기 동작은 그대로 확인한다.

롤플레이에서 완료한 메신저·통화·비주얼 노벨은 `Back to list`를 표시하고 롤플레이 목록으로 돌아간다. 여정에서 완료한 경우에는 `Back to map`을 유지한다.
