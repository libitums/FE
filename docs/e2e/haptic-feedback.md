# 학습 판정 진동 — 기기 확인

결정은 [ADR-0109](../adr/0109-haptic-feedback.md)가 진다. 자동 테스트는 정책 표(어느 효과음에 어느 진동) · `playSound`의 결선(효과음 먼저, 진동은 판정 넷에만 한 번) · 옛 호스트 · 모듈 없음에서의 무동작 · 호스트의 문자열 → 플랫폼 상수 분류를 지키지만,
**실제로 손에 느껴지는지 · 시스템 햅틱 설정을 끄면 멈추는지 · 옛 빌드 위에 덮어 깔았을 때 · 햅틱 없는 기기에서 조용한지**는 기기에서만 판정한다.

## 준비

- Android 실기(저가 · 중가, API 30 이상 — 예: Galaxy A52s) · Android API 28 에뮬레이터(26 ~ 29 경로) · iPhone 실기 · iOS 시뮬레이터(Debug 호스트 + `--bundle-url=main.lynx`).
- 판정: 손(진동) · 귀(효과음) · logcat `FATAL` · `AndroidRuntime` · Xcode 콘솔. Android 26 ~ 29 구간은 「진동이 났다」만 판정한다 — 그 구간의 두 상수는 길이 차이만 있고 성공 · 오류를 뜻으로 구별하지 않는다.
- 시스템 설정: Android 「설정 › 소리 및 진동 › 시스템 소리 및 진동 › 터치 피드백」(기기마다 이름이 조금 다르다), iOS 「설정 › 사운드 및 햅틱 › 시스템 햅틱」.

## 접근성 확인

- HF-E5(진동 끔)에서도 정답 · 오답 · 통과 · 미통과가 색 · 모양 · 문구 · 소리로 전달된다 — 진동만으로 전하는 정보가 없다(WCAG 1.3.3).
- `AnswerVerdict` light 면의 흰 잉크 대비 미달은 **변경 없음 · 기존 기록**(`apps/mobile/src/components/answer-verdict-face.ts`)이다. 이 작업이 만들지도 고치지도 않았고, 진동은 1.4.3의 완화책이 아니다.
- 스크린리더(HF-E11 · E12): iOS VoiceOver는 자체 햅틱을 내므로 판정 진동과 수십 ms 안에 겹칠 수 있다. 정보 손실은 없고, VoiceOver 실행 중 진동을 억제하는 코드는 두지 않는다 — 스크린리더와 햅틱을 함께 쓰는 사용자의 채널을 빼앗기 때문이다.

## 실행 기록

### 2026-11-06 — Android 에뮬레이터(Pixel_8 AVD, 읽기 전용, API 37 이미지) · `bundled` · 에이전트 실행, 사람 미확인

- **HF-E6 부분 통과** — 이 메서드가 없는 옛 빌드(0.1.0)가 깔린 상태에서 새 빌드를 `install -r`. `versionName` 1.2.0 · `firstInstallTime` 2026-10-14 그대로 · logcat `FATAL EXCEPTION` 0건(`AndroidRuntime` 다섯 줄은 `monkey` 런처 자체) · 앱 프로세스 생존 · 온보딩 첫 면 정상. **「정답 1회」는 못 했다** — 로그인 뒤 레슨이 필요하고 에뮬레이터에 로그인 수단이 없다. 에뮬레이터에는 진동이 없어 체감 판정은 어차피 실기 몫이다.
- HF-E9는 API 28 AVD가 없어 미실행.

### 2026-11-06 — iOS 시뮬레이터(iPhone 17 Pro) · Debug 호스트 + `--bundle-url=main.lynx`(이 변경의 번들) · 에이전트 실행, 사람 미확인

- **HF-E7 부분 통과** — 호스트 로그 `SoundEffectsModule registered` · 크래시 보고 0 · 로그인 화면까지 평소대로. 정답 · 오답 · 결과 화면은 로그인(소셜 OAuth) 뒤라 시뮬레이터에서 닿지 못했다. HostTests `testHapticNeverThrowsForAnyInput`이 시뮬레이터(햅틱 없음)에서 `haptic("success")` · `haptic("bogus")` · `haptic(nil)`이 던지지 않는 것은 지킨다.
- HF-E1 ~ E5 · E8 · E10 ~ E12는 실기가 필요해 미실행.
