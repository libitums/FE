# 끝낸 에피소드 업데이트 안내 · NEW 태그

끝낸 에피소드에 업데이트로 새 유닛이 생겼을 때 지도 위 가운데 대화상자와 새 유닛의 NEW 태그를 기기에서 확인하는 **수동 절차**다.
결정은 [ADR-0089](../adr/0089-catalog-update-notice.md), 시안은 디자인 캔버스 G-A.

| 이미 지는 층 | 무엇을 |
|---|---|
| unit | 판정(`catalogFreshUnitKeysOf` UF1 · UF2 · UF4) · 서명(UF3) · 기록 읽기 · 띄울지 · 닫은 뒤(UN1 ~ UN3) |
| ui | 대화상자 문구 · 체크 토글 · 닫기 · 시스템 뒤로(UNU1 ~ UNU3) · 지도 NEW 태그 · 낭독 꼬리(UFU1) |
| integration | 진행 조회 → 안내 · 태그 → 닫기 → 저장소 기록 → 다시 켜면 안 뜸 · 체크하면 끔 · 조회 전 · 실패면 안 뜸(UNI1 ~ UNI3) |

**이 문서만 보는 것**: 기기에서의 모습 — 태그 자리(원형 · 스페셜 노드의 어깨), 대화상자 · 체크 행, 시스템 뒤로, 다시 켰을 때.

## 준비

- 최종 테스트까지 끝낸 에피소드가 있는 계정. 그 에피소드의 내장 콘텐츠에 유닛 하나를 더하고 버전을 올린 임시 빌드(회차 뒤 되돌림).
- 기록을 지우려면 앱을 지웠다 다시 깐다(`libitum.catalog-update-notice`).

## 절차

| # | 하기 | 기대 |
|---|---|---|
| CU1 | 앱을 켜 지도에 닿는다 | 진행을 읽은 뒤 가운데 대화상자 — 「Psst, something new! 👀」 · 본문 · 「Cool, got it」 · 「☐ Don't show this again」. 에피소드 이름 · 목록 없음 |
| CU2 | 대화상자 뒤 지도 | 새 유닛 노드 오른쪽 위에 주황 「NEW」 알약. 다른 노드엔 없음 |
| CU3 | 「Cool, got it」 | 닫힘. 태그는 남음 |
| CU4 | 앱을 다시 켠다 | 대화상자가 다시 뜨지 않음 · 태그는 남음 |
| CU5 | 새 유닛을 끝낸다 | 그 노드의 태그가 사라짐 |
| CU6 | (기록을 지우고) 체크 행을 누른 뒤 닫는다 · 다시 켠다 | 체크 표시가 주황 칸 · 흰 체크. 다시 켜도 안 뜸 |
| CU7 | Android 시스템 뒤로 | 「Cool, got it」과 같음 |
| CU8 | VoiceOver | 제목이 머리로 읽히고, 체크 행이 「Don't show this again, not checked / checked」, 태그 노드가 「…, new」 |

## 기록 ⟨2026-10-28⟩

- 회차: iPhone 17 Pro 시뮬레이터(iOS 26.5), Debug 호스트 + 내장 번들. 시험 계정(ADR-0085)으로 로그인한 설치. 내장 u00에 임시 유닛 `S4`(S3 복제)를 더하고 버전을 올린 빌드, 회차 뒤 되돌림.
- CU1 **통과** — 진행을 읽은 뒤 가운데 대화상자(제목 · 본문 · 버튼 · 체크 행), 에피소드 이름 · 목록 없음.
- CU2 **통과** — Lesson 4(S4) 원형 노드 오른쪽 위에 「NEW」. 이 회차에서 결함 둘을 고쳤다: 태그가 글자마다 꺾임(`white-space: nowrap`) · 태그가 노드가 아닌 곳에 서거나 그려지지 않음(표식 무대 안 자리 상자로 옮기고 `z-index`를 뺌).
- CU3 · CU4 · CU6 **통과** — 체크 → 주황 칸 · 흰 체크, 닫으면 기록 `muted: true`, 다시 켜도 안 뜸 · 태그는 남음.
- 관찰: 시험 계정은 유닛을 건너뛰고 최종을 끝낸 에피소드(u03 · u08 · u10)도 「새 유닛」으로 잡혔다 — ADR-0089 대가 1 그대로.
- CU5 · CU7 · CU8(새 유닛 끝내기 · Android 뒤로 · VoiceOver)은 실행하지 않았다.
