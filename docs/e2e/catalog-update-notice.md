# 끝낸 에피소드 업데이트 안내

끝낸 에피소드에 업데이트로 새 유닛이 생겼을 때 지도 위 가운데 대화상자를 기기에서 확인하는 **수동 절차**다. ⟨2026-10-28⟩ 새 유닛의 NEW 태그는 사용자 결정으로 뺐다.
결정은 [ADR-0089](../adr/0089-catalog-update-notice.md), 시안은 디자인 캔버스 G-A.

| 이미 지는 층 | 무엇을 |
|---|---|
| unit | 판정(`catalogFreshUnitKeysOf` UF1 · UF2 · UF4) · 새 유닛 에피소드(UF3) · 기록 읽기 · 띄울지 · 적기 · 맞출지(UN1 ~ UN4) |
| ui | 대화상자 문구 · 체크 토글 · 닫기 · 시스템 뒤로(UNU1 ~ UNU3) |
| integration | 진행 조회 → 안내 → 닫기(버전 기록) → 다시 켜면 안 뜸 · 진행이 바뀌어도 안 뜸 · 버전이 오르면 한 번(UNI4) → → 저장소 기록 → 다시 켜면 안 뜸 · 체크하면 끔 · 조회 전 · 실패면 안 뜸(UNI1 ~ UNI3) |

**이 문서만 보는 것**: 기기에서의 모습 — 대화상자 · 체크 행, 시스템 뒤로, 다시 켰을 때.

## 준비

- 최종 테스트까지 끝낸 에피소드가 있는 계정. 그 에피소드의 내장 콘텐츠에 유닛 하나를 더하고 버전을 올린 임시 빌드(회차 뒤 되돌림).
- 기록을 지우려면 앱을 지웠다 다시 깐다(`libitum.catalog-update-notice`).

## 절차

| # | 하기 | 기대 |
|---|---|---|
| CU1 | 앱을 켜 지도에 닿는다 | 진행을 읽은 뒤 가운데 대화상자 — 「Psst, something new! 👀」 · 본문(「…your progress is safe.」에서 끝) · 「Cool, got it」 · 「☐ Don't show this again」. 에피소드 이름 · 목록 없음 |
| CU2 | 대화상자 뒤 지도 | 새 유닛은 열린 노드로 서고, 노드에 태그는 없음 |
| CU3 | 「Cool, got it」 | 닫힘 |
| CU4 | 앱을 다시 켠다 | 대화상자가 다시 뜨지 않음 |
| CU5 | 새 유닛 하나를 끝내거나 다른 에피소드를 클리어한다 | 뜨지 않음(버전 그대로) |
| CU5b | 그 에피소드 버전이 오른 콘텐츠로 켠다 | 한 번 뜸 |
| CU6 | (기록을 지우고) 체크 행을 누른 뒤 닫는다 · 다시 켠다 | 체크 표시가 주황 칸 · 흰 체크. 다시 켜도 안 뜸 |
| CU7 | Android 시스템 뒤로 | 「Cool, got it」과 같음 |
| CU8 | VoiceOver | 제목이 머리로 읽히고, 체크 행이 「Don't show this again, not checked / checked」 |

## 기록 ⟨2026-10-28⟩

- 회차: iPhone 17 Pro 시뮬레이터(iOS 26.5), Debug 호스트 + 내장 번들. 시험 계정(ADR-0085)으로 로그인한 설치. 내장 u00에 임시 유닛 `S4`(S3 복제)를 더하고 버전을 올린 빌드, 회차 뒤 되돌림.
- CU1 **통과** — 진행을 읽은 뒤 가운데 대화상자(제목 · 본문 · 버튼 · 체크 행), 에피소드 이름 · 목록 없음.
- (그때의 CU2) Lesson 4 노드 어깨의 「NEW」 태그를 봤다 — 이 회차 뒤 태그를 뺐으므로 지금 빌드의 기대가 아니다. 태그가 빠진 지도는 단위 · 통합 테스트로만 봤다.
- CU3 · CU4 · CU6 **통과** — 체크 → 주황 칸 · 흰 체크, 닫으면 기록 `muted: true`, 다시 켜도 안 뜸. 이때 본문은 태그를 가리키던 옛 문장이었다.
- 관찰: 시험 계정은 유닛을 건너뛰고 최종을 끝낸 에피소드(u03 · u08 · u10)도 「새 유닛」으로 잡혔다 — ADR-0089 대가 1 그대로.
- CU5 · CU7 · CU8(또 새 유닛 · Android 뒤로 · VoiceOver)은 실행하지 않았다.
