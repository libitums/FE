# 음성 길이 맞춤 타이핑 (카탈로그 컷)

카탈로그 에피소드의 표지 컷 · 통과 뒤 컷에서 대사 타자기가 **음성 길이에 맞춘 속도로 쓰여 말소리 끝과 함께 끝나는지**,
음성 정보 파일이 없거나 그 음성의 항목이 없을 때 **지금처럼 글자당 35ms인지**, 동작 줄이기에서 **즉시 전체**인지를 기기에서 확인하는 **수동 절차**다.
결정은 [ADR-0074](../adr/0074-voice-synced-typing.md), 화면은 [화면 명세](../screens.md) 「여정 탭」의 카탈로그 표지(컷) 행,
음성 정보 파일의 형식 · 지금의 값은 [콘텐츠 계약](../specs/episode-content-json-contract.md) 부록 E가 진다. 소리가 언제 나고 멈추는지는 [에피소드 음성 e2e](episode-audio.md)가 진다.

| 이미 지는 층 | 무엇을 |
|---|---|
| unit | 정보 파일 해석(파일 단위 · 항목 단위 버림) · 맞출 길이(`speech_end_ms` 우선 · 넘치면 `duration_ms`) · 받기 결과 여섯 갈래(저장 · 유지 · 지움) · 글자 간격 식([35, 300]) · 컷 뷰의 길이 |
| ui | 뷰의 길이가 첫 렌더부터 타자기 간격이 되는지 · 컷마다 바뀌는지 · 항목 없는 컷 35 · 동작 줄이기 즉시 · 쓰는 중 탭 완성 |
| integration | 앱을 띄워 받기 한 차례에서 에피소드 받기 뒤 정보 파일을 받고 · 저장하고 · 화면 간격까지 닿는지, 실패 · 없음 · 오프라인이 흐름을 막지 않는지 |

**이 문서만 보는 것**: 실제 재생 시작 지연 위에서 **글 끝이 귀로 듣는 말소리 끝과 맞는지**, 끝 무음(`speech_end_ms`)을 어떻게 볼지 — 둘 다 기기에서만 판정된다.
Maestro 흐름은 두지 않는다 — 소리와 글 끝의 시각 대조는 접근성 트리로 판정할 수 없다.

## 전제

- [공통 전제](README.md#공통-전제) — 자체 호스트 앱, 로그인된 상태.
- iOS: iPhone 17 Pro 시뮬레이터, Release 호스트 + 내장 번들(`--bundle-url=main.lynx`)([README 「자동화」](README.md#ios)). Debug 호스트는 dev 서버를 읽어 다른 작업 트리의 코드가 뜰 수 있다.
- `apps/mobile/.env.local`에 Supabase 값이 있어야 음성 · 정보 파일 주소가 만들어진다(설정이 없으면 늘 무음 · 35ms다). 값은 기록에 적지 않는다.
- **정보 파일이 버킷에 있어야 한다**(VTE1 · VTE2 · VTE4 ~ VTE6) — 납품본 또는 앱 쪽이 지금 음성 16개를 재 만든 판(부록 E 「지금의 판」)을 버킷 `content`의 `audio/manifest.json`에 올린다.
  **올리기 · 내리기는 외부 반영이라 사용자 확인 뒤에만 한다.** 올린 뒤 공개 주소가 200인지 먼저 본다(2026-10-19 올라감 — 200). CDN 캐시 때문에 올린 직후에는 옛 응답이 올 수 있다.
- 앱은 실행 시작 · 연결 복귀 · 포그라운드 복귀 때 정보 파일을 받는다. 올린 뒤에는 **앱을 완전히 종료했다가 다시 켠다** — 켠 직후 받기 한 차례가 끝나기 전에 표지를 열면 컷이 35ms로 섰다가 처음부터 다시 쓰일 수 있다(ADR-0074 「대가」 1). 켠 뒤 몇 초 기다리고 연다.
- 판정은 **눈 · 귀 + 화면 녹화**다. 녹화(`xcrun simctl io <UDID> recordVideo`)에서 컷이 선 프레임과 대사 마지막 글자가 선 프레임의 시각 차를 읽고, 말소리 끝은 귀와 정보 파일 값으로 대조한다. 허용 오차는 **±0.3초**다.

### 기대 시간 (정보 파일 값 · 글자 수에서)

| 컷 | 대사 · 글자 수(code point) | 정보 파일 | 간격 | 글이 다 서는 때 | 정보 파일이 없을 때 |
|---|---|---|---|---|---|
| u02 표지 컷 1 | 「사장님, 손님 오셨어요!」 · 13 | `u02-checkin/pre-1` 2027 · 2027 | 155 ms | 약 2.0초 | 약 0.46초 |
| u01 표지 컷 3 | 「어서 오세요.」 · 7 | `u01-water/pre-3` 2299 · 1763(끝 무음 0.54초) | 251 ms(`duration_ms`만이면 300 — 상한) | 약 1.76초(`duration_ms`만이면 약 2.10초) | 약 0.25초 |

## 관찰 항목 (VTE1 ~ VTE7 · VTA1)

통과·실패는 `통과` / `실패: <관찰>` / `판정 불가: <이유>` / `미실행`으로만 적는다.

| id | 단계 | 관찰(통과 조건) |
|---|---|---|
| VTE1 | 정보 파일을 올린 뒤 앱을 다시 켠다 → 맵 → u02 표지 화면 → `Next` → 컷 1 | 글이 소리와 함께 쓰이기 시작하고 **말소리 끝 무렵(±0.3초)** 약 2.0초에 대사가 다 선다. 정보 파일이 없을 때(약 0.46초)보다 확연히 느리다 |
| VTE2 | u01 표지 → `Next` → 컷 3 「어서 오세요.」 | 약 1.76초(말 끝)에 다 서고 그 뒤 약 0.5초 동안 소리 꼬리(무음)만 남는다. **끝 무음 판단 자료** — 말 끝에 맞춘 것이 자연스러운지 · 파일 끝(약 2.30초)에 맞춰야 하는지를 기록에 적는다(ADR-0074 재검토 조건 1) |
| VTE3 | 정보 파일이 **없는** 상태(올리기 전 지금 버킷 · 또는 VTE7 뒤)에서 VTE1 · VTE2의 컷, 그리고 정보 파일이 있어도 소리 없는 컷(u01 컷 4) | 모두 지금처럼 빠르다(글자당 35ms — u02 컷 1 약 0.46초, u01 컷 3 약 0.25초). 소리 · 버튼 · 번역 토글은 [에피소드 음성 e2e](episode-audio.md) S1 그대로 |
| VTE4 | VTE1 컷에서 쓰는 중 `Next` → 다시 `Next` | 첫 `Next`에 대사가 **즉시** 다 서고 소리는 계속 난다. 두 번째 `Next`가 컷을 넘기며 소리가 끊긴다 |
| VTE5 | 설정 → 손쉬운 사용 → 동작 줄이기 켬 → 앱을 다시 켜서 VTE1 | 컷이 서는 순간 대사가 **처음부터 전체**다(타이핑 없음). `Next` 한 번에 넘어가며 소리가 끊긴다 |
| VTE6 | VTE1을 한 번 마친 뒤 비행기 모드를 켜고 앱을 완전히 종료했다가 다시 켜서 VTE1 | VTE1과 같다(기기에 저장한 정보 파일). 소리는 받아 둔 파일이 있을 때만 난다([백그라운드 받기 e2e](episode-background-download.md) EB3) — 소리가 없으면 글 속도만 본다 |
| VTE7 | (사용자가 허락할 때만) 버킷에서 정보 파일을 내리고(공개 주소 400 확인) 연결된 상태로 앱을 다시 켠다 → VTE1 컷 | 35ms로 돌아간다(서버에 없으면 기기 저장본을 지운다). 허락이 없으면 `미실행 — 외부 반영` |
| VTA1(권장) | Android 에뮬레이터에서 VTE1 · VTE4 | iOS와 같은 결과 |

- 원격 스트리밍(받아 둔 음성 파일이 없는 설치)에서는 재생 시작이 늦어 글이 소리보다 조금 먼저 갈 수 있다 — 끝이 말소리 끝 **이전**이면 통과로 보고, 시작 지연이 0.3초를 넘으면 그 값을 기록에 적는다(ADR-0074 재검토 조건 2).

## 실행 기록

| 날짜 | 기기 | 빌드 | VTE1 | VTE2 | VTE3 | VTE4 | VTE5 | VTE6 | VTE7 | VTA1 |
|---|---|---|---|---|---|---|---|---|---|---|
| 2026-10-19 | iPhone 17 Pro 시뮬레이터(FE-catalog-e2e, iOS 26) | `feat/voice-synced-typing` 86619674, Debug 호스트(같은 브랜치 빌드) + `--bundle-url=main.lynx` | 통과(u03 대체 — 아래 1) | 미실행 | 통과(소리 없는 컷 — 아래 2) | 미실행 | 미실행 | 미실행 | 미실행 — 외부 반영 | 미실행 |

**2026-10-19 회차 메모.** 정보 파일은 사용자가 버킷에 올렸다(공개 주소 200, 내용이 앱 쪽 실측판 16항목과 같음, `cache-control: max-age=3600`). 시뮬레이터 화면을 녹화하고 초당 4장으로 뽑아 대사가 다 서는 시점을 셌다(녹화에 소리가 없어 소리 끝은 정보 파일 값으로 본다).

1. **VTE1 대체 — u03 표지 → `Next` → `Next` → 컷 2** 「아, 캐리어는 침대 밑에 넣으면 돼요. 저도 거기 넣었어요.」(33자, `u03-mina/pre-2` 말 끝 4,894ms → 간격 148ms, 예상 4.88초). 컷이 선 뒤 약 4.75 ~ 5.0초에 대사가 다 섰고(±0.25초 — 표집 간격), 그 사이 한 글자씩 고르게 늘었다. 35ms였다면 약 1.2초다. 맵 위치상 u02 대신 u03을 썼다 — 판정 기준(말 끝 ±0.3초)은 같다.
2. **VTE3 일부 — 같은 표지의 컷 1(소리 없는 나레이션)** 은 약 1초 안에 다 섰다 — 지금 속도(35ms) 그대로.
3. 호스트는 #273 이전 빌드가 설치돼 있어 같은 브랜치로 다시 빌드해 설치했다(`pod install` 뒤 `project.pbxproj` 되돌림).
4. **확인자 · 수용** — 화면 녹화와 판정은 에이전트가 했고(사람이 귀로 듣지 않음), 사용자가 이 회차를 부분 확인으로 받아들였다(2026-10-19). 절차의 전제(Release 호스트)와 달리 Debug 호스트 + `--bundle-url=main.lynx`로 돌았다 — 번들은 앱에 넣은 같은 브랜치 빌드라 dev 서버를 읽지 않았다.
5. 남은 항목(VTE2 끝 무음 판단 · VTE4 탭 완성 · VTE5 동작 줄이기 · VTE6 오프라인 · VTA1)은 실기 · 에뮬레이터 회차에서 본다. VTE4 · VTE5는 ui 테스트(VT5 · VT6)가 같은 동작을 고정한다.
