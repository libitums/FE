# 롤플레이 목록 — 특별 유닛을 연습 모드로 연다 — iOS Release 수동 e2e

> ⟨2026-09-29 — UI 문구표⟩ **앱의 안내 · 버튼 · 판정 · 접근성 이름 · 제목 · 이름이 영어로 바뀌었다**
> ([ADR-0031](../adr/0031-ui-language-catalog.md)). 이 절차 · 기대값 · 실행 기록의 한국어 라벨은 **바뀌기 전 값**이다 —
> 누를 것 · 들릴 것은 ADR-0031 부록의 대응표로 영어로 읽는다(예: `맵으로` → `Back to map`, `, 선택됨` → `, selected`).
> 학습 콘텐츠(제시문 · 보기 칩 · 대사 · 받아쓰기 대상 · 문화 노트의 「」 안)는 한국어 그대로다. 날짜가 박힌 실행
> 기록은 고치지 않는다. 영어 UI 전체를 한 번에 훑는 절차는 [UI 언어 e2e](ui-language.md)다.

## 판정 채널과 범위

이 문서는 롤플레이 탭의 목록에서 메신저·전화·비주얼 노벨 세 특별 유닛을 **연습 모드**로
여는 흐름을 iOS Release Host와 실기기에서 확인하는 수동 functional·Dynamic Type·VoiceOver
e2e 절차다. 저장소 profile에는 `test.e2e` 명령과 runner가 없다 — **자동 E2E: not
applicable(runner/command 없음)**이며, 이 계층의 「테스트를 쓰는 행위」는 이 흐름 문서를
세우는 것 자체다(LIB-247 §6.4(d)).

F1–F8·D1은 시뮬레이터에서 먼저 돌 수 있다(카페 도착 비주얼 노벨 e2e 선례,
[visual-novel.md](visual-novel.md)). 그러나 그 결과만으로 `e2e-red`의 `moot` 값을 주장하지
않는다. **V1–V3은 iPhone 실기 · Release · VoiceOver로 사람만 판정한다** — Simulator나
정적/UI/integration 결과로 대체하지 않는다. V가 돌지 않으면 `e2e-implementation` →
`e2e-green` → `documentation` → `review`가 전부 서지 않는다
(`.agent-harness/work/lib-255/spec.md` §12.2, LIB-247 §6.4(e)와 같은 사슬).

**이벤트는 이 문서의 판정 항목이 아니다.** 운영 이벤트 sink가 현재 명시적 `null`이라
기기에서 이벤트 전송 여부를 관측할 수 없다(spec §7.5). 세 유닛의 이벤트·payload는
integration 계층(`App.roleplay.integration.test.tsx` 등)이 진다.

정확한 제품 문자열과 testid는 다음을 정본으로 삼는다. 이 문서에 없는 이름이나 ID를 현장에서
새로 만들지 않는다. 기능 계약의 요약은 [롤플레이 목록 스펙](../specs/roleplay-list.md)에 있다.

- `apps/mobile/src/screens/roleplay-list/roleplay-list.contract.ts`
- `apps/mobile/src/screens/messenger/messenger.contract.ts`
- `apps/mobile/src/screens/phone-call/phone-call.contract.ts`
- `apps/mobile/src/screens/visual-novel/visual-novel.contract.ts`
- `apps/mobile/src/lib/special-unit-entry-source.ts`(나가기 라벨 `맵으로`/`목록으로`의 어휘 정본)

## 전제

공통 전제([docs/e2e/README.md](README.md)) + **Release Host** + **완료 기록이 없는 새 앱
세션**. 각 행의 결과에는 `통과` 또는 `실패: <관찰>`만 기록하고, 추정이나 인상은 넣지 않는다.
아직 돌지 않은 행은 `미실행`, 아직 채우지 않은 증거는 `미기록`으로 둔다 — 결과 값이 아니라
결과가 아직 없다는 표시다([전화](phone-call.md) · [메신저](messenger.md) ·
[비주얼 노벨](visual-novel.md) 흐름과 같은 표기).

## 기능 여정 F1–F8

완료 기록이 없는 새 앱 세션에서 시작한다.

| ID | 절차와 관찰 기준 | 결과 |
|---|---|---|
| F1 | 바텀 네비게이션의 롤플레이 탭을 누른다. `roleplay-list-screen-title`이 `롤플레이`로 뜨고, `roleplay-list-screen-list` 안에 항목이 정확히 **셋**, 순서가 `roleplay-list-item-appointment-confirmation` → `roleplay-list-item-appointment-confirmation-phone-call` → `roleplay-list-item-cafe-arrival-visual-novel`인지 확인한다. 세 항목의 제목/형태 텍스트가 각각 `약속 확인 메시지`/`메신저`, `약속 확인 전화`/`전화`, `카페에 도착한 지민`/`비주얼 노벨`인지 확인한다. 체크 아이콘 · `완료됨` · `잠김` · 흐린(dimmed) 모양이 **0건**인지 확인한다. | 미실행 |
| F2 | 메신저 항목(`roleplay-list-item-appointment-confirmation`)을 누른다 → 화면의 나가기를 누른다 → 바텀 네비게이션의 여정 탭을 누른다. 누른 직후 `messenger-screen`이 뜨고 바텀 네비게이션의 선택이 롤플레이로 유지되는지 확인한다. `messenger-screen-progress`가 `대화 1 / 2`이고, 나가기 텍스트가 `목록으로`인지 확인한다. 나가기를 누르면 `roleplay-list-screen-title`로 돌아오는지 확인한다. 이어서 여정 탭을 누르면 여정 맵 루트(화면 제목 `여정 맵`)가 서고 메신저 화면이 남아 있지 않은지 확인한다. | 미실행 |
| F3 | 전화 항목(`roleplay-list-item-appointment-confirmation-phone-call`)을 누른다 → 나가기를 누른다. `phone-call-status`가 `통화 준비`, `phone-call-audio-button`이 `통화 시작`이고, transcript가 1개, 음성 자동 재생 횟수가 `0`인지 확인한다. 나가기 텍스트가 `목록으로`이고 누르면 목록으로 돌아오는지 확인한다. | 미실행 |
| F4 | 비주얼 노벨 항목(`roleplay-list-item-cafe-arrival-visual-novel`)을 누른다 → 나가기를 누른다. `visual-novel-progress`가 `장면 1 / 3`이고 beat가 `visual-novel-scene-arrive`인지 확인한다. 나가기 텍스트가 `목록으로`이고 누르면 목록으로 돌아오는지 확인한다. | 미실행 |
| F5 | 여정에서 메신저를 완료 · 전화를 완료 · 비주얼 노벨을 `find`까지 진행하고 각각 나간 뒤, 롤플레이에서 세 항목을 차례로 연다. 이어서 여정에서 비주얼 노벨을 완료하고 롤플레이에서 다시 연다. 매번 F2–F4와 같은 **처음 상태**(메신저 `대화 1 / 2`, 전화 `통화 준비`/`통화 시작`/transcript 1개, 비주얼 노벨 `arrive`·`장면 1 / 3`)로 열리는지 확인한다. 비주얼 노벨은 여정에서 미완료일 때와 완료된 뒤 두 경우 모두 `arrive`·`장면 1 / 3`로 열려야 한다. | 미실행 |
| F6 | 새 앱 세션에서 여정 맵의 일반 스텝 다섯 상태를 적는다 → 롤플레이에서 세 항목을 각각 끝까지 본다(메신저 마지막 메시지 · 전화 `통화 완료` · 비주얼 노벨 `이야기 완료`) → 여정 탭으로 이동한다. 일반 스텝 다섯이 `done`·`done`·`current`·`locked`·`locked`에서 그대로인지 확인한다. 특별 항목 셋이 여정 맵에서 미완료 표시(`, 완료됨` 접미사 없음) 그대로인지 확인한다. 여정에서 메신저를 열면 `대화 1 / 2`로 처음부터 시작하는지 확인한다. | 미실행 |
| F7 | 여정 맵에서 세 특별 유닛을 차례로 연다. 각 화면의 나가기 텍스트가 모두 `맵으로`이고, 누르면 여정 맵으로 돌아오는지 확인한다. | 미실행 |
| F8 | 롤플레이에서 메신저 항목을 열고 답장을 하나 누른 뒤 설정 탭 → 롤플레이 탭 순서로 이동한다. 메신저 화면이 롤플레이 탭 스택에 그대로 서 있고, `대화 1 / 2`로 처음부터인지 확인한다(탭 전환이 연습 세션을 초기화하지 않는다). | 미실행 |

## Dynamic Type 판정 D1

D1은 **판정이다**(r1 — 기록에서 판정으로 바뀌었다. spec §12.1 · §14 Q-5). Q-5는 2026-09-15
사용자 결정 K-1(design §6.3 2회차)로 이번 단위에서 닫혔다 — 비주얼 노벨 나가기를 메신저·전화처럼
머리 행의 첫 흐름 자식으로 옮기고 제목의 고정 여백을 지웠다(§2.9). 그 결과 이 항목은 배율과
겹침 여부를 그대로 적는 관찰 기록이 아니라 **AX5까지 겹침 0을 확인하는 통과/실패 판정**이다.
결과 칸에는 `통과` 또는 `실패: <배율 · 관찰>`만 쓴다.

| ID | 절차와 관찰 기준 | 결과 |
|---|---|---|
| D1 | Dynamic Type을 기본에서 최대(AX5, `accessibility-extra-extra-extra-large`)까지 올리며 F1의 목록, 롤플레이에서 연 세 화면(F2–F4)의 나가기, **여정에서 연 비주얼 노벨(F7)의 나가기**를 본다. 항목이 세로로 자라고 흐름(목록) 영역만 스크롤되며, 화면 제목 `롤플레이`는 고정돼 있는지 확인한다. **비주얼 노벨은 두 경로 모두 — 롤플레이 `목록으로` · 여정 `맵으로` — AX5까지 나가기 글자와 제목 · 진행 글자의 겹침이 0인지 확인한다**(r1 R2, design §2.9). 나가기는 머리 행의 첫 자리에 서고 눌리는지도 확인한다. | 미실행 |

한 항목이라도 겹침·잘림·눌림 불가가 관찰되면 `실패: <배율 · 관찰>`로 적는다 — 어느 배율에서
처음 보였는지, 겹친 두 요소가 무엇인지 그대로 적는다. D1 실패는 `e2e-red`의 `confirmed` 근거이고,
`e2e-red`의 `moot`가 요구하는 「전 항목 통과」에도 D1이 든다(spec §12.2).

## VoiceOver 여정 V1–V3 — 실기 · 사람만

동일한 Release Host를 **실제 iPhone**에서 실행하고 VoiceOver를 켠다. Simulator나 정적/UI
테스트는 이 판정을 대체하지 않는다. 자동 announcement나 임의 focus 이동은 기대하지 않는다.

| ID | 절차와 관찰 기준 | 결과 |
|---|---|---|
| V1 | VoiceOver를 켠 채 목록을 처음부터 훑는다. 제목이 `롤플레이, 머리말`로 읽히는지 확인한다. 항목마다 **정지가 정확히 하나**이고, 각각 `약속 확인 메시지, 메신저, 버튼` · `약속 확인 전화, 전화, 버튼` · `카페에 도착한 지민, 비주얼 노벨, 버튼`으로 읽히는지 확인한다. 항목 안의 제목과 형태가 따로 정지해 읽히지 않는지, `완료됨`·`잠김` 낭독이 **0회**인지 확인한다. | 미실행 |
| V2 | VoiceOver를 켠 채 롤플레이와 여정에서 각각 연 세 화면(메신저·전화·비주얼 노벨)의 나가기를 읽는다. 롤플레이에서 연 경우 `목록으로, 버튼`으로, 여정에서 연 경우 `맵으로, 버튼`으로 읽히는지 확인한다. | 미실행 |
| V3 | VoiceOver를 켠 채 롤플레이에서 비주얼 노벨을 끝까지 본 뒤 `처음부터 보기`를 누르고 다시 끝까지 본다. 마지막 장면 전이마다 `이야기 완료`가 들리는지 확인한다. | 미실행 |

## 이벤트 운영 범위

메신저·전화·비주얼 노벨 세 이벤트 sink의 현재 제품 진입점은 명시적 `null`이다. 따라서 이
문서의 어떤 관찰도 이벤트가 실제 운영 집계로 전송되었다는 증거로 쓰지 않는다. 운영 sink
연결과 서버 집계는 별도 후속 범위다. ⟨**2026-09-29** — 제품 진입점이 이제 sink를 PostHog로 잇는다(키가 있는 빌드만, [ADR-0029](../adr/0029-product-analytics-posthog.md)). 이 문서의 판정은 그대로이고, 전송 관찰은 [분석 e2e](analytics.md) 한 곳에 모은다⟩

## 에피소드 구획 · 해금 뒤에 더해진 확인 (2026-09-28)

롤플레이 화면이 디자인(Figma 76-692)을 따라 에피소드 구획으로 바뀌고, 에피소드 단위로
열리게 됐다. 위 표는 고치지 않고 여기에 덧붙인다 — 위 표가 가리키는 spec이 아직 옛
모양을 적고 있다.

**위 표에서 달라진 자리**

- 롤플레이는 **여정에서 그 에피소드의 유닛을 모두 끝내야** 열린다. 위 F 항목들은 롤플레이
  항목을 곧장 여는 것을 전제하므로, 여정의 여덟 유닛을 먼저 끝낸 뒤에 돈다.
- 항목은 줄 항목이 아니라 카드이고, 세로로 쌓이지 않고 **가로로 넘긴다.**
- V1의 「`잠김` 낭독 0회」는 **열린 에피소드에서만** 참이다. 잠긴 에피소드는 잠김을 읽는다.

|---|---|---|---|---|
| E1 | 앱을 처음 켠 진행(스텝 둘 완료)에서 롤플레이 탭을 누른다 | 구획 하나(`Episode 0.` / `Tutorial.`). 카드 셋이 흐린 막과 자물쇠를 얹고 있다. `전체 보기`가 없다 | 시뮬레이터 또는 실기 | 통과 — iPhone 17 Pro 시뮬레이터 · iOS 26.5 · Release, 2026-09-28 |
| E2 | E1에서 잠긴 카드를 누른다 | 아무 일도 일어나지 않는다. 롤플레이 화면 그대로다 | 〃 | 미실행 |
| E3 | 카드 줄을 왼쪽으로 민다 | 카드가 옆으로 넘어가 셋째 카드가 온전히 보인다. 화면은 세로로 움직이지 않는다 | 〃 | 통과 — 위와 같은 환경(134pt 넘어감) |
| E4 | 여정에서 유닛 여덟을 모두 끝낸 뒤 롤플레이 탭을 누른다 | 막과 자물쇠가 사라지고 `전체 보기`가 선다. 카드를 누르면 그 유닛이 처음부터 열린다 | 〃 | 미실행 — 열린 모양은 진행을 끝난 값으로 바꾼 임시 번들로만 봤다 |
| E5 | 여정에서 일곱만 끝내고 롤플레이 탭을 누른다 | 여전히 잠겨 있다 | 〃 | 미실행 |
| E6 | 열린 구획에서 `전체 보기`를 누른다 | 그 에피소드의 카드가 세로로 줄 폭에 펼쳐진 화면. 머리는 동그란 뒤로 버튼과 가운데 제목(`Episode 0. Tutorial.`). 바텀 탭 `롤플레이` 선택 유지 | 〃 | 미실행 — 위와 같은 임시 번들로만 봤다 |
| E7 | E6에서 뒤로 버튼을 누른다 | 롤플레이 화면 | 〃 | 미실행 |
| E8 | E6에서 카드를 열고 `목록으로`를 누른다 | 펼친 화면이 아니라 **롤플레이 화면**(스택의 루트, ADR-0007 D6) | 〃 | 미실행 |
| E9 | 롤플레이 화면을 세로로 스크롤하며 손가락이 카드 줄 위를 비스듬히 지난다 | 세로 스크롤이 끊기지 않는다. 카드 줄이 멋대로 넘어가지 않는다 | **실기** | 미실행 |
| E10 | VoiceOver로 잠긴 구획을 훑는다 | `Episode 0. Tutorial., 잠김, 여정에서 이 에피소드를 끝내면 열립니다, 머리말` → 카드마다 `<제목>, <형태>, 잠김`(버튼이라고 읽지 않는다). 화면 밖에 있는 셋째 카드에 순회로 닿는다 | **실기 · 사람만** | 미실행 |
| E11 | Dynamic Type을 최대(AX5)까지 올린다 | 카드 제목이 두 줄까지 자라고 카드 밖으로 넘치지 않는다. 구획 머리와 `전체 보기`가 겹치지 않는다 | 시뮬레이터 또는 실기 | 미실행 |

E9 · E10은 시뮬레이터가 답하지 못한다. 세로 스크롤 안에 가로 스크롤이 든 구조라, 두
스크롤이 제스처를 어떻게 나눠 갖는지는 손가락으로만 보인다.

**카드에 그림이 없다.** 디자인은 카드마다 인물 그림을 깔지만 자산이 아직 없어 어두운
면만 그린다. 그림이 오면 E1 · E4를 다시 본다.

## 플러스 줄 뒤에 더해진 확인 (2026-09-28)

⟨2026-10-01 — 심사 빌드⟩ 결제와 유료 롤플레이 콘텐츠가 제공되기 전까지 실제 앱은
Plus 항목을 롤플레이 구획에 싣지 않는다. 아래 P1~P11은 이전 구현의 확인 기록으로
남긴다. 현재 빌드에서는 잠긴 에피소드와 열린 에피소드 모두 기본 카드만 보이고,
Plus 줄·카드·안내 창이 없어야 한다.

에피소드 구획에 결제 사용자를 위한 롤플레이 줄(플러스)이 더해졌다. **디자인 없이 정해
그린 자리다** — 아래 기대는 디자인이 아니라 구현이 정한 모양을 적는다.

결제도 결제 롤플레이의 컨텐츠도 아직 없다. 그래서 플러스 카드는 **열 수 있는 화면이
없는 예고**이고, 「결제해서 열린」 상태는 오늘 볼 수 없다.
