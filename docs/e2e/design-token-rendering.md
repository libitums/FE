# 디자인 토큰과 아이콘이 호스트에서 실제로 칠해진다

전제: 자체 호스트 앱. `pnpm bundle:host`로 번들을 넣고 Xcode에서 빌드한 상태

Debug 빌드는 dev 서버를 보므로, 앱 번들에 들어간 산출물로 판정하려면 실행 인자를 준다.

```
xcrun simctl launch booted com.libitum.host --bundle-url=main.lynx
```

단계:
1. 앱을 새로 띄운다(첫 화면 = 여정 맵. LIB-257로 홈이 걷혔다)
2. 제목과 알림 버튼(종 아이콘 + 낱말 `알림`)이 나란히 있는 여정 맵 머리를 본다

**새 대상 요소**: 여정 맵 머리(제목 + 알림 버튼) — 홈 머리가 사라진 뒤 이 저장소에서 아이콘 +
문구가 나란히 서는 화면 머리 중 진입 즉시 보이는 유일한 후보다(design.md §2).

관찰:
- **아이콘이 보인다.** 크기는 24pt(`icon.size.md`)
- 아이콘 색이 **검정(`#000000`)이 아니라 `#555D6D`**(`color.fg.neutral-muted`)이다 — 값이
  바뀌었다. 옛 홈 머리 아이콘은 `fg-neutral`(`#1A1C20`)이었지만 알림 버튼 아이콘은
  `fg-neutral-muted`다(design.md §1.1 · §2.2)
- 화면 좌우에 **16pt 여백**이 있다 (`layout.screen.padding-x`) — 화면 루트 선언은 기존 그대로다
- 화면 위쪽 여백은 **12pt**다 (`layout.screen.padding-top`) — 좌우와 값이 다르다
- 버튼 안 아이콘과 낱말 사이에 **4pt 간격**이 있다 (`spacing.4`) — 값이 바뀌었다. 옛 홈 머리의
  아이콘-제목 간격은 8pt(`spacing.8`)였지만 알림 버튼 내용 줄은 `spacing-4`다(design.md §2.2)
- 배경이 흰색이 아니라 **크림색 `#FFFDFC`**다 (`color.background.primary`)

> **이 체크리스트는 실제로 돌려봤다 (2026-09-01, 옛 홈 화면 머리 기준).** 위 관찰이 모두
> 성립하는 것을 iPhone 17 시뮬레이터에서 확인했다. 아이콘 색은 스크린샷의 픽셀을 직접 읽어
> `#1A1C20`인 것을 확인했다 — 눈으로는 검정과 구별되지 않는다. **LIB-257로 그 화면(홈 머리)이
> 걷혔다 — 이 기록은 그 회차에 참이던 관찰이고, 이후 회차는 위 여정 맵 머리 관찰과 새 색·간격
> 값으로 갱신한다.**

## 왜 이 흐름이 여기 있나

**토큰이 안 먹는 실패는 조용하다.** `var(--오타)`도, Lynx가 풀지 못하는 값도 에러 없이
선언째로 사라진다(ADR-0014 D1). 화면은 그냥 밋밋하게 뜬다.

**자동 테스트가 이것을 덮지 못한다.** 테스트 환경이 jsdom 기반이라 계산된 스타일을 볼 수
없다(ADR-0006 D4). `JourneyMapScreen.notifications.ui.test.tsx`는 testid와 접근성 속성이
붙는 것까지만 확인하고, **그 값이 실제로 칠해지는지는 확인하지 못한다.**

**검정과 `#1A1C20`을 구별하는 것이 핵심이다.** 아이콘 색이 안 먹으면 SVG 원본의
fallback인 순수 검정으로 렌더된다. 둘은 눈으로 구별되지 않으므로, 색 경로가 끊긴 것을
눈으로는 알 수 없다. 그래서 이 관찰만 픽셀 값으로 적었다.

한 번 이렇게 깨졌다 — 배포된 토큰 CSS의 별칭이 Lynx에서 풀리지 않아 padding·gap이
사라지고 아이콘이 크기를 못 받아 **아예 보이지 않았다**. 위 다섯 줄은 그때 하나씩
확인한 것들이다.
