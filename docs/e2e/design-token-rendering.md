# 디자인 토큰과 아이콘이 호스트에서 실제로 칠해진다

전제: 자체 호스트 앱. `pnpm bundle:host`로 번들을 넣고 Xcode에서 빌드한 상태

Debug 빌드는 dev 서버를 보므로, 앱 번들에 들어간 산출물로 판정하려면 실행 인자를 준다.

```
xcrun simctl launch booted com.libitum.host --bundle-url=main.lynx
```

단계:
1. 홈 화면을 띄운다
2. 아이콘과 제목이 나란히 있는 헤더를 본다

관찰:
- **아이콘이 보인다.** 크기는 24pt(`icon.size.md`)
- 아이콘 색이 **검정(`#000000`)이 아니라 `#1A1C20`**(`color.fg.neutral`)이다
- 화면 좌우에 **16pt 여백**이 있다 (`layout.screen.padding-x`)
- 아이콘과 제목 사이에 **8pt 간격**이 있다 (`spacing.8`)
- 배경이 흰색이 아니라 **크림색 `#FFFDFC`**다 (`color.background.primary`)

> **이 체크리스트는 실제로 돌려봤다 (2026-09-01).** 위 다섯 관찰이 모두 성립하는 것을
> iPhone 17 시뮬레이터에서 확인했다. 아이콘 색은 스크린샷의 픽셀을 직접 읽어 `#1A1C20`인
> 것을 확인했다 — 눈으로는 검정과 구별되지 않는다.

## 왜 이 흐름이 여기 있나

**토큰이 안 먹는 실패는 조용하다.** `var(--오타)`도, Lynx가 풀지 못하는 값도 에러 없이
선언째로 사라진다(ADR-0014 D1). 화면은 그냥 밋밋하게 뜬다.

**자동 테스트가 이것을 덮지 못한다.** 테스트 환경이 jsdom 기반이라 계산된 스타일을 볼 수
없다(ADR-0006 D4). `HomeScreen.ui.test.tsx`는 클래스 이름과 `current-color` 속성이 붙는
것까지만 확인하고, **그 값이 실제로 칠해지는지는 확인하지 못한다.**

**검정과 `#1A1C20`을 구별하는 것이 핵심이다.** 아이콘 색이 안 먹으면 SVG 원본의
fallback인 순수 검정으로 렌더된다. 둘은 눈으로 구별되지 않으므로, 색 경로가 끊긴 것을
눈으로는 알 수 없다. 그래서 이 관찰만 픽셀 값으로 적었다.

한 번 이렇게 깨졌다 — 배포된 토큰 CSS의 별칭이 Lynx에서 풀리지 않아 padding·gap이
사라지고 아이콘이 크기를 못 받아 **아예 보이지 않았다**. 위 다섯 줄은 그때 하나씩
확인한 것들이다.
