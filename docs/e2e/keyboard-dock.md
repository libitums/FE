# 자판 바닥 붙이기 — 메신저 · 타자 입력의 자판 면이 화면 아래 · 좌우 끝까지

앱 자판(`MessengerKeyboard`)의 흰 면이 바텀시트처럼 화면 아래 · 좌우 끝에 닿고, 키는 안전 영역 안(홈 인디케이터 · 시스템 바 위)에 서는지를 확인하는 **수동 절차**다.
자판이 없는 국면 · 다른 화면의 아래 여백이 그대로인지(회귀 없음)도 함께 본다.
결정은 [ADR-0070](../adr/0070-keyboard-dock.md), 화면은 [화면 명세](../screens.md)의 타자 입력 행 · 메신저 문단, 메신저 트리 · test-id는 [메신저 특별 유닛 계약](../specs/messenger-special-unit.md)이 진다.

| 이미 지는 층 | 무엇을 |
|---|---|
| unit | 세 변 뽑기(`keyboardDockEdgesOf` — `top` 버림 · 유한한 양수 아니면 0) · 몸통 · 키 줄 묶음 인라인 여백 · 셸 모드(`shellEdgeModeFor` — full-bleed 먼저 · 메신저 둘 · 카탈로그 타자만) · 셸 인셋 · 카탈로그 활동 학습형 조회 · 메신저 답장 자리 · 타자 도킹 |
| ui | 자판 면 · 키 줄 묶음 여백 · 메신저 바깥 상자의 마지막 자식이 자판 · 국면별 몸통 여백 · 안내가 떠 있는 동안 자판까지 가림 · 타자에서 자판이 껍데기 · 카드 스크롤 밖 · `Check`가 문서 순서상 자판 앞 |
| integration | 실제 App + globalProps 대역 — 3버튼 · iOS에서 메신저 · 롤플레이 메신저의 셸 padding 아래 0 · 묶음 margin 48 / 34 · 탭 바 없음 · 뒤로 가면 맵에서 `padded`로 복귀(`App.system-insets` II7 ~ II10) · 카탈로그 타자 활동만 `keyboard-dock`, 다른 학습형 · 같은 레슨의 다른 활동은 그대로(`App.catalog-lessons` KL1 ~ KL3) |

**이 문서만 보는 것**: 실제 기기 레이아웃 — 면이 정말 화면 끝에 닿는가, 키가 홈 인디케이터 · 시스템 바와 겹치지 않는가, 3버튼 바 위의 키가 눌리는가, 작은 기기에서 카드 영역, 낭독 순서.

## 전제

- [공통 전제](README.md#공통-전제) — 자체 호스트 앱, 로그인된 상태.
- iOS: iPhone 17 Pro 시뮬레이터(홈 인디케이터 — 아래 인셋 34pt), 이 브랜치의 번들. 다른 작업 트리의 개발 서버를 읽지 않게 한다([README 「자동화」](README.md#ios)). **빌드 commit · 설정(Debug/Release · CI/로컬)을 회차에 적는다.**
  비교 기준은 같은 기기의 `main`(`02dfee15`) 스크린샷이다.
- 메신저 자판 국면: 여정의 메신저 특별 유닛(「A Message from Minseo」) 첫 답장, 또는 롤플레이 탭의 메신저. 자판이 서는 답장이 있는 대화여야 한다.
- 타자 입력: 카탈로그 에피소드의 받아쓰기가 든 레슨(`S6`) — 순차 잠금이라 앞 레슨을 끝낸 계정이 필요하다.
- Android(권장): Pixel_8 AVD · API 37 에뮬레이터, 3버튼 · 제스처 두 모드.

## 미확인

- **메신저 자판 국면(KDE1 · KDE2 · KDE4)** — 자판이 서는 답장이 있는 대화(여정 메신저 · 롤플레이)로. 키 아래 끝 ↔ 화면 아래 ≈ 58pt와 `main` 대비 키 위치를 스크린샷으로 대조한다.
- **iPhone SE(3세대)의 카드 영역(KDE3)** — 자판(232 + 아래 인셋)이 스크롤 밖 고정이라 카드 영역이 얼마나 남는지 적는다(ADR-0070 Q2 · 「대가」 1).
- **자판 없는 국면 · 다른 화면의 회귀(KDE2 · KDE5)** — `main` 스크린샷과 나란히.
- **VoiceOver(KDE6)** — 타자 화면의 낭독 순서가 바뀌었다(「카드 → 버튼 → 자판」).
- **Android(KDA1 · KDA2)** — 특히 3버튼 바 위 맨 아래 줄 키가 눌리는지(AC4의 실기 확인).
