# 콘텐츠 수준 5 — 기기 확인 절차

[ADR-0137](../adr/0137-content-level-5.md). 이 절차는 두 번에 나눠 실행한다.
- **업로드 전 항목(P):** 새 빌드가 지금 운영 콘텐츠에서 깨지지 않는지 본다. 병합 전에 실행한다.
- **업로드 뒤 항목(C):** 콘텐츠를 운영 버킷의 `manifests/level-5.json`과 `episodes/level-5/`에 올린 **뒤에** 실행한다.

## 준비
- **새 빌드:** 이 변경이 들어간 Android 빌드. 화면 확인은 `assembleBundled`로 한다.
- **비교 빌드:** 1.3.0(versionCode 14) 스토어 빌드
- **기기 설정:** 소리를 끄고 시작한다.
- **로그:** logcat 또는 PostHog 개발 환경에서 `episode_update_splash_closed`와 받기 요약을 본다.

## 업로드 전 항목 (지금 운영 콘텐츠로)

| # | 확인 | 기대 |
|---|---|---|
| P1 | 새 빌드를 새로 설치하고 실행한다 | 매니페스트 요청 첫 경로 `manifests/level-5.json` → 없음(Supabase Storage는 **400**으로 답한다 — 앱은 다음 경로로 넘어간다), 다음 `manifests/level-4.json` → 200. 앱이 주소를 로그에 남기지 않으므로 Supabase 로그(`edge_logs`, `okhttp`)로 본다 |
| P2 | 지도 | u11 ~ u17(내장판 없음) 잠김 0편. u00 ~ u10은 원격이 실패해도 내장판으로 물러나므로 이 항목으로는 가려지지 않는다 — 그 근거는 단위 단계의 운영판 18편 디코드 확인 |
| P3 | UI 언어 vi | 번역이 지금과 같다(level-4 번역 파일) |

| # | 확인 | 기대 |
