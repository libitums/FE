# 작업 스펙: 초급 이야기와 최종 복습

## 목적 (goal)
일반 유닛에서 배운 짧은 표현을 메시지·전화·카페 이야기에서 다시 만나고, 세 문항으로 튜토리얼을 마칩니다.

## 타깃 (target)
[추론] 한글 입력과 발화가 아직 어려운 최초 사용자. 기존 모바일 Lynx 지원 범위를 유지하며 웹 지원 확대는 없습니다.

## 디자인 (design_ref)
DESIGN.md 표준 따름. 별도 DESIGN.md가 없어 기존 메신저·전화·비주얼 노벨·VisualNovelDialog와 디자인 토큰을 사용합니다. 벗어남 없음.

## 범위
- 포함(scope_in): 중간 스페셜 세 유닛의 대사·뜻·로마자 안내, 메신저 단일 답장 선택, 전화 음원 일치, 개발/프로덕션 이미지 URL 보존, 최종 복습 세 문항, 전체 여정 완료 검증.
- 제외(scope_out): 새 등장인물·배경 제작, 본 에피소드 1, 인증·진행 저장 체계 변경, 범용 발화·쓰기 엔진 변경.

## 수용 기준 (acceptance_criteria)
1. 메신저는 안녕하세요 / 내일 만나요를 한 개 보기에서 골라 보냅니다. 뜻·로마자 표기와 선택 안내를 보여 주고 한글 자판을 요구하지 않습니다.
2. 전화는 3턴이며 상대는 안녕하세요 / 저는 지민이에요. / 내일 만나요, 사용자는 이름이 뭐예요? / 안녕하세요 / 내일 만나요로 답합니다. 양쪽에 뜻·로마자를 표시하고 녹음 내용은 상대 대사와 일치합니다.
3. 카페의 세 장면은 안녕하세요 / 물 주세요 / 내일 만나요를 뜻·로마자와 함께 표시합니다. 기존 수동 넘김과 다시보기 동작을 유지합니다.
4. 최종 복습은 인사·물 주문·내일 인사 3문항입니다. 보기에는 일반 유닛에서 배운 다섯 표현만 사용하고 로마자와 질문의 영어 뜻을 제공합니다. 발화·손글씨 인식을 요청하지 않습니다.
5. 진척 없는 여정에서 프롤로그 → 일반 4개 → 메시지·전화·카페 → 길 묻기 → 최종 복습 → 결과 확인 후 롤플레이 해금까지 실제 데이터로 검증합니다.
6. 범용 메신저 자판·오답 처리와 일반 최종 테스트의 발화·쓰기 회귀는 명시적 테스트 픽스처로 유지합니다.

## 측정 (measurement)
[추론] 기존 완료 이벤트와 결과 기록을 사용합니다. 새 계측은 추가하지 않습니다.

## 제약 (constraints)
기존 유닛·턴·음원 ID와 진행 계약을 유지합니다. 전화·카페 계약의 대사 리터럴은 string으로 풀고 선택적 translation/romanization을 추가합니다. 인물·장면 순서는 유지합니다. 음원은 기존 macOS Yuna 테스트 자산 제작 방식을 사용합니다.

## 시각 레퍼런스 (visual_reference)
기존 스페셜 화면과 최종 VisualNovelDialog. 배경·인물 아트 변경 없음.

## 추론
세 문항의 선정, 대사, 안내 방식은 사용자의 초급화 방향을 구체화한 구현 판단입니다. 전화에서 지민의 자기소개는 뜻을 함께 읽는 서사이며 시험에 나오지 않습니다.
