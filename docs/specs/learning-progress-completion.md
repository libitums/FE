# 작업 스펙: 일반 학습 진행률과 완료 화면

## 목적 (goal)
사용자가 실제 문항 진행을 정확하게 파악하고, 모든 문항을 마쳤음을 알아본 뒤 결과로 이동합니다.

## 타깃 (target)
- 디바이스: [추론] 기존 모바일 Lynx 앱 지원 범위를 유지합니다.
- 브라우저 하한: [추론] 네이티브 앱 작업으로 웹 지원 범위를 확대하지 않습니다.

## 디자인 (design_ref)
DESIGN.md 표준 따름. 별도 DESIGN.md가 없어 기존 LearningShell, @libitums/design-tokens, 아이콘 패키지를 기준으로 합니다. 벗어남: 없음.

## 범위
- 포함(scope_in): 일반 학습 5종의 공통 진행률 계산, 완료 카드, 완료 시 지시문 숨김.
- 제외(scope_out): 평가·보상·채점 규칙, 스페셜 유닛, 학습 데이터 변경.

## 수용 기준 (acceptance_criteria)
1. 진행 막대는 현재 문항 순번 / 실제 문항 수이며 완료 화면을 추가 문항으로 세지 않습니다. 3문항은 약 33% → 67% → 100%, 1문항은 100%입니다.
2. 마지막 문항과 완료 화면에서 N/N과 100%를 유지합니다. 빈 활동은 진행 순번 없이 0%입니다.
3. 듣기·문장 순서·단어 선택·말하기·쓰기에 같은 토큰 기반 완료 카드가 표시됩니다. 문항 수 요약과 See results를 표시하며 문제 지시문은 숨깁니다.
4. 기존 결과 전달·완료 낭독·나가기 동작을 유지합니다. 완료 카드가 정답률이나 보상을 판정하지 않습니다.

## 측정 (measurement)
[추론] 기존 활동 완료·결과 기록으로 완료 후 결과 이동 여부를 확인합니다. 새 이벤트는 추가하지 않습니다.

## 제약 (constraints)
ReactLynx 요소와 기존 디자인 토큰·아이콘만 사용합니다. 문구는 UiCopy를 통합니다.

## 시각 레퍼런스 (visual_reference)
[추론] 기존 학습 카드와 하단 버튼을 유지하며 가운데 체크 원형 아이콘, 완료 제목, 설명, 문항 수 요약을 배치합니다.

## 비고
타깃·측정·완료 카드 구성은 사용자 미확인 추론입니다. 마지막 문항에서 100%가 되는 계산은 사용자의 end 제외 요청을 현재 문항 순번 기준으로 해석한 것입니다.
