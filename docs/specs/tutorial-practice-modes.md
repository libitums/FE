# 작업 스펙: 튜토리얼의 짧은 학습 방식 체험

## 목적 (goal)
초급 사용자가 중간 이야기와 최종 복습 사이에서 듣기·말하기·쓰기를 짧고 쉬운 별도 유닛으로 경험합니다.

## 타깃 (target)
- 디바이스: [추론] 기존 모바일 Lynx 앱 지원 범위.
- 브라우저 하한: [추론] 네이티브 앱이며 웹 지원 확대 없음.

## 디자인 (design_ref)
DESIGN.md 표준 따름. 별도 DESIGN.md가 없어 기존 LearningShell·학습 화면·결과 화면과 디자인 토큰을 재사용합니다. 벗어남: 없음.

## 범위
- 포함(scope_in): 카페 이후·최종 복습 이전에 듣기·말하기·쓰기 일반 유닛 각각 추가, 한 문제와 조작 안내, 단일 문항 통과·결과·해금, 말하기·쓰기의 선택적 건너뛰기, 직접 확인할 미리보기.
- 제외(scope_out): 새 이야기·인물·이미지, 본편 에피소드 1, 기존 다섯 일반 유닛의 교체, 전역 음성·필기 인식 기준 변경.

## 수용 기준 (acceptance_criteria)
1. 기존 다섯 일반 유닛의 순서를 유지하고, 마지막 길 묻기 뒤에 듣기·말하기·쓰기를 각각 별도 맵 항목으로 추가합니다. 최종 복습은 새 유닛까지 완료한 뒤 열립니다.
2. [추론] 듣기는 기존 한국어 녹음 안녕하세요와 로마자, 뜻 보기 Hello / Thank you 두 개로 구성합니다. 재생·다시 듣기와 기존 대본 설정을 유지합니다.
3. [추론] 말하기는 안녕하세요 한 문장, 로마자·뜻·조작 안내를 제공합니다. 사용자가 Skip을 누르면 건너뛴 것으로 완료할 수 있고, 인식 불가 상태에서도 이 선택을 제공합니다. 건너뛴 결과는 만점으로 표시하지 않습니다.
4. [추론] 쓰기는 내일 만나요의 나 한 글자를 흐린 안내 위에 따라 씁니다. 기존 채점 기준과 다시 쓰기를 유지하며 Skip으로 넘어갈 수 있습니다. 빈 입력을 정답 처리하지 않으며, 명시적으로 건너뛴 경우에만 완료에 반영합니다.
5. 각 유닛은 한 문항이며 성공 또는 명시적 건너뛰기 후 기존 결과 화면을 거쳐 Check를 누르면 다음 유닛을 엽니다. 중도 이탈·오답은 완료하지 않습니다.
6. 진행 헤더는 한 문제만 세고 끝 화면을 추가 문제로 세지 않습니다. 새 유닛의 진행·해금과 최종 이야기→시험→엔딩→결과 흐름을 통합 검증합니다.

## 측정 (measurement)
[추론] 기존 학습 완료·건너뛰기 기록으로 방식별 완료율과 이탈을 확인합니다. 새 이벤트는 추가하지 않습니다.

## 제약 (constraints)
기존 한국어 녹음과 native 인식 모듈을 재사용합니다. 전역 인식 기준을 낮추지 않습니다. 새로운 노드는 기존 일반 유닛 뒤에 추가해 이전 순번을 보존합니다.

## 시각 레퍼런스 (visual_reference)
현재 듣기·말하기·쓰기 LearningShell과 LessonCompleteScreen.

## 비고
- 사용자는 한 유닛 체험에서 별도 유닛으로 선택을 변경했고, 최신 선택을 적용합니다.
- 문항 선정·위치·건너뛰기 정책·타깃·측정은 사용자 발화로부터 구체화한 미확인 추론입니다.
