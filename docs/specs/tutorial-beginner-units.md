# 작업 스펙: 나머지 일반 유닛 초급화

## 목적 (goal)
한글을 처음 보는 사용자가 짧은 표현 하나를 안내받아 완성하고 다음 일반 유닛으로 이동합니다.

## 타깃 (target)
- 디바이스: [추론] 기존 모바일 Lynx 앱 지원 범위.
- 브라우저 하한: [추론] 네이티브 앱이며 웹 지원 확대 없음.

## 디자인 (design_ref)
DESIGN.md 표준 따름. 별도 DESIGN.md가 없어 기존 LearningShell·문장 만들기·디자인 토큰을 사용합니다. 벗어남: 없음.

## 범위
- 포함(scope_in): 이름 묻기·주문하기·약속 잡기·길 묻기를 뜻·발음·예문이 있는 한 문항으로 축소. 실제 문항 수에 맞는 통과 판정과 진행 유지. 안내 문구 가독성.
- 제외(scope_out): 중간 스페셜·최종 테스트 개편, 새 녹음 제작, 범용 듣기·말하기·쓰기 엔진 변경.

## 수용 기준 (acceptance_criteria)
1. 다섯 일반 유닛은 sentence-order 활동 하나, 문항 하나를 배정합니다. 첫 인사를 유지하고 나머지는 이름이 뭐예요? / 물 주세요 / 내일 만나요 / 역이 어디예요?입니다.
2. 모든 문항에 뜻·로마자 표기·조작 안내가 있습니다. 처음 두 유닛은 전체 문장 하나, 이후는 두 조각으로 제한하고 오답용 보기는 없습니다.
3. 주문하기는 조각 순서를 직접 알려주고, 약속·길 묻기는 예문을 보며 조합하도록 안내를 줄입니다.
4. 실제 배정이 한 문항이면 1개 정답으로 통과해 다음 유닛을 엽니다. 빈 결과·오답은 통과하지 않으며 기존 여러 문항의 2개 정답 기준을 유지합니다.
5. 상단 젬 수·완료 카드·진행률을 유지합니다. 튜토리얼 중 긴 듣기나 음성·손글씨 인식을 요구하지 않습니다.

## 측정 (measurement)
[추론] 기존 유닛 결과·완료 기록으로 초반 일반 유닛의 완료율과 중도 이탈을 확인합니다. 새 이벤트는 추가하지 않습니다.

## 제약 (constraints)
기존 녹음과 범용 연습 문항은 남기되 튜토리얼 경로에서는 배정하지 않습니다. 결과가 누락됐다는 이유로 통과 기준을 낮추지 않습니다.

## 시각 레퍼런스 (visual_reference)
기존 첫 인사 안내 화면과 공통 완료 카드.

## 비고
- 표현 선정·조각 수·도움 감소 방식·타깃·측정은 사용자 미확인 추론입니다.
- 한 문항을 전부 맞혀도 기존 2개 정답 기준 때문에 실패하던 문제를 실제 앱 통합 테스트에서 발견해 함께 수정합니다.
