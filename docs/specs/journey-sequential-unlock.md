# 작업 스펙: 에피소드 유닛 순차 해금

## 목적 (goal)
사용자가 에피소드 시작부터 맵 순서대로 하나씩 완료하며 다음 학습으로 진행한다.

## 타깃 (target)
- 디바이스: [추론] 기존 모바일 Lynx 앱 사용자.
- 브라우저 하한: 해당 없음. 네이티브 앱의 기존 지원 범위를 유지한다.

## 디자인 (design_ref)
DESIGN.md 표준 따름. 벗어남: 없음. 기존 잠금·진행·완료 표시를 사용한다.

## 범위
- 포함(scope_in): 신규 진행 0, 맵의 모든 유닛 순차 해금, 알림·푸시의 동일 접근 판정, 완료 기록 복원 및 회귀 검증.
- 제외(scope_out): 에피소드 콘텐츠·통과 기준 변경, 기존 사용자의 완료 기록 초기화.

## 수용 기준 (acceptance_criteria)
1. 신규 사용자는 완료 기록이 없으며 시작 유닛만 열려 있다.
2. 앞선 모든 맵 항목을 완료해야 다음 미완료 유닛 하나가 열린다. 메신저·전화·카페도 같은 규칙을 적용한다.
3. 중도 이탈이나 미통과로 다음 유닛이 열리지 않는다.
4. 잠긴 유닛은 알림·푸시로도 열리지 않는다.
5. 기존 완료 기록은 유지한다. 표지 완료 후 완료한 유닛은 재방문할 수 있으나 미완료 항목을 건너뛰어 새로운 유닛을 열 수 없다.
6. 최종 테스트는 모든 선행 유닛 완료 후 열리며, 완료 결과 확인 전에는 에피소드 완료로 기록하지 않는다.

## 측정 (measurement)
[추론] 신규 이벤트는 추가하지 않는다. 기존 유닛 완료 이벤트와 저장된 진행으로 순차 진행과 중도 이탈을 확인한다.

## 제약 (constraints)
기존 서버 진행 스키마와 단조로운 완료 기록 병합을 유지한다.

## 시각 레퍼런스 (visual_reference)
기존 여정 맵의 잠금·활성·완료 표식.

## 비고
- 사용자 요청: 시작 유닛부터 하나씩 완료해야 다음 유닛이 열리도록 수정.
- [추론] 기존 지원 환경·시각 디자인·이벤트 유지. 별도 기능 확장 없이 현재 앱의 해금 규칙을 수정하는 범위로 해석했다.
