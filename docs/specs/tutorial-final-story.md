# 작업 스펙: 이야기 속 최종 복습과 도착 엔딩

## 목적 (goal)
사용자가 기내에서 시작한 상상을 이어 가며 배운 표현으로 대화하고, 시험 통과 뒤 한국에 도착하는 이야기로 튜토리얼을 마칩니다.

## 타깃 (target)
- 디바이스: [추론] 기존 모바일 Lynx 앱의 초급 사용자.
- 브라우저 하한: [추론] 기존 네이티브 앱 지원 범위이며 웹 지원 확대 없음.

## 디자인 (design_ref)
DESIGN.md 표준 따름. 별도 DESIGN.md가 없어 기존 VisualNovelDialog·EpisodeNarrativeScreen과 디자인 토큰을 따릅니다. 벗어남 없음.

## 범위
- 포함(scope_in): 기내·상상 속 카페·공항 도착의 생성 이미지, 시험 전 이야기, 상황별 3문항, 통과/재도전, 통과 후 엔딩, 완료 기록 경계, 직접 열 수 있는 개발 미리보기.
- 제외(scope_out): 본 에피소드 1 내용 확정, 새로운 본편 인물, 범용 통화·발화·쓰기 엔진 변경.

## 수용 기준 (acceptance_criteria)
1. 첫 서사의 화풍과 이어지는 배경 3장을 제작해 저장소에 넣고 화면에서 사용합니다. 신규 인물은 그리지 않습니다.
2. 최종 유닛은 기내 → 상상 속 카페의 3개 도입 대사 후 시험으로 넘어갑니다. 기존 비주얼 노벨 다이얼로그와 장면 전환을 사용합니다.
3. 시험은 안녕하세요 / 물 주세요 / 내일 만나요를 정답으로 하는 기존 3문항이며 각 문항에 구체적인 상황을 제공합니다. 뜻·로마자 안내는 유지합니다.
4. [추론] 3문항 중 2개 이상 정답이면 통과합니다. 결과가 누락되면 통과하지 않으며, 0~1개 정답이면 정답 표현을 알려주는 2개 대사 후 다시 풉니다. 재시도 점수는 이전 시도와 섞지 않습니다.
5. 통과 뒤 카페의 인사 → 기내 현실 복귀 → 공항 도착 → 첫 인사의 4개 대사가 진행됩니다. 이 끝에 결과 화면으로 가고 Check를 눌러야 완료·롤플레이 해금이 반영됩니다.
6. 도입·시험·재도전·엔딩 중 나가기와 연속 탭으로 완료를 우회하지 못합니다. 재진입은 도입부터 시작합니다.
7. 기존 story 없는 최종 시험과 통화 시험은 기존 동작을 유지합니다.

## 측정 (measurement)
[추론] 기존 최종 결과·에피소드 완료 기록을 사용합니다. 새 이벤트는 추가하지 않습니다. 이후 통과 후 엔딩 완료율을 검토할 수 있도록 완료 경계를 유지합니다.

## 제약 (constraints)
신규 이미지는 810×1440 JPEG로 납품하며 생성 원본 PNG는 로컬 output에 보관합니다. 실제 이미지 증가분을 측정해 정적 이미지 예산에 반영합니다. 프레임·메모리 성능 개선을 주장하지 않습니다.

## 시각 레퍼런스 (visual_reference)
첫 서사의 airplane-descent.jpg와 imagined-cafe.jpg. 생성 프롬프트는 tutorial-final-image-prompts.md에 기록합니다.

## 비고
- 통과 기준 2/3, 대사, 장면 수, 타깃과 측정은 사용자 미확인 추론입니다. 사용자가 요청한 이야기→시험→통과 후 마무리 구조를 구체화했습니다.
- 최종 UI 제목은 Almost There이며 등장하는 민서는 기존 튜토리얼 속 상상의 친구입니다.
