## 0. 고정 범위와 불변식

1. 이 문서는 **1단계 컴패니언**만 다룬다. 캐릭터와 관계 중심의 끝이 없는 자유대화다.
2. **화면 설계는 쓰지 않는다.** 화면 · UI/UX는 FE 팀 몫이고, 이 문서는 「어떤 정보가 어느 시점에 클라이언트로 오는가」까지만
   쓴다(§1 · §4).
3. 캐릭터 대사는 **항상 한국어**다. 유저 입력은 한국어 · 모국어 · 혼용 모두 받는다.
4. 공식 캐스트만 쓴다. 유저가 만드는 캐릭터(UGC)는 없다.
5. **로맨스는 없다.** 친밀도만 쓰고 수치는 유저에게 보이지 않는다.
6. 컴패니언에는 **세션 끝 리포트가 없다.** 피드백은 대화 중 메시지마다 붙는다.
7. 답변은 **SSE 하나**로 흐른다. 교정도 같은 스트림에 끼워 보낸다. v1은 Supabase Realtime을 쓰지 않는다.
8. 컴패니언 데이터는 전부 DB 스키마 `companion`에 두고 모든 표에 RLS를 켠다. 앱은 표에 직접 닿지 않는다.

## 1. 역할 경계

| 누가 | 정하는 것 |
|---|---|
| 백엔드 · AI(이 문서) | 페르소나 프롬프트 · 친밀도 규칙 · 말투 단계 전환 · 교정 생성 · 학습 표현 선택 · 대화 분기 · 메모리 · 크레딧 차감 · 가드레일 · 연령 판정 · 시간 상한 · 평가 · ops-dashboard 컴패니언 탭(조회 함수와 화면 모두) |
| FE | 채팅 화면 · 말풍선 · 아이콘 · 시트 · 칩 · 번역과 로마자 표시 방식 · 문구 · 오류를 화면에 어떻게 보이나 · 비회원에게 무엇을 보이나 |
| 계약(`packages/companion-contract`) | 둘을 잇는 요청 · 응답 · SSE 이벤트 · 에러 코드의 모양. 이 모양이 바뀌면 두 팀이 같이 본다 |

FE가 받는 것은 **값과 시점**이다. 예를 들어 「말투가 반말로 바뀌었다」는 이벤트는 오지만, 그것을 토스트로 보일지 말지는 FE가 정한다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 페르소나 | 공식 캐릭터 하나. v1은 윤경 · 미나 · 도윤 · 재민 · 덕수쌤 다섯 |
| 친밀도 | 유저와 캐릭터 사이의 관계 수치. **유저에게 보이지 않는다.** 말투 단계를 정하는 입력이다 |
| 말투 단계 | `polite`(존댓말) → `casual`(반말) → `slang`(슬랭). 유저가 볼 수 있는 유일한 관계 결과다 |
| 턴 | 유저 메시지 하나와 그에 대한 캐릭터 답변 하나 |
| 메시지별 피드백 | 유저 메시지 하나에 붙는 교정 · 더 나은 표현 · 「한국어로는 이렇게」 |
| 피드백 방식 | `separate`(분리형) · `natural`(자연형) · `prefix`(앞머리형) |
| 학습 표현 | 유저가 끝낸 유닛에서 나온 단어 · 표현 · 문형. 전역 표 `companion.expressions`가 정본이다 |
| 화제 씨앗 | 화제를 바꿀 때 캐릭터에게 주는 다음 화제 후보 |
| 선톡 | 유저가 한동안 말이 없을 때 캐릭터가 먼저 보내는 메시지. 앱이 꺼져 있으면 푸시로 간다 |
| 크레딧 | 대화에 쓰는 재화. 구독 지급분(`sub`) · 무상 지급분(`grant`) · 구매분(`paid`) 세 버킷 |
| 상태 JSON | 메인 LLM 호출이 답변과 함께 내는 구조화된 신호(친밀도 증감 · 화제 신호 · 넣은 학습 표현) |

## 3. 기능 규칙

### 3.1 페르소나 5명과 덕수쌤 체험

- v1 페르소나는 윤경 · 미나 · 도윤 · 재민 · 덕수쌤이다. M1은 덕수쌤 한 명으로 시작하고 M3에서 다섯이 된다.
- 페르소나의 정본은 duru-curation `bible.yaml`이다. 거기에 `companion:` 블록(말투 · 단계별 말투 · 자주 쓰는 말 · 수위선 ·
  회피 방식 · 보이스 ID)을 확장하고, 빌드 결과를 `companion.characters.persona`에 싣는다. 세부 성격은 만들면서 깎는다(§8 C).
- 장소 · 시간은 Duru 서사를 따른다. **캐릭터는 유저가 해금한 에피소드까지만 안다**(스포일러 방지). 해금 판정은 진도의
  `catalogProgress`를 쓴다(§3.7).
- **덕수쌤은 무료 · 저가 티어 유저의 체험용 기본 페르소나**다. 고가 티어로 넘어가기 전 맛보기다. 체험 범위(메시지 수 등)는
  정하지 않는다(§8 O3). 서버는 체험 사용량을 세고, 한도에 닿으면 정해진 에러로 알린다(API §5 `trial_exhausted`).
- 미나는 같은 외국인 학습자 시선, 덕수쌤은 선생님 시선을 갖는다. 나머지 인물 방향은 위키(재민 INTJ · 도윤 ENFP)를 따르고
  그 밖은 미정이다.

### 3.2 친밀도와 말투 단계

- 메인 LLM 호출이 턴마다 상태 JSON의 `intimacy_delta`로 증감을 낸다. 서버가 그 값을 범위 안으로 자르고 누적한다.
  **증감 규칙과 전환 지점은 만들면서 깎는다**(§8 C).
- 누적값이 문턱을 넘으면 말투 단계가 `polite → casual → slang` 차례로 바뀐다. 이 전환 자체가 한국어 학습 콘텐츠다.
- **수치 · 게이지는 클라이언트로 보내지 않는다.** 클라이언트가 받는 것은 지금 말투 단계와 「이번 턴에 단계가 바뀌었다」는
  사실뿐이다(§4).
- [제안] 단계는 올라가기만 하고 내려가지 않는다. 내려가면 유저가 관계가 깨졌다고 느낄 수 있어서다. 팀 확인 전이다(§8 O13).

### 3.3 로맨스 없음

- 이성적 호감도 · 연인 단계 · 고백은 v1에 없다. 미국 12 ~ 17세 「친구 모드」와 모든 연령의 v1 동작이 같다.
- 유저가 플러팅하면 캐릭터는 **친근하게 받되 수위를 올리지 않는다.** 시스템 경고문을 띄우지 않고 캐릭터 성격대로 피한다.
- 성적 표현은 형식(나레이션 · 지문)과 상관없이 막는다. 스토어 · 규제는 내용을 본다.
- 캐릭터는 인간 행세를 하지 않고, 의식이 있다고 주장하지 않는다. 구매를 유도하는 대사(「우리 관계를 위해 사 줘」 류)를 하지
  않는다(캘리포니아 SB 1119 · 기타 주법 요약 기준).

### 3.4 메시지 모양

- 캐릭터 답변은 **조각(segment)의 목록**이다. 조각 종류는 셋 — 대사(`speech`) · 지문 · 속마음(`action`, 원문의 `*…*`) ·
  나레이션(`narration`). 조각은 스트림으로 조금씩 온다(§4).
- 유저 메시지는 글자 하나와 입력 방식(`text` · `voice`)을 갖는다. `voice`는 기기 내장 STT가 받아 적은 글자다. 녹음 원본은
  서버로 오지 않는다.
- 번역 · 로마자는 **표시 설정 하나로 묶인다**(위키 02). 서버가 정하는 것은 「무엇이 언제 오는가」다.
  - **[결정 2026-11-09] 로마자는 클라이언트가 규칙으로 만든다.** 서버는 보내지 않는다(답 · 피드백 · 추천 답변 모두).
  - **[결정 2026-11-09] 모국어 번역은 턴마다 만든다** — 답이 끝난 뒤 **따로 가벼운 호출 하나**(답 호출에 섞지 않는다). SSE
    `translation`으로 `state` · `done` 앞에 오고 조각의 `translation`에 저장된다. 제한 시간 6초, 실패 · 시간 초과면 번역만 없다.
    `l1`이 `ko`면 건너뛰고, 차단 · 위기 답은 번역하지 않는다. 서버 스위치 `COMPANION_TRANSLATION`(`every` · `off`).
    「탭할 때만 번역」은 미룬다 — 원가 판단은 §8 O9에 남는다.
- **[결정 2026-11-09] 추천 답변 칩은 1단계에 넣는다**(O10). ⟨2026-11-10⟩ 요청형에서 아래로 바뀌었다(`feat/companion-m1`
  `d2c6f999` · `092528a0` · `655ef642` · `c21ba45f`, 마이그레이션 20261119 · 20261121 · 20261122).

**추천 답변 칩 [결정 2026-11-10]** — 설계 문서 「AI 컴패니언 선택지 기능 설계」(2026-11-09, 제타 역공학)를 따른다.

### 3.5 메시지별 피드백

유저 메시지마다 서버가 피드백을 만든다. **메인 답변과 병렬로** 돌리고 같은 SSE 스트림에 `correction` 이벤트로 끼워 보낸다.

| 종류 | 내용 | 언제 |
|---|---|---|
| 교정 `correction` | 원문 → 교정 후 → 이유. 틀린 곳이 여럿이면 목록 | 유저 한국어 문장에 오류가 있을 때 |
| 더 나은 표현 `better` | 같은 뜻을 더 자연스럽게 쓴 문장 + 뜻(모국어) + 설명(모국어) | 오류가 없어도 붙을 수 있다 |
| 한국어로는 `l1_to_ko` | 「자연스러운 한국어 표현은 ~」 문장 + 뜻 | 유저 메시지에 한국어가 아닌 부분이 있을 때(모국어만 · 섞어 씀 모두). 교정과 같은 자리를 쓴다 |

**카드 한 장 [결정 2026-11-09]** — 카드 모양은 고정이다(Moly식). 「올바른 문장 → 고친 곳마다 원문 · 고친 표현 · 이유 → 더 나은
표현(뜻 · 설명)」 차례로 그린다. 필드는 API §4.2 `correction`, 저장은 `corrections.card`.

**맥락 [결정 2026-11-09]** — 피드백 호출은 유저 메시지 하나만 보지 않는다. 최근 메시지 6개(유저 · 캐릭터 합쳐, 하나당 500자까지,
번역 없이) · 관계 말투 단계 · 캐릭터 `{ name, role, banmalFeedback }` · `l1`을 함께 넣는다. 피드백은 마지막 유저 메시지에만 준다.

**규칙 [결정 2026-11-09]** — 위에서부터 보고 종류 하나만 고른다.

| 경우 | 종류 | 비고 |
|---|---|---|
| 한국어가 아닌 부분이 있음(전부 · 일부) | `l1_to_ko` | 「자연스러운 한국어 표현은 ~」만. 한국어로 써야 하는 이유 같은 메타 설명은 없다. 이름 · 브랜드(BTS · iPhone) · 숫자 · 이모지는 외국어로 보지 않는다 |
| 문법 · 조사 · 활용 · 맞춤법 · 오타 · 틀린 단어 | `correction` | 띄어쓰기는 뜻이 바뀌거나 읽기 어려울 때만 |
| 한 메시지 안에서 존댓말 · 반말이 섞임 | `correction` | 관계 말투 하나로 맞춘다 |
| 존댓말 관계에서 반말 | `better` | 캐릭터의 `banmalFeedback: correction`이면 `correction` — 지금 덕수쌤 |
| 누구를 겨냥하지 않은 욕(「아 씨 시험 망했어」) | `better` | 이유에 「비속어」라고 적고 중립 표현을 준다 |
| 뜻은 통하지만 번역투 · 부자연스러움 | `better` | 이미 자연스러운 문장에는 대안을 내지 않는다 |
| 그 밖 | 없음(`none`) | |

- `*…*` 안의 글(학습자의 행동 · 속마음 — 지원한다)도 틀린 한국어는 고치지만 말투는 판정하지 않는다.
- ㅋㅋ · ㅎㅎ · ~ 어미 · 이모지 · 문장부호 빠짐 같은 채팅 관습은 피드백하지 않는다.

- 피드백이 없을 수 있다(완벽한 문장). 그때도 `correction` 이벤트는 「없음」으로 한 번 온다 — 클라이언트가 기다림을 끝낼 수
  있게 한다(API §4).
- 피드백 생성이 실패하거나 늦으면 답변은 그대로 끝나고, 피드백은 「만들지 못함」으로 온다. 피드백 실패로 턴 전체를 실패시키지
  않는다.
- 설명 · 뜻은 유저 모국어(`l1`)로 쓴다. `l1`이 없으면 영어다.
- 음성 재생은 피드백 카드에는 없다(§0). 캐릭터 메시지의 「음성」은 [스냅샷 · 음성](ai-companion-snapshot.md) §4.

### 3.6 피드백 방식 3종

| 방식 | 페르소나 답변 | `correction` 이벤트 |
|---|---|---|
| `separate` 분리형 | 교정하지 않는다 | 온다 |
| `natural` 자연형 | 대사 안에서 맞는 표현으로 되받는다(recast) | 온다 |
| `prefix` 앞머리형 | 답하기 전에 짧게 교정을 먼저 말하고 대화를 잇는다 | 온다 |

- 세 방식 모두 `correction` 이벤트는 똑같이 온다. 방식이 바꾸는 것은 **페르소나 프롬프트**다.
- 유저는 대화를 시작할 때 고르고, 대화 중에도 바꿀 수 있다. 바꾼 방식은 **다음 턴부터** 적용된다.
- **[결정 2026-11-09] 기본값은 `separate`다**(O5). 프로필의 `feedback_mode`가 비면 `separate`로 본다. 매 메시지마다 바꾸는 것까지 열지는 실험 항목이다(지표: 사용률 · 대화 길이 · 교정 열람률).

### 3.7 학습 표현

v1은 단순하게 간다.

1. 전역 표 `companion.expressions`에 배포 에피소드의 단어 · 표현 · 문형을 모은다. id 접두사는 배포 콘텐츠에서 관찰한 다섯이다 —
   `voca:`(어휘) · `expr:`(표현) · `patt:`(문형) · `gram:`(문법) · `nume:`(수 단위). 뒤의 둘은 위키에 없다(비고 9).
2. 유저의 완료 유닛(`learning_progress.progress.catalogProgress` — 에피소드 id → 끝낸 유닛 키 배열, [ADR-0035](../adr/0035-learning-progress-and-streak-on-server.md)
   적용 기록 ⟨2026-10-12⟩)을 읽는다.
3. 끝낸 유닛에 걸린 표현을 골라 프롬프트에 넣는다. 캐릭터 어휘는 그 범위 + 약간 위(i+1)다.
4. 캐릭터는 배운 표현을 쓰게 만드는 질문을 가끔 던진다. 넣는 시점은 대화 분기가 정한다(§3.8).

**유닛 → 표현 대응 [제안]** — 에피소드 JSON의 `words[]` · `patterns[]`는 에피소드 단위라 유닛과 바로 이어지지 않는다
([콘텐츠 계약](episode-content-json-contract.md) §8). 그래서 `expressions`를 채우는 빌드 스크립트가 문항의 `steps[].items[].ref`로
**표현 ↔ 유닛 대응표**(`companion.expression_units`)를 함께 만든다.

- `ref`가 없는 유닛(`RP` · `CULT` · 막간)은 표현을 내지 않는다.
- 다른 에피소드의 id를 가리키는 `ref`(에피소드 3이 에피소드 2 단어를 쓰는 경우 — 콘텐츠 계약 합의 Q4)도 전역 표라서 그대로
  풀린다.

- id는 바꾸거나 재사용하지 않는다. 지울 때는 `retired` 표시만 한다. 앞으로 유저 기록이 이 id에 걸린다.

`expressions`의 기준은 Storage `content` 버킷의 배포 에피소드 JSON이다(유저가 실제로 본 것). 수준별 매니페스트

| 칩 | 추천 답변 후보 하나에 그 표현을 넣는다 | 칩 「친구랑 영화 보고 싶어요」 | 다시 보기. 칩은 탭 전송뿐이라(2026-11-10 결정) **산출로 치지 않는다** |

- 한 턴에는 방식 하나만. 처음 넣는 표현은 노출부터, 노출된 적이 있으면 유도 쪽 비중을 올린다. [구현] 만난 적 있고 아직 안 쓴 표현은
  유도 0.5 · 칩 0.3 · 노출 0.2, 이미 쓴 표현은 노출 0.5 · 유도 0.3 · 칩 0.2. 칩 스위치가 꺼져 있으면(또는 운영이 칩을 껐으면) 칩 대신 유도.
- [구현] 노출 · 유도는 답 요청의 `directive`(유저 말 뒤 system 메시지)로 한 줄 — 「자연스러우면 한 번 써라, 억지스러우면 넘겨라 — 썼으면 `@state.learned`」 ·
  「그 표현으로 답할 쉬운 질문 하나, 직접 쓰지도 말하지도 말고 퀴즈처럼 묻지 마라」. 칩은 답 지시 없이 칩 요청에 `target`을 실어 후보 하나에 넣게 하고,
  검증을 지난 그 후보가 먼저 보일 자리를 받는다(`pickShown`의 keep).
- 칩은 칩 검증(§3.4)을 그대로 지나야 한다 — 표현을 넣으려고 검증을 느슨하게 하지 않는다.
- 첫 인사 · 선톡에도 노출로 하나 넣을 수 있다(튜토리얼만 끝낸 유저는 주로 여기, 아래). [구현] 첫 인사 · 선톡은 늘 노출 하나를 고르고(설정이
  꺼졌거나 풀이 비면 없음) 지시 끝에 「자연스러우면 한 번 써라」 한 줄을 붙인다. 정해진 인사(생성 실패)면 세지 않는다(`companion-opener.ts`).
- 모델이 「넣을 자리가 아니다」라고 판단하면 넘긴다(지금과 같다). 억지로 끼우지 않는 것이 규칙 1번이다.

**대상 유저 [결정 2026-11-10]**

| 유저 | 동작 |
|---|---|
| 끝낸 유닛 없음 | 넣지 않는다. 한국어를 아주 쉽게 쓴다(지금 프롬프트의 「none yet — keep it very simple」) |
| 튜토리얼만 끝냄 | 「안녕하세요」 · 「감사합니다」 둘만. 주로 첫 인사 · 선톡에 노출로. 유도는 하지 않는다(너무 뻔하다) |
| `u01` 이상 | 위 규칙 전부 |

**범위 [결정 2026-11-10 · 구현 — `feat/companion-learning`, 마이그레이션 20261126]** — 유저가 설정에서 배운 표현을 고를 범위를 정한다.

- 기본은 **자동**: 끝낸 유닛 전부(위 규칙 그대로). **직접 고르기**로 바꾸면 체크박스로 고른 **에피소드**(u01-water …)의 끝낸 유닛만 쓴다.
  화면의 「유닛」은 에피소드 하나이고, 이름은 배포 매니페스트의 제목(없으면 id)이다.
- 고를 수 있는 에피소드 = 유닛을 하나 이상 끝냈고 학습 표현이 있는 에피소드(「끝낸 유닛만」). 고른 에피소드 안에서도 끝낸 유닛의 표현만 쓴다.
- 직접 고르기인데 고른 것이 없으면 넣지 않는다 — 자동으로 되돌리지 않고, 설정 응답이 `empty`로 알린다(지표 까닭 `manual_empty`).
  고른 에피소드가 나중에 콘텐츠에서 빠지면(대응표에 없으면) 건너뛴다. 자동으로 돌아가도 고른 목록은 남는다(다시 바꾸면 그대로).
- 튜토리얼 규칙은 고른 범위에 그대로 적용한다 — 고른 범위가 튜토리얼뿐이면 턴에는 넣지 않는다.
- 저장 `companion.profiles.learning_scope`(`auto` · `manual`) · `learning_units`(에피소드 id, 최대 50). 에피소드 제목은 `companion.episodes`
  (`companion.sync_episodes` — 표현 동기화 SQL 끝에 함께 실린다). 창구는 API §2.8.

**기록 [구현 2026-11-10 — 20261125]** — 새 표 `companion.user_expressions`(유저 × 표현, 서버만 — `companion_record_learning(p_user_id, p_events, p_now)`이 센다)

| 열 | 뜻 |
|---|---|
| `exposed_count` · `last_exposed_at` | 캐릭터가 실제로 쓴 횟수 · 시각(노출 · 첫 인사 · 선톡) |
| `elicited_count` | 유도 질문을 던진 횟수 |
| `chip_shown_count` | 칩에 실린 횟수 |
| `produced_count` · `first_produced_at` · `last_produced_at` | 유저가 직접 입력해 쓴 횟수(칩 전송은 세지 않는다) |
| `last_elicited_at` · `last_chip_at` | 마지막 유도 · 칩 시각(「오래 안 본 것」은 셋 가운데 가장 늦은 것) |

- **캐릭터가 썼는지**: [구현] 한 턴에 표현이 하나라 id 대신 `@state.learned`(지시를 따랐으면 true)를 받고, 노출이면 서버가 답 글자에서 한 번 더
  확인한다(문형 · 자리 있는 표현은 활용 때문에 보고만). 유도는 보고만, 칩은 표현을 넣은 칩이 실제로 보였는가. 모델이 넘기면 세지 않는다.
  저장 meta `learning {open, reason, mode?, expressionId?, surface?, done?, produced?}` — `reason`은 ok · disabled · no_pool · tutorial_only ·
  first_turn · wants_switch · heavy · switch · cooldown · daily_cap · chance.
- **유저가 썼는지**: 피드백 단계(§3.5)에서 같이 판정한다. 그 턴의 후보 표현(최근 노출 · 유도된 것)만 넘겨 비용을 묶는다.
  쓰면 교정 카드에 「배운 표현을 썼어요」 한 줄을 붙인다(칭찬만, 점수 없음). [구현] 직접 입력한 글을 배운 표현 전체와 글자로 비교하고(한 글자
  어휘는 다른 낱말 속에 흔해 뺀다), 최근 지시한 표현 가운데 문형 · 자리 있는 것만 피드백 모델에 `t1` · `t2` …로 넘겨 `learned_used`로 고르게 한다.
  둘을 합쳐 `correction.learnedUsed [{id, surface}]`(있을 때만). 칩을 그대로 보낸 말(`skipped`)에는 없다.
- **판별 규칙**: 어휘(`voca`) · 고정 표현(`expr`)은 글자 일치 + 띄어쓰기 · 문장부호 무시. 문형(`patt` · `gram`)은 `{수단}` 같은
  자리와 활용(먹고 싶어요 · 가고 싶었어요)이 있어 글자 일치로 안 된다. `expressions.lemma`가 비어 있으므로 문형마다 판별 규칙
  (정규식 또는 핵심 어미)을 따로 두거나 LLM 판정에 맡긴다(O25). [구현] 글자 판정: 공백 · 문장부호를 걷고 끝 「요」를 떼고 비교, 「-다」 용언은
  어간(두 글자 이상이면 끝 글자를 뗀 앞부분까지 — 따뜻하다 → 따뜻해요), `{자리}`는 자리를 경계로 조각이 차례로 모두 있어야 한다
  (`companion-learning-match.ts`). 활용형 문형은 위의 모델 판정이 맡는다 — lemma 채우기는 여전히 O25.
- 기억(§3.9)에는 넣지 않는다 — 학습 기록은 이 표가 진다. 칩으로 고른 말은 산출 근거가 아니다(기억 규칙과 같다).

**지표와 평가 [구현 2026-11-10 — 20261125]** — `companion_learning_stats(p_since, p_playground)`: 턴 · 열린 턴 · 넣은 턴 · 방식별 넣음/따름 ·
출처별(턴 · 첫 인사 · 선톡) · 넣지 않은 까닭 · 산출 턴 · 유도 뒤 3턴 안 산출 · 다시 쓴 표현(산출 2번 이상, 하루 넘게 떨어져 — 7일 유지율의 단순판) · 많이
넣은 표현. 평가는 `companion-eval`의 `kind: "learning"`(케이스 `target {surface, gloss?, kind?, mode}`), ops-dashboard 기본 세트 「기본 · 학습 표현」과
세 축(natural · level · flow). 플레이그라운드는 대화 줄의 meta.learning 태그와 검사 칸 「학습 표현」(시험 계정의 풀 · 지표).

- 지표: 삽입률(후보가 열린 턴 중 실제로 넣은 턴) · 방식별 비율 · 유저 산출률(유도한 표현을 3턴 안에 직접 쓴 비율) · 유지율(산출한
  표현을 7일 뒤 다시 쓴 비율) · 표현이 들어간 턴의 대화 이어짐(다음 유저 턴이 왔는가).
- 평가(§6)에 축 「학습 표현 자연스러움」을 더한다 — 억지로 끼웠는가 · 수준에 맞는가 · 유도 질문이 대화 흐름에 맞는가. 고정 세트에
  진도 단계별(튜토리얼만 · u01 · u05 이상) 케이스를 넣는다.
- ops-dashboard 컴패니언 섹션 플레이그라운드에서 그 턴에 고른 표현 · 방식 · 실제 사용 여부를 보여 준다.

### 3.8 대화 분기 — 화제 전환 · 학습 삽입 · 선톡

단일 LLM에 맡기면 대화가 늘어지거나 같은 화제를 맴돈다. 메인 호출이 신호를 내고, **서버가 규칙과 랜덤을 섞어 다음 턴 지시를
고른다.**

| 신호 | 출처 |
|---|---|
| 유저 답이 짧은 턴이 k번 연속 | 서버 계산 |
| 같은 화제가 M턴 넘게 이어짐 | 상태 JSON `topic_signal` + 서버 카운트 |
| 유저가 전환을 원함(`user_wants_switch`) | 상태 JSON |
| 마지막 메시지 뒤 공백 시간 | 서버 계산 |

| 행동 | 규칙 |
|---|---|
| 화제 전환 | 신호가 임계값을 넘으면 화제 뱅크에서 씨앗을 뽑아 다음 턴 지시에 넣는다 |
| 학습 표현 삽입 | 쿨다운 + 확률. 메인 호출이 「지금 넣을 자리」라고 판정할 때만. ⟨2026-11-10⟩ 주기 · 방식 · 대상은 §3.7 「학습 연결」 |
| 선톡 | 공백이 길면 캐릭터가 먼저 메시지를 보낸다. 하루 상한이 있다 |

- 원칙: **임계값으로 후보를 열고, 그 안에서 랜덤으로 고른다.** 임계값만 쓰면 기계적이고 랜덤만 쓰면 엉뚱하다.
- k · M · 쿨다운 · 확률 · 선톡 공백 · 하루 상한 값은 정하지 않는다(§8 C). 서버 설정 값으로 받는다.
- 화제 뱅크의 내용(캐릭터 일상 · 고민 상담 · K-culture · 미니게임 · 친밀도 단계별 비밀 이야기)은 어느 것을 v1에 넣을지 팀
  논의다(§8 O6).
- 선톡은 앱이 꺼져 있으면 푸시로 간다. 앱이 켜져 있을 때 바로 띄우는 것은 v1에서 하지 않는다(Realtime 미사용) — 다음 조회 때
  메시지 목록에 보인다.
- 미국 12 ~ 17세에게는 선톡 · 푸시를 보내지 않는다(§3.12).

**선톡 빈도 [결정 2026-11-09]**

| 규칙 | 값 |
|---|---|
| 유저 설정 `proactive_pref` | `off` · `daily1`(기본) · `daily2` |
| 선호 시각 `proactive_hour` | 현지 0 ~ 23시, 비우면 아무 때나. `daily2`는 그 시각과 10시간 뒤 |
| 시간대 | 프로필 `timezone`(IANA), 없으면 지역의 대표 시간대. 둘 다 모르면 시각 맞추기 · 조용한 시간을 건너뛰고 하루는 UTC |
| 조용한 시간 | 현지 22:00 ~ 08:00에는 보내지 않는다 |
| 전체 하루 상한 | 2(`settings.proactive_daily_cap`) — 유저 설정보다 앞선다 |
| 예약 작업 | 매시간. 한 번 돌 때 유저마다 후보 하나(가장 오래 조용한 대화) |
| 건너뛴 이유 | `companion.proactive_skip_reason`이 `off` · `quiet_hours` · `hour` · `daily_cap` · `gap` · `spacing` 중 하나를 낸다 |
| 플레이그라운드 `force` | 빈도 규칙을 모두 건너뛴다. **연령 · 지역 규칙은 건너뛰지 않는다** |

- 푸시는 아직 나가지 않는다 — 선톡 메시지는 저장되고 앱은 다음 조회 때 본다. 푸시 연결은 세현님이 맡는다(인계: API §2.3).

### 3.9 메모리 2층

| 층 | 누가 읽나 | 내용 |
|---|---|---|
| 공유 프로필 | 모든 캐릭터 | 이름(기존 `learner_profiles`) · 모국어 · 관심사 · 진도에서 계산한 수준 |
| 캐릭터별 장기 메모리 | 그 캐릭터만 | 사실 · 사건 · 요약 |
| 단기 메모리(대화 안) | 그 대화 | 최근 N턴 원문 + N턴마다 갱신하는 요약 |

- 단기 메모리는 M1, 장기 메모리는 M3다.
- 장기 메모리는 턴 뒤 비동기 작업이 추출 · 요약한다. **[결정 2026-11-09] 의미 검색(pgvector)은 미룬다** — 지금은 최근 기억
  N개(`settings.memory_prompt_limit`)를 프롬프트에 넣는다. 임베딩 모델을 고르면 다시 본다([ADR-0136](../adr/0136-companion-memory-in-postgres.md)).
- **유저는 기억을 보고 · 고치고 · 지울 수 있고, 무료다.** 지운 기억은 다음 턴부터 프롬프트에 들어가지 않는다.
- **[결정 2026-11-09] 기억 용량 상한** — 캐릭터 층 `settings.memory_cap`(초안 50, 유저 × 캐릭터마다) · 공유 층
  `settings.shared_memory_cap`(초안 30, 유저마다). 값은 §8 O22. 새 기억이 상한을 넘기면 유저가 고치지 않은 기억 중 가장 오래된
  것부터 지운다(`deleted_at`). **유저가 고친 기억(`memories.user_edited` — `companion_update_memory`가 켠다)은 지우지 않고**, 지울 것이
  없으면 새 기억을 넣지 않는다. 「가득 참」 = 그 층의 기억 수가 상한 이상이고 모두 고친 것 — 따로 저장하지 않고 읽을 때 계산하므로
  유저가 하나를 지우거나 상한을 올리면 풀린다. 앱은 목록 RPC `{ memories, count, cap, full }` · 턴 `state.memoryFull`(턴 시작
  기준)로 안다 — 정리를 권하는 것은 FE 몫이다.
- 장기 메모리 용량 과금은 후보로만 둔다(§8 O8).
- 미국 12 ~ 15세는 장기 메모리를 끈다(16세 이상 예외, SB 1119 기본값). 끈 동안에는 추출 작업도 돌지 않는다.
- **미성년자의 건강 · 심리 정보는 메모리에 저장하지 않는다**(뉴욕 Art.48). 추출 단계에서 걸러 낸다.
- 외부 메모리 서비스(mem0 등)는 쓰지 않는다. 대화 원문이 제3자 서버에 쌓이고, 캐릭터별 격리 · 스포일러 게이트가 특수해서다
  ([ADR-0136](../adr/0136-companion-memory-in-postgres.md) 초안, §9).

### 3.10 크레딧

원칙만 정한다. 숫자는 LLM 벤더 비교 뒤 원가를 실측해서 정한다(§8 O1 · O2).

- 1크레딧 = 고정 원가 X원. 행동별 크레딧 = 실측 원가 × 마진 배수.
- 1단계의 과금 행동은 **메시지 하나**였다(TTS는 범위 밖, §0). 2026-11-13 사진(35) · 사진 다시 그리기(25) · 음성(15)을 더했다 — [스냅샷 · 음성](ai-companion-snapshot.md) §6, ADR-0146. 미션은 2단계에 더한다.
- 유저에게 보이는 단가는 고정이다. 맥락이 길어져 생기는 원가 상승은 메모리 요약으로 묶는다.
- 버킷 셋: 구독 지급분(`sub`, 매달 소멸) · 무상 지급분(`grant`, 가입 무료 크레딧 등) · 구매분(`paid`, 1년 유지).
- 차감은 DB 트랜잭션 함수 하나에서 잔액 확인 → 차감 → 기록을 한 번에 한다. 같은 메시지를 두 번 보내도 한 번만 차감한다
  (API §6).
- [제안] **유저에게 답이 가지 않은 턴은 차감하지 않는다** — 입력 검사 차단 · 위기 프로토콜 · 출력 검사 차단 · 서버 오류. 위기
  상황에서 크레딧이 깎이면 안 되고, 받은 것이 없는데 돈을 내게 하지 않기 위해서다.
- [제안] 선톡은 유저 행동이 아니라 차감하지 않는다.
- 차감 버킷 순서(소멸이 가까운 것부터인지 등)는 정하지 않는다(§8 O2).
- 18세 미만 월 결제 상한은 결제 작업의 몫이고 값은 미정이다(초안 $100, §8 O4).

### 3.11 가드레일 6층

공식 캐릭터만 쓰니 캐릭터 발화는 전부 회사의 말이다. UGC로 책임을 나눌 수 없다.

| 층 | 내용 | 마일스톤 |
|---|---|---|
| 1. 입력 검사 | 싼 분류기로 성적 요청 · 자해 신호 · 개인정보를 잡는다 | M1 |
| 2. 페르소나 프롬프트 | 수위선과 회피 방식을 캐릭터마다 적는다 | M1(덕수쌤) · M3(다섯) |
| 3. 출력 검사 | **동기**(보내기 전): 미성년자 · 나이 모르는 유저. **비동기**(사후): 성인 — **만들지 않았다, 미룸**(아래) | M1 |
| 4. 위기 프로토콜 | 자해 · 자살 신호면 연기를 멈추고 안내와 현지 상담 기관 정보를 보낸다. 건수를 기록한다 | M1 |
| 5. 반복 위반 단계 제재 | 성격대로 회피 → 경고 → 일시 차단. 페르소나 거절(아래) | M3 |
| 6. 신고와 로그 보관 | 메시지 신고 RPC, 판정 로그 보관(Play 정책) | M1 |

**비속어 [결정 2026-11-09]** — 검사 분류에 `profanity`를 더했다. 언어를 가리지 않는다(검사 지시문에 ko · en · tl · vi · id · ja · es ·
th 예시와 변형 표기 — ㅅㅂ · 시1발 · f*ck 등).

| 입력 | 조치 |
|---|---|
| 캐릭터를 겨냥한 심한 욕설 · 혐오 표현 · 비하 · 성적 괴롭힘 · 위협 | 차단(`profanity`) |
| 가벼운 핀잔(바보 · 멍청이 · idiot) | 통과 |
| 누구를 겨냥하지 않은 욕(혼잣말) | 통과 — 피드백이 「비속어」로 짚는다(§3.5) |

- 캐릭터는 욕하지 않는다 — 출력 검사가 캐릭터 답의 비속어를 가벼운 것까지 막는다.

**성인 비동기 출력 검사 [결정 2026-11-09 — 미룸]** — 만들지 않고 둔다. 심한 · 성적 내용은 입력 차단과 페르소나 프롬프트 규칙이
막는다. 버린 것이 아니라 미룬 것이다 — 신고 · 판정 로그를 보고 다시 본다(§8 O21).

**페르소나 거절 [결정 2026-11-09]** — 입력 검사가 막으면(위기 제외) 시스템 오류 대신 캐릭터가 자기 성격 · 말투 단계로
거절하고 화제를 돌린다. 단계는 창(`settings.strike_window`, 24시간) 안의 반복 위반 수에 이번 차단을 더해 정한다.

| 이번 차단 | 단계 | 캐릭터 |
|---|---|---|
| 1번째 | `deflect` | 가볍게 피하고 화제를 돌린다 |
| 2번째(문턱 하나 앞) | `warn` | 분명한 경고와 함께 거절한다 |
| 문턱(`settings.strike_limit`, 기본 3) | 일시 차단 | 거절 답 없이 기존 `guardrail_blocked`. `settings.block_duration`(30분) 동안 다음 요청은 403 `temporarily_blocked` |

- 답 모델이 페르소나 프롬프트 + 거절 지시(단계 · 분류)로 만든다. **막힌 글은 모델에 주지 않는다.** 대사 2개 + 지문 1개까지.
- 미성년자 · 나이 모름은 거절 답도 출력 검사를 지난다. 생성 실패 · 시간 초과(10초) · 출력 검사 차단이면 페르소나의 정해진 줄
  (`persona.refusalLines[단계][말투]` → 없으면 존댓말 줄 → 코드 기본 줄)로 끝낸다 — 거절 턴은 늘 끝까지 간다.
- 거절 턴은 차감하지 않고, 보통 답처럼 번역되며, 피드백(`correction`)은 없다. 위반 수는 센다. 기억 추출 · 요약은 돌지 않는다.
- 위기 턴은 그대로 연기 없는 안전 안내다. 캐릭터 자신의 답이 출력 검사에 걸린 정상 턴은 거절로 바꾸지 않고 `guardrail_blocked`다.

- **AI 고지**: 첫 메시지 전과 3시간마다 「AI와 대화 중」이라는 고지를 보낸다(캘리포니아 SB 243 · 뉴욕 Art.47 · EU AI Act 50조 ·
  한국 AI 기본법 31조 요약 기준). 미성년자에게는 「미성년자에게 적합하지 않을 수 있음」 고지와 3시간마다 휴식 알림을 더한다.
  서버는 고지가 필요한 턴에 `notice` 이벤트를 보내고, 보낸 시각을 기록한다(API §4).
- **위기 프로토콜**: 위기 판정 턴은 캐릭터 연기 없이 정해진 안내만 보낸다. 상담 기관 정보는 유저 지역에 맞춘다. 판정 건수는
  보고용으로 남긴다(SB 243 연례 보고). 프로토콜 내용은 공개한다(SB 243). 안내 문안과 국가별 기관 목록은 만들면서 깎는다(§8 C).
- 동기 출력 검사가 걸리는 턴은 답변을 다 만든 뒤 검사를 통과해야 조각이 나간다. 그래서 첫 글자가 늦다. 이 지연은 미성년자
  보호의 대가로 받아들인다.
- 분류기 선택 · 임계값 · 연령대별 경계 예시는 만들면서 깎는다(§8 C). 경계 예시는 프롬프트와 평가 세트(§6)에 그대로 들어간다.

### 3.12 연령 · 미성년자

**연령 확인**

- 생년을 받는다. 스토어 연령 신호(예: Google Play Age Signals API)가 있으면 같이 쓴다. 소셜 로그인에서 받을 수 있는지는 팀원이
  확인 중이다(§8 O11).
- 결제 여부는 나이 신호로 쓰지 않는다(부모 카드일 수 있다).
- **나이를 모르면 미성년자 기본값을 적용한다.**
- [제안] 연령 필드는 기존 `public.learner_profiles`를 고치지 않고 `companion.profiles`에 둔다. 저장하는 것은 생년과 출처이고,
  연령대는 읽을 때 계산한다(해가 바뀌면 나이가 바뀐다).

**미성년자 기본값**

| 규칙 | 대상 | 값 |
|---|---|---|
| 성적 콘텐츠 없음 · 로맨스 없음 | 전 연령(v1) | — |
| 동기 출력 검사 | 18세 미만 · 나이 모름 | — |
| 하루 이용 시간 상한 | 18세 미만 | 초안 3시간(§8 O4) |
| 휴식 알림 · AI 재고지 | 18세 미만 | 3시간마다 |
| 연속 1시간 · 하루 2시간 상한 | 미국 12 ~ 17세 | SB 1119 기본값 |
| 장기 메모리 끔 | 미국 12 ~ 15세 | 16세 이상 예외 |
| 선톡 · 푸시 끔 | 미국 12 ~ 17세 | — |
| 건강 · 심리 정보 메모리 저장 금지 | 18세 미만 | 뉴욕 Art.48 |

- 미국 판정은 「스토어 국가 · 결제 국가 · 기기 지역 중 하나라도 미국이면 미국」이 위키 안이다. 판정 방식은 확인 필요다(§8 O12).
  출시가 시행일(2027-01 · 07)보다 빨라도 처음부터 이렇게 간다.
- 시간 상한에 닿으면 서버는 그 턴을 받지 않고 정해진 에러를 낸다. 언제 다시 쓸 수 있는지를 함께 보낸다(API §5).
- 보호자 동의가 필요한 연령(미국 13세 미만 · 한국 14세 미만 · 인도와 인도네시아 18세 미만)은 위키 04가 출시 전 필수로 적었지만
  동의 경로가 없다. [제안] 동의 경로가 생기기 전까지 그 연령은 컴패니언을 쓰지 못한다(`age_restricted`). 팀 확인 전이다(§8 O12).
- 부모 통제(16세 미만 부모가 접근 차단)는 경로가 없어 1단계 마일스톤에 넣지 않았다. 열린 질문이다(§8 O12).

### 3.13 계정 조건

- [제안] 1단계 컴패니언은 **로그인한 계정만** 쓴다. 덕수쌤 체험도 같다. 비회원([ADR-0111](../adr/0111-guest-entry-without-account.md))은
  진도가 기기에만 있고 서버 계정이 없어서 진도 기반 프롬프트 · 크레딧 · 연령 판정 · 메모리 · 시간 상한이 성립하지 않는다. 앱을
  지웠다 깔아 무료 체험을 되풀이하는 것도 막을 수 없다. 비회원에게 무엇을 보일지는 FE가 정한다. 팀 확인 전이다(§8 O7).
- [제안] M4 전(크레딧이 없는 동안)에는 **시험 계정만** 컴패니언을 부를 수 있다. 시험 계정 표시는 기존
  `app_metadata.duru_tester`([ADR-0085](../adr/0085-tester-access.md))를 쓴다. 같은 표시로 지표 집계에서도 뺀다.
  시험 계정도 크레딧 차감을 우회하지 않는다 — 운영자가 크레딧을 지급한다. 그래야 과금 경로를 시험 계정으로 검증할 수 있다.

### 3.14 LLM 단계별 모델 [결정 2026-11-09]

단계마다 모델을 환경 변수로 따로 고른다. 운영 값이 Sonnet · Haiku다(코드 기본값이 아니다). 계층은
[ADR-0135](../adr/0135-companion-llm-vendor-layer.md) 초안.

| 단계 | 환경 변수 | 비우면 | 운영 |
|---|---|---|---|
| 답변 · 선톡 | `COMPANION_MODEL` | 코드 기본값 | Sonnet |
| 피드백 | `COMPANION_FEEDBACK_MODEL` | `COMPANION_MODEL` | Sonnet |
| 입력 · 출력 검사 · 기억 추출 · 요약 | `COMPANION_MODERATION_MODEL` | `COMPANION_MODEL` | Haiku |
| L1 번역 | `COMPANION_TRANSLATION_MODEL` | 검사 모델 | Haiku |
| 추천 답변 | `COMPANION_SUGGEST_MODEL` | 검사 모델 | Haiku |
| 페르소나 거절 | `COMPANION_MODEL`(답변과 같다) | — | Sonnet |

- 번역 스위치 `COMPANION_TRANSLATION`: `every`(기본) · `off`.
- 서버 쪽 대체 모델(정책 거절 때 다른 모델로 다시)은 답변 호출에만 싣고, **Haiku로 도는 호출에는 싣지 않는다**(Haiku에는 대체
  모델이 없어 옵션을 실으면 요청이 거절된다).


### 3.15 답변 평가 버튼 · 고쳐서 다시 보내기 [결정 · 구현 2026-11-10]

⟨구현⟩ FE `feat/companion-m1`(마이그레이션 20261124): 평가 `companion.message_ratings` · `companion_rate_message` · 메시지 목록의 `rating` ·
운영 지표 `companion_rating_stats`, 고쳐서 다시 보내기 `chat-send`의 `replaces_message_id` → `companion_begin_replacement`. 이름 · 모양은
API §2.8. 공지(AI 고지 등)는 숨기지 않고 두며, 고쳐서 숨긴 턴은 앱 메시지 목록에서 아예 빠진다(운영 조회에는 남는다).

**👍/👎 답변 평가** — 캐릭터 메시지마다 유저가 평가를 남긴다.

- 👎을 누르면 이유를 고른다(여럿 가능): `awkward_korean` 한국어가 어색함 · `out_of_character` 캐릭터답지 않음 · `too_hard` 너무
  어려움 · `uncomfortable` 불편함 · `other` 기타(짧은 글 선택). 👍에는 이유를 묻지 않는다.
- 메시지당 하나, 다시 누르면 바꾸거나 지운다. 첫 인사 · 선톡 · 거절 답에도 단다. 위기 안내 · 공지에는 없다.
- 저장: 새 표 `companion.message_ratings`(메시지 · 유저 · 👍/👎 · 이유 · 시각). 신고(`companion_report_message`)와는 따로다 —
  「불편함」을 고르면 화면이 신고도 권할 수 있다(FE).
- 쓰임: ops-dashboard 컴패니언 지표(캐릭터 · 모델 · 단계별 👎 비율과 이유)와, 👎 받은 턴을 평가 세트 후보로 모으는 데. 크레딧과 무관.
- 로그에 대화 원문을 싣지 않는다(§7) — 평가 표는 메시지 id만 건다.

**고쳐서 다시 보내기** — 마지막 유저 메시지 하나를 고쳐 다시 보낸다. 학습 앱에서는 교정 카드를 본 뒤 고친 문장으로 다시 말해
보는 연습이 된다.

| 규칙 | 내용 |
|---|---|
| 범위 | **마지막 유저 메시지만.** 그 뒤에 캐릭터 답이 하나 더 오기 전까지. 더 앞 메시지는 고칠 수 없다 |
| 들어가는 곳 | 교정 카드의 「고친 문장으로 다시 보내기」(고친 문장이 입력창에 채워진다)와 유저 말풍선의 「고치기」 |
| 이전 턴 | 지우지 않고 숨긴다(유저 메시지 · 캐릭터 답 · 칩 · 교정 모두). 목록에서 빠지고 운영 조회에서는 보인다 |
| 크레딧 | 새 턴으로 차감한다 |
| 검사 | 입력 검사를 그대로 받는다. 차단된 메시지를 고쳐 보내는 것은 되지만 위반 횟수(§3.11)는 지우지 않는다 |
| 뒤 작업 | 숨긴 턴은 기억 추출 · 요약 원문에서 뺀다. 이미 그 턴으로 뽑힌 기억은 그대로 둔다(유저가 기억 화면에서 지울 수 있다) |
| 친밀도 · 화제 상태 | 숨긴 턴에서 바뀐 값은 되돌리지 않는다(작은 오차를 받아들인다) |

**답 다시 만들기** — 미룬다. 기억 · 요약 · 칩 · 피드백이 원래 답에 걸려 있어 얽히는 것이 많고, 학습 대화에서는 우선순위가 낮다.
넣는다면 마지막 답만, 원래 답은 숨긴 변형으로 남기고, 비용 정책을 먼저 정한다(O23).

## 4. 정보가 클라이언트로 오는 시점

한 턴의 흐름이다. 이벤트 이름 · 필드는 [API 명세](ai-companion-api.md) §4가 정본이다.

```text
앱 ── POST chat-send ──▶ 서버
                         ① 인증 · 요청 검사 · 접근 · 연령 · 시간 상한 · 체험 한도 · 크레딧 예약
   ◀── HTTP 4xx/5xx ─────┘  (여기서 막히면 스트림 없이 JSON 오류 하나)
   ◀── 200 SSE 시작 ─────── ② 유저 메시지 저장 → start
   ◀── notice ───────────── ③ AI 고지 · 휴식 알림이 필요한 턴만
                         ④ 입력 검사 — 막히면 blocked / 위기면 crisis 뒤 끝
   ◀── delta × n ────────── ⑤ 메인 답변 조각(성인은 생성되는 대로, 미성년자는 출력 검사 통과 뒤)
   ◀── correction ───────── ⑥ 메시지별 피드백(메인과 병렬, ⑤ 사이 어디든)
   ◀── translation × n ──── ⑥' 답 조각의 L1 번역(답이 끝난 뒤 따로 호출, 2026-11-09)
   ◀── state ────────────── ⑦ 말투 단계 · 단계 변경 여부
   ◀── done ─────────────── ⑧ 차감 확정 · 사용한 크레딧
                         ⑨ 저장 · 후처리(메모리 추출 · 요약 — 구현은 큐 대신 같은 요청의 waitUntil, 사후 출력 검사는 미룸)
```

| 정보 | 언제 오나 | 어떻게 |
|---|---|---|
| 답변 글자 | 같은 턴, 조각으로 | `delta` |
| 메시지별 피드백 | 같은 턴, 답변과 섞여서 | `correction`. 놓쳤으면 메시지 목록 RPC로 다시 받는다 |
| 말투 단계 변경 | 같은 턴 끝 | `state` |
| 친밀도 수치 | **오지 않는다** | — |
| AI 고지 · 휴식 알림 | 필요한 턴의 답변 앞 | `notice` |
| 답변 번역(L1) | 같은 턴, 답 조각 뒤 · `state` 앞 | `translation`. 메시지 목록에도 조각의 `translation`으로 |
| 차단 · 위기 | 같은 턴, 답변 대신 | `error`(`guardrail_blocked`) · `crisis`. 입력 차단은 문턱 전까지 페르소나 거절 답(`delta` … `done.refusal`)으로 온다(§3.11) |
| 크레딧 잔액 | 턴 끝(M4) · 지갑 RPC | `done` · RPC |
| 장기 메모리 | 턴 뒤 비동기로 만들어짐 | 메모리 목록 RPC로 조회. 가득 참은 `state.memoryFull` · 목록 `{ memories, count, cap, full }` |
| 추천 답변 | 앱이 버튼으로 요청할 때 | `companion-suggest`(API §2.6) |
| 사후 출력 검사 결과 | — | 미룸(§3.11). 목록의 `hidden`은 자리만 있다 |
| 선톡 | 앱이 꺼져 있으면 푸시, 켜져 있으면 다음 목록 조회 | 메시지 목록 RPC. 푸시는 아직 없다(API §2.3 인계) |

## 5. 마일스톤과 완료 조건

마일스톤마다 짧은 `feat/companion-*` 브랜치 → PR → `main`이다. 열린 값은 완료 조건에 숫자로 넣지 않는다 — 「설정 값으로 받는다」
까지가 조건이다. 운영 DB 반영(`supabase db push`)은 마일스톤마다 따로 확인한다.

## 6. LLM 평가

모델 선택과 프롬프트 수정 때마다 돌린다. 시나리오 · 채점 코드는 `apps/supabase-functions`에 둔다(위키 05 「개발 환경과 레포」).

- 고정 시나리오 50 ~ 100개: 캐릭터별 일상 · 레벨별 발화 · 한국어와 모국어 혼용 · 틀린 문장 · 수위 넘기 시도 · 자해 신호 ·
  플러팅 · 개인정보 · 미성년자 건강 정보.
- 채점 축: 페르소나 유지 · 한국어 자연스러움 · 레벨 준수(i+1) · 교정 정확도 · 가드레일 통과 · 스포일러 없음.
- 1차는 LLM-as-judge 자동 채점, 한국어 원어민 팀원이 샘플을 검수한다.
- 벤더 비교 항목에 이용약관의 로맨스 · 미성년자 허용 범위를 넣는다.
- 마일스톤 게이트: M1은 가드레일 · 위기 시나리오, M2는 교정 정확도 · 방식별 답변, M3는 다섯 캐릭터의 페르소나 유지와 메모리
  시나리오를 통과해야 끝난다. 기준값은 각 마일스톤을 시작할 때 평가 세트와 함께 정한다.
- 평가 결과는 ops-dashboard 컴패니언 탭에서 본다(위키 05).
- ⟨2026-11-09⟩ 한 단계 평가 창구 Edge Function `companion-eval`(서버 키)이 있다 — 운영과 같은 프롬프트로 검사 · 피드백 · 번역 하나를
  케이스 1 ~ 20개에 돌린다(API §2.7). ops-dashboard 컴패니언 섹션은 플레이그라운드 · 워크플로 · 문서 · 평가 · 판정 · 신고 화면이다.
  고정 시나리오 세트 · LLM-as-judge 자동 채점은 이 저장소에 아직 없다.
- ⟨2026-11-10 제안⟩ 채점 축에 「학습 표현 자연스러움」(§3.7)을 더한다. 👎 받은 턴(§3.15)을 고정 세트 후보로 모은다.

## 7. 측정과 위험

**서버가 남기는 것**

| 무엇 | 왜 |
|---|---|
| 턴 수 · 첫 조각 지연 · 턴 소요 시간 · 실패 사유 | 품질 · 원가 |
| LLM 호출별 토큰 · 모델 | 크레딧 단가 산정(§8 O1) |
| 가드레일 판정(층 · 분류 · 조치) | 정책 · 신고 대응 |
| 위기 프로토콜 발동 건수 | SB 243 연례 보고 |
| 교정 생성 수 · 종류 | 피드백 방식 실험 |
| 신고 | Play 정책 · 품질 |

- 대화 내용은 광고 · 판매에 쓰지 않는다. 로그 · 분석 이벤트에 대화 원문 · 생년 · 이메일을 싣지 않는다.
- 클라이언트 측 지표(교정 열람률 · 대화 중단 지점)의 이벤트 설계는 FE 몫이다.
- 시험 계정(`duru_tester`)은 집계에서 뺀다.

**위험**

1. **Lynx 앱에서 SSE를 읽을 수 있는지 확인되지 않았다.** 2026-11-08 기준 앱 코드에 스트리밍 응답을 읽는 자리가 없다
   (`getReader` · `EventSource` 0건). 안 되면 호스트 네이티브 모듈이 스트림을 받아 JS로 넘기는 경로가 필요하다. M1 전에 FE가
   확인한다. 결과에 따라 ADR-0134 초안(SSE)을 다시 본다.
2. **운영 DB에서 개발한다**(위키 05, 2026-11-08). `db push` 전에 `main`의 다른 미배포 마이그레이션이 같이 올라가지 않는지
   확인한다. 컴패니언 표는 `companion` 스키마라 기존 표와 이름이 섞이지 않는다.
3. **Deno가 계약 패키지를 불러오는 방식이 검증되지 않았다.** M0에서 생성 사본 + import map으로 실제 배포까지 확인한다
   (API §8).
4. **동기 출력 검사의 지연** — 미성년자 · 나이 모르는 유저는 첫 글자가 늦다(§3.11).
5. **운영 DB의 마이그레이션 기록이 비어 있다**(2026-11-09). 컴패니언 마이그레이션(20261108 ~ 20261116)은 `db push`가 아니라 SQL
   편집기로 적용했고, `supabase_migrations.schema_migrations`에는 일부러 쓰지 않았다. 뒤에 더한 20261117 · 20261118(거절 · 기억 상한 ·
   추천 답변)의 운영 적용 여부는 이 갱신에서 확인하지 않았다. 그래서 다음 `supabase db push`는 이 판들을
   미적용으로 보고 다시 올리려 한다. 기록을 맞추는 방법(`supabase migration repair` 등)과 시점은 **세현님이 정한다**. [제안] 그 전에는
   운영에 `db push`를 돌리지 않는다.
6. **성인 사후 출력 검사가 없다** — 성인 답은 검사 없이 나간다. 입력 차단 · 페르소나 규칙에 기댄다(§3.11, O21).
