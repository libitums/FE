# 화면 명세

이 문서는 **무엇을 만들지**를 적는다. 어떻게 만들지는 ADR이, 어떻게 확인할지는
`docs/e2e/`가 맡는다.

출처는 오래 **사용자 발화 하나뿐이었다** (2026-08-31 논의). 디자인 파일이나 다른
저장소를 읽어서 채우지 않았다. 발화에서 추론한 항목은 `[추론]`으로 표시했고, 확인을
받기 전까지 표시를 유지한다.

**2026-09-03에 두 번째 출처가 들어왔다.** 여정 맵을 실기로 확인하다가 이 문서가
비워 둔 자리가 드러났고, 사용자가 그 자리를 확정했다 (아래 「여정 탭」). 실기가
드러낸 빈칸을 사용자가 직접 메운 것이므로 추론이 아니고, `[추론]`을 붙이지 않는다.

**2026-09-07에 세 번째 출처가 들어왔다.** 앞의 둘과 성격이 다르다 — 실기가 빈칸을
드러낸 것이 아니라, **이 문서가 스스로 「아직 정하지 않은 것」으로 세어 둔 표의 항목
둘이 닫혔다** (아래 「문화 학습과 문화 퀴즈」의 제시 형태 · 퀴즈 문항 형태). 사용자가
**버린 대안과 그 이유까지 함께** 냈으므로 추론이 아니고, `[추론]`을 붙이지 않는다.

**2026-09-15에 네 번째 출처가 들어왔다** — 사용자 결정 열 건(Q1~Q10, LIB-257)이다. 홈 탭을
계획에서 걷었고(Q1), 노티피케이션의 진입점을 여정 맵 머리의 알림 버튼으로 옮겼으며(Q2 · Q6 ·
Q9), 여정을 **공통으로 시작해 진행 중간에 선택지가 주어지는** 형태로 바꿔 여정 선택을 단순
입장 화면으로 줄였다(Q5 · Q8). 사용자가 직접 정했으므로 추론이 아니고, `[추론]`을 붙이지
않는다. 바뀐 자리는 「진입 흐름」 · 「여정 탭」 · 「탭별 스택」 · 「여정 입장 화면」 ·
「순서」다.

---

## 목적 (goal)

서사와 그 안의 에피소드라는 **배경** 속에서 한국어를 배워, 단어·조사·상황을 따로
외울 때 생기는 *"이해가 어렵고 기억이 안 되는"* 문제를 푼다.

습관을 세로로 쌓는 방식(듀오링고)이 아니라 **경험을 가로로 넓히는** 방식이다. 이
차이가 화면 구조에 그대로 드러난다 — 중심은 연속 기록이 아니라 여정과 에피소드다.

## 타깃 (target)

- 디바이스: 모바일 (iOS). 시연은 iOS 시뮬레이터
- 브라우저 하한: 해당 없음. Lynx는 브라우저가 아니다 (ADR-0012)

## 화면 목록

세 곳으로 나뉜다. 진입 흐름은 **탭이 아직 없는 구간**이고, 나머지는 탭 안이다.

탭은 **셋 — 여정 · 롤플레이 · 설정**이다. 홈 탭은 2026-09-15에 계획에서 걷었다 (LIB-257) —
노티피케이션은 여정 탭으로(아래 「여정 탭」), 여정 선택은 입장 화면으로(아래 「여정 입장
화면」) 옮겼다.

### 진입 흐름 (탭 밖)

스플래시에서 갈린다.

```
스플래시 ─┬─ 첫 사용자   온보딩 → 로그인 → [전화번호면] 코드 검증 → 언어 선택 → 여정 입장 → 여정 맵
          └─ 재방문      여정 맵
```

⟨2026-09-30⟩ **로그인에 닿는 셋째 경로가 생겼다 — 앱 구간에서 떠날 때.** 설정의 `Sign out` 또는 계정 삭제가
끝나면 스플래시 없이 **로그인**이 선다(뒤로가면 온보딩). 스택만 되돌리는 것이 아니라 앱 상태 전체(진행 ·
알림 · 세션 옵션 · 젬)가 처음 값으로 다시 선다([ADR-0032](adr/0032-account-sign-out-and-deletion.md) D6).

```
설정 ─ Sign out / Delete account ─→ [온보딩, 로그인] → 로그인 → … → 여정 맵
```

여정 입장 뒤는 탭 구간이고, 앱의 첫 화면은 여정 탭의 **여정 맵**이다 (2026-09-15, LIB-257 —
그 전에는 홈이었다).

재방문 판단은 **로그인 토큰이 있는지**로 한다. 새 저장 항목을 만들지 않는다 — 저장소에
넣는 것은 로그인 토큰뿐이라는 ADR-0007 D1을 그대로 지킨다.
⟨2026-09-29⟩ 로그인 자격이 **둘**이 됐다 — 전화번호로 들어오면 Supabase 세션, 소셜로 들어오면
임시 토큰이다. 세션이 있으면 스플래시가 서버에 갱신을 요청하고, **성공하면 여정 맵 · 실패하면
로그인**이다. 둘 다 로그인 자격이라 D1은 그대로다([ADR-0027](adr/0027-phone-otp-auth-supabase.md) D3 · D4).
⟨2026-09-29, 같은 날 뒤⟩ **새 설치의 자격은 다시 하나 — 세션이다.** 소셜 셋도 Supabase OAuth로
들어와 같은 세션 · 같은 갱신을 탄다([ADR-0028](adr/0028-social-oauth-web-authentication.md)). 임시
토큰은 이 변경 전에 소셜로 들어온 설치에만 남고, 스플래시는 그것을 여전히 곧장 앱으로 보낸다
(⚠ 사용자 확인 필요 — ADR-0028 D6).
⟨2026-09-29, 같은 날 셋째 — 사용자 결정⟩ **옛 임시 토큰도 자격이 아니다.** 스플래시는 그 키를 읽지
않고, 세션이 없으면 누구든 **온보딩부터** 간다(ADR-0028 D6). 로그인 자격은 **세션 하나**다.

온보딩만 보고 나간 사용자는 다시 오면 온보딩부터 본다. 온보딩 완료 플래그를 따로
저장하지 않기 때문이다. 그 정도는 감수한다 — 플래그를 하나 두는 순간 무효화를 사람이
책임지게 되고, 그것이 D1이 막으려던 것이다.

**이 분기는 2026-09-17에 실재하게 됐다 (LIB-261).** 원래 이 자리는 *"토큰이 생긴 뒤에야 실제로
확인된다 — 서버가 없어 지금은 토큰을 발급할 수단이 없다"* 였다. **임시 토큰이 생겼다** — 로그인
수단을 고르면 호스트 저장소에 고정 리터럴 하나가 `libitum.auth.token` 키로 저장되고, 다음 실행의
스플래시가 그 키의 유무로 갈린다. ⚠ **확인되는 것은 「분기가 돈다」이지 「인증이 된다」가 아니다** —
서버가 없어 발급도 검증도 없고, 저장되는 값은 누가 로그인했는지도 언제인지도 담지 않는다.
**진짜 인증은 여전히 범위 밖**이고, 그날 바뀌는 것은 그 값을 만드는 함수 본문 하나다.

**2026-09-29 — 전화번호 경로는 진짜 인증이 됐다** ([ADR-0027](adr/0027-phone-otp-auth-supabase.md)).
번호를 내면 Supabase가 SMS로 6자리 코드를 보내고, 코드가 맞아야 세션이 저장된다 — **검증 전에는
저장소에 아무것도 쓰지 않는다.** 위 문단은 **소셜 셋에 대해서만** 참으로 남는다. ⚠ 위 문단의
예고(*"바뀌는 것은 함수 본문 하나"*)는 **틀렸다** — 세션은 임시 토큰과 모양이 달라 키를 따로 두었고,
스플래시에 갱신 갈래가 생겼으며 두 화면이 요청 중 · 실패 상태를 얻었다.

**2026-09-29 — 소셜 셋도 진짜 인증이 됐다** ([ADR-0028](adr/0028-social-oauth-web-authentication.md),
제안 상태). 수단을 누르면 **시스템 인증 창**이 앱 위에 떠 제공자 로그인을 받고, 창이 닫힌 뒤
Supabase가 세션을 내줘야 저장된다. 그래서 위 임시 토큰 문단은 **이 변경 전에 들어온 설치**에만
참으로 남는다. ⚠ 제공자 · 대시보드 설정이 아직 없어 실서버로 돈 적은 없다.
⟨같은 날 뒤 — 사용자 결정⟩ **Apple은 창이 아니라 네이티브 Sign in with Apple 시트**다 — 시트가 준 ID
토큰을 Supabase가 세션으로 바꾼다(ADR-0028 D7). Google · Facebook은 위 인증 창 그대로다. 그리고 **위
임시 토큰 문단은 이제 어느 설치에서도 참이 아니다** — 옛 설치도 온보딩부터 다시 지난다(ADR-0028 D6).
화면(버튼 · 문구 · 상태)은 바뀌지 않았다.

⚠ **되돌릴 수단이 없다.** 토큰을 지우는 수단이 앱에 없어서(로그아웃은 만들지 않았다) **한 번
끝까지 지나가면 진입 흐름을 다시 볼 수 없고, 다시 보려면 앱을 삭제하고 재설치해야 한다.**
결함이 아니라 이 회차의 대가이고, 계약과 절차는 [진입 흐름 스펙](specs/entry-flow.md)과
[진입 흐름 e2e](e2e/entry-flow.md)가 진다.
⟨2026-09-30⟩ **되돌릴 수단이 생겼다** — 설정의 `Sign out`이 세션을 지우고 로그인으로 보낸다. 다시 켜면 새
설치와 같이 스플래시 → **온보딩**이다(「온보딩을 봤다」를 저장하지 않는다 — 위 문단의 판단 그대로).

아래 표는 첫 사용자 경로다.

| 화면 | 내용 |
|---|---|
| 스플래시 | 서비스 이름과 한 줄 문구만 보인다. **조작 수단이 0건**이고 **고정 시간 뒤 스스로 넘어간다** — 토큰이 있으면 여정 맵으로, 없으면 온보딩으로 갈린다. **세션이 있으면(2026-09-29 — 전화번호 · 소셜 모두) 갱신 요청이 끝날 때까지 그대로 서 있다가** 성공하면 여정 맵, 실패하면 로그인으로 간다. 로고·진행 표시·모션이 없다 |
| 온보딩 | 서비스 요약 3종. **화면 하나에 `step: 0\|1\|2`.** 형태가 동일하고 문구·이미지만 달라서 레이아웃을 세 번 복사할 이유가 없다 |
| 로그인 / 회원가입 | 전화번호 · 구글 · 애플 · 페이스북. ⟨2026-09-29⟩ **전화번호 수단은 잠시 숨겼다** — 로그인 화면에는 소셜 셋만 서고 제목은 `Log in or Sign up`이다([ADR-0027](adr/0027-phone-otp-auth-supabase.md) D7). 아래 전화번호 동작은 되살렸을 때의 것이다. 전화번호는 **코드 요청이 성공해야** 코드 검증으로 넘어가고, 실패하면 로그인에 오류 문구가 선다. 소셜 셋은 **시스템 인증 창에서 로그인을 마쳐야** 언어 선택으로 넘어간다 — 창을 닫으면(취소) 아무 일 없이 로그인에 남고, 실패하면 같은 자리에 오류 문구가 선다. 어느 수단이든 요청 중이면 네 수단 전부가 무동작이다 |
| 코드 검증 | **6자리**(2026-09-29 — 4자리에서 바뀌었다, Supabase SMS OTP). **전화번호 경로에서만** 나타난다. 틀리거나 만료된 코드는 오류 문구로 서고, 재전송은 실제로 코드를 다시 요청한다 |
| 언어 선택 | 자신의 언어. ⟨2026-09-29⟩ **고른 언어가 곧 UI 언어다** — 확정(`Continue`) 때 저장되고 재실행 · 재방문에도 유지된다. 지금 고를 수 있는 것은 영어뿐이고, 없는 언어 · 빠진 문구는 영어로 대체된다([ADR-0031](adr/0031-ui-language-catalog.md)) |
| 여정 입장 (옛 여정 선택) | 여정에 들어가는 단순 입장 화면. **고르지 않는다** — 여정은 모두 공통으로 시작한다 (아래 「여정 입장 화면」) |

### 여정 탭

듀오링고의 레벨형 UI와 비슷한 형태다.

| 화면 | 내용 |
|---|---|
| 여정 맵 | 레벨형. **완료·현재 스텝**을 누르면 **맵 위에 시트**가 겹쳐 뜬다. **잠긴 스텝은 눌러도 열리지 않는다.** ⚠ **구획의 표지를 끝내기 전에는 그 에피소드의 나머지가 전부 잠긴다** (아래 「유닛」). **에피소드 하나가 구획 하나**이고 구획 사이를 **연한 가로 선**이 가른다 — **세로 줄 하나 그대로**이고 가로로 넘기는 것이 없다. **아직 유닛이 없는 에피소드도 자기 구획을 만든다**: 머리(번호·이름)는 읽히고 그 아래는 가려진 표식 하나와 `COMING SOON`이며 **눌러도 아무 일이 없다**(아래 「유닛」). **에피소드 머리 카드는 스크롤 밖에 하나만** 서고 무엇을 말할지는 스크롤 자리가 고른다 — 구획마다 달라붙이는 방식은 Lynx에서 서지 않는다(ADR-0022 D4) |
| 학습 | 아래 세 유형. **셋은 분류가 아니라 각각 화면이고, 스텝 하나가 학습형 목록을 갖는다** — 다섯 스텝이 셋을 다 도는 것이 아니다. **결선은 됐고 배정만 남았다** — 시작이 배정표(`learningFormsByStep`)의 목록을 앞에서부터 한 활동씩 열고, 목록이 끝나면 평가로 간다. 배정 값이 오는 날 **코드 변경 없이** 화면이 갈린다. ⚠ **오늘 스텝마다 열리는 것이 무엇인지는 그 스텝의 목록이 말한다 — 표의 값은 배정이 아니라 문항이 있는 표의 전사(轉寫)다** (아래 「학습의 세 유형」) |
| 말하기 | 기본 학습형의 다섯째(`speaking`, Figma 65-282). 따라 말할 문장 · 발음 표기 · 파형이 카드에 서고, 호스트의 음성 인식(`SpeechRecognitionModule`)으로 듣는다. 결과는 말하기를 멈출 때 한 번 오고, **앞에서부터 맞게 말한 낱말**을 주황으로 칠해 문장을 다 맞으면 정답이다. **건너뛰기는 두 갈래이고 결과가 반대다.** ⓐ **모듈이 없거나 권한이 없으면** 판정하지 않고 건너뛴다 — 그 문항은 **결과에 싣지 않는다**(기기 탓을 오답으로 접지 않는다). ⓑ **사용자가 `건너뛰기`를 누르면** 그 문항을 **`correct`로 싣는다** — 기기가 멀쩡해도 누를 수 있다. **다만 말하기 전에만** 선다: 듣는 중에는 「멈춰서 판정받기」와 「건너뛰기」가 결과가 반대인데 되돌릴 수 없고, 판정 뒤에는 이미 실린 결과를 덮게 된다. **두 갈래를 뭉치지 마라** — ⓐ는 기기 탓이고 ⓑ는 사용자 사정이라, 합치면 ⓐ의 근거가 사라진다. ⓑ로 건너뛴 수는 **통과 계산에는 들어가고 만점에는 안 들어간다**(아래 「학습 완료」 행). 이름 묻기 스텝이 듣기 뒤에 잇고, 문항은 임시 셋이다 |
| 쓰기 | 기본 학습형의 여섯째(`writing`). **형제 학습형과 같은 배치다** — 무대 카드에 판정 자리 · 빈칸 문장 · 번역 · 음절 칸이, 카드 아래 작업 영역에 쓰기 캔버스(340 × 200)가 서고, 아래 버튼은 껍데기의 주색 버튼이다. 작업 영역은 스크롤을 끈다(그리기 표면과 스크롤이 제스처를 다투지 않게). 빈칸의 음절을 **하나씩** 흐린 안내 글자 위에 따라 쓴다. 안내는 호스트(`HandwritingTraceModule`)가 구운 그림이라 **보는 것과 재는 것이 같은 픽셀**이다. `확인하기`로 견주고(덮음 · 머무름이 둘 다 문턱 이상이면 정답 — 문턱은 `lib/writing-judge.ts`의 임시값), 판정 배지가 카드에 서고 안내가 걷히며 `Next`으로 다음 음절로 간다(문장 만들기처럼 버튼으로 넘긴다 — 스스로 넘어가는 층은 `다시 쓰기`를 가린다). 틀리면 캔버스의 `다시 쓰기`로 같은 음절을 다시 쓸 수 있고, 넘어갈 때의 판정이 실린다. **모듈이 없으면 안내를 글자로 대신 보이고 판정하지 않고 넘어간다** — 잰 음절이 없는 문항은 결과에 싣지 않는다. 쓰기의 핵심(흐름 · 판정 · 캔버스)은 최종 테스트의 쓰기 문항(장면 위 어두운 패널, Figma 79-6378)과 공용이다. 길 묻기 스텝이 듣기 뒤에 잇고, 문항은 임시 셋이다 |
| 평가 | 학습 완료 후 **미통과**일 때. **방금 푼 문항별 정오 + 종합 판정 낱말**(`Passed`/`Not passed`)만 보여준다 — **점수도 정답 수도 없다.** 나가는 수단은 **"Back to map" 하나**다 |
| 학습 완료 | 학습 완료 후 **통과**일 때 평가 대신 선다(Figma 65-466). 같은 `assessment` route이고 판정으로 갈린다. 제목(`PERFECT LESSON!` / `LESSON COMPLETE!`) · 설명만 바뀐다 — 실수가 있는 경우의 문구는 디자인이 없어 임시다. ⚠ **제목과 설명이 보는 수가 다르다** — 제목은 **실수 수와 건너뛴 문항 수**를 함께 보고(둘 다 0이어야 만점이다), 설명은 **실수 수만** 본다. 그래서 `LESSON COMPLETE!` + `YOU MADE NO MISTAKES IN THIS LESSON`이 함께 설 수 있고 **그것이 참이다** — 틀리지는 않았지만 다 풀지도 않았다. 낭독은 건너뛴 수를 덧붙인다 — 시각에 만점이 아닌 제목이 섰는데 낭독만 만점처럼 들리면 **보는 사람과 듣는 사람이 다른 정보를 받는다**(WCAG 1.3.1). 상단 지표 칩 둘(연속 학습·트로피, 젬 칩 숨김) · 연속 알약 · 보상 카드 둘(다이아 · 등급)이 있고, **지표는 규칙이 없어 0, 보상은 임시값**(`lessonRewardPlaceholder`)이다. 나가는 수단은 **`Check` 하나**이고 맵으로 간다 |
| 문화 학습 | 기본 학습형의 여섯째 형태. **낱말이 아니라 맥락을 가르친다** |
| 문화 퀴즈 | 문화 학습이 가르친 것을 묻는다. **평가와 다른 화면이다** |
| 카페 도착 비주얼 노벨 | 여정 맵의 `Jimin arrives at the café` 특별 항목에서 여는 고정 3장면 화면. 마지막 장면에 닿으면 완료되고 `Back to map` 나간다 |
| 에피소드 표지 | 에피소드의 **첫 유닛**이다. 맵의 그 항목을 눌러야 열린다 — **다른 유닛을 눌렀을 때 끼어드는 화면이 아니다**(아래 「유닛」). 에피소드의 두 줄(`Episode 0.` / `Tutorial.`)과 `Skip` · `Next`가 서고, `Skip`은 **확인 모달**(`Skip the story?` — `Skip` / `Keep watching`)을 거친다. **`Skip`과 `Next`는 둘 다 학습 완료(PERFECT LESSON) 결과 화면에 닿고 그 화면의 `Check`가 완료를 적는다** — 서사에는 잴 것이 없어 실수도 건너뛴 문항도 0이라 만점인 것이지 「건너뛰면 만점」이 규칙인 것이 아니다. 뒤로(`Back to map`)는 완료로 적지 않아 다음에 표지부터 다시 선다. **측정 이벤트 다섯**(표지 열림 · 건너뛰기 · `Next` · 뒤로 나가기 · 서사 완료)은 `episode-intro.contract.ts`의 `EpisodeIntroEvent`가 정본이고, 키가 있는 빌드에서는 PostHog로 나간다([ADR-0029](adr/0029-product-analytics-posthog.md) D14) |
| 에피소드 서사 | 에피소드 표지의 **`Next`** 뒤에 서는 서사 전개다. **에피소드마다 형식을 하나 고른다** — 통화 · 메신저 · 비주얼 노벨이고, 이 행이 적는 것은 그중 비주얼 노벨(Figma 79-6304)이다. 표지를 갈아타고(`replace`) 서며, 화면 어디를 · 대화 패널을 눌러도 다음 장면으로 넘어간다. **어느 형식이든 끝나면 학습 완료(PERFECT LESSON)를 거쳐 맵으로 간다** — 흐름은 표지 → 서사 → 학습 완료 → 맵이고, 그 에피소드에 서사가 없으면 `Next`가 `Skip`과 **같은 곳**으로 간다. 뒤로(`Back to map`)는 맵으로 가며 본 것으로 적지 않아 다음에 표지부터 다시 선다. **대본은 임시**다 — 모든 에피소드가 뷰티 스토어 · 이유나 세 장면을 함께 쓴다(`episodeNarrativeFor`). 그림은 온보딩 첫 스텝과 같은 그림(`src/assets/story/`)이다 |
| 노티피케이션 (화면 제목 `Notifications`) | 여정 맵 머리의 알림 버튼이 연다 — **여정 스택에 쌓이고** 나가기는 `Back to map`다. 항목을 누르면 **특별 유닛**(메신저 · 전화 · 비주얼 노벨 — 여정 모드라 완료가 기록되고 나가기가 `Back to map`) 또는 **롤플레이 목록**(롤플레이 탭으로 전환 — 여정 스택의 알림은 남는다)으로 간다. 읽음 표식 · 배지가 **없다.** 항목은 **임시값**이다 |

스텝을 누르면 뜨는 것은 **화면이 아니라 시트**다. 스텝 정보와 "시작" 버튼이 맵 위에
겹친다. `Screen` 유니온에 들어가지 않고 여정 맵의 내부 상태로 있어서 스택이 깊어지지
않고, 닫을 곳도 늘지 않는다.

**여는 것은 완료·현재 스텝뿐이다. 잠긴 스텝은 눌러도 시트가 뜨지 않는다.** 잠긴
스텝의 시트에는 아직 갈 수 없는 곳으로 보내는 "시작" 버튼이 있어서, 열면 할 수 없는
일을 약속하게 된다.

**왜 잠겼는지**를 알리는 수단은 **구현 순서 2번이 답했다.** 별도의 안내 문구를 두지
않는다 — **스텝을 통과하면 진행이 갱신되고 다음 스텝이 열린다.** 잠김이 *"아직 도달하지
않음"* 이라는 것을 사용자가 **맵에서 목격한다**(방금 돈 스텝이 완료가 되고 현재 노드가
다음으로 옮겨간다). 진행 갱신은 **되돌아가지 않는다** — 이미 완료한 스텝을 다시 돌아도
줄지 않는다.

**스텝 완료를 거는 것은 학습이 아니라 평가의 판정이다** (구현 순서 3번이 뒤집었다).
**문항 셋 중 2 이상**을 맞히면 통과이고 그때만 진행이 갱신된다. **미통과면 완료가
걸리지 않아 그 스텝이 맵에서 여전히 현재 스텝으로 남고, 노드를 다시 눌러 시트의
"시작"으로 처음부터 다시 풀 수 있다.** 재시도 수단을 새로 만들지 않은 것이 그
때문이다 — **맵이 이미 재시도 수단이다.** 학습 도중에 나가는 것(중도 이탈)도 진행을
갱신하지 않는다: **미통과와 중도 이탈은 결과가 같고 경로가 다르다.**

**평가 화면은 「다시 풀 수 있다」를 낱말로 말하지 않는다.** 나가는 수단이 통과·미통과
모두 "Back to map" 하나이고, 재시도가 맵에 있다는 것은 **앱의 구조가 말한다.** 문구를 늘릴
근거는 관측에서만 나온다 — 그 자리는 `docs/e2e/assessment.md`의 **E7 · M2**다.

**진행은 세션 안에서만 산다.** 앱을 다시 켜면 초기값으로 돌아간다 — 진행은 루트가
소유한 클라이언트 상태이고, 영속 저장에 넣는 것은 로그인 토큰뿐이다 (ADR-0007 D1).
**버그가 아니라 결정이다** (`docs/e2e/listening.md` 21번).

> 2026-09-03 여정 맵 실기 확인에서 잠긴 스텝도 시트를 여는 것이 드러났고, 그 자리가
> 위 문단이 세 상태를 구분하지 않아 생긴 빈칸이었다. 경위와 버린 안(시트를 열되
> "시작"만 막기)은 `docs/e2e/journey-map.md` 「잠긴 스텝이 열린다」에 있다.

#### 학습의 세 유형

| 유형 | 형태 | 롤플레이 탭에 |
|---|---|---|
| **기본 학습형** | 듀오링고와 비슷한 형태 — 듣기 · 문장 순서 배치 · 단어 선택 · **문화** · 말하기 · 쓰기 | 없음 |
| **학습 동반형** | 여정 속 캐릭터와 상호작용하며 배운다 | 있음 |
| **서사 주입형** | 서사만 전달한다 | 있음 |

서사 주입형과 학습 동반형은 **배우는 방식이 같고 화면만 다르다.** 그래서 학습 로직은
공유하고 표현만 가른다.

**기본 학습형 여섯 가운데 화면이 없는 것은 쓰기 하나다** — 듣기 · 문장 순서 · 단어 선택 ·
문화 · 말하기가 화면을 갖는다(말하기는 위 「여정 탭」 표의 말하기 행이 진다). **세는 것은
개수가 아니라 이 목록이다** — 화면이 서는 날마다 숫자를 갈아 끼우면 다음 사람이 어느 쪽이
맞는지 모른다.

아래 표는 그중 **탭으로 답하는 넷**을 가른다 — 말하기는 조작 원시가 소리라 이 표에 들어가지
않는다. 넷이 무엇을 묻고 무엇으로 답하는지가 갈린다. **넷째만 묻지 않는다.**

| 학습형 | 무엇을 묻나 | 무엇으로 답하나 |
|---|---|---|
| **듣기** | 들은 말의 뜻 | 보기 넷 중 하나를 **누른다.** 누르면 즉시 판정된다 |
| **문장 순서** | 말의 **차례** | 조각을 **눌러 문장 끝에 놓고**, 놓인 조각을 다시 누르면 빠진다. 전부 놓은 뒤 `확인`을 눌러야 판정된다 |
| **단어 선택** | 문항에 알맞은 **낱말** (제시문이 빈칸 문장이면 그 빈칸에 들어갈 낱말) | 보기 넷 중 하나를 **누른다.** 듣기와 같다 |
| **문화** | **묻지 않는다.** 짧은 서사(글)로 **맥락**을 전한다 — 문항도 정답도 없다 | **답하지 않는다.** 사용자가 입력하는 것이 **0건**이라 채점할 대상이 없고, 데이터에 정답 필드도 없다. 읽고 머리의 `Back to map`로 나간다 — **진행을 갱신하지 않는다.** **다만 화면 아래에 `Take the quiz`가 선다** — 문화 퀴즈로 **나아가는** 수단이고 나가는 수단이 아니다(눌러도 이 화면이 스택에서 안 사라져 `Back to map`와 공존한다). **묻는 일은 문화 퀴즈의 몫**이다 (아래 「문화 학습과 문화 퀴즈」) |

**⚠ 이 표는 「무엇이 있나」이지 「어느 스텝이 어느 것인가」가 아니다.** 다섯 스텝이 셋을 다
도는 것이 아니라 **스텝 하나가 학습형 목록을 갖는다.** 그 축의 **자리는 2026-09-05에 데이터에
생겼고**(`journey-map-learning-form.ts`의 `learningFormsByStep` — 어휘의 정본은
`lib/learning-form.ts`), **배정 값은 아직 없다.**

> **오른쪽이 학습형 하나에서 목록이 된 것은 2026-09-26의 설계 판단이다** — 유닛 하나가
> 5~10분 동안 활동 여럿(듣기 · 조합 · 낱말 고르기 · 문화 카드 …)을 잇는다. **그래서 「스텝
> 하나 = 학습형 하나」로 적은 옛 문면이 낡았다.** 활동이 유닛마다 어떻게 섞이는지에
> **별도 규칙은 없다**(ADR-0024) — 순서만 진행 순서다.

- **표의 값은 배정이 아니라 전사(轉寫)다** — 「이 스텝이 그것으로 정해졌다」가 아니라
  「오늘 이 스텝에 있는 문항이 그것뿐이다」이다. **세는 것은 개수가 아니라 그 표와 문항
  표의 대조다** — 문항이 없는 학습형은 목록에 서지 않는다. **이 값을 배정으로 읽지 마라.**
- **배정은 컨텐츠 판단이고 문항 값과 같은 시점에 온다** — 문항 없이 배정만 옮기면 그 스텝이
  문항 0개인 화면을 연다. 갈 곳은 `docs/adr/README.md` 보류 표의 **「스텝별 학습형 배정」** 행.
- **문화의 서사 표는 다섯 키가 다 차 있는데, 그것도 배정이 아니다** — 서사 타입에 빈 값이
  없고 `Record`가 다섯 키를 전부 요구해서 찬 것이지 다섯 스텝이 전부 문화라는 뜻이
  아니다. **「빈 배열 = 아직 아님」이라는 읽기가 이 표에는 안 통한다.** 서사 값 다섯도
  **임시**다 — 진짜는 페르소나 기획에서 오고, 갈 곳은 `docs/adr/README.md` 보류 표의
  **「문화 서사 컨텐츠의 출처」** 행이다.
- **여정 맵 노드는 자기 학습형을 보여 주지 않는다** — 시각으로도 낭독으로도. 판정이고
  기본값이 아니며, 근거와 되돌리는 조건 다섯은 `docs/e2e/journey-map.md`의 **「노드 위의
  학습형 표식」** 절에 있다.

**답하는 셋은 조작 원시가 다 탭 하나다.** 문장 순서에도 **드래그가 없다** — 끌어 놓는
조작은 이 저장소에서 한 번도 열린 적이 없는 축이고(선례 0건), 스크롤 영역 안에서 손가락을 누가
받는지도 확인되지 않았다. 탭이 배치·해제·재배치를 다 하고 되돌릴 수 있으므로 사용자가
갇히지 않는다. **대가는 중간 삽입이 안 된다는 것**이고 — 셋째 자리를 고치려면 뒤의
조각을 빼야 한다 — 그 대가가 실제로 무는지는 `docs/e2e/sentence-order.md`의 **M2**가
잰다. **관측 없이 중간 삽입을 만들지 않는다.**

**판정은 답하는 셋 다 이분법이다** — `정답` / `오답`뿐이고 「셋 중 둘 맞음」 같은 중간 값이
타입에도 화면에도 없다. 문장 순서에서 조각 하나만 틀려도 오답이다. 부분 점수를 열려면
**평가의 세는 규칙**(`문항 셋 중 2 이상`)을 먼저 열어야 한다 — 중간 값이 몇 개로
세어지는지가 새 결정이기 때문이다.

**듣기의 제시 채널은 지금 오디오와 텍스트 대본 병기다.** 화면에 들어오면 문항 오디오가
자동으로 나고, 카드 안 조작 하나(`듣기`/`멈춤`)로 다시 듣거나 멈춘다. 소리는 호스트
네이티브 모듈이 낸다 (위 「오디오 재생은 호스트 네이티브 모듈이 낸다」).

**대본은 임시 채널이다 — 실제 컨텐츠가 오면 걷는다.** 지금 번들에 든 소리는 판정용
기계 음성이라 대본을 걷으면 문항을 풀 수 없다. 대본을 감출지 접을지는 **실제 문항
오디오의 공급 경로가 정해지는 날의 판단**이고, 갈아끼울 자리는 **제시 필드 하나 + 제시
컴포넌트 하나**로 이미 국한돼 있다.

#### 문화 학습과 문화 퀴즈

**기본 학습형의 여섯째 형태다.** 일반 유닛에서 돌고 듀오링고식 틀을 그대로 쓴다 —
새 유형을 만들지 않는다.

**화면 둘이 다 섰고 결선도 됐지만 아직 열리지 않는다.** 배정이 문화 학습에 닿지
않아서다(위 「학습의 세 유형」) — **닫아 둔 것은 코드가 아니라 구성**이고, 배정이 오는 날
이 화면들 쪽에서 고칠 것이 0줄이 되는 것이 목표다.

**문화 퀴즈의 도달 경로는 문화 학습의 액션 행 하나다.** 문화 학습 아래에 `Take the quiz`가
**조건 없이** 서고(「끝까지 읽었는가」로 게이트하지 않는다) 그것을 누르면 퀴즈가 **위에
쌓인다** — 문화 학습이 스택에 남는다. **다만 퀴즈에서 나가면 맵이다** — 나가는 수단은 한
겹 위가 아니라 활성 스택의 루트로 가기 때문이다(ADR-0007 D6). 그래서 퀴즈는
**한 겹 더 닫혀 있다**: 배정이 문화 학습을 가리켜야 하고, 그 위에 문항 값도 있어야 문항이
보인다. 수동 확인 흐름은 `docs/e2e/culture.md`와 `docs/e2e/culture-quiz.md`가 **하나씩**
진다 — 파일 하나 = 흐름 하나다.

**다른 다섯과 갈리는 것은 무엇을 묻느냐다.** 듣기·문장 순서·단어 선택은 **말**을 묻고,
문화는 **맥락**을 묻는다 — 언제 어떤 말을 쓰는지, 왜 그렇게 말하는지. 언어를 배우는
목적이 그 맥락에 있으므로 **다섯의 곁가지가 아니라 여섯째다.**

**문화 퀴즈는 평가와 다른 화면이다.**

| | 무엇을 묻나 | 언제 |
|---|---|---|
| 평가 | **방금 푼 문항들**의 판정 | 학습 직후, 스텝마다 |
| 문화 퀴즈 | **문화 학습이 가르친 것** | 문화 학습의 짝 |

**같은 화면을 재사용하지 않는다.** 평가는 *"이 스텝을 통과했는가"* 를 답하고 문화 퀴즈는
*"이것을 아는가"* 를 묻는다. 합치면 평가 계약이 문항 출처를 알아야 하고, 그 순간 평가가
학습 유형마다 갈린다.

**두 화면이 갈리는 축은 「그 화면의 데이터에 정답이 있는가」다.** 둘이 나란히 섰으므로
다음 사람이 어느 쪽을 따라 할지 판단할 규칙을 여기 적는다. 가르는 축은 하나다 — **그
화면이 읽는 데이터 타입에 정답을 지는 필드가 있는가.** 아래 「그 틀은 「채점이
결정적이다」이지 …」 문단이 그 틀을 *"정답이 데이터에 있고 사람의 해석 없이 기계가
`정답`/`오답`을 가른다"* 로 정의하므로, 축은 **데이터** 쪽이다.

| | 데이터에 정답 필드 | 그래서 |
|---|---|---|
| 문화 학습 | **없다** — 서사 타입이 제목 + 문단뿐이고 **옵셔널이 금지라 나중에 조용히 생길 수도 없다** | 판정이 **없다** |
| 문화 퀴즈 | **있다** — 문항 타입이 정답 보기의 인덱스를 진다 | 판정이 **있다** |

**⚠ 「사용자 입력이 0건이다」는 축이 아니라 귀결이다.** 정답이 없어서 답할 것이 없고, 그래서
입력이 0건이 된 것이다. **순서를 뒤집어 읽으면 말하기·쓰기를 잘못 분류한다** — 위 기본
학습형 여섯 중 남은 그 둘은 입력이 0건이 아니지만 **데이터에 정답이 없으므로 문화 학습
쪽**이다.

**따라 하는 규칙 (한 줄).** 새 화면을 만들 때 **먼저 그 화면의 데이터 타입에 정답 필드를 둘
것인지**를 정한다. 두면 문화 퀴즈를 따라 한다 — 판정 값이 화면 안으로 들어오고, 판정은
**누른 그 보기의 라벨 접미사**로 낭독되며(ADR-0016 D3), 표식은 **아이콘 + 낱말**이다.
안 두면 문화 학습을 따라 한다 — 판정 값이 안 들어오고, 능동 낭독도 판정 표식도 **0건**이다.

**⚠ 「능동 낭독」이 이 축에서만 오는 것이 아니다** ⟨2026-09-08에 더했다, LIB-247⟩.
위 한 줄이 재는 것은 **판정의 낭독**이고, 그것과 별개로 **완료 전이의 낭독**이 있다 —
종료 상태가 처음 서는 순간 한 번 발화하는 것이고(ADR-0016 **D11-7**), 그것을 정하는 축은
정답 필드가 아니라 **「이 화면에 문항이 있는가」**다. ⇒ 정답 필드를 **안 두어도** 문항이
있으면 완료 전이 발화가 서고, 정답 필드를 **두어도** 문항이 없으면 서지 않는다.
**이 문단이 없으면 다음 사람이 「능동 낭독은 판정 축에서만 온다」로 읽고**, 문항은 있는데
판정이 없는 화면을 만들 때 종료를 조용히 지나가게 한다.

**⚠ 액션 행이 있느냐 없느냐는 이 축이 정하지 않는다.** 그것을 정하는 것은 **그 화면에서
나아갈 곳이 있는가**이고(ADR-0022 D1), 문화 학습이 판정 없이도 액션 행을 갖는 것이 그
증거다.

**넷이었고 둘이 닫혔다.** 닫힌 둘(제시 형태 · 퀴즈 문항 형태)은 **입력값의 「모양」**이라
컨텐츠 없이도 고를 수 있었다 — 모양만 고정하면 진짜가 오는 날 교체가 싸다. 남는 둘은
각각 **진행 계약**(파생값 축에 닿는다)과 **컨텐츠 공급 경로**라 지금 고르면 지어내는
것이 된다.

**아직 정하지 않은 것 둘.** 지어내지 않는다 —

| 무엇 | 왜 못 정하나 |
|---|---|
| 진행에 거는 방식 | 문화 스텝이 여정 맵의 스텝 하나인지, 스텝 안의 한 단계인지 |
| 컨텐츠 출처 | 오디오와 같은 축이다 — 공급 경로가 정해지는 날의 판단 |

**⚠ 「퀴즈 판정은 진행을 걸지 않는다」가 정해졌다. 그런데 위 「진행에 거는 방식」은 그것으로
닫히지 않는다.** 둘을 한 낱말로 묶으면 미정 하나가 조용히 사라진다 —

- **정해진 것**: 퀴즈의 판정은 **진행을 갱신하지 않는다.** 스텝 완료를 거는 권한은
  **평가의 판정 하나**이고(위 「학습의 세 유형」), 걸려면 통과 기준이 필요한데 그 기준은
  **문항 수 위에 서는 값**이라 문항 수가 미정인 오늘은 지어내야 한다. 그래서 퀴즈는
  판정을 화면 밖으로 내보내지 않는다 — 종합 판정도, 완료 콜백도 없다.
- **여전히 미정인 것**: 위 표의 「진행에 거는 방식」이 묻는 것은 **문화 스텝이 스텝 하나인지
  스텝 안의 한 단계인지**이고, 그 질문은 **퀴즈가 진행을 거느냐와 독립**이다 — 퀴즈가 걸든
  안 걸든 그대로 남는다. **되돌리는 조건**은 그 미정이 어느 쪽으로든 닫히는 날이고, 그날
  퀴즈에 통과 기준을 둘 것인지도 함께 열린다.

**정한 것 둘.** 미정 표에서 빠져 결정으로 섰다. **둘 다 2026-09-07에 정해졌다** — 위 머리말의 **세 번째 출처**다.

**제시 형태는 짧은 서사(글)다.** 글은 **지금 만들 수 있고 이미지가 오면 붙는 형태**다 —
채널이 하나 붙는 모양은 이 문서에 이미 있다(듣기가 「오디오 + 텍스트 대본」으로 간다).
**버린 대안은 이미지 제시**이고, 자산 공급 경로가 **오디오와 같은 축**이라 그 축이 아직
열려 있기 때문이다 (위 「오디오 재생은 호스트 네이티브 모듈이 낸다」의 *"아직 없는 것은
실제 문항 오디오(컨텐츠)다"*). **대가는 이미지가 오는 날 제시 채널이 하나 는다는 것**이고
— 그때 글을 걷는 것이 아니라 **채널을 더하는 형태로 국한한다.** 국한하지 않으면 글이
임시 채널이 되어 「대본」과 같은 종류의 미결정을 하나 더 만든다. **되돌리는 조건은 컨텐츠
공급 경로가 정해지는 날**이다(위 미정 표의 「컨텐츠 출처」).

**퀴즈 문항 형태는 객관식이다.** 4번의 판정 틀(**채점이 결정적이다**)에 가장 가깝고,
보기 UI가 이미 둘 있다 — `ListeningChoice`와 `WordChoiceOption`(후자가 이미 전자를 잇고
있다). **버린 대안은 둘이다. O·X**는 객관식의 특수형이라 **나중에 좁힐 수 있지만 반대는
어렵다.** **짝짓기**는 끌기·연결이라는 조작 원시를 여는 것이고, **이 저장소의 제품 화면에는
그것이 딛고 설 제스처 원시가 없다** — 누르기(`bindtap`) 하나로만 조작해 왔다.
⟨2026-09-17, LIB-261⟩ 코드 검증이 `bindinput`을 더했지만 **그것은 문자 입력 채널이지
제스처가 아니다.** 그 축은 `docs/adr/README.md` 보류 표의
**「제스처·커스텀 액션 축」** 행이 잡고 있다. ⚠ **저장소 전체로는 2026-09-19에 터치
바인딩 선례가 하나 생겼다** (LIB-263의 손글씨 탐침이 `bindtouchstart` 계열을 쓴다).
**그래도 짝짓기를 버린 판단은 그대로 선다** — 그 선례는 **도달 경로 0건인 탐침**에서
왔고 제품 제스처 어휘를 한 글자도 정하지 않았으며, 위 행은 닫히지 않았다.
**대가는 객관식이 아닌 형태가 더 맞는 컨텐츠가 오면 그때 형태를 다시 연다는 것**이고,
**좁히는 방향(객관식 → O·X)은 싸고 넓히는 방향은 비싸다**는 것이 이 선택의 값이다.

**이 결정이 정하지 않는 것 — 보기 개수와 문항 수.** 그것은 컨텐츠이고 남는 미정
「컨텐츠 출처」에 딸린다. 그래서 위 **「학습형 | 무엇을 묻나 | 무엇으로 답하나」 표에
문화 행을 더하지 않는다** — 더하려면 보기 수를 지어내야 한다.

**보기 UI를 빌린다는 것은 접근성 어휘도 함께 빌린다는 뜻이다.** 판정 접미사는 ADR-0016
D3의 라벨 접미사 규약 그대로이고, **새 어휘를 열지 않는다.**

**구현 순서 5번**이고 4번 뒤다. 근거가 둘로 갈린다 — **4번이 만든 판정 틀을 쓰기
때문**이고, **객관식 결정이 4번이 만든 보기 UI를 재사용하기로 했으므로 순서 의존이 더
단단해졌다.** **그 틀 없이 먼저 만들면 지어내게 된다**가 가리키는 것은 이제 **남는 미정
둘**(진행에 거는 방식 · 컨텐츠 출처)이다 — 제시 형태와 퀴즈 문항 형태는 더 이상 그
문장의 대상이 아니다.

**그 틀은 「채점이 결정적이다」이지 「보기 중에서 고른다」가 아니다.** 문장 순서는
보기를 고르지 않고 조각을 배치하는데도 같은 틀 안이다 — 정답이 데이터에 있고 사람의
해석 없이 기계가 `정답`/`오답`을 가른다는 뜻이기 때문이다. **문화 퀴즈가 빌리는 것은
그 판정 틀이지 UI 형태가 아니다.** 문화 퀴즈가 객관식이 된 것은 **틀이 형태를 지정했기
때문이 아니라 따로 고른 결과**다(위 「정한 것 둘」). 같은 틀 안에 **문장 순서**라는 다른
형태가 여전히 서 있다 — 틀을 빌린다고 형태가 따라오지 않는다.

유닛은 두 종류이고, **유형이 유닛을 따라간다.**

| 유닛 | 도는 유형 | 화면 형태 |
|---|---|---|
| 일반 유닛 | **기본 학습형만** | 듀오링고식 |
| 특별 유닛 (몇 개만) | 서사 주입형 · 학습 동반형 | 비주얼 노벨 · 메신저 · 전화 통화 · 최종 테스트 · **에피소드 표지** |

**화면 형태를 세는 방법은 개수가 아니라 `JourneyUnit`의 특별 변형 목록이다** — 그 union의
`screen` 값이 곧 이 칸이고, 변형이 늘면 이 칸도 는다(늘 때 `mapItemsOf`의 `never` 대입이
컴파일에서 선다).

기본 학습형은 **일반 유닛에서만** 돈다. 특별 유닛으로 넘어오지 않는다. 그래서 두
갈래는 화면을 공유하지 않고, 서로 독립적으로 만들 수 있다.

**특별 유닛은 여정 맵의 같은 세로 줄에 서는 별도 항목이다** (ADR-0024 D1). 별도 층도,
맵 밖의 다른 화면도 아니다 — 여정의 순서가 한 줄로 남고, 특별 유닛이 여정의 **중간**에
있다는 사실이 화면에 남는다. 그 항목은 스텝 노드와 **다른 컴포넌트**이고(D2), 완료는
판정이 아니라 **끝까지 닿는 것**이 건다 — **판정이 없으므로 미통과가 없다**(D6). 버린
대안과 대가, 그리고 특별 유닛이 오는 날 함께 와야 하는 것들은 ADR-0024에 있다.

**유닛 축은 코드에 섰고 유닛을 묶는 에피소드도 섰다.**
`journey-map-units.ts`의 유닛 목록은 `tutorial-intro` 표지 → 일반 스텝 넷 →
`appointment-confirmation` 메신저 → `appointment-confirmation-phone-call` 전화 →
`cafe-arrival-visual-novel` 비주얼 노벨 → 일반 `directions` → `tutorial-final-test`
최종 테스트 순서이고, 맵은 그 목록에서 파생한 항목을 그대로 그린다. 일반 스텝 목록
`journeySteps`는 여전히 다섯이며 특별 유닛은 스텝을 갖지 않는다(ADR-0024 D4·D5).
**줄에 서는 것의 수를 이 문서에 박지 않는다** — 세는 곳은 이 목록 하나이고, 에피소드
헤더의 분모도 같은 것을 센다.

**에피소드는 목록이고 하나가 아니다.** ⟨2026-09-29⟩ 에피소드를 더하는 일이 **데이터 한 줄**이
됐고(ADR-0024 D13), 맵은 **에피소드 하나를 구획 하나로** 낸다. **에피소드의 수도 이 문서에
박지 않는다** — 세는 곳은 에피소드 목록 하나다.

**에피소드는 두 모양이다 — 유닛을 가진 것과 아직 없는 것**(ADR-0024 D13). 가르는 것은 진행이
아니라 **구조**다: 준비 중 갈래에는 `units` 필드가 **아예 없다**. 빈 배열로 두면 아래 튜플이
거짓말을 하고 유닛을 읽는 자리마다 빈 배열 확인을 잊을 수 있는 분기가 생긴다. 이름과 번호는
있다 — 다음 이야기를 *보는* 것이 그 구획의 목적이라 이름을 못 보여 주면 아무것도 말하지 않는다.
**준비 중 구획도 자기 자리를 만들고**, 가려진 자리에 서는 것은 **장식이지 맵 항목이 아니다**
(ADR-0024 D14 — 누를 수도 없고 진행에 세어지지도 않는다).

**에피소드의 첫 자리와 마지막 자리는 타입이 진다.** 첫 유닛이 **표지**이고 마지막 유닛이
**최종 테스트**이며, **가운데에는 규칙이 없다** — 일반 학습과 서사 연계 학습(특별 유닛)을
유닛마다 다르게 섞는다. 데이터 순서로만 두면 최종 테스트를 가운데 둬도 컴파일도 런타임도
통과하므로, 유닛 목록을 `[표지, …가운데, 최종]` 튜플로 닫았다(ADR-0024 D10). ⚠ ⟨2026-09-29⟩
**그 튜플이 걸리는 것은 유닛을 가진 갈래뿐이다** — 튜플을 느슨하게 한 것이 아니라 그것을
만족할 수 없는 에피소드를 **다른 타입으로 뺐다**(D13). **에피소드 목록의 첫 자리도 타입이
진다**: 반드시 유닛을 가진 에피소드다.

**표지를 끝내기 전에는 그 구획의 나머지가 잠긴다** (ADR-0024 D11). 전에는 어느 유닛을 먼저
눌러도 결선이 가로채 표지를 띄웠는데, 이제 표지가 스스로 항목이라 **순서를 지는 자리가
가로채기에서 맵의 잠김 파생으로 옮겨 갔다.** 사용자가 보는 것이 「눌렀더니 다른 화면이
떴다」에서 **「아직 열리지 않았다」**로 바뀐다. 표지를 끝내면 그 아래 규칙(스텝 순차 · 최종
테스트 해금)이 그대로 산다 — **특별 유닛끼리는 여전히 서로 순서가 걸리지 않는다.**

첫 특별 유닛의 제목은 `Appointment message`다. 일반 `JourneyStepNode`의 불리언 변형이
아니라 별도 `MessengerMapItem`이고, 완료 ID 목록과 `locked/available/completed` 상태를
쓴다 — 잠김 어휘가 항목 종류마다 갈려 있던 것을 하나로 합쳤고, 그 값은 항목이 아니라
파생(`mapItemStatus`)이 낸다. **표지를 끝낸 뒤에는 언제든 열 수 있으며** 완료해도 일반
`completedStepCount`와 스텝의 `done/current/locked` 계산은 바뀌지 않는다.

메신저 화면은 고정된 지민/나 메시지 다섯 개를 답장 두 번에 걸쳐 1/3/5개 순서로 공개한다.
⟨2026-09-28⟩ 에피소드의 서사 기반 최종 테스트라 답장은 **두벌식 가상 키보드로 친다**(Figma
80-7082) — 입력창에 답장이 초성으로 가려져 보이고(`ㅈㅇㅇ!`) 그 아래 영문 뜻이 늘 서며, 맞히면 초록 입력창 · 정답 배지 뒤 답장이 대화에
서고, 틀리면 `Try Again`으로 다시 친다. 답장에 보기가 있으면 자판 대신 **객관식 보기 넷**에서 골라 보낸다(Figma 80-7380 — 약속 확인 메시지의 둘째 답장). 둘째 답장으로 끝까지 닿을 때만 완료하고, 미완료 재진입은 처음부터, 완료 재진입은 전체
기록부터 시작한다. 끝난 대화의 `See results`는 학습 완료(PERFECT LESSON — 답장마다 첫 시도에 틀린 적이 있으면 LESSON COMPLETE)로 가고, 나가면 맵 · 롤플레이 목록으로 돌아간다.

비주얼 노벨의 제목은 `Jimin arrives at the café`이고, `VisualNovelMapItem`에서 별도
`VisualNovelScreen`으로 들어간다. `arrive` → `find` → `enter`의 고정 세 장면에서 같은 카페
배경과 지민의 두 pose, 화자·대사를 로컬 임시 이미지 bundle과 함께 보여 준다. `Next`만 한
장면씩 진행시키며 `enter`가 나타나는 전이에서만 최초 완료한다. 미완료 재진입은 마지막 도달
장면에서, 완료 재진입은 `enter`에서 시작한다. 완료 뒤 `Start over`는 화면만 처음으로
돌리고 완료와 저장된 최원점은 유지한다. 이 진행은 앱 세션 안에서만 살며 일반
`completedStepCount`, 메신저와 전화 상태를 바꾸지 않는다. 실제 이미지 crop·Dynamic Type·
VoiceOver 확인은 [수동 iOS E2E](e2e/visual-novel.md)에 남아 있고 아직 실행되지 않았다.

**노티피케이션이 코드에 섰다 (LIB-257, 구현 순서 9번).** 진입점은 여정 맵 머리의 알림 버튼
하나다 — 홈이 걷히면서 여기로 옮겼다. 항목 넷은 대상 종류마다 하나를 둔 임시값이고, 행선지
낱말 · 네비게이션 동작 · 측정 이벤트는 [알림 스펙](specs/notifications.md)에 있다. 수동 iOS
흐름은 [알림 e2e](e2e/notifications.md)에 있고 아직 실행되지 않았다.

### 롤플레이 탭

세 유형 중 **기본 학습형을 뺀** 것이다 — 서사 주입형과 학습 동반형만 남는다. 그래서
롤플레이는 새 학습 형태가 아니라 **기존 두 유형의 재배치**다.

| 화면 | 내용 |
|---|---|
| 롤플레이 목록 | 롤플레이를 골라서 들어간다. 여정 탭의 맵과 대응되는 자리다. 항목은 **다시 연습할 수 있는 특별 유닛(메신저 · 전화 · 비주얼 노벨) · 여정 순서 · 잠김 없음**이고 — **표지와 최종 테스트는 서지 않는다**(서사를 다시 보는 것도, 에피소드를 끝내는 시험도 연습이 아니다), 각 항목은 **제목 + 형태**만 보인다 — 완료·잠김 표식이 없다 |
| 롤플레이 진행 | 서사 주입 + 캐릭터 상호작용. **새 화면이 아니다** — 6번의 특별 유닛 화면 셋을 그대로 연다. **연습 모드**다: 언제나 처음부터 시작하고, 여정의 완료·도달 상태를 **읽지도 쓰지도 않는다.** 나가기는 `Back to list` |

**롤플레이 목록이 코드에 섰다 (LIB-255, 구현 순서 7번).** 목록은 여정 맵의 항목에서
**연습할 수 있는 특별 유닛만** 골라 여정 순서 그대로 세운다 — `Appointment message` →
`Appointment call` → `Jimin arrives at the café`. **고르는 규칙은 개수가 아니라 `roleplayItemsFrom`의
`switch`다** — 항목 종류가 늘 때마다 그 자리에서 「연습인가」를 한 번 답하게 되어 있고,
표지와 최종 테스트가 거기서 빠졌다. 형태 낱말과 그 확인 상태, 연습 모드가 무엇을 막는지, 진입 출처
이벤트는 [롤플레이 목록 스펙](specs/roleplay-list.md)에 있다.

같은 특별 유닛이 두 탭에서 열린다. 여정에서 열면 완료가 기록되고 나가기가 `Back to map`,
롤플레이에서 열면 아무것도 기록되지 않고 나가기가 `Back to list`다 — **라벨이 목적지를 따르고,
동작은 둘 다 활성 스택의 루트로 접는 하나다**(ADR-0007 D6). 롤플레이에서 끝까지 봐도 여정
맵의 완료 표시와 일반 스텝 진행은 바뀌지 않는다. 수동 iOS 흐름은
[롤플레이 목록 e2e](e2e/roleplay-list.md)에 있고 아직 실행되지 않았다.

### 설정 탭

| 화면 | 내용 |
|---|---|
| 설정 | 탭 루트. **이동 항목 넷**(사용자 프로필 · 알림 · 개인정보 처리방침 · 이용약관 — ⟨2026-09-30⟩ [ADR-0033](adr/0033-legal-documents-in-app-browser.md) · [ADR-0034](adr/0034-server-push-notifications.md) · [ADR-0042](adr/0042-android-push-host.md) — 알림은 권한을 묻거나 이 앱의 시스템 알림 설정을 연다) 다음에 **세션 토글 둘**(`자동 재생` · `대본 표시`)이 온다. 나가는 수단이 없다 — 탭 루트라 바텀 네비게이션이 그 자리다 (ADR-0022 D1). ⟨2026-09-30⟩ 목록 끝에 **셋째 묶음 `Account actions`** — `Sign out` · `Delete account`. 둘 다 **확인 대화상자**를 먼저 띄운다(`Sign out?` · `Delete account?`). 삭제는 대화상자가 선 채 확인 버튼이 로딩하고(Apple 사용자는 그 위에 Apple 시트), 실패하면 대화상자가 닫히고 묶음 아래에 문구가 선다 |
| 사용자 프로필 | **표시 전용이다.** 항목 셋(이름 · 학습 언어 · 학습 목표)을 보여 주고 **입력 · 편집 · 저장 수단이 0건**이다. 값은 **고정 임시 값**이고 진짜는 계정과 온보딩에서 온다. **파생값(연속 학습일 · 완료 스텝 수 · 진행률 · 클리어 수)은 항목으로 두지 않는다** — 셋 다 입력값이다 (아래 「파생값은 임시로 채우지 않는다」) |
| 개인정보 처리방침 · 이용약관 | ⟨2026-09-30⟩ **앱 안 화면이 아니다.** 설정 항목과 로그인의 동의 문구 링크가 Notion 공개 페이지를 앱 안 브라우저 시트(`SFSafariViewController`)로 연다. 목적지는 호스트에 고정된 URL 둘이다([ADR-0033](adr/0033-legal-documents-in-app-browser.md)). LIB-259의 고정 임시 본문 화면은 지워졌다 |

**설정 탭이 코드에 섰다 (LIB-259, 구현 순서 10번).** 이동 항목 둘은 **설정 탭 스택에** 쌓이고
나가기는 둘 다 `Back to settings`다. 세션 토글 둘은 **지금 있는 동작만** 끈다 — 문항 오디오 자동 재생과
듣기 대본 표시이고, 새 기능을 여는 토글이 아니다. **끈 값은 저장하지 않는다** — 앱을 다시 켜면
둘 다 켜짐으로 돌아간다 (ADR-0007 D1). **대본을 끄면 오늘 번들의 문항을 풀 수 없다**(소리가
판정용 기계 음성이다) — 그 대가와 측정 이벤트 넷은 [설정 스펙](specs/settings.md)에 있다.
수동 iOS 흐름은 [설정 e2e](e2e/settings.md)에 있고 아직 실행되지 않았다.

**2026-09-30 — 로그아웃 · 계정 삭제가 섰다** ([ADR-0032](adr/0032-account-sign-out-and-deletion.md) — 제안 상태).
설정 탭의 **첫 서버 동작**이다. 로그아웃은 기다리지 않는다 — 오프라인이어도 곧장 로그인이 선다. 계정 삭제는
서버 함수(`apps/supabase-functions`)가 Supabase 사용자를 지우고 진행 기록은 DB가 함께 지운다. Apple로 가입한
사용자는 삭제 확인 뒤 Apple 시트를 한 번 더 거쳐 Apple 연결까지 철회한다. 시트를 닫으면 대화상자가 로딩 전으로
돌아가고 아무것도 지워지지 않는다. 화면 계약은 [설정 스펙](specs/settings.md) §9, 수동 흐름은
[계정 삭제 e2e](e2e/account-deletion.md)가 진다. ⚠ 함수 배포가 사용자 몫이라 실서버 삭제는 아직 돈 적이 없다.

## 네비게이션 구조

### 탭 밖 구간은 `entry` 스택에 담긴다

ADR-0007 D3이 정한 모양이다.

```ts
type Nav = {
  entry: Screen[];                    // 탭 밖 구간. 비면 앱 구간이다
  tab: Tab;
  stacks: Record<Tab, Screen[]>;
};
```

스플래시부터 여정 입장까지가 `entry`에 쌓인다. `entry`가 비면 앱 구간으로 넘어간다 —
`phase` 같은 필드를 따로 두지 않는 이유는 그 값이 `entry`에서 그대로 나오기 때문이다.

`push` · `back` · `replace` · `backToRoot`는 **활성 스택**에 작용한다. `entry`가 비어
있지 않으면 `entry`, 아니면 현재 탭의 스택이다. `enterApp`이 `entry`를 비운다.
**나가는 수단이 쓰는 것은 `backToRoot`(활성 스택의 루트)이고 `back`(한 겹 위)이
아니다** — 목적지는 라벨이 정하고 스택 깊이가 정하지 않는다(ADR-0007 D6).

### 여정 입장 화면 (옛 여정 선택)

**진입점은 하나다 — 온보딩 끝.** 언어 선택 다음에 서고, 끝나면 여정 맵으로 **진행**한다
(위 「진입 흐름」).

**여정은 모두 공통으로 시작하고, 진행 중간에 선택지가 주어진다.** 그래서 이 화면은 여정을
**고르지 않는다** — 들어가는 **단순 입장 화면**이다. 이름을 「여정 선택」에서 「여정
입장」으로 바꾼 것도 그 때문이다 — 고르지 않는 화면을 「선택」이라 부르면 거짓이 된다.

**입장 화면은 코드에 섰다 (LIB-261, 구현 순서 11번).** 제목 · 본문 한 줄 · **고른 언어의 라벨
한 줄** · `여정 시작하기` 하나이고, 누르면 `entry`가 비면서 여정 맵이 서고 **바텀 네비게이션이
그때 처음 보인다.** 언어 라벨을 보이는 것은 앞 화면에서 고른 값이 **세션 안에서 유지된다는 것을
화면에서 관찰할 수 있는 유일한 자리**이기 때문이고, 라벨 문자열을 그대로 한 줄 둔다 — 그것을
감싸는 문장을 새로 짓지 않는다. 계약은 [진입 흐름 스펙](specs/entry-flow.md)에 있다.

**진행 중 선택지는 여전히 만들지 않았다 — 형태가 미정이고 지어내지 않는다.** 이 화면이 선 것이
그 미정을 닫지 않는다: 입장 화면은 여정에 **들어가는** 자리이고, 선택지는 들어간 **뒤** 진행
중간에 주어지는 것이라 서로 다른 자리다.

> 2026-09-15 전까지 이 절은 「여정 선택 화면의 두 진입점」이었다 — 온보딩(첫 여정 선택, 홈으로
> 진행)과 홈의 「여정 변경」(홈으로 복귀). 홈이 계획에서 걷히며(LIB-257) 둘째 진입점이
> 사라졌고, *"화면에 어디서 왔는지를 넘겨야 한다"* 도 함께 걷었다 — 진입점이 하나면 넘길
> 것이 없다.

### 탭별 스택

| 탭 | 스택 | 근거 |
|---|---|---|
| 여정 | 있음 | 맵 → 학습 → 평가. **학습에서 평가로 갈 때 쌓이지 않고 갈아탄다**(`replace`) — **끝난 학습 세션은 스택에 남길 자리가 아니다.** ⚠ **평가의 "Back to map"가 맵에 닿는 근거는 이것이 아니다** — 나가는 수단은 진입 동작이 무엇이든 활성 스택의 루트로 간다(ADR-0007 **D6**). 진입 동작을 출구에 맞춰 고르는 근거는 D6.3이 금지한다. 스텝 시트는 맵의 내부 상태라 스택에 안 쌓인다. **맵 → 알림 → 특별 유닛**도 이 스택이다 — 알림은 `push`로 쌓이고, 알림에서 연 특별 유닛은 여정 모드라 나가기 `Back to map`가 알림이 아니라 맵으로 접는다(D6). **롤플레이 알림은 이 스택을 건드리지 않는다** — 롤플레이 탭으로 바꾸고 그 스택을 루트(목록)로 접으므로, 여정 탭으로 돌아오면 알림 화면이 서 있다 |
| 롤플레이 | 있음 | 목록 → 진행. 목록 항목을 고르면 그 특별 유닛 화면이 **롤플레이 탭 스택에** `push`된다 — 여정 탭 스택은 그대로다. 나가기 `Back to list`는 `backToRoot`로 목록에 돌아온다. 여정의 `Back to map`와 **같은 동작**이고 라벨만 목적지를 따른다(ADR-0007 **D6**). 유닛을 연 채 다른 탭을 다녀오면 그 화면은 처음부터 다시 선다 — 연습에는 이어 갈 진행이 없다 |
| 설정 | 있음 | 설정 → 프로필(⟨2026-09-30⟩ 법률 문서 둘은 스택에 서지 않고 시트로 뜬다 — ADR-0033). 이동 항목을 누르면 그 화면이 **설정 탭 스택에** `push`된다 — 나머지 두 스택은 그대로다. 나가기 `Back to settings`는 `backToRoot`로 설정 화면에 돌아온다. 여정의 `Back to map` · 롤플레이의 `Back to list`와 **같은 동작**이고 라벨만 목적지를 따른다(ADR-0007 **D6**). 프로필이나 약관을 연 채 다른 탭을 다녀오면 **그 화면이 그대로 서 있다** — 스택 보존이다. 둘은 서로를 열지 않아 깊이가 최대 2다 |

iOS에는 하드웨어 뒤로가기가 없다. **모든 화면이 화면 안에 뒤로 갈 수단을 갖는다**
(ADR-0007).

## 제약 (constraints)

### 서버가 없다

모든 데이터는 **고정 데이터**다. 그래서 갈라지는 것:

- ~~로그인 · 코드 검증은 **진짜로 만들 수 없다.** 화면은 만들 수 있어도 검증이 없다~~
  **전화번호 경로는 더 이상 해당하지 않는다.** 2026-09-29에 Supabase Auth를 잇는 것이 이 앱의
  첫 서버 연동이 됐다([ADR-0027](adr/0027-phone-otp-auth-supabase.md)). ⟨같은 날 뒤⟩ 소셜 셋도
  Supabase OAuth로 이어졌다([ADR-0028](adr/0028-social-oauth-web-authentication.md)). ~~소셜 셋과~~ **그 밖의 모든
  데이터는 여전히 고정 데이터**다
- **영속 저장은 늘리지 않는다.** `src/lib/storage.ts`(호스트 `StorageModule`)에 넣는
  것은 로그인 토큰뿐이다 (ADR-0007 D1). 화면 상태나 서버 응답을 넣으면 무효화가 사람
  손으로 넘어온다. 고정 데이터는 저장할 것이 아니라 코드에 있는 것이라 이 제약에
  걸리지 않는다. Lynx 자체에는 영속 저장 API가 없다 (ADR-0012)

### 오디오 재생은 호스트 네이티브 모듈이 낸다

**이 절은 2026-09-03에 뒤집혔다.** 원래 *"오디오 재생 수단이 아직 없다"* 로 시작했다.

**Lynx 쪽에는 여전히 재생 수단이 0개다.** `<audio>`는 Lynx 타입 정의에 없고, `<video>`는
타입에는 있으나 **판정 환경(Lynx Pod 4.0.1)에 등록된 UI가 없다.** JS 런타임에도 웹
오디오가 없다 — 브라우저가 아니다. 확인한 자리는 ADR-0017의 「맥락」에 있고, `<video>`
우회는 거기서 버려졌다(D4). **없는 요소를 렌더하면 화면이 비는 것이 아니라 페이지가
죽는다** (`docs/e2e/listening.md` 20번).

**남은 경로가 호스트 네이티브 모듈이었고, 그 문이 열리면서 같은 날 실체화됐다**
(ADR-0017 D1·D3). `AudioPlaybackModule`이 `play(source, done)` · `stop()` 둘로 소리를
내고, 화면 쪽 접점은 `src/lib/audio.ts` **파일 하나**다. 목록은 `docs/adr/README.md`의
**호스트 모듈 표**에 있다 — 그 표가 곧 Android 이관 목록이다.

**소리가 나는지는 호스트에서만 확인된다.** 개발 루프(Explorer)에는 이 모듈이 없어
언제나 무음이고, **정상과 고장이 같아 보인다.** 판정은 `docs/e2e/listening.md`의
A~I가 진다.

**아직 없는 것은 실제 문항 오디오(컨텐츠)다.** 번들에 든 자산은 판정용 기계 음성이라
*소리가 나는가*는 판정하지만 *무엇을 들려줄 것인가*는 판정하지 않는다. 그래서 듣기
화면이 **오디오와 텍스트 대본을 함께** 낸다. 남은 미결정은 `docs/adr/README.md` 보류
표의 「오디오 자산의 출처·형식」 행에 있다 — **닫히지 않았다.**

### 디자인 시스템은 이미 붙어 있다

**이 절은 2026-09-02에 뒤집혔다.** 원래 *"확정 전까지 UI는 임시다"* 로 시작해
`src/styles/tokens.temp.css`에 임시 값을 두는 전략을 적고 있었다. **그 파일은 만들어진
적이 없다.** 패키지가 먼저 도착했다 — `@libitums/design-tokens` · `@libitums/icons`
`0.2.0`을 홈 화면에서 소비하고 호스트에서 확인했다 (ADR-0014).

지금 성립하는 것:

- **값은 패키지에서 온다.** 임시 토큰 파일도, `src/styles/`도 없다.
- 화면 CSS는 `var(--libitum-*)`만 참조한다 (ADR-0014 D1). 아이콘 색만 예외로 TS
  상수를 쓴다 (ADR-0014 D2).
- 시각 값은 **컴포넌트와 1:1인 CSS 파일**에만 둔다 (ADR-0015 D2).

**ui 테스트는 여전히 시각을 단언하지 않는다.** 환경이 계산된 스타일을 못 본다
(ADR-0006 D4). 그래서 ui 테스트는 *무엇이 보이는가*가 아니라 *무엇이 있는가*를
단언한다 — 요소 존재, 속성, 상호작용 후 상태 변화. 값이 실제로 칠해지는지는
`docs/e2e/design-token-rendering.md`의 눈 확인 몫이다.

> 마크업이 아직 확정이 아니므로 **트리 전체 스냅샷은 쓰지 않는다.** 원래 이 자리에
> *"`HomeScreen.ui.test.tsx`가 트리 전체를 인라인 스냅샷으로 박고 있다"* 고 적혀
> 있었는데, 그 테스트는 그 뒤에 다시 쓰여 `data-testid`와 속성만 단언했고, LIB-257에서 홈
> 화면과 함께 지워졌다.

## 작업 분해

### 최소 단위 = 화면 + 들어오는 전이 하나

화면만 만들면 `ui` 테스트는 통과하지만 **시뮬레이터에서 볼 수가 없다.** 도달 경로가
없기 때문이다. 이대로 쌓으면 마지막에 "네비게이션 연결" 이슈 하나가 거대해지고,
그때 몰아서 터진다.

이슈 하나가 담는 것:

- `Screen` 유니온에 이름 추가
- 화면 컴포넌트 (고정 데이터, 패키지 토큰 — ADR-0014 D1)
- `ui` 테스트 — 화면 자체
- **전이 하나** + `integration` 테스트 — 도달 경로
- 시뮬레이터에서 눈으로 확인

**시트와 모달은 화면이 아니다.** `Screen` 유니온에 들어가지 않고, 그것을 띄우는 화면의
이슈에 함께 들어간다. 스텝 시트는 여정 맵 이슈의 일부다.

### 예외는 하나 — 뼈대

첫 화면을 붙일 자리가 없어서 앞에 하나만 둔다.

> `Nav`를 ADR-0007 D3의 모양(`entry` 포함)으로 · `Screen`/`Tab` 유니온 확정 ·
> 바텀 네비게이션 셸 + 빈 탭 4개 (LIB-257부터 탭 셋)
> **확인**: 탭 4개가 전환된다 (LIB-257부터 탭 셋)

따로 떼는 이유는 여기에만 **모든 이슈가 건드릴 파일**(`navigation.ts`)이 모여
있기 때문이다. 먼저 확정하면 이후 화면 이슈들이 서로 충돌하지 않는다.

### 순서 — 만드는 쪽을 먼저, 요약하는 쪽을 나중에

사용자가 보는 순서와 만드는 순서는 다르다. 두 가지가 순서를 뒤집는다.

**파생값은 임시로 채우지 않는다.** 여정과 학습이 만들어 낸 결과에서 **계산되는** 값(파생값)을
보여 주는 화면은, 그 값을 만드는 화면이 선 뒤에 얹는다. 뒤로 가는 근거는 「값이 아직
없어서」가 아니라 **그 값이 파생값이기 때문이다.**

**파생값에 가짜를 넣으면 가짜 값 하나가 아니라 가짜 계산 규칙이 굳는다.** 무엇을 하루로
세는지, 무엇을 클리어로 세는지가 임시 값을 꽂는 그 자리에서 정해져 버린다. 그래서 진짜가
오는 날 갈아끼울 자리가 **한 곳으로 좁혀지지 않고 화면을 다시 만든다.** 그래서 만드는 쪽을
먼저 만들고 요약하는 쪽을 나중에 얹는다.

위 「서버가 없다」 절의 「모든 데이터는 고정 데이터다」와 부딪히지 않는다. **가르는 선은
「고정 값인가」가 아니라 「그 값이 무엇에서 나오는가」다** — 고정 데이터라도 파생값 자리에
임시 값을 꽂으면 **세는 규칙**이 함께 굳는다.

> 2026-09-15 전까지 이 규칙은 「홈은 소비자다」라는 이름으로 홈 화면을 예로 들었다. 홈이
> 계획에서 걷히며(LIB-257) 예는 걷고 규칙은 이 이름으로 남겼다 — 규칙은 홈의 것이 아니라
> 파생값 일반의 것이고, ADR-0007 · ADR-0024 · `docs/conventions/code.md`가 이 자리를
> 인용한다.

**이것은 위 「문화 학습과 문화 퀴즈」의 「지어내지 않는다」와 다른 규칙이다.** 그쪽이
비워 둔 것은 **입력값**(컨텐츠의 모양)이고, 입력값은 **모양만 고정하면 교체가 싸다.**
두 자리가 같은 규칙에서 나온 것처럼 읽히면 다음 사람이 **입력값 자리에서도 화면을
미루거나**, 반대로 **파생값 자리에 임시 값을 꽂는다.** 임시 **입력값**을 어떻게 두는지는
이 문서가 지지 않는다 — `docs/conventions/code.md`의 「임시 입력값의 이음매」다.

**진입 흐름은 서버가 필요하다.** 로그인과 코드 검증은 검증할 것이 없다. 게다가 먼저
만들면 이후 모든 확인이 매번 로그인을 통과해야 해서 개발이 느려진다.
⟨2026-09-29⟩ 서버는 전화번호 인증 하나에서 왔다(ADR-0027). 순서의 근거였던 「검증할 것이 없다」가
그 경로에서 풀렸을 뿐 순서는 이미 지나갔다 — 진입 흐름은 12번으로 섰다.

```
0.  뼈대
1.  여정 맵 + 스텝 시트
2.  기본 학습형 1종 (듣기)             ← 학습 루프의 첫 증명
3.  평가
4.  기본 학습형 나머지 (문장 순서 · 단어 선택)
5.  문화 학습 + 문화 퀴즈               ← 4번의 판정 틀을 쓴다
6.  서사 주입형 · 학습 동반형 (비주얼 노벨 · 메신저 · 전화 통화)
7.  롤플레이 (목록 → 진행)             ← 6번의 화면을 재사용한다
8.  — 계획에서 걷었다 (2026-09-15, LIB-257)
9.  노티피케이션                         ← 진입점은 여정 맵 머리의 알림 버튼
10. 설정 · 프로필 · 개인정보 및 약관     ← 코드에 섰다 (LIB-259)
11. 여정 입장 (옛 여정 선택)            ← 코드에 섰다 (LIB-261)
12. 진입 흐름 나머지 (언어 선택 · 코드 검증 · 로그인 · 온보딩 · 스플래시)  ← 코드에 섰다 (LIB-261)
13. 말하기 · 쓰기                        ← **말하기는 화면이 섰다.** 쓰기는 아직이다
14. 에피소드 (서사 표지 · 서사 전개 · 최종 테스트)  ← 6번의 특별 유닛을 에피소드로 묶는다
```

**11번과 12번은 한 이슈가 함께 세웠다 (LIB-261).** 둘을 가른 것은 의존이 아니라 분량이었는데,
여정 입장이 언어 선택에서 고른 값을 보여야 해서 **따로 세우면 그 값을 넘길 자리가 없었다.**
`entry` 스택과 그 리듀서 분기는 0번(뼈대)이 이미 만들어 두었고 — 그때부터 줄곧 비어 있었다 —
이 이슈가 그 자리를 채웠다.

번호는 **구현 순서**다. 사용자가 지나가는 순서가 아니다. **걷은 번호는 다시 매기지 않는다** —
8번이 비어도 9번 이하는 그대로다. 다른 문서가 「구현 순서 N번」으로 이 목록을 인용한다.

**14번을 뒤에 붙인 것은 의존 때문이다** — 에피소드는 특별 유닛(6번)을 묶는 자리라 그것 없이는
묶을 것이 없다. **13번을 앞지른 것이 아니다**: 13번의 말하기가 먼저 섰고, 번호는 도착 순서가
아니라 무엇에 매여 있는가를 적는다.

앞으로 당길 수 없는 것은 아래 표가 진다.

| 항목 | 무엇에 매여 있나 |
|---|---|
| **7. 롤플레이** | 6번. 롤플레이는 서사 주입형과 학습 동반형으로만 이뤄져 있어서, 그 둘이 없으면 만들 것이 없다 |

> 2026-09-15에 **8. 홈** · **11. 여정 선택** 행을 걷었다 (LIB-257). 8번은 계획에서 빠졌고,
> 11번은 매여 있던 8번(홈의 「여정 변경」)이 걷혀 그 의존이 사라졌다.

**13. 말하기 · 쓰기**가 기본 학습형에서 떨어져 나온 것은 성격이 다르기 때문이다.
이 둘은 마이크와 키보드라는 **네이티브 능력**이 필요한데, **그 둘의 상태가 2026-09-17에
갈렸다** (LIB-261).

- **키보드는 화면에 실제로 섰다.** 진입 흐름이 입력 둘(전화번호 · 코드 검증)을 세우면서
  **이 저장소에서 소프트 키보드가 호스트에 처음 열렸다** — 그전까지 `apps/mobile/src`에
  `<input>`이 0건이었다. 실기 관측 자리도 생겼다([진입 흐름 e2e](e2e/entry-flow.md)의 K 항목 —
  키보드 종류 · **가림** · 내리는 수단).
- **마이크는 그대로다.** Lynx에서 확인된 바 없다. ⟨2026-09-19 갱신⟩ **권한 축은 열렸다** —
  마이크가 ADR-0026 D1의 **입장 조건 다섯**을 통과한 첫 사례이고, 열린 것은 *요구해도
  되는가*다(그 D2의 권한 표 — 호스트에 usage description도 입력 API 호출도 아직 0건이다).
  **남은 것은 모듈과 화면이었다** — 마이크 모듈은 ADR-0017 D1의 입장 조건 셋을 **따로**
  통과해야 했고(*"두 게이트는 직렬이다"* — ADR-0026 D1), 그때는 말하기 화면이 없었다.
  ⟨2026-09-28 갱신⟩ **둘 다 섰다** — `SpeechRecognitionModule`이 호스트에 있고
  `SpeakingScreen`이 그것을 쓰는 학습 화면으로 여정에 닿았다(`learningFormsByStep`의
  `introduction`). **그래서 말하기 쪽은 이 불릿이 기다리던 것이 남아 있지 않다.**

⚠ **키보드가 섰다는 것이 13번을 앞당기는 근거가 되지 않는다.** 이 단위가 세운 것은 **한 줄
입력의 존재**이고, 쓰기 학습형이 요구하는 것은 **자유 텍스트 입력 + 채점**이다 — 무엇을 정답으로
볼지가 데이터에 있어야 하고 그것은 컨텐츠 판단이다. 게다가 **키보드가 뜬 뒤의 축이 아직 열려
있다** — 뜬 키보드가 화면을 덮는지, 내릴 수단이 있는지가 미확인이고 회피 기구를 이 저장소의 화면
CSS로 처리할 수 없다(`docs/adr/README.md` 보류 표 「소프트 키보드가 화면을 가리는 축」).
**「능력의 경로가 확인됐는가」가 기준인데, 키보드는 경로가 보이기 시작했을 뿐 아직 확인되지
않았다.**

> **2026-09-03 정정.** 이 문단은 원래 *"나머지 세 종(듣기 · 문장 순서 · 단어 선택)은
> 화면만 있으면 되지만"* 으로 시작했다. **듣기는 화면만으로 되지 않았다** — 오디오
> 재생도 스피커라는 네이티브 능력이고, 그 능력이 구현 순서 2번에서 실제로 요구됐다.
> **떨어져 나온 기준은 "네이티브 능력이 필요한가"가 아니라 "능력의 경로가 확인됐는가"다**
> — 재생은 경로가 확인됐고 **같은 날 실체화됐다**(호스트 네이티브 모듈, ADR-0017 D1·D3
> · 위 「오디오 재생은 호스트 네이티브 모듈이 낸다」). 마이크와 키보드는 아직이고,
> **마이크는 권한까지 여는 것이라** ADR-0017 D1의 입장 조건 셋을 처음부터 다시 통과해야
> 한다.

> **2026-09-19 덧붙임 (LIB-263).** 위 *"떨어져 나온 기준은 '능력의 경로가 확인됐는가'다"*
> 가 말하는 확인을 **쓰기 쪽에서 한 번 했다.** 확인된 것: 손으로 쓴 획을 모아 **온디바이스
> 인식에 넣는 경로**가 이 스택 안에 선다 — 그리는 면은 Lynx `<svg>`이고, 인식은 호스트
> 네이티브 모듈이 오프스크린 래스터화 뒤 Vision에 넣는다(ADR-0017 D1의 넷째 사례).
> **확인되지 않은 것**: 연속 터치가 실기에서 실제로 전달되는지, 몇 획까지 견디는지,
> 한글 한 글자를 실제로 읽어 내는지 — 셋 다 **사람이 실기에서** 판정하고
> `docs/e2e/handwriting-probe.md`가 그 자리다. **그리고 화면은 서지 않았다** — 선 것은
> 도달 경로 0건인 탐침이다.
> ⚠ **그래서 이것도 13번을 앞당기는 근거가 되지 않는다.** 위 본문의 ⚠ 문단
> (*"키보드가 섰다는 것이 13번을 앞당기는 근거가 되지 않는다"*)과 **같은 결론에 다른 길로
> 닿는다** — 키보드 쪽은 **한 줄 입력이 섰을 뿐 자유 텍스트 입력 + 채점이 아니고**,
> 손글씨 쪽은 **경로를 한 번 밟았을 뿐 실기가 아직 답하지 않았다.** 둘 다 기준
> (*"능력의 경로가 확인됐는가"*)을 통과하지 못한다. 마이크(말하기)는 권한까지 여는 별
> 축이라 그 문단이 한 글자도 약해지지 않는다.

## 범위

**어디까지 이번에 만드는가는 이 문서가 정하지 않는다.** 작업 범위는 이슈에서 정한다.

이 문서는 화면이 **무엇인지**와 **무엇에 매여 있는지**만 적는다. 그래야 범위를 어디에
긋든 같은 문서를 쓴다. 범위를 문서에 박으면 범위가 바뀔 때마다 문서를 고쳐야 하고,
곧 문서와 실제 범위가 어긋난다.

위의 구현 순서도 마찬가지다. **순서는 의존성에서 나온 것이지 범위가 아니다.** 어디서
끊을지는 이슈가 정한다.

### 만들지 않는 것

범위와 무관하게, 제약과 이미 내린 결정에서 곧바로 따라오는 것들이다.

- ~~**실제 인증** — 서버가 없다. 로그인·코드 검증에 통과/실패가 없다~~ — **전화번호 경로는 더
  이상 해당하지 않는다.** 2026-09-29에 Supabase SMS OTP로 섰다(ADR-0027). ⟨같은 날 뒤⟩ 소셜 셋도
  Supabase OAuth로 섰다(ADR-0028 — 제안 상태, 제공자 설정 전). ~~소셜 셋의 실제 인증과~~
  ~~**로그아웃은 여전히 만들지 않는다**~~ ⟨2026-09-30⟩ **로그아웃과 계정 삭제도 섰다**(ADR-0032 — 제안 상태)
- ~~**디자인 시스템 적용**~~ — **더 이상 해당하지 않는다.** 2026-09-01에 적용했다
  (ADR-0014). 화면을 만들 때 처음부터 패키지 토큰을 쓴다
- **공용 컴포넌트 미리 만들기** — 화면 2개가 쓰기 전까지 화면 폴더 안에 둔다 (ADR-0015 D3).
  **예외는 design-system이 스펙을 가진 컴포넌트**(Button · Dialog · Bottom Sheet ·
  Bottom Navigator · Header · Indicator)로, 두 번째 화면을 기다리지 않는다
  (ADR-0015 `정정 기록` 2026-09-02)
- ~~**오디오 재생**~~ — **더 이상 해당하지 않는다.** 2026-09-03에 호스트에 재생 모듈이
  생겼다 (ADR-0017 D1·D3). **남은 것은 실제 문항 오디오(컨텐츠)의 공급 경로**이고,
  그것은 `docs/adr/README.md` 보류 표의 「오디오 자산의 출처·형식」 행에 있다.
  **일시정지·시크·배속·배경 재생·녹음은 여전히 만들지 않는다** — ADR-0017 D3의 제외
  목록이다
- ~~**말하기**~~ · **쓰기** — 마이크·키보드는 네이티브 능력이다. **말하기는 더 이상 해당하지
  않는다** (⟨2026-09-28⟩ 화면이 섰다 — 아래 ⚠ 문단). ⟨2026-09-17, LIB-261⟩ **둘의 상태가
  갈렸다** — **키보드는 진입 흐름의 입력 둘로 화면에 섰고**(실기 관측 자리는
  [진입 흐름 e2e](e2e/entry-flow.md)의 K 항목이다), 그때 **마이크는 확인된 바 없었다**(그
  뒤 열렸다 — 아래 ⚠ 문단).
  **그래도 쓰기는 앞당겨지지 않는다** — 쓰기 학습형이 요구하는 것은 한 줄 입력이 아니라
  **자유 텍스트 입력 + 채점**이고, 키보드 쪽도 **뜬 뒤의 축**(가림 · 내릴 수단)이 아직 미확인이다
  (위 「13. 말하기 · 쓰기」 문단).
  ⚠ **마이크의 권한 축은 2026-09-19에 열렸고**(ADR-0026 D1의 **입장 조건 다섯**을 통과한 첫
  사례) **2026-09-28에 말하기 화면이 섰다** — `SpeechRecognitionModule`이 ADR-0017 D1의 입장
  조건 셋을 따로 통과했고(*"두 게이트는 직렬이다"* — ADR-0026 D1), `SpeakingScreen`이 여정의
  학습 활동으로 열린다. **그래서 이 불릿에서 말하기는 걷혔고 남은 것은 쓰기다.** 녹음을 재생
  모듈에 얹지 않는다는 제외는 그대로다 (ADR-0017 D3).
  ⚠ **쓰기의 경로는 키보드만이 아니다 (2026-09-19, LIB-263).** 손글씨 + 온디바이스 인식
  경로가 호스트 모듈로 열렸고(ADR-0017 D1의 넷째 사례), 그 경로가 실기에서 실제로
  되는지는 `docs/e2e/handwriting-probe.md`가 판정한다. **그래서 이 불릿을 걷지 않는다** —
  화면은 여전히 만들지 않고, 선 것은 **도달 경로 0건인 탐침**이다
- **Android** — ADR-0012 D1
- **다크 모드** — ADR-0014 D7 (ADR-0011 D5를 잇는다)

## 확인 방법

화면이 되었는지는 `docs/e2e/`의 흐름 파일이 판정한다. 흐름은 **실제로 만들 때 하나씩**
추가한다 — 만들지 않은 화면의 흐름을 미리 적지 않는다.

## 비고

### `[추론]`

**남은 것이 없다.** 초안의 추론 셋은 모두 확인을 받아 본문에 반영했다.

| 무엇이었나 | 어떻게 정해졌나 |
|---|---|
| 롤플레이 목록 화면 | 있다. 롤플레이를 골라서 들어간다 |
| 스텝 상세 | 화면이 아니라 **맵 위 시트** |
| 온보딩 화면 개수 | 화면 하나 + `step` 인덱스 |

### 이 문서가 만든 후속

둘 다 닫혔다.

| 후속 | 어떻게 닫혔나 |
|---|---|
| ADR-0007 D3에 탭 밖 구간이 담기지 않음 | `entry: Screen[]`를 더했다. `phase` 필드는 두지 않았다 — `entry`에서 파생되는 값이다 |
| ADR-0010 D1 문서 트리에 이 문서의 자리가 없음 | 네 번째 종류로 인정하고, 네 종류가 각각 어떤 질문에 답하는지 표로 갈랐다 |
