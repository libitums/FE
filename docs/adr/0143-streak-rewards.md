# ADR-0143 — 연속 학습(스트릭) 엽전 보상

- 상태: **채택 — 서버 마이그레이션 운영 적용 전.**
- 날짜: 2026-11-14.
- **사용자 결정**
  - ADR-0140 D3 「스트릭 시 보상은 화면 따로 설계」 → 시안 [N1XiHjnx7E243xFAu4wwU2](https://claude.ai/artifact/N1XiHjnx7E243xFAu4wwU2) 3판 「스트릭」 탭(기존 연속 학습 화면을 그대로 고쳐 씀).
  - 「좋다 진행」(2026-11-14) — 숫자는 A안, 지급은 서버 지갑(엽전 출시와 같은 경로).
- 이어받는 결정: [ADR-0035](0035-learning-progress-and-streak-on-server.md)(학습한 날 · 연속) · [ADR-0064](0064-stat-motion.md)(지표 모달 움직임) · [ADR-0140](0140-yeopjeon-launch.md)(서버 지갑 · `grant_once` · 엽전 날기)

## 결정

### D1. 보상표(A안)

| 연속 | 보상 |
|---|---|
| 3일 | +15 |
| 7일 | +40 |
| 14일 | +70 |
| 30일과 그 뒤 30일마다(60, 90, …) | +150 |

- 연속 한 번(run)에 이정표마다 **한 번**. 끊겼다가 새로 시작한 연속은 같은 이정표를 다시 받는다.
- 한 달 매일이면 275엽전(대화 3 · 음성 15 · 사진 35 기준, ADR-0140).
- 표의 단일 출처는 서버 설정(`companion.settings.streak_rewards` · `streak_repeat_days` · `streak_repeat_reward`)이다. 앱 표
  (`screens/journey-map/streak-rewards.ts`)는 화면을 그리려고 같은 값을 들고, unit 테스트(SR-U4)가 마이그레이션의 기본값과 같음을 본다.
  운영에서 설정을 바꾸면 앱 표도 함께 바꿔야 한다(그 사이 화면의 꼬리표와 실제 지급이 어긋날 수 있다 — 지급은 늘 서버 값).

### D2. 서버가 연속을 센다(`20261128120000_streak_rewards.sql`)
- `public.companion_claim_streak_reward(p_today date)` — 로그인 필수(security definer · search_path '').
- 연속 일수 = `learning_streak(p_today)` — **서버의 학습한 날 표(learning_days)만** 읽는다. 앱이 보낸 일수는 받지 않는다.
- 앱은 기기의 오늘 날짜만 보낸다. 학습한 날이 기기 날짜로 적히므로(ADR-0035) 서버가 UTC로 「오늘」을 정하면 시간대에 따라 하루가
  어긋나기 때문이다. 그 날짜는 `record_learning_days`와 같은 창(UTC 오늘 ±1일)만 받고 밖이면 22023. 창 안에서 날짜를 골라도
  같은 연속이면 지급 열쇠가 같아 두 번 받지 못한다.
- 기준일 = 오늘 학습했으면 오늘, 아니면 어제(오늘 하면 이어지는 연속 — `learning_streak`과 같은 규칙). 시작일 = 기준일 − (연속 − 1).
- 오늘 연속이 이정표면 `grant_once(사용자, 액수, 'streak', '<uid>:<시작일>:<일수>')` — 같은 연속의 같은 이정표는 원장 유니크 색인이 막고,
  새로 시작한 연속은 시작일이 달라 다시 받는다.
- 돌려주는 값 `{ days, amount, granted, wallet }` — 이정표가 아니면 amount 0 · granted false.

### D3. 화면(연속 학습 모달, 로그인 사용자만)
- 7칸 줄 위 꼬리표: 지난 이정표 칸은 초록 체크 꼬리표(+n), 앞으로의 이정표 칸은 엽전 꼬리표(+n). 체크가 찍힌 뒤 톡.
- 큰 목표 줄: 이번 줄 마지막 날 뒤의 첫 이정표(「14-day goal」 · +70 · 차오르는 막대). 줄 안의 이정표는 꼬리표가 이미 보인다.
- 문구: 「Amazing work! **2 more days** to +40 Yeopjeon.」
- 이정표 날이고 아직 안 받았으면 문구 · 목표 줄 대신 보상 카드(+40 · 「7-day streak reward」)와 **Collect**.
- Collect → 서버 지급 한 번 → 모달이 걷히고 → 카드의 엽전이 머리 엽전 칩으로 날아감(엽전 출시 모달의 `LaunchCoinFlight` 재사용 — 안전
  타이머 포함) → 닿을 때마다 칩이 받은 몫만큼 오름 → 모달 닫힘. 칩은 응답의 지갑 잔액(엽전 출시 결선의 서버 잔액)을 보인다.
- 지급 실패(10초 시간 초과 포함) · 이미 받음(granted false)이면 Continue처럼 그냥 닫는다. 곧바로 다시 부르지 않는다 — 다음에 모달을 열면
  Collect가 다시 보인다(실패면). 기다리는 동안에도 뒤로가기 · 머리 닫기는 언제든 닫는다.
- 받은 뒤 같은 연속의 같은 날 다시 열면 오늘 칸이 초록 꼬리표이고 Continue — 기기 기록(`libitum.streak-reward.<uid>` = 일수 · 그날)로
  고른다. 다음 날(오늘 학습 전)에도 같은 연속이라 받은 것으로 본다. 다른 기기에서 받았으면 Collect가 보이지만 누르면 granted false로 닫힌다.
- 움직임은 모두 토큰(`reward` · `enter-expressive` · `d9` 지연 · `d5` 걷힘). 움직임 줄이기면 등장 움직임 · 날기 없이 최종 상태.
- 비회원(손님) · 트로피 모달은 그대로다(지갑이 서버에만 있다).
- 제품 이벤트 `streak_reward_collected { surface: "learning", days, amount }` — 이번에 지급됐을 때 한 번(ADR-0029 D3).

### D4. 보류 — 연속 보호권(streak shield)
- 시안의 「끊겼을 때 보호권(30엽전)」은 사용자 결정 전이라 넣지 않았다. 넣게 되면 `learning_days`에 「보호한 날」을 더하는 서버 쪽 결정이 먼저다.

## 버린 대안
1. **앱이 일수를 보내고 서버가 그 일수로 지급** — 기기에서 일수를 바꿔 이정표를 몇 번이고 받을 수 있다.
2. **이정표마다 사용자당 한 번(시작일 없이)** — 끊겼다가 다시 시작한 연속이 보상을 못 받아 다시 쌓을 동기가 사라진다.
3. **연속이 오를 때 서버가 자동 지급(`record_learning_days` 안에서)** — 모달의 Collect 순간과 칩 오름이 따로 놀고, 기존 RPC의 반환형을
   바꿔야 한다. 받는 순간을 화면이 쥐도록 따로 부른다.
4. **새 날기 구현** — 측정이 답하지 않는 Android에서 막이 남는 문제를 이미 푼 `LaunchCoinFlight`를 그대로 쓴다.

## 대가
- 앱 표와 서버 설정이 따로 있다(테스트가 기본값만 맞춘다).
- 「받았나」는 기기 기록이라 다른 기기에서는 Collect가 한 번 더 보일 수 있다(누르면 지급 없이 닫힘).
- 서버 마이그레이션이 운영에 적용되기 전에는 Collect가 실패로 닫힌다(지급 없음).
