# ADR-0073 — 단어 카드는 레슨 카운터에 세지 않고, 카드 구간에는 가벼운 헤더가 선다 (카드 본문 정리 · `Got it` 하나 · 학습 지시문 heading-m)

- 상태: **채택 — 클라이언트 쪽.** 호스트 · 서버 · 콘텐츠 변경은 0이다.
  **사용자 결정**(2026-10-19)이다 — 아래 D1 ~ D4의 굵은 문장은 사용자가 정했고, 같은 날 「알아요 / 처음 봐요」 두 버튼 안을 사용자가 **`Got it` 하나로 바꿨다**(D3).
  ⚠ **기기에서 보지 않았다** — 테스트(unit · ui · integration)와 번들 크기만 확인했다([카탈로그 새 문항 e2e](../e2e/catalog-items.md) NW1 ~ NW7, 미실행).
- 날짜: 2026-10-19.
- 다루는 축: **단어 카드 구간의 진행 표시와 카드 본문** — 레슨 카운터(`Lesson n / N`)가 무엇을 세는가, 카드 구간에 서는 헤더, 카드 한 장에 서는 정보와 버튼,
  학습 지시문의 글자 크기. **다루지 않는 것**: 카드의 순서(카드 먼저 · 문제 나중 — 그대로, 섞지 않는다), 채점 · 통과 기준([ADR-0058](0058-catalog-learning-session.md) A3 그대로),
  분석 이벤트의 수(`shownItemCount` 그대로), 맵 말풍선의 `n/N activities`(그대로 표시 문항 수), 문화 카드 · 따라 읽기의 카운터(그대로 센다).
- 이어받는 결정(결정 문장을 이 문서가 바꾼다 — 그 문서에 정정 기록):
  [ADR-0058](0058-catalog-learning-session.md) 3d-1 적용 기록 A3 「**카운터는 카드를 센다 — 사용자 결정**」 · 같은 절 머리의 「채점하지 않되 카운터에는 센다」 · 「마지막 카드의 버튼이 레슨 중간이면 `Next`, 끝이면 `See results`」.

**왜 새 번호인가** — ADR-0058의 **사용자 결정** 문장 하나(카운터는 카드를 센다)를 뒤집고, 그 위에 카운터 · 헤더 · 카드 화면 · 테스트가 지어져 있다(ADR README 「형식」의 첫째 · 둘째 줄).
제자리로 고치면 「그때 왜 카드를 셌는가」가 지워진다.

근거 표시: **[코드]** 저장소 코드(`apps/mobile/src/` 기준) · **[실측]** 빌드 · 테스트 · **[ADR]** 기존 결정 · **[추론]** 관찰 없이 이어 붙인 것.

## 맥락

1. **카드가 카운터를 부풀렸다** [코드]. `catalogActivityPositionOf`의 오프셋 · 전체가 표시 문항 수(`shownItemCount` — 카드 포함)였다. 새 형식 u01 `S1`은 카드 7장 뒤 문제가 이어져,
   첫 문제가 `Lesson 8 / N`으로 섰다 — 한 문제도 풀지 않았는데 절반 가까이 온 것으로 읽힌다.
2. **카드가 문제처럼 보였다** [코드]. 카드도 회색 세션 헤더 상자(`Lesson n / N` · 막대 · `New words`) 아래에 섰다. 카드는 묻지 않는데(채점 없음) 모양은 문제와 같았다.
3. **카드 한 장의 정보가 너무 많았다** — 사용자 지적. 표식 · 표제어 · 로마자 · 뜻 아래에 예문 상자(`Example` · 예문 · 로마자 · 번역)가 섰다.
4. **지시문이 화면에서 가장 작은 글씨였다** [코드]. `.learning-shell-instruction`이 label-l(14/20)이었다(요청 문면은 heading-s라 했으나 코드는 label-l이었다).

## 결정

### D1. **단어 카드는 레슨 카운터에 세지 않는다 — 사용자 결정**

- 표 `catalogCountsInLessonCounter`(`app/catalog-lesson-plan.ts`)가 학습형마다 카운터에 드는가를 진다 — **`vocab-card`만 `false`**. 새 학습형이 생기면 타입 검사가 답을 강제한다.
- `catalogActivityPositionOf`의 오프셋 = 앞 활동들의 **카운터 문항 수** 합, 전체 = 카운터 문항 수. 카드 뒤 첫 문제가 `Lesson 1 / N`이고 N은 카드를 뺀 수다.
- **채점 표와 같은 표가 아니다.** 문화 카드 · 따라 읽기는 채점하지 않아도 세션 헤더 안에서 한 장씩 넘기므로 그대로 센다 — 빠지는 것은 단어 카드뿐이다(사용자 문면).
- **분석 `shownItemCount`는 그대로 카드를 센다** — 「화면에 무엇이 섰나」의 수이고, 카운터는 「몇 번째 문제인가」의 수라 다른 질문이다. 맵 말풍선의 `n/N activities`도 그대로다.
- 카드뿐인 레슨의 전체는 0이다 — 그 레슨에는 세션 헤더가 서지 않으므로(D2) `Lesson 1 / 0`이 서지 않는다.
- 버린 것: `shownItemCount`의 뜻을 바꾸는 안(이벤트 의미가 조용히 바뀐다) · 채점 표를 카운터에 쓰는 안(문화 카드 · 따라 읽기도 빠진다).

### D2. **카드 구간에는 세션 헤더 대신 가벼운 헤더가 선다 — 사용자 결정**

- `LearningShell`이 `runProgress?: { segments, label }`를 받으면 세션 헤더 상자 대신 `LearningRunHeader`가 선다 — `×`(세션 헤더와 같은 두 걸음 나가기) · **카드마다 한 칸인 막대** · 그 아래 캡션 한 줄.
  헤더 자리의 갈림은 `LearningShellHeader`가 진다. 회색 상자 · 학습형 이름 · 백분율이 없다.
- 칸 상태는 셋이다 — 지난 칸 `done`(`brand-primary`) · 지금 칸 `current`(`brand-secondary`, 한 단계 밝은 브랜드) · 남은 칸 `upcoming`(`gray-300`). 값은 순수 함수 `vocabCardRunProgress`가 낸다.
  `current`를 `background-elevated`(#FFF3EA)로 두지 않은 것은 `gray-300`(#EEEFF1)과 거의 구별되지 않아서다 [추론 — 색 값 비교].
- 캡션은 왼쪽 `Word {i} of {n}` 하나(label-s · muted). **막대는 낭독에서 빠지고**, 막대와 캡션을 묶은 한 요소가 같은 이름(`Word 4 of 7`)으로 읽힌다.
- 카드 구간이 끝나면 다음 활동(문제)에서 세션 헤더가 돌아온다. 카드 순서 · 끝남(`onFinish([], 0)`)은 바뀌지 않았다.
- 시안의 「이미 아는 수」 자리와 녹색 칸은 D3의 정정으로 없다.

### D3. **카드 본문은 표식 · 표제어 · 로마자 · 뜻뿐이고, 버튼은 `Got it` 하나다 — 사용자 결정**

- 지시문은 그대로 `Learn this word.`다. 무대 카드 안에 `New word` 표식 · 한글 표제어(display · `fg-brand`) · 로마자(body-l · muted) · 구분선 · 뜻(heading-s)이 선다.
- **예문을 그리지 않는다.** 매핑은 예문을 그대로 실어 두어(`VocabCardQuestion.example`) 되돌릴 자리가 화면 하나다.
- 아래 버튼은 ui-lynx `Button`(brand · xl · fill) **`Got it` 하나**이고 **마지막 카드도 같은 라벨**이다 — 레슨 중간이면 다음 활동으로, 끝이면 결과로 간다(전의 `Next` / `See results` 갈림이 없어졌다).
  껍데기는 `actionButton`으로 받는다. 누름 소리는 그 버튼이 낸다.
- **정정(같은 날, 사용자)**: 처음 안은 「New to me(outline) / I know it(brand)」 두 버튼, 「처음 봐요」는 구간 끝에 한 번 다시, 「이미 아는 수」 캡션 · 녹색 칸이었다.
  사용자가 버튼 하나로 바꿨다 — 그래서 아는 / 모르는 상태 · 다시 넣기 · 그 리듀서가 없고, 세션 안 기록도 없다.

### D4. **학습 지시문은 heading-m(22/28)이다 — 사용자 결정**

- `.learning-shell-instruction`을 label-l(14/20)에서 heading-m으로 키웠다 — 껍데기를 쓰는 모든 학습 활동에 걸린다. 색은 그대로 muted, 가운데 정렬 · 줄바꿈(말줄임 없음)이다.
- 긴 지시문은 두 줄이 된다. 작업 영역이 문턱 아래로 줄면 껍데기가 지시문 · 무대 · 작업 영역을 한 스크롤로 합친다(`learning-shell-flow` — 지금 규칙 그대로).

## 대가

1. 카드 구간과 문제 구간의 헤더 모양이 다르다 — 한 레슨 안에서 헤더가 한 번 바뀐다. 카드 구간은 「레슨 전체 중 어디」를 말하지 않는다.
2. 「이 단어를 아는가」를 묻지 않으므로 카드에서 얻는 신호가 없다(전에도 없었다).
3. 지시문이 커져 작은 화면에서 작업 영역이 줄어든다 — 기기에서 본 적이 없다.
4. 번들 +3,950 bytes(main 기록 2,198,142 → 2,202,092), 상한 2,200,000 → 2,204,000(사용자 사전 승인) — [성능 보고서](../performance/reports/new-word-cards-iphone-17-pro-simulator-01.md)(번들만).

- **지시문 줄 상자의 하한이 36이 됐다**(판정 배지 높이). 판정이 나면 배지가 지시문 위에 겹치고 지시문 글은 흐름에 남아 가려진다 — 2줄 지시문(56)에서도 높이가 그대로라 아래가 밀리지 않는다.
