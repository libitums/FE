# ADR-0157: 배경 미리 받기 창 — 진행 중인 편 + 다음 1편만 그림 · 음성을 미리 받는다

- 상태: **채택** (2026-11-17)
- 날짜: 2026-11-17
- **사용자 결정** (2026-11-17): 「백그라운드 다운로드 기준을 현재 에피소드 진행 + 1」 — 창 크기 N = 1.
- 바꾸는 결정: [ADR-0071](0071-episode-background-download.md) D3(새 · 바뀐 편을 모두 받는다) · [ADR-0095](0095-content-delivery-and-data-policy.md) D5(요금 없는 연결은 전부 자동).

## 맥락

- 2026-11-17 Supabase가 Cached Egress 초과(Pro 포함 250 GB/월)를 알렸다. 운영 edge 로그 하루 ≈ 57 GB 중 **≈ 96%가 새로 설치된 기기가 첫 실행에 카탈로그 18편의 그림 · 음성을 모두 받는 것**이었다(설치당 ≈ 64 MB, 캐시 결함 아님 — 같은 기기의 다시 받기는 거의 0).
- 활성 사용자 대부분은 u00 ~ u02에 있다(7일 u02 완료 89명, u04 이후 편당 1 ~ 5명). 설치당 받는 양의 ≈ 82%가 99%의 사용자가 열지 않는 편이었다.

## 결정

### D1. 창 = 진행 중인 편 + 다음 `PREFETCH_WINDOW_AHEAD`(= 1)편
- 진행 중인 편 = 맵 순서(카탈로그 구획 — 열린 편과 「준비 중」 편 모두)에서 **첫 미완료 편**. 모두 끝냈으면 마지막 편(`lib/prefetch-window.ts` `prefetchWindowIds`).
- 창은 진행에서 파생해 세션 동안 메모리에 둔다(`setPrefetchWindow`). 저장하지 않는다. 진행을 아직 모르면(실행 시작 첫 차례) 내장 매니페스트 순서의 앞 편 = 새 사용자 창.
- 편을 끝내 창이 밀리면 받기 차례를 다시 돌린다(`use-download-gate.tsx` effect → `requestSync`) — 다음 편이 그때 받아진다.

### D2. 창은 그림 · 음성(자산)에만 — 본문은 모두 받는다
- 본문(JSON) · 번역은 지금처럼 모든 편을 받는다(번역 표가 본문에 매인다).
- 판정(`assetDownloadDecision`): 튜토리얼 · 사용자가 허락한 편 · 레슨(허락 목록) → `allow` · **창 밖 → `skip`(연결과 상관없이)** · 창 안 → 지금 정책(요금 없는 · 모르는 연결 `allow`, 요금 연결은 `always` · 허락이면 `allow`, 아니면 `defer`).
- `skip`은 `defer`와 다른 결과다 — 받기 차례 요약 `skipped`에 들고 **60초 연결 재확인을 깨우지 않는다**(`deferred`만 재확인 — 안 그러면 매분 매니페스트를 다시 받는다).
- 이미 다 받아 둔 묶음은 판정을 묻지 않는다 — 창 밖이어도 지우지도 다시 받지도 않는다(옛 설치의 받은 파일은 그대로).

### D3. 창 밖 편은 열 때 받는다
- 창 밖 원격 편은 ADR-0071 D4대로 자산을 갖추기 전에는 「준비 중」 카드다. 그 카드나 표지 · 유닛을 누르면 받기 문지기(ADR-0095 D6)가 `open`일 때 그 편을 **이번 실행의 창에 더하고**(`openEpisodeForPrefetch`) 받기 차례를 돌린다 — 다 받으면 같은 자리에 열린 구획이 선다.
- 요금 연결이면 지금처럼 받기 시트(D6)가 묻는다 — 「지금 받기」는 허락 목록에 올라 창보다 우선한다.
- 레슨 단위 받기 · 「이 편 나머지 받기」 · 「오프라인용으로 모두 받기」(ADR-0095 D8)는 허락 목록이라 그대로 동작한다.

## 버린 대안
1. **N = 2** — 설치당 ≈ 11 MB. 주 사용자(u00 ~ u02)는 창 밖을 거의 열지 않아 N = 1로 충분하고, 편을 끝내는 순간 다음 편을 받기 시작한다.
2. **본문도 창 안만** — 창 밖 편이 내장본으로 물러나 번역 표를 잃는다.
3. **창을 저장소에 둠** — 진행에서 늘 다시 셀 수 있다. 저장하면 진행과 어긋날 수 있다.

## 대가
- **오프라인 약속이 좁아진다**: 「오프라인 = 진행 중인 편과 다음 편 + 사용자가 받은 편 · 레슨(모두 받기 포함)」. 비행기 모드에서 창 밖 편은 「준비 중」이다.
- 창 밖 편을 처음 열 때 그 편을 받는 몇 초를 기다린다(편 하나 ≈ 2.4 ~ 4.8 MB).
- 바뀐 판(스테이징)이 창 밖이면 새 자산이 필요한 편은 옛 판에 머문다 — 창에 들거나 열 때 바뀐다.
- 옛 앱(1.5.0 전)은 계속 전부 받는다 — 효과는 새 판 설치 비율만큼이다.

## 재검토 조건
- 콘텐츠가 R2(전송료 0)로 옮겨지면 → N을 넓혀 오프라인 범위를 되돌릴지 본다.
- 창 밖 편 열기 대기에 대한 불만이 보이면 → N = 2 또는 Wi-Fi에서만 N 넓히기.
