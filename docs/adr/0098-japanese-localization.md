# ADR-0098 — 일본어를 넷째 다른 UI 언어로 연다

- 상태: **채택 — 클라이언트 + 콘텐츠.** 서버 코드 변경 0. 콘텐츠 수준은 올리지 않는다. 호스트 글꼴 파일 변경 0.
- 날짜: 2026-11-04.
- **사용자 결정**(2026-11-04): 「일본어도 진행」 — [ADR-0097](0097-spanish-localization.md)(스페인어)과 같은 범위(문구표 · 내장본 · 레이아웃 검수).
- 다루는 축: ADR-0091 · 0093 · 0097의 구조에 넷째 언어를 더한다. 이로써 언어 목록의 다섯이 모두 열린다.
  **다루지 않는 것**: 언어별 번역 파일 분리, 스토어 등록 정보, 랜딩.

## 결정

### D1. 언어 코드는 `ja` — 목록의 다섯이 모두 고를 수 있다

- `isEntryLanguageAvailable`은 다섯 모두 참이다. 판정 함수는 다음에 고를 수 없는 언어를 다시 둘 때를 위해 남긴다.
- 기기 태그 `ja` · `ja-JP`는 `ja`다.

### D2. 콘텐츠 번역표에 `translations.ja`

- `ContentLanguage` = `vi | id | es | ja`. 규칙은 ADR-0091 D1 그대로.
- 내장 u00 ~ u10에 싣고 내장 목록 sha256 · bytes를 다시 계산한다(판 번호 그대로).
- 버킷 수준 3 묶음 u00 ~ u13에도 싣는다 — 스페인어 묶음(2026-11-04.1)에 `ja`를 더한 통합본, 판 `2026-11-04.2`. 업로드는 사람이 한다.

### D3. 문구표 `ja`는 영어와 같은 모양의 완전한 표다(번역 초안)

- `uiCopyJa: UiCopy` — `ui-copy-ja-*.ts`. 파일 머리에 「원어민 검수 필요」.
- 문장은 です・ます, 버튼 · 탭 · 칩은 짧은 명사 · 동사(「次へ」 「確認」). 구두점은 전각(、。？！), 인용은 「」.
- 이야기 속 점원 · 주인 · 역무원의 손님 응대는 경어, 친구 사이는 영어가 보이는 대로 반말. 한글 · 로마자 · `{자리표시}`는 그대로.
- 이로써 덮어쓰기가 빈 언어 표가 없어진다 — 「빈 표는 영어로 채운다」는 병합 규칙은 `uiCopyWithOverrides`가 지고 테스트도 그 함수를 직접 본다.

### D4. 일본어 UI에서는 글꼴 토큰 전체에 일본어 글꼴을 먼저 둔다(`.app-lang-ja`)

- Jost · Pretendard에는 가나 · 한자가 없고, 토큰의 대체 목록은 한국어 글꼴(`Apple SD Gothic Neo` · `Noto Sans KR`)을 일본어 글꼴보다 먼저 둔다. 같은 한자도 나라마다 자형이 달라(예: 「直」 「骨」), 일본어 문장의 한자가 한국 · 중국 자형으로 그려질 수 있다.
- `.app-lang-ja`가 글꼴 토큰 22개를 `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", "Noto Sans CJK JP"`를 앞에 둔 목록으로 다시 정의한다. 한글은 이 글꼴들에 없어 시스템 대체로 지금처럼 그려진다.
- Android Lynx가 시스템 글꼴을 이름으로 찾지 못하면 기기 언어의 기본 대체를 따른다 — 일본어 기기는 일본어 자형, 다른 언어 기기는 그 기기의 자형이다(받아들인 한계).

## 테스트 계획

| 계층 | 무엇 |
|---|---|
| unit (episode-core) | TR9: `translations.ja` 정규화 |
| unit (app) | EL4(다섯 모두), UL5e(`ja` · `ja-JP`), LZ8, JA1 ~ JA3(문구표 완전성 · 번역 비율), AS3(`app-lang-ja`), 빈 덮어쓰기 병합 규칙 |
| integration | 일본어 사용자가 내장 콘텐츠를 번역으로 본다 · 설정 › 언어에서 일본어로 바꾸면 즉시 바뀌고 저장된다 |
| 콘텐츠 | 내장 11편 · 버킷 14편이 열리고 sha256 일치 · 번역표 경고 0 · 한글 · 자리표시 보존 |
| 레이아웃 | iOS 시뮬레이터에서 진입 · 지도 · 레슨 · 결과 · 설정 — 잘림 · 넘침 · 한자 자형 · 줄바꿈 |

## 대가

- 번들 + 일본어 문구표 · 내장 번역표(UTF-8 한 글자 3바이트) — 번들 상한을 넘으면 실제 기능 증가로 올린다(성능 보고서 `ja-localization-01`).
- 번역은 초안이다(검수용 표: 업로드 묶음의 CSV).

## 재검토 조건

- 콘텐츠 번역 언어가 넷이 됐다 — 에피소드 하나에 번역표 넷이 실리고 모든 사용자가 다 받는다. 번역 파일 분리 ADR(초안, 번호 미정)을 다음 언어 전에 반드시 정한다.

## 적용 기록

- ⟨2026-11-04⟩ **레이아웃 검수**(iOS 시뮬레이터 iPhone 17 Pro, 에이전트 실행 · 사람 미확인): 언어 선택 · 설정 · 이름과 나라 · 알림 · 여정맵 · 업데이트 안내 창 · 스텝 말풍선 · 레슨(새 단어 · 그림 고르기 · 듣기 · 음절 조립) · 정답 배지 · 결과 · 롤플레이 목록 · 온보딩 세 장 · 로그인(저장 언어 `ja`인 새 기기). **잘림 · 넘침 없음.**
  - 글꼴: 화면을 원본 해상도로 잘라 보면 가나 · 한자가 Hiragino Sans로 그려진다(D4 동작 확인).
  - 일본어는 띄어쓰기가 없어 Lynx가 글자 단위로 줄을 바꾼다. **한 글자만 다음 줄로 넘어가던 셋을 고쳤다** — 스텝 말풍선 제목(「…チュートリア / ル”」 → 일본어는 `sheetHeading`이 유닛 이름 다음에 줄을 바꿔 제목을 둘째 줄에 둔다, 다른 언어는 지금과 같다), 음절 조립 지시문(콘텐츠, 「音節を並べて単語を作りましょう。」로 줄임), 이름과 나라 설명(문구표, 한 줄로 줄임). 문화 퀴즈의 일회성 질문(18 ~ 21자)은 두 줄로 감겨도 읽히므로 두었다.
  - 말투가 섞이던 업데이트 안내 창 두 문구(반말)를 です・ます로 맞췄다.
  - 콘텐츠 문장(에피소드 · 롤플레이 제목, 이름과 나라 예문)은 버킷 판이 내장본을 이겨 영어였다 — 통합 업로드 묶음을 올리면 바뀐다. 내장본을 쓰는 튜토리얼은 「こんにちは」 · 「何と言っていましたか？」처럼 일본어가 화면까지 닿았다.
