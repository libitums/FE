# ADR-0176: 컴패니언 2단계 — 롤플레이 미션의 뼈대 (에피소드에 묶인 과업 대화 · 격리된 대화 · 미션 전용 프롬프트와 SQL · 코드가 계산하는 점수)

- 상태: **채택 — 문서만.** 코드 · 마이그레이션은 조각마다 따로 들어온다([PRD](../specs/ai-companion-mission.md) §8).
- 날짜: 2026-11-18
- **사용자 결정** (2026-11-17 ~ 18): 질문 60여 개로 맞췄다. 아래 D1 ~ D9가 그 결과이고, 값(횟수 · 정액 · 가중치 · 턴 상한)은 실측 뒤로 미뤘다.
- 이어받는 결정: [1단계 PRD](../specs/ai-companion.md) §0 「범위 밖」(미션은 2단계 · `conversations.kind`에 자리만), [ADR-0135](0135-companion-llm-vendor-layer.md)(미션 채점 때 오케스트레이션 계층을 다시 본다), [ADR-0076](0076-episode-roleplay.md)(대본형 롤플레이는 규칙 기반으로 둔다), [ADR-0144](0144-subscriptions-revenuecat.md)(요금제 셋).
- 근거 문서: 팀 위키 「AI 컴패니언 기획 3: 롤플레이 미션」과 위키 ADR-0004. 위키와 다르게 간 곳은 PRD §10.

## 맥락

- 1단계(끝없는 자유대화)가 마무리 단계다. 저장소에는 2단계가 「미룬다」는 한 줄뿐이었고 `mission`은 문서 두 곳에만 나왔다.
- 1단계 턴 엔진은 「캐릭터당 대화 하나」에 묶여 있다 — `chat-send` 요청에 대화 id가 없고, 대화를 `kind = 'companion'`으로 고르는 SQL이 마이그레이션 열 개 남짓에 흩어져 있으며, 턴의 SQL 한 쌍이 차감 · 친밀도 · 기억을 한 몸으로 한다. 시스템 프롬프트의 틀(계속 이어 가라 · 친밀도 상태 줄 · 로맨스 줄)은 하드코딩이다.
- 캐스트의 페르소나 카드는 「메신저 친구가 된 뒤」의 인물이라 본편 시점의 상대역과 어긋난다(6화의 도윤 — 서비스 말씨의 점원 / 카드 — 반말 인사 · 오디션 화제 · 가벼운 호감). 에피소드 11편의 상대역 가운데 다섯은 캐스트가 아니다.
- 한국어 자유 발화의 발음 평가는 믿을 만한 것이 확인되지 않았다(2026-11-17 조사).

## 결정

### D1. 미션 = 에피소드 하나에 묶인 과업 대화
- 진입 대사 · 목표(필수 / 선택) · 턴 상한 · 상대역 역할 카드 · 목표 표현. 에피소드를 끝내면 열리고, 몇 번이든 다시 하며, 이어 하기는 없다.

### D2. 미션 대화는 격리한다
- `conversations.kind = 'mission'`, 판마다 새 행. 친밀도 · 말투 단계 · 기억 · 화제 · 이야기 · 선톡 · 체험을 읽지도 쓰지도 않는다.
- 기존의 `kind = 'companion'` 조건은 건드리지 않는다 — 격리의 보장이 거기서 나온다.

### D3. 함수는 같이 쓰고 프롬프트와 SQL은 나눈다
- `mission-start` · `mission-finish` · `mission-hint`를 새로 두고, 턴은 `chat-send`에 `conversation_id`(선택)를 더해 같이 쓴다.
- 답 만들기의 부품(LLM 계층 · 조각 해석 · 교정 · 번역 · 검사 · SSE)은 공유한다. 시스템 프롬프트와 턴의 begin · finish SQL은 미션 전용이다.

### D4. 상대역 설명은 미션 파일에 새로 쓴다
- 캐스트는 카드에서 이름 · 나이 · 직업 · 말버릇만 읽는다. 단역은 `companion.characters`에 넣지 않는다.
- 미션 정의의 정본은 저장소 파일이고 스크립트가 서버 표로 올린다. 1판은 6화(캐스트)와 1화(단역) 둘이다.

### D5. 성공은 필수 목표로, 점수는 코드가 계산한다
- 성공 = 필수 목표를 모두 달성. 최종 점수 = 0.5 × 과업 + 0.3 × 정확도 + 0.2 × 목표 표현 − 5 × 힌트 횟수. 세부 점수는 상위 모델이 판당 한 번 내고 합산은 코드가 한다.
- 발음은 채점 축에서 뺀다. 결과 표의 칸만 남긴다.

### D6. 힌트 · 끝
- 힌트는 못 이룬 목표 하나의 예시 문장 하나, 판당 3번, 1회 −5점.
- 필수 목표를 다 이루면 마무리 대사 뒤 자동으로 끝나고, 턴 상한이면 실패다. 채점 호출이 실패하면 값을 돌려주고 채점만 다시 부른다. 그만두면 리포트도 환불도 없다.

### D7. 값은 판 단위 — 하루 무료 횟수 다음에 엽전 정액
- 턴마다 빼지 않는다. 판정은 함수 하나에 모은다(「무료 횟수와 엽전이 함께 있는」 정책은 따로 다시 본다).

### D8. 출력 검사는 지금의 나이 규칙 그대로, 입력은 글자 + 내장 STT로 시작
- 성인은 스트리밍, 미성년 · 나이 모름만 검사 뒤 전송. 서버 STT는 발음 트랙이 벤더를 정한 뒤 끼운다.

### D9. 순서 — 문서 → 서버와 계약 → 미션 둘과 평가 → 화면 → 나머지와 운영
- 운영 DB에는 1단계 마이그레이션 기록이 정리될 때까지 2단계를 적용하지 않는다.

## 버린 대안
1. **컴패니언 프롬프트 · SQL에 스위치를 단다** — 1단계 코드를 건드려 평가를 다시 돌려야 하고, 프롬프트의 방향(이어 가라 / 끝내라)이 반대다.
2. **미션만 규칙 기반** — 위키 ADR-0004가 이미 버렸다(엔진이 둘로 갈린다).
3. **캐스트 카드를 그대로 읽는다** — 본편과 다른 인물이 나온다.
4. **턴마다 차감** — 판 도중 엽전이 떨어져 채점 없이 끊긴다.
5. **「목표 넷 중 셋」 같은 개수 기준** — 결제 없이 주문만 해도 성공이 된다.
6. **최종 점수를 모델이 낸다** — 같은 대화에 다른 점수가 나오고, 가중치를 바꾸려면 프롬프트를 고쳐야 한다.
7. **전 연령 동기 출력 검사**(위키 04) — 성인의 답이 스트리밍되지 않는다.
8. **발음을 넷째 채점 축으로**(위키 03) — 자유 발화 평가의 근거가 없다.
9. **전체 사용자 랭킹을 1판에** — 점수의 안정성을 모르고, 다시 하기와 충돌하며, 닉네임 공개가 따라온다.

## 대가
- `chat-send`가 두 갈래를 고르는 지점 하나를 갖는다.
- 캐스트가 상대역인 여섯 편도 역할 카드를 사람이 써야 한다.
- 턴 판정과 채점의 품질은 N2의 고정 시나리오 평가 전에는 모른다 — 점수가 흔들리면 식과 프롬프트를 거기서 고친다.
- 내장 STT의 약점(틀린 발음을 그럴듯한 낱말로 받아 적음)이 1판의 정확도 점수에 들어온다.
- 서버 조각은 운영에서 돌려 보지 못한 채 머지된다(D9).

## 테스트
- 이 ADR은 문서만 바꾼다. 조각마다의 테스트는 PRD §8의 「끝났다는 것」이 정한다.
