# ADR-0102 — 에피소드 번역표를 언어별 파일로 나눈다 (새 수준부터)

- 상태: **채택** (2026-11-05 — D4는 미룸, 아래 「적용 기록」).
- 날짜: 2026-11-05.
- **사용자 결정**(2026-11-05): 번역을 본문에서 떼어 버킷에 언어별로 둔다. 이미 나간 앱을 위해 **새 수준 매니페스트부터만** 나누고, 수준 2 · 3 본문은 지금처럼 번역표를 품는다.
- 다루는 축: 콘텐츠 번역의 버킷 배치 · 매니페스트 키 · 앱이 받는 범위 · 내장본. [ADR-0091](0091-vietnamese-localization.md) D1(「영어 → 번역」 표)의 **표 모양은 그대로** 두고 놓이는 자리만 바꾼다.
  **다루지 않는 것**: 번역 내용 · 검수 절차, UI 문구표(앱 안 `i18n`), 그림 · 소리의 언어별 판.

## 맥락

1. **안 쓰는 언어까지 받는다.** 번역표는 에피소드 최상위 `translations`에 vi · id · es · ja가 모두 들어 있다. 내장 11편 기준 본문 2,394,065 B 중 번역이 약 451 kB(19 %, 언어당 107 ~ 121 kB)다 [실측 2026-11-05]. 한 언어 사용자는 나머지 세 언어(약 340 kB)를 받고, 언어를 하나 더할 때마다 모든 사용자의 본문이 에피소드당 약 10 kB 늘어난다.
2. **번역 한 줄이 본문 전체를 다시 받게 한다.** 원어민 검수로 값 하나만 고쳐도 본문 sha256이 바뀌어 `version`을 올려야 하고, 모든 사용자가 본문(편당 200 kB 안팎)을 다시 받으며 스테이징 교체(ADR-0078)를 탄다. 검수는 앞으로 언어마다 따로, 여러 번 온다.
3. **번들도 같은 값을 진다.** 내장본(u00 ~ u10)에 표를 붙이며 번들 상한을 올렸다(ADR-0091 적용 기록 ⟨2026-11-03⟩).

## 결정

### D1. 버킷 배치 — `translations/<언어>/<id>.json`

```json
{ "schema": "translation-1", "episode": "u01-water", "language": "vi",
  "entries": { "Fill in the blank.": "Điền vào chỗ trống.", "water": "nước" } }
```

- `entries`는 지금의 `translations.<언어>` 값과 **같은 표**다(키는 그 에피소드의 영어 원문, 값은 번역). 정규화 · 경고 규칙(문자열 아닌 값 · 빈 값 버림)도 그대로 쓴다.
- 경로는 수준과 무관하게 하나다 — 표의 키가 영어 원문이라, 본문이 수준별로 갈려도 같은 표를 함께 쓴다. 영어가 바뀐 줄은 표에서 못 찾아 영어로 보일 뿐 깨지지 않는다.
- `en`은 파일이 없다(원문이 영어).

### D2. 매니페스트 — 항목의 선택 키 `translations`

```json
{ "id": "u01-water", …, "url": "episodes/level-4/u01-water.json",
  "translations": { "vi": { "url": "translations/vi/u01-water.json", "version": "2026-11-05.1", "sha256": "…", "bytes": 10127 } } }
```

- 언어마다 `url` · `version` · `sha256` · `bytes`. 본문 `version`과 **따로** 오른다 — 번역만 고치면 그 언어 파일만 바뀌고 본문은 그대로다.
- 이 키는 **새 수준(`manifests/level-4.json`)에만** 적는다. 그 수준의 본문(`episodes/level-4/<id>.json`)에는 최상위 `translations`가 없다.
- 수준 2 · 3 매니페스트와 본문은 지금 그대로(번역표를 품은 본문). 콘텐츠 도구가 같은 원본에서 두 모양을 만든다 — 사람이 두 벌을 손으로 맞추지 않는다.

### D3. 앱은 지금 UI 언어의 파일만 받는다

- 받기 차례에서 ready 에피소드마다 **지금 UI 언어**의 파일만 받는다. 검증(sha256) · 저장은 본문과 같은 길이고, 저장 키는 언어 · id별이다.
- 연결 정책: 번역은 본문처럼 **텍스트**라 요금제 연결에서도 자동으로 받는다(ADR-0095 D5의 「매니페스트 · 본문」 줄). 그림 · 음성 허락과 묶지 않는다.
- 언어를 바꾸면 그 언어의 파일을 받는 차례를 한 번 돌린다 — UI 언어를 저장하는 순간(`saveUiLanguage`)의 알림을 받기 실행기가 듣는다. 받기 전(오프라인 포함)에는 그 언어 표가 없는 상태 — 지금 표가 없는 에피소드처럼 **영어로** 보인다. 이미 받아 둔 다른 언어 파일은 지우지 않는다(되돌아오면 바로 쓴다).
- 적용 우선순위: 별도 파일이 있으면 그것, 없으면 본문 안 `translations`(수준 3 본문 · 내장본), 둘 다 없으면 영어. 섞지 않는다 — **한 언어 안에서는** 한 출처의 표만 쓴다(파일이 있는 언어는 본문 표를 통째로 바꾼다).
- 파일은 이긴 매니페스트 항목이 그 언어를 적었을 때만 적용한다. 매니페스트의 `version`이 바뀌어 새 파일을 받기 전까지는 받아 둔 이전 파일을 쓴다(영어 원문 키라 어긋나도 그 줄만 영어).
- 번역 파일이 없거나 받기에 실패해도 에피소드는 열린다. 번역은 에피소드를 잠그지 않는다.

### D4. 내장본은 지원 언어의 파일을 모두 싣는다

- 내장 에피소드의 본문에서 `translations`를 빼고, 지원 UI 언어(지금 vi · id · es · ja) 파일을 `content/translations/<언어>/<id>.json`으로 싣는다. 오프라인 첫 실행에서도 기기 언어로 보여야 하므로 언어를 고르지 않는다.
- 번들 크기는 지금과 거의 같다(표를 옮길 뿐). 줄어드는 것은 **받는** 양이다.
- 내장 매니페스트에도 D2의 `translations`를 적는다. 버킷과 `version`이 같으면 받지 않는다(본문과 같은 규칙).

### D5. 앱 수준을 올린다

- `CONTENT_CLIENT_LEVEL` 3 → 4. 이 앱은 `manifests/level-4.json`부터 읽고, 없으면(404) `level-3.json`으로 내려가 번역표를 품은 본문을 쓴다(ADR-0087 D1 그대로). 그래서 버킷에 수준 4를 올리기 전에 앱이 먼저 나가도 번역이 사라지지 않는다.

## 버린 대안

- **지금 모든 수준에서 바로 떼기** — 관리는 단순하지만 이미 나간 앱(번역표가 본문에 있어야 읽음)에서 문항 안내 · 뜻 풀이가 영어로 돌아간다. 사용자가 고르지 않았다.
- **언어마다 본문을 따로(`episodes/vi/<id>.json`)** — 받는 양은 같지만 번역 한 줄에 본문 전체가 바뀌는 문제(맥락 2)가 남고, 본문이 언어 수만큼 늘어난다.
- **모든 언어를 한 파일(`translations/<id>.json`)** — 본문과는 떨어지지만 안 쓰는 언어를 받는 문제(맥락 1)가 남는다.

## 대가

1. 수준 3을 그만 고칠 때까지 본문이 두 모양(번역 품음 · 뗌)이다 — 콘텐츠 도구가 한 원본에서 만들어야 한다(ADR-0087 대가 1과 같은 결).
2. 받기 요청이 에피소드당 하나 는다(그 언어 파일). 편당 약 10 kB라 크기 부담은 작다.
3. 언어를 바꾼 직후 오프라인이면 받지 않은 에피소드는 영어로 보인다.
4. 내장본은 언어를 더할 때마다 번들이 언어당 약 110 kB 는다(D4).

## 적용 기록

- ⟨2026-11-05⟩ **앱 구현** — **사용자 결정**(「구현」). 매니페스트 항목 `translations` 디코드 · 인코드(`episode-manifest.ts`, 언어마다 틀리면 그 언어만 버림), `translation-1` 디코더와 표 덧씌우기(`lib/episode-translation-files.ts` — 표 정규화는 episode-core `translationsOf` 재사용), 받기 차례의 번역 단계(`lib/episode-translation-sync.ts` — 본문보다 먼저, UI 언어 하나, sha256 대조 · 저장 키 `libitum.content.translation.<언어>.<id>`), 카탈로그가 저장된 파일로 그 언어 표를 바꿈, UI 언어 저장 알림으로 받기 재실행, `CONTENT_CLIENT_LEVEL` 3 → 4.
  - 같은 판(version · 출처가 같음)이 열린 세션에서는 **번역표만** 새 것으로 바꾼다(`mergeCatalogForSession`) — 언어를 바꿔 받은 파일이 다음 실행을 기다리지 않는다. 판이 다르면 지금 규칙(다음 실행 · 스플래시 교체)대로.
  - **D4(내장본의 언어별 파일)는 미룬다.** 내장 본문(u00 ~ u10 balance 판)을 level-4 판으로 바꾸는 것은 콘텐츠 교체라 따로 한다. 그동안 내장본은 본문 안 표(vi · id · es · ja)를 그대로 쓰고, 원격 판이 이기면 파일 표가 쓰인다.
