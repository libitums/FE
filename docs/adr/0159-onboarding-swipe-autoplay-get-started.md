# ADR-0159: 온보딩 — 밀기 · 자동 넘김, 모든 스텝에 「Get started」, 첫 스텝은 도윤 · 편의점 앞 골목

- 상태: **채택** (2026-11-18)
- 날짜: 2026-11-18
- **사용자 결정** (2026-11-18)
  - 「1,2,3은 스와이핑이나 몇 초 후 자동으로 넘어가게 하고 하단 버튼은 Get Start로 해서 바로 로그인으로 넘어가게」.
  - 첫 스텝은 지금 화면 그대로에 **캐릭터 · 배경 · 말풍선만** 바꾼다 — 인물은 도윤(전신 컷), 배경은 에피소드 1 편의점 앞 골목,
    인물은 가게와 겹치지 않게 골목 쪽에 더 크게(시안 「현재 1 · 캐릭터 · 배경만 도윤으로」).
- 바꾸는 결정: 진입 흐름 계약([entry-flow](../specs/entry-flow.md)) §3 온보딩 행 — 「`다음` / 마지막은 `시작하기`」.

## 맥락

- 최근 14일 온보딩을 본 사람 12,291명 중 로그인 화면까지 간 사람은 9,722명(79%)이었다. 지금 화면은 「Next」를 세 번 눌러야
  시작하고, 어느 스텝에서 떠나는지 재는 이벤트가 없었다.
- 첫 스텝 카드는 화장품 가게 직원 그림이었다 — 지금 앱의 이야기(편의점 · 도윤)와 맞지 않았다.

## 결정

### D1. 스텝 넘기기 — 밀기와 자동 넘김
- 카드 영역(`onboarding-screen-pager`)을 왼쪽으로 밀면 다음, 오른쪽이면 앞 스텝이다. 가로 32 이상이고 가로가 세로보다 커야 밀기다
  (알림 줄 밀기와 같은 값). 한 번 민 손가락은 떼기 전에 더 넘기지 않는다. 밀기는 소리를 내지 않는다.
- 손대지 않은 채 `onboardingAutoAdvanceMs`(4초) 서 있으면 다음 스텝으로 간다. **마지막 스텝에서 멈춘다**(돌지 않음 — 자동으로
  로그인에 가지 않는다). 화면에 손이 닿으면(재생 단추 · 카드 포함) 시계를 처음부터 다시 센다.
- **동작 줄이기(reduced motion)를 켠 사람에게는 자동으로 넘기지 않는다** — 밀기 · 버튼으로만 간다. 스스로 바뀌는 화면은
  WCAG 2.2.2(움직이는 · 자동 갱신 콘텐츠)의 정지 수단 요구에 걸리고, 동작 줄이기를 고른 사람은 화면이 스스로 움직이지 않기를
  바란 사람이라 보수적으로 끈다.
- 좌상단 뒤로 버튼 · 시스템 뒤로가기는 그대로 한 칸 앞 스텝이다(첫 스텝은 떠남).

### D2. 모든 스텝의 버튼은 「Get started」 — 곧바로 로그인
- 아래 버튼 하나(`onboarding-screen-start`, 문구 `onboarding.getStarted`)가 어느 스텝에서든 `onComplete`(로그인 열람 → push)다.
  「Next」 버튼과 문구 `onboarding.next`(다섯 언어)는 지웠다.

### D3. 첫 스텝 — 도윤 · 편의점 앞 골목
- 배경: 에피소드 1 도입 장면(`content/images/u01-water/pre-1.webp`)을 한옥 골목 + 오른쪽 가게 앞이 보이게 가로로 잘라
  `assets/onboarding/convenience-store-alley.webp`(847×431, ≈ 67 kB)로 넣었다.
- 인물: 도윤 전신 컷(투명 배경)의 윗부분을 잘라 `assets/onboarding/doyun.webp`(417×819, 알파, ≈ 46 kB)로 넣었다. 카드보다 80 크게
  그려 머리가 위로 튀어나오고 아래 끝이 카드 아래 끝과 맞는다. 가게(오른쪽)와 겹치지 않게 왼쪽에 둔다.
- 옛 `assets/story/story-background.png` · `story-character.png`(≈ 1.3 MB)는 쓰는 곳이 없어 지웠다.
- 말풍선(한국어는 학습 콘텐츠): 도윤 「저 지금 편의점 앞이에요. 뭐 마실래요?」 → 나 「물 한 병 사 주세요!」 → 도윤 「좋아요. 금방
  갈게요!」. 번역 줄 · 화자 이름은 UI 언어 문구표(`onboarding.storyChat` — `friend` · `atStore` · `water` · `onMyWay`)가 진다.
- 둘째 · 셋째 스텝은 그대로다.

### D4. 측정
- `onboarding_step_viewed { step: "1" | "2" | "3", via: "start" | "auto" | "swipe" | "back" }` — 스텝이 **그 방문에서 처음 보일 때
  한 번**. 다시 본 스텝은 내지 않는다(도달 퍼널이 되게). `back`은 앞 스텝으로 밀기 · 뒤로 버튼 · 시스템 뒤로가기다
  (처음 보는 스텝이 뒤로 오는 일은 없어 실제로는 거의 나지 않는다).
- `onboarding_started { step, autoAdvanced }` — 「Get started」를 누른 스텝과 그 전에 자동 넘김이 있었는지. 속성 이름은 저장소
  규약(camelCase)을 따른다.
- 둘 다 진입 sink(`entry_screen_viewed`와 같은 sink)로 나간다. 읽는 법: 스텝별 도달 = `onboarding_step_viewed` 단계별 사람 수,
  시작 스텝 분포 = `onboarding_started.step`, 자동 넘김의 몫 = `autoAdvanced`. 기존 `entry_screen_viewed(onboarding)` →
  `entry_screen_viewed(login)` 전환율(지금 79%)이 이 변경의 결과 지표다.

## 대가 · 위험
1. 「Get started」가 첫 스텝부터 있어 둘째 · 셋째 스텝을 보지 않고 시작하는 사람이 늘 수 있다 — 의도된 교환이다(시작이 먼저).
   `onboarding_started.step`으로 본다.
2. 자동 넘김 4초는 짧은 글을 읽기엔 빠를 수 있다 — 손이 닿으면 다시 세고, 마지막에서 멈춘다. 값은 상수 하나라 고치기 쉽다.
3. 밀기는 배경 스레드 터치 이벤트로 판정한다(알림 줄과 같은 방식) — 손가락을 따라 카드가 움직이는 애니메이션은 없다.
