# ADR-0058 — 카탈로그 학습 세션: 콘텐츠 문항을 기존 학습 화면에 데이터로 넘기고, 타자 입력 · 최종 테스트 · 통과 뒤 컷을 붙인다

- 상태: **채택 — 클라이언트 쪽.** 타자 입력까지 3c에 넣기 · 최종 테스트는 지금 콘텐츠 모양(타일) · 3b-2와 함께 출시는 **사용자 결정이다**(2026-10-12).
  계약 고정 뒤 사용자가 기본값 넷을 바꿨다(2026-10-12) — 빈칸 채우기(`CLOZE`)를 단어 선택으로 3c에 넣는다 · 통과 기준은 정답률 60 % · 활동 순서는 콘텐츠 순서 ·
  소리 없는 받아쓰기는 로마자 + 영어 뜻. 시뮬레이터 확인 뒤 다시 셋을 바꿨다(2026-10-13) — 학습형 사이에 완료 카드 없음 · 오디오 없는 듣기는 건너뜀 ·
  대화 순서는 화자를 번갈아 말풍선으로 조립. 그 밖(매핑 표 · route · 세션 고정 · 그림 실패 처리 · import 예외)은 계약 단계가 정했다.
  ⚠ **기기 확인이 반쪽이다.** 레슨 노드 · 단어 선택 · 대화 조립 · 학습형 연속은 iOS 시뮬레이터에서 봤고, **타자 입력 · 최종 테스트 · 통과 뒤 컷 · 그림 404 처리는
  기기에서 보지 못했다**(순차 잠금이라 앞 레슨을 모두 풀어야 닿는다 — [카탈로그 레슨 e2e](../e2e/catalog-lessons.md) 「미확인」).

## 맥락

1. **3b-2가 레슨 · 최종 노드를 잠근 채 세웠다** [코드]. 표지를 끝내면 다음이 막다른 길이었고, 그래서 3b-2는 이 작업과 함께 출시하기로 했다(ADR README 보류 표).
2. **튜토리얼 학습 화면은 문항을 스텝 id로 표에서 읽는다** [코드]. 듣기 · 문장 순서 · 단어 선택이 `stepId` prop을 받고, 그 표를 읽는 ui 테스트 · mock · integration 픽스처가 많다.
   사용자 지침은 「안정성 최우선」이었다 — 튜토리얼 경로의 props · 표 · 판정 · 테스트 소스를 바꾸지 않는 쪽을 고른다.
3. **콘텐츠 문항 13종 가운데 그대로 그릴 수 있는 것이 정해져 있다** [데이터]. 세 에피소드 288문항, 스텝은 `S1` · `S3` ~ `S9` · `RP`.
   오디오는 하나도 없다(계약 문서 §9 · Q21 — 「파일이 오기 전까지 텍스트를 보여 주고 재생 버튼을 비활성」이 콘텐츠 쪽 답).
4. **최종 테스트(`ROLEPLAY_TURN`)는 디코더가 불투명으로 받고 있었다** [코드]. `{ id, type }`만 검사하고 원본을 `raw`로 보존(계약 문서 §12 디코더 정책).
5. **3b-2 컷 화면 실기에서 404 그림이 앞 컷 그림을 남겼다** [실기]. u01 `pre-2`가 서버에 없어 로드되지 않았는데 컷 1 그림이 그대로 남았다([카탈로그 맵 e2e](../e2e/catalog-map.md) 「미확인」).

## 결정

### D1. 학습 화면 셋은 「Activity(문항 prop) + Screen(표 어댑터)」로 가른다

듣기 · 문장 순서 · 단어 선택의 본문을 `ListeningActivity` · `SentenceOrderActivity` · `WordChoiceActivity`로 떼어 **문항 목록을 prop으로** 받고,
기존 `…Screen`(`stepId` prop)은 표를 읽어 Activity에 넘기는 얇은 어댑터로 남긴다. 문항 출처는 경로마다 하나다 — 튜토리얼은 어댑터가 표에서,
카탈로그는 렌더 층이 수업 계획에서. 「표가 없으면 prop」 같은 겸용은 없다. 튜토리얼의 렌더 층 · 화면 props · ui 테스트는 한 줄도 바뀌지 않았다.

### D2. 문항 매핑은 `app/`의 순수 모듈 하나가 진다

`app/catalog-lesson-plan.ts`(+ 매핑을 나눈 `catalog-item-map.ts` · `catalog-choice-map.ts` · `catalog-typing-map.ts` · `catalog-shuffle.ts`)가 문항 하나를
학습형 넷 중 하나의 문항 또는 **건너뜀 + 사유**로 바꾼다. 화면 넷의 문항 타입을 한 함수가 모두 만들므로 화면 폴더가 아니라 `app/`에 둔다.

| 콘텐츠 `type`                                  | 학습형                    | 비고                                                                                                         |
| ---------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `CLOZE`                                        | 단어 선택                 | 빈칸 문장(`context`)이 제시문, `tiles`가 보기, 정답은 `answers[0]`과 같은 타일 — **사용자 결정**(2026-10-12) |
| `ROLE_LINE` · `TRANSLATE_TO_EN`                | 단어 선택                 | 보기 셋(2개 이상 허용으로 넓혔다 — 제품 튜토리얼은 단어 선택을 쓰지 않는다)                                  |
| `LISTEN_SELECT`                                | 듣기                      | **오디오가 없으면 건너뛴다**(`audio-missing`) — **사용자 결정**(2026-10-13). 지금 데이터는 전부 건너뛴다     |
| `WORD_ORDER`                                   | 문장 순서                 |                                                                                                              |
| `TURN_ORDER`                                   | 문장 순서(대화 조립 — D7) |                                                                                                              |
| `DICTATION` · `TRANSLATE_TO_KO` · `SENT_BUILD` | 타자 입력(D6)             |                                                                                                              |
| `VOCAB_CARD` · `IMG_MATCH` · `PAIR_MATCH`      | 건너뜀(`screen-pending`)  | 3d                                                                                                           |
| `ROLEPLAY_TURN`(레슨 안)                       | 건너뜀(`malformed`)       | RP는 최종 테스트에서만                                                                                       |

건너뜀 사유는 여섯이다 — `screen-pending` · `no-options` · `no-source` · `audio-missing` · `untypeable` · `malformed`. 계측(`skippedItemCount`)이 3d 우선순위의 근거가 된다.
⟨2026-10-13 — 3d-1⟩ **위 표의 `VOCAB_CARD` · `IMG_MATCH` · `PAIR_MATCH` 행과 사유 `screen-pending`은 3c 시점의 것이다** — 세 유형은 화면을 얻었고 사유는 일곱이 됐다(「적용 기록」 A2).
⟨2026-10-16 — 새 에피소드 형식⟩ **위 표는 13종 시점의 것이다** — 새 유형 11종이 더해져 24종이 됐고 `screen-pending`이 되살아나 사유가 여덟이다(「적용 기록」 ⟨2026-10-16⟩ · [ADR-0065](0065-episode-format-additions.md) D8).
⟨2026-10-16 — PR ③⟩ 말하기 둘이 화면을 얻어 `screen-pending`이 다시 지워졌다 — **사유는 일곱**이다(「적용 기록」 ⟨2026-10-16 — PR ③⟩ · [ADR-0067](0067-episode-format-speaking.md) D9).
`{이름}` · `{나라}`는 화면에 서는 ko · 로마자 문자열을 모두 치환한다(프로필은 3d 전까지 기본값). 타일(낱말 순서 · 대화 순서 · 빈칸 채우기 · 최종 테스트)은 **결정적으로 섞는다** — 씨앗 `${episodeId}/${itemId}`,
다시 풀어도 같은 순서이고 항등 순열이 나오면 한 칸 돌린다(계약 문서 Q20 「앱이 섞는다」). `options` 보기는 파일 순서 그대로다. 보기 중 하나라도 네 글자를 넘으면 단어 선택은 보기를 세로로 쌓는다(칩 안 글자 잘림 — [실기]).

### D3. 3c는 오디오를 연결하지 않는다 — 소리 없는 받아쓰기의 재생 조작은 꺼진 채 선다

매핑은 늘 `audioSource: null`이다. 콘텐츠에 오디오 id가 생겨도 3c 앱은 쓰지 않는다 — `playAudio`는 번들 id만 찾고 원격 해석이 없다([ADR-0017](0017-host-native-capabilities-and-audio.md) D3).
⟨2026-10-14⟩ **이 문단의 「원격 해석이 없다」는 그때의 상태다** — 재생 모듈이 https URL을 받게 됐고 컷 · 최종 테스트는 소리를 낸다([ADR-0060](0060-episode-voice-remote-audio.md)).
**학습 문항의 매핑은 여전히 늘 `audioSource: null`이다** — 아래 듣기 · 받아쓰기 규칙은 그대로 산다(ADR README 보류 표 「학습 문항 오디오의 연결」).

- **듣기**: 오디오가 없는 듣기는 계획에서 뺀다(D2 `audio-missing`). 계약 단계는 대본을 늘 보이고 재생 조작을 끈 `ListeningSilentPrompt`를 세웠으나,
  시뮬레이터에서 대본과 보기가 같은 문장이라 **베끼기**가 됐다 — 사용자가 건너뜀으로 바꿨다(2026-10-13). **`ListeningSilentPrompt`와 듣기 쪽의 꺼진 재생 조작은 지우지 않았다** — 오디오가 문항 일부에만 올 때
  (일부 누락) 그 자리가 다시 쓰이기 때문이다. 지금 실데이터 경로에서는 닿지 않는 코드이고 번들에 실린다(「대가」 9).
  오디오가 생기면 그 문항은 매핑 규칙을 바꾸지 않고 다시 선다 — 단 그때 `audioSource`를 넘기려면 원격 해석(보류 표)이 먼저다.
- **받아쓰기(타자)**: 로마자 + 영어 뜻을 단서로 보이고 한글은 확인 뒤 공개한다 — **사용자 결정**(2026-10-12, 계약 문서 Q21 「노출 시점」).
  카드에 꺼진 재생 조작 `AudioUnavailableControl`(`components/`)이 선다 — `accessibility-traits="disabled"`, 낭독 `Audio not available yet`, `bindtap` 없음.
- **[ADR-0016](0016-assistive-technology-semantics.md) D10의 예외다.** D10은 「영구히 조작 불가한 것에만 `disabled`」인데 이 조작은 오디오가 오면 걷힌다.
  콘텐츠 쪽 답(Q21)이 「재생 버튼을 비활성」이고, 걷을 날의 조건(오디오 파일 + 원격 해석)이 보류 표에 있다 — 예외를 이 한 자리로 묶는다.

### D4. 레슨 = 콘텐츠 순서의 같은 학습형 연속 구간. 학습형 사이에 완료 카드가 없다

활동은 건너뜀을 걸러낸 문항을 **콘텐츠 순서 그대로** 두고 같은 학습형이 이어지는 구간을 하나로 묶는다 — **사용자 결정**(2026-10-12). 학습형별 정렬은 버렸다.
활동 하나 = 학습 화면 하나(route `catalog-lesson`의 `activityIndex`), 활동 사이는 `replace`다.

- **중간 활동이 끝나면 완료 카드(`All questions done · See results`) 없이 다음 학습형 첫 문항으로 간다.** 완료 카드와 `See results`는 레슨의 마지막 활동에서만.
  셸의 카운터와 진행 막대는 **레슨 전체 문항 기준**(앞 활동들의 문항 수를 오프셋으로 더한 `5 / 12`) — **사용자 결정**(2026-10-13, 시뮬레이터에서 학습형마다 완료 카드가
  서고 카운터가 `1 / N`으로 재시작했다). 활동은 `lesson { offset, total, last }`를 받는다. 튜토리얼(학습형 하나짜리 스텝)은 그 prop을 주지 않아 동작이 같다.

### D5. 통과 기준은 정답률 60 %(최소 1). 문항 0개 유닛은 결과 화면을 세운다

`catalogPassCriterion(n)` = `n = 0`이면 0, 아니면 `max(1, ⌈0.6 n⌉)` — **사용자 결정**(2026-10-12). 채점 문항은 건너뛰지 않은 문항이다. 레슨과 최종 테스트가 같은 함수를 쓰고,
결선(기록)과 결과 화면(표시)이 각각 부른다. 튜토리얼 기준(`learningPassCriterionForStep`)은 그대로다. 결과 화면은 튜토리얼 `LessonCompleteScreen`을 다시 쓴다(실패면 `Try again` → 첫 활동).

남은 문항이 0개면 시작 결선이 곧장 통과를 기록하고 결과(PERFECT)를 세운다 — 노드를 눌러 아무 화면도 안 서면 고장으로 읽힌다. ⚠ `CLOZE`가 들어오면서 **실데이터에서는 일어나지 않는다**
(u01 `S1`이 3문항이 됐다 — unit 테스트가 고정). 규칙은 오디오 · 3d 문항이 빠지는 데이터에 대비해 남긴다.
⟨2026-10-16 — 새 에피소드 형식⟩ **「실데이터에서는 일어나지 않는다」는 그때의 데이터에서 참이었다** — 새 형식의 문화 단계(`CULT`)는 문항 여섯이 전부 화면이 없는 유형이라 활동이 0개이고,
세 에피소드에서 이 경로가 **실데이터로 처음 일어난다**. 규칙은 바뀌지 않았다(A4의 조건 그대로 — 「적용 기록」 ⟨2026-10-16⟩).
⟨2026-10-16 — PR ②⟩ **「실데이터에서는 일어나지 않는다」가 다시 참이다** — 문화 카드 · 문화 확인이 화면을 얻어 `CULT`가 활동 둘(채점 3 · 표시 6)이 됐다. 0개 경로는 코드에 남고 합성 픽스처 테스트가 지킨다(「적용 기록」 ⟨2026-10-16 — PR ②⟩).

⟨2026-10-13 — 3d-1⟩ 단어 카드가 들어오면서 **「채점 문항」은 카드를 뺀 수**가 됐고, **「곧장 결과」의 조건은 채점 문항 0개가 아니라 활동 0개**로 좁혀졌다(「적용 기록」 A3 · A4).
⟨2026-10-16 — PR ③⟩ **분모는 이제 「판정한 채점 문항 수」다** — 런타임에 건너뛴 채점 문항(낱말 말하기의 `Skip`)은 분모에서 빠진다(`catalogJudgedCountOf` = 채점 문항 수와 결과 수 중 작은 값). 위 「채점 문항은 건너뛰지 않은 문항이다」는 **매핑 때의 건너뜀**만 말하던 문면이다. 결과 route의 `questionCount`도 이 분모를 싣는다(「적용 기록」 ⟨2026-10-16 — PR ③⟩).

### D6. 타자 입력 — 새 활동 `TypingActivity`

`screens/typing/`. 학습 껍데기 위에 단서 카드와 답 칸이, 작업 영역에 메신저 자판(`MessengerKeyboard`)이 선다. 종류 셋은 데이터가 정한다 —
`dictation`(단서 = 로마자, 보조 = 영어 뜻) · `translation`(영어 문장) · `pattern`(영어 문장 + 패턴 안내). 한 번 답하고 정답을 공개한 뒤 `Next`(건너뛰기 없음).
⟨2026-10-19⟩ **위 「작업 영역에 메신저 자판」은 그때의 상태다** — 자판은 껍데기 밖 화면 바닥에 서고 `Check`는 그 위다(「적용 기록」 ⟨2026-10-19⟩ · [ADR-0070](0070-keyboard-dock.md) D4).

- 채점은 **메신저와 같은 정규화**(공백 · 문장 부호 무시, NFC) + 정답 목록 중 하나 — **사용자 결정**(2026-10-12). 정답에 한글 밖 글자가 남으면 자판으로 칠 수 없어 건너뛴다(`untypeable`).
- **`LearningForm`은 넓히지 않는다.** 껍데기 어휘만 `LearningActivityForm = LearningForm | "typing"`. `LearningForm`에 더하면 튜토리얼의 망라 switch · 스텝 기준 표 · 테스트가 없는 route를 요구한다.
- 순수 자판 모듈은 `lib/hangul-keyboard.ts`로 승격했다(메신저 · 타자 · 최종 테스트 · 계획 넷이 쓴다). 옛 경로는 재수출 한 줄이다.

### D7. 대화 순서(`TURN_ORDER`)는 화자를 번갈아 말풍선으로 조립한다

정답 순서의 칸 i는 **짝수 = 상대(왼쪽 회색 말풍선) · 홀수 = 나(오른쪽 주황 말풍선)**다. 빈 칸은 화자 쪽 자리표시 말풍선이고, 타일을 누르면 다음 빈 칸에 그 화자 모양으로 들어간다
(놓은 말풍선을 누르면 되돌림 — 문장 순서 규칙 그대로). 채점은 기존(순서 일치). 지시문 말풍선은 없다 — **사용자 결정**(2026-10-13, 시뮬레이터에서 상대 말풍선에 지시문이 들어갔다).
`SentenceOrderDialogue`가 그리고 문항의 `dialogue: true`가 가른다(튜토리얼 표에는 없다).
⚠ **번갈아는 앱의 가정이다** — 콘텐츠에 턴별 화자가 없다(계약 문서 Q25). 정답 순서 자체가 흐름과 어긋나 보이는 문항 셋은 Q26으로 물었고 앱은 데이터대로 채점한다.
⟨2026-10-16 — 새 에피소드 형식⟩ **이 문단의 「짝수 = 상대 · 홀수 = 나」는 [ADR-0065](0065-episode-format-additions.md) D9가 부분 대체했다** — 콘텐츠가 턴 화자(`tiles[].speaker`)를 싣게 됐고,
칸의 화자는 그 값이다(문항 prop `dialogue: { speakers }`). 짝 · 홀은 **화자가 없는 데이터의 기본값**으로만 남는다. 말풍선 두 모양 · 조작 · 채점 · 지시문 말풍선 없음은 그대로다.

### D8. 최종 테스트 문항(`ROLEPLAY_TURN`)의 디코드는 엄격하다

불투명 `raw`를 걷고 일반 문항 모양(`prompt` · `context` · `stimulus` · `tiles` · `answers` · `feedback` · `roleplay { line_id, tiles_gloss }`)으로 검사한다.
`roleplay`의 나머지 키는 읽지 않는다(계약 문서 Q2 제안 — 정답의 정본은 `answers`). 모양이 어긋나면 그 에피소드가 `decode-failed`로 잠긴다(구획 캡션 `NOT AVAILABLE`).
느슨하게 받으면 망가진 RP가 「턴 0개 = 즉시 통과」로 새어 최종 테스트를 건너뛸 수 있다.

### D9. 최종 테스트는 새 화면이고 부품을 다시 쓴다

`screens/catalog-final/CatalogFinalScreen` — 전체 화면, 밝은 상태바 아이콘. 장면 그림 위에 상대 대사 상자(화자 = 에피소드 `counterpart`, 즉시 표시) ·
내 대답 줄(문장 순서 칩을 놓는다) · 뜻 힌트 · 판정 + 오답이면 정답 공개 · `Check` / `Next` / `See results`.
장면 그림은 턴의 그림이 있으면 그것, 없으면 **표지 컷 중 그림이 있는 마지막 컷**이다 — **사용자 결정**(2026-10-12, 콘텐츠 RP에 그림이 없다).
튜토리얼 최종 테스트(`EpisodeFinalScreen`)에 타일 종류를 더하는 안은 버렸다 — 그 화면의 ui 테스트가 흔들린다.
⟨2026-10-20⟩ 상대 대사 상자와 답안 판은 어두운 반투명 면이다 — 판 안 부품은 어두운 면 변형을 쓴다(「적용 기록」 ⟨2026-10-20⟩).

### D10. 통과 뒤 컷은 최종 테스트 결과 뒤에 붙는다 — 맵에 노드를 더하지 않는다

[ADR-0024](0024-journey-units-and-special-unit-placement.md) D10(첫 자리 표지 · 마지막 자리 최종 테스트)의 **확장**이다. 콘텐츠의 `post_cuts`는 맵의 자리가 아니라
**최종 테스트 결과 화면의 나가기 뒤**에 선다 — 통과일 때만, `CatalogCoverScreen`을 `stage="epilogue"`로 다시 써서(다른 점은 마지막 버튼 낭독 `Finish episode` 하나).
끝 · 나가기 모두 맵으로 간다. **기록 시점은 판정 순간**이다 — 통과 뒤 컷을 중간에 나가도 다음 에피소드 표지가 열린다. 튜플에 넷째 자리를 더하는 안(계약 문서 §12 표의 다른 갈래)은
에피소드의 최소 길이 · 맵 노드 수 · 진행 분모를 함께 바꿔 버렸다.
⟨2026-10-14⟩ 「끝 · 나가기 모두 맵으로」의 **끝**에 배너가 낀다 — 마지막 버튼 뒤 「Episode clear!」 배너가 서고 그 닫힘이 맵으로 간다. 나가기는 배너 없이 맵이다.
기록 시점(판정 순간)은 그대로다 — 「적용 기록」 ⟨2026-10-14⟩ B3.

### D11. route 넷 — 튜토리얼 route는 그대로

`catalog-lesson`(episodeId · unitKey · activityIndex) · `catalog-final`(episodeId) · `catalog-unit-complete`(results · skippedCount · questionCount — 레슨 · RP 공용, 역할은 결선이 파생) ·
`catalog-epilogue`(episodeId). 렌더는 `app/render-catalog.tsx`가 진다. 모델이 없으면(가드와 D12가 막으므로 결함) 던져 에러 경계가 받는다.
`catalog-final` · `catalog-epilogue`는 전체 화면이다. 학습 route에 판별 union을 넣는 안은 튜토리얼 route를 만드는 테스트 · 결선을 모두 바꿔 버렸다.
⟨2026-10-14⟩ 표지 화면과 배너가 들어왔지만 **route는 늘지 않았다** — `catalog-cover` · `catalog-epilogue` 안의 걸음이다(「적용 기록」 ⟨2026-10-14⟩ B1).

### D12. 실행 안에서 ready 항목을 고정한다 — 계획은 그 참조로 메모한다

`mergeCatalogForSession`은 **이전에 ready였던 항목을 새 버전으로도 갈지 않는다.** 3b-2의 「같은 실행 안에서 열려 있던 것을 닫지 않는다」를 「바꾸지도 않는다」로 넓혔다
([ADR-0056](0056-episode-content-delivery.md) 적용 기록 ⟨2026-10-13⟩). 레슨 도중 새 버전이 들어오면 `activityIndex`가 다른 계획을 가리켜 결과와 기준이 어긋나기 때문이다.
대가는 서버 수정본이 **다음 실행**부터 보인다는 것이다(캐시에는 바로 저장된다). 수업 계획 · 최종 계획은 ready 항목 참조로 메모한다 — 렌더마다 같은 문항 참조가 나와야
활동 화면의 자동 넘김이 관계없는 리렌더로 되돌지 않는다. 3d가 프로필을 내리면 메모 키에 프로필을 더한다.

### D13. 그림 실패는 이전 층을 걷고 단색 바탕을 보인다

`NarrativeBackground`(튜토리얼과 공유)에 `binderror` — 실패하면 이전 그림 층을 걷고 현재 층은 투명으로 남아 호출자의 단색 바탕(`gray-950`)이 보인다. 루트에 `data-load-state`
(`loading` | `loaded` | `failed`). 튜토리얼 그림은 번들 자산이라 실패하지 않고, 실패가 아닌 동안 식 · 클래스 · DOM은 그대로다(기존 ui 테스트 무수정 green).
표지 컷 · 통과 뒤 컷 · 최종 테스트 장면이 이 한 곳으로 같은 처리를 얻는다. ⚠ Lynx iOS에서 404가 `binderror`를 쏘는지는 **기기에서 보지 못했다**.

### D14. 화면 폴더 사이 값 import 예외 셋

재사용 부품 셋을 **제자리에서 값 import**한다 — `NarrativeBackground`(→ `catalog-cover` · `catalog-final`) · `SentenceOrderChip`(→ `catalog-final`) · `MessengerKeyboard`(→ `typing`).
옮기면 그 파일의 경로를 읽는 튜토리얼 테스트와 도구 허용 목록이 바뀐다. 예외 표와 정리 조건은 [코드 관례](../conventions/code.md) 「import」가 진다.
⟨2026-10-14⟩ 예외는 **셋 그대로**다 — 화면 폴더 둘(`episode-intro` · `catalog-cover`)의 화면을 잇는 흐름 컴포넌트는 `app/`에 뒀다(「적용 기록」 ⟨2026-10-14⟩ B2).

### 측정

새 sink 없이 `episodeIntroEventSink`로 이벤트 셋 — `episode_lesson_started` · `episode_lesson_finished` · `episode_final_passed`. 발생 조건 · 속성 · 한계는
[ADR-0029](0029-product-analytics-posthog.md) D14 적용 기록 ⟨2026-10-13⟩이 진다. ⟨3d-1⟩ 시작 이벤트에 속성 하나가 더해졌다(「적용 기록」 A7).
⟨2026-10-16 — PR ③⟩ 끝 이벤트에 속성 하나(`skippedCount` — 런타임 건너뜀 수)가 더해졌다(「적용 기록」 ⟨2026-10-16 — PR ③⟩).

## 버린 대안

1. **화면 props를 `questions`로 바꾸고 렌더 층이 표를 넘김**(지침 문면) — 튜토리얼 ui 테스트와 `onFinish` 단언이 동작 변화 없이 바뀐다(D1).
2. **`LearningForm`에 `"typing"`** — 튜토리얼 망라 switch가 없는 route를 요구한다(D6).
3. **학습형별 안정 정렬**(유닛당 최대 넷) — 콘텐츠 순서를 바꾼다. 사용자가 콘텐츠 순서를 골랐다(D4).
4. **소리 없는 듣기를 대본 + 꺼진 재생으로 세움** — 처음 계약이었다. 대본과 보기가 같아 베끼기가 됐다(D3).
5. **RP를 느슨하게 받고 앱에서 거름** — 망가진 RP가 즉시 통과로 샌다(D8).
6. **통과 뒤 컷을 맵의 넷째 자리로** — 노드 수 · 분모 · 최소 길이가 함께 바뀐다(D10).
7. **부품 셋을 `components/`로 승격** — 경로를 읽는 튜토리얼 테스트 · 허용 목록을 고친다(D14). 후속 정리로 넘긴다.
8. **새 `catalogLearningEventSink`** — sink 목록을 펼치는 테스트 · 진입점 · App props가 바뀐다(측정).

**사용자 결정**(2026-10-13)은 넷이다 — 그림 주소가 없는 그림 문항은 건너뛴다 · 단어 카드는 한 장씩 `Next`로 넘기고 채점하지 않되 카운터에는 센다(⟨2026-10-19⟩ 「카운터에는 센다」 · `Next`는 [ADR-0073](0073-new-word-cards.md)이 뒤집었다) ·

#### A1. 새 활동은 둘이다 — 그림 고르기는 단어 선택의 문항 변형이다 (D1 · D6의 연장)

- **단어 카드** `VocabCardActivity`(`screens/vocab-card/`)와 **짝 맞추기** `PairMatchActivity`(`screens/pair-match/`)가 새 활동이다. props 꼴은 3c Activity 그대로이고
  학습 껍데기 위에 선다. 껍데기 어휘는 `LearningActivityForm = LearningForm | "typing" | "vocab-card" | "pair-match"`(머리 라벨 `New words` · `Matching`) —
  **`LearningForm`은 이번에도 넓히지 않았다**(D6과 같은 이유).
- **그림 고르기는 활동을 따로 두지 않는다.** 단어 선택 문항에 선택 필드 `picture`가 붙은 것이고 `WordChoiceActivity`가 그린다. 콘텐츠에서 빈칸 채우기와 번갈아 나오므로
  (u01 `S1`: 빈칸 · 그림 · 빈칸 · 그림 · 빈칸) 활동을 가르면 그 다섯 문항이 화면 다섯으로 갈려 D4(학습형 사이를 끊김 없이)와 반대로 간다. 같은 활동이면 화면 하나다.
  갈림은 boolean prop이 아니라 **문항 데이터**에 있고, 그림 쪽 상태와 표현은 조각 `WordChoicePicture` · 훅 `useWordChoicePicture` · 순수 모듈 `word-choice-picture.ts`가 진다.
  `picture`가 없는 문항(튜토리얼 전부)의 동작은 그대로다 — 보기 컨테이너에 `data-interaction="enabled"` 속성 하나가 더해졌을 뿐이다.
- 버린 것: `ImageChoiceActivity`를 따로 두는 안(위의 화면 갈림) · 카드를 다음 활동의 머리말로 두는 안(카드가 레슨 끝에 오거나 카드뿐인 유닛에서 설 자리가 없다).

#### A2. 매핑 — 건너뜀 사유 하나를 지우고 둘을 더했다 (D2의 연장)

| 콘텐츠 `type` | 학습형                  | 읽는 것 · 건너뛰는 조건                                                                                                                                                                                                                                                              |
| ------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `VOCAB_CARD`  | 단어 카드               | 표제어 = `context`, **뜻 = 에피소드 `words[]`에서 `ref`로 찾은 `gloss_en`**(없으면 `context.en`), 예문 = `example`. 뜻이 어디에도 없으면 **`no-gloss`**. 예문이 비었거나 표제어와 같으면 예문 상자 없이 선다(건너뛰지 않는다). 표제어가 비면 `malformed`                             |
| `PAIR_MATCH`  | 짝 맞추기               | 디코더가 정답 문자열에서 푼 `pairs`가 정본이다(낱말 = 왼쪽, 뜻 = 오른쪽). **`tiles_gloss_en`은 읽지 않는다.** 짝이 둘 미만 · 짝 수 ≠ 타일 수 · 빈 낱말이나 뜻 · 같은 낱말 둘이면 `malformed`                                                                                       |
| `IMG_MATCH`   | 단어 선택(그림 — A6)    | 그림 = `stimulus.image_url`(버킷 기준 상대 경로), 보기 = `options`. **그림 주소가 비었거나 풀 수 없으면 `image-missing`** — **사용자 결정**(오디오 없는 듣기와 같은 규칙). 그림을 대신할 영어 뜻(정답 보기의 `en`, 없으면 `words[]`의 뜻)이 없으면 `no-gloss`. 검사 순서는 모양 → 그림 → 뜻 |

- 건너뜀 사유는 **일곱**이 됐다 — `no-options` · `no-source` · `audio-missing` · `image-missing` · `no-gloss` · `untypeable` · `malformed`.
  **`screen-pending`은 타입에서 지웠다** — 내는 자리가 없어졌고, 남기면 「아직 화면이 없는 유형이 있다」는 거짓 어휘가 된다.
  ⟨2026-10-16 — 새 에피소드 형식⟩ **되살렸다** — 새 형식에 화면이 없는 유형 여섯이 생겨 「아직 화면이 없는 유형이 있다」가 다시 참이 됐다. 사유는 여덟이다([ADR-0065](0065-episode-format-additions.md) D8).
- **지금 데이터에서 그림 문항은 하나도 서지 않는다** [데이터]. 세 에피소드의 `IMG_MATCH` 10문항은 그림 주소가 전부 빈 값이라 모두 `image-missing`이다.
  그림이 채워지면 매핑 규칙을 바꾸지 않고 선다. 단어 카드 28장과 짝 맞추기 2문항은 전부 선다.

  그림 주소는 3c 최종 테스트 모델과 같은 길(`imageUrlOf`를 인자로 내림)이라 `catalogLessonPlanOf`가 넷째 인자를 받는다. 디코더 · 스키마 · 도메인 모델은 바뀌지 않았다.
  D12의 메모 키는 그대로다 — `imageUrlOf`는 실행 안에서 설정이 정하는 상수 함수라 키에 넣지 않는다.
- 낱말 열은 콘텐츠 순서 그대로이고 **뜻 열만** D2의 결정적 섞기로 섞는다. 화면에 서는 문자열은 뜻(`gloss_en`)까지 전부 `{이름}` · `{나라}` 치환을 지난다.

#### A3. 채점 수와 표시 수를 가른다 (D5의 연장)

단어 카드는 채점하지 않는다 — 결과를 올리지 않고(`onFinish([], 0)`) 판정 배지 · 판정음도 없다. 그래서 수업 계획의 수가 둘이 됐다.

| 값               | 뜻                                              | 쓰는 곳                                                         |
| ---------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| `questionCount`  | **채점 문항 수**(단어 카드를 세지 않는다)       | 통과 기준 · 측정 이벤트 · 결과 route의 분모 — 3c의 뜻 그대로    |
| `shownItemCount` | **표시 문항 수**(채점 문항 + 단어 카드) — 새 값 | 껍데기 카운터와 진행 막대의 분모, 활동 오프셋(D4의 `5 / 12`)    |

- 불변식: `shownItemCount + 건너뛴 문항 수` = 유닛의 문항 수, `questionCount ≤ shownItemCount`, 카드 수 = 둘의 차.
- 어느 활동이 채점되는지는 표 `catalogActivityScoring`이 진다(`vocab-card`만 `ungraded`) — 새 학습형이 생기면 타입 검사가 답을 강제한다.
- **통과 기준 함수 `catalogPassCriterion`은 바뀌지 않았다.** 채점 문항이 셋이면 카드가 몇 장이든 기준은 2다. D5의 「채점 문항은 건너뛰지 않은 문항이다」는 이제
  「건너뛰지 않은 문항 가운데 단어 카드가 아닌 것」으로 읽는다.
- **카운터는 카드를 센다 — 사용자 결정.** u01 `S1`은 `1 / 6`에서 시작해 카드 셋이 1 ~ 3, 단어 선택 셋이 4 ~ 6이다(그림 문항 둘은 건너뜀).
  ⟨2026-10-19 — 정정⟩ **뒤집혔다 — 카드는 카운터에 세지 않는다(사용자 결정, [ADR-0073](0073-new-word-cards.md) D1).** 위 표의 「`shownItemCount` — 껍데기 카운터와 진행 막대의 분모」도
  그때의 상태다: 분모 · 오프셋은 이제 카드를 뺀 수이고(`catalogCountsInLessonCounter`), `shownItemCount`는 분석 · 맵 말풍선의 수로만 남았다. 이 문서 끝의 적용 기록 ⟨2026-10-19⟩.
- **단어 카드 활동에는 완료 카드(`All questions done`)가 없다.** 풀어낸 문항이 없기 때문이다. 마지막 카드의 버튼이 곧 다음 걸음이다 — 레슨 중간이면 `Next`(다음 활동으로),
  레슨의 끝이면 `See results`. ⟨2026-10-19 — 정정⟩ 버튼은 이제 어느 카드에서나 `Got it` 하나다([ADR-0073](0073-new-word-cards.md) D3). 완료 카드가 없는 것은 그대로다.

#### A4. 「곧장 결과」의 조건은 활동 0개다 (D5의 둘째 문단을 좁힌다)

D5는 「남은 문항이 0개면 시작 결선이 곧장 통과를 기록하고 결과를 세운다」였고 구현의 조건은 `questionCount === 0`이었다. 그 조건을 **`activities.length === 0`**(= 표시 문항 0)으로 바꿨다.
`questionCount === 0`으로 두면 **카드뿐인 유닛이 카드를 한 장도 보이지 않고 통과한다.** 지금은 카드뿐인 유닛도 화면이 서고, 끝까지 넘기면 기준 0으로 통과해 기록된다.

- 카드뿐인 유닛의 결과 화면 제목은 **지금 규칙 그대로 `PERFECT LESSON!`이다 — 사용자 결정**(건드리지 않는다). 디자인은 `LESSON COMPLETE!`를 원했으나 결과 화면이 튜토리얼 공용이다.
  실데이터에 그런 유닛은 없다.

#### A5. 짝 맞추기 — 다 잇고 `Check` 한 번

- 순수 리듀서 하나(`screens/pair-match/pair-match.ts`). 낱말(왼쪽 열) · 뜻(오른쪽 열) **어느 쪽을 먼저 눌러도** 되고, 양쪽이 하나씩 골라지면 짝이 맺힌다.
  짝은 **비어 있는 가장 작은 번호**를 받아 양쪽 타일에 같은 번호가 선다(색에만 기대지 않는다). 맺힌 타일을 누르면 그 짝만 풀리고, 골라 둔 반대쪽 선택은 남는다.
- **맺는 순간에는 맞고 틀림을 말하지 않는다 — 사용자 결정.** 전부 맺혀야 `Check`가 서고, 한 번에 문항 전체를 판정한다 — **한 문항 = 채점 1건**. 맺는 즉시 틀림을 알리면
  소거법으로 전부 맞게 돼 채점이 뜻을 잃는다.
- 판정은 인덱스가 아니라 **뜻 글자**로 한다 — 같은 뜻이 둘 있는 문항에서 어느 쪽에 이어도 정답이다.
- 확인 뒤: 타일은 잠기고(`disabled` — 문장 순서 칩 선례), 맺힌 타일마다 그 짝의 정오가 서며, 오답이면 **틀린 짝의 정답만** 공개한다. `Next`로 넘긴다(자동 넘김 · 건너뛰기 · 다시 하기 없음).
- 지시문은 문구표 하나(`Tap a word, then its meaning.`)다 — 콘텐츠의 `prompt.en`은 쓰지 않는다(조작법을 말하는 문장을 골랐다).

#### A6. 그림 제시 — 로드 실패는 뜻 글자로 대신한다 (D13 옆)

D13은 **장면 그림**(표지 컷 · 통과 뒤 컷 · 최종 테스트)의 실패를 단색 바탕으로 처리한다. 그림 문항은 그림이 곧 문제라 그 처리를 쓸 수 없다.

- 문항이 서면 로드 상태가 `loading`에서 시작해 그림의 `bindload`면 `loaded`, `binderror` **또는 6초 안에 끝나지 않으면** `failed`가 된다. 두 끝 상태는 되살리지 않는다.
  시간 제한을 두는 이유는 D13의 ⚠와 같다 — Lynx iOS가 실패에 `binderror`를 쏘는지 기기에서 본 적이 없다. 이벤트가 영영 안 와도 타이머가 로딩을 끝낸다.
- `loading` 동안 **보기는 서 있되 탭을 받지 않는다**(흐리게) — 근거 없이 찍지 않게 한다. 보기의 trait은 `button` 그대로다
  ([ADR-0016](0016-assistive-technology-semantics.md) D10 — `disabled`는 영구 불가에만. 그래서 `WordChoiceOption`이 무수정이다).
- `failed`면 그림 자리에 **정답 낱말의 영어 뜻**과 `Picture unavailable`이 서고 보기가 열린다. 문항 수 · 통과 기준 · 이벤트 속성이 계획과 어긋나지 않는다.
- 답한 뒤에는 그림 아래에 이름표(정답의 한글 · 로마자 · 뜻)가 선다.
- 그림 틀은 접근성 요소 하나(trait `image`)이고 이름이 상태를 따른다 — `Picture, loading` · `Picture: water` · `Picture unavailable. Meaning: water`.
  **이름은 영어 뜻만이다**(한글 · 로마자를 넣으면 정답을 흘린다). 콘텐츠의 `image_brief`는 생성 지시문이 섞여 쓰지 않는다(콘텐츠 계약 Q23).
- 버린 것: 실패한 문항을 그 자리에서 건너뛰기(실행 중에 채점 문항 수가 줄어 계획의 `questionCount`와 어긋난다) · 대체 없이 보기만 두기(찍기가 된다) ·
  타이머 없이 로드를 기다리기(이벤트가 안 오면 정말로 막힌다).
- ⚠ **이 절은 기기에서 한 번도 돌지 않았다** — 실데이터에 그림이 없다(A2). ui · integration 테스트(픽스처)로만 참이다.

#### A7. 측정 — 속성 하나

`episode_lesson_started`에 `shownItemCount`가 더해졌고 `questionCount`는 채점 문항 수로 뜻을 유지한다. 새 이벤트는 없다 —
[ADR-0029](0029-product-analytics-posthog.md) D14 적용 기록 ⟨2026-10-13 — 3d-1⟩이 진다.

#### 구현 판단

1. **짝 타일의 「맺힘」 상태 클래스는 `-linked`다.** 예약 상태어에 없던 낱말이라 [ADR-0003](0003-workspace-and-directory-structure.md) D7의 표에 행을 더했다(그 문서의 정정 기록 2026-10-13).
2. **단어 카드의 `New word` 표식은 판정 라벨 컴포넌트가 아니라 글자다.** `AnswerLabel`은 `data-result`를 내는데, 카드 화면에는 판정이 없어야 한다.
3. **`WordChoiceActivity`는 결과를 한 번만 올린다.** 레슨 중간 활동에서 마지막 문항의 자동 넘김이 두 번 돌면 결과가 두 번 쌓인다 — 한 번으로 막았다.
4. **단어 선택 보기 칩의 좌우 여백 토큰을 고쳤다 — 사용자 결정.** `word-choice-option.css`가 정의되지 않은 이름 `--libitum-spacing-14`를 써서 여백이 0이었고, `--libitum-spacing-12`로 바꿨다.
   **튜토리얼 낱말 고르기 칩의 폭도 함께 바뀐다.** `lint:tokens`가 이것을 통과시킨 이유(접두사만 검사한다)는 ADR README 보류 표가 진다.
   카탈로그 문항의 지원 줄(로마자 · 번역) 클래스 `.word-choice-screen-support`에 규칙이 없던 것도 채웠다.

#### 대가

1. **번들 +58,702 bytes**(1,793,164 → 1,851,866, +3.3 %) [실측]. 계약 예측(+18 ~ 30 kB)의 두 배다 — 항목별로 쪼개 재지 않았다. 상한은 1,794,000 → 1,852,000으로 올렸고
   (**사용자 사전 승인**) 여유는 134 bytes다 — [성능 보고서](../performance/reports/episode-catalog-items-iphone-17-pro-simulator-01.md). 위 「대가」 1의 수치는 3c 시점의 것이다.
2. **그림 문항의 코드 전부가 실데이터에서 닿지 않는 채 번들에 있다**(A2 · A6) — 「대가」 9와 같은 부류다.
3. **짝 맞추기 낱말 타일 · 그림 문항의 보기에 로마자가 없다.** 한글을 못 읽는 초급자에게 어렵다(3c의 칩 · 보기와 같은 부채 — 그림 문항은 답한 뒤 이름표가 로마자를 보인다).
4. **「봉투」의 뜻이 두 자리에서 다르다** [데이터]. 카드는 `envelope`(`words[]`), 그림 문항의 대체 글자 · 이름표는 `bag`(보기의 `en`)이다. 앱은 데이터 그대로 보인다 — 콘텐츠 계약 Q27.
5. **단어 선택에는 채점 순간의 능동 낭독이 없고 그림 문항도 같다.** 더하면 단어 선택 전체(튜토리얼 문항 포함)의 낭독 규칙이 바뀐다 — 따로 묶는다.

### ⟨2026-10-13 — 3d-2⟩ 학습자 프로필이 계획에 들어온다

적용 기록이고 **위 결정 문장을 뒤집지 않는다.** 학습자 프로필(저장 · 동기화 · 묻는 자리 · 나라 표)의 결정은 [ADR-0059](0059-learner-profile.md)이 진다.
여기에는 이 문서의 결정이 그 결과로 바뀐 자리만 적는다.

- **D2의 「프로필은 3d 전까지 기본값」은 3d-1까지의 상태다.** 이제 기록이 있으면 레슨 · 최종 테스트 · 표지 · 통과 뒤 컷의 문자열에 이름과 나라가 선다.
  영어 출처(`.en` · 뜻 · 지시문)는 새 스크립트 `"en"`으로 치환한다 — 나라가 영어 이름으로 선다([ADR-0056](0056-episode-content-delivery.md) ⟨3d-2⟩ 기록).
  매핑 모듈에 영어 출처를 읽는 도우미 `englishOf`가 더해졌다(`latinOf`의 `"en"`판).
- **D12의 「3d가 프로필을 내리면 메모 키에 프로필을 더한다」가 실체화됐다.** `catalogLessonPlanFor` · `catalogFinalPlanFor`가 넷째 인자 `profile`을 **필수로** 받고,
  메모 키는 「ready 항목 참조 + 프로필 참조 + 유닛 키」다. 프로필 참조는 값이 바뀔 때만 새로 서고 기록이 없으면 늘 `noLearnerProfile` 그 참조라,
  프로필 없는 실행의 메모 동작은 3d-1과 같다(ADR-0059 D9). 기존 테스트의 호출에는 `noLearnerProfile`이 붙었고 단언은 그대로다.
- **레슨 도중 프로필이 바뀌는 길이 하나 남는다** — 부팅 직후 내려받기가 늦게 끝났고 서버 값이 캐시와 달랐을 때. 그때 렌더가 새 계획을 본다(문항 글자가 바뀐다).
  D12가 막는 「활동 번호가 다른 계획을 가리키는」 위험과는 다르다 — 콘텐츠 버전은 고정이고 바뀌는 것은 치환 값이다. 받아들인다.
- **표지 · 유닛 시작 앞에 묻는 화면이 하나 선다**(route `learner-profile-gate`, 여정 스택). 표지 · 학습 결선을 합치는 `catalog-wiring.ts`가 두 시작 함수를 같은 이름으로 감싸고,
  원래 시작 가드(D11의 잠금)를 지난 뒤에만 묻는다. 저장 · 건너뜀 뒤에는 새 프로필로 다시 만든 원래 시작 함수를 부른다(ADR-0059 D7). route 넷(D11)은 그대로다.
  ⟨2026-10-20⟩ **이 묻는 화면은 걷혔다** — 이름 · 나라는 가입 직후 화면이 묻고(ADR-0059 D7 적용 기록), `catalog-wiring.ts`는 표지 · 학습 결선을 합치기만 한다.
- **[데이터] 이름이 서는 곳은 u02 · u03의 최종 테스트뿐이다.** 레슨 문항의 같은 대사는 고정 이름 「은지」라 레슨 화면에서는 학습자 이름이 보이지 않는다 —
  [콘텐츠 계약](../specs/episode-content-json-contract.md) Q31. 기기에서는 이 경로를 아직 보지 못했다([학습자 프로필 e2e](../e2e/learner-profile.md)).

### ⟨2026-10-14⟩ 표지 화면 · 「Episode start!」 · 「Episode clear!」 배너

적용 기록이고 **위 결정 문장을 뒤집지 않는다.** 카탈로그 에피소드의 표지 유닛이 컷을 곧장 세우던 것을 「표지 화면 → 컷 → 배너」로 바꾸고, 통과 뒤 컷의 끝에도 같은 배너를 세웠다 —
route · 진행 저장 형식 · 이벤트 이름은 그대로라 새 ADR을 만들지 않았다. 위 본문에서 이 기록이 덧붙인 자리는 D10(통과 뒤 컷의 끝) · D11(route 넷 — 그대로) · D14(값 import 예외 — 그대로)다.
본문은 3c 시점의 기록으로 남기고 그 자리마다 이 절을 가리키는 표시만 달았다. 목적은 둘이다 — 표지에서 「볼지 · 건너뛸지」를 고르게 해 **건너뛰기 비율을 재고**
([ADR-0029](0029-product-analytics-posthog.md) D14 적용 기록 ⟨2026-10-14⟩), 컷을 끝까지 본 순간을 짧게 축하한다.
튜토리얼(Episode 0)의 표지와 그 뒤 흐름은 바꾸지 않았다 — 튜토리얼 표지 테스트는 한 줄도 바뀌지 않고 통과한다.

- ⚠ **기기 확인은 일부다** [실기]. iOS 시뮬레이터에서 표지 화면 · `Next` → 컷 · 「Episode start!」 배너의 자동 닫힘 · `Skip` 확인 모달을 봤다.
  **배너를 눌러 바로 닫기 · 「Episode clear!」 · 동작 줄이기 · 등장 모션의 체감 · VoiceOver · Android · 표지에서 뒤로 · PostHog 수신은 보지 못했다** — 아래 「미확인 · 후속」 1.

#### B1. route를 늘리지 않는다 — 한 route 안의 걸음 (D11의 연장)

`catalog-cover` route 하나 안에서 표지 화면 → 컷 → 배너, `catalog-epilogue` route 하나 안에서 컷 → 배너가 **걸음**으로 선다. 걸음은 넷이다 — `intro` · `cuts` · `banner` · `left`(화면이 없는 끝 걸음).

- 닿는 면이 좁다 — route를 가르면 탐색 상태 · 화면 렌더 분기 · 전체 화면 목록 · 상태바 등록부의 route 목록이 함께 바뀐다. 걸음이면 새 route 0이다.
- 선례가 있다 — 튜토리얼의 서사 구간(`app/EpisodePrologueScreen.tsx`)이 통화 → 메신저 → 비주얼 노벨을 한 route 안에서 잇는다.
- 배너는 스택에 남을 자리가 아니다 — 1.6초짜리 이행이라 「뒤로 가면 무엇이 나오는가」의 답이 없다.
- 뒤로의 뜻이 그대로다 — 표지 화면 · 컷 어느 걸음에서 나가도 `back` 하나로 맵이다(컷에서 뒤로 가면 표지 화면이 아니라 맵).

버린 대안: route 셋으로 가르기(위 첫 줄), 배너를 컷 화면 안의 겹침 층으로 두기(컷 화면이 표지 컷인지 통과 뒤 컷인지를 알아야 하고 고립 테스트 단위가 커진다).

#### B2. 흐름 컴포넌트는 명시적 변형 둘이고, 걸음 전이는 순수 함수 하나가 진다

`app/CatalogCutsFlow.tsx`가 `CatalogCoverFlow`(표지 화면 → 컷 → 「Episode start!」)와 `CatalogEpilogueFlow`(컷 → 「Episode clear!」)를 내보낸다. 「표지가 있는가」 「끝에 기록이 있는가」를
모드 prop 조합으로 숨기지 않으려고 갈랐다 — 각 변형은 자기가 쓰는 콜백만 받는다. 위치가 `app/`인 것은 화면 폴더 둘의 화면을 잇는 자리라 어느 한 화면 폴더에 둘 수 없어서다(D14의 예외를 늘리지 않는다).

걸음 전이는 `app/catalog-cuts-flow.ts`의 `nextCatalogCutsFlowStep(step, event)`가 진다. 표에 없는 짝은 **제자리**다.

| 걸음 \ 사건 | `continue` | `skip` | `exit` | `cuts-done` | `banner-done` |
|---|---|---|---|---|---|
| `intro` | `cuts` | `left` | `left` | — | — |
| `cuts` | — | — | `left` | `banner` | — |
| `banner` | — | — | — | — | `left` |
| `left` | — | — | — | — | — |

흐름 컴포넌트는 **걸음이 바뀔 때만** 그 사건의 콜백을 부른다. 그래서 `Next` 연타는 이어 가기 한 번, 확인 모달의 건너뛰기 연타는 건너뛰기 한 번이고, 나간 뒤 늦게 온 사건은 무시된다 —
연타를 막는 근거가 이 함수 하나다. `left`에서는 직전 걸음의 화면을 그대로 둔다(결선의 `back`이 다음 렌더에서 route를 걷으므로 빈 프레임이 생기지 않는다).

#### B3. 결선 — 이벤트 → 기록 → 이동, 완료와 닫힘을 가른다 (D10의 연장)

완료 이벤트 · 기록 · 이동을 한꺼번에 하던 `onCompleteCatalogCover`를 **없앴다.** 배너 때문에 「기록」과 「이동」 사이에 시간이 생겼고, 남겨 두면 배너를 거치지 않고 이동하는 길이 타입에 남는다.

| 함수 | 부르는 자리 | 하는 일(순서) | 이벤트 |
|---|---|---|---|
| `onStartCatalogCover` | 맵의 표지 노드(가드 뒤) | **불변** — 시작 가드 → 이벤트 → 컷이 있으면 `catalog-cover`를 쌓는다 | `episode_intro_viewed` |
| `onExitCatalogCover(episodeId, stage)` | 표지 화면의 뒤로(`"intro"`) · 컷의 나가기(`"prologue"`) | 이벤트 → `back`. 기록 없음 | `episode_intro_exited` |
| `onSkipCatalogCover` | 표지 확인 모달의 건너뛰기 | 이벤트 → 진행에 `intro` 기록 → `back` | `episode_intro_skipped` |
| `onContinueCatalogCover` | 표지 화면의 `Next` | 이벤트만(컷으로 넘기는 것은 흐름 컴포넌트) | `episode_intro_continued` |
| `onFinishCatalogCoverCuts` | 마지막 컷의 버튼 | 이벤트 → 진행에 `intro` 기록. **이동 없음** | `episode_prologue_completed` |
| `onCloseCatalogCover` | 「Episode start!」 배너의 닫힘 | `back`만 | — |
| `onLeaveCatalogEpilogue` | 통과 뒤 컷의 나가기 · 「Episode clear!」 배너의 닫힘 | **불변** — 스택 루트(맵)로 | — |

- **진행 기록은 배너가 서기 전이다.** 배너 도중 앱이 죽어도 표지는 끝난 것으로 남는다. 배너의 닫힘은 이동만 한다.
- `onExitCatalogCover`의 `stage`는 **필수**다 — 기본값이 있으면 표지 화면에서 나간 것을 `prologue`로 세는 실수가 타입을 통과한다.
- 건너뛰기에서는 완료 이벤트(`episode_prologue_completed`)도 배너도 없다.
- 통과 뒤 컷의 결선은 그대로이고 이벤트를 더하지 않았다 — 기존 이름은 「표지」의 것이라 통과 뒤 컷에 쓰면 뜻이 틀린다.
- **바꾸지 않은 것**: 학습자 프로필 가드는 지금처럼 `onStartCatalogCover`를 감싼다 — 순서는 가드 → 표지 화면 → 컷이다. 컷이 없는 에피소드는 화면을 쌓지 않고 곧장 완료로 적는다(표지 화면도 배너도 없다 —
  실데이터 u01 ~ u03은 모두 컷이 있다).

#### B4. 배너 화면 — 데이터 prop 하나, 조작 하나, 닫힘 한 번

`screens/catalog-cover/EpisodeBannerScreen.tsx`. props는 `insets` · `kind`(`"start"` | `"clear"`) · `onDone`이다.

- **글자를 받지 않고 종류를 받는다.** 문구는 화면이 문구표에서 고른다(`catalogCover.episodeStart` = `Episode start!`, `catalogCover.episodeClear` = `Episode clear!`) — 호출자가 임의 문자열을 넘길 수 없다.
- **화면 전체가 조작 하나다.** 시간제한이 있는 화면이라(WCAG 2.2.1) 루트가 버튼이고 낭독 이름은 배너 글자 그대로다. 안쪽 글자는 따로 정지점이 되지 않는다.
- **닫힘은 한 번이다.** 닫히는 길 셋 — 유지 시간 · 탭 · 시스템 뒤로 — 이 같은 가드를 지난다. 타이머는 마운트 때 한 번 걸고, 재렌더가 유지 시간을 늘리지 않는다.
- 유지 시간은 `EPISODE_BANNER_HOLD_MS = 1600`(표준 · 동작 줄이기 공용)이다. 모션 토큰이 아니다 — 머무는 시간에 맞는 토큰이 없다. 대신 unit이 「등장이 끝난 뒤 1초 이상 남는다」를 토큰 값으로 단언한다.
- 면은 검정(`color-black`), 글자는 브랜드 주황(`color-brand-primary`) · `accent-display`다 — 대비 6.96 : 1 [계산]. 표지 화면 첫 줄(`Episode n.`)과 같은 색 · 같은 서체라 표지 → 컷 → 배너가 한 쌍으로 읽힌다.
- 등장 모션은 레슨 완료의 통과 배지와 **같은 토큰 조합**이고 동작 줄이기에서는 크기 변화 없이 불투명도만 바뀐다. 퇴장 · 눌림 표시는 없다 — 닫히면 곧 다음 화면이다.
  보상 모션의 자리가 하나에서 둘이 된 것은 [ADR-0053](0053-motion-policy.md) D4의 날짜 주 ⟨2026-10-14⟩가 진다.
- 두 route가 전체 화면이라 배너가 가장자리 여백을 스스로 받는다 — 면은 가장자리까지 깔리고 여백은 글자 자리에만 쓴다.
- 어두운 면이라 상태바 표지를 단다. Android 상태바 등록부에 컴포넌트 하나와 route별 목록 두 줄이 바뀌었다 — 표는 [화면 명세](../screens.md) 「상단 띠를 어둡게 칠하는 면은 상태바 표지를 단다」가 진다.
- 효과음 · 진동은 없다.

#### B5. 표지 화면 — 튜토리얼 표지를 다시 쓰고, 긴 이름은 띄어쓰기에서만 끊는다

표지 화면은 새 화면이 아니라 튜토리얼 표지(`EpisodeIntroScreen`)다 — 첫 줄 `Episode n.`, 둘째 줄 에피소드 이름, `Skip` · `Next`. 버튼 이름도 그대로다.

- `EpisodeIntroScreen`에 **선택 prop `titleLines`** 하나가 더해졌다. 주면 둘째 줄을 그 줄들로 나눠 그리고, 낭독 이름은 줄을 띄어쓰기로 이은 것이다(띄어쓰기에서만 끊으므로 원래 이름과 같다).
  카탈로그 표지만 맵 머리 카드와 같은 순수 함수(`catalogTitleLines`)로 줄을 정해 넘긴다. **주지 않는 튜토리얼은 렌더가 그대로다.**
  ⟨2026-10-16⟩ 맵 머리는 이제 이 함수를 쓰지 않는다(띠가 되어 나누지 않는다 — [ADR-0062](0062-progress-cache-first.md) D13). 표지 화면의 쓰임은 그대로다.
  한 줄 글자 수 상한(`CATALOG_INTRO_TITLE_MAX_CHARS = 10`)은 **잠정값**이다 — 계약 단계가 브라우저 근사 렌더로 잡았고 기기 실측으로 확정하지 않았다.
- 표지 CSS에 `flex-shrink: 0`이 둘 들어갔다(버튼 줄 · 뒤로 버튼 상자). 긴 이름이 큰 글자에서 넘칠 때 버튼이 눌리지 않게 하는 **최소 조치**다. 기본 배율의 그림은 같고 튜토리얼 표지도 같은 덕을 본다.
  넘친 이름을 스크롤로 받는 일은 하지 않았다(아래 「미확인 · 후속」 3).

#### 사용자 결정과 사용자 미확인

**사용자가 명시로 정한 것**(2026-10-13):

1. 표지 화면의 버튼 이름은 튜토리얼과 같은 `Skip` · `Next` 그대로다.
2. 배너는 컷을 **끝까지 봤을 때만** 선다 — 건너뛰기 · 나가기에서는 서지 않는다.
3. 배너는 스스로 닫히고, 그 전에 화면을 누르면 바로 닫힌다.
4. 새 에피소드(카탈로그)에만 넣는다 — 튜토리얼은 바꾸지 않는다.
5. 통과 뒤 컷의 끝에 「Episode clear!」 배너를 더한다.
6. 배너는 검은 면 위 주황 글자이고 등장 애니메이션이 있다.

번들 상한은 넘으면 실측만큼 올린다는 **사전 승인**이 있었다(아래 「대가」 1).

**사용자 미확인 — 기본값으로 진행한 것.** 기본값으로 진행한다고 알렸고 반대가 없었다. **명시 승인은 아니다.** 답이 다르면 고칠 자리를 함께 적는다.

| # | 기본값 | 답이 다르면 |
|---|---|---|
| 1 | **건너뛰기는 표지 유닛을 끝낸 것으로 기록한다** — 다음 레슨이 열리고 진행 저장이 나간다. 튜토리얼 표지의 `Skip`이 완료로 이어지는 선례를 따랐다 | `onSkipCatalogCover`에서 기록 한 줄을 뺀다 — 표지 노드는 열린 채 남고 다음 레슨은 잠긴 채다 |
| 2 | **배너 유지 1.6초** — 사용자는 「약 1.5초」를 골랐고 정확한 값은 디자인 단계가 정했다(등장 400 ms + 다 선 뒤 1,200 ms) | 상수 값 하나. 테스트는 상수를 참조한다 |
| 3 | **표지의 긴 이름을 띄어쓰기에서 줄바꿈한다**(B5의 `titleLines`) — 계약의 기본값은 「넣지 않는다」였고 계약 고정 뒤 이번 범위에 넣기로 바꿨다 | 카탈로그 표지가 `titleLines`를 넘기지 않으면 된다 |
| 4 | **가드 → 표지 화면 → 컷** 순서 — 표지에서 건너뛸 사람에게도 이름 · 나라를 먼저 묻는다 | 가드를 `Next` 뒤로 옮긴다. [ADR-0059](0059-learner-profile.md)의 가드 계약을 다시 열어야 한다 |
| 5 | **이미 끝낸 표지를 다시 끝까지 봐도 「Episode start!」가 선다** | 마지막 컷의 결선이 「이번에 새로 적었는가」를 흐름에 돌려줘야 한다 |
| 6 | 컷이 없는 에피소드에는 표지 화면을 세우지 않는다(B3) | 그런 에피소드가 생기면 건너뛰기 비율의 분모에 「건너뛸 수 없던 방문」이 섞인다 |
| 7 | 배너 서체는 `accent-display`(Jost 700) | CSS 변수 다섯의 이름만 바뀐다 |

배너 도중 시스템 뒤로가 「넘어가기」(맵으로)인 것은 요구사항의 수용 기준에 적혀 있던 것이다.

#### 대가

1. **번들 +9,150 bytes**(1,903,173 → 1,912,323, +0.48 %) [실측]. 계약 예측(+4.5 ~ 7 kB)보다 조금 컸다 — 항목별로 쪼개 재지 않았다. 상한은 1,905,000 → 1,914,000으로 올렸다(**사용자 사전 승인**) —
   [성능 보고서](../performance/reports/catalog-cover-intro-iphone-17-pro-simulator-01.md)(번들만 · 렌더링 · 메모리 미측정).
2. **걸음은 컴포넌트 상태라 재마운트되면 첫 걸음으로 돌아간다.** 흐름 도중 콘텐츠 갱신이 새 버전을 들이면 표지 화면부터 다시 선다(이전에도 컷 1로 돌아가던 같은 성질이다).
   배너가 서 있는 동안 갱신이 끼면 표지 화면이 다시 서지만 진행은 이미 적혔다. 고치지 않았다.
3. **표지 방문이 탭 하나만큼 길어졌다** — 컷을 보려면 `Next`를 한 번 더 누른다.
4. **건너뛰기가 완료를 적으므로**(위 표 1) 컷을 한 장도 보지 않고 표지 유닛이 끝난다. 표지를 다시 열 수는 있다.
5. `EpisodeIntroScreen`이 선택 prop 하나만큼 넓어졌다 — 튜토리얼 화면의 계약 파일과 소스에 diff가 생겼다(렌더와 테스트는 그대로).

#### 미확인 · 후속

1. **기기 미확인** [실기]. iPhone 17 Pro 시뮬레이터(iOS 26.5, 에피소드 셋을 통과한 계정)에서 **본 것**: 에피소드 2 표지 유닛 → 표지 화면(`Episode 2.` / 「익선 게스트하우스 / 프런트」 두 줄 — 낱말 중간 끊김 없음, `Skip` · `Next`) ·
   `Next` → 컷 1 / 5 · 마지막 컷 뒤 검은 면 주황 「Episode start!」 → 약 1.6초 안에 스스로 맵 · 다시 표지 → `Skip` → 확인 모달 → `Skip` → 배너 없이 맵.
   **보지 못한 것**: 배너를 눌러 바로 닫기 · 「Episode clear!」(최종 테스트를 다시 통과해야 닿는다) · 동작 줄이기 변형 · 등장 모션의 체감(스크린숏은 정지 화면이다) · VoiceOver · Android(상태바 아이콘 포함) ·
   표지 화면에서 뒤로 · 확인 모달의 계속 보기 · 가드 뒤 표지 화면 · 가장 긴 이름(「익선 게스트하우스 여성 도미토리」)과 큰 글자 · PostHog 실제 수신.
   절차와 회차는 [카탈로그 맵 e2e](../e2e/catalog-map.md) · [카탈로그 레슨 e2e](../e2e/catalog-lessons.md)가 진다.
2. **알려진 문제 — 표지의 건너뛰기 확인 모달 문구가 카탈로그에서는 사실과 다르다.** 모달은 튜토리얼 표지의 것을 그대로 써서 `If you skip it, this episode's story won't appear again.`이라고 말하는데, **⟨2026-10-14 같은 변경에서 고침 — 사용자 결정⟩** 카탈로그 표지의 모달은 이제 `You can watch it again anytime from the episode intro.`라고 말한다(`catalogCover.skipDescription`, 튜토리얼 문구는 그대로). 고친 문구는 기기에서 보지 않았다.
   카탈로그에서는 끝낸 표지를 맵에서 다시 열 수 있다(시뮬레이터에서 관찰). 고치려면 카탈로그용 문구 키와 `EpisodeIntroScreen`의 문구 주입이 필요하다 — 후속.
3. **알려진 문제 — 아주 큰 글자에서 표지가 넘친다.** 디자인 단계의 근사 렌더로는 iOS 접근성 크기(대략 2.3배 이상)에서 가장 긴 이름과 버튼이 한 화면에 들어가지 않는다 [추론 — 기기에서 재지 않았다].
   이번에는 `flex-shrink: 0`만 넣어 버튼이 눌리지 않게 했고, 넘친 이름을 받는 **스크롤 영역은 후속**이다(화면 구조와 스크롤 등록부 — [ADR-0022](0022-scroll-regions-and-fixed-affordances.md) — 가 바뀐다).
   튜토리얼 표지에도 있던 결함이고 긴 한국어 이름이 앞당겼다. Android(최대 2.0배)와 iOS 200 %까지는 근사 렌더에서 넘치지 않았다.
4. **표지 이름의 한 줄 글자 수 상한 10은 잠정값이다**(B5). 시뮬레이터에서 본 것은 에피소드 2의 이름 하나다.
5. **이벤트 사전(GitHub wiki)을 고쳐야 한다** — 다섯 이벤트의 카탈로그에서의 발생 시점 · `stage: "intro"` · 건너뛰기 비율의 정의 · 해석 단절. 저장소 밖이라 이 변경에 들어 있지 않다. **⟨2026-10-14 사용자 결정⟩ 이미 끝낸 표지를 다시 열어 건너뛴 것은 세지 않는다** — 진행에 `intro`가 있으면 `episode_intro_skipped`를 내지 않고 맵으로만 돌아간다(진행 기록도 다시 하지 않는다). `episode_intro_viewed`는 다시 열 때도 나므로 건너뛰기 비율의 분모는 에피소드별 **첫 조회**로 잡아야 한다.
6. **보조기술** — 배너의 낭독 이름이 1.6초 안에 끝까지 읽히는지, 닫힌 뒤 초점이 맵의 어디에 서는지는 기기에서만 닫힌다.
7. `episode-intro.contract.ts`의 이벤트 설명 주석은 튜토리얼만 말한다 — 카탈로그에서의 시점은 ADR-0029 적용 기록이 진다. 그 파일을 다음에 고칠 때 함께 고친다.
8. 맵으로 돌아오면 맵이 맨 위로 스크롤돼 있었다(시뮬레이터 관찰). 이 변경 전에도 그랬는지는 확인하지 않았다.

### ⟨2026-10-14 — 에피소드 음성⟩ 컷과 최종 테스트가 소리를 낸다

적용 기록이고 **위 결정 문장 가운데 D3의 컷 · 최종 테스트 몫만** [ADR-0060](0060-episode-voice-remote-audio.md)이 부분 대체한다. 출처 · id 규약 · 네이티브 원격 판정 · 실패 처리는 그 ADR이 진다.
여기에는 이 문서의 화면이 바뀐 자리만 적는다.

- **D10 통과 뒤 컷 · 3b-2의 표지 컷**: 컷이 서면 그 컷의 소리가 한 번 난다(콘텐츠 컷의 선택 키 `audio_url`). 다음 컷으로 넘어갈 때 · 나가기 · 시스템 뒤로 · 배너로 넘어갈 때 멈춘다 —
  타자기 도중의 `Next` 첫 탭은 글만 마저 보이고 소리는 계속 난다. 소리가 끝나도 넘기지 않는다. 표지 화면 · 건너뛰기 모달 · 배너는 무음이다.
- **D9 최종 테스트**: 턴이 서면 상대 줄, **정답 직후 내 줄**(정답 효과음과 겹친다), 오답에는 바뀌는 것이 없다. **다시 듣기 조작은 없다 — 사용자 결정**(2026-10-14).
  두 줄은 문항의 `roleplay.line_id`(`D<n>`)로 대화의 `seq n-1`(상대) · `seq n`(나)을 찾는다 — 모양이 어긋나면 그 턴은 무음이다. D8이 디코드만 하던 `line_id`가 처음 쓰인다.
- **화면 props · route · 리듀서 · 문구 · testid는 바뀌지 않았다.** 소리는 이미 받던 데이터(`cuts` · `turns`)의 선택 필드이고, 재생 훅 하나(`lib/use-audio-cue.ts`)가 두 화면에 같은 규칙으로 붙었다.
- **D3의 학습 문항 규칙은 그대로다** — 오디오 없는 듣기는 건너뛰고, 받아쓰기의 꺼진 재생 조작(ADR-0016 D10의 예외)도 그대로다. 걷을 날의 조건은 ADR README 보류 표 「학습 문항 오디오의 연결」로 옮겼다.
- ⚠ 기기 확인은 요청까지다 — iOS 시뮬레이터에서 버킷 주소로 요청이 나간 것을 봤고 실제 청음은 하지 않았다([에피소드 음성 e2e](../e2e/episode-audio.md)).

### ⟨2026-10-16 — 새 에피소드 형식⟩ 매핑 표가 24종이 되고, 대화 조립의 화자가 데이터에서 온다

적용 기록이다. 결정은 [ADR-0065](0065-episode-format-additions.md)이 지고, **위 결정 문장 가운데 D7의 「짝수 = 상대 · 홀수 = 나」와 A2의 「`screen-pending`을 지웠다」만** 부분 대체한다.
여기에는 이 문서의 매핑 · 화면이 바뀐 자리만 적는다. 튜토리얼 테스트 파일은 한 줄도 바뀌지 않았다.

- **D2 매핑 표 — 새 11종**(ADR-0065 D8이 기준과 근거를 진다):

  | 콘텐츠 `type` | 학습형 · 결과 |
  |---|---|
  | `CLOZE_CHOICE` | 단어 선택 — 빈칸 문장(`context`) + 로마자 · 번역 줄, 보기는 `options` **콘텐츠 순서 그대로**(섞지 않는다 — `CLOZE`와 다르고 `ROLE_LINE`과 같다) |
  | `REPLY_SELECT` | 단어 선택 — 제시문이 상대 말(`stimulus.audio`)이고 지시문 `How do you reply?`. **듣기를 글로 — 사용자 결정**(ADR-0065 Q3) |
  | `PARTICLE_FILL` · `PARTICLE_SWAP` | 단어 선택 — 제시문 `stimulus.text`(빈칸 문장 / 틀린 구), 보기는 조사 |
  | `MIN_PAIR_AB` | 듣기 모양(보기 2)이지만 소리가 없어 건너뜀 `audio-missing` — 듣기 매핑 함수를 함께 쓴다 |
  | `CULTURE_CARD` · `CULTURE_CHECK` · `LISTEN_BUILD` · `SYLLABLE_BUILD` · `SHADOW` · `SPEAK_WORD` | 건너뜀 **`screen-pending`** — PR ② · ③ |

- **건너뜀 사유는 여덟이다** — A2의 일곱에 **`screen-pending`이 되살아났다**(같은 이름 · 같은 뜻). 「아직 화면이 없는 유형이 있다」가 새 형식에서 다시 참이 됐다.
- **기존 유형의 차분** — `WORD_ORDER`의 제시 영어와 `TRANSLATE_TO_KO`의 단서는 문항의 `stimulus.en`을 **먼저** 쓰고, 없으면 지금처럼 정답의 `en`이다.
  `VOCAB_CARD`는 `example`이 없으면 예문 상자 없이 선다(A2의 「예문이 비었으면」과 같은 결과).
- **D5 · A4 — 「곧장 결과」가 실데이터에서 처음 일어난다.** 문화 단계 `CULT`(맵의 `Lesson 9`)는 문항 여섯이 전부 `screen-pending`이라 활동이 0개다 — 노드를 누르면 레슨 화면 없이
  결과(`PERFECT LESSON!`)가 서고 `CULT`가 기록된다. 코드는 그대로이고 테스트로 고정했다. D5의 「실데이터에서는 일어나지 않는다」는 그때의 데이터에서 참이었다.
- **D7 — 칸의 화자는 콘텐츠의 턴 화자다.** 문항 prop `dialogue`가 `true`에서 `{ speakers }`가 됐고 `SentenceOrderDialogue`는 `slotCount` 대신 `speakers`를 받는다. 화자는
  매핑의 순수 함수 `catalogTurnSpeakersOf`가 정답 순서로 낸다 — 모두 있으면 그대로, 모두 없으면 짝 · 홀, 섞이면 그 문항을 건너뛴다(`malformed`). 같은 화자가 연이어 서는 칸도 데이터대로 그린다.
  시각 · CSS · 문구 · testid · 낭독 문구는 바뀌지 않았다. 「재검토 조건」 2가 발동했다.
- **A6 · 단어 선택 — 그림 문항이 실데이터에서 선다.** 새 형식의 `IMG_MATCH` 7문항은 그림 주소가 채워져 있다. A6의 「기기에서 한 번도 돌지 않았다」는 **아직 그대로다** — 2026-10-16 회차도 그림 문항에 닿지 못했다.
  빈칸 채우기 계열의 제시문 · 로마자 줄은 이제 밑줄 자리를 `blank` 낱말로 바꿔 읽는다(접근성 감사 지적 — ADR-0065 「구현 판단」 4).
- ⚠ **기기 확인은 일부다** [실기] — 옛 진행 계정의 iOS 시뮬레이터 한 회차가 플레이어 먼저인 대화 조립 · 건너뜀 뒤 분모 · 새 유형 셋의 단어 선택 · `CULT` 곧장 결과를 봤다.
  `CLOZE_CHOICE` · 그림 문항 · VoiceOver · Android는 보지 못했다([새 에피소드 형식 e2e](../e2e/episode-format.md)).

### ⟨2026-10-16 — 새 에피소드 형식 ③⟩ 말하기 둘이 학습형이 되고, 건너뜀 수가 활동에서 나오며, 통과 분모가 판정한 문항이 된다

- **말풍선의 내용(사용자 선택)** — 제목 줄은 `Lesson n: “<에피소드 영어 제목>”`(문화 `Culture: …` · 최종 `Final test: …`). 콘텐츠에 스텝별 제목이 없어 에피소드 제목을 쓴다. 영어 제목은 콘텐츠의 `title_en`이고
  디코더가 선택 필드(`Episode.titleEn`)로 받는다 — 없으면 매니페스트 제목.
- **진행 줄** — 전체는 그 유닛을 열면 서는 문항 수(레슨 = 계획의 `shownItemCount` — 레슨 화면 카운터와 같은 수, 최종 = 턴 수), 끝낸 유닛이면 전부 · 아니면 0(진행이 유닛 단위로만 남는다 — 튜토리얼 스텝과 같은 규칙).

### ⟨2026-10-19⟩ 타자 입력의 자판이 껍데기 밖 화면 바닥에 선다

적용 기록이다. 결정은 [ADR-0070](0070-keyboard-dock.md)이 진다. 이 문서의 결정 가운데 **D6의 「작업 영역에 메신저 자판이 선다」**만 그때의 상태가 됐고(D6 옆 표시), 나머지 결정 문장은 그대로다.

- **자판의 자리** — `TypingActivity`는 `LearningShell`에 `workspace`를 넘기지 않는다. 바깥 상자(`typing-activity`) 안에 몸통(`typing-activity-body` › `LearningShell`)과 자판을 형제로 두고,
  자판 면이 화면 아래 · 좌우 끝까지 닿는다. 키는 안전 영역 안이다(키 아래 = 24 + 아래 인셋).

- **카드 스크롤 · 문항 전환 밖** — 자판은 카드와 함께 스크롤되지 않고 문항이 바뀔 때 미끄러지지 않는다. 카드 영역은 자판 높이(232 + 아래 인셋)만큼 좁다(ADR-0070 「대가」 1).
- **셸** — 이 활동에서만 셸이 위만 비운다(`keyboard-dock`). 같은 레슨의 다른 학습형 활동은 지금 그대로다.
- `LearningShell` · 매핑 · 채점 · 결선(`catalog-lesson-wiring.ts`) · route · 이벤트는 바뀌지 않았다. 렌더(`render-catalog.tsx`)는 `insets`를 넘긴다.
- ⚠ **기기 확인은 일부다** — iOS 시뮬레이터에서 u03 `S6` 타자 입력의 자판 면 · `Check` 자리를 봤다. iPhone SE의 카드 영역 · Android는 보지 못했다([자판 바닥 붙이기 e2e](../e2e/keyboard-dock.md)).

### ⟨2026-10-19 — 대화 조립 아바타⟩ 대화 조립 줄마다 원형 아바타가 붙는다

적용 기록이다 — **사용자 결정**(2026-10-19, 「문장 순서 바꾸기 — 아바타만 적용」: 지금 디자인은 그대로 두고 아바타만 더한다). D7의 결정 문장은 그대로다.

- **모습** — 대화 조립(`dialogue`가 있는 문항)의 줄마다 지름 36의 원형 아바타가 말풍선 옆 아래 끝에 붙는다. 상대 줄은 말풍선 **왼쪽**(짙은 중립 면 `gray-900` · 흰 머리글자),

- ⚠ **기기 확인은 하지 않았다** — [카탈로그 레슨 e2e](../e2e/catalog-lessons.md) 「대화 조립 아바타」 AV1 ~ AV5가 미실행이다. 번들은 [성능 보고서](../performance/reports/sentence-order-avatars-iphone-17-pro-simulator-01.md).

### ⟨2026-10-20⟩ 최종 테스트의 대사 패널과 답안 판이 어두운 반투명 면이 된다
