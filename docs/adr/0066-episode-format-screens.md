## 맥락

1. **네 유형 38문항이 레슨에서 빠져 있었다** [데이터]. `CULTURE_CARD` 9 · `CULTURE_CHECK` 9(세 에피소드의 `CULT` 전부) · `SYLLABLE_BUILD` 7(세 에피소드의 `S3`) · `LISTEN_BUILD` 13이 `screen-pending`이었고,
   그래서 `CULT`는 0문항 단계 — 누르면 곧장 결과였다(ADR-0065 D10).
2. **문화 카드는 「제목 + 세 문장 산문 두 언어」다** [데이터]. 제목 `context`(`ko` · `roman` · `en`), 본문 `stimulus.text`(`ko` 68 ~ 101자 · `roman` 최대 226자 · `en` 133 ~ 211자). 단어 카드의 「표제어 하나 + 뜻 · 예문」과 모양이 다르다.
3. **문화 확인의 보기는 긴 한국어 문장이다** [데이터]. 2 ~ 21자, 27/27 보기에 `en`이 있다. u02 `CULT-05`처럼 보기 셋이 모두 4자 이하인 문항도 있다(지금 규칙이면 가로 칩).
4. **음절 조립의 타일은 정답 순서로 실려 오고 오답 음절이 뒤에 붙는다** [데이터]. 7문항 모두 그렇다(예 `괜 찮 아 요 | 세 원`). **같은 음절이 두 장인 문항이 둘**이다 — u02 `일주일`(`일` ×2) · `와이파이`(`이` ×2).
   정답은 모두 하나, 공백이 없다. 칸 수(정답을 이루는 타일 수)는 2 ~ 5.
5. **콘텐츠에는 단계 종류 필드가 없다** [데이터]. `steps[]`의 키는 `id` · `order` · `items` · (`RP`의) `scene`뿐이고, 단계 id는 PR ①에서 실제로 이름째 바뀌었다(`S3` ~ `S9` → `S1` ~ `S8` · `CULT`).

## 결정

### D1. 화면 결정 표 — 뜻을 잃지 않으면 넓히고, 잃으면 새로 만든다

| 유형 | 결정 | 근거 |
|---|---|---|
| `CULTURE_CARD` | **새 학습형 `culture-card`**(폴더 `screens/culture-card/`) | 단어 카드에 실으면 「영어 본문 = 뜻」처럼 필드 이름이 뜻을 잃고 표식 `New word` · 머리 라벨 `New words`가 거짓이 된다 |
| `CULTURE_CHECK` | **단어 선택을 넓힌다**(보기 번역 줄 — D3) | 「질문 하나 + 보기 셋 · 정답 하나」는 단어 선택의 모양 그대로다. PR ①이 건너뛴 두 이유(근거 카드가 없다 · 보기 번역 자리가 없다)가 이 변경에서 풀린다 |
| `SYLLABLE_BUILD` | **새 학습형 `syllable-build`**(폴더 `screens/syllable-build/`) | 문장 조립은 조각을 띄어 잇고(`카 드`) **인덱스 순서**로 판정하며 말풍선 모양이다 — 셋 다 바꾸면 그 화면에 잇기 · 판정 · 배치 모드가 생긴다 |
| `LISTEN_BUILD` | 건너뜀 **`audio-missing`** | **사용자 결정** — D8 |

새 화면은 기존 활동의 골격(`LearningShell` · `AnswerVerdict` · `LearningActivityComplete` · `lessonCounter` · `handsOffAfter`)을 그대로 쓰는 **명시적 변형**이다. 새 boolean prop은 0개다 —
타일의 누름 가능 여부는 `interaction: "tappable" | "locked"`, 낱말 줄의 낭독 방식은 판별 유니온, 보기 번역은 데이터(`translation?: string`)다.

### D2. 문화 카드 — 단어 카드와 같은 「채점 없음」 규칙

- `catalogActivityScoring["culture-card"] = "ungraded"` — 통과 분모 · 정답 · 오답 수 밖, 레슨 카운터 · 진행 막대(표시 수)에는 든다. 단어 카드 선례 그대로다.
- `Next`가 처음부터 서고 마지막 카드의 버튼에서 `onFinish([], 0)`을 **한 번**. 레슨 중간이면 `Next`, 끝이면 `See results`. 완료 카드 · 판정 배지 · 판정음 · 건너뛰기가 없고 배지 자리에 중립 표식이 선다.
- *(2026-10-19 주: **바로 위 줄(`Next`가 처음부터)과 바로 아래 줄(카드 안 낭독 순서)은 [ADR-0072](0072-culture-card-flip.md)가 바꿨다** — 첫 버튼은 앞면의 `Flip card`이고(뒷면이 걸음을 진다), 카드는 앞 · 뒤 두 면 · 접근성 요소 하나다. 채점 없음 · 결과 한 번 · 완료 카드 없음은 그대로다.)*
- 카드 안(위 → 아래 = 낭독 순서): 표식 → 한국어 제목 → 제목 로마자 → 영어 제목 → 구분선 → **영어 본문(크게, 왼쪽 정렬)** → 한국어 본문 상자(소제목 `In Korean` + 한국어 본문, 작게).
  영어가 크고 한국어가 작은 것은 **사용자 결정**(요구사항)이다. 로마자는 **제목에만** 싣고 본문 로마자는 싣지 않는다(최대 226자 산문 로마자는 상자를 두 배로 키우고 낭독 잡음이 된다 — 추천안, 사용자 미확인).
- 매핑 판정 순서: 제목(`context.ko`)이 비면 `malformed` → `stimulus.text`가 없으면 `malformed` → 영어 본문이 비면 `no-gloss` → 나머지는 비면 그 줄이 서지 않는다. `feedback.correct`(요령)는 읽지 않는다.
- 걸음 계산(`cultureCardStepOf`)은 화면 자기 순수 모듈이다 — 단어 카드의 같은 함수를 값으로 가져오지 않는다(화면 폴더 사이 값 import 금지).

### D3. 문화 확인 — 단어 선택 + 보기 번역 줄, 번역은 늘 보인다

- 제시문 = 질문 `context.ko`, 로마자 · 번역 줄 = `context.roman` · `.en`, 지시문 = `prompt.en`, 보기 = `options[].ko` **콘텐츠 순서**(섞지 않는다 — `CLOZE_CHOICE` · `ROLE_LINE` 선례, 정답 자리가 이미 흩어져 있다).
- 문항 필드 `WordChoiceQuestion.choiceTranslations?` — **모든 보기에 `en`이 있을 때만** 싣는다(일부만 번역된 보기 줄을 만들지 않는다). 있으면 보기마다 둘째 줄에 작은 번역이 서고,
  **배치는 늘 세로**(4자 이하 보기도), 제시문은 산문 크기(`word-choice-screen-prompt-sentence`)다. 번역 줄은 판정 색을 받지 않는다.
- **번역은 고르기 전부터 보인다 — 사용자 결정**(Q1). 문화 확인이 묻는 것은 「카드에 적힌 사실」이고 카드가 영어 중심이다 — 읽을 수 없는 한국어 보기로 재면 한글 독해 시험이 된다.
- 낭독: 보기 하나가 정지 하나, 이름 `한국어, English[, Correct|Incorrect]`(`optionAccessibilityLabel` 넷째 인자). 판정 · 2.5 초 자동 넘김 · 배지는 단어 선택 그대로이고 머리 라벨은 `Word choice`다.

### D4. 음절 조립 — 낱말 문자열로 판정하고, 칸 수는 철자 탐색으로 정하고, 판정 뒤 정답을 보인다

- **판정은 놓인 타일 글자를 `""`로 이은 낱말이 정답 중 하나와 같은가**(`judgeSyllableBuild`)다 — 타일 인덱스가 아니다. 같은 음절 두 장(`일주일`)을 바꿔 놓아도 정답이다.
- **칸 수 = 첫 정답을 이루는 타일 수**. 매핑의 `catalogSpellingOf(tiles, word)`가 각 타일을 한 번씩만 써서 그 낱말이 되는 인덱스 열을 찾는다(깊이 우선 · 작은 인덱스 먼저 · 접두 비교 — 결정적). 못 찾으면 `malformed`.
- 정답은 치환 · trim 뒤 **모든 공백을 지운** 꼴로 받는다(「띄어쓰기 없이」 — 요구사항). 뜻은 `stimulus.en` → `answers[0].en` → 낱말 목록 순이고 없으면 `no-gloss`.
- 타일은 **섞는다**(`shuffledOrder`, 씨앗 `episodeId/itemId` — `WORD_ORDER` · `TURN_ORDER`와 같은 규칙). 정답 순서 그대로 보이면 앞에서부터 누르는 것이 답이다.
- 조작: 창고 타일을 누르면 다음 빈 칸에 붙고, 놓인 타일을 누르면 빠지며 뒤가 당겨진다. 칸이 다 차면 창고 타일은 잠기고(`locked`) **막는 자리는 리듀서 하나**다. 칸이 차면 `Check`, 채점 뒤 `Next`.
- **판정 뒤 정답 상자(`Answer: 카드`)가 선다 — 사용자 결정**(Q2, 계약 초안의 「공개 없음」을 뒤집었다). 타자 입력의 정답 상자와 같은 부품 · 같은 문구(`copy.typing.answerReveal`)이고 **맞혀도 선다**(타자 입력과 같다).
  여러 정답이 있으면 첫 정답을 보인다.
- 낭독: 뜻 줄 `Meaning: card`, 창고 타일 = 글자 그대로(한국어 음성), 빈 낱말 줄 `Your word, empty, 2 syllables`, 놓이는 중에는 타일이 각자 요소(`카, position 1 of 2`), 채점 뒤 줄 하나(`Your word: 카드`). 판정은 한 번 announce, 완료는 `All questions done, See results`.

### D5. 새 화면은 각자 폴더다 — 공유는 셸 · 공용 부품만

음절 타일은 자기 컴포넌트(`SyllableTile` · `SyllableTilePlaceholder`)다. `SentenceOrderChip`을 값으로 가져오면 관례 예외 표에 셋째 소비자가 생기고 그 표의 정리 조건(「`components/` 승격을 먼저 한다」)을 이 변경으로 끌어온다.
문장 조립 폴더 안의 변형으로 두면 testid가 섞이고 다른 판정 규칙 둘이 한 폴더에 선다. 공유하는 것은 모두 기존 활동이 쓰는 경로다(새 import 예외 0 — `docs/conventions/code.md` 표의 행이 늘지 않았다).

### D6. 학습형 어휘 — 셸 값 둘

`LearningActivityForm`에 `"culture-card"` · `"syllable-build"`. 머리 라벨은 `Culture` · `Spelling`, 타이밍 표식은 `libitum:navigation:learning-culture-card` · `…-syllable-build`다.
튜토리얼 `LearningForm`의 `"culture"`(튜토리얼 문화 화면)는 넓히지 않는다 — 단어 카드 · 짝 맞추기와 같은 규칙이다. 카탈로그 활동 학습형은 여덟이 됐다.

### D7. 문화 단계는 콘텐츠로 가린다 — 노드 role만 늘린다

- **판별 규칙**: 유닛의 문항이 **하나 이상이고 모두** `CULTURE_CARD` · `CULTURE_CHECK`이면 문화 유닛이다. `catalogCultureKeysOf(units)`가 그 id 목록을 내고 맵 구획(`CatalogReadySection.cultureKeys`)이 싣는다 —
  완료 키 `completionKeys`를 구획이 싣는 ADR-0065 D6과 같은 자리 · 같은 방식이다.
- **바뀌는 것은 보이는 것뿐**: 노드 role `CatalogUnitNodeRole`에 셋째 값 `"culture"` — 라벨 `Culture` · 아이콘 `@libitums/icons/lynx/lantern-05`(열린 상태에서만 보인다 — 잠김 · 끝은 자물쇠 · 체크) · 낭독 `Episode n. Culture` + 상태 접미사 · **한 줄 전용**(`catalogNodePlacement.culture = "solo"`).
- **바뀌지 않는 것**: `lessonKeys`(문화 키도 든다) · 사슬 잠금 · 진행 키(`"CULT"`) · 완료 키 · `catalogUnitRoleOf`(결선 · 이벤트용 — 문화는 `"lesson"`) · 이벤트 `unitRole: "lesson"` · 시작 결선 · 결과 화면 · testid.
  **제품 코드에 `"CULT"` 리터럴 0** — ADR-0065 D7의 「이름으로 분기하지 않는다」를 그대로 지킨다.
- 왜 콘텐츠 판별인가: ① 콘텐츠에 단계 종류 필드가 없다(맥락 5) ② 단계 id는 콘텐츠가 바꾸는 이름이다 ③ 문항 유형은 디코더의 **닫힌 목록**이라 판별의 입력이 계약 안에 있다 ④ 문화 카드 한 장이 일반 레슨에 섞여도 그 레슨은 레슨으로 남는다(「모두」).
  「어느 유닛이 특별한가는 콘텐츠 판단」([ADR-0024](0024-journey-units-and-special-unit-placement.md) D7)과 같은 방향이다.
- 한 줄 전용인 이유: 문화 노드는 표지 · 최종처럼 **특별한 자리**다. 지금 데이터(레슨 8 + 문화 + 최종)에서는 짝 잃은 레슨(가운데 한 줄)과 모양이 거의 같지만, 문화 단계가 레슨 사이로 오면 짝을 이루게 된다 — 위치에 따라 특별함이 바뀌지 않게 한다.

### D8. `LISTEN_BUILD` — 화면 없이 `audio-missing` (사용자 결정)

`catalogItemOf`의 `LISTEN_BUILD` 갈래가 모양 검사 없이 `audio-missing`을 낸다. **뜻의 차이를 적는다** — `audio-missing`은 지금까지 「화면은 있고 소리만 없다, 소리가 오면 매핑 변경 없이 선다」(`LISTEN_SELECT` · `MIN_PAIR_AB`)였고,
`LISTEN_BUILD`는 「**소리가 먼저다** — 소리가 오면 그때 화면을 만든다」다. 사유의 정의(「문항 음성이 없음」)는 둘 다에 참이고 사유 타입 · 이름은 바꾸지 않았다(사유는 여덟 그대로).
사유를 더 쪼갤 소비자(이벤트 · 화면)가 없다 — 사유는 이벤트로 나가지 않는다(`skippedItemCount`만). ADR-0065 「구현 판단」 2(디자인 `audio-missing` ↔ 계약 `screen-pending`)는 사용자 결정으로 디자인 쪽으로 닫혔다.
`screen-pending`은 이제 말하기 둘(`SHADOW` · `SPEAK_WORD`)만 낸다.
⟨2026-10-16 — PR ③⟩ **위 문장은 PR ② 시점의 것이다** — 말하기 둘이 화면을 얻어 `screen-pending`을 내는 유형이 0이 됐고 사유를 지웠다(사유 일곱 — [ADR-0067](0067-episode-format-speaking.md) D9).

### D9. `CULT`는 0문항 단계에서 실단계가 됐다 — 레슨 공통 기준을 건다 (사용자 결정)

- u01 기준: 활동 `[문화 카드 ×3, 문화 확인 ×3]`, 채점 3 · 표시 6 · 건너뜀 0. 카운터 `1 / 6` → `6 / 6`, 카드 셋 뒤 완료 카드 없이 문화 확인으로(학습형이 바뀌는 기존 규칙). 세 에피소드 같다.
- 통과 = 셋 중 **둘**(`catalogPassCriterion(3)`). 하나만 맞히면 실패 → `Try again`(첫 카드부터) · 기록하지 않음 · `RP` 잠김 유지. **새 규칙이 아니라 레슨 공통 규칙이 문화 단계에 처음 걸린 것**이다(Q3).
- 옛 진행: PR ① 빌드에서 `CULT`를 곧장 끝낸 기기는 진행에 `"CULT"`가 남아 **그대로 끝남**이다(다시 풀 수 있다). 에피소드 완료 판정은 ADR-0065 D6 그대로다.
- **0문항 경로는 실데이터에서 다시 사라졌다** — ADR-0058 D5 · A4의 코드는 남고 합성 픽스처 테스트가 지킨다.

### 측정

새 이벤트 · 속성은 없다. **해석이 바뀐다**: PR ① 빌드의 `CULT` 이벤트는 늘 `questionCount "0"` · `skippedItemCount "6"` · `passed`라 「노드를 열었는가」만 뜻했다. 이 변경부터 `CULT`의
`episode_lesson_started`는 `questionCount "3"` · `shownItemCount "6"` · `skippedItemCount "0"`이고, `episode_lesson_finished`는 「카드 셋을 읽고 확인 셋 중 둘 이상 맞혔는가」이며 **`failed`가 생긴다.**
두 빌드가 섞인 기간에는 앱 버전(공통 속성)으로 갈라 본다. 음절 조립이 든 `S3`의 정답률은 단계 단위 `correctCount / questionCount`로 보인다(유형별 정답률은 이 변경의 질문이 아니다).

## 구현 판단

1. **카드 로마자는 제목 줄의 `titleRomanization`이다** — 계약 초안은 한국어 상자 안의 본문 로마자(`koreanBody.romanization`)였다. 본문 로마자 숨김을 따라 필드를 제목으로 옮겼다(testid `culture-card-title-romanization`, 낭독 `Pronunciation: …`).
   `koreanBody`는 문자열 하나(`string | null`)가 됐다.
2. **정답 상자는 맞혀도 선다** — 개정된 계약은 「맞히면 서지 않는다(타자 입력과 같은지 구현이 확인)」였다. 타자 입력이 맞혀도 세우므로 그쪽에 맞췄다(testid `syllable-build-reveal`).
3. **한국어 상자의 소제목 `In Korean`은 보이기만 하고 낭독하지 않는다** — 디자인은 소제목을 두지 않았고 계약이 뒀다. 처음에는 잎 `<text>`에 `accessibility-elements-hidden`을 붙였는데 이 속성은 자기 자신이 아니라 자손을 가린다(ADR-0016 D5) —
   접근성 감사가 잡았고(A1) `accessibility-element={false}`로 고쳤다.
4. **음절 조립의 칸 수를 낭독에 싣는다**(접근성 감사 A2) — 보는 사용자는 밑줄 칸 수로 낱말 길이를 안다. 빈 줄 `Your word, empty, n syllables`(1이면 `syllable`) · 놓인 타일 `…, position k of n`. 문구 둘의 시그니처가 칸 수를 받게 바뀌었다(`wordEmpty(slotCount)` · `placedTile(text, position, slotCount)`).
5. **문화 카드 한국어 제목 · 본문에 `word-break: keep-all`** — 기기에서 어절 중간 줄바꿈(`계산/할`)을 보고 넣었고 어절 단위로 접히는 것을 기기에서 확인했다. 디자인은 Lynx 지원이 확인되지 않아 열지 않았던 자리다.
6. **음절 조립의 빈 칸은 밑줄 칸이고 좌우에 `spacing-4`** — 기기에서 빈 칸 넷이 밑줄 하나로 뭉쳐 칸 수가 안 보였다. 디자인의 「붙어 서는 칸(gap 0)」은 놓인 음절의 모양으로 남고, 빈 칸만 간격을 둔다. 판정 테두리는 칸이 아니라 답 칸 상자가 진다.
7. **문화 확인 제시문은 산문 크기 변형**(`heading-m` + `fg-brand`) — 디자인 결정이다. 켜는 조건은 문항 필드(`choiceTranslations`가 있음)이고 기존 문항은 한 픽셀도 바뀌지 않는다.

4. **문항 음성이 오면** — `LISTEN_BUILD` 화면을 만들고(D8), 음절 조립의 소리 자리를 다시 본다.
   ⟨2026-10-22⟩ **발동했고 처리했다 — 새 화면은 만들지 않았다**(사용자 결정). 아래 「적용 기록」 ⟨2026-10-22⟩.
5. **셋째 카드 활동이 생기면** — 걸음 함수를 셸 공용으로 올린다(「대가」 7).
   ⟨2026-10-16 — PR ③⟩ **발동했고 올리지 않았다** — 아래 「적용 기록」 ⟨PR ③⟩. 이 조건은 닫히지 않는다.

## 적용 기록

### ⟨2026-10-16 — PR ③⟩ 말하기 두 학습형(`read-aloud` · `speak-word`)

적용 기록이다. 결정은 [ADR-0067](0067-episode-format-speaking.md)이 지고 **이 문서의 결정 문장은 바뀌지 않는다** — 그때의 상태가 된 문장 셋에 표시를 달았다.

- **머리 「다루지 않는 것」의 말하기** — ADR-0067가 다룬다. 말하기 두 유형은 새 학습형 둘로 섰다(채점 없는 읽기 · 채점하는 낱말 말하기).
- **D8 끝 「`screen-pending`은 이제 말하기 둘만 낸다」** — 그 둘이 화면을 얻어 사유를 내는 유형이 0이 됐고 **사유를 지웠다**(여덟 → 일곱, ADR-0067 D9). 건너뜀 분포(세 에피소드 합)는 `screen-pending` 15 → 0.
- **「대가」 7 · 재검토 조건 5(셋째 카드 활동)** — 읽기(`read-aloud`)가 셋째 사례다: 결과 `[]` · 완료 카드 없음 · 마지막 문항의 버튼이 레슨 중간이면 `Next`, 끝이면 `See results`. 걸음 함수(`readAloudStepOf`)를 **화면 자기 순수 모듈에 또 하나** 뒀다 —
  셸 공용으로 올리면 기존 두 카드 화면의 테스트를 함께 건드려 이 변경의 범위를 넘었다. 조건은 발동했지만 이행은 미뤘다(ADR-0067 「대가」 7). 다음에 카드처럼 끝나는 활동이 오면 그 작업을 먼저 한다.
- **D5(새 화면은 각자 폴더)** — 같은 규칙을 이었다. 새 두 화면의 공유는 `components/`(결선 훅 · 마이크 부품) · `lib/`(순수 규칙 · 그림 로드 전이)이고 새 import 예외는 0이다.

### ⟨2026-10-19⟩ 문화 카드 G2 — 카드 덱 + 앞 · 뒤 뒤집기

- **D2 둘째 · 셋째 줄이 바뀌었다** — 결정은 [ADR-0072](0072-culture-card-flip.md)가 진다(사용자가 시안 G2를 골랐다). 「`Next`가 처음부터」 → 앞면의 버튼은 `Flip card`, 뒷면이 `Next card` · `Next` · `See results`.
  「카드 안 위 → 아래 = 낭독 순서」 → 앞면(그림 · 제목) · 뒷면(본문 · `In Korean`) 두 면이고 카드가 버튼 하나의 접근성 요소다(이름이 글을 대신 읽는다).
- **D2 「매핑 판정 순서」는 그대로이고 `stimulus.image_url`이 실린다** — 레슨 포트 `imageUrlOf`로 풀고, 없거나 못 풀면 `null`(건너뛰지 않음). 「구현 판단」 8의 「음원 · 그림은 싣지 않는다」 중 그림만 풀렸다.
- **「미확인 · 후속」 2의 A4(표식 `Culture`가 머리 라벨과 두 번 들림)** — 이 화면에서는 닫혔다: 앞면 머리글 `CULTURE`는 카드 이름에 들지 않는다. A3(문화 확인 질문 로마자)는 그대로 열려 있다.
- 채점 없음(D2 첫 줄) · 걸음 함수가 화면 자기 모듈인 것(D2 끝 · 「대가」 7)은 그대로다.

### ⟨2026-10-22⟩ 학습 문항 음성 · 「천천히」 — `LISTEN_BUILD`가 기존 문장 순서 화면에 선다

결정은 [ADR-0081](0081-item-audio-and-slow-playback.md) D8 · D9. 이 문서의 D8 · D1 표 `LISTEN_BUILD` 행은 그때의 상태다.

- **`LISTEN_BUILD`는 소리가 있으면 문장 순서 화면(대화 아닌 갈래)으로 선다** — 새 화면 없이 상대 말풍선 자리에 듣기 3열 줄(다시 듣기 · 재생/일시정지 · `Slow`)을 두고, 대본 · 로마자 · 뜻은 보이지 않는다(대본이 곧 정답). 내 말풍선 · 답 줄 · 창고는 그대로다 — 사용자 결정(2026-10-21 「기존 조립 화면 재사용」).
  D8의 「소리가 먼저다 — 소리가 오면 그때 화면을 만든다」는 「소리가 오면 기존 화면 위에 선다」로 풀렸다. 소리가 없으면 지금처럼 `audio-missing`(사유는 일곱 그대로).
- 매핑: 정답을 공백으로 나눈 조각마다 같은 글자의 타일을 찾고(못 찾으면 `malformed`), 정답에 안 쓰인 타일은 오답 조각이다. 앞뒤 `WORD_ORDER` · `TURN_ORDER`와 한 활동으로 묶인다.
- **재검토 조건 4 후반(음절 조립의 소리 자리)** — 음절 조립은 판정 순간 정답 음성을 1.0으로 한 번 낸다(조작 없음 — 판정 전 재생은 답을 알려 준다). 화면 모양은 바뀌지 않았다.
- 보류 표 「새 형식의 화면이 없는 유형」의 마지막 남은 몫(`LISTEN_BUILD`)이 닫혔다([ADR README](README.md#보류-표)).
