# ADR-0139 — 메신저 첫 입장 안내 (하단 탭 NEW · 덕수쌤 목록 오버레이 · 방 코치마크)

- 상태: **채택.**
- 날짜: 2026-11-13.
- **사용자 결정**
  - 「바텀 네비게이션 채팅에 new 태그 추가하고 첫 입장 사용자를 위한 메신저와 이미지 음성에 대한 가이드 … 덕수 쌤으로 가이드 … 이미 미나가 해금된 유저도 … 문제 없게」
  - 고른 것: NEW = 처음 + 새 친구 · 가이드 = 덕수쌤 말풍선 코치마크 · 사진 · 음성 단계는 만들어 두고 서버 연결 전까지 숨김.
  - 시안 [KMsLcR9rCRbVjqRtGcC2Ji](https://claude.ai/artifact/KMsLcR9rCRbVjqRtGcC2Ji) 2판 — 「목록 첫입장도 원본에서 오버레이에서 덕수 쌤 채팅 리스트만 떠잇는 형태」.
- 이어받는 결정: [ADR-0137](0137-messenger-companion-server-source.md)(덕수쌤 = 서버 모드 인물) · [ADR-0117](0117-messenger-chat-turns-coins-new-friend.md)(새 친구 isNew) · [ADR-0128](0128-messenger-access.md)(접근) · [ADR-0104](0104-lesson-activity-guides.md)(문항 안내 — 본 기록 저장 방식)

## 결정

### D1. 하단 탭 NEW
- 메신저 탭에 한 번도 안 들어갔으면 NEW. 들어가면 기기에 `libitum.messenger.tab-visited`를 남겨 사라진다.
- 그 뒤에는 열 수 있는 방 가운데 안 연 새 친구(isNew)가 있으면 NEW, 그 방을 열면 사라진다. 손님 · 시험 계정 아님은 방을 못 열어 새 친구로는 달지 않는다.
- ui-lynx `BottomNavigator`에 글자 배지 `kind: "label"`(글자 + 낭독)을 더했다 — 숫자 배지 모양을 그대로 쓰고 낭독은 「Chats, new」. 색은 앱 CSS로 brand-primary(목록 NEW 알약과 같음).
- 저장소를 못 읽으면 「들어감」으로 봐 배지가 붙어 있지 않게 한다.
- 탭 배지 훅은 출처를 「새 친구가 있나」 불값으로만 구독한다 — 답 조각마다 세션 루트가 다시 그려지지 않게(리뷰 W-2).
- ui-lynx 배지가 기기에서 처음 쓰였는데 아이콘 아래로 밀리고 잘려 보이지 않았다 — 배지 감싸개를 아이콘 오른쪽 위에 붙이고 항목 · 면 · 아이콘 상자가 넘침을 자르지 않게 고쳤다(기기 확인 2026-11-13).

### D2. 목록 첫 입장 — 덕수쌤 줄만 떠 있는 오버레이
- 덕수쌤 방(`duksu`)이 열려 있는 메신저(서버 모드)에서 처음 목록을 보면 화면 전체(하단 탭 포함)를 덮고 덕수쌤 줄만 맨 위에 띄운다. 그 아래 덕수쌤 말풍선 + Skip · 「Chat with 덕수쌤」.
- 떠 있는 줄은 **원본 줄의 복사본**(같은 `ChatListRow`)이다 — 원본 목록에 구멍을 뚫지 않아 줄 위치를 재지 않는다. 새 친구가 있어 덕수쌤이 원본에서 아래에 있어도 떠 있는 줄은 맨 위다.
- 줄 · 「Chat with」 = 덕수쌤 방 열기, Skip · 뒤로가기 = 닫기. 어느 쪽이든 `libitum.messenger.guide-seen`에 `list`를 남긴다. 떠 있는 동안 뒤 목록은 낭독에서 숨는다.
- 막(ui-lynx Overlay)은 오버레이 안에서 absolute로 내린다 — fixed 안의 fixed는 Lynx에서 떠 있는 줄 위에 그려졌다(기기 확인 2026-11-13, 새 친구 시트와 같은 처리).

### D3. 덕수쌤 방 첫 입장 — 코치마크
- 덕수쌤의 첫 인사가 도착하고 입력 중이 아닐 때 한 번. 머리 · 로그 위만 덮고(Overlay area) 입력 줄 영역은 밝게 둔다 — 입력 줄은 화면 아래 고정이라 위치를 재지 않는다.
- 단계: ① 보내기 · 교정(입력 칸 고리) ② 추천 답변(전구 고리) ③ 사진 · 음성(사진 · 음성 줄 고리) — ③은 `MESSENGER_MEDIA_READY`(지금 false)일 때만.
- 아무 데나 탭 = 다음, 마지막은 「Got it」, Skip · 뒤로가기 = 끝. 끝나면 `room`과 `list`를 남긴다(푸시 · 새 친구 시트로 방에 먼저 온 사용자가 목록 안내를 또 보지 않게).
- 방 위에 다른 겹침(생년 시트 · 사이드바 · 대화상자)이 열려 있으면 숨었다가 닫히면 같은 단계로 돌아온다 — 기기에서 생년 시트가 먼저 떠 코치마크가 묻혔다(2026-11-13).
- 방 겹침은 z-index 없이 문서 순서로 쌓는다(ADR-0022) — 코치마크 중 연 「…」 메뉴가 그 위에 선다.

### D4. 이미 미나를 해금한 사용자
- 안내는 덕수쌤만 가리키고 원본 목록 순서 · 해금 · NEW 줄을 바꾸지 않는다(테스트로 확인). 탭 NEW는 D1 규칙 그대로(안 연 미나 방이 있으면 NEW).

## 버린 대안
1. **목록 맨 위 줄 안 카드** — 1판. 사용자가 오버레이로 바꿈.
2. **실제 버튼 위치를 재서 구멍을 뚫는 스포트라이트** — Lynx에서 위치 측정이 기기마다 어긋나기 쉽다. 복사본 줄 · 고정 입력 줄로 대신.
3. **덕수쌤 방 안 대화로 안내** — 서버 대화 기록에 섞인다.

## 대가
- 사진 · 음성 단계는 서버 연결 전까지 보이지 않는다.
- 업데이트 전부터 메신저를 쓰던 시험 계정도 안내 · 탭 NEW를 한 번 본다(전에 들어간 기록이 없음).
- ui-lynx 공개 타입이 하나 늘었다(`BottomNavigatorLabelBadge`). 글자 길이 상한은 없다 — 짧은 글자(NEW · NUEVO · BARU · MỚI)만 쓴다. 배지 자리 `right: -18px`은 「NEW」 실측(토큰 없음).
- 새 친구 isNew는 실행 동안만이라(ADR-0117), 안 연 새 친구의 탭 NEW도 재시작하면 사라진다 — 목록 NEW 알약과 같다.
- 떠 있는 줄은 원본과 같은 test id를 쓴다(vitest에서는 기기 저장소가 없어 안내가 안 떠 겹치지 않음). 기기 자동화가 생기면 접두사를 둔다.
