# ADR-0151: 출력 검사에 걸린 캐릭터 답은 화제를 돌려 한 번 다시 만든다

- 상태: **채택** (2026-11-15)
- 날짜: 2026-11-15
- **사용자 결정** (2026-11-15): 「이것도 진행해야할듯」 — 운영에서 본 차단 경고를 줄이는 방향을 채택.
- 다루는 축: 자유 대화 턴(chat-send)에서 미성년자 · 나이 모름의 동기 출력 검사(`output_sync`)가 답을 막았을 때의 처리.

## 맥락

- **운영 사례(2026-11-15 13:48 UTC, 미나 방, 나이 모름 → 엄격 규칙):** 대화가 해변 · 수영복으로 흐른 뒤 학습자가 「넵」 · 「왓나요」를 보냈다.
  - 입력 검사는 둘 다 `allow`였다.
  - 그런데 캐릭터 답이 앞 맥락을 이어 받아 출력 검사에 걸렸다(`sexual`, `romance`).
- **지금까지의 처리:** 답 없이 `guardrail_blocked`로 끝내고, 유저 메시지를 `blocked`로 저장했다.
  - 학습자에게는 **자기 무해한 글이 막힌 것처럼** 보이고, 이유를 알 수 없다.
  - 맥락이 그대로라 다음 답도 같은 쪽으로 가서 또 걸린다.
- 반복 위반(strike)은 원래 입력 차단만 센다(`companion_finish_turn`, 마이그레이션 20261116). 그래서 출력 차단은 학습자 몫이 아니라 캐릭터 몫이다.

## 결정

### D1. 출력 검사에 걸린 답을 한 번 다시 만든다
- 걸린 답의 글은 모델에 주지 않는다. 분류만 사람 말로 바꿔(`refusalTopic`) 이번 답 지시(`recoveryDirective`)에 넣는다.
  - 글을 주면 모델이 그 내용을 다시 이어 받을 수 있다(입력 차단의 성격대로 거절과 같은 이유 — PRD §3.11, `chat-send-refusal.ts`).
- 지시 내용: 그 화제를 잇지 말고, 학습자의 마지막 말에 짧게 성격대로 답한 뒤, 쉬운 질문 하나로 다른 일상 화제로 돌린다. 규칙 · 앱 · 검사 · 버린 답은 말하지 않는다.
- 학습자의 글은 그대로 준다(입력 검사를 통과했다).
- 다시 만든 답도 **같은 출력 검사**를 거친다.
  - 통과하면 보통 답처럼 내보내고 `complete`로 저장한다. 크레딧은 한 번만 확정된다.
  - 걸리거나, 만들기에 실패하거나, 대사가 없으면 지금처럼 `guardrail_blocked` · `blocked`.
- 다시 만드는 것은 **한 번뿐**이다.
- 학습 지시(`branch.directive`)는 다시 만들 때 싣지 않는다. 화제 돌리기가 우선이다.

### D2. 걸린 답에서 나간 것은 없다 · 기록은 남긴다
- 미성년자 · 나이 모름은 원래 검사를 통과한 뒤에만 조각을 내보낸다. 그래서 앱이 받는 이벤트 순서와 모양은 그대로다(앱 변경 없음).
- 걸린 답으로 시작한 번역 · 칩은 끊고, 다시 만든 조각으로 새로 시작한다. 피드백(교정 카드)은 학습자 글이 대상이라 그대로 쓴다.
- assistant `meta.guardrailRecovered = { category }`를 단다.
- `moderation_events`에는 첫 차단과 다시 검사가 모두 남는다(저장 RPC가 목록을 그대로 넣는다).

### D3. 첫 인사 · 선톡에는 적용하지 않는다
- 첫 인사(`companion-greet`)는 출력이 걸리면 이미 정해진 인사 줄로 대신한다.
- 선톡(`companion-proactive`)은 걸리면 보내지 않는다.
- 어느 쪽도 학습자에게 오류로 보이지 않으니, 모델 호출을 더 들이지 않는다.

## 대가

- 걸린 턴마다 답 모델 1회 + 출력 검사 1회가 더 든다. 응답은 대략 1 ~ 3초 늦어진다(걸린 턴에서만).
- 다시 만든 답은 학습 목표 표현을 쓰지 않을 수 있다(그 턴의 학습 결과가 「놓침」으로 기록될 수 있다).
- 학습자가 일부러 같은 쪽으로 계속 몰아도 출력 차단은 strike로 세지 않는다(지금과 같음). 입력이 걸리는 글은 여전히 입력 거절 · strike로 간다.
