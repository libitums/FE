# ADR-0214: 컴패니언 답 모델을 Haiku 5.5로 — 답 프롬프트 다듬기 · 인물별 예시 · 다시 만들기 검사 · refusal 대체

- 상태: **채택 — 서버 파일(PR #696), 운영 미적용**. 모델 전환(`COMPANION_MODEL=claude-haiku-5-5` · `COMPANION_REPLY_EFFORT=medium`)과 함수 배포는
  머지 뒤 따로. 다시 만들기 검사(`companion-reply-check.ts`)는 평가 하니스에서만 쓰고 운영 연결은 따로(D6).
- 날짜: 2026-11-28
- **사용자 결정** (2026-11-27 ~ 28):
  - 답 모델은 결국 Haiku를 쓴다(원가). Sonnet 경로는 남기지 않고 처음부터 끝까지 Haiku — 턴마다 모델 고르기는 보류.
  - 답 형식: 말풍선 대부분 1 ~ 2개(3개는 가끔), 행동 · 묘사 줄은 잘 쓰되 매 답은 아니게, 앞 질문에 답했으면 받아 주고 피하면 넘어가기.
  - 덕수쌤의 「뭐 더하기 뭐」 퀴즈를 줄이고 예시 · 장면 · 이야기로 다양하게. 눈높이는 덕수쌤만 다듬는다.
  - 캐릭터마다 초반엔 학습자 신상을 묻고, 기억이 생기면 그 줄을 뺀다.
  - 영어 · 학습자 나라 말로 물어도 **언제나 한국어로만** 답한다(번역은 앱의 번역 단계가 한다).
  - AI냐고 **직접 물을 때만 한 번** AI라고 답하고, 그 뒤엔 캐릭터 자신의 삶(학교 · 일 · 가족)으로 그대로 말한다.
  - 장면 안의 환대(게스트하우스 · 가게 인물의 「오면 밥 준비해 둘게요」)는 만남 약속이 아니다 — 허용.
- 다루는 축: 답 모델 · 생각 깊이, 답 프롬프트(형식 · 대화 규칙), 인물별 예시, 답 검사 · 다시 만들기, refusal 처리, 칩 · 기억 추출의 사실 규칙.
- 바꾸는 결정: 답 모델 기본값(운영 `claude-sonnet-5-5` · effort low). [ADR-0210](0210-companion-memory-quality.md)의 기억 추출 규칙(「학습자가 말했거나 확인한 것만」)을 조인다(D8).

## 맥락

- 운영 답 모델은 Sonnet 5.5(effort low), 검사 모델은 이미 Haiku 5.5다(2026-11-28 운영 시크릿을 후보 값의 해시와 맞춰 확인). Haiku 5.5는 원가가 약 1/12(입력
  $0.10 · 출력 $0.50 / 100만 토큰, 캐시 읽기 $0.01)이고 서버 쪽 refusal 대체(fallbacks)가 없다.
- 처음 비교(옛 프롬프트 그대로 Haiku)에서는 운영 Sonnet이 실데이터 학습자 12대화 중 8번 이겼다(Haiku 4/12). 가장 큰 차이는 초급 눈높이 · 말투 깨짐 · 질문
  여러 개였다. 운영 Sonnet도 「Wait — I need to fix the state line.」 같은 메모를 말풍선에 냈다.
- 운영 데이터에서 본 문제: 칩이 학습자 이름을 지어냈다(「저는 민수예요」 칩 132세트, 그대로 보낸 메시지 46개). 학습 표현 끼워 넣기 지시의 「한동안 안 썼으면
  웬만하면 써라」가 「따뜻한 주스 드릴까요?」 · 「카드로 할게요」 같은 뜬금없는 말을 만들었다(두 모델 공통).

## 실험 (평가 하니스 `apps/supabase-functions/scripts/haiku-loop/`, 기록 `LOG.md`)

- 평가 대상만 API로 부르고(운영 `_shared` 코드를 Node 22로 그대로 불러 같은 프롬프트 · 같은 조각 나누기), 학습자 역할은 Sonnet 서브에이전트(실제 학습자 말
  표본을 말투 참고로 — 원문은 커밋하지 않음), 채점은 매번 새 Opus 서브에이전트가 운영 Sonnet 대화와 섞어 1:1로 매긴다(축: 몰입 · 페르소나 · 눈높이 ·
  받아주기 · 다양성 · 형식, 세기: 말투 깨짐 · 질문 둘+ · 경계). 정적 세트(실데이터 80장면)도 있다.
- 회차 i1 ~ i18(대화 수백 개, API 약 $13). 주요 수치:

| 회차 | 무엇을 바꿨나 | 대 처음 운영 Sonnet(1위) | 눈높이 Haiku/Sonnet |
| --- | --- | --- | --- |
| i9 | 예시 증류 · 놀이 재료 · 매 턴 상기문 | 4/12 | 2.75 / 3.83 |
| i11 | 말풍선 1 ~ 2개 · 앞 질문 · 덕수쌤 다양화 · 알아 가기 · 다시 만들기 · 행동 줄 연달아 빼기 | 10/12 | 3.25 / 3.67 |
| i13 | 같은 틀 되풀이 금지 · 「?」에 더 쉽게 · AI · 발음 규칙 | 10/12 | 3.25 / 3.42 |
| i18 | 한국어 전용 강화 · 덕수쌤 예시 재작성(과적합 경계) · 기억 규칙 · 질문 검사 완화 | **9/12** | 3.42 / 3.67 |

- i18 축: 몰입 3.67 대 3.08 · 페르소나 3.58 = · 받아주기 3.75 대 2.83 · 다양성 2.75 대 2.08 · 형식 3.75 대 2.00 · 질문 둘+ 8 대 98 · 경계 0 대 3.
- 같은 새 프롬프트 · 둘 다 다시 만들기를 켠 공정 비교(i14)에서는 Sonnet이 10/12 — 이 결정은 「새 프롬프트 Haiku > 지금 운영 Sonnet」이지 「Haiku > Sonnet」이 아니다.
- 고칠 때 안 쓴 학습자로 덕수쌤(i18H): Haiku 페르소나 3.67 · 눈높이 4.00 대 그때 운영 Sonnet 3.33 · 3.33(표본 3).
- 요약 · 기억을 흉내 낸 50턴(운영 `companion_summary_source` 값 — 최근 20개 밖 30개 · 기억은 유저 메시지 5개마다): 요약 뒤에도 Haiku 점수가 떨어지지 않았다.
  실패 1건: 오타(「비미리에요」)를 「베트남에서 왔군요」로 잘못 받은 답이 기억 · 요약에 들어가 굳었다 → D8.
- 지연(같은 시각 비교, 첫 말풍선 p50): Haiku medium 약 2.1 ~ 2.4초 · Sonnet low 약 1.1초.
- 검사(입력) 실데이터: 운영 판정 비safe 187건 + safe로 통과한 의심 후보 41건을 Opus 4명이 지금 기준으로 정답 매김 — 지금 지시문 + Haiku 허용/차단 97%
  (Sonnet 98%, 운영 당시 판정 68% — 당시 오판 73건은 모두 과잉 차단, 대부분 옛 지시문 시절). Haiku의 남은 무거운 놓침: 오타 섞인 영어의 성적 사진 요구.

## 결정

- **D1. 답 모델**: Haiku 5.5, 답 생각 깊이 `medium`. `COMPANION_REPLY_EFFORT`에 `high` · `off`(생각 끔 + effort low, Haiku만)를 더한다.
- **D2. 답 프롬프트 형식 · 대화 규칙**(`companion-prompt.ts` · `companion-prompt-requests.ts`)
  - 말풍선 대부분 1 ~ 2개(행동 줄 포함), 3개는 가끔. 행동 줄은 세 번에 한 번꼴로 장면을 살릴 때만, 같은 몸짓 되풀이 금지.
  - 질문은 많아야 하나 · 맨 끝, 답의 절반쯤은 질문 없이. 앞 질문에 답했으면 받아 주고, 피하면 다시 묻지 않는다.
  - 같은 첫마디 · 같은 문장 틀(「자, 퀴즈! A + B는?」 등)은 한 대화에 두 번까지, 같은 당부는 한 번, 작별은 한 번 짧게.
  - 한국어로만. 초급에겐 한 말풍선 한 문장 · 문법 용어 금지 · 뜻풀이는 그 낱말보다 쉽게. 오타는 너그럽게 읽고 이름 · 새 사실로 받지 않는다.
    「?」만 오면 같은 말을 더 쉽게. 글 채팅이라 발음 칭찬 금지. 맞는 답은 맞다고, 조금 틀린 꼴만 「거의 맞았어요」.
  - 지어낸 기억 · 사실 금지, 실제 만남 · 기다림 약속 금지(장면 안 환대는 허용).
  - AI냐고 직접 물을 때만 한 번 인정, 그 뒤엔 캐릭터의 삶 그대로.
  - **알아 가기**: 기억이 비면 동적 부분에 「Getting to know them」(이름 · 출신 · 하는 일 · 좋아하는 것을 한 번에 하나씩), 기억이 있으면 「이미 아는 것은 다시 묻지 않기」.
- **D3. 매 턴 인물 상기문**: 이번 턴 지시(유저 말 뒤 system 메시지) 끝에 「Reply as {이름}, in your own voice. {말투} 1 ~ 2 bubbles … easy words …
  at most one question」을 붙인다(`personaAnchor`, `chat-send-story.ts`의 `turnDirective`). 긴 대화에서 작은 모델이 인물을 잃는 것을 막는다.
- **D4. 인물별 대화 예시 · 놀이 재료**: 「Who you are」 끝에 인물마다 예시 6개(`companion-persona-examples*.ts`, Opus 증류 · 생성 파일)와 놀이 재료
  (`companion-persona-kits.ts` — 덕수쌤 가르치는 방식 · 확인한 합성어, 해준 부산말). 예시는 서로 다른 방식 · 상황, 소품 되풀이 없음, 평가 장면과 겹치지 않게
  (과적합 경계). 카드에 `examples`가 있으면 그쪽이 먼저(나중에 DB로 옮길 자리). 고정 부분이라 캐시된다.
- **D5. 학습 표현 끼워 넣기 · 칩**: 오래 안 썼어도 「학습자가 방금 한 말에 맞을 때만」, 음식 · 음료 · 계산을 갑자기 꺼내지 않는다. 칩은 학습자 이름 · 나이 ·
  나라 · 직업 · 가족을 지어내지 않는다.
- **D6. 다시 만들기 검사**(`companion-reply-check.ts`): 질문 둘+(퀴즈 · 「~죠?」 제외) · 말풍선 4+ · 말 단계 깨짐(문장 끝 꼴) · 영어 메모 · 한국어 자기 수정
  (「… 아니, …」) · 만남 약속(장소 + 기다릴게 · 「…에서 만나요」) · 빈 답 · 지난 답들과 같은 첫마디 · 틀 · 65자 넘는 말풍선. 걸린 턴만 위반을 적은 한 줄을
  붙여 한 번 다시 부르고, 지난 답에 행동 줄이 있었으면 이번 행동 줄은 코드로 뺀다. 하니스에서 위반 턴 11 ~ 19%, 말 단계 · 긴 말풍선 · 메모 · 만남은 거의 다
  해결(질문 둘+는 62%). **운영 연결은 이 ADR 밖** — 답을 다 모아 검사하면 첫 말풍선이 답 전체 시간만큼 늦어지므로 말풍선 단위 검사 · 행동 줄 빼기부터 붙인다.
- **D7. refusal**: 아무것도 보내기 전 거절이면 `COMPANION_REPLY_FALLBACK_MODEL`(Haiku면 기본 `claude-sonnet-5-5`)로 한 번 다시 부르고, 이미 보냈으면 보낸 데까지로
  조용히 끝내고, 대체도 거절이면 지금처럼 오류. 거절 분류는 경고 로그로 남긴다(`companion-llm-reply.ts`).
- **D8. 기억 추출**: 캐릭터가 짐작하거나 잘못 읽은 사실은 학습자가 직접 쓰거나 「네」라고 답해야만 기억으로 남긴다. 반박하지 않은 것은 확인이 아니다.
  고정 시스템 글에 있어 캐시는 그대로다.
- **D9. 말풍선 거르기**: 태그 없이 샌 상태 JSON은 상태로, `Wait` · `Let me` · `Note:` · `_state` · `<<` 같은 줄은 버린다(`companion-segments.ts`).


## 버린 대안

- **Sonnet 유지(새 프롬프트로)**: 같은 조건에서는 Sonnet이 가장 낫다(i14 10/12). 원가 약 12배를 이유로 버렸다(사용자 결정).
- **턴마다 모델 고르기**(입력 검사 신호로 쉬운 잡담은 Haiku, 학습 질문 · 무거운 이야기는 Sonnet): 보류(사용자 결정 — Haiku만으로).
- **처음 20턴은 Sonnet, 뒤는 Haiku**: 시험한 적 없는 조합이고, Haiku 단독 50턴에서 뒤가 나빠지지 않아 쓸 까닭이 없다.
- **best-of-2**(Haiku 답 둘 + Haiku 선택자): 실수는 걸렀지만 맞대결이 그대로이고 느려 버렸다.
- **예시를 늘려 덕수쌤 눈높이 맞추기**: 지시를 세게 하면 놀이가 사라지거나(페르소나 하락) 한 가지 놀이만 되풀이했다. 예시를 방식별로 고르게 다시 쓰는 쪽으로.

## 대가

- 첫 말풍선이 약 1초 늦다(Haiku medium의 생각). 생각을 끄면(`off`) 빨라지지만 품질이 떨어졌다.
- 고정 프롬프트가 예시 · 놀이 재료만큼 길어졌다(인물당 수백 토큰, 캐시 읽기라 원가 영향은 작다).
- 덕수쌤이 음절 끊어 따라 하기를 자주 되풀이한다(i18 다양성 2.75). 눈높이는 아직 처음 Sonnet보다 조금 낮다(3.42 대 3.67).
- 다시 만들기를 운영에 붙이기 전까지는 말투 깨짐 · 질문 여러 개가 프롬프트만큼만 줄어든다.

## 재검토 조건

- 모델 전환 뒤 일주일 운영에서 답 👎 비율 · 대화 길이(유저 메시지 수/대화)가 전환 전보다 10% 넘게 나빠지면 Sonnet으로 되돌리고 원인을 본다.
- refusal 경고 로그가 하루 답의 0.5%를 넘으면 대체 모델 경로 · 분류를 다시 본다.
- 다시 만들기 운영 연결 PR이 나오면 D6을 갱신한다.
- 새 Haiku · Sonnet 세대가 나오면 같은 하니스(`run static` · 대화 평가)로 다시 비교한다.
