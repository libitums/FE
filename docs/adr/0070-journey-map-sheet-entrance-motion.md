# ADR-0070 — 여정 맵 유닛 탭: 띠 · 말풍선은 스크롤이 멈춘 뒤 등장하고, 누른 유닛이 튀며 진행 값이 차오른다

- 상태: **채택 — 클라이언트 쪽.** 서버 · 저장 상태 · 분석 이벤트 변경은 0이다.
  사용자 결정(2026-10-19)은 둘이다 — 시안의 **「playful」 기준으로 하되 완료 도장은 뺀다** · 접근성 검토 A11Y-1에 대해 **대기 중 시작 자리 탭은 지금처럼 세션을 연다**(D6).
  숨쉬기 3회 · 새 번호 · `bindscrollend`를 쓰지 않음 · Android 에뮬레이터 실측 보고서 · 카탈로그 최종도 튕김 · 반짝임 포함은 계약의 열린 질문 다섯(Q1 ~ Q5)에서 **메인이 추천안을 골랐다** — 사용자 명시 승인이 아니다.
  ⚠ **Android 에뮬레이터에서만 봤다**(에이전트 실행 · 사람 미확인) — [보상 모션 e2e](../e2e/motion-reward.md#유닛-탭-등장-모션-2026-10-19-adr-0070) SM1 ~ SM9 통과 · SM10 기록. **iOS는 시뮬레이터 · 실기 모두 미확인**이다.
- 날짜: 2026-10-19.
- 다루는 축: 유닛 탭 뒤 띠 · 말풍선 등장이 **언제** 시작하는가(스크롤 도착 판정 · 대기 상한) · 모션 종류를 무엇에서 파생하는가 · 누른 노드의 튕김 · 반짝임 · 진행 막대 채움과 백분율 카운트업의 구현 방식 ·
  `overflow` 잘림 · 대기 중(보이지 않는 동안) 탭의 의미 · 시작 버튼 숨쉬기의 반복 횟수 · 토큰 밖 연출 값 · 움직임 줄이기 · [ADR-0053](0053-motion-policy.md)의 「한 화면 한 번」 · 「standard DOM 불변」과의 관계.
  **다루지 않는 것**: 말풍선이 서는 자리 · 스크롤 목적지([ADR-0022](0022-scroll-regions-and-fixed-affordances.md) 적용 기록 ⟨2026-10-19⟩ — 그대로), 띠가 서는 조건(말풍선이 열린 동안 — 그대로), 퇴장 모션(D10), 완료 도장(사용자 결정으로 뺌),
  노드의 기존 현재 유닛 고리, 카탈로그 「Coming soon」 등 다른 시트.
- 이어받는 결정(결정 문장은 바꾸지 않는다 — 각 ADR에 적용 기록):
  [ADR-0053](0053-motion-policy.md) D1(토큰 규칙 — allowlist 두 줄) · D2(「standard DOM byte 불변」의 예외 — 래퍼 다섯) · D4(「한 화면 한 번」의 둘째 예외) · D5(등장만 · 입력 비차단 · 타이머 종료 — 이 작업의 적용),
  [ADR-0064](0064-stat-motion.md) D4(조각을 0 × 0 축에 세우고 축을 돌려 두는 방식) · D5(연출 값 파일 allowlist),
  [ADR-0055](0055-scroll-bars-off.md) D6(`user-interaction-enabled={false}`의 hit-test — 이 구조에서는 성립하지 않았다, D6).

**왜 새 번호인가** — 등장 시작 판정 · 카운트업 방식 · 노드 래퍼의 Context 합성 · ui-lynx `EpisodeHeader`의 새 prop · 대기 중 탭 같은 **새 축이 여럿**이고, ADR-0053 · 0064의 결정 넷을 한꺼번에 건드린다(ADR README 「형식」의 둘째 · 다섯째 줄).
ADR-0053 적용 기록으로 쓰면 결정 아홉이 조각으로 흩어진다. ADR-0064가 같은 꼴(사용자 결정 예외 + 모션 축)이었다.

근거 표시: **[코드]** 저장소 코드(`apps/mobile/src/screens/journey-map/` 기준, 다른 뿌리는 전체 경로) · **[실측]** 빌드 · 테스트 · 기기 실행 · **[사용자]** 요구사항 · 사용자 결정 · **[추론]** 관찰 없이 이어 붙인 것.
계약의 정본은 저장소 밖 하네스 작업 폴더의 spec · design이고 이 문서는 그중 **결정**만 옮긴다. 시그니처는 코드가, 시간 · 곡선 · 크기 값은 CSS와 `devtools/motion-literals/allowlist.json`이 진다.

## 맥락

1. **유닛을 누르면 띠와 말풍선이 움직임 없이 즉시 섰다** [코드]. `useStepSheet`가 유닛을 재고 `mapUnitPlacement`로 스크롤하지만(standard 부드럽게 · reduced 즉시) **도착을 재지 않는다** — `handleScroll`은 스크롤 값만 갱신한다.
2. **목적지에 닿지 않는 스크롤이 있다** [코드]. 맨 아래 유닛은 목적지가 스크롤 끝 너머라 상자가 끝에서 멈추고, 측정 실패 경로(`scrollIntoView`)는 목적지를 모른다. 「도착」만 기다리면 영영 서지 않는다.
3. **Lynx의 표현 제약** [코드 · 문서]. `overflow` 기본값이 `hidden`이다 · iOS 플랫폼 keyframe 애니메이터는 transform · opacity · background-color만 읽는다 · `::after` · `filter` · `color-mix()`가 없다 ·
   `bindtransitionend`가 없다 · 요소마다 무작위 방향을 줄 수 없다(ADR-0064 D4) · `%` · `calc()` `transform-origin`의 기기 기록이 없다 · `@lynx-js/react` 0.125에 `use()`가 없다(`useContext`만).
4. **ReactLynx 테스트 렌더러의 사정** [코드]. 조건부 자식(`{cond ? <view/> : null}`)을 테스트 DOM에서 `<wrapper>`로 감싼다(기존 `LearningShell.merged.ui.test.tsx` · `RoleplayCard.ui.test.tsx`가 풀어서 본다).
   그리고 언마운트 · 노드 걷기 때 `@lynx-js/react` commit이 **스냅숏 정리용 10초 타이머 하나**를 남긴다 [실측 — ui 테스트] — 「닫힌 뒤 타이머 0」을 세는 테스트가 이 몫을 감안해야 한다.
5. **번들 여유가 약 1 kB였다** [실측]. main 상한 2,192,000(직전 실측 2,190,958), ui-lynx dist 상한 530,000(실측 528,482).

## 결정

### D1. 등장 시작(t₀) — 이미 제자리 · 도착 · `d4` 조용함 · `d9` 상한 중 먼저 오는 것

순수 리듀서 `sheetEntranceReducer`(`journey-map-sheet-entrance.ts`)가 `idle → measuring → (travelling →) entering`을 진다. 훅 `useSheetEntrance`가 `useStepSheet` 안에서 부르고 결과를 `StepSheetControls.sheetEntrance`로 내보낸다.

| 신호 | 조건 | 근거 |
|---|---|---|
| 이미 제자리 | 측정 성공, `|목적지 − 잰 순간 scrollTop| ≤ 1` | 자동 스크롤로 선 유닛은 움직이지 않는다(ADR-0022 ⟨2026-10-19⟩). 측정 답 렌더에서 곧장 등장 |
| 도착 | `travelling`에서 스크롤 이벤트의 `|scrollTop − 목적지| ≤ 1` | 자동 스크롤 보정과 같은 판정 · 같은 허용오차(`autoScrollTolerance = 1`) |
| 조용함 | 마지막 측정 답 · 스크롤 이벤트 뒤 **`d4`(200 ms)** 동안 이벤트 없음 | 끝에서 멈춘 스크롤 · 측정 실패 · 호스트가 움직이지 않음을 덮는다 |
| 상한 | 열린 뒤 **`d9`(1,000 ms)** | 측정 답이 오지 않는 경우까지 — 대기는 반드시 끝난다 |

- 조용함 · 상한은 같은 행동 `expire(stepId)`를 보낸다 — 리듀서는 출처를 모른다. 타이머 시간은 화면 모션 값이 아니라 행동 계약이지만 ADR-0053 D5 선례대로 `motionDurationMs(d4 | d9)`로 읽는다(생값 0).
- 늦은 답(`measured` · `expire`의 `stepId`가 지금 것과 다름)은 버린다. `close`는 언제나 `idle`.
- [실측 — Android] 띠 첫 프레임은 스크롤 마지막 이동 프레임 뒤 약 17 ~ 50 ms였다(7회, SM2). 스크롤 도중 시작한 회차는 없었다. 맨 아래 유닛(끝에서 멈춤)의 「조용함 200 ms 지연」은 재지 못했다.

### D2. 단계 → 모션 종류 → 클래스: 세 번의 순수 파생

- `sheetEntrancePhaseOf(state)` → `"waiting" | "entering"` → `sheetEntranceMotionFor(phase, motion)` → `"awaiting"`(standard · 대기) · `"expressive"`(standard · 등장) · `"fade"`(reduced — 단계 무관, 대기 없음) →
  `sheetEntranceClasses(entrance)` 한 묶음(띠 · 띠 진행 · 말풍선 · 말풍선 탭 · 막대 · 숨쉬기 층 · reduced 표식). 노드는 `mapUnitStageMotionOf`, 백분율은 `sheetPercentView`가 같은 입력에서 낸다.
- 기본값 `"none"`은 직접 렌더(테스트) 전용이고 그때 DOM은 이 작업 전과 같다. 앱 결선은 늘 셋 중 하나를 넘긴다.
- **「한 번만」은 ref · `key`가 아니라 마운트 수명이 보장한다** — 말풍선 · 띠는 열릴 때 마운트되고 닫힐 때 언마운트, 튕김 클래스는 열린 노드에만 붙는다(ADR-0053 D4의 「순수 파생」 꼴).
- 대기 중 백분율 글자는 **최종값**이다(보이지 않는 동안) — 등장 첫 렌더에서 0으로 바뀌어 오른다.

### D3. 노드 — 튕김은 탭 시각, 반짝임 · 후광은 t₀

- 앱 래퍼 `MapUnitStage`(`MapUnitEntranceProvider`의 Context 소비)가 `.journey-step-node-stage > [반짝임, .journey-step-node-pop > 표식]`을 세운다. prop drilling이 아니라 Context + children 합성이다.
  ui-lynx `LearningUnit` · `SpecialUnit`은 고치지 않았다.
- 튕김 클래스는 `"pop"`(대기)과 `"pop-burst"`(등장)에서 **같은 클래스**라 대기 → 등장 사이에 다시 시작하지 않는다 — [실측 — Android SM3] 한 번만 튄다.
- 반짝임 조각 8개는 **ADR-0064 D4의 축 방식**이다 — 0 × 0 축을 45°씩 돌려 두고(인라인 `rotate`, 정지값) keyframe 하나를 공유한다. 후광 고리 하나가 함께 번진다.
- **측정 대상(`#journey-step-node-<id>` · 카탈로그 셀)에는 transform을 걸지 않는다** — 튕김은 그 안쪽 래퍼라 자리 계산이 재는 상자가 바뀌지 않는다.
- 카탈로그 최종(`SpecialUnitMapItem`)도 같은 래퍼다(Q5). 말풍선을 열지 않는 튜토리얼 특별 유닛도 같은 래퍼로 감싸 DOM 모양을 하나로 두고, 대상 id가 없어 늘 `"none"`이다.
- 눌림 축소(ui-lynx 안쪽 `:active`)와 튕김(앱 바깥 래퍼)은 다른 요소라 겹치지 않고 곱해진다.

### D4. 백분율 카운트업 — `d6` 뒤 `d1` × 12칸 간격 타이머, 잎 컴포넌트 하나만 다시 그린다

- 잎 컴포넌트 `StepSheetPercent`가 `d6`(300 ms) 뒤 `d1`(50 ms)마다 한 칸, `d8 / d1 = 12`칸을 오른다. 값은 `enter` 곡선(`cubicBezierEase`)으로 계산한다 — 막대 CSS(`d8` · `enter`)와 같은 토큰이라 함께 끝난다.
  마지막 칸 렌더에서 숫자 pop 클래스가 붙는다(타이머 하나 더 없음). 0 %는 오르지도 튀지도 않는다.
- 타이머는 effect가 걸고 cleanup이 걷는다 — 닫기 · 모드 바뀜에서 남지 않는다.
- 접근성 이름(`.step-sheet-progress`의 `accessibility-label`)은 **처음부터 최종값**이다. 오르는 글자는 그 접근성 요소의 자손이라 따로 읽히지 않는다.
- [실측 — Android SM5] 100 %에서 `0 → 29 → 47 → … → 99 → 100%`로 오르고 막대와 함께 끝났다.

### D5. `overflow: visible` 사슬

- Lynx 기본 `overflow: hidden` 때문에 노드 둘레 반짝임과 말풍선의 1.06 넘침이 조상에서 잘린다. 노드 쪽(반짝임 · 래퍼 · `.journey-step-node` · `.journey-special-unit` · 셀 몸통 · 셀 · 줄)과
  말풍선 쪽(`.step-sheet-anchor` · `.step-sheet-pop` · 진행 줄 · 진행 행 · 숫자 pop · 시작 래퍼)에 `overflow: visible`을 둔다. 크기 값은 변하지 않는다.
- ui-lynx `EpisodeHeader` 트랙에는 반대로 `overflow: hidden`을 **늘** 둔다 — 빛 자식이 둥근 채움 밖으로 나가지 않게. 정지 화면 변화는 0이다.
- [실측 — Android SM9] 조각 · 후광 · 말풍선 넘침이 셀 · 줄 경계에서 잘리지 않았고, 다른 유닛의 포커스 링 · 그림자가 새로 드러나는 것은 보이지 않았다. 큰 글자에서의 겹침은 미확인(A11Y-5 — 「남은 위험」).

### D6. 대기 중 탭 — 말풍선 래퍼가 잡아 닫고, 시작은 받는다

- 대기(`awaiting`, 말풍선 · 띠 불투명도 0) 중 **말풍선이 설 자리를 누르면 닫는다**(말풍선 밖을 누른 것과 같다). 래퍼 `.step-sheet-pop`의 `catchtap`이 **단계와 무관하게 늘** 걸려 있고,
  손을 뗀 순간의 단계를 ref로 읽어 대기일 때만 `onClose`를 부른다. 등장 뒤에는 아무것도 하지 않는다(패널 탭으로 닫히지 않음).
- **시작 버튼은 대기 중에도 탭을 받는다** — 세션이 열린다. 첫 구현에서 끄자 기존 ui 3 · integration 162가 깨졌고, ADR-0053 D5 「전환은 입력을 막지 않는다」와 요구의 우선순위(입력을 막지 않음 최상)에 맞춰 되돌렸다.
  접근성 검토가 「대기는 아직 아무것도 보이지 않는 상태라 D5의 근거가 그대로 서지 않는다, 보이지 않는 자리에서 결과가 갈린다」고 지적했고(A11Y-1, Major),
  **사용자가 「지금처럼 세션 열기」를 골랐다**(2026-10-19). 버린 대안은 「버린 대안」.
- **계약의 첫 방식은 기기에서 반증됐다.** 계약은 대기 중 `.step-sheet-pop`에 `user-interaction-enabled={false}`를 걸어 탭이 아래 가림막(`step-sheet-close`)에 닿아 닫히리라 봤다 —
  근거는 ADR-0055 D6(「`LynxBaseUI.hitTest`가 그 값이 꺼진 자식을 건너뛴다」)이었다. [실측 — Android SM6 첫 실행, `d94ea84b`] 대기 중 제목 · 시작 자리 탭이 **닫지 못했다**(3/3) — 탭이 형제 가림막에 닿지 않았다.
  ADR-0055 D6의 상자는 띠 밑의 **형제**를 덮은 잎이었고, 여기서는 꺼진 요소의 부모(`.step-sheet-anchor`)가 탭을 받을 수 있는 상태로 남는다 — 그 차이가 원인이라고 [추론]한다. ui 테스트는 속성만 봐서 통과했다(ADR-0055 D6의 「속성이 있다 ≠ 터치가 통과한다」와 같은 교훈).
- 처음 수정은 대기일 때만 `catchtap`을 펼침 prop으로 붙였다. 경계 프레임 탭 무반응(A11Y-3)의 원인 후보로 **붙였다 떼지 않고 늘 거는 꼴**로 바꿨으나 [실측 — r3] 경계 무반응은 그대로였다(D6 끝, 「남은 위험」). 동작은 같아 늘 거는 꼴을 유지한다.
- 뒤로가기는 `useLayerBack(onClose)` 그대로 — 대기 중에도 닫는다.

### D7. Lynx 표현 — 막대는 `translateX`, 빛은 자식 view, 숨쉬기는 뒤 층

- **막대 채움**(말풍선 · 띠): `width` 전환이 아니라 채움 상자의 `translateX(-100% → 0)` keyframe — iOS keyframe 애니메이터가 읽는 속성 안이다.
- **띠 빛**: `::after`가 없어 ui-lynx `EpisodeHeader` 채움 안의 자식 view(노랑 `feedback-warning` 단색, 불투명도 keyframe)다. 패키지 안 요소라 앱 CSS로 만들 수 없어 패키지가 열거형 prop `progressEntrance?: "none" | "fill"`을 연다
  (기본 `"none"` = 이전 DOM 그대로, 잘못된 문자열은 계약 함수가 `"none"`으로 정규화). 패키지는 `useMotion()`을 읽지 않는다 — 언제 · reduced 여부는 앱이 정해 넘긴다.
- **시작 버튼 숨쉬기**: box-shadow 반복 대신 버튼 뒤 같은 모양 층의 scale + opacity(`.step-sheet-start-glow`, `expressive`일 때만 DOM, `user-interaction-enabled={false}`).
- **말풍선 기준점**: 꼬리 끝을 인라인 px(`stepSheetBubbleOrigin`)로 준다 — [실측 — Android SM4] 왼쪽 · 오른쪽 칸 모두 꼬리 쪽에서 커졌다.
- **테스트 DOM의 `<wrapper>` 회피**: 숨쉬기 층과 시작 버튼, 반짝임과 튕김 래퍼는 조건부 자식이 아니라 **키를 단 한 배열**로 낸다. 층이 들고 나도 버튼 · 래퍼가 같은 노드로 남고(다시 마운트되면 애니메이션이 다시 돈다), 둘이 형제로 서며,
  테스트 렌더러가 조건부 자식에 두르는 `<wrapper>`가 DOM 사슬 단언에 끼지 않는다.

### D8. 숨쉬기는 3회(약 4.8초)로 끝난다

- 1.6초 × 3회. 자동으로 시작해 5초 넘게 이어지는 움직임에는 멈출 수단이 있어야 한다(WCAG 2.2.2) — 말풍선 닫기는 내용을 치우는 것이고 OS 동작 줄이기만으로는 충분하지 않다고 읽어 5초 미만으로 끝낸다.
  요구의 「떠 있는 동안 반복」을 「떠 있는 동안, 최대 3회」로 좁혔다(Q1). 끝없는 반복은 정지 수단 설계와 사용자 결정이 필요하다 — [보류 표](README.md#보류-표).
- [실측 — Android SM10] 띠 시작 약 5.57초 뒤 화면 변화가 끝났다.

### D9. 관찰 채널 · DOM — ADR-0053 D2의 예외

- standard는 등장 클래스(`-awaiting` · `-enter`)만, reduced는 `-motion-reduced` 클래스 + `data-motion="reduced"`를 **움직이는 요소**(띠 래퍼 · `.step-sheet-pop`)에만 조건부 spread로 단다. 접근성 노드에는 섞지 않는다.
- **「standard DOM byte 불변」의 예외**: 새 래퍼 다섯(`.step-sheet-pop` · `.step-sheet-progress-percent-pop` · `.step-sheet-start-wrap` · `.journey-step-node-stage` · `.journey-step-node-pop`)이 standard · reduced 모두에 늘 선다 —
  단계마다 DOM 모양이 바뀌면 다시 마운트되어 애니메이션이 다시 돈다.
- 분석 이벤트는 정하지 않는다 — 요구 측정은 프레임 드롭 관찰과 번들 상한이고 제품 지표가 아니다. 관찰은 e2e SM10과 [성능 보고서](../performance/reports/journey-map-sheet-motion-pixel-8-emulator-01.md)가 진다.

### D10. 「한 화면 한 번」의 사용자 결정 예외 · 퇴장 없음 · 움직임 줄이기

- **ADR-0053 D4 「보상 모션은 한 화면에서 한 번」의 둘째 예외다**(첫째는 ADR-0064 D4 학습 완료). 한 번의 탭에 띠 · 말풍선 · 노드 튕김 · 반짝임 · 띠 빛이 서고 숨쉬기가 반복된다 — 사용자 결정(2026-10-19 「playful」).
  순수 파생(D2) · 퇴장 없음은 그대로다. 정본(design-system motion.md)에 되묻는 것으로 남긴다(ADR-0064와 같은 자리).
- **퇴장은 없다.** 닫기(가림막 · 뒤로가기 · 시작)는 즉시이고 그 렌더에서 말풍선 · 띠 · 반짝임 · 숨쉬기가 사라지며 타이머가 걷힌다 — ADR-0053 D5. 닫기를 늦추면 그 사이 탭이 옛 말풍선에 간다.
  [실측 — Android SM8] 등장 중 · 숨쉬기 중 닫기 · 시작이 매번 즉시였고 잔상이 없었다.
- **움직임 줄이기**: 이동 · 확대 · 반짝임 · 튕김 · 빛 · 숨쉬기가 없고 띠 · 말풍선은 불투명도만(`d2` · `linear`), 막대 · 백분율은 처음부터 최종값이다(ADR-0053 D3 표). 대기도 없다.
  [실측 — Android SM7] 세 배율 0과 전환 배율 0 둘 다.

### D11. 토큰 규칙 — 연출 값 두 파일은 allowlist다

- `step-sheet-motion.css`(말풍선 팝 0.35 · 1.06 · 0.98, 숫자 pop 1.3, 숨쉬기 주기 1600 ms)와 `journey-step-node-motion.css`(튕김 정점 1.12, 후광 0.6 → 1.5, 조각 시작 0.3)는
  scale 토큰 셋 · 가장 긴 시간 토큰(`d9`)으로 적을 수 없어 `devtools/motion-literals/allowlist.json`에 사유와 함께 둔다. 그 밖의 길이 · 가속은 전부 토큰이고 새 토큰은 0이다. 띠 · 막대 keyframe(`episode-header.css` 포함)은 예외가 아니다.

## 버린 대안

- **고정 지연(예: 300 ms 뒤 등장)** — 스크롤이 짧거나 없을 때 늦고, 길 때 이르다.
- **`bindscrollend`** — 저장소 사용 0, 프로그램 스크롤에서 오는지 기기 기록이 없다(Q3). SM2에서 「끝에서 멈춘 뒤 200 ms 늦음」이 눈에 띄면 다시 본다.
- **도착만 기다림** — 끝에서 멈추는 맨 아래 유닛에서 영영 서지 않는다.
- **카운트업을 프레임마다 background setState(rAF)** — 600 ms에 36 ~ 72번 렌더 + 스레드 간 패치. 요구가 지목한 비용이다.
- **카운트업을 main thread 스크립트로** — 저장소 사용 0, 테스트 하네스 · 빌드 설정에서의 동작 미확인. 새 패턴의 위험이 기능의 가치보다 크다.
- **카운트업을 keyframe 숫자 띠로** — 글자 내용은 keyframe으로 못 바꾸고, 자릿수 띠는 `0% → 100%`(자릿수 1 → 3)에서 구조가 커진다.
- **조각을 말풍선 겹침 층에 그리기** — 조상 잘림은 피하지만 자리를 말풍선 위치에서 거꾸로 셈해야 하고 가둠이 있어 노드를 벗어난다.
- **띠 전체를 훑는 빛을 앱 래퍼에 겹치기(ADR-0064 칩 선례)** — 패키지 수정 0이지만 디자인이 「막대 빛」으로 정했다. `children` · render prop 슬롯은 뜻이 「채움 장식」뿐이라 열거형이 더 좁다.
- **그러데이션 빛** — 토큰만으로 「투명한 노랑」을 적을 수 없고(`rgba()` 생값 · `color-mix()` 없음) Lynx의 보간 방식이 미확인이다.
- **대기 중 `.step-sheet-pop`에 `user-interaction-enabled={false}`(계약 D6)** — 기기에서 반증(D6).
- **대기 중 시작 자리도 닫기로 통일(A11Y-1 (a))** · **대기 중 탭하면 바로 등장(A11Y-1 (b))** — 사용자가 「지금처럼 세션 열기」를 골랐다.
- **숨쉬기 끝없는 반복** — WCAG 2.2.2 정지 수단이 필요하다(D8).

## 대가

1. 여정 맵 유닛 탭이 정본의 「한 화면 한 번」을 넘는다(D10). 정본이 다른 답을 주면 반짝임 · 띠 빛 · 숨쉬기 순으로 걷는다(요구 우선순위의 아래부터).
2. 말풍선이 열린 동안 노드에 view 9(후광 1 · 조각 8)가 잠깐, 띠 빛 · 숨쉬기 층이 각 하나 선다. 래퍼 다섯이 모든 노드 · 말풍선에 늘 선다(D9).
3. 번들 — main 상한 2,192,000 → 2,215,000 bytes(실측 2,213,826 — 상한 반영 commit `38cf8683`, 약 +23.0 kB · 뒤의 D6 수정까지 든 `c55ae393` 2,213,883), ui-lynx dist 530,000 → 534,000 bytes(실측 532,091). 새 의존성 · 미디어 0. 사용자 사전 승인 범위다.
4. 대기 중(최대 1초) 보이지 않는 시작 자리를 누르면 세션이 열린다(D6 — 사용자 결정). 같은 보이지 않는 덩어리 안에서 제목 · 패널 자리는 닫기다.
5. `overflow: visible` 사슬로, 예전에 잘리던 것이 이제 겹쳐 보일 수 있다(A11Y-5).
6. 지표 모달의 `infinite` 반복(ADR-0064 D3)도 WCAG 2.2.2에 걸릴 수 있다 — 이 작업 범위 밖이고 기록만 한다.
7. 백분율 글자는 원래 `gray-300`(흰 바탕 약 1.2:1, 알려진 대비 위반)이다. 이 작업이 그 글자에 카운트업 · pop을 얹어 시선을 모은다(A11Y-2 — 「남은 위험」).

## 미확인 · 후속

1. iOS 회차 전부(위 표). 시뮬레이터 통과를 실기 통과로 적지 않는다.
2. 맨 아래 유닛(끝에서 멈춤)에서 조용함 대기 200 ms가 체감되는가(SM2 미측정) — 체감되면 `bindscrollend`를 다시 본다.
3. 띠 빛이 둥근 채움 안에서 잘리는가 — Android에서는 잘린 직선을 보지 않았고, iOS는 ADR-0064 미확인 2와 같은 질문이다.
4. 보조기술 실기(A11Y-4) · 큰 글자(A11Y-5).
5. 노드 쪽 순수 함수가 `journey-map-sheet-motion.ts`에 함께 있다(262줄) — 300줄에 닿으면 `journey-step-node-motion.ts`로 뗀다(export 이름 그대로).

## 재검토 조건

1. design-system 정본이 「한 화면 한 번」에 다른 답을 줄 때(D10).
2. 숨쉬기 반복 수 · 주기나 등장 연쇄의 지연(`d9` 상한 포함)을 바꾸는 변경 — WCAG 2.2.2 재판정 대상이다(t₀ 뒤 연쇄 전체 약 5.8초, 숨쉬기 4.8초로 여유가 적다).
3. iOS 회차에서 SM1 · SM4 · SM6 중 하나라도 실패할 때.
4. 「대기 중 보이지 않는 시작이 눌렸다」 또는 「눌렀는데 반응 없음」 보고가 처음 올 때(D6 · A11Y-3).
5. main 번들이 새 상한(2,215,000)을 넘는 변경이 이 화면에 올 때 — 카운트업 · 반짝임 몫을 다시 잰다.
