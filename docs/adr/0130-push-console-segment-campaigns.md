# ADR-0130 — 로컬 푸시 콘솔: 진행 단계별 맞춤 알림 · 대조군으로 알림마다 복귀 측정

- 상태: **채택 — 도구.** 첫 실제 발송 전이다.
- 날짜: 2026-11-12
- **사용자 결정** (2026-11-12, 다시 묻지 않는다)

| # | 물음 | 결정 |
|---|---|---|
| U1 | 무엇을 | 사용자별 맞춤 알림 전략과, 그것을 관리 · 실행하는 페이지 |

| U4 | 매일 학습 리마인더 | **넣는다** — 스트릭이 끊기기 직전, 현지 저녁, 하루 한 통 상한 |
| U5 | 기존 자동 발송 | **유지 + 겹침 제외** — 「다시 돌아오기」 cron은 그대로, 콘솔이 겹치는 사람을 뺀다 |
| U6 | 문구 언어 | **나라별 언어**(vi · id · ms · es · ja, 나머지 영어) |

- 이어받는 결정: [ADR-0034](0034-server-push-notifications.md)(발송 함수 `send-push` · 닫힌 목적지 · 문구는 서버가 고른다 — 적용 기록), [ADR-0035](0035-learning-progress-and-streak-on-server.md)(진행 · 학습한 날이 서버에 있다), [ADR-0127](0127-companion-push-target.md) D4(PostHog distinct_id = 사용자 id).
- 다루지 않는 것: 앱 변경(0) · 새 표 · 마이그레이션(0) · 자동 예약 발송.

## 결정

### D1. 로컬 Node 서버 하나 + 페이지 하나, 발송은 기존 `send-push` announcement
- `pnpm push:console` → `127.0.0.1:4777`. 호스트 이름이 다르면 403, POST는 사용자 정의 헤더가 있어야 받는다(다른 사이트가 이 주소를 부르지 못하게).
- 읽기는 service role로 PostgREST(`push_devices` · `learner_profiles` · `learning_progress` · `learning_days`) · Auth 관리 API(시험 계정 표시). 키는 실행마다 Supabase CLI에서 받고 파일에 쓰지 않는다. 프로젝트 ref · PostHog 키는 저장소 밖 `~/.duru/push-console/config.json`.
- 발송은 `{kind: "announcement", audience: {userIds}, title, body, target: null}` — 같은 문구끼리 묶어 1,000명씩. 이름 · 에피소드 자리표시 때문에 묶음이 많아질 수 있어 동시에 넷.
- **서버 · 앱 변경 0.** 목적지는 여정 맵(목적지 없음)뿐이다.

### D2. 세그먼트는 서버의 카탈로그 진행으로 가른다
- 진행 단계 일곱(튜토리얼 표지 · 레슨 1 · 레슨 2 · 나머지, 다음 에피소드 · 진행 중 에피소드, 다 끝냄) + 겹쳐 붙는 「스트릭이 끊기기 직전」. 근거는 위키 버전별 퍼널 기록 — 첫 레슨 직전 26% · 레슨 2 33%가 빠진다.
- 현지 시각 · 날짜는 프로필 나라의 대표 시간대(표에 없으면 시각 창에서 빠진다), 문구 언어도 나라로 고른다.
- 기본 문구 · 조건은 `copy.mjs`. 콘솔에서 고쳐 보내고, 보낸 문구는 캠페인 기록에 남는다.

### D3. 겹침 · 횟수
- 자동 「다시 돌아오기」의 직전 · 다음 실행(10:00 UTC)에서 3일 · 7일 조건에 드는 사람은 기본으로 뺀다(U5).
- 이 콘솔로 받은 뒤 기본 24시간은 다시 보내지 않는다(U4의 하루 한 통). 기록은 로컬 파일이라 **콘솔을 쓰는 기기가 하나**라는 가정이다.

### D4. 알림마다 대조군 — 복귀는 차이로 읽는다
- 캠페인마다 `hash(캠페인 id, 사용자 id)`로 대상의 일정 비율(기본 20%)을 **보내지 않는다**. 대조군도 받았을 문구와 함께 기록한다.
- 지표: 앱 열기 · 알림 누름(PostHog, 24 · 72시간 — 키가 없으면 없음), 학습한 날(`learning_days`, 현지 날짜), 발송 뒤 앱을 연 적(`push_devices.last_active_at`). 발송 − 대조의 차이 · 95% 신뢰구간 · p값, 누적 복귀 곡선.
- **누른 알림을 캠페인과 잇는 칸을 앱에 더하지 않는다** — 하루 한 통 상한 아래에서는 시간 창으로 충분하고, 앱 출시가 필요 없다.

### D5. 페이지는 design-system을 따른다 (사용자 요청 2026-11-12)
- 색 · 글자 · 간격 · 반경 · 그림자 · 움직임은 모두 `@libitums/design-tokens`의 CSS 변수로만 쓴다(ADR-0011 · ADR-0014의 소비 규칙). 서버가 설치된 패키지의 `variables.css` · `typography.css`와 랜딩의 폰트 패키지를 내준다 — 복사본을 두지 않는다.
- 컴포넌트는 스펙대로 맞춘다: Card · Button · Text Field · Toggle · Option Selector · Status Indicator · Dialog(README 표). 한 화면의 주 행동은 Brand 「보내기」 하나, 누를 수 없을 때는 이유 문구를 곁에 둔다(button.md).
- 어두운 모드는 없다 — 디자인 시스템이 밝은 테마 하나다.

### D6. Claude 추천 — 로그인된 Claude Code 세션을 쓴다 (사용자 요청 2026-11-12)
- 콘솔이 `claude -p`(구조화 출력 · 도구 · MCP · 세션 기록 끔)를 기록 폴더에서 돌려 다음 캠페인 2 ~ 4개를 받는다. API 키를 따로 두지 않는다.
- 보내는 것은 집계뿐이다(세그먼트 수 · 쉰 기간 · 언어 분포 · 시간별 도달 수 · 지난 캠페인 지표 · 퍼널 사실). 사람 단위 값은 보내지 않는다.
- 추천은 양식을 채울 뿐 보내지 않는다 — 발송은 D7의 확인을 거친다.

### D7. 보내기 확인은 보낼 사람 수를 적는다
- 처음에는 `SEND`를 적게 했는데, 한글 자판에서 「ㄴ둗」으로 들어가 버튼이 켜지지 않았다(사용자 보고 2026-11-12). 숫자는 자판과 상관없다.
- 미리보기와 발송은 같은 기준값으로 대조군을 나눈다(D8 — 묶음 이름) — 확인창의 수와 실제 수가 같다. 그사이 대상이 바뀌면 서버가 보내지 않고 다시 계산하라고 답한다.

### D8. 같은 실험 묶음 · 내 기기로 먼저 보기 (사용자 요청 2026-11-12)
- 한 번에 150 ~ 400명이라 한 회차로는 효과를 읽기 어렵다. 같은 실험을 며칠 반복해 **묶음**으로 합쳐 본다 — 묶음 이름은 적거나, 캠페인 이름에서 「N차」를 뗀 것.
- 대조군은 묶음 이름으로 나눈다(D7의 「미리보기 seed」를 대체). 회차가 바뀌어도 같은 사람이 대조군에 남아 누적 효과를 재고, 미리보기와 발송의 수도 그대로 같다. 대가: 같은 사람이 여러 회차에 세어져 합친 신뢰구간이 실제보다 좁다 — 화면에 적는다.
- 기본 대조군을 올렸다: 튜토리얼 레슨 세그먼트 50%(첫 실험), 나머지 30%.
- 시험 계정 기기에만 지금 문구로 한 통 보내는 테스트 발송을 둔다(서버가 시험 계정인지 확인). 캠페인 기록 · 대조군 · 쉬는 시간에 들어가지 않는다.

### D9. 컴퓨터가 꺼져 있을 때는 Supabase pg_cron 한 번짜리 작업 (사용자 결정 2026-11-12)
- Claude Code 클라우드 예약은 service_role 키를 클라우드 환경에 넣어야 해서 버렸다. 대신 그 시각 기준으로 대상을 미리 계산해 기록하고, 캠페인마다 한 번만 도는 pg_cron 작업이 Vault 키로 `send-push`를 부른다(ADR-0034 D5의 cron과 같은 경로). 작업은 실행 뒤 `cron.unschedule`로 스스로 지운다.
- 대가: 대상이 계산한 때의 데이터로 고정된다. 기록에 전달 수가 없다 — 함수 로그 요약으로 본다(캠페인마다 1분씩 띄움).

### D10. 문구 A/B — 캐릭터 톤을 기본 톤과 비교한다 (사용자 요청 2026-11-12)
- 「듀오링고처럼 귀엽게」에서 가져올 것은 **누군가 말을 거는 느낌**이고, 가져오지 않을 것은 죄책감 · 슬퍼하는 척 · 다른 앱 마스코트의 말투다. DURU는 이야기 속 인물이 있어 그 인물이 한국어 한 마디로 말을 건다(`{character}` — 그 사람이 하던 에피소드의 상대 인물).
- 한 캠페인 안에서 받는 사람을 변형 A · B(최대 C)로 무작위로 나눈다(`variant:${묶음}:${사용자}` — 대조군 배정과 다른 키). 대조군은 변형이 없다.
- 결과는 변형마다 대조군과, 그리고 B를 A와 바로 비교한다. 시간대 · 날짜를 달리해 보내면 나라 · 요일이 섞여 톤만 가를 수 없어서다.
- 추천 스키마에 `copyB`(캐릭터 톤)를 더했다.

### D11. 단계별 예고 — 끝낸 단계 뒤 장면을 예고 파일 문구로 보낸다 (사용자 요청 2026-11-13)
- 문구 원본은 공개 버킷 `content/push/level-5/`(`index.json` + `u00-tutorial.json` … `u17-samgyeopsal.json`, 스키마 push-1)이다. 단계마다 `after[단계]`에 훅 3개 · 8개 언어가 있다. 콘솔은 새로 고칠 때마다 다시 읽고, 못 읽으면 이 세그먼트만 비운다.
- 세그먼트 `story-next`(겹침형): 지금 에피소드(파이널이 없는 첫 에피소드)에서 단계 순서상 마지막으로 끝낸 단계, 아직 시작 안 했으면 앞 에피소드의 파이널. 표지(intro)는 단계가 아니라 튜토리얼 레슨 1 전이면 대상이 아니다. 단계 순서는 앱 묶음 카탈로그가 아니라 `index.json`의 `steps`를 따른다(예고 파일 쪽 에피소드가 더 많다).
- 보내는 방식은 우선 콘솔 캠페인이다 — 대조군으로 효과를 먼저 재고, 효과가 보이면 서버 자동 발송을 따로 정한다(사용자 결정).
- 훅은 사람마다 무작위(`variant:${묶음}:${사용자}`)로 골라 변형 이름으로 남기고, 결과 탭에서 훅끼리 비교한다(사용자 결정). 단계마다 훅 조합이 달라 훅 비교에는 단계 차이가 섞인다 — 여러 회차를 합쳐 본다.
- 제목은 에피소드 영어 이름, 파이널 뒤면 다음 에피소드 이름이다(사용자 결정). 본문 언어는 나라로 고르고 말레이시아는 말레이어가 없어 인도네시아어다(사용자 결정). `my`는 미얀마어다. 없는 언어는 영어.
- 콘솔 문구 · 추천 대상이 아니다(`copySource: "story"`). 시험 발송은 그 시험 계정의 자리 예고를 누를 때마다 다음 훅으로 보낸다.

## 버린 대안
1. **관리 웹을 서버(Vercel · Edge Function)에 띄우기** — 로그인 · 권한 · 비밀 보관이 더 필요하다(U2).
2. **PostHog 기능 플래그 · 실험으로 배정** — 발송이 서버 밖이라 배정을 콘솔이 하는 편이 단순하다. 플래그 노출 이벤트도 필요 없다.
3. **페이로드에 캠페인 id를 실어 누름을 정확히 잇기** — Android 호스트가 `target`의 아는 칸만 옮겨(ADR-0127 D5) 앱 출시가 필요하다. 상한 아래에서는 시간 창으로 대신한다.
4. **누름만 재기** — 알림을 보고 누르지 않고 돌아오는 사람이 빠지고, 원래 돌아올 사람이 섞인다. 대조군 차이가 알림의 몫이다.

## 대가
- 기록이 한 기기의 파일이다 — 다른 기기에서 보낸 캠페인은 쉬는 시간 · 결과에 잡히지 않는다.
- 나라 → 시간대 · 언어는 추정이다(여러 시간대 나라 · 다른 언어 사용자).
- 학습한 날은 날 단위라 발송 전 같은 날 학습도 든다 — 대조군도 같아 차이는 그대로 읽는다.
- 영어 외 기본 문구는 원어민 확인 전 초안이다.
