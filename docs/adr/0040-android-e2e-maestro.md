# ADR-0040 — Android 최소 호스트와 소셜 OAuth E2E: Maestro

- 상태: **채택** — Android 에뮬레이터에서 흐름을 실행해 통과했다(2026-10-01).
- 날짜: 2026-10-01
- 다루는 축: Android `e2e` 테스트 계층 · 실행 명령 · 판정 환경
- 부분 확장: [ADR-0037](0037-ios-e2e-maestro.md) D1·D3·D4·D5의 iOS 범위.
  루트 `test:e2e`는 iOS 흐름만 실행한다.

## 맥락

Android 최소 호스트와 소셜 OAuth 브리지가 생겼다. 기존 `e2e/entry-flow.yaml`은 iOS에서
접근성 이름으로 동작하지만 Android API 35에서 `Next`와 로그인 버튼 이름이 접근성
트리에 나오지 않았다. 첫 화면의 대화 문구는 나왔다. 서버·제공자 계정 없이 실제
OAuth 성공을 재현할 수 없는 상태다.

## 결정

1. Android도 **자체 호스트의 `bundled` APK**를 Maestro로 판정한다. iOS
   `test:e2e`와 Android `test:e2e:android`를 분리한다. Android 명령은 최소 호스트
   흐름과 Apple·Google·Facebook 세 회차를 각각 실행한다.
2. 전용 API 35 에뮬레이터를 **390×844·160 dpi·글자 배율 1.0**으로 고정한다.
   `clearState`가 세션을 지우므로 개인 기기에서 돌리지 않는다. `pnpm verify`와 CI에는
   에뮬레이터·APK·Maestro 설치가 필요하므로 넣지 않는다.
3. 최소 호스트는 온보딩 대화 문구·단계 이동·로그인 화면을 확인한다. Android
   접근성 트리에 없는 버튼은 화면 비율 좌표로 누르고, 로그인 화면은 기준 이미지와
   비교한다. 브라우저의 URL은 접근성 트리로 제공자·콜백·PKCE challenge를 확인한다.
4. 소셜 흐름은 `https://example.invalid` 설정과 `code=fake` 딥링크로 브리지와 오류
   반환을 결정적으로 확인한다. 실제 제공자 로그인 성공과 세션 유지(A3)는 이 흐름의
   통과로 간주하지 않는다.

## 대가

이미지 기준은 기기 크기·글자 배율·렌더러 버전에 묶인다. 문구 선택자가 없는 화면은
버튼의 접근성 회귀를 Maestro가 직접 발견하지 못한다. 화면 구성이나 기기 조건이
바뀌면 흐름과 기준 이미지를 함께 갱신해야 한다.

## 재검토 조건

- Android Lynx 버튼이 접근성 트리에 안정적으로 나오면 좌표와 이미지 단언을
  접근성 선택자로 바꾼다.
- 제공자 설정과 테스트 계정이 준비되면 실제 인증 성공·재시작·갱신(A3)을 별도
  회차로 추가한다.
- CI에 Android 에뮬레이터와 APK 빌드 환경이 마련되면 이 흐름을 게이트에 넣을지
  다시 판단한다.
