# ADR-0037 — iOS e2e 자동화: Maestro

- 상태: **제안** — Maestro를 쓰는 것은 사용자 결정이다(2026-10-01). 흐름 파일 위치(루트 `e2e/`)도 사용자 결정이다(같은 날).
  나머지 세부(명령 이름 · 선택자 · 자동화 범위)는 기본값으로 정했고 사용자 확인 전이다.
- 날짜: 2026-10-01
- 다루는 축: **테스트 계층**(`e2e` — [ADR-0006](0006-command-interface-and-test-layers.md) D4 · D6이 보류로 둔 자리) ·
  **명령 인터페이스**(`test:e2e` 한 줄)
- 부분 대체: ADR-0006 D4의 *"`e2e` 제외"* 와 *"뷰 기반 도구는 쓰지 않는다"*, D3의 *"`test.e2e` 키를 두지 않는다"*,
  D6의 *"파일 하나 → `<flow>.e2e.test.ts`"*. ADR-0006의 나머지(계층 셋 · `verify` 구성 · D6의 수동 흐름 목록)는 그대로다.
- Android 확장: [ADR-0040](0040-android-e2e-maestro.md)이 별도 APK·흐름·명령을 정한다.
  이 문서의 `test:e2e`는 iOS `entry-flow.yaml`만 실행한다.

## 맥락

이 앱은 Lynx 번들을 Swift 호스트(`apps/ios`)가 읽어 띄운다. 기기 위의 동작 — 호스트 · 번들 로드 · 실제 탭 — 을
자동으로 잡는 계층이 없었고, `docs/e2e/`의 흐름을 사람이 돌거나 `idb`로 좌표를 찍어 왔다.

ADR-0006 D4가 `e2e`를 뺀 근거는 둘이었다.

1. *"뷰 기반 도구(Maestro · Appium 계열)는 쓰지 않는다. Lynx는 캔버스로 직접 그려 접근성 속성을 붙여도 요소가
   잡히지 않는다."*
2. 남는 도구 `@lynx-js/kitten-lynx-test-infra`는 Android Explorer를 구동하는데, 개발도 시연도 iOS라 Android는
   e2e만을 위해 세우는 환경이다.

**1번이 이 저장소의 iOS 호스트에서는 사실이 아니었다.** 2026-10-01에 직접 돌려 확인했다.

| 무엇을 봤나 | 결과 |
|---|---|
| `maestro hierarchy` — 여정 맵(첫 실행 안내가 떠 있는 상태) | Lynx 요소가 접근성 이름으로 잡힌다 — `Episode intro, story` · `Tap to start your lesson!` · `Episode 0. Tutorial., 0 of 13 units completed`. 좌표(bounds)도 함께 온다 |
| 같은 덤프에서 안내 뒤쪽(머리의 수치 · 바텀 네비게이션) | **안 잡힌다.** 화면에는 보이지만 트리에 없다 — 안내가 떠 있는 동안 뒤쪽을 보조기술에서 가린 것(ADR-0016 D9)이 그대로 반영된다 |
| `maestro hierarchy` — 온보딩 둘째 장 | `Next` · `Step 2 of 3` · `Practice Korean` · 본문 · 학습 콘텐츠 한국어 문장까지 잡힌다 |
| `e2e/entry-flow.yaml` (온보딩 세 장 → 로그인) | 통과 — 열한 단계, 9초 |
| 같은 흐름에서 단언 하나를 일부러 틀리게 | 실패 — 종료 코드 1, `Assertion is false: "Get started" is visible` |

환경: 커밋 `49ead081` · **Release** Host(시뮬레이터용 빌드) · iPhone 17 Pro 시뮬레이터 iOS 26.5 · Maestro 2.11.0 ·
OpenJDK 21.

**Maestro가 보는 것은 VoiceOver가 보는 것과 같은 트리다.** 이 저장소는 이미 `accessibility-label`을 넓게 붙여
왔으므로(ADR-0016) 선택자로 쓸 이름이 있다. 반대로 보조기술에서 가린 요소는 Maestro도 못 본다.

## 결정

### D1. iOS e2e 도구는 Maestro다

자체 호스트 앱을 시뮬레이터에서 구동한다. `@lynx-js/kitten-lynx-test-infra`는 버리지 않는다 — Android Explorer용이고,
Android 환경이 생기는 날의 후보로 [보류 표](README.md#보류-표)에 남는다.

### D2. 판정 환경은 **Release Host + 내장 번들**이다

수동 e2e와 같은 기준이다([ADR-0012](0012-native-host-app-minimal.md) D5). **Debug Host로 돌리지 않는다** — Debug는
`http://localhost:3000/main.lynx.bundle`을 읽고(`ViewController.swift`의 `templateURL`), 그 포트를 다른 작업 트리의
dev 서버가 잡고 있으면 **다른 코드가 조용히 뜬다.** Release는 인자 없이 앱에 든 `main.lynx`를 읽으므로 흐름 파일이
실행 인자를 넘길 필요가 없다.

빌드와 설치는 흐름 파일이 하지 않는다 — 절차는 [docs/e2e/README.md](../e2e/README.md) 「자동화」에 있다.

### D3. 흐름 파일은 루트 `e2e/<flow>.yaml`이고 `docs/e2e/<flow>.md`와 이름이 같다

ADR-0006 D6의 *"파일 하나 = 흐름 하나 = 나중의 테스트 파일 하나"* 는 유지하고, 대응하는 파일명만
`<flow>.e2e.test.ts`에서 `<flow>.yaml`로 바뀐다. 러너가 vitest가 아니기 때문이다.

- **플랫폼에 매이지 않는 경로에 둔다.** 흐름이 적는 것은 사용자가 지나는 길이지 iOS 호스트의 구현이 아니다. Android
  호스트가 생기면 같은 파일을 돌리고, 갈리는 단계만 Maestro의 `runFlow` + `when: platform`으로 감싼다. `apps/ios` 아래에
  두면 그날 파일을 옮기거나 두 벌로 만들게 된다. ⚠ **같은 흐름이 Android에서 도는지는 확인한 적이 없다** — 경로만 열어 둔
  것이다(재검토 조건).
- **루트에 디렉터리가 하나 는다.** [ADR-0003](0003-workspace-and-directory-structure.md) D4의 트리에 없던 자리다. 그
  결정이 막은 것은 루트의 문서 · 산출물 · 스크립트 디렉터리이고, 흐름 파일은 셋 중 어느 것도 아니다 — 특정 앱의 소스도
  아니어서 `apps/<앱>` 아래에 둘 근거가 없다.
- ADR-0006 D7(테스트는 소스와 같은 폴더)의 대상은 vitest가 파일명 패턴으로 고르는 세 계층이다. e2e 흐름은 화면 하나가
  아니라 여러 화면을 건너므로 옆에 둘 소스가 없다.
- **흐름 문서의 항목 ID를 주석으로 적는다**(`# T1 — …`). 어느 행을 옮겼는지가 흐름 파일에서 읽혀야 한다.
- **흐름 문서의 표를 흐름 파일에 맞춰 고치지 않는다.** 표의 정본은 그대로이고, 자동화한 행에 표시만 더한다.

### D4. 명령은 루트 `test:e2e` 하나이고 `test` · `verify` · CI에 넣지 않는다

```sh
pnpm test:e2e                       # 부팅된 시뮬레이터가 하나일 때
E2E_UDID=<UDID> pnpm test:e2e       # 여럿일 때
```

- **`verify`에 넣지 않는 근거는 ADR-0012 D6과 같다** — Xcode · 시뮬레이터 · 빌드된 Host가 없으면 `verify` 자체가
  불가능해지고, 실패 원인이 코드인지 환경인지 읽히지 않는다.
- **ADR-0006의 *"없는 계층의 명령을 만들지 않는다"* 를 어기지 않는다** — 흐름 파일이 하나 있고, 틀리면 0이 아닌 코드로
  끝나는 것을 확인했다(위 표).
- Maestro와 Java는 `package.json`의 의존이 아니다. 버전은 이 문서에만 적혀 있다(대가 참조).

### D5. 자동화하는 것과 하지 않는 것

**자동화한다**: 접근성 트리로 판정되는 기능 관찰 — 무엇이 보이는가 · 누르면 어디로 가는가.

**자동화하지 않는다 — 수동 흐름 문서가 계속 진다.**

| 무엇 | 왜 |
|---|---|
| VoiceOver의 실제 발화 · 중복 · 포커스 위치 | 트리에 이름이 있는 것과 들리는 것은 다르다. 실기에서 사람이 듣는다 |
| Dynamic Type의 겹침 · 잘림, 색 · 간격 | Maestro는 보이는 모양을 판정하지 않는다 |
| 소프트 키보드 가림(K 행) | 시뮬레이터가 실물 키보드를 재현하지 않는다 |
| Apple 로그인 시트 · 웹 인증 창 · 권한 알림 | 시스템 UI이고 제공자 설정 · 서명 · Apple ID에 매여 있다 |
| 말하기(음성 인식) | 시뮬레이터에 마이크 입력을 넣을 수단이 없다 |
| 실기 전용 관찰 전부 | 시뮬레이터에서만 돌았다 |

**로그인 뒤의 흐름은 지금 열지 않는다.** 새 설치는 서버 없이 로그인을 지날 수 없고(e2e 공통 전제), 흐름이 테스트 계정
자격을 들고 있어야 한다. 자격을 어디에 두는지가 정해지기 전까지 자동화 범위는 **로그인 화면에 닿는 데까지**다.

### D6. 선택자는 보이는 문구 · 접근성 이름이다 — id는 아직 들이지 않는다

`tapOn: "Next"`처럼 쓴다. Lynx iOS에는 네이티브 `accessibilityIdentifier`를 지정하는 속성
`ios-platform-accessibility-id`가 있다(`Pods/Lynx/platform/darwin/ios/lynx/ui/LynxUI.m`). **이 저장소의 사용처는 0건이고
Maestro의 `id:`로 잡히는지는 확인하지 않았다.** 기존 `data-testid`는 vitest 환경용이라 네이티브 트리에 오지 않는다.

## 버린 대안

- **XCUITest** — 같은 접근성 트리를 본다. Swift 테스트 타깃과 서명 설정이 늘고, Android 호스트가 생기면 다시 써야 한다.
- **`@lynx-js/kitten-lynx-test-infra`를 지금 들이기** — Android 에뮬레이터와 Explorer APK가 전제다. 판정 환경이 자체
  호스트 앱이어야 한다는 기준(ADR-0012 D5)과도 어긋난다 — Explorer를 구동한다.
- **Detox · Appium** — Detox는 React Native 전용이다. Appium은 같은 트리를 보면서 서버와 드라이버 설치가 더 든다.
- **`idb`로 좌표 탭** — 지금까지의 수단이다. 화면 크기 · 레이아웃이 바뀌면 조용히 다른 곳을 누르고, 단언이 없다.
- **Debug Host + `--bundle-url=main.lynx` 실행 인자** — Maestro의 `launchApp` 인자가 그 꼴(`--이름=값` 한 덩이)로
  전달되는지 확인하지 않았고, Release가 인자 없이 같은 일을 한다(D2).

## 대가

- **문구가 바뀌면 흐름이 깨진다**(D6). 선택자가 접근성 이름이라 UI 문구표(ADR-0031)를 고치는 PR이 흐름 파일도 고쳐야 한다.
  강제 수단은 없다 — CI에서 돌지 않으므로(D4) 깨진 채로 머지될 수 있다.
- **사람이 기억해서 돌려야 한다.** `verify`가 초록이어도 e2e는 돌지 않은 것이다.
- **도구 버전이 고정되지 않는다.** Maestro는 저장소 밖에 설치되고 스스로 갱신을 권한다. 다른 버전에서 같은 결과가 나오는지
  모른다.
- **`clearState: true`는 그 시뮬레이터의 앱 데이터를 지운다.** 로그인해 둔 시뮬레이터에 돌리면 세션이 사라진다 — 전용
  시뮬레이터를 쓴다.
- **보조기술에서 가린 요소는 단언할 수 없다.** 안내 · 시트 · 대화상자가 떠 있는 동안 뒤쪽은 트리에 없다. 「뒤쪽이 그대로
  있다」는 관찰은 흐름으로 못 쓴다.
- **수동 흐름 문서는 줄지 않는다.** 자동화가 덮는 것은 D5의 한 줄뿐이고 나머지 행은 그대로 사람 몫이다.

## 재검토 조건

- 흐름 파일이 **문구 변경 때문에 두 번** 깨지면 → D6. `ios-platform-accessibility-id`가 Maestro `id:`로 잡히는지 확인하고
  선택자를 옮긴다.
- 테스트 계정 자격을 둘 자리가 정해지면 → D5. 로그인 뒤 흐름(여정 맵 · 학습 · 설정)을 연다.
- macOS 러너에서 시뮬레이터 빌드를 돌릴 수 있게 되면 → D4. CI에 넣을지 다시 본다. 그때 도구 버전도 고정한다.
- Android 호스트가 생기면 → D1 · D3 · D6. `maestro hierarchy`로 같은 접근성 이름이 잡히는지 먼저 본다. 잡히면 흐름 파일의
  `appId`를 실행 인자로 빼고 갈리는 단계만 `when: platform`으로 감싼다. 안 잡히면 선택자를 플랫폼별로 나눠야 한다.
- 실기에서 돌려야 하는 관찰이 자동화 후보로 올라오면 → D2. 시뮬레이터 외의 판정 환경은 확인한 적이 없다.

## 확인하지 않은 것

- 실기에서의 구동, Android, CI 러너.
- 문자 입력(`inputText`) · 스크롤(`scrollUntilVisible`) · 시스템 알림 처리. 통과한 흐름은 탭과 단언뿐이다.
- 로그인 뒤 화면 전부. 여정 맵은 계층 덤프만 봤고 흐름을 돌리지 않았다.
- 같은 흐름을 여러 번 돌렸을 때의 흔들림 — 두 번 돌렸고 두 번 통과했다.
