**왜 새 번호인가** — 콘텐츠 쪽이 새 형식을 보냈다는 **바깥 사실 하나**가 디코더 · 완료 판정 · 매핑 · 대화 조립 화면 · 내장 데이터의 결정을 한꺼번에 움직였다. 제자리로 흩으면 ADR 다섯에
조각이 흩어지고 *왜* 함께 바뀌었는지가 사라진다(ADR-0010 D10 넷째 줄).

근거 표시: **[코드]** 저장소 코드 · **[데이터]** 새 내장본 `apps/mobile/content/episodes/*.json` 전수 조사 · **[실측]** 빌드 · 실행 · **[실기]** iOS 시뮬레이터 관찰 · **[추론]** 관찰 없이 이어 붙인 것.

## 맥락

1. **판별자는 그대로인데 모양이 넓어졌다** [데이터]. 새 파일 셋도 `schema: "delivery-2"`다. 최상위에 `completion`이 더해졌고(`requires` = `S1` ~ `S8` · `CULT` · `RP`, 셋 같음),
   단계 id가 **이름째 바뀌었다** — 옛 내장본은 `S1` · `S3` ~ `S9` · `RP`, 새 것은 `S1` ~ `S8`(order 1 ~ 8) · `CULT`(9) · `RP`(10). 옛 `S3`은 새 `S3`과 다른 단계다.
   문항 355개(최종 테스트 13 포함), 유형 22종 — 새 유형 11종이 들어왔고 `PAIR_MATCH` · `SENT_BUILD`는 **새 데이터에 없다.**
2. **옛 디코더는 새 파일을 통째로 거부했다** [실측]. 셋 다 `unknown-item-type`이고, 새 유형을 걸러도 u02는 `VOCAB_CARD` 한 장(`S3-04`)에 `example`이 없어 `invalid-shape`였다.
3. **공통 새 필드가 모든 문항에 있다** [데이터]. `level`(정수) · `skill`(문자열, 지금 다섯 값) · `skill_level`(정수)이 355문항 전부에 있고 옛 내장본에는 없다. `event`에 `"D"`가 생겼다.
4. **대화 순서에 턴 화자가 실렸다** [데이터]. `TURN_ORDER.tiles[].speaker`(`"counterpart"` · `"player"`)가 29문항 전부에 있고, **15문항이 플레이어 줄부터** 시작한다.
   앱은 짝수 칸을 늘 상대로 그려 왔다(ADR-0058 D7) — 그 15문항에서 화자가 뒤바뀐 대화를 보인다. 옛 내장본에도 같은 문항(u01 `S3-05` 등)이 있었다 — 데이터에 화자가 없어 드러나지 않았던 기존 결함이다.
5. **문항 음성은 여전히 없다** [데이터]. 새 문항의 `stimulus.audio_url`은 전부 빈 값이다. 문항 그림은 처음으로 채워졌다 — `IMG_MATCH` 7 · `SPEAK_WORD` 6 · `ROLEPLAY_TURN` 13(버킷 응답 200 [실측]).

## 결정

### D1. 「추가만 하는 확장」 — 판별자 · 실패 단위는 그대로다

`schema`는 `"delivery-2"` 그대로 받는다. 새 키는 전부 **선택**이거나 새 유형 안에만 있어, 옛 내장본 · 단위 테스트 픽스처 · 버킷의 옛 본문이 같은 결과로 디코드된다. 실패는 지금처럼 에피소드 단위다.

### D2. 새 11종의 와이어 모양 — 「관찰에서 전부 있으면 필수, 일부면 선택」

`KNOWN_ITEM_TYPES`가 13종에서 **24종**이 됐다. 새 11종(`CLOZE_CHOICE` · `REPLY_SELECT` · `MIN_PAIR_AB` · `PARTICLE_FILL` · `PARTICLE_SWAP` · `CULTURE_CHECK` · `CULTURE_CARD` ·
`LISTEN_BUILD` · `SYLLABLE_BUILD` · `SHADOW` · `SPEAK_WORD`)의 키는 콘텐츠 계약 §7.2의 관찰 원칙을 잇는다. 같은 모양끼리 와이어 조각을 나눠 쓰되 **모델은 유형마다 한 갈래**다
(`Extract`로 좁혀진다). 정답 하나 불변식(`option-correct-count`)은 보기가 있는 새 유형 전부에 그대로 걸린다.
기존 유형의 변화도 받는다 — `VOCAB_CARD.example`이 **선택**이 됐고(없으면 예문 없이 선다), `TRANSLATE_TO_KO` · `WORD_ORDER`의 `stimulus.en`(옮길 영어 원문), `TURN_ORDER.tiles[].speaker`,
`ROLE_LINE.feedback.wrong.en`을 읽는다.
와이어 스키마는 파일 셋으로 나뉘었다(`lib/episode-content.schema.ts` · `-schema-parts.ts` · `-schema-items.ts` — 300줄 한도), 새 유형의 변환은 `lib/episode-content.items-added.ts`다. 넷 다 `background-only`다.

### D3. 공통 새 필드 — 디코드만 하고 쓰지 않으며 열거하지 않는다

`level` · `skill_level`은 선택 정수, `skill`은 **선택 문자열**이다 — 닫힌 목록이 아니어서 콘텐츠가 값을 늘려도 에피소드가 거부되지 않고, 앱 코드에 「읽기」 같은 한국어 리터럴이 생기지 않는다.
모델 키는 `level?` · `skill?` · `skillLevel?`. `event`만 닫힌 목록에 `"D"`를 더했다. 화면 · 계획 · 이벤트는 이 필드를 읽지 않는다.

### D4. 버리는 키 — 지금 정책 그대로

최종 테스트의 `steps[RP].scene` · `roleplay.lead` · `roleplay.reask` · `words[].use` · `patterns[].use` 등은 스키마에 적지 않는다 — 모르는 키는 조용히 버린다. 쓰기 전에 모양을 고정하면
콘텐츠 쪽 수정마다 디코드가 깨질 수 있다. PR ② · ③이 쓸 키(문화 카드 본문 · 말하기 정답 등)는 **새 11종 안에 있어** 지금 고정했다.

### D5. `completion.requires` — 모델에 보존하고, 검사는 의미 단계에서

- 모델 `Episode.completion?: { requires }` — 중복은 앞의 것만 남기고 와이어 순서를 지킨다. 없으면 키가 없다.
- 새 디코드 코드 **`completion-malformed`**(실패): `requires`가 비면 경로 `completion.requires`, 원소가 `steps[].id`(`RP` 포함)에 없으면 `completion.requires[i]`. `"intro"`는 단계가 아니라 거부한다.
- 실패시키는 이유: 경고로 두고 모르는 id만 버리면 남은 목록이 비거나 `RP`가 빠져 「완료 불가」나 「즉시 완료」 에피소드가 조용히 생긴다. 실패하면 원격본은 **내장 폴백**이 막고, 콘텐츠 쪽은 경로가 든 오류를 받는다.
  `RP` 포함은 강제하지 않는다 — 콘텐츠의 정책이다(지금 데이터는 포함).

### D6. 에피소드 완료 = 완료 키가 모두 끝남 — 판정 함수 하나, 소비자 셋

- `lib/catalog-progress.ts`: `isCatalogEpisodeComplete(progress, episodeId, completionKeys)` = 키마다 끝냈는가. 키가 비면 `DEFAULT_CATALOG_COMPLETION`(`["RP"]`)으로 본다.
  `completedCatalogEpisodeCount(progress, completionKeysOf)` = 진행에 있는 에피소드 가운데 완료인 수.
- 완료 키의 출처는 **맵 구획**이다 — `CatalogReadySection.completionKeys` = `episode.completion?.requires ?? [episode.finalTest.id]`. 콘텐츠를 모르는 id(진행에만 남은 에피소드 · 준비 안 된 구획)는
  기본값 — **지금 규칙과 같은 결과**다.
- 소비자 셋: ① 다음 에피소드 표지 열림(`catalogCoverStatus`), ② 트로피(`trophyCountFrom`의 셋째 인자), ③ (간접) 학습 화면 머리 칩(⟨2026-10-20⟩ 학습 중 상단 줄을 걷어 지금은 결과 화면의 칩만). 진행 훅(`useJourneyProgress`)은 콘텐츠를 모르므로
  **판정 규칙을 셋째 인자로 주입받는다** — 세션이 맵 구획에서 만든 `catalogCompletionKeysOf(sections)`.
- **지웠다**: `isCatalogEpisodePassed` · `passedCatalogEpisodeCount`. 이름이 「`RP` 통과」를 뜻해 남기면 잘못 쓰인다.
- **바꾸지 않았다**: 사슬 잠금(표지 → 레슨들 → 최종), 최종 테스트 통과 뒤 컷 · 「Episode clear!」 배너 · `episode_final_passed`(모두 「`RP` 통과」라는 **사건**이다).
  사슬 때문에 앱 안에서 `RP`를 끝냈다면 앞 단계는 이미 끝나 있다 — 두 판정이 갈리는 것은 **다른 버전의 진행 키가 남은 경우뿐**이다(아래 「대가」 2).
- 버린 대안: 진행 저장에 「에피소드 완료」 키를 따로 적기 — 서버 형식 · 병합 규칙이 늘고, 콘텐츠의 `requires`가 바뀌면 낡는다.

### D7. 문화 단계(`CULT`) — 이름으로 분기하지 않는다

디코더는 `"RP"`만 특별히 본다(지금 그대로). `CULT`는 `units`의 아홉째라 맵 노드 **`Lesson 9`**(role `lesson`, 낭독 `Episode 1. Lesson 9`) · 진행 키 `"CULT"` · 이벤트 `unitKey: "CULT"` ·
`unitRole: "lesson"` · 계획 · 결과 화면이 모두 기존 레슨 경로를 탄다. 제품 코드에 `"CULT"` 리터럴이 없다. 문화 단계 전용 라벨 · 아이콘은 PR ②와 함께 본다(Q5).
⟨2026-10-16 — PR ②⟩ **노드 `Lesson 9`는 이 변경의 상태다** — 이제 문항이 모두 문화 유형인 유닛은 콘텐츠로 가려 노드 role `culture`(`Culture` · `lantern-05` · `Episode n. Culture` · 한 줄 전용)로 선다([ADR-0066](0066-episode-format-screens.md) D7).
진행 키 · 이벤트 `unitRole` · 계획 · 결과 화면은 그대로 레슨 경로이고 **`"CULT"` 리터럴 0도 그대로다.**

### D8. 매핑 — 「베끼기 기준」으로 소리 없는 유형을 가르고, 화면이 없는 유형은 `screen-pending`으로 건너뛴다

소리 자극 유형은 **「대본을 글로 보이면 답이 드러나는가」**로 가른다 — ADR-0058 D3이 오디오 없는 듣기를 건너뛴 사유를 일반화한 것이다.

| 유형 | 학습형 · 결과 | 근거 |
|---|---|---|
| `CLOZE_CHOICE` | 단어 선택 — 제시문 `context`(빈칸 문장) · 로마자 · 번역 줄, 보기 `options[].ko`(**콘텐츠 순서**), 지시문 `prompt.en` | 형제 `CLOZE`와 같은 꼴. 보기는 섞지 않는다(`ROLE_LINE`과 같다) |
| `REPLY_SELECT` | 단어 선택 — 제시문 = 상대 말 `stimulus.audio.ko`(+ 로마자 · 번역), 지시문 `How do you reply?` | 대본(상대 말)과 정답(내 대답)이 다른 문장이라 드러나지 않는다. **듣기가 읽기가 된다 — 사용자 결정**(Q3) |
| `PARTICLE_FILL` · `PARTICLE_SWAP` | 단어 선택 — 제시문 `stimulus.text`(빈칸 문장 / 틀린 구 「봉투이」), 보기 조사 | 글 자극 + 보기. `SWAP`은 지시문 `Fix the particle.`이 뜻을 진다 |
| `MIN_PAIR_AB` | 듣기 모양이지만 **건너뜀 `audio-missing`** | 대본 「빵」 = 정답 「빵」이라 드러난다. 문항 음성이 오면 `LISTEN_SELECT`와 같은 자리에서 매핑 변경 없이 선다 |
| `LISTEN_BUILD` | **건너뜀 `screen-pending`** | 대본 = 조립할 문장이라 드러나고, 문장 조립 화면에 소리 제시 자리가 없다 — 소리가 와도 서지 않는다 |
| `SYLLABLE_BUILD` | **건너뜀 `screen-pending`** | 문장 조립은 칩 사이를 띄어 잇는 화면이라 「음절을 붙여 낱말 하나」의 뜻을 잃는다(Q8) |
| `CULTURE_CARD` | **건너뜀 `screen-pending`** | 단어 카드는 「New word · Learn this word.」 화면이라 세 문장 산문을 실으면 뜻이 바뀐다 |
| `CULTURE_CHECK` | **건너뜀 `screen-pending`** | 「카드에 적힌 사실」을 묻는 문항이고, 단어 선택은 보기의 번역을 보이지 않아 긴 한국어 보기를 초급자가 못 읽는다. 카드와 함께 PR ②에서 연다(Q2) |
| `SHADOW` · `SPEAK_WORD` | **건너뜀 `screen-pending`** | 말하기 — PR ③ |

⟨2026-10-16 — PR ②⟩ **위 표의 `LISTEN_BUILD` · `SYLLABLE_BUILD` · `CULTURE_CARD` · `CULTURE_CHECK` 네 행은 이 변경의 상태다** — 문화 카드 · 음절 조립은 새 학습형, 문화 확인은 보기 번역 줄을 단 단어 선택으로 서고,
`LISTEN_BUILD`는 **`audio-missing`**으로 건너뛴다(사용자 결정 — 소리가 먼저, [ADR-0066](0066-episode-format-screens.md) D1 · D8). `screen-pending`은 이제 말하기 둘만 낸다. 사유는 여덟 그대로다.
⟨2026-10-16 — PR ③⟩ **위 표의 `SHADOW` · `SPEAK_WORD` 행도 이 변경의 상태다** — 읽기(`read-aloud`, 채점 없음) · 낱말 말하기(`speak-word`, 채점)로 서고 `screen-pending`은 지워졌다(사유 일곱 — [ADR-0067](0067-episode-format-speaking.md) D1 · D9).

- **건너뜀 사유 `screen-pending`을 되살렸다** — 3d-1이 지운 이름이다(ADR-0058 적용 기록 A2). 「유형에 맞는 화면이 아직 없음」이라는 뜻이 같고, PR ② · ③의 목록이 곧 이 사유를 받는 유형이다.
  사유는 **여덟**이 됐다 — `screen-pending` · `no-options` · `no-source` · `audio-missing` · `image-missing` · `no-gloss` · `untypeable` · `malformed`.
- 기존 유형의 차분: `TURN_ORDER`의 칸 화자(D9) · `WORD_ORDER` 제시 영어와 `TRANSLATE_TO_KO` 단서는 **`stimulus.en`을 먼저**, 없으면 지금처럼 정답의 `en` · `VOCAB_CARD`는 예문이 없으면 예문 없이.
  나머지 아홉 종은 그대로다(`ROLEPLAY_TURN`은 레슨에서 지금처럼 `malformed`).
- **새 데이터의 결과** [데이터 — unit 테스트가 실제 값으로 고정]: 문항이 0개가 되는 단계는 세 에피소드의 `CULT`뿐이고, 나머지 단계는 모두 1개 이상 선다.
  듣기 학습형(`LISTEN_SELECT` 58 · `MIN_PAIR_AB` 6)은 카탈로그에서 여전히 한 번도 서지 않는다. 그림 문항(`IMG_MATCH` 7)은 그림 주소가 채워져 **처음으로 선다**.

### D9. 대화 조립의 화자는 콘텐츠의 턴 화자다 — `dialogue: true` → `dialogue: { speakers }`

- 문항 타입 `SentenceOrderQuestion.dialogue`가 `true`에서 **`{ speakers }`**(칸마다 화자, 길이 = 칸 수)로 바뀌었다. 화면(`SentenceOrderDialogue`)은 칸을 `speakers`로 그린다 — prop `slotCount`가
  `speakers`로 바뀌었다. 화면의 짝 · 홀 함수(`dialogueSpeakerAt`)는 지웠다. boolean 모양이 데이터 모양으로 바뀐 것이다.
- 순수 함수 `catalogTurnSpeakersOf(tiles, answer)`(`app/catalog-item-map.ts`): 정답 순서의 타일이 **모두** 화자를 가지면 그대로(`player` → 나), **모두** 없으면 짝 · 홀(지금 규칙 —
  옛 데이터의 결과 불변), **섞여 있으면** 문항을 `malformed`로 건너뛴다(뒤바뀐 대화를 그리지 않는다).
- **같은 화자가 연이어 서는 칸도 데이터대로 그린다** — 말풍선 모양 · 색은 기존 두 화자 클래스뿐이고 새 시각이 없다. 지금 데이터 29문항에는 연속 칸이 없다(ui 테스트 픽스처에만 있다).
- 시각 · CSS · 문구 · testid · 낭독 문구는 바뀌지 않았다 — 칸의 화자 **값**만 데이터에서 온다. 클래스 · `data-speaker` · 낭독 이름이 같은 값 하나에서 나와 시각과 낭독이 갈릴 길이 없다.
- 이번 PR에 넣은 것은 **사용자 결정**이다(Q4).

### D10. 문항이 하나도 남지 않는 단계 — 기존 「곧장 결과」 경로가 실데이터에서 처음 일어난다

`CULT`는 문항 여섯(`CULTURE_CARD` · `CULTURE_CHECK`)이 전부 `screen-pending`이라 활동이 0개다. 노드를 누르면 ADR-0058 D5 · A4의 경로 그대로 —

결과 화면(`PERFECT LESSON!`)이 쌓인다. **코드 변경은 0이고 테스트로 고정했다.** 새 빈 상태 · 안내 문구는 만들지 않았다. **0문항 그대로가 사용자 결정**이다(Q2).
⟨2026-10-16 — PR ②⟩ **해소됐다** — `CULT`는 문화 카드 3 → 문화 확인 3의 실단계이고(채점 3 · 표시 6) 레슨 공통 통과 기준(셋 중 둘)이 걸린다(사용자 결정, [ADR-0066](0066-episode-format-screens.md) D9). 0문항 경로는 코드에 남고 합성 픽스처 테스트가 지킨다.

### D11. 옛 내장본은 테스트 픽스처로 남긴다

`apps/mobile/content/test-fixtures/delivery-2-2026-10-14/`에 옛 내장 셋과 매니페스트를 **바이트 그대로** 옮겼다. 제품 코드가 import하지 않아 번들에 실리지 않는다.

2. **`LISTEN_BUILD`의 사유는 `screen-pending`이다** — 디자인 초안은 `audio-missing`이었다. 소리가 와도 문장 조립에 소리 제시 자리가 없어 서지 않으므로 「소리만 오면 선다」로 읽히는 사유를 피했다.
3. **세션 파일의 줄 수(300줄 한도)는 순증 0이다** — 맵 구획 메모를 진행 훅 호출 위로 옮기고 셋째 인자를 넘겼다.
4. **단어 선택의 빈칸 낭독을 고쳤다**(접근성 감사 지적) — 제시문 · 로마자 줄에 밑줄 둘 이상(`___`)이 있으면 그 줄의 낭독 이름이 밑줄 자리를 `blank` 낱말로 바꾼 문장이다
   (`wordChoiceSpokenText` — 「카드___ 할게요.」 → 「카드 blank 할게요.」). 밑줄이 없는 줄은 낭독 이름을 따로 두지 않아 보이는 글자가 그대로 읽힌다. 보이는 글자는 바뀌지 않는다.
   낱말은 최종 테스트 빈칸과 같은 문구(`copy.common.blank`)이고 이어 붙이는 방식만 다르다(최종 테스트는 쉼표로 가른다). 새 문구 키 · 새 traits는 없다.
   이번 데이터가 이 자리에 새 유형 10문항(`PARTICLE_FILL` 6 · `CLOZE_CHOICE` 4)을 더 싣기 때문에 같은 PR에서 고쳤다 — `CLOZE` 38문항에도 원래 있던 결함이다.
5. **⟨2026-10-16⟩ 콘텐츠 경로의 선두 `content/`를 앱이 뗀다**(사용자 결정) — 같은 날 버킷 업로드가 그림 경로를 `content/images/…`로 적기 시작했다. 앱 기준이 이미 `content` 버킷이라 그대로 붙이면
   `…/content/content/…`가 되어 400이다. 콘텐츠를 되돌리는 대신 `resolveContentUrlSafe`가 선두 `content/` 조각을 한 번 떼게 했다 — 그림 · 음성 · 본문 받기가 모두 이 함수를 지난다.
   두 꼴(`images/…` · `content/images/…`)을 모두 받는다. 조각은 한 번만 떼고, 뗀 뒤에도 빈 값 · `..` 거부는 그대로다.

## 대가

1. **번들 +104,765 bytes**(1,917,303 → 2,022,068, 운영 설정, +5.46 %) [실측]. 대부분이 내장 JSON의 교체(압축 표현 약 +97.6 kB)다. 상한은 1,919,000 → 2,024,000으로 올렸다(**사용자 사전 승인**) —
   [성능 보고서](../performance/reports/episode-format-v3-iphone-17-pro-simulator-01.md) · `devtools/bundle-size/budget.json` note.
2. **옛 진행의 완료가 뒤로 간다**(Q1 — 알고 받아들였다). 옛 빌드로 u01을 끝낸 기기의 진행은 `intro · S1 · S3 ~ S9 · RP`라 새 규칙으로는 `S2` · `CULT`가 없어 **완료가 아니다** —
   트로피가 하나 줄고 u02 표지가 다시 잠긴다(이미 끝낸 표지는 그대로 보인다). `S2`와 `CULT`(누르면 곧장 끝난다)를 하면 돌아온다 [실기 — 아래 e2e]. 옛 `S3` ~ `S8`은 새 콘텐츠의
   **다른 단계**를 끝낸 것으로 보이고 옛 `S9`는 아무것도 가리키지 않는다(세지 않는다 — 테스트로 고정). 진행 키 이전은 하지 않았다 — 단계 내용이 1:1이 아니라 근거가 없다. 출시 전 테스터 기기만 해당한다.
3. **같은 진행에서 사건과 판정이 갈릴 수 있다** — 옛 진행에서 `RP`만 다시 치르면 통과 뒤 컷 · 「Episode clear!」가 서지만 완료 키가 남아 있으면 트로피는 늘지 않는다.
4. **`REPLY_SELECT`는 듣기 문항인데 읽기로 선다**(Q3). 듣기 학습형은 카탈로그에서 여전히 0번 선다(`LISTEN_SELECT` · `MIN_PAIR_AB`는 문항 음성이 올 때까지 빠진다).
5. **빈칸 문장의 번역 줄이 정답을 암시할 수 있다** — `CLOZE`에 `context.en`이 생겨 「___ 할게요.」 아래 「I'll pay by card.」가 선다. 콘텐츠가 넣은 값이고 지금 규칙(있으면 보인다)이라 그대로 뒀다.
   `CLOZE_CHOICE`도 같다.
6. **`why_wrong` · `feedback.correct`는 디코드만 되고 화면에 서지 않는다**(지금과 같다). 최종 테스트의 `scene`(장면 그림 · 맺음말 · 재시도)과 턴의 `stimulus.image_url`도 쓰지 않는다 —
   최종 테스트 장면은 지금처럼 표지 컷에서 고른다.
7. **그림 문항이 로드되는 동안 보기의 낭독이 「누를 수 없다」를 말하지 않는다**(접근성 감사 지적 — 수용). 보기는 흐리게 서서 탭을 받지 않는데 낭독은 그대로 「봉투, button」이다.
   3d-1부터 있던 코드이고 그림이 실데이터에서 서는 것이 이번이 처음이라 실제로 드러난다. 후속은 ADR README 보류 표 「그림 문항 로딩 중 보기의 낭독」.

### ⟨2026-10-22⟩ 학습 문항 음성 · 「천천히」

결정은 [ADR-0082](0082-item-audio-and-slow-playback.md) D4 · D8 · D9. 이 문서의 결정 문장은 바뀌지 않는다 — D8 표의 세 행에 닿는 자리만 적는다.

- **`MIN_PAIR_AB`는 매핑 규칙을 바꾸지 않고 섰다**(재검토 조건 1 전반) — 듣기 매핑 함수의 소리 자리가 실제 주소를 내어, 소리가 있으면 듣기 화면(3열 줄 · `Slow`)으로 서고, 없으면 건너뛰지 않고 대본 + 보기의 소리 없는 듣기 화면으로 선다(ADR-0082 v4 정정 — `audio-missing`은 이제 `LISTEN_BUILD`의 것만).
- **`REPLY_SELECT`는 듣기로 옮기지 않았다**(재검토 조건 1 후반) — 단어 선택 그대로이고, 상대 말(제시문 · 로마자 · 뜻)도 **그대로 보인다.** 소리가 있으면 그 다음에 간이 줄(다시 듣기 · `Slow`)이 서고 문항이 설 때 한 번 자동 재생한다. 「듣기가 읽기가 된다」(Q3)는 글이 남아 있어 여전히 참이다.
- **`LISTEN_BUILD` 행** — 소리가 있으면 **문장 순서 화면**(상대 말풍선 자리에 재생 줄, 대본 없음)으로 선다. 소리가 없으면 지금처럼 `audio-missing`. 화면 결정은 [ADR-0066](0066-episode-format-screens.md) 적용 기록 ⟨2026-10-22⟩.
- 그 밖의 소리 있는 새 유형(`SYLLABLE_BUILD` · `SPEAK_WORD` · `IMG_MATCH`)은 판정 순간 정답 음성을 1.0으로 한 번 낸다(ADR-0082 D5). 와이어 모양 · 디코드는 바뀌지 않았다.
