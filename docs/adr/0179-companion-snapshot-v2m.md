# ADR-0179: 스냅샷 v2m — 장면 설계(플랜) + 코드 조립 + 미리 합친 기준 그림 한 장

- 상태: **채택 — 서버 파일, 운영 미적용**. 브랜치 `feat/companion-snapshot-v2m`. 스위치 `COMPANION_SNAPSHOT_PIPELINE` 기본값은 `v1`이다(바꾸지 않으면 지금과 같다).
- 날짜: 2026-11-24
- **사용자 결정** (2026-11-23 ~ 24, 운영 대시보드 스냅샷 실험실에서 평가 세트를 세 번 비교한 뒤):
  - 방식 = **v2m**: 회전 시트 · 고른 표정 얼굴 · (기본 옷이 아니면) 의상 그림을 **한 장으로 합친** 기준 그림. 따로 넣는 v2a와 품질이 비슷했고 v2m이 더 싸다.
  - 의상 = 기본 옷이 원칙. 장면이 정말 다른 옷을 요구할 때만(날씨 · 활동 · 행사 · 집 · 일) 바꾼다.
  - 학습자 = **실제로 함께 있을 때만** 그림에 넣는다. 채팅 · 전화 중이면 넣지 않는다.
  - 체형 유지 = 다은 · 서연 · 건우 · 해준처럼 디자인에 몸매 · 옷 핏이 들어 있는 인물은 「단정하게, 체형 강조 없음」 대신 「기준 그림 그대로, 더 강조하지는 않게」.
    **연령대와 상관없이** 켠다(엔진 회사 가드레일 안쪽이면 괜찮다). 선정적 자세 · 성적 내용 금지는 그대로다.
  - 새 옷 = 옷장에 없는 옷을 고르면 **글로만 그리고 후보는 기록만** 한다. 운영 대시보드가 **이틀에 한 번 새벽에** 모아 의상 그림을 그리고, 사람이 채택하면 다음 묶음에 들어간다.
  - 미성년자 · 나이 모름 규칙 = 「침실 금지」를 **「인물 혼자 자기 방은 괜찮고, 학습자가 그 방에 함께 있는 장면은 금지」**로 바꾼다(v1에도 적용).
  - 켜는 순서 = 처음에는 **시험 계정만**(`v2m-test`), 확인한 뒤 모두(`v2m`).
- 위: [ADR-0146](0146-companion-snapshot-voice.md)(스냅샷 · 음성) · [ADR-0152](0152-companion-romance-refusal-charge-unlock-message.md)(성인 수위선 · 검사 노드 스위치).

## 맥락

- v1은 Haiku가 이미지 프롬프트를 자유롭게 쓴다. 실험실에서 보니 비슷한 구도(정면 · 상반신 · 미소)가 되풀이되고, 표정을 글로만 시켜서 엔진이 웃는 얼굴로 쏠렸다.
  옷도 매번 시트의 옷이라 비 오는 날 · 집에 있는 새벽 같은 장면이 어색했다.
- 실험실(ops-dashboard `snapshot_v2.py` · `snapshot_assets.py`)에서 장면 설계 + 얼굴 에셋을 만들고 블라인드로 비교했다(평가 세트 12장면 × 3방식, 2026-11-23).
  생각 · 당황 · 슬픔처럼 웃는 얼굴이 아닌 표정에서 에셋 효과가 뚜렷했고, 얼굴 동일성은 21장 모두 4 ~ 5점이었다.
- 운영 Edge Function에서 그림을 합치면 느리고 CPU 한도에 걸릴 수 있다 — 대시보드가 미리 합쳐 버킷에 올린다.

## 결정

### D1. 장면 설계 노드(snapshot_plan)

- 프롬프트 노드 대신 **정해진 칸만 채우는** 도구를 쓴다: 구도(5) · 각도(11) · 표정(8) · 옷 바꾼 까닭(6) · 옷 id 또는 새 옷 · 학습자(none · back_view · hands) ·
  동작 · 장소 · 빛 · 비율 · 배경 글 · 안전 판단. 글은 실험실 `PLAN_SYSTEM`을 그대로 옮겼다(`companion-snapshot-v2.ts`).
- 받은 값은 코드가 정리한다(`normalizePlan`): 목록 밖 값은 무난한 값, 까닭이 none이면 기본 옷, 학습자가 없는데 어깨 너머면 미디엄(끼워 넣지 않는다),
  셀카면 학습자 없음, 학습자 모습이 「손만」이면 뒷모습 대신 손.
- **다양성**: 그 유저 × 인물의 최근 v2m 계획 6개(`companion.media.prompt`)를 「피할 것」으로 보여 주고, 최근에 덜 쓴 구도 · 각도를 권한다(어깨 너머는 권하지 않는다).
- 수위: 성인은 실험실 글 그대로(손잡기 · 포옹까지), 미성년자 · 나이 모름은 「로맨스 없음」 줄 + v1과 같은 엄격한 규칙 + 입력 데이터 규칙.

### D2. 코드가 이미지 프롬프트를 조립한다

- 계획 칸 → 고정 문장(구도 · 각도 · 표정 · 옷 · 학습자 · 배경 글 · 기준 그림 역할). 모델이 규칙 문장을 바꾸지 못한다.
- 기준 그림 문장은 「왼쪽은 인물(네 방향), 오른쪽 위는 쓸 표정, 오른쪽 아래는 입을 옷 — 각 부분은 그 용도로만, 배치 · 칸을 따라 그리지 말 것」.
  표정 칸이 있으면 「머리 크기 · 몸 비율은 왼쪽 인물대로」를 붙인다(표정 그림 때문에 다리가 짧아졌던 것, 실험실 2026-11-23).
- 끝 문장: 보통 인물은 `Modest clothing, no body emphasis.`, 체형 유지 인물(묶음 `figureKeep`)은 「기준 그림의 몸매 · 옷 핏 그대로, 깎지도 더 강조하지도 말 것.
  선정적 자세 없음」.

### D3. 기준 그림 묶음(대시보드가 만든다)

- `companion-refs/v2/<slug>/manifest.json` + 표정 8 × 그림 있는 승인 옷마다 한 장(`<expression>.png` · `<expression>--o<id>.png`).
  slug는 시작 RPC가 고른 `<slug>-ref.png`에서 얻는다 — **시작 RPC는 고치지 않는다**.
- manifest: 옷장(id · 이름 · 설명 · 기본 여부 · 그림 여부) · 체형 유지 · 파일마다 역할(angles · expression · outfit)과 합침 여부.
- 계획의 표정 × 옷 칸 → 없으면 기본 옷 칸 → 없으면 무표정 칸. 그림 없는 승인 옷은 기본 칸 그림 + 옷 설명 글.
- 묶음은 운영 대시보드 「운영용 묶음 만들기」(ops-dashboard `snapshot_bundle.py`)가 만든다. 버킷에 올리는 건 사람이 확인한 뒤다.

### D4. 스위치와 되돌아가기

- `COMPANION_SNAPSHOT_PIPELINE`: `v1`(기본) · `v2m`(모두) · `v2m-test`(시험 계정 `duru_tester`만 v2m).
- v2m이어도 다음이면 **그 스냅샷은 v1으로** 그린다: slug를 모름 · 시험 계정 아님(`v2m-test`) · 묶음 없음 · 묶음 모양이 틀림 · 묶음을 못 읽음.
  까닭은 `meta.v2`, 쓴 방식은 `meta.pipeline`에 남는다.
- 결과 행 `prompt`에 계획(+ 권한 구도 · 옷 이름 · 기준 그림 경로 · 체형 유지)을 남긴다. 앱에는 나가지 않는다(`media_json`에 없음).

### D5. 확인 노드

- 켰을 때(또는 미성년자 · 나이 모름) v2m 글을 쓴다: v1 항목 + **학습자 배치가 계획과 맞는지**(`learner_matches`). 맞지 않으면 탈락.
- 체형 유지 인물은 「기준 그림 수준의 핏 · 목선은 강조가 아니다 — 기준 그림보다 과하거나 몸에 초점을 맞춘 자세 · 구도만」을 더한다.

### D6. 새 옷 후보(이틀에 한 번 새벽)

- 새 옷을 고른 스냅샷이 완료되면 `companion_snapshot_outfit_candidate`로 **옷 설명만** 기록한다(대화 글 · 유저 id는 남기지 않는다). 실패해도 스냅샷은 그대로.
- 운영 대시보드 크론이 `companion_snapshot_outfit_candidates_pending`으로 모아 비슷한 옷을 합치고 의상 그림을 그린 뒤(상한 있음) `…_mark`로 표시한다.
  채택은 사람이 하고, 채택된 옷은 다음 묶음에 들어간다. 크론은 이 PR 밖(ops-dashboard)이다.

### D7. 미성년자 규칙 — 자기 방

- 프롬프트 · 장면 설계 · 확인 노드의 미성년자 규칙에서 「침실」을 「학습자가 인물과 함께 침실에 있는 장면」으로 좁힌다. 인물 혼자 자기 방은 괜찮다.

## 결과

- 스위치를 켜기 전에는 아무것도 바뀌지 않는다(미성년자 규칙 D7만 v1에도 적용된다).
- 원가: 기준 그림이 한 장(1536 × 768 이하)이라 지금(`all` — 시트 + 표정 시트)보다 입력이 작다. 장면 설계 출력이 조금 길다(Haiku).
- 시간: 묶음 · 맥락 읽기와 기준 그림 한 장 내려받기가 장면 설계 앞뒤로 한 번씩 더 든다(실험실 기준 1초 안쪽).

## 운영 반영 순서(각 단계 사람이 확인)

1. 마이그레이션 적용(`20270101120000_companion_snapshot_v2m.sql`) · Edge Function 배포 — 스위치는 `v1` 그대로.
2. 대시보드 「운영용 묶음 만들기」 결과를 `companion-refs/v2/`에 올린다.
3. `COMPANION_SNAPSHOT_PIPELINE=v2m-test` — 시험 계정으로 앱에서 확인.
4. 시간 · 원가 · 차단율을 v1과 견준 뒤 `v2m`.
