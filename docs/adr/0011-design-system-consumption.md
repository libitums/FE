# ADR-0011 — 디자인 시스템 소비 경계

- 상태: 대체됨
- 날짜: 2026-08-25
- 대체한 것: **ADR-0014** (2026-09-01)
- 다루는 축: 디자인 토큰, 컴포넌트 프리미티브, 아이콘, private registry 인증
- 대체: **ADR-0008**

> **이 ADR은 ADR-0014로 대체됐다.** 패키지를 설치해 보기 전에 쓴 결정이라,
> 실제로 호스트에 올려 확인한 사실과 어긋나는 부분이 있다. **D1의 근거 중
> "중첩 참조"는 사실이 아니고, D2의 인증 형태는 더 이상 동작하지 않는다.**
> 보류 표의 두 항목(버전 범위·아이콘 소비 형태)도 ADR-0014에서 닫혔다.
> 지금 따라야 하는 것은 [ADR-0014](0014-design-system-consumption-verified.md)다.
>
> **D3만은 살아남아 있었다** — 컴포넌트 프리미티브 축이 ADR-0014의 `다루는 축`에 없어서,
> 대체된 이 문서 안의 D3이 유일한 근거였다. **2026-09-02에
> [ADR-0015](0015-component-primitives-and-style-application.md) D3으로 옮겼다.**
> 이제 이 문서에는 유효한 결정이 하나도 없다 — 어느 D도 여기서 인용하지 않는다.

## 맥락

ADR-0008은 **토큰을 이 저장소가 소유한다**고 전제했다. `apps/mobile/src/styles/tokens.css`
하나가 유일한 출처이고, 값은 디자인 작업이 나중에 채운다는 그림이었다.

**사실이 아니다.** 별도의 design-system 저장소가 원본을 소유하고, 값은 이미 확정돼 있다.
경계는 LIB-108에서 이미 결정됐다.

```text
foundations/*.json + components/**/*.md + assets/icons/**/*.svg   ← 원본
                          │
                          ▼  validate / build      (design-system 소유)
        @libitums/design-tokens  +  @libitums/icons   ← GitHub Packages, private
                          │
                          ▼
              FE 모노레포 / @libitums/ui-lynx        (이 저장소 소유)
```

원본에는 색 33 · 타이포 22 · 4px 리듬 간격 · layout · radius · elevation · motion ·
iconography가 [W3C Design Tokens 포맷](https://tr.designtokens.org/format/)으로 들어 있고,
아이콘 SVG가 815개 × 2 변형 있다. 컴포넌트 스펙(Button 5종 · Dialog · Bottom Sheet ·
Bottom Navigator · Header · Indicator)도 Markdown으로 있다.

**이 ADR이 정하는 것은 소비 쪽 규칙뿐이다.** 원본·패키지 이름·배포처는 design-system이
정했고 여기서 다시 정하지 않는다. 정할 것은 넷이다 — 어떤 형태로 쓰나, 어떻게 설치하나,
컴포넌트를 어디에 두나, 값이 필요할 때 무엇을 하나.

## 결정

### D1. 토큰은 **CSS 커스텀 프로퍼티로만** 소비한다

`@libitums/design-tokens`는 CSS 변수와 TypeScript 상수를 **둘 다** 제공한다.
**첫 단계에는 CSS 변수만 쓴다.**

```tsx
// 쓴다
<view className="card" />
```
```css
.card { background: var(--color-bg-surface); padding: var(--spacing-16); }
```
```tsx
// 안 쓴다
import { spacing } from '@libitums/design-tokens';
<view style={{ padding: spacing[16] }} />
```

**근거:**

- Lynx의 CSS 변수는 웹 표준과 거의 같다 — `:root` 스코프, 상속·캐스케이드,
  `var(--x, fallback)`, 중첩 참조, `calc()`, 런타임 `setProperty()`. 우회할 이유가 없다.
- 값이 **한 경로로만** 흐른다. 두 경로를 열어두면 같은 색이 어디서 오는지를 매번 추적하게 된다.
- 상속과 클래스 전환을 그대로 쓸 수 있다. TS 상수로 가면 인라인 스타일이 되고 그 둘을 잃는다.

**여는 조건**: JS에서 토큰 값을 **계산하거나 분기해야 하는 첫 사례**가 실제로 나올 때.
그때 그 사례를 근거로 규칙을 연다. 미리 열어두지 않는다.

> **알고 감수하는 실패 하나**: `var(--오타)`는 **조용히 무시된다.** 에러가 없고,
> 테스트 환경이 스타일을 계산하지 않으므로(ADR-0006 D4의 제약) 테스트로도 안 잡힌다.
> **토큰 이름 오타는 기기에서 눈으로만 발견된다.** TS 상수 경로였다면 컴파일 타임에
> 잡혔을 것이다 — 이 안전망을 포기하고 위의 셋을 얻는다.

### D2. private registry 인증 — `.npmrc`를 **커밋하고** 토큰은 환경변수로

> **스코프는 `@libitums`다 — 브랜드(`libitum`)가 아니라 GitHub 조직명(`libitums`)을 따른다.**
> GitHub Packages가 조직명을 스코프로 강제하기 때문이고, 우리가 고를 수 있는 것이 아니다.
>
> 저장소 안에 `libitum`(s 없음)이 남아 있는 자리가 둘 있는데 **둘 다 맞다** —
> iOS 번들 ID `com.libitum.host`와 저장소 키 접두사 `libitum.`은 **브랜드**를 쓴다.
> npm 스코프만 조직을 따른다. 셋을 같게 맞추려 하지 않는다.

```ini
# .npmrc  (커밋한다)
@libitums:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```
```ini
# .env.example  (커밋한다)
NODE_AUTH_TOKEN=   # GitHub PAT, scope: read:packages
```

- **토큰 값은 저장소에 들어가지 않는다.** 참조만 들어간다. pnpm이 `.npmrc`에서
  `${NAME}` 치환을 지원한다(`${NAME:-fallback}` 형태도 된다).
- **`.gitignore`에 `.npmrc`를 넣지 않는다.** ADR-0009 D1의 목록 그대로 두면 추적된다.
- registry 설정은 **반드시 `.npmrc`에** 둔다. pnpm 11.5.3부터 `pnpm-workspace.yaml`의
  registry URL에서는 환경 변수를 확장하지 않는다(자격증명 유출 방지).
- CI를 넣을 때는 Actions의 `GITHUB_TOKEN`에 `packages: read`를 주면 그대로 동작한다.

**근거**: ADR-0009 D2가 `.env.example`을 추적하는 이유와 같다 — **무엇이 필요한지가
저장소에 없으면 새 환경에서 왜 안 되는지 알 수 없다.** private 패키지는 인증이 없으면
`pnpm install`이 404로 죽는데, 그 원인이 어디에도 안 적혀 있으면 매번 다시 알아내야 한다.

### D3. `@libitums/ui-lynx`를 **첫 단계에 만들지 않는다**

컴포넌트는 `apps/mobile/src/components/`에 둔다. `packages/` 아래에는 아무것도 만들지
않는다 — **ADR-0004 D2가 그대로 유효하다.** 소비자가 `apps/mobile` 하나뿐이다.

LIB-108은 `@libitums/ui-lynx`의 **위치**(FE 모노레포)만 정했고, *"이 package의 배포 여부는
FE 모노레포에서 별도로 결정"* 이라고 명시했다. 시점은 이 저장소가 정할 몫이다.

**근거**: 먼저 확인해야 하는 것이 **토큰과 아이콘이 실제 화면에서 도는가**다(LIB-131).
패키지를 먼저 만들면 실패 지점이 둘(패키지 경계 + 토큰 소비)로 늘어나고, 무엇이 원인인지
가리는 데 시간이 간다.

**승격 조건**: ADR-0004 D2 그대로 — **두 번째 소비자가 실제로 나타났을 때.**
이름은 `@libitums/ui-lynx`로 예약돼 있다고 본다.

### D4. 원본을 복사하지 않고, 값을 하드코딩하지 않는다

LIB-108이 저장소 책임으로 정한 두 규칙을 이 저장소의 규약으로 받는다.

- **원본 JSON·Markdown·SVG를 복사하거나 fork하지 않는다.** 패키지로만 소비한다.
- **새 토큰이 필요하면 하드코딩하지 않고 design-system 변경을 요청한다.**
- 컴포넌트 스펙과 구현이 다르면 **design-system의 스펙이 기준**이다.

**근거**: 복사본은 반드시 갈라지고, 갈라진 시점을 알 수 없다. 하드코딩된 값은 QC 루프에서
"색을 바꿨는데 일부만 바뀐다"로 나타나며, 원인을 찾는 비용이 값을 요청하는 비용보다 크다.

### D5. 다크모드는 첫 단계 제외

ADR-0008 D3을 그대로 유지한다. **근거가 오히려 강해졌다** — 원본의 `color.json`이
라이트 모드 단일 값이고, LIB-107·LIB-108 모두 dark mode를 제외 범위로 명시한다.
FE가 혼자 정할 수 있는 축이 아니다.

## 보류

| 무엇 | 왜 못 정하나 | 그때까지 |
|---|---|---|
| `@libitums/*` 버전 범위 (정확 vs caret) | SemVer·changelog 정책이 LIB-128에서 아직 정해지지 않았다. minor에 무엇이 들어오는지 규정이 없다 | **첫 설치는 정확 버전으로 적어둔다.** 결정이 아니라 기본값 방지용이다 — `pnpm add`가 caret을 박아버리면 그게 조용히 규칙이 된다 |
| 아이콘 소비 형태 | 개별 export 생성기가 LIB-125에서 아직 나오지 않았다 | 아이콘을 실제로 쓰는 화면이 나올 때까지 미룬다 |

## 정정 기록

**2026-08-26 — 스코프가 틀렸다.** `@libitum`으로 적었는데 실제 배포는 **`@libitums`**다.
결정(패키지로만 소비한다)은 그대로이고, 이름이 틀렸다.

저장소 전체 **32곳**을 고쳤다 — `.npmrc`와 문서 여덟. 그대로 뒀다면 첫 설치에서
**404가 났을 것**이고, 원인이 스코프라는 것을 알아내는 데 시간이 갔을 것이다.

**어떻게 틀렸나** — LIB-108이 *"npm scope: `@libitum/*`"* 로 적은 것을 그대로 옮겼다.
**GitHub Packages는 스코프를 조직명으로 강제한다**는 사실을 확인하지 않았다. 조직은
`libitums`이고 브랜드는 `libitum`이라 한 글자 차이였다.

확인 범위에 한 줄 더한다 — **다른 저장소가 정한 이름은 그 저장소의 실제 산출물로
확인한다.** 이슈 본문은 결정 당시의 의도이지 배포된 사실이 아니다.

## 버린 대안

- **TS 상수를 기본 경로로** — 토큰 이름 오타가 컴파일 타임에 잡히는 이득이 있다. 그럼에도
  버린 이유는 Lynx의 CSS 처리(상속·클래스 전환·`calc()`·런타임 `setProperty`)를 통째로
  잃고 스타일이 컴포넌트마다 흩어지기 때문이다 (D1).
- **CSS와 TS를 용도별로 둘 다** — 규칙이 "계산이 필요할 때"처럼 말랑하면 경계가 닳는다.
  예외를 미리 열지 않고, 첫 사례가 나올 때 그 사례로 연다 (D1).
- **`.npmrc`를 커밋하지 않고 개인 `~/.npmrc`에만** — 저장소에 인증 흔적이 안 남는 대신,
  새 환경마다 설치가 404로 죽고 그 원인이 저장소 어디에도 없다 (D2).
- **패키지를 public으로 전환 요청** — 인증 문제 자체가 사라지지만 LIB-108이 private으로
  정했고, 디자인 스펙과 아이콘 815개가 외부에 공개된다. FE가 정할 범위 밖이다 (D2).
- **처음부터 `packages/ui-lynx`로** — 나중에 옮기는 비용을 안 낸다. 그러나 rspeedy가
  workspace package의 TS 소스를 그대로 처리하는지가 **미확인**이라, 프로토타입 초반에
  빌드 설정 디버깅을 하게 될 위험이 있다 (D3).
- **`@lynx-js/lynx-ui` 도입** — ReactLynx용 **공식 headless UI 라이브러리**가 있다
  (`button` · `dialog` · `sheet` · `overlay` · `popover` · `swiper` · `swipe-action` ·
  `slider` · `sortable` · `list` 등 22개 패키지, 개별 import 가능). 스타일이 없으므로
  design-system과 층이 겹치지 않는다 — **동작은 lynx-ui, 겉모습은 우리 토큰**이 성립한다.
  그럼에도 첫 단계에 넣지 않는 이유:
  - **동작 계약의 출처가 둘이 된다.** design-system의 컴포넌트 스펙이 상태·구조·예외를
    표로 정의하고, D4가 *"스펙이 기준"* 이라고 못 박았다. lynx-ui의 동작 모델과 스펙이
    어긋나는 자리마다 어느 쪽이 기준인지 다시 정하게 된다.
  - 필요한 컴포넌트가 많지 않다. design-system 스펙이 현재 7종이다.
  - 이 ADR 묶음의 태도 그대로 — **필요해질 때 넣는다.** 개별 import가 되므로
    필요한 패키지 하나만 나중에 들일 수 있다. 지금 전부 받을 이유가 없다.
- **원본을 FE에 복사해 두고 쓰기** — 오프라인·인증 없이 돌아가는 이득이 있지만
  LIB-108이 금지했고, 복사본은 갈라진 시점을 알 수 없다 (D4).

## 대가

- **토큰 이름 오타를 자동으로 못 잡는다.** D1이 명시적으로 감수하는 실패다. 화면이
  이상한데 에러가 없는 상태가 가능하다.
- **인증 없이는 아무것도 설치되지 않는다.** 새 기기·에이전트 컨테이너·CI마다
  `NODE_AUTH_TOKEN`이 있어야 한다. 오프라인에서 첫 설치가 불가능하다.
- **토큰이 바뀌면 화면이 바뀌는데 테스트가 못 잡는다.** 시각 회귀는 사람이 볼 수밖에
  없고(ADR-0006 D6), 버전을 올리는 PR이 그 확인을 붙일 유일한 자리다.
- **design-system에 요청하고 기다리는 왕복이 생긴다.** 값이 필요할 때 그 자리에서
  못 정한다. 1인이 양쪽을 다 하더라도 저장소를 오가는 비용은 남는다.
- **제스처·포커스·접근성을 직접 만든다.** `lynx-ui`를 안 쓰기로 했으므로(위) 바텀 시트의
  드래그와 스냅, 스와이프 액션, 오버레이의 포커스 처리를 우리가 구현한다. **여기가 가장
  아플 수 있는 지점**이고, 아래 재검토 조건이 그 시점을 잡는다.
- **컴포넌트가 나중에 이사한다.** D3의 승격 조건이 오면 `apps/mobile/src/components/`에서
  `packages/ui-lynx/`로 옮기고 import 경로가 전부 바뀐다.

## 재검토 조건

- **`@libitums/design-tokens`가 배포되면** → D1의 감수한 실패를 메운다. 알려진 토큰
  이름만 허용하는 CSS 검사를 `lint`에 붙인다(ADR-0006 D1이 검토했으나 토큰 목록이
  없어 만들지 못했다). **`var(--오타)`가 조용히 무시되는 것을 잡을 유일한 수단이다**
- **JS에서 토큰 값을 계산·분기해야 하는 첫 사례**가 나오면 → D1. 그 사례를 근거로
  TS 상수 경로를 연다. 사례 없이 열지 않는다
- **Explorer의 Lynx 런타임이 3.9 미만인 것이 확인되면** → D1. CSS 변수가 통째로 안 되므로
  TS 상수 경로가 fallback이 된다 (ADR-0005의 런타임 하한)
- **두 번째 소비자가 실제로 나타나면** → D3. `packages/ui-lynx`로 승격 (ADR-0004 D2)
- **LIB-128의 SemVer 정책이 확정되면** → 보류 표의 버전 범위
