# ADR-0043 — 랜딩 페이지: Astro 정적 사이트 `apps/landing`

- 상태: **제안** — 구현은 끝났다. 도구(Astro) · 기본 언어(영어) · 검색 노출 요구는 사용자 결정이고, 배포처와 도메인이 남았다.
  ⟨2026-10-05, 같은 날 뒤⟩ 답변 엔진 수집기를 어디까지 허용할지(D6)와 FAQ 문구(D7)도 **사용자 확인 전**이다.
- 날짜: 2026-10-05
- 다루는 축: 앱 로스터(웹 타깃 하나 추가), 그 앱의 도구, 그 앱의 검색 · 답변 엔진 노출(수집기 정책 포함)

## 맥락

서비스를 소개하는 웹 페이지가 필요해졌다. [ADR-0002](0002-app-roster-and-lynx-bundle-boundary.md)는 웹 앱을
*"요구사항에 없어서"* 뺐고, 생기면 같은 이름 규칙(타깃으로 짓는다, D4)으로 들어온다고 적었다.

이 저장소의 사실과 사용자 결정(2026-10-05):

- 화면은 Lynx 번들이고 브라우저에서 돌지 않는다. 랜딩이 앱 코드를 import할 일이 없다.
- 페이지는 하나이고, 서버에서 받아 오는 데이터가 없다.
- **검색 노출이 요구다.** 기본 언어는 영어, 한국어는 선택이다.
- 도구는 Astro나 Gatsby 같은 정적 사이트 프레임워크를 쓴다.
- ⟨같은 날 뒤⟩ 검색엔진뿐 아니라 **생성형 답변 엔진**(ChatGPT · Perplexity · Google AI 개요 등)도 이 페이지를 수집하고
  사실대로 인용하게 한다(사용자 발화 「seo 최적화 및 geo 둘 다」 — 「geo」를 Generative Engine Optimization으로 읽은 것은
  추론이다). D6~D9가 그 결정이다.

## 결정

### D1. 자리는 `apps/landing`, 패키지는 `@libitums/landing`이다

서비스명이 아니라 타깃으로 짓는다(ADR-0002 D4). `web`은 앱의 웹 클라이언트가 생길 때를 위해 비워 둔다.

### D2. Astro로 정적 HTML을 굽는다

`astro build`가 `dist/`에 페이지별 HTML을 만든다. 서버 런타임과 어댑터가 없다. 페이지에 실리는 스크립트는
스크롤 연출과 탭(`src/scripts/main.ts`) 하나이고, 없어도 본문은 다 보인다.

더한 의존(전부 정확 버전, [ADR-0013](0013-dependencies-and-version-notation.md)): `astro` 7.3.5 · `@astrojs/sitemap` 3.7.4 ·
`sharp` 0.35.5(이미지 변환) · `@libitums/design-tokens` 0.3.0, 개발용 `@astrojs/check` 0.9.10 · `typescript` 6.0.3.
⟨같은 날 뒤⟩ 테스트용으로 개발 의존 넷을 더했다 — `vitest` 3.2.7 · `jsdom` 27.4.0 · `@types/jsdom` 27.0.0 ·
`@types/node` 22.20.0(D9). `astro check`가 테스트 파일도 보므로 테스트가 쓰는 패키지는 이 앱의 의존이어야 한다.

루트의 `pnpm build`와 `pnpm typecheck`가 이 앱을 함께 돈다 — `pnpm verify`와 CI에 새 잎 명령을 더하지 않는다.
⟨같은 날 뒤⟩ 루트 `test:unit` · `test:ui` · `test:integration`도 이 앱을 함께 돈다(D9). 잎 명령 이름은 그대로다.

### D3. 언어마다 주소 하나 — 기본 언어(영어) `/`, 나머지 `/<코드>/`

- 문구는 `src/i18n/copy.ts`(영어, `Copy` 타입의 출처)와 `ko.ts`에 둔다. 한국어는 `Copy`를 전부 채워야 타입 검사를 지난다.
- 두 페이지는 같은 `Landing.astro`를 언어만 바꿔 그린다. 한국어를 스크립트로 덮어쓰지 않는다.
- 브라우저 언어로 자동 이동하지 않는다. 언어는 헤더의 언어 메뉴로만 오간다.
- **언어는 더 늘 수 있다**(사용자 결정). 그래서 언어 목록은 `src/site.ts`의 `languages` 하나가 지고, 주소 · 메뉴 · hreflang ·
  sitemap이 그 목록에서 나온다. 메뉴는 둘을 나란히 놓는 전환이 아니라 목록이 길어져도 되는 펼침 메뉴다.
- `<head>`에 제목 · 설명 · 공유 카드 · 구조화 데이터를 언어별로 넣는다. 배포 주소가 있으면 canonical · hreflang ·
  `og:url` · `og:image` · `twitter:image` · JSON-LD의 `url` · sitemap · `robots.txt`의 `Sitemap:` 줄을 더한다 —
  **주소가 정해지기 전에는 이것들이 빠진다.**
- **배포 주소는 `astro.config.ts`가 한 번 정한다** — 빌드 때의 환경 변수 `SITE_URL`이 우선이고, 없으면 `src/site.ts`의
  `fallbackSiteUrl`(지금은 빈 값)이다. 컴포넌트와 엔드포인트는 `Astro.site`만 읽는다. 값은 `https://호스트[:포트]`
  꼴이어야 하고 **틀리면 빌드가 실패한다**(아래 정정 기록 — 처음 문면은 「`src/site.ts`의 `siteUrl`」이었다).
  `site.ts`가 환경 변수를 직접 읽지 않는 이유: 그 모듈은 페이지에도 들어가므로 읽는 자리가 둘이 되고, 컴포넌트가 상수를
  직접 import하는 길이 열린다.

### D4. 토큰은 패키지의 CSS 변수를 잇는다

`@libitums/design-tokens/css/variables.css` · `typography.css`를 가져오고, `base.css`가 짧은 이름(`--bg` 등)으로 잇는다.
값을 옮겨 적지 않는다. `lint:tokens`의 범위(앱 · ui-lynx · storybook)에는 넣지 않았다.

### D5. 그림은 앱 자산의 사본이다

`apps/mobile/src/assets`의 JPEG를 WebP로 바꿔 `src/assets/img/`에 둔다. 다른 앱의 `src`를 직접 import하지 않으려는 것이다. 크기별 변환과 파일명 해시는 Astro가 한다.

### D6. 답변 엔진 수집기를 이름으로 허용한다 — **정책은 사용자 확인 전**

`robots.txt`는 `User-agent: *`에 `Allow: /`를 유지하고, 수집기 여섯을 **묶음 하나씩** 이름으로 다시 허용한다:
GPTBot · OAI-SearchBot · ChatGPT-User · ClaudeBot · PerplexityBot · Google-Extended. `Disallow` 줄은 어디에도 없다.
목록은 `src/seo/robots-txt.ts`의 `answerEngineCrawlers` 하나가 진다.

- 이름으로 적는 이유: 이미 `*`로 허용돼 있어 동작은 같다. 「이 수집기를 알고 허용했다」가 파일에 남고, 하나를 빼거나
  막을 때 고칠 줄이 정해진다.
- **이 목록에는 답변에 인용하려고 읽는 수집기와 모델 학습용으로 읽는 수집기가 섞여 있다**(GPTBot · ClaudeBot ·
  Google-Extended는 학습에도 쓰인다). 학습용 수집까지 여는 것은 기술 선택이 아니라 **정책 결정**이다. 지금 값(전부 허용)은
  「답변 엔진 노출」 요구에서 끌어온 추론이고 사용자가 확인하지 않았다.

### D7. FAQ는 출처가 하나다 — 화면 = `FAQPage` = `llms.txt`

질문 일곱의 문구는 기존 문구 파일(`src/i18n/copy.ts` · `ko.ts`)의 납작한 키로 두고, 목록 · 순서 · 스토어 주소 유무에
따른 「받는 곳」의 답은 `src/seo/faq.ts`의 `buildFaq`가 진다. `Landing.astro`가 그것을 **한 번** 불러 같은 배열을
화면의 FAQ 섹션(`Faq.astro`)과 JSON-LD의 `FAQPage`(`SeoHead.astro`)에 넘기고, `llms.txt`도 같은 함수를 기본 언어로 부른다.

- 두 자리가 따로 문구를 가지면 어긋난다. `FAQPage`의 질문 · 답은 보이는 문구와 **글자까지 같아야** 한다(스펙의 수용 기준).
- 문구는 **태그 없는 평문**이다. `<`가 섞이면 `buildFaq`가 던져 빌드가 실패한다.
- JSON-LD는 페이지마다 하나, `@graph`에 `WebSite` · `SoftwareApplication` · `FAQPage` 셋이다. **`offers` · 평점 · 리뷰 ·
  조직 정보는 타입에 없다** — 근거 없는 구조화 데이터를 싣지 않는다([스펙](../specs/landing-page.md)의 「사실만 싣는다」).
- FAQ 섹션은 Phrases 다음, 맺음 인용 앞에 서고 헤더 메뉴의 넷째 항목이 된다. 질문은 `<details>`이고 스크립트가 없다.
- 문구는 저장소 문서에서 뽑은 **초안**이고 사용자 확인 전이다.

### D8. `llms.txt`와 404는 파일 하나씩, 기본 언어로 쓴다

- **`/llms.txt`** — 답변 엔진용 요약이다: `# Duru`, 한 문단 요약(기본 언어의 검색 설명을 그대로 쓴다 — 새 문구를 만들면
  어긋날 자리가 하나 는다), 언어별 페이지 링크, FAQ 전부(D7).
- **`/404.html`** — `noindex`이고 canonical · hreflang · 공유 카드 · JSON-LD · 랜딩 스크립트를 싣지 않는다. 홈 링크와,
  기본 언어가 아닌 언어의 홈 링크를 준다. sitemap에는 들지 않는다. 헤더에는 섹션 메뉴와 언어 메뉴가 없다 — 스크립트가
  없는 페이지에서 언어 메뉴가 `Escape` · 바깥 누름으로 닫히지 않기 때문이다.
- 이를 위해 `Base.astro`를 **모든 페이지의 문서 껍데기**로 줄이고, 색인용 head는 `SeoHead.astro`가 지게 갈랐다.
  `Base`에 「404인가」를 묻는 값을 더하는 대신 조합으로 가른 것이다. `Header` · `Footer`는 `variant`(`"landing"` | `"page"`)로
  404용 모양을 고른다 — 불리언이 아니라 이름 붙은 변형이고, 계약(`landing.contract.ts`)에 올라 있다.

### D9. 테스트 계층 셋을 들인다 — vitest, node 환경

`apps/landing`이 `test:unit` · `test:ui` · `test:integration`을 갖고 루트의 같은 이름 사슬 끝에 명시 `--filter`로 붙는다
([ADR-0006](0006-command-interface-and-test-layers.md) D2 · D7과 그 정정 기록). 파일은 소스 옆, 계층은 파일명이 가른다.

| 계층 | 무엇을 | 케이스 (2026-10-05) |
|---|---|---|
| unit | `src/seo/`의 순수 함수 여덟과 FAQ 문구 데이터 | 64 |
| ui | 컴포넌트 하나를 Astro Container로 그려 마크업 · 속성을 본다 | 35 |
| integration | 임시 폴더로 `astro build`를 실제로 돌려 산출 파일을 본다(주소 있음 · 없음 · 틀린 값) | 27 |

- **vitest의 환경은 node다.** `jsdom` **환경**에서는 `.astro`가 서버 컴포넌트로 변환되지 않아 렌더가 깨진다. 그려진
  문자열을 `jsdom`으로 **명시적으로** 파싱한다. 그래서 `.astro`를 그리는 ui 테스트도 확장자가 `.ts`다.
- `src/pages/` 아래의 `.ts`는 전부 주소가 되므로 테스트를 거기 두지 않는다. 404의 본문을 `NotFound.astro`로 뗀 이유다.
- `src/seo/`의 모듈은 Astro · `site.ts` · 문구를 import하지 않고 값을 인자로 받는다 — 언어가 늘어도 unit에서 잴 수 있다.

브라우저 e2e는 Playwright다(`apps/landing/e2e/`, `pnpm test:e2e:landing`) — chromium · firefox · webkit · 모바일 구성으로
FAQ의 키보드 조작, 스크립트 없는 화면, 404, 폭별 넘침, 그림 요청 우선순위, axe 검사를 본다. 이 저장소의 e2e가 수동 절차인 까닭
(실기기 · VoiceOver)은 웹인 이 앱에는 해당하지 않는다. **`pnpm verify`와 CI에는 넣지 않았다** — CI에 브라우저를 받는 단계를
더하는 것은 따로 정할 일이다. 스크린리더 낭독과 외부 검증기는 여전히 수동 절차(`docs/e2e/landing-seo-geo.md`)에 남는다.

## 버린 대안

- **Gatsby** — React 런타임과 GraphQL 데이터 계층이 한 페이지에 과하고, 유지보수가 눈에 띄게 느려졌다.
- **Next.js** — 서버 기능을 쓰지 않는 페이지에 React 런타임을 싣는다.
- **의존 없는 HTML + 자체 생성 스크립트**(처음 구현) — 동작했지만 언어별 HTML · 메타 · sitemap을 만드는 일을 직접 짠
  정규식 스크립트가 졌다. 그 일을 프레임워크에 넘겼다.
- **`apps/mobile`의 Lynx Web 번들로 그리기** — 검색 노출과 첫 화면 속도가 필요한 페이지에 런타임을 싣는다.
- ⟨같은 날 뒤⟩ **`src/site.ts`의 상수가 환경 변수를 읽기** — D3에 적은 이유로 버렸다(읽는 자리가 둘이 된다).
- **`Base.astro`에 「404인가」 불리언 더하기** — 변형마다 무엇을 싣는지가 조건문 안에 숨는다. 조합으로 갈랐다(D8).
- **`llms.txt`의 요약을 새로 쓰기** — 검색 설명과 어긋날 자리가 하나 는다(D8).
- **`robots.txt`의 한 묶음에 `User-agent` 여러 줄** — 표준이지만 묶음 하나씩이 엉성한 해석기에도 안전하고 이름을
  하나 빼기 쉽다(D6).
- **vitest의 `jsdom` 환경** — Container 렌더가 `No valid renderer was found`로 깨진다(D9).
- **404의 헤더에 언어 메뉴를 두고 스크립트를 싣기** — 404에 스크립트를 싣지 않는다는 쪽을 지켰다(D8).

## 대가

- workspace 패키지와 의존이 늘었다. 랜딩만 배포할 때도 설치에 `@libitums/*`용 GitHub 토큰이 필요하다.
- 그림이 **사본**이다. 원본이 바뀌어도 아무것도 알려 주지 않는다.
- ~~화면의 자동 테스트가 없다. 확인은 눈과 브라우저로 한다.~~ ⟨같은 날 뒤 — 거짓이 됐다, 아래 정정 기록⟩ 자동 테스트는
  **마크업과 산출 파일까지만** 본다(D9). 레이아웃 · 색 대비 · 스크롤 연출 · 브라우저의 실제 요청 순서 · 보조 기술의
  낭독 · 외부 검증기의 판정은 여전히 브라우저와 사람 몫이고, 그 절차는
  [랜딩 SEO · GEO e2e](../e2e/landing-seo-geo.md)가 진다. 접근성 자동 검사(axe)도 없다.
- 테스트 러너와 프레임워크가 **서로 다른 Vite**를 쓴다(vitest 3.2.7은 Vite 7, Astro 7.3.5는 Vite 8). 지금은 돌지만
  `vitest.config.ts`가 타입 어긋남을 우회하고 있고, 둘 중 하나를 올릴 때 깨질 수 있는 자리다.
- 수집기 허용이 **기본값으로 열려 있다**(D6). 사용자가 확인하기 전에 배포되면 학습용 수집까지 허용한 채 나간다.
- `llms.txt`와 404는 기본 언어(영어)뿐이다(D8).
- `llms.txt` · `robots.txt`는 정적 파일이라 **`Content-Type`의 charset을 호스팅이 정한다.** 로컬 preview는 charset 없이
  내려 헤드리스 브라우저에서 `llms.txt`의 한글이 깨져 보였다(바이트는 올바른 UTF-8). 실제 호스트에서는 미확인이다.
- 좁은 화면에서는 히어로 세 그림이 같은 자리에 겹쳐 있어, 미루려고 `loading="lazy"`를 붙인 둘도 **스크롤 전에
  요청된다.** 첫 그림이 높은 우선순위로 먼저 나가는 것까지만 얻었다.
- 프로덕션 HTML에 `data-testid`가 남는다(FAQ · 404 — 빌드 산출물을 파싱하는 integration이 쓴다).
- 서체를 외부 CDN(Google Fonts · jsDelivr)에서 받는다.
- 공유 카드 그림(`public/og-*.jpg`)은 손으로 찍은 것이다. 히어로가 바뀌면 다시 찍어야 한다.

## 재검토 조건

- 서체 요청이 첫 화면 속도 측정에서 문제로 잡히면 → 서체를 번들에 넣는다.
- 그림 사본이 원본과 어긋난 것이 **한 번이라도** 배포되면 → 변환을 스크립트로 묶는다.
- 블로그 · 보도자료처럼 글이 쌓이는 페이지가 생기면 → Astro 콘텐츠 컬렉션을 들인다.
- 사용자가 학습용 수집을 막기로 하면 → `answerEngineCrawlers`에서 그 이름을 빼는 것으로는 막히지 않는다(`*`의 허용으로
  돌아갈 뿐이다). `Disallow` 묶음을 내는 쪽으로 `buildRobotsTxt`의 계약을 바꾼다(D6).
- vitest나 Astro를 올린 뒤 `test:ui`가 렌더 단계에서 깨지면 → 러너의 판(저장소 전체가 같은 vitest를 쓴다)을 다시 정한다.
- 호스팅이 언어별 404를 지원하면 → 404를 언어마다 굽는다(D8).
- 스토어 주소가 **하나만** 먼저 열리면 → 「받는 곳」의 답이 스토어를 가르지 않는다는 점을 다시 본다(지금 답은 스토어
  이름을 부르지 않아 하나만 있어도 참이다).
- 실제 호스트가 `llms.txt`를 charset 없이 내려 한글이 깨지는 것이 확인되면 → 호스팅의 헤더 설정을 고친다(코드가 아니다).

  대가(자동 테스트가 보지 못하는 것)를 다시 적었다.

**제자리에서 고친 근거**([README](README.md) 「형식」): 이 ADR은 아직 `제안`이고, 옛 문면 위에 따로 지어진 것이 없다 —
