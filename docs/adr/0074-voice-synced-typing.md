# ADR-0074 — 카탈로그 컷의 대사 타이핑은 음성 길이에 맞춰 쓰고, 그 길이는 버킷의 음성 정보 파일 `audio/manifest.json`(`audio-manifest-1`)에서 읽는다

- 상태: **채택 — 클라이언트 쪽.** 호스트 · 재생 모듈 · 파일 모듈 · 에피소드 콘텐츠 스키마 · 매니페스트(`manifest-1`) 변경은 0이다. 버킷에 새 정적 파일 하나(`audio/manifest.json`)와 기기 저장 키 하나가 생긴다.
  정보 파일은 2026-10-19 사용자가 버킷에 올렸다(공개 주소 200, 앱 쪽 실측판 16항목).
  ⚠ **기기 확인은 부분이다 — 사용자가 부분 확인으로 받아들였다(2026-10-19).** iOS 시뮬레이터 화면 녹화로 음성 컷(u03 컷 2)이 말 끝 길이(4.88초 예상, 관찰 약 4.75 ~ 5.0초)에 걸쳐 쓰이고 소리 없는 컷은 35ms 그대로임을 봤다. **귀로 들은 확인은 없다** — 소리 끝과 글 끝의 실제 일치 · 재생 시작 지연 · 끝 무음 판단(재검토 조건 1, `speech_end_ms`가 다른 컷)은 열려 있다.
  절차와 회차는 [음성 길이 맞춤 타이핑 e2e](../e2e/voice-synced-typing.md).
- 날짜: 2026-10-19.
- 사용자 결정(2026-10-19): 길이의 출처는 **버킷의 별도 음성 정보 파일**(호스트가 받아 둔 파일의 길이를 읽지 않는다) · 정보 파일은 **콘텐츠 납품 쪽이 만든다**(앱 쪽은 요청문만) · 간격의 안전 범위 **[35, 300] ms** ·
  끝 무음은 선택 필드 **`speech_end_ms`** 로 열어 두고 기기에서 보고 판단한다 · **호스트 변경 없음**.
- 다루는 축: **컷 대사 타이핑과 음성 길이** — 글자 간격의 식과 안전 범위, 맞출 길이의 출처(파일 · 위치 · 형식), 맞출 길이의 선택(`speech_end_ms` · `duration_ms`), 정보 파일의 받기 · 저장 · 변경 확인 · 없음 · 실패 · 오프라인, 생성 책임.
  **다루지 않는 것**: 소리가 언제 나고 멈추는가([ADR-0060](0060-episode-voice-remote-audio.md) D5 그대로), 재생 위치 실시간 동기(일시정지 · 시크 추적) · 단어 단위 맞춤, 튜토리얼 내장 음성(서사 · 프롤로그 통화 · 전화 — 기존 `revealTiming` · 기본 속도),
  최종 테스트 대화(`reveal="instant"`) · 메신저 말풍선, 동작 줄이기의 즉시 표시([ADR-0053](0053-motion-policy.md) 그대로).
- 이어받는 결정(결정 문장은 바꾸지 않는다 — 각 ADR에 적용 기록 ⟨2026-10-19⟩):
  [ADR-0071](0071-episode-background-download.md) D3 · D4 · D6(받기 실행기 한 차례의 순서 · 실패 갈래 · 「다 갖춘 뒤 열기」 · 겹친 요청 — 정보 파일은 그 차례 **끝에** 붙는다),
  [ADR-0056](0056-episode-content-delivery.md) D5 · D8(검증을 통과한 것만 저장 · 원격 경로 — `manifest-1` 밖의 파일 하나),
  [ADR-0060](0060-episode-voice-remote-audio.md) D5(컷이 서면 소리 한 번 · 탭 · 정지 · 자동 넘김 없음 — 그대로, 타자기 속도만 소리를 따른다).
  [ADR-0017](0017-host-native-capabilities-and-audio.md)은 손대지 않는다 — 재생 모듈의 「재생 상태 · 진행 조회」 제외(D3)에 닿는 코드가 없다. 길이는 앱 밖에서 미리 잰 **콘텐츠 데이터**다.

**왜 새 번호인가** — 없던 축이다. ADR-0060의 축은 「소리가 언제 나고 멈추는가」, ADR-0056은 에피소드 본문의 전달, ADR-0071은 에피소드를 받는 때와 차례다. 대사 표시 속도의 기준과 그 데이터의 형식은 어느 `다루는 축`도 덮지 않고,
버킷 · 기기에 납품 쪽과 앱이 함께 지킬 새 계약(파일 형식 · 저장 키)이 생긴다(ADR README 「형식」의 「없던 축을 처음 정하면」).

근거 표시: **[코드]** 저장소 코드(`apps/mobile/src/` 기준) · **[실측]** 이 작업이 잰 값 · **[ADR]** 기존 결정 · **[사용자]** · **[추론]** 관찰 없이 이어 붙인 것.
계약의 정본은 저장소 밖 작업 폴더의 spec이고 이 문서는 그중 **결정**만 옮긴다. 시그니처는 코드가 진다. 납품 쪽에 보낸 요청문의 요약은 [콘텐츠 계약](../specs/episode-content-json-contract.md) 부록 E에 있다.

## 맥락

1. **컷 대사는 음성 길이와 무관하게 글자당 35ms로 쓰였다** [코드]. `CatalogCoverScreen`이 `useTypewriter({ text, resetKey, reducedMotion })`를 간격 없이 불러 기본값(`motion.duration.reveal` = 35)을 썼다.
   음성이 긴 줄은 글이 먼저 끝나고, 짧은 줄은 음성이 먼저 끝났다.
2. **기기는 음성의 길이를 모른다** [ADR]. 재생 모듈은 `play` · `stop`만 있고 재생 상태 · 길이 조회는 제외됐다(ADR-0017 D3). 받아 둔 파일(ADR-0071)의 길이를 호스트가 읽게 하면 길이는 알지만 **끝 무음**은 여전히 모른다.
3. **실제 음성의 끝 무음은 0 ~ 0.54초다** [실측 2026-10-19]. 지금 있는 음성 16개(u01 6 · u02 4 · u03 6)를 ffprobe · ffmpeg `silencedetect`(−40 dB, 0.1초)로 쟀다 — 앞 무음은 모두 0,
   끝 무음은 u01 · u02 0.16 ~ 0.54초(u01 `pre-3` 「어서 오세요.」가 가장 길어 0.54초), u02 `pre-1`과 u03 6개는 0이다. 파일 길이에 맞추면 끝 무음이 긴 줄은 말이 끝난 뒤에도 글이 이어진다.
4. **글자당 간격의 실제 범위** [실측]. 컷 대사(표시되는 `ko`의 code point 수 N)로 나누면 `speech_end` 기준 **110 ~ 274 ms**, 파일 길이 기준 136 ~ 328 ms다
   (가장 빠른 u01 `d-01` 「봉투 드릴까요?」 110, 가장 느린 u02 `post-1` 274 · 파일 길이로는 u01 `pre-3` 328).
5. **버킷은 없는 파일에 HTTP 400을 낸다** [실측]. `audio/manifest.json`은 지금 400(본문 `"statusCode":"404"`, `NoSuchKey`)이고, 있는 `manifest.json`은 200이다 — ADR-0071 D3이 이미 400을 「서버에 없음」으로 본다.
6. **JS 텍스트 GET은 파일 모듈이 필요 없다** [코드]. 매니페스트를 받는 전송(`fetchContentText`)과 문자열 저장소(`StorageModule`)만으로 작은 JSON을 받아 둘 수 있다 — Explorer에서도 돈다.

## 결정

### D1. 컷 타자기의 글자 간격 = 맞출 길이 ÷ 글자 수, [35, 300] ms로 묶는다 — 그 밖은 지금 그대로 35

- 간격 = `min(300, max(35, floor(L ÷ N)))`. L = 맞출 길이(D3), N = 화면이 쓰는 `cut.text.ko`의 code point 수(공백 · 문장부호 · 독백 괄호 포함 — 타자기가 쓰는 단위와 같다).
- L이 없음 · 비유한 · 0 이하이거나 대사가 비면 기본 간격(35)이다. 소리 없는 컷 · 정보 파일 없음 · 그 id의 항목 없음 · 형식 틀림도 모두 여기다 — **지금과 같은 렌더 · 같은 타이머**.
- 하한 35 = 「음성이 있어도 지금보다 빨라지지 않는다」. 실제 말은 110 이상이라 깨진 값(엉뚱한 id에 짧은 길이)에서만 걸리고, 그때 지금 동작이 가장 안전하다.
  상한 300 = 가장 느린 실제 줄(274)보다 약 10 % 위 — 두 글자 줄에 긴 소리 · 단위 실수(초를 ms로)를 「한 글자에 수 초」로 두지 않는다. **사용자 확인**(2026-10-19).
- 내림이라 범위 안이면 글은 맞출 길이보다 늦게 끝나지 않는다. `speech_end_ms`가 있으면 지금 16개 중 범위에 걸리는 컷이 0이다.
- 적용 자리는 **카탈로그 컷 화면(`CatalogCoverScreen` — 표지 · 통과 뒤 컷) 하나**다. 컷 뷰가 이미 푼 길이(`voiceSyncMs`)를 싣고 화면은 순수 함수 하나로 간격을 고른다 — 새 컴포넌트 · prop · 훅 · Flow 변경 0.
- 간격은 첫 렌더에 정해져 있다 — 타자기 타이머와 소리 재생이 같은 커밋의 effect에서 함께 선다. 동작 줄이기는 간격과 무관하게 즉시 전체, 쓰는 중 `Next`는 대사 완성(ADR-0060 D5) 그대로다.
- 상한 300은 토큰이 아니라 이 화면의 동작 규칙이다(쓰는 자리 하나 · 전환 길이가 아님). 기본 35는 `motion.duration.reveal` 그대로다.

### D2. 맞출 길이의 출처는 버킷의 음성 정보 파일 하나다 — 호스트 · 재생 모듈 · 에피소드 스키마가 아니다

- 위치: 버킷 `content`의 **`audio/manifest.json`**(음성 파일 `audio/<id>.m4a`과 같은 폴더의 맨 위). 형식 이름 **`audio-manifest-1`**.
- 모양: `{ "schema": "audio-manifest-1", "generated_at": "<ISO 8601 UTC>", "audio": { "<음성 id>": { "duration_ms": <정수>, "speech_end_ms"?: <정수> } } }`.
  키 = 콘텐츠 `audio_url`의 id(`u01-water/pre-3`) — 콘텐츠와 같은 id 규약(소문자 · 숫자 · 하이픈 조각을 `/`로 이음). 값은 1 이상의 정수 ms.
- **파일 단위로 쓰지 않음**: JSON이 아님 · 최상위가 객체 아님 · `schema`가 정확히 `audio-manifest-1`이 아님(`audio-manifest-2`도 — 모르는 판을 추측해 읽지 않는다) · `audio`가 객체 아님.
  **항목 단위로 버림**: 키가 id 규약 밖 · 값이 객체 아님 · `duration_ms`가 양의 안전 정수 아님 · `speech_end_ms`가 **있는데** 양의 안전 정수 아님(반쪽 항목을 살리지 않는다 — 납품 오류의 신호다). 던지지 않는다.
- 무시: `generated_at`(앱은 읽지 않는다 — 사람이 판을 구별하는 값) · 모르는 최상위 키 · 항목의 모르는 키(필드가 늘어도 옛 앱이 읽는다). `audio: {}`는 빈 표(유효).
- 소리가 나는 컷만 길이를 싣는다. 받아 둔 파일(`file://`)이든 원격 스트리밍이든 가리지 않는다 — 같은 소리다(차이는 시작 지연뿐, 「대가」 2).

### D3. 맞출 길이 = `speech_end_ms` 우선, 없거나 `duration_ms`를 넘으면 `duration_ms`

- `speech_end_ms` = 파일 끝까지 이어지는 마지막 무음이 시작되는 때(말소리 끝). 끝 무음이 없으면 `duration_ms`와 같은 값이다.
- `speech_end_ms > duration_ms`인 항목은 버리지 않고 `duration_ms`를 쓴다.
- 끝 무음을 어떻게 다룰지는 **기기에서 보고 판단한다**(사용자 결정) — 그때까지 납품 쪽은 두 값을 모두 넣는다. 판단 결과가 「파일 길이에 맞춘다」면 코드 한 줄이 아니라 이 결정을 고친다(재검토 조건 1).

### D4. 받기 · 저장 · 변경 확인 · 없음 · 실패 · 오프라인

- **자리**: ADR-0071의 받기 실행기(`createSyncRunner` — 실행 시작 · `contentSyncOpportunity`) **한 차례 안에서, 에피소드 받기(`refreshEpisodeCatalog`)와 그 이벤트가 끝난 뒤** 정보 파일을 한 번 받는다.
  카탈로그가 바뀌었거나 정보 파일이 바뀌었으면(`updated` · `removed`) 다시 읽기는 **한 번**이다. 그래서 에피소드 받기의 순서 · 실패 · 「다 갖춘 뒤 열기」(ADR-0071 D3 · D4)는 한 글자도 바뀌지 않고,
  정보 파일 실패가 에피소드 받기를 막지 않으며, 겹친 신호는 실행기가 한 번으로 모은다(D6).
- **저장**: 기기 키 **`libitum.content.audio-manifest`** 에 받은 원문 그대로(`StorageModule`). **유효한 파일만 쓴다** — 깨진 파일이 올라와도 기기의 좋은 표가 남는다.
- **변경 확인은 원문 비교다** — 저장 원문과 같으면 아무것도 하지 않는다. 매니페스트(`manifest.json`)와 같은 방식이다. `generated_at`이 바뀌면 값이 같아도 다시 읽기가 한 번 생기지만 대가는 그뿐이다.
- **없음은 지운다** — HTTP 400 · 403 · 404 · 410(ADR-0071 D3과 **같은 상수** `ABSENT_HTTP_CODES` — 「Supabase는 없는 파일에 400」 사실의 자리를 하나로 열었다)이면 저장본을 지운다. 납품 쪽이 파일을 내리면(잘못된 값 철회) 기기도 35로 돌아간다.
- **실패는 둔다** — 연결 실패 · 미설정 · 5xx · 저장소 없음은 저장본을 그대로 쓴다. 형식 틀림도 저장본을 둔다.
- **오프라인**: 앱이 켜질 때 저장 원문을 읽어 표로 만든다(원문이 같으면 이전 표 — 카탈로그와 같은 메모). 한 번 받은 표는 연결 없이 쓴다.
- 분석 이벤트 · 속성은 더하지 않는다(`episode_content_refreshed` 그대로 — 측정 없음).

### D5. 정보 파일은 콘텐츠 납품 쪽이 만들고 갱신한다

- 앱은 음성 파일을 열어 길이를 재지 않는다. 측정 방법(ffprobe 길이 반올림 · `silencedetect=noise=-40dB:d=0.1`의 끝 무음 시작) · 키 규칙 · 갱신 규칙(음성을 먼저 올리고 정보 파일을 다음에, 내릴 때는 반대 · 매번 전체를 다시 만들어 덮어씀) · 올리기 전 검사는
  납품 쪽에 보낸 요청문이 정본이고, 요약은 [콘텐츠 계약](../specs/episode-content-json-contract.md) 부록 E다.
- 처음 한 판(지금 음성 16개, `generated_at` 2026-10-19T08:41:18Z)은 앱 쪽이 같은 방법으로 만들어 두었다 — 2026-10-19 사용자가 버킷에 올렸다(외부 반영은 사용자가 한다).

## 버린 대안

1. **호스트가 받아 둔 파일의 길이를 읽는다(`durationMs`)** — 처음 검토한 안. 길이는 정확하지만 호스트 두 플랫폼 · 파일 모듈 메서드가 늘고, 끝 무음은 여전히 모르며, 받아 둔 파일이 없는 원격 스트리밍 · Explorer에서는 길이가 없다.
   조회가 동기 호스트 호출이라 화면이 effect로 미뤘다가 「35로 섰다가 다시 그려 새 간격」이 되는 훅도 필요했다. **사용자가 호스트 변경 없음 · 별도 정보 파일을 골랐다.**
2. **재생 모듈에 재생 상태 · 진행 조회를 연다** — ADR-0017 D3 제외를 걷어야 하고, 재생이 시작된 뒤에야 길이를 알아 첫 글자가 늦는다.
3. **에피소드 `manifest.json`(`manifest-1`)이나 에피소드 JSON에 길이를 싣는다** — 스키마 변경이고, 같은 음성 id를 여러 에피소드가 다시 쓰면(ADR-0060 D5 끝 줄) 값이 흩어진다.
4. **에피소드 받기 안(매니페스트 직후)에서 받는다** — ADR-0071 순서 안에 끼고 결과 타입이 바뀐다. 정보 파일이 늦어 에피소드가 늦게 열릴 이유가 없다.
5. **변경 확인을 `generated_at` · 해시로** — 해시를 둘 곳이 없고(매니페스트 불변), `generated_at`만 믿으면 같은 시각 재업로드를 놓친다. 원문 비교가 더 단순하고 정확하다.
6. **형식이 틀린 파일이 오면 저장본도 지운다** — 납품 실수 하나가 기기의 좋은 표를 지운다.
7. **`speech_end_ms`만 틀리면 그 필드만 버리고 `duration_ms`를 쓴다** — 반쪽 항목은 납품 오류의 신호다.
8. **받아 둔 파일(`file://`)일 때만 맞춘다** — 원격 재생도 같은 소리다.
9. **하한 없음(1) · 상한 400** — 하한이 없으면 깨진 짧은 값에서 글이 거의 즉시, 상한 400이면 두 글자 줄 · 잘못된 값에서 한 글자 0.4초. 사용자가 [35, 300]을 골랐다.

## 대가

1. **정보 파일이 처음 닿거나 바뀐 다시 읽기가 보고 있는 컷의 길이를 바꾸면 그 줄을 처음부터 다시 쓴다** — 간격이 바뀌면 타자기 세션이 새로 선다. 첫 실행 직후 표지를 바로 연 경우 정도라 받아들인다.
2. **원격 스트리밍 컷은 글이 소리보다 조금 먼저 간다** [추론] — 재생 시작이 버퍼링만큼 늦다. 끝은 여전히 말소리 끝 이전이다. 받아 둔 파일은 수십 ms 차이다.
3. **갱신이 최대 1시간 늦게 닿을 수 있다** [추론] — 공개 객체의 CDN 캐시(기본 `max-age=3600`). 업로드 때 짧은 `cacheControl`을 권고로 요청문에 적었다. 앱 동작은 바뀌지 않는다.
4. **키가 본문 id와 어긋나면(오타) 그 컷은 조용히 35다** — 앱은 알리지 않는다(측정 없음). 납품 쪽의 올리기 전 검사 항목에 넣었다.
5. **앱은 파일과 정보가 어긋났는지 알 수 없다** — 같은 id의 음성을 다시 녹음하고 정보 파일을 그대로 두면 글과 소리가 어긋난다. 갱신 규칙(요청문)에 기댄다.
6. **녹음이 없는 음성 id는 길이도 없다** [실측]. 내장 본문이 참조하는 음성 id 13개 가운데 `u03-mina/d-01`(u03 대화 seq 1 · 표지 컷 pre-4가 다시 씀)은 버킷이 **400**이다(녹음 없음 — ADR-0071 D3의 「400」 관찰 · [백그라운드 받기 e2e](../e2e/episode-background-download.md) 실행 기록과 같다).
   정보 파일에도 그 항목이 없어 그 줄은 소리 없이 35ms다. 반대로 정보 파일의 u03 `d-03` · `d-09` · `d-11` · `post-1`은 지금 내장 본문이 쓰지 않는 id다(원격 판 · 대화 줄) — 앱은 쓰이지 않는 키를 무시한다.
   콘텐츠 계약 부록 C의 업로드 현황(⟨2026-10-14⟩ 14개, u03 `d-01` 포함)과 지금 버킷이 다르다 — 그 표는 그때의 기록으로 두고 부록 E에 지금 관찰을 적었다.
7. **번들 +2,431 bytes**(CI 2,203,193 → 2,205,624 · 로컬 2,203,382 → 2,205,813) — 상한 2,205,000 → 2,207,000. main(#275 ~ #278) 병합 뒤 CI 2,242,358 · 로컬 2,242,547(main 대비 같은 +2,431), 상한 2,241,000 → 2,244,000([성능 보고서](../performance/reports/voice-synced-typing-iphone-17-pro-simulator-01.md)).

## 재검토 조건

1. **기기에서 끝 무음 판단을 마쳤을 때** — 말소리 끝(`speech_end_ms`)과 파일 끝 중 어느 쪽이 자연스러운지 VTE1 · VTE2 결과로 D3을 확정하거나 고친다.
2. **원격 스트리밍의 시작 지연이 0.3초를 넘는 것이 관찰되면** — 재생 시작 신호에 타자기를 묶는 길(재생 모듈 조회 — ADR-0017 D3)을 다시 본다.
3. **튜토리얼 · 최종 테스트 · 메신저로 넓히자는 요구가 오면** — 지금은 카탈로그 컷 하나다. 다른 화면의 노출 방식(`reveal="instant"` · 말풍선)부터 다시 정한다.
4. **단어 단위 맞춤 · 재생 위치 추적 요구가 오면** — 길이 하나로는 안 된다. 정보 파일 형식(`audio-manifest-2`)과 재생 모듈 조회를 함께 연다.
5. **정보 파일이 에피소드 매니페스트로 합쳐지거나 서버 쪽 매니페스트 생성기가 생기면**(ADR-0071 재검토 조건 3) — 위치 · 변경 확인(해시) · 저장 키를 옮긴다.
6. **간격이 상한 · 하한에 걸리는 컷이 실제 콘텐츠에서 나오면** — 범위가 아니라 그 음성 · 대사를 먼저 확인하고, 둘 다 맞으면 범위를 다시 본다.

## 적용 기록

### ⟨2026-10-22⟩ 학습 문항 음성 · 「천천히」 — 문항 쪽 길이 동기화는 해당 없다

결정은 [ADR-0080](0080-item-audio-and-slow-playback.md) D11. 이 문서의 결정은 바뀌지 않는다.

- **컷 타자기는 늘 1.0 재생에 맞춘다** — 컷은 `play(source, done)` 인자 둘로 가고 「천천히」가 닿지 않는다. 맞출 길이(D3) 식은 그대로다.
- 학습 문항에는 음성 길이에 맞추는 자리가 없다(문항 타자기 없음). 문항 쪽에 그런 자리가 생기면 맞출 길이 = `speech_end_ms ÷ rate`(`duration_ms`도 같은 비율)로 맞춘다 — ADR-0080 재검토 조건 2.
