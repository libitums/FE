# ADR-0116 — 학습 보상은 엽전이다 (처음 통과 10 · 받은 유닛에서 파생 · 머리 칩 · 하나씩 날아 차는 결과 화면)

- 상태: **채택 — 클라이언트 + 서버 병합 함수.** 호스트 · 콘텐츠 변경은 0이다. **사용자 결정**(2026-11-09) — 아래 굵은 문장.
  시안: Artifact 「엽전 재화 시안」(Main · Chips · Shop · Refill 보드), 상품 그림은 사용자가 준 세 장.
  ⚠ 원격 DB 마이그레이션 `20261109120000_learning_progress_coin_units.sql`은 **적용 전**이다 — 사용자가 대시보드 SQL Editor로 적용한다(아래 D3 「적용 전」).
- 날짜: 2026-11-09.
- 다루는 축: 보상 재화의 이름 · 그림, 지급 규칙, 보유량의 저장과 병합, 머리 칩, 결과 화면의 보상 카드와 움직임.
  **다루지 않는 것**: 엽전 쓰기(상점 · 티켓 충전 · 이야기 해금), 젬 구매 화면(`screens/gem-purchase` — 숨김 그대로), 결제 연동, 롤플레이 이야기 결과 화면의 지급.

근거 표시: **[코드]** 저장소 코드(`apps/mobile/src/` 기준) · **[실측]** 빌드 · 테스트 · 시뮬레이터 · **[ADR]** 기존 결정 · **[추론]** 관찰 없이 이어 붙인 것.

## 맥락

1. 결과 화면의 보상 카드는 다이아(젬) 「+ 0 REWARD」였다 — 출시 때 젬을 주지 않기로 해 0으로 고정한 자리였다 [코드 `lessonRewardPlaceholder`]. 보유 젬은 시작값 0으로 고정이고 저장되지 않았다 [코드 `AppSession` `gemCount`].
2. 사용자가 이 앱에 맞는 재화로 엽전을 골랐다 — 한국어 학습 앱의 정체성, 16px에서도 갈리는 네모 구멍, 무제한 티켓의 주황과 같은 따뜻한 계열(대화 기록).
3. 진행 스냅숏은 이미 선택 필드 · 키별 합집합 병합 · 기기 미전송 · 저장본 경로를 갖는다(ADR-0075 `tickets` · `ticketUnits`) [ADR].

## 결정

### D1. **카탈로그 레슨 · 최종 테스트를 처음 통과하면 엽전 10개 — 사용자 결정**

- 처음 = 이 세션을 열기 전 진행에도, 엽전을 받은 유닛(`coinUnits`)에도 그 유닛이 없었다(`catalog-lesson-wiring.ts` `firstClearOf`, 렌더 시점). 미통과 · 이미 끝낸 유닛 다시 하기 · 이미 엽전을 받은 유닛은 0.
- 보일 문항이 없어 바로 통과하는 유닛도 같은 규칙이다 [코드]. 표지 · 막간 이야기 · 롤플레이는 결과 화면이 없거나 레슨이 아니라 주지 않는다.
- 이 기능 전에 끝낸 유닛은 받은 것으로 치지 않는다 — 소급 지급 없음 [추론 — 사용자 미확인, 아래 「사용자 확인 필요」].

### D2. 보유 엽전은 따로 세지 않고 「엽전을 받은 유닛」에서 파생한다

`lib/coins.ts` — `coinBalanceOf(coinUnits) = 10 × 유닛 수`.

- 값 하나(보유량)를 저장하면 두 기기의 병합이 「큰 값」이 되어 한쪽에서 받은 엽전을 잃는다. 유닛 목록은 키별 합집합이라 **두 기기에서 받은 엽전이 합쳐지고 줄지 않으며, 같은 유닛을 두 번 받지 않는다**.
- 대가: 유닛마다 금액이 같다는 가정이 모양에 들어 있다. 금액이 갈리거나 엽전을 쓰게 되면 새 선택 필드(쓴 양 · 유닛별 금액)가 필요하다 — 이 결정의 재검토 조건이다.
- 버린 것: 보유량 숫자 하나(병합에서 잃음) · 「카탈로그 진행에서 파생」(이 기능 전 진행까지 소급 지급되고, 지급 규칙을 바꾸면 과거 보유량이 바뀜).

### D3. `coinUnits`는 진행 스냅숏의 선택 필드다

- `LearningProgressSnapshotV1.coinUnits?`, `JourneyProgressState.coinUnits?` — 비면 싣지 않는다(옛 서버 · 옛 앱과 바이트가 같다). 모양은 `catalogProgress` · `ticketUnits`와 같고, 틀리면 그 필드만 비운다.
- 오프라인 · 미전송 · 저장본 · 재시도 · 계정 전환 · 비회원은 진행과 똑같다 — 새 저장 키가 없다.
- 서버: 마이그레이션 `20261109120000_learning_progress_coin_units.sql`이 `merge_learning_progress_v1`에 검증(어기면 `22023 invalid coin units`)과 키별 합집합을 더한다(SQL 테스트 CU1 ~ CU3).
  **적용 전**에는 서버가 들어온 쪽 `coinUnits`를 남긴다(`p_saved || p_incoming`) — 앱이 불러올 때 기기 쪽과 합친 값을 보내므로 한 기기에서는 차이가 없고, 두 기기가 같은 순간 저장할 때만 뒤에 온 쪽이 이긴다 [추론 — ADR-0075 D3과 같다].
- 스냅숏 16 KiB 상한: `coinUnits`는 끝낸 유닛 키만큼 자라 `catalogProgress`와 비슷한 크기다 [추론].

### D4. 머리 칩 — 지도 상단 바 · 결과 화면 머리

- `StatChip` tone `coin`(`diamond`를 대체 — 소비처가 없었다 [코드]). 시안 A안: 흰 칩 그대로, 아이콘 `components/coin-icon.ts`(다색 · 구멍 투명), 숫자 #9A5E12(흰 바탕 5.3:1 · 카드 4.8:1).
- 지도: 연속 · 트로피 · 티켓 다음. 진행을 불러오는 동안은 그리지 않는다(트로피와 같음). ⟨2026-11-09 개정⟩ 지도 칩은 숫자 뒤에 작은 「+」(시안 B)를 단 버튼이고 누르면 엽전 상점(D7)을 연다 — 이름 「N coins, get more」. 「+」 상자는 시안 #E8A848이 흰 칩 위 2:1 남짓이라 #C27A22(3.2:1)로 칠했다. 결과 화면 머리 칩은 읽기 전용(「N coins」) 그대로다.
- 엽전 칩이 서면 칩이 넷이라 상단 줄을 조밀하게 한다(간격 9 → 6, 칩 좌우 여백 12 → 8) — 402pt 실측 기준으로 360 폭에서 엽전 세 자리부터 알림 버튼과 겹칠 수 있었다(리뷰 W1). 조밀한 줄은 402pt에서 알림 앞 약 96pt가 남는다 [실측].
- 숫자 색: 시안의 #B26E16은 흰 바탕 4.1:1 · 카드 3.75:1로 AA(4.5:1) 미달이라 **#9A5E12**(흰 5.3:1 · 카드 4.8:1)로 어둡게 했다 — 접근성 점검 지적, 사용자 확인 필요 4.

### D5. **결과 화면 — 엽전이 하나씩 머리 칩으로 날아가 숫자가 찬다 — 사용자 결정**

- 보상 카드: 받은 엽전이 있을 때만 엽전 카드(황동 면 #FFF4E0 · 「+ 10 REWARD」 · 이름 「Reward, 10 coins」). 0이면 등급 카드만 선다 — 「+ 0」은 얻지 않은 것을 그리는 것이다(ADR-0022 D1과 같은 근거). 미통과에서는 줄 전체가 서지 않는다(그대로).
- 성취 모션: 보상 카드가 다 올라온 뒤(`d7 + d6`) 카드 아이콘 · 칩 아이콘 자리를 재고(`boundingClientRect`), 엽전 10개가 `d1` 간격으로 떠나 `d7` 동안 날아 0.7배로 작아지며 칩에 닿는다. 닿을 때마다 칩 숫자 +1, 마지막 엽전이 닿을 때 아이콘 톡(매번 튀면 50 ms 간격으로 떨려 보인다 — 접근성 점검). 칩은 보상 전 값에서 시작하고 이름은 처음부터 보유량이다.
- 자리를 재지 못하면 날지 않고 칩이 바로 보유량이 된다 — 숫자가 보상 전에 멈추지 않게.
- 움직임 줄이기: 날지 않고 칩 숫자만 보상 전 값에서 보유량으로 페이드(기존 `StatChip` 오름 경로).

### D7. **엽전 상점 — 결제 전에도 모두에게 보인다 — 사용자 결정 (2026-11-09)**

- 지도 엽전 칩 → `screens/coin-shop/CoinShopScreen`(머리 겹침 레이어, 시안 「엽전 상점」). 팩은 엮음 500 · 주머니 1,000+200(BEST VALUE, 처음 고름) · 큰 주머니 2,000+1,000, $4.99 · $9.99 · $19.99 — ⟨2026-11-10 개정, 사용자 결정⟩ 1엽전 ≈ 1센트. 처음 통과 10엽전이라 에피소드 하나 ≈ 100엽전인데 옛 임시값(50 · 140 · 360)은 버는 양에 비해 너무 비쌌다. 메신저 자유 대화의 엽전 가격(무료 3통 뒤 메시지 10 · 음성 40 · 사진 60, ADR-0113 · PR #406)과 같은 눈금이다. 그림은 사용자 주머니 그림을 webp 204px로 줄여 실었다(`assets/`, 번들 밖 static).
- 결제 연동이 없어 「Buy for $…」는 「결제 준비 중」 안내만 띄우고 엽전은 늘지 않는다. 옛 젬 구매 화면(`screens/gem-purchase`, PR #140 · #211에서 숨김)은 지우고 이 화면이 대신한다. 문구 구획 `gemPurchase` → `coinShop`(5개 언어).
- ⚠ **App Store 심사 위험**: PR #211은 결제 없는 구매 진입점을 심사 전에 숨겼다. 사용자가 「모두에게 보이기」를 골랐다 — 실제 결제가 없는 가격표가 심사에서 2.1 · 3.1.1로 지적될 수 있다. 재검토 조건에 둔다.
- ⟨2026-11-10 개정, 사용자 결정 — 「엽전으로 전부」⟩ **메신저(ADR-0113, PR #406)도 엽전을 쓴다.** #406은 젬(자리 표시 잔액 `gemCount` = 0 · 다이아 칩 · 옛 젬 화면)을 썼는데 이 PR이 젬 화면과 다이아 칩을 지웠다. 목록 칩 · 사진/음성 요청 대화상자 · 설정 사이드바의 잔액은 보유 엽전(`coinCount`), 칩 · 요청 버튼 아이콘은 엽전, 「Get …」은 엽전 상점(`GemShopLayer` → `CoinShopScreen`, 방 안에서는 `ownsBack={false}`로 층을 올리지 않음), 메신저 문구의 gems는 5개 언어 모두 상점과 같은 말(coins · monedas · koin · コイン〇枚 · xu)로 바꿨다. 가격 숫자(`CHAT_PLACEHOLDERS`)는 그대로다. 컴포넌트 · 속성 · testid 이름(`gemBalance` · `GemShopLayer` · `messenger-list-gem`)은 아직 gem — 다음 정리에서 바꾼다.

### D6. 문구 — 5개 언어

`lessonComplete.rewardDiamonds` → `rewardCoins`, `common.count.diamonds` → `coins`: en coin(s) · es moneda(s) · id koin · ja コイン〇枚 · vi xu. 화면 글자 「+ 10 REWARD」는 그대로다. 「엽전」이라는 이름은 화면 글자에 아직 없다(아이콘이 말한다) [추론].

## 사용자 확인 필요

1. 소급 지급 없음(D1) — 이 기능 전에 끝낸 레슨은 0. 주려면 첫 불러오기 때 `catalogProgress`를 `coinUnits`로 한 번 옮기면 된다.
2. 원격 DB 마이그레이션 적용(D3).
3. 최종 테스트도 10(레슨과 같음)인지.
4. 엽전 숫자 · 카드 글자 색을 시안 #B26E16에서 #9A5E12로 바꾼 것(D4 — 명도 대비).
5. 결과 화면 진입 낭독에 받은 엽전을 덧붙일지(접근성 점검 제안 — 지금은 카드에 가야 들린다).

## 재검토 조건

- 앱 심사에서 엽전 상점(결제 없는 가격표)이 지적되면 D7을 다시 본다 — 숨기거나 결제를 붙인다.

- 엽전을 쓰는 화면(상점 · 티켓 충전)이 생길 때 — 쓴 양 필드와 병합 규칙(D2).
- 유닛마다 금액이 달라질 때(D2).

## 적용 기록

- ⟨2026-11-09⟩ iOS 시뮬레이터(iPhone 17 Pro, 6.3")에서 결과 화면만 띄운 임시 진입점으로 성취 모션을 녹화했다 — 엽전이 카드에서 줄지어 칩으로 날아가며 칩 20 → 21 … → 30, 마지막 30 정지. [성능 기록](../performance/reports/yeopjeon-reward-iphone-17-pro-simulator-01.md), [e2e](../e2e/yeopjeon-reward.md).

⟨2026-11-10⟩ 상단 바 좁은 폭(사용자 결정): 320 · 340 · 360 · 375 · 390 폭에 최악의 수(연속 365 · 트로피 999 · 티켓 99 · 엽전 9,999)를 넣어 iOS 시뮬레이터로 쟀더니 360 미만에서 알림 버튼이 엽전 칩을 덮었다. 그래서 (1) 칩 넷 모두 999를 넘는 수는 「999+」로 보이고 낭독은 실제 수를 읽는다(`components/top-bar-layout.ts` `statChipText`, 오르기 · 내리기 움직임 중에도 같은 규칙 — `StatChip.formatValue`), (2) 창 폭(`SystemInfo`)이 360 미만이면 엽전 칩의 「+」를 뺀다(칩 자체가 상점 버튼, 이름 「N coins, get more」 그대로). 결과: 340은 맞고, 320은 아직 약 18pt 모자란다(후속 결정).

⟨2026-11-10, 2차⟩ 340 미만 폭은 촘촘하게(사용자 결정 A): 320 폭 iOS 시뮬레이터에서 「+」를 빼도 알림 버튼이 엽전 칩 끝을 약 18pt 덮었다. 340 미만(`topBarDenseAt`, `SystemInfo` 폭, 모르면 끔)에서만 칩 줄에 `top-bar-stats-dense`를 달아 간격 6 → 4 · 칩 좌우 여백 8 → 6(약 22pt)으로 줄인다. 340 이상은 그대로. 테스트 TBL6 · TBL7 · TB-N5 · TB-N6(먼저 실패 확인). ⚠ 320 폭 실측 재확인은 아직이다.
