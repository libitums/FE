# ADR-0067 — 새 에피소드 형식 ③: 말하기 둘은 각자 새 학습형으로 서고, 인식할 수 없으면 활동 안에서 잠가 `Skip`으로 넘기며, 건너뛴 문항은 건너뜀 수에 들고 통과 분모에서 빠진다

- 상태: **채택 — 클라이언트 쪽.** [ADR-0065](0065-episode-format-additions.md)이 나눈 PR 셋 가운데 **③**이다(① 디코더 · 단계 · 완료 계약 · 내장본 교체, ② 문화 · 조립 화면 — [ADR-0066](0066-episode-format-screens.md), ③ 말하기 — 이 문서).
  사용자 결정(2026-10-16)은 넷이다 — 낱말 말하기에 **영어 뜻을 보인다**(Q1) · 낱말 말하기 준비 국면에 **사용자 `Skip`을 둔다**(Q3 — 건너뜀 수에 든다) · `episode_lesson_finished`에 **`skippedCount`를 더한다**(Q4) ·
  건너뛴 문항은 **통과 분모에서 뺀다**(Q5). 나머지 일곱(Q2 · Q6 ~ Q11)은 **메인이 추천안을 골랐다** — 사용자 명시 승인이 아니다(아래 「사용자 결정과 메인 추천안」).
  ⚠ **기기 확인이 일부다.** iOS 시뮬레이터 한 회차(옛 진행 계정)가 u01 `Lesson 5` 읽기 화면 · 권한 창 둘 · 둘 다 거부한 뒤의 막힘과 활동 안 잠금을 봤고,
  **허용 경로 · 실제 음성 인식 · 낱말 말하기 화면 · 레슨 결과 · 접근성 수정이 든 빌드 · VoiceOver · Android는 보지 못했다**([말하기 화면 e2e](../e2e/episode-format-speaking.md)).
- 날짜: 2026-10-16.
- 다루는 축: **새 형식의 말하기 문항 두 유형의 자리** — `SHADOW`(글 보고 소리 내어 읽기) · `SPEAK_WORD`(그림 보고 낱말 말하기)를 어느 화면에 싣는가, 채점 여부, 인식 결선과 불가 사유, 권한 거부 · 인식기 없음의 처리,
  낱말 판정 · 정답 공개 · 뜻 줄, 카탈로그 활동이 내는 **런타임 건너뜀 수**와 **통과 분모**, 건너뜀 사유 `screen-pending`의 삭제, 측정 속성 하나.
  **다루지 않는 것**: 소리 조립(`LISTEN_BUILD`)의 화면(ADR-0066 D8 그대로 — 문항 음성이 먼저), 학습 문항 음성(ADR README 보류 표 「학습 문항 오디오의 연결」), 튜토리얼 말하기 화면(`screens/speaking/`)과 최종 테스트 말하기(`screens/episode-final/`)의 동작 —
  바뀌지 않았다(문구 하나는 공유 키라 함께 바뀌었다 — 「구현 판단」 6), 「하나만 거부된 상태의 처방」 · 설정 이동([ADR-0026](0026-permission-entry-conditions-and-denial-handling.md) 재검토 조건 — 여전히 비어 있다).
- 부분 대체:
  - [ADR-0065](0065-episode-format-additions.md) D8 표의 **`SHADOW` · `SPEAK_WORD` 행**(`screen-pending` — PR ③) — 아래 D1 · D9.
  - [ADR-0066](0066-episode-format-screens.md) D8 끝 문장 **「`screen-pending`은 이제 말하기 둘만 낸다」** — 이제 아무 유형도 내지 않아 사유를 지웠다(D9).

- 이어받는 결정: [ADR-0058](0058-catalog-learning-session.md) D2(매핑은 `app/`의 순수 모듈) · D4(같은 학습형 연속 = 한 활동) · D5 · A3(채점 수와 표시 수) · A6(그림 로드 실패 처리),
  [ADR-0026](0026-permission-entry-conditions-and-denial-handling.md) D3 · D5(미요청만 묻는다) · 2026-09-28 기록(「거부돼도 학습을 계속한다」 · 설정 이동 없음), [ADR-0017](0017-host-native-capabilities-and-audio.md)(접점 · 모듈 변경 0),
  [ADR-0016](0016-assistive-technology-semantics.md) D5 · D10 · D11(낭독 — 바꾸지 않는다), [ADR-0029](0029-product-analytics-posthog.md) D14(카탈로그 학습 이벤트 — 속성은 10진 문자열), 화면 폴더 사이 값 import 금지(`docs/conventions/code.md` 「import」).
  각 ADR에는 적용 기록이 붙었다.

**왜 새 번호인가** — ADR-0066은 「문화 · 조립 화면과 문화 노드」의 결정이다. 이 변경은 **말하기 · 권한 · 채점 분모 · 측정 속성**이라 결정의 대상이 다르고,
ADR-0066 「미확인 · 후속」 3과 ADR-0065 머리의 「(PR ③) 말하기 권한이 없으면 건너뛴다」가 가리킨 자리다. 제자리로 쓰면 0058의 통과 분모 · 0026의 권한 처리 · 0029의 이벤트 모양 위에 조각이 흩어진다(ADR-0010 D10 넷째 줄).

근거 표시: **[코드]** 저장소 코드 · **[데이터]** 내장본(version `2026-10-16.1`) 전수 조사 · **[실측]** 빌드 · 실행 · **[실기]** iOS 시뮬레이터 관찰 · **[추론]** 관찰 없이 이어 붙인 것.
계약의 정본은 저장소 밖 작업 폴더의 spec이고 이 문서는 그중 **결정**만 옮긴다. 시그니처는 코드가 진다. 파일 모양의 관찰값은 [콘텐츠 계약](../specs/episode-content-json-contract.md) §7.2가 진다.

## 맥락

1. **말하기 두 유형 15문항이 레슨에서 빠져 있었다** [데이터]. `SHADOW` 9(세 에피소드 `S5` 끝 셋씩) · `SPEAK_WORD` 6(각 에피소드 `S6` · `S8`에 하나씩)이 `screen-pending`이었고, `screen-pending`을 내는 유형은 이 둘뿐이었다.
2. **`SHADOW`는 이름이 「듣고 따라 말하기」인데 음성이 없다** [데이터]. `prompt`는 「듣고 따라 말하세요 / Listen and repeat.」이지만 `audio_url`은 9/9 빈 값이다. 문장은 8 ~ 17자 · 2 ~ 5어절이고 **문장 부호가 9/9**(`.` `,` `?`) 있다 — 튜토리얼 말하기 문장은 부호가 0이다.
   u03 `S5-10`의 `stimulus.text.en`은 「Hello, I'm {이름}.」인데 한국어는 고정 이름 「은지」이고 `answers[0].en`은 「Hello, I'm Eunji.」다.
3. **`SPEAK_WORD`는 그림 한 장 + 한 낱말 정답이다** [데이터]. 정답 2 ~ 4자 · 공백 0(카드 · 영수증 · 비밀번호 · 여권 · 학생 · 나라), `answers[0].en` · `roman` · `image_url` 모두 6/6. 그림 한 컷이 낱말 하나를 못 정하는 문항이 있다(password · country · student).
4. **말하기 자산은 이미 있다** [코드]. 판정 `lib/speaking-judge.ts`(앞에서부터 연달아 맞은 낱말 수 · 문장 전부면 정답) · 접점 `lib/speech-recognition*`(미요청만 묻는다 · 결과 콜백 한 번) · 튜토리얼 화면 · 최종 테스트 훅.
   튜토리얼 화면은 문항 표가 스텝 표에 묶였고, 카드에 대비 미달 값 넷이 있으며, 건너뛰기 규칙이 카탈로그 요구와 반대다(사용자 `Skip` = `"correct"`).
5. **카탈로그 활동은 런타임 건너뜀 수를 낸 적이 없다** [코드]. 모든 카탈로그 활동이 `onFinish(results, 0)`이었고, 이벤트 `episode_lesson_started.skippedItemCount`는 **매핑 때** 건너뛴 수라 런타임 건너뜀을 싣지 않는다.

## 결정

### D1. 화면 결정 — 새 학습형 둘, 튜토리얼 화면은 넓히지 않는다

| 유형 | 결정 | 근거 |
|---|---|---|
| `SHADOW` | **새 학습형 `read-aloud`**(폴더 `screens/read-aloud/`) — 문장을 보고 소리 내어 읽는다, **채점하지 않는다** | 채점 표는 학습형마다 한 행이라 튜토리얼 `speaking`과 같은 학습형일 수 없다. 끝이 카드 활동이다(결과 0 · 완료 카드 없음). 판정 배지 자리의 `Practice` 표식 · 맞은 낱말 수 줄 · `Try again`은 튜토리얼에 없는 자리 셋이다. 이름은 **화면이 하는 일**로 짓는다 — 음성이 없어 콘텐츠 이름(듣고 따라 말하기)과 뜻이 다르다 |
| `SPEAK_WORD` | **새 학습형 `speak-word`**(폴더 `screens/speak-word/`) — 그림 · 뜻을 보고 낱말을 말한다, **채점한다** | 그림 제시 + 말하기 + 채점 + 정답 공개는 단어 선택(고르기)도 튜토리얼 말하기(문장 읽기)도 아니다. 그림 문항의 **로드 규칙**만 단어 선택과 공유한다(D6) |

두 활동이 함께 쓰는 것은 **결선 · 부품 · 순수 규칙**이고(D2 · D3 · D4), 활동 컴포넌트는 각자다(명시적 변형). 새 boolean prop은 0개다 — 마이크 상태는 `state: "idle" | "listening" | "off"`,
국면은 판별 유니온(`SpeechAttemptPhase`), 버튼은 이름 있는 조작(`SpeechControl` — `speak` · `stop` · `next` · `skip` · `retry`)이다. 새 화면 둘은 셸 · `components/` · `lib/`만 값으로 가져온다 — **새 import 예외 0**.

### D2. 인식 결선 — 공유 훅 하나, 불가 사유 셋

- `components/use-speech-attempt.ts`가 튜토리얼 · 최종 테스트와 **같은 결선**을 한다: `requestSpeechPermissions`(미요청인 것만 — ADR-0026 D5) → 들을 수 있으면 `startSpeechRecognition`, 아니면 막힘. 화면을 떠나면 인식을 멈추고 늦게 온 콜백은 버린다.
- 국면 `ready` · `listening` · `heard{text}` · `unavailable{reason}`. `recognized`는 빈 글자도 `heard`다(읽기는 「0 of n」, 낱말은 오답). 불가 사유:

| 사유 | 무엇으로 아는가 | 화면 |
|---|---|---|
| `blocked` | 접점 없음 · 권한 거부 · 제한 · 인식기 없음(결과 `permission-denied` · `recognizer-unavailable` 포함) | 안내 줄 + `Skip`. **활동 안에서 잠긴다**(D5) |
| `dictation-off` | iOS 받아쓰기 꺼짐(`kLSRErrorDomain` 201 — **다른 사유보다 먼저** 가린다, 튜토리얼과 같은 조건) | 지시문이 받아쓰기 안내로 바뀌고 `Try again` + `Skip` |
| `failed` | 그 밖의 비인식 결과 | 안내 줄 + `Skip`. 잠기지 않는다(다음 문항은 `ready`) · **재시도 없음**(Q8) |

- **듣기 시작 때 알리지 않는다** — 마이크가 켜진 동안의 화면 낭독은 인식기에 그대로 들어간다. 듣는 중은 주 버튼 이름(`Stop speaking`)과 마이크 요소 이름이 말한다.
- 튜토리얼 화면 · 최종 테스트 훅은 이 훅으로 옮기지 않았다 — 같은 결선이 셋이 됐다(「대가」 2).

### D3. 마이크 부품 — `components/SpeechWaves`, 상태 셋

`idle`(대기 — `gray-700`, 누를 수 있음) · `listening`(`brand-primary`) · `off`(`gray-300` — 접근성 요소도 아니고 탭도 받지 않는다). 국면에서 나온다: `ready` → `idle`, `listening` → `listening`, 그 밖 → `off`.
낱말 말하기는 그림 로딩 중에도 `off`다. 누를 수 있으면 이름은 주 버튼과 같은 `Speak` / `Stop speaking`이고 같은 조작이다. 튜토리얼 카드의 대기색(`gray-300`, 1.15:1)을 복사하지 않았다.

### D4. `SHADOW` → `read-aloud` — 채점 없음, 결과만 보이고 넘긴다

- **문항의 출처는 한 묶음이다** — `answers[0]`의 한국어가 비지 않으면 `answers[0]`, 아니면 `stimulus.text`에서 문장 · 로마자 · 영어 세 줄을 **같은 묶음에서** 읽는다(u03 `S5-10`의 자리표시자를 피하고, 따라 말할 정답 문장이 곧 보이는 문장이 되게). 둘 다 비면 `malformed`.
  **`prompt.en`(「Listen and repeat.」)은 쓰지 않는다** — 음성이 없다. 지시문은 `Read the sentence out loud.`(튜토리얼 말하기와 같은 문구).
- **부호를 지키며 칠한다** — `speakingChunks`가 공백으로만 자른 조각(「왔어요?」)마다 칠할지를 정한다. 칠할 낱말 수는 지금 `matchedWordCount`(부호를 뗀 대조) 그대로다. 튜토리얼 판정은 바뀌지 않는다.
- **국면별 조작**:

| 국면 | 주 | 보조 | 안내 줄 |
|---|---|---|---|
| `ready` | `Speak` | `Next` | — |
| `listening` | `Stop speaking` | — | — |
| `heard` | `Next` | `Try again` | 맞은 낱말 수(「구현 판단」 4) |
| `dictation-off` | `Skip` | `Try again` | — (지시문 교체) |
| `blocked` · `failed` | `Skip` | — | 인식 불가 안내 |

  마지막 문항의 `Next`는 레슨 끝이면 `See results`다. **듣는 중만 빼고 늘 넘길 수 있다.** `Try again`은 채점 없는 연습이라 둔다(Q10).
- **`ready`의 `Next`는 건너뜀이 아니다** — 채점 대상이 아니라 건너뛸 점수가 없다. **불가 국면의 `Skip`만** 건너뜀 수 +1이다(Q2). 결과 배열은 늘 `[]`이고, 완료 카드 · 판정 배지 · 판정음이 없다.
- 걸음(`readAloudStepOf`)은 화면 자기 순수 모듈이다 — 단어 카드 · 문화 카드의 같은 꼴 함수를 값으로 가져오지 않는다(화면 폴더 사이 값 import 금지).

### D5. 권한 거부 · 인식기 없음 — 활동 안에서 잠그고, 자동으로 넘기지 않는다

- 활동 상태에 `availability: "open" | "blocked"`. `blocked`가 서면 **같은 활동 안에서는 되돌아가지 않고**, 다음 문항은 처음부터 `blocked` 불가 국면(안내 + `Skip` 하나)으로 선다 — 다시 `Speak`를 누르게 하지 않는다.
- **같은 레슨의 다른 활동 · 다시 하기는 새로 연다**(`open`) — 그 첫 `Speak`가 다시 확인하고(거부된 권한은 다이얼로그 없이 즉시 거부) 곧장 막힌다. 지금 데이터는 한 레슨에 말하기 활동이 하나뿐이라(`S5`는 읽기 셋이 한 활동, `S6` · `S8`은 낱말 하나) 이 차이가 실데이터에서 일어나지 않는다.
  레슨 단위로 잠그려면 결선에 상태가 생겨 300줄 상한에 걸린 세션 파일(`app/AppSession.tsx`)을 열어야 해서 하지 않았다(Q6).
- **자동으로 넘기지 않는다** — 문항이 사용자 조작 없이 지나가면 스크린리더 사용자가 무엇이 지나갔는지 듣지 못한다. 각 문항은 내용을 보이고 안내 + `Skip`을 낸다.
- **설정으로 보내는 수단을 두지 않는다** — 튜토리얼 말하기와 같은 선택(ADR-0026 2026-09-28 기록). 새 외부 이동 0. `failed`는 기기 능력이 아니라 그 한 번의 실패라 잠그지 않는다.

### D6. `SPEAK_WORD` → `speak-word` — 그림 · 뜻 · 판정 · 정답 공개

- **매핑 판정 순서**: 정답이 0개 → `malformed` → 그림 주소가 없거나 풀리지 않음 → `image-missing` → 뜻(`answers[0].en` → 낱말 목록)이 없음 → `no-gloss`. 로마자 = `answers[0].roman`, 지시문 = `prompt.en`(「Say the word for the picture.」).
  그림 고르기(`IMG_MATCH`)와 같은 순서 · 같은 사유다 — **그림 주소가 없는 낱말 말하기는 건너뛴다**.
- **판정은 기존 규칙 그대로다** — 정답 중 하나라도 `judgeSpeaking(정답, 들은 글자)`가 정답이면 정답. 즉 **들은 글자의 앞 낱말이 정답 낱말과 같으면** 정답이고 뒤에 붙은 낱말은 무시된다(「카드 주세요」 → 정답, 「카드요」 · 「비밀 번호」 → 오답).
  띄어쓰기 · 어미 관용은 넓히지 않았다 — 실제 인식 글자를 기기에서 본 뒤 정한다(Q7, ADR README 보류 표).
- **영어 뜻 줄을 보인다 — 사용자 결정**(Q1). 그림이 낱말 하나를 못 정하는 문항이 있고, 그림 틀 낭독이 이미 `Picture: password`라 보는 사람에게도 같은 정보를 준다. 영어 → 한국어 산출이라 정답을 흘리지 않는다.
  뜻 줄은 접근성 요소가 아니다(틀 이름과 두 번 읽히지 않게). 그림이 실패하면 틀 안 대체 글자가 같은 뜻을 보여 뜻 줄을 그리지 않는다.
- **그림 로드**는 단어 선택 그림 문항과 같은 규칙이다(`loading → loaded / failed` · 6초 시한 · 실패 시 뜻 글자 + `Picture unavailable`). 순수 전이 · 시한을 `lib/picture-load.ts`로 올려 둘이 함께 쓴다(옛 경로는 재수출 — `docs/conventions/code.md` 「import」 ⟨2026-10-16⟩).
  로딩 중에는 `Speak`가 없고(그림을 보기 전에 말하지 않게) `Skip`은 선다.
- **판정 뒤**: 판정 배지 · **정답 상자 `Answer: 비밀번호 · bimilbeonho`가 맞아도 선다**(발음 확인 — 로마자를 붙인다, Q11) · 안내 줄 `Tap the screen to continue` · 2.5초 뒤 자동 넘김(튜토리얼 말하기 · 단어 선택과 같은 값). **판정 뒤 재시도 없음.**
  들은 글자는 보이지 않는다(기존 말하기와 같다). 레슨 끝 활동이면 완료 카드 → `See results`.
- **준비 국면에 사용자 `Skip`이 선다 — 사용자 결정**(Q3). 기기가 멀쩡해도 소리 낼 수 없는 자리의 사용자가 틀리는 수밖에 없게 하지 않는다. 결과에 싣지 않고 건너뜀 수 +1이다 —
  튜토리얼처럼 `"correct"`로 싣지 **않는다**(정답 수가 측정에 나가므로 하지 않은 것을 맞힌 것으로 세면 측정이 거짓이 된다).

### D7. 건너뜀 수와 통과 분모 — 카탈로그의 규칙(튜토리얼과 다르다)

- **활동이 건너뜀 수를 낸다** — 읽기 = 불가 국면의 `Skip` 수, 낱말 = 건너뛴 문항 수(사용자 `Skip` + 불가 `Skip`). 결선이 이미 있던 레슨 합계로 잇고(새 상태 0), 결과 화면이 받는다 → **만점(`PERFECT LESSON!`) 아님** · 낭독에 `, n skipped question(s)`.
  **런타임 건너뜀 수를 내는 첫 카탈로그 활동**이다.
- **통과 분모 = 판정한 채점 문항 수** — `catalogJudgedCountOf(채점 문항 수, 결과) = min(채점 문항 수, 결과 수)`. 채점 활동은 판정한 문항마다 결과 하나를 올리고 비채점 활동은 `[]`라 **결과 수 = 판정한 채점 문항 수**다 — **사용자 결정**(Q5).
  건너뛴 낱말은 분모에서 빠지고, 건너뛴 읽기는 처음부터 분모 밖이다. 「채점 문항 수 − 건너뜀 수」로 빼지 않는 이유: 건너뜀 수에 **비채점 읽기의 건너뜀이 섞여** 채점 분모가 틀어진다.
  - 예: u02 `S6`(채점 12, 기준 8) — 낱말을 건너뛰면 분모 11 · 기준 7.
  - 채점 문항을 전부 건너뛰면 분모 0 → 기준 0 → 통과(「단계 완료를 막지 않는다」 — 지금 데이터에 그런 단계는 없다).
- 결과 route의 `questionCount`(「통과 기준의 분모」)는 판정 분모이고, 이벤트의 `questionCount`는 **계획의 채점 문항 수 그대로**다(뜻 불변 — 「측정」).
- **튜토리얼과 갈리는 점** — 튜토리얼 말하기는 기기 불가 건너뜀을 세지 않고 사용자 `Skip`을 `"correct"`로 싣는다(고정 기준 「셋 중 둘」에서 사용자 건너뜀이 통과를 막지 않게). 카탈로그는 기준이 비율이라 **분모에서 빼는 것**으로 같은 목적을 이룬다.

### D8. 학습형 어휘 — 셸 값 둘, 머리 라벨은 둘 다 `Speaking`

`LearningActivityForm`에 `"read-aloud"` · `"speak-word"`. 머리 라벨은 둘 다 `Speaking`(디자인 — 「Speaking 그대로」), 타이밍 표식은 `libitum:navigation:learning-read-aloud` · `…-speak-word`다.
보이는 결과는 디자인의 「`form="speaking"`」 가정과 같고, 학습형 값이 둘인 것은 채점 표 · 계획 묶음 · 타이밍 표식이 학습형마다 한 행이기 때문이다. 튜토리얼 `LearningForm`은 넓히지 않았다. 카탈로그 활동 학습형은 열이 됐다.

### D9. 건너뜀 사유 `screen-pending`을 지운다

이 변경 뒤 `screen-pending`을 내는 유형이 0이다. 쓰지 않는 사유를 남기면 「화면이 아직 없는 유형이 있다」로 읽힌다 — ADR-0058(3d-1)이 같은 이유로 한 번 지웠고(ADR-0065이 되살림) 같은 저울로 다시 지운다(Q9).
사유는 **여덟 → 일곱**(`no-options` · `no-source` · `audio-missing` · `image-missing` · `no-gloss` · `untypeable` · `malformed`). 사유는 이벤트로 나가지 않아 대시보드 영향이 없다. 다음에 화면 없는 유형이 오면 그때 되살린다.
세 에피소드의 건너뜀 분포는 `screen-pending` 15 → 0이고, 단계 표시 수는 `S5` 6 → 9 · 6 → 9 · 7 → 10, `S6` · `S8`은 각 +1이다(채점 수는 `S6` · `S8`만 +1) [데이터 — unit 테스트가 실제 값으로 고정].

### 측정

**새 이벤트 0, 속성 하나** — `episode_lesson_finished.skippedCount`(10진 문자열)는 그 레슨의 활동들이 낸 건너뜀 수의 합이다(최종 테스트 · 0개 경로는 `"0"`) — **사용자 결정**(Q4).
요구사항이 원한 「건너뜀으로 권한 · 인식기 불가 비율을 간접 관찰」은 기존 이벤트로는 불가하다(맥락 5). 정의 · 읽는 법 · 연속성은 [ADR-0029](0029-product-analytics-posthog.md) D14 적용 기록 ⟨2026-10-16⟩이 진다.
**GitHub wiki 이벤트 사전은 저장소 밖이라 이 변경에 들어 있지 않다** — 속성 한 줄과 읽는 법을 옮겨야 한다(후속, 아래 「미확인 · 후속」 4).

## 버린 대안

1. **`SpeakingScreen`에 `graded` / `practice` 모드** — 한 화면 두 모드(boolean 증식과 같은 문제), 튜토리얼 문항 표 · 건너뜀 규칙(사용자 `Skip` = `"correct"`)과 섞인다(D1).
2. **튜토리얼 `SpeakingSentenceCard` 재사용** — 대비 미달 값 · `judged`/`listening` boolean · 부호 지움을 그대로 끌고 온다(D1 · D4).
3. **단어 선택 폴더에 낱말 말하기 변형** — 말하기 결선이 단어 선택에 들어오고 testid가 섞인다. **읽기와 낱말을 한 활동 + `variant`로** — 채점 · 끝 · 버튼 규칙이 달라 갈래가 화면 전체에 퍼진다(D1).
4. **`WordChoicePicture`를 `components/`로 올려 공유** — 이름표 · `word-choice-picture-*` testid · 단어 선택 훅에 묶여 있어 옮기면 단어 선택 테스트가 바뀐다. 순수 전이 · 시한만 올렸다(D6).
5. **권한이 막히면 남은 말하기 문항을 자동으로 넘김** — 탭은 줄지만 문항이 보이지 않고 지나간다. **레슨 단위 잠금** — 세션 파일(300줄)을 연다(D5 · Q6).
6. **사용자 `Skip`을 튜토리얼처럼 `"correct"`로** — 측정 `correctCount`가 거짓이 된다(D6 · Q3). **준비 국면 `Skip` 없음** — 측정이 순수한 불가 신호가 되지만 소리 낼 수 없는 자리의 사용자는 틀리는 수밖에 없다(Q3).
7. **통과 분모를 그대로 두기** — 건너뛰면 남은 문항으로 더 많이 맞혀야 하고 채점이 적은 단계에서는 통과가 막힐 수 있다. **`채점 수 − 건너뜀 수`** — 비채점 읽기의 건너뜀이 섞인다(D7 · Q5).
8. **낱말 판정을 너그럽게**(공백을 지우고 「들은 글자가 정답으로 시작」) — 「카드요」는 정답이 되지만 「카드뮴」도 정답이 되고 문장 말하기와 규칙이 갈린다(D6 · Q7).
9. **일반 인식 실패에도 `Try again`** — 튜토리얼 · 최종 테스트와 규칙이 갈린다(D2 · Q8).
10. **`screen-pending` 남기기** — 「화면 없는 유형이 있다」로 읽힌다(D9).
11. **새 이벤트(예: 말하기 불가)** — 속성 하나로 같은 질문에 답한다(「측정」).

## 구현 판단

1. **`data-*` 속성은 소문자다** — 계약은 `data-questionIndex` · `data-loadState`였고 기존 화면도 낙타 꼴(`data-cardIndex` · `data-loadState`)이다. 새 두 화면은 `data-questionindex` · `data-loadstate`로 달았다 — Lynx 테스트 라이브러리가 속성 이름을 소문자로 바꿔 읽어서 테스트와 같은 꼴로 맞췄다.
   기존 화면은 바꾸지 않았다. 관례로 올리지는 않았다(한 PR의 선택이다).
2. **그림 로딩 중 `Skip`은 작업 영역에 서고, 그림이 서면 셸 버튼 행으로 옮겨 간다** — 셸은 주 버튼이 있어야 버튼 행을 그리는데 로딩 중에는 주 버튼이 없다. 접근성 감사가 지적했다(**S3** — P2, 최대 6초 동안 같은 버튼이 다른 부모에서 다시 만들어져 VoiceOver 포커스가 튈 수 있다).
   고치려면 셸 계약(주 버튼 필수)을 바꿔야 해서 **이 PR에서는 수용하고 후속으로 넘겼다** — ADR README 보류 표 「셸의 보조 단독 버튼 행」. 기기 확인 항목은 [말하기 화면 e2e](../e2e/episode-format-speaking.md) 「미확인」.
3. **뜻 줄은 `accessibility-element={false}`다**(감사 **S1**) — 처음에는 잎 `<text>`에 `accessibility-elements-hidden`을 붙였는데 이 속성은 자손을 가린다([ADR-0016](0016-assistive-technology-semantics.md) D5) — PR ②의 A1과 같은 무효 꼴이 다시 들어왔던 것을 고쳤다.
4. **판정 알림에 정답을 싣는다**(감사 **S2**) — 이 화면은 정답 상자와 2.5초 자동 넘김을 처음 함께 쓴다. 정답 상자는 순회해야 들리는데 그 사이 넘어가 버려, 틀렸을 때 알림이 `Incorrect, Answer: 비밀번호 · bimilbeonho`다.
   맞으면 `Correct` 하나다(그때 정답은 사용자가 방금 말한 낱말이다). 새 요소 · 새 타이머 · 새 키는 없다.
5. **맞은 낱말 수 문구가 「앞에서부터」를 말한다**(감사 **S4**) — 듣는 사람은 칠이 어디서 끊겼는지 볼 수 없다. `You said the first 2 of 5 words.` · 다 맞으면 `You said all 5 words.`(한 낱말이면 `You said the word.`) · 0이면 `You said 0 of 5 words.`. 보이는 안내 줄과 알림이 같은 문구다.
6. **인식 불가 안내가 위치를 말하지 않는다**(감사 **S5**) — `Speech recognition isn't available right now. Tap Skip to continue.` 낱말 말하기는 활동에 한 문항이라 「다음 낱말로」가 늘 틀렸다.
   ⚠ **튜토리얼 말하기 화면의 같은 안내도 바뀌었다** — 읽기 화면이 튜토리얼의 키(`speaking.recognitionUnavailable`)를 함께 쓰므로 그 값(`… Skip to the next sentence.`)이 같은 문구가 됐다. 튜토리얼의 동작은 바뀌지 않았다.
7. **읽기 문장 요소는 이름(`accessibility-label`)을 문장 전체로 둔다** — 계약은 「라벨 없음」이었다. 조각마다 앞 공백을 붙여 그리므로 이름을 두어 낭독을 문장 그대로 고정했다(감사가 「더 안전하고 해가 없다」로 확인).
8. **그림 틀의 CSS는 단어 선택 것을 복제했다** — 부품을 공유하지 않으므로(버린 대안 4) 값만 같다. 디자인 값이 바뀌면 두 곳을 함께 고친다.

2. **권한 → 시작 → 결과 결선이 셋이다** — 튜토리얼 화면 안 · 최종 테스트 훅 · 새 공유 훅. 둘을 옮기면 그 화면 테스트를 함께 건드려 따로 연다(보류 표 「기존 말하기 화면의 대비 부채 · 말하기 결선 셋의 통합」).
   그림 로드 **훅**도 둘이다(순수 전이 · 시한만 하나).
3. **기존 말하기 화면의 대비 미달은 그대로다** — 튜토리얼 카드의 넷(안 맞은 낱말 · 로마자 · 안내 줄 · 파형 대기색)과 최종 테스트 말하기의 낱말 · 로마자 값 · `Say` 표식. 새 화면에만 고친 값이 들었다(보류 표 「기존 말하기 화면의 대비 부채 · 말하기 결선 셋의 통합」).
4. **튜토리얼과 카탈로그의 건너뜀 규칙이 다르다**(D7) — 같은 「말하기」인데 튜토리얼 사용자 `Skip`은 정답으로, 카탈로그는 건너뜀으로 센다. 화면 명세에 두 규칙을 함께 적었다.
5. **잠금은 활동 단위다**(D5) — 한 레슨에 말하기 활동이 둘 이상인 데이터가 오면 둘째 활동의 첫 `Speak`가 다시 한 번 막힌다(조작 한 번 더).
6. **낱말 판정이 「앞 낱말 일치」라 「카드 카드」 · 「카드 주세요」도 정답이다** — 문장 말하기에서 뒤 낱말을 무시하던 성질이다. 반대로 「카드요」 · 「비밀 번호」는 오답이다.
7. **카드처럼 끝나는 활동의 걸음 함수가 셋이 됐다**(단어 카드 · 문화 카드 · 읽기) — [ADR-0066](0066-episode-format-screens.md) 재검토 조건 5가 발동했는데 올리지 않았다(화면 폴더 사이 값 import 금지를 지키며 각자 둠). 적용 기록 ⟨PR ③⟩.
8. **결과 화면 부제는 실수 수만 본다** — 읽기 셋을 모두 `Skip`하면 `LESSON COMPLETE!`(만점 아님) + 실수 없음 부제가 함께 선다. 기존 「학습 완료」 규칙 그대로다(화면 명세).

## 재검토 조건

1. **`SHADOW`에 문항 음성(`audio_url`)이 오면** — 「듣고 따라 말하기」는 이 화면을 넓히는 일이 아니라 다시 정할 일이다. 학습형 이름(`read-aloud`)과 지시문 · `prompt.en`의 쓰임을 함께 본다. ADR README 보류 표 「문항 음성이 오는 `SHADOW`」.
   ⟨2026-10-22⟩ **발동했고 다시 정했다 — 이름 · 지시문은 그대로다.** 아래 「적용 기록」.
2. **한 단계에 말하기 유형이 섞이거나 말하기 활동이 둘 이상이 되면** — 활동 안 잠금(D5)과 이벤트 읽는 법(분모 = `questionCount − skippedCount`, ADR-0029 기록)이 성립하지 않는다. 레슨 단위 잠금 · 유형별 건너뜀 속성을 다시 본다.
3. **기기에서 낱말의 실제 인식 글자를 보면** — Q7(판정의 너그러움)을 연다.
4. **튜토리얼 · 최종 테스트 말하기를 다시 손볼 때** — 결선 셋을 공유 훅 하나로 모으고 대비 부채를 함께 갚는다(「대가」 2 · 3).
5. **셸 계약을 바꾸는 작업이 열리면** — 보조 단독 버튼 행으로 로딩 중 `Skip`의 자리를 고정한다(「구현 판단」 2).
6. **화면 없는 유형이 다시 오면** — 사유 `screen-pending`을 되살린다(D9).

## 적용 기록

### ⟨2026-10-22⟩ 학습 문항 음성 · 「천천히」 — `SHADOW`에 문항 음성이 붙었다

결정은 [ADR-0081](0081-item-audio-and-slow-playback.md) D8. 이 문서의 결정 문장은 바뀌지 않는다.

- **재검토 조건 1을 다시 정했다 — 학습형 이름 `read-aloud` · 지시문 `Read the sentence out loud.` · `prompt.en`의 쓰임을 바꾸지 않는다.** 화면 구조는 문장 묶음 다음 · 파형 앞에 간이 줄(다시 듣기 · `Slow`) 하나가 더해질 뿐이고, 채점 없는 연습(D4)이라는 성격이 같다.
- 소리가 있으면 문항이 설 때 지금 속도로 한 번 자동 재생한다. `Speak` · `Try again`은 **먼저 재생을 멈추고** 녹음한다 — 문장 음성이 마이크로 들어가지 않는다. 녹음 중 간이 줄을 누르면 녹음을 멈추고(그 시도의 결말은 D4 그대로) 재생한다. 간이 줄 다시 듣기는 재생 중 `Stop`이 된다.
- 낱말 말하기(`SPEAK_WORD`, D6)는 판정(`heard`)이 서는 순간 정답 음성을 1.0으로 한 번 낸다(조작 없음). 재시도는 먼저 재생을 멈춘다.
- 「맥락」 · D4의 「문항 음성이 9/9 비어 있다」와 「글을 보고 읽는다」는 그때의 데이터다 — 지금 버킷 에피소드의 `SHADOW` 51문항은 모두 소리가 있다. 소리 없는 문항은 지금처럼 글 보고 읽기다.
- 이벤트: 따라 읽기 문항마다 `episode_listen_item_answered`(`result` `practiced` · `skipped`)가 난다(ADR-0081 「측정」).
