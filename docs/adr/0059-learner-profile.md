# ADR-0059 — 학습자 프로필: 이름과 나라를 계정에 두고, 레슨 문장의 `{이름}` · `{나라}`를 채운다

- 상태: **채택 — 클라이언트 쪽.** 서버 표 · RPC는 저장소와 embedded Postgres 테스트에서만 돌았고 원격 DB 적용은 2026-10-13 사용자가 했다(SQL Editor — 확인 쿼리 기대값 일치, 시뮬레이터에서 기기 값 업로드 확인).
  사용자 결정(2026-10-13)은 넷이다 — **이름과 나라는 둘 다 있어야 저장된다** · 온보딩의 **넷째(마지막) 스텝**에서 묻는다 · 에피소드 전에는 **기록이 없을 때만** 묻는다 ·
  **한글 이름을 받는다**. 그 밖의 기본값(나라 표의 기준과 범위 · 로마자 연음 · 로그아웃 때 기기 값 보존 · 나라 고르기의 모양 · 설정 줄의 이름과 설명)도 사용자가 그대로 확정했다.
  ⚠ **기기 확인이 반쪽이다.** iOS 시뮬레이터에서 **설정 경로만** 봤다 — 온보딩 넷째 스텝 · 에피소드 전 묻기 · 최종 테스트 대사의 이름 · 원격 업로드 · 다른 기기 로그인 ·
  VoiceOver · Android는 보지 못했다([학습자 프로필 e2e](../e2e/learner-profile.md) 「미확인」).
- 날짜: 2026-10-13. ⟨2026-10-20 개정⟩ D7의 「언제 묻는가」를 사용자가 바꿨다 — 온보딩 넷째 스텝과 에피소드 전 가드를 걷고 **가입 직후 ① 이름 → ② 나라 → 언어 선택**에서 묻는다(아래 D7 적용 기록).
- 다루는 축: **학습자 프로필** — 무엇을 저장하는가(저장 단위) · 어디에 두는가(서버 표와 기기 캐시) · 기기와 서버가 어긋날 때 누가 이기는가 · 나라 목록의 범위와 한국어 · 로마자 · 영어 표기 ·
  이름으로 받는 글자 · 언제 묻는가(세 진입점) · 레슨 문장에 어떻게 서는가(치환 스크립트 셋) · 개인정보로서 무엇을 내보내지 않는가.
  **다루지 않는 것**: 계정 정보(소셜 계정의 이름 · 이메일 — 설정의 `User profile`은 그대로 읽기 전용이다), 콘텐츠가 앱에 오는 길([ADR-0056](0056-episode-content-delivery.md)),
  레슨 화면 자체([ADR-0058](0058-catalog-learning-session.md)), 분석 전송([ADR-0029](0029-product-analytics-posthog.md)).
- 이어받는 결정: [ADR-0056](0056-episode-content-delivery.md) D7(치환은 조사 규칙 표 하나 — 아래 D6이 **스크립트를 셋으로 넓히고** 「로마자 이름 필드는 3d에서 정한다」에 답한다),
  [ADR-0058](0058-catalog-learning-session.md) D12(계획 메모 — 아래 D9가 **키에 프로필을 더한다**),
  [ADR-0035](0035-learning-progress-and-streak-on-server.md) D1(표 + RPC, 앱은 표에 닿지 않는다 — 같은 틀의 셋째 표),
  [ADR-0032](0032-account-sign-out-and-deletion.md) D6(로그아웃 · 삭제 뒤처리 — 키 둘이 표에 붙는다),
  [ADR-0007](0007-app-internals-state-routing-data-errors.md) D1(영속 저장소의 예외 — 둘이 는다),
  [ADR-0016](0016-assistive-technology-semantics.md) D10 · D11(주 버튼은 꺼진 모양을 두지 않는다 · 능동 낭독),
  [ADR-0031](0031-ui-language-catalog.md) D7(한글 리터럴의 자리 — 새 한글 리터럴은 TS에 0, 나라 이름 · 미리보기 틀은 JSON 자산).
  **바꾸는 결정 문장은 없다.** 각 ADR에는 적용 기록이 붙었다.
- 받은 적용 기록(결정을 바꾸지 않는다):
  2026-10-18 [ADR-0069](0069-returning-learner-login.md) D3 — 새 로그인의 동기화 시작이 기존 회원 판정 뒤로 옮겼다(D3 「흐름」에 주).

근거 표시: **[코드]** 저장소 코드 · **[데이터]** `apps/mobile/content/*.json` 실측 · **[실기]** iOS 시뮬레이터 관찰 · **[추론]** 관찰 없이 이어 붙인 것.
계약의 정본은 저장소 밖 작업 폴더의 spec(「사용자 결정 반영」 절 포함)이고 이 문서는 그중 **결정**만 옮긴다. 시그니처는 코드가 진다.

## 맥락

1. **치환기는 있었고 값이 없었다** [코드]. 3a가 `{이름}` · `{나라}`를 앱이 프로필로 치환하기로 했고(ADR-0056 D7), 그 프로필을 넘기는 자리 여섯이 늘 빈 프로필
   `noLearnerProfile`을 넘겼다. 계획 메모 둘(레슨 · 최종)은 프로필을 받을 인자조차 없었다.
2. **토큰이 화면에 서는 곳은 에피소드 2 · 3의 최종 테스트뿐이다** [데이터]. u02 · u03의 `dialogue`와 최종 테스트(`RP-01` · `RP-04`)에 `{이름}` · `{나라}`가 있고,
   **레슨 문항의 같은 대사는 고정 이름 「은지」를 쓴다**(대사 고르기 보기 · 받아쓰기 정답 · 단어 카드 예문). 그래서 학습자 이름은 최종 테스트에서 처음 보인다 —
   콘텐츠 질문으로 넘겼다([콘텐츠 계약](../specs/episode-content-json-contract.md) Q31). u01에는 토큰이 없다.
3. **영어 줄도 로마자 스크립트로 치환하고 있었다** [코드]. 프로필이 비어 차이가 안 났을 뿐, 값이 서면 `I'm from {나라}.`에 로마자 나라 이름이 선다.
4. **서버 표의 틀이 이미 셋 있다** [코드] — `learning_progress` · `learning_days` · `push_devices` · `feedback`. RLS를 켜고 정책 없이, RPC는 `security definer` + `auth.uid()`.
5. **기기 저장소는 동기 · 실패 신호 없음이다** [코드]. `StorageModule.set`은 `void`라 「기기 저장 중」 · 「기기 저장 실패」 상태를 만들 근거가 없다.
6. **원격 DB 적용은 사용자가 손으로 한다**(SQL Editor). 앱 배포와 마이그레이션 적용의 순서를 강제할 수 없다.

## 결정

### D1. 저장 단위 — 이름과 나라가 **둘 다** 있거나, 기록이 없다

`LearnerProfileRecord = { name: string; countryCode: string }`(`lib/learner-profile.contract.ts`). 한 칸만 채운 기록은 없다 — **사용자 결정**(2026-10-13).
건너뛰었거나 아직 묻지 않았으면 기록이 없고(= 프로필 없는 지금의 동작), 서버에도 기기에도 아무것도 쓰지 않는다.

- 양식은 둘 다 채워야 저장한다. **한 칸만 채운 채** 주 버튼을 누르면 빈 칸에 오류를 세우고 머문다 — 나라는 `Select your country.`,
  이름은 진입점이 고른 빈 이름 문구(온보딩 · 설정 `Enter your name.` · 에피소드 전 `Enter your name, or tap Skip.`).
- **둘 다 빈 채** 누르면 진입점마다 다르다 — 온보딩은 건너뜀, 에피소드 전 · 설정은 같은 오류로 막는다(에피소드 전의 건너뛰기는 머리의 `Skip`).
- 기록을 지우는 기능은 없다(프로필 전체 삭제는 계정 삭제뿐 — 범위 밖, 재검토 조건 4).
- 버린 대안: 계약 단계의 기본값이던 「한 칸만 채운 저장 허용」 — 사용자가 둘 다 필수로 바꿨다. 한 칸만 밝히려는 사람은 건너뛴다(대가 1).

### D2. 서버 — 표 하나 · RPC 둘, 앱은 표에 닿지 않는다

마이그레이션 `apps/supabase-functions/supabase/migrations/20261013120000_learner_profiles.sql`.

- `learner_profiles(user_id PK → auth.users ON DELETE CASCADE, name text NOT NULL, country_code text NOT NULL, updated_at)`. RLS를 켜고 정책 없이, `anon` · `authenticated`의 표 권한을 걷는다.
- RPC는 둘 — `load_learner_profile()`(행이 없으면 `null`) · `save_learner_profile(p_name, p_country_code)`(두 열을 통째로 덮어쓴다). 둘 다 `security definer` · `set search_path = ''` ·
  사용자 id를 인자로 받지 않는다(남의 행을 가리킬 길이 없다). `anon`은 실행 권한이 없고, 로그인하지 않은 호출의 저장은 `28000`이다.
- **서버도 검증한다**(앱을 믿지 않는다): 이름은 스페이스 · 탭 연속을 한 칸으로 접고 앞뒤를 걷은 뒤 1 ~ 30자 · 금지 문자 없음, 나라는 `^[A-Z]{2}$`. 한쪽이라도 어기거나 비면 `22023`.
  표의 CHECK 제약도 같은 조건이다(함수를 거치지 않는 쓰기 방어).
- **서버는 나라 목록을 모른다** — 형식만 본다. 목록은 앱 릴리스와 함께 바뀌는 표시 데이터이고, 서버가 들면 목록이 바뀔 때마다 손으로 적용하는 마이그레이션이 생긴다.
  형식이 맞는데 이 앱의 표에 없는 코드(새 앱이 넣은 코드를 옛 앱이 읽음)는 기록을 그대로 두고 치환에서 나라만 뺀다.
- `updated_at`은 운영 확인용이다 — 충돌 판정에 쓰지 않는다(D3).
- 계정 삭제는 CASCADE가 진다 — `delete-account` 함수는 이 표를 모른다(ADR-0032 D2 · `push_devices` 전례).
- 버린 대안: 진행 스냅숏(`learning_progress.progress`)의 필드로 — 진행은 앞으로만 합치는 병합이고 프로필은 덮어쓰기라 규칙이 섞이고, 개인정보가 진행 jsonb에 섞인다.
  `auth.users`의 사용자 메타데이터 — 소셜 제공자가 덮어쓰고 앱이 쓰려면 Auth 권한이 넓어진다.

### D3. 기기 캐시와 동기화 — 미전송 기기 값이 이기고, 없으면 서버가 이긴다

- **키 둘**: 사용자별 `libitum.learner-profile.<userId>`(`{record, sync: "pending" | "synced"}`) · 로그인 전 손님 칸 `libitum.learner-profile.guest`.
  **확인된 값도 기기에 둔다** — 부팅 직후(내려받기 전)에도 문장이 채워져야 하고, 서버 표가 없는 상태(원격 미적용)에서도 동작해야 하기 때문이다.
  `lib/storage.ts` 머리말의 「서버 응답 캐시는 두지 않는다」의 새 예외 둘이다(ADR-0007 D1 적용 기록). 건너뜀 · 서버에 행 없음에는 키를 만들지 않는다.
- **충돌 규칙**: 미전송(`pending`) 기기 값이 서버 값을 덮는다. 미전송이 없으면 서버 값이 기기 값을 덮는다. **시계를 견주지 않는다.**
  `pending`은 「이 기기에서 사용자가 방금 한 명시적 입력」이다 — 새 기기 온보딩에서 다시 넣은 값(손님 칸)이 서버의 옛 값을 덮는 것이 사용자가 방금 한 일과 맞는다.
  건너뛰었으면 손님 칸이 없어 서버 값이 내려온다. 서버에 행이 없는데 기기에 `synced` 값이 있으면 다시 `pending`으로 올린다(사용자 입력을 잃지 않는 쪽).
- **흐름**: 세션이 서는 자리(`storeSession` — 부팅의 갱신 성공 · 새 로그인) 하나에서 동기화가 선다. 손님 칸이 있으면 그 값이 사용자별 칸을 `pending`으로 덮고 손님 칸을 지운다
  (네트워크보다 먼저 영속화). 그 뒤 `pending`이면 올리고, 아니면 내려받는다. 로그인 중 수정은 캐시에 `pending`으로 **먼저** 적고 올린다.
  올리기가 끝났을 때 그 사이 새 수정이 있었으면 한 번 더 돈다. 로그아웃 · 계정 전환 뒤 늦은 응답은 반영하지 않는다.
  ⟨2026-10-18 적용 기록⟩ **새 로그인(소셜 · 코드 검증)에서는 동기화가 `storeSession`이 아니라 기존 회원 판정이 끝난 직후 선다**(갈래와 무관하게,
  최대 3초 뒤) — 손님 칸 업로드가 판정의 프로필 조회보다 먼저 서버 행을 만들어 신규 사용자를 기존 회원으로 오판하지 않게 한다([ADR-0069](0069-returning-learner-login.md) D3).
  부팅의 갱신 성공은 판정이 없어 지금처럼 세션 저장 직후 선다. 충돌 규칙 · 손님 칸 처리 · 재시도는 그대로다.
- **재시도**: 올리기 실패는 1 · 5 · 15 · 30 · 60초 **다섯 번 뒤 멈추고** 다음 기회(부팅 · 로그인 · 수정)에 다시. 내려받기 실패는 재시도하지 않는다.
  진행 대기열처럼 영원히 돌지 않는 이유 — 「계속 실패」의 가장 흔한 꼴이 원격 미적용(RPC 404)이고, 그 상태에서 실행 내내 분당 요청을 내지 않는다(ADR-0029 D12와 같은 판단).
- **화면을 막지 않는다** — 스피너 · 대화상자 · 능동 낭독이 없다. 상태는 설정 줄의 설명 한 줄로만 보인다(`pending`이면 `Saved on this device. We'll sync it when you're back online.`).
- **배포 순서 제약이 없다**: 마이그레이션이 원격에 없으면 RPC가 404 → 올리기 · 내려받기 실패 → 기기 캐시로 레슨에 쓰이고 실행마다 다시 올린다 [실기 — 설정 경로].
- 계정: 키가 사용자별이라 다른 계정은 자기 키만 읽는다. **로그아웃은 캐시를 남긴다** — 같은 계정으로 다시 들어오면 미전송이 이어진다(진행 대기열과 같은 규칙). **계정 삭제 성공은 지운다.**
- 버린 대안: `updated_at` · 기기 편집 시각 비교 — 기기 시계를 믿을 수 없고(ADR-0035 D6이 같은 한계를 적었다) 시계가 늦은 기기의 수정이 조용히 되돌려진다.
  서버 리비전(낙관적 잠금) — 충돌 때 누가 이기는지 규칙이 다시 필요하고 손님 칸에는 기준 리비전이 없다.

### D4. 나라 표 — 199개, 외교부 표기 + 관용 약칭, JSON 자산 하나 · 백그라운드 전용

- **범위**: UN 회원국 193 + UN 옵서버 2(바티칸 `VA` · 팔레스타인 `PS`) + 대만 `TW` · 홍콩 `HK` · 마카오 `MO` · 코소보 `XK`(ISO 밖의 관용 코드) = **199**.
  그 밖의 속령(푸에르토리코 · 괌 등)은 넣지 않는다. 화면의 나라 수는 표에서 센다.
- **한국어 표기 기준**: 외교부 국가 · 지역 목록의 국명을 따르되, 문장(「저는 ○○에서 왔어요.」)에 넣는 말이라 정식 국명 대신 **관용 약칭**을 쓴다(한국 · 북한 · 미국 · 독일 · 대만 · 바티칸 · 콩고공화국 / 콩고민주공화국 등).
  띄어쓰기 없이 붙여 쓴다. 외교부와 표준국어대사전이 갈리는 자리는 외교부를 따른다(사이프러스 · 튀르키예).
  **구현 단계가 외교부 목록(197개 국가 · 지역)과 ISO 코드로 대조했다** — 차이는 셋으로 정리됐다:
  - 관용 약칭으로 둔 **7곳**은 계약대로 뒀다 — 미국(외교부 미합중국) · 바티칸(교황청) · 알제리 · 이집트 · 이란 · 베네수엘라 · 가이아나(외교부 목록은 정체 명칭을 붙인 꼴). 쿡제도 · 니우에는 외교부 목록에 있지만 속령이라 넣지 않았다.
  - **모리타니 · 나우루는 표준국어대사전 표기로 되돌렸다.** 대조 중 외교부 철자로 바뀌었다가, 학습자가 자기 문장으로 말하는 이름이라 사전 표기가 맞다고 보고 되돌렸다(예외 둘).
  - 외교부 목록에 있는 **쿡제도 · 니우에는 넣지 않았다** — UN 회원국 · 옵서버가 아니고 위 범위 규칙 밖이다.
- **로마자**: 국어의 로마자 표기법(2000) — 표준 발음을 적고(`독일 → dogil` · `핀란드 → pillandeu`) 소문자다. 규칙은 순수 함수 하나로 고정하고
  **표의 모든 행이 그 함수의 출력과 같음을 unit이 지킨다** — 손으로 적은 로마자가 표에 남지 않는다.
- **영어 이름**: 흔히 쓰는 짧은 이름(`South Korea` · `Vietnam` · `Czechia` · `DR Congo`). 문장 안에서 관사가 필요한 나라는 `the`를 붙인다(`I'm from the United States.`).
  검색은 영어 이름 · 별칭만 본다(`korea` → `South Korea`). 한국어 · 로마자로는 찾지 않는다.
- **자산**: `apps/mobile/content/learner-profile.json` 하나(나라 행 `[code, ko, roman, en, 관사?, 별칭?]` + 미리보기 문장 틀 둘). 읽는 모듈은 `background-only`라
  **표가 메인 스레드 번들에 실리지 않는다** — 빌드 stats로 레이어를 확인했고 표에만 있는 로마자 문자열이 번들에 한 번 나온다. 화면은 포트(`search` · `byCode` · `previewOf`)를 prop으로 받는다.
  JSON이라 한글 리터럴 검사 허용 목록 · 300줄 규칙을 건드리지 않는다.
- 버린 대안: TS 표 파일 둘 + 허용 목록(줄 수 규칙 때문에 데이터가 임의로 갈린다) · 로그인 국가 번호 표(245지역)에 열 더하기(범위 · 국기 · 국가 번호가 섞이고 두 스레드에 실린다) ·
  서버에서 받기(온보딩은 로그인 전이고 오프라인에서 못 쓴다).

### D5. 이름 — 치환을 깨는 글자만 막는다. 한글 이름을 받는다

- 정규화: JS `\s` 공백류(줄바꿈 · U+2028 · U+2029 · NBSP · 전각 공백 포함) 연속을 **거절하지 않고 한 칸 공백으로 접은 뒤** 앞뒤 공백을 걷고, 그 결과를 검증한다.
  막는 것: `{` · `}`(치환 틀과 겹친다 — 이름에 `{나라}`가 들면 둘째 치환이 그것을 바꾼다) · `\s`가 아닌 제어 문자 · **짝 없는 서로게이트**(서버 jsonb가 받지 못한다) ·
  30 코드 포인트 초과. 금지 문자 · 길이 초과는 **치는 즉시** 오류가 서고 미리보기가 견본으로 돌아간다. 입력 칸은 30에서 멈춘다(붙여넣기 · 조합 입력이 넘겨 오는 경우를 검증이 받는다).
- **앱과 서버의 규칙 차이**: 서버는 스페이스 · 탭만 접고 줄바꿈 · 제어 문자 · 줄 · 문단 구분자를 **거절**한다(D2). 앱이 먼저 접어 보내므로 앱 경로에서는 그 거절에 닿지 않고,
  **앱을 거치지 않는 직접 호출에서만 서버가 더 엄격하다.** 그래서 앱 쪽 「줄 구분자」 테스트는 거절이 아니라 접기를 검증한다.
- **한글 이름을 받는다 — 사용자 결정**(2026-10-13). 라틴 · 악센트(`José`) · 한글(시스템 한글 자판) · 그 밖의 글자도 받는다. 앱이 한글 자판을 띄워 주지는 않는다.
- 조사의 받침은 **이름 자체**로 판정한다 — 한글이면 한글 받침(`민준이에요` · `지아예요`), 라틴이면 3a 규칙(끝 글자가 `[aeiouy]`면 모음 끝 — `Liam으로` · `Emma로`).
  판정할 수 없는 글자로 끝나면 기본 문구의 판정을 쓴다.
- **로마자 줄의 한계**: 이름은 세 스크립트에 **입력한 글자 그대로** 선다. 그래서 한글 이름은 로마자 줄에도 한글로 선다(`minjunieyo`가 아니라 `민준ieyo`).
  이름을 로마자로 바꾸지 않는 것은 사람 이름의 로마자 표기가 본인이 정하는 것이라서다(여권 표기와 규칙 표기가 다르다). 로마자 이름 필드를 따로 두지 않는다 — ADR-0056 D7의 「3d에서 정한다」에 대한 답이다.
  라틴 이름에도 한국어 연음을 적용하지 않는다(`Johneuro` 그대로).
- 알려진 한계(3a의 것 그대로): 라틴 `l` 끝을 ㄹ로 보지 않는다(`Paul으로`) · 묵음 `e` 끝을 모음 끝으로 본다. 이름이 미리보기에 바로 서면서 눈에 띄게 됐다(재검토 조건 2).

### D6. 치환 — 스크립트 셋, 나라는 세 표기, 로마자는 연음

- `fillPlaceholders(text, profile, script)`의 스크립트가 `"ko" | "roman" | "en"` 셋이 된다. 화면 문자열의 출처가 `.en` · 뜻 · 지시문이면 `"en"`, `.roman`이면 `"roman"`, `.ko`면 `"ko"`.
  `LearnerProfile.country`는 문자열(3a 그대로) 또는 `{ ko, roman, en }`이다.
- 나라가 서는 값: ko 줄 = 한국어 이름 · 로마자 줄 = 로마자(**연음 적용** — `migugeseo` · `dogillo`) · 영어 줄 = 영어 이름(+ 관사). 받침 판정은 늘 ko 값이다.
- 프로필이 없으면 결과가 지금과 **한 글자도 다르지 않다** — `"en"`은 `"roman"`과 같은 기본값(`ireum` · `nara`)과 규칙 표를 쓴다. 그래서 3b ~ 3d-1의 기존 단언이 그대로 섰다.
  (영어 문장의 `ireum` · `nara`는 어색하지만 이 작업의 범위가 아니다 — 건너뛴 사용자만 본다.)
- 버린 대안: 스크립트 둘에 호출부가 프로필을 갈아 끼우기 — 받침 판정이 ko를 잃는다(`dogil`은 라틴 규칙으로 「자음 끝」이 되어 「독일로」의 반대가 선다).
  연음 없이 이어 붙이기 — `migukeseo`는 같은 화면의 다른 로마자 줄(`hangugeo`)과 규칙이 어긋난다.

### D7. 언제 묻는가 — 세 진입점, 화면은 명시적 변형 셋

| 진입점                             | 자리                                                                        | 건너뛰기                          | 둘 다 빈 채 주 버튼 | 뒤로                                         |
| ---------------------------------- | --------------------------------------------------------------------------- | --------------------------------- | ------------------- | -------------------------------------------- |
| **온보딩 넷째 스텝** — 사용자 결정 | 온보딩의 마지막 스텝(진행 점 4 · `Make it yours` · 주 버튼 `Get started`)   | 버튼 없음 — 빈 채 넘어감 = 건너뜀 | 건너뜀 → 로그인     | 셋째 스텝                                    |
| **에피소드 전**                    | 토큰이 든 에피소드의 표지 · 유닛을 처음 열 때(route `learner-profile-gate`) | 머리 오른쪽 `Skip`                | 오류 + 머묾         | 맵 — **건너뜀이 아니다**, 다음에 다시 묻는다 |
| **설정**                           | `Name and country in lessons`(route `learner-profile`)                      | 없음                              | 오류 + 머묾         | 설정(고친 것을 버린다)                       |

- **에피소드 전 가드**는 결선 한 자리(`catalog-wiring.ts`)에서 표지 · 유닛 시작을 감싼다. 원래 시작 가드(잠금 등)를 지나고 · 그 에피소드에 토큰이 있고 · **기록이 없고** ·
  이번 App 세션에서 아직 묻지 않았으면 묻는다 — **기록이 있으면 다시 묻지 않는다(사용자 결정)**. 저장 · 건너뜀 뒤에는 **새 프로필로 다시 만든** 원래 시작 함수를 부른다
  (같은 틱의 상태 갱신이 결선 클로저에 아직 닿지 않았다 — 옛 프로필로 계획을 만들면 다음 렌더의 계획과 어긋난다).
- 「토큰이 든 에피소드」는 치환이 글자를 바꾸는가로 판정한다(`{수단}` · `{명사}`는 토큰이 아니다). 지금 데이터: u01 아님 · u02 · u03 맞음.
- 「이번 세션에서 물었다」는 저장하지 않는다 — 로그아웃 · 계정 삭제로 세션이 다시 서면 다시 묻는다. 온보딩에서 건너뛴 세션도 묻지 않는다.
  **가드는 내려받기를 기다리지 않는다** — 기다리면 원격 미적용 상태에서 한 번도 묻지 못한다. 대가: 새 기기 로그인 직후 내려받기가 끝나기 전에 u02를 열면 한 번 묻는다.
- 화면은 공유 조각 셋(양식 묶음 — 미리보기 · 이름 칸 · 나라 줄 / 양식 자리에 대신 서는 나라 고르기 / 머리 · 스크롤 · 주 버튼 뼈대)과 **명시적 변형 셋**이다.
  진입점을 가르는 boolean · mode prop은 없다. 나라 고르기는 바텀 시트가 아니라 화면 교체다(검색 자판이 아래에 붙은 목록을 가린다).
- 로그아웃 뒤(`[온보딩, 로그인]`)는 로그인이 먼저 보여 온보딩 넷째 스텝을 지나지 않는다 — 그 사용자는 에피소드 전 · 설정이 받는다.

#### D7 적용 기록 ⟨2026-10-20 — 사용자 결정: 가입 직후 ① 이름 · ② 나라⟩

위 표의 진입점 셋 가운데 **온보딩 넷째 스텝과 에피소드 전을 걷었다.** 사용자 말: 「온보딩은 사용자가 기능을 통해 흥미가 갈 수 있도록 하는 것이고, 회원가입하면 언어 선택과 비슷한 형태로
그 사이에 이름 · 나라를 물어야 한다」 — 유닛을 진행하다 묻는 화면이 갑자기 서던 것이 계기다. 시안은 캔버스 7행(ProfName · ProfCountry · ProfLang).

| 진입점 | 자리 | 건너뛰기 | 빈 채 Continue | 뒤로 |
| --- | --- | --- | --- | --- |
| **가입 직후 ① 이름** | 새 사용자 로그인 뒤(기존 회원 판정이 `language-select`일 때) route `learner-name` · 진행 막대 1/3 | **없음** — 이름은 늘 미리 채워진다 | 빈 이름 오류 + 머묾 | 로그인(전화는 코드 검증) |
| **가입 직후 ② 나라** | route `learner-country` · 진행 막대 2/3 · 다음은 언어 선택(3/3) | 없음 | `Select your country.` + 머묾 | ① 이름(친 이름 그대로) |
| **설정** | 그대로 | 없음 | 오류 + 머묾 | 설정 |

- **이름은 미리 채운다** — 이 기기에 남은 기록의 이름 → 소셜 로그인 토큰의 `user_metadata.full_name`(없으면 `name`) → 내장 무작위 이름 40개(`content/learner-profile.json`
  `randomNames` — 여러 문화권의 짧은 라틴 이름) 순. 어느 값이든 D5의 이름 규칙을 지나야 쓴다. `Shuffle`은 지금 이름을 뺀 무작위 이름으로 바꾼다. 그래서 건너뛰기가 없고, 가입을 마친
  모든 새 사용자는 기록을 갖는다 — 레슨 대사의 `{이름}`이 늘 찬다.
- **나라는 추천 없이 전체 199개**다 — 검색(영어 · 한국어 · 별칭) · 영어 이름 첫 글자 머리 · 오른쪽 A–Z 막대. 「기타 / 직접 입력」은 두지 않는다(한국어 이름 · 로마자를 지을 수 없다 —
  D4). 글자 묶음에 한 나라뿐인 경우(Q · Y …)가 있어 줄은 OptionSelector가 아니라 앱이 짓는다(OptionSelector는 두 줄부터).
- **저장 시점은 ②의 Continue**다. 로그인 뒤라 동기화 객체가 이미 서 있어(로그인 직후 `syncLearnerProfile`) 저장은 사용자 칸 → 서버로 곧장 간다. 토큰에서 사용자를 못 읽는 드문
  경우에만 손님 칸에 남는다(D3 그대로).
- **에피소드 전 가드는 없다** — route `learner-profile-gate` · 결선 · 화면을 지웠다. 기록이 없는 사용자(가입이 이 개정 전이었거나 서버 판정으로 기존 회원이 된 계정)는
  설정에서만 고친다. 그 사용자의 대사는 치환기의 기본값(「이름」)으로 선다(D6 그대로).
- **이벤트** — `learner_profile_saved`의 `entry`는 `signup` | `settings`이고 `learner_profile_skipped`는 없다(건너뛸 길이 없다). 진입 열람 `entry_screen_viewed`의 `screen`에
  `learner-name` · `learner-country`가 더해졌다([ADR-0029](0029-product-analytics-posthog.md) D14 적용 기록 ⟨2026-10-20⟩).
- **기존 회원**은 바뀌지 않았다 — 판정(ADR-0069)이 맵으로 보내면 ① · ②를 지나지 않는다.

### D8. 개인정보 — 값은 서버의 계정 행과 기기에만 있고, 분석에는 싣지 않는다

- 이름과 나라는 **사용자가 입력한 학습용 값**이고 계정에 연결된다(앱 기능 목적). 광고 · 추적에 쓰지 않는다.
- **분석 이벤트에 값이 없다.** 이벤트 셋 — `learner_profile_saved { entry, change }` · `learner_profile_skipped { entry }` · `learner_profile_opened` — 은 진입점과
  처음인지 고친 것인지만 싣는다. 이름 · 나라 · 길이 · 문자 종류 같은 파생값도 싣지 않는다([ADR-0029](0029-product-analytics-posthog.md) D14 적용 기록). 로그에도 남기지 않는다.
- 나라는 **자기 신고**다 — PostHog의 IP 기반 위치 추정(ADR-0029 D15)과 무관하고 그 값과 합치지 않는다.
- App Store 개인정보 신고 · 공개 처리방침은 **갱신이 필요하다** — 대조와 문안 초안은 [iOS 개인정보](../ios-privacy.md) 「학습자 프로필」이 진다(보류 표).

### D9. 계획 메모 — 프로필 참조를 키에 더한다

`catalogLessonPlanFor` · `catalogFinalPlanFor`가 넷째 인자 `profile`을 **필수로** 받고 메모 키에 그 참조를 더한다(ADR-0058 D12의 「3d가 프로필을 내리면」).
훅이 지키는 규율: 프로필 참조는 값이 바뀔 때만 새로 서고, 기록이 없으면 늘 `noLearnerProfile` 그 참조다 — 프로필 없는 실행의 메모 동작은 지금과 같다.
기본값 인자를 두지 않는 이유 — 넘기는 것을 잊은 호출이 조용히 빈 프로필로 컴파일되는 것이 이번에 고친 결함의 꼴이다.

## 버린 대안

1. **기존 `User profile` 화면에 학습용 이름을 섞기** — 그 화면은 계정 정보 읽기 전용이고 「조작 단위는 나가기 하나」다. 계정 이름과 학습용 이름은 출처와 수정 규칙이 다르다.
2. **온보딩 세 스텝은 그대로 두고 로그인 앞에 독립 화면** — 「점 셋이 끝났는데 한 장 더」가 되고, route로 세우면 뒤로 갔을 때 온보딩이 첫 스텝에서 다시 선다.
3. **로그인 뒤(언어 선택 다음)에 묻기** — 요구가 온보딩(로그인 전)을 골랐다. 그래서 손님 칸이 생겼다.
4. **에피소드마다 빈 칸이 있으면 다시 묻기** — 둘 다 필수라 부분 기록이 없어 쓸모가 없고, 한 번 답한 사람을 붙잡는다.
5. 그 밖은 각 D의 「버린 대안」.

## 대가

1. **한 칸만 밝히고 싶은 사람은 건너뛴다**(D1). 그 사용자의 문장에는 기본 문구(「이름」 「나라」 · `ireum` · `nara`)가 선다.
2. **두 기기 + 긴 오프라인이 겹치면 옛 값이 이길 수 있다**(D3) — 기기 A가 오프라인에서 고친 값을 오래 들고 있다가 기기 B의 더 새로운 수정 뒤에 올리면 A가 이긴다. 설정에서 다시 고친다.
3. **한글 이름은 로마자 줄에 한글로 선다**(D5). 로마자만 읽는 학습자에게는 그 줄의 이름을 읽을 수 없다.
4. **학습자 이름이 레슨에서는 보이지 않는다** — 레슨 대사는 고정 이름 「은지」라 최종 테스트에서 처음 이름이 선다(맥락 2). 콘텐츠가 답할 때까지 그대로다(Q31).
5. **영어 줄에 받침 판정이 늘 ko 값이다** — 영어 문장에는 조사가 없어 지금은 영향이 없다.
6. **번들 +49,787 bytes**(1,851,801 → 1,901,588, +2.7 %) [실측]. 양식 · 나라 고르기 · 세 변형 · 순수 모듈 · 동기화 · 치환 확장 · 결선 · 문구 · CSS가 두 스레드에 실렸다.
   나라 표는 백그라운드에만 실렸다. 상한을 1,853,000 → 1,903,000으로 올렸다 — **사용자 사전 승인**. [성능 보고서](../performance/reports/learner-profile-iphone-17-pro-simulator-01.md)(번들만).
7. **기기 저장소에 개인정보가 남는다** — 로그아웃해도 그 계정의 이름 · 나라가 기기에 남는다(같은 계정 재로그인 때 미전송을 잇기 위해). 지우는 것은 계정 삭제 · 앱 삭제다.
