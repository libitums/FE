# ADR-0213 — 메신저 목록 맞추기 (푸시 없이 온 선톡 · 스토리 반응)

- 상태: **채택 — 앱, PR(머지는 사용자), 서버 변경 없음.** 옛 앱 영향 없음(서버 그대로, 이미 있는 RPC를 앱이 새로 읽음).
- 날짜: 2026-11-27.
- **사용자 말**: 「스토리 답장 받았을 때 채팅방 리스트 화면에 반영되지 않는다」(2026-11-27). 범위 확대: 「캐릭터에게 답장을 받았을 때 알림 ·
  토스트 · 채팅방 목록(맨 위로 · 안 읽음 · 최신 미리보기) 등 최신 반영 사항을 다 검토해서 화면에 문제없이 떠야 한다」.
- 이어받는 결정: [ADR-0138](0138-messenger-delivery-failures.md)(앞으로 오면 열린 방 다시 읽기) ·
  [ADR-0200](0200-chat-reply-toast.md)(답장 토스트 · 앞에서 받은 푸시 · 폴링 없음) · [ADR-0127](0127-companion-push-target.md)(누른 푸시 목적지) ·
  [ADR-0191](0191-my-stories-reactions-as-chat.md) · [ADR-0194](0194-my-stories.md)(반응은 그 인물 방의 메시지 · 살아 있는 보기).

## 원인

서버 크론(`companion-story-reactions` 매분 → `companion-reaction-make.ts`)과 선톡이 만든 메시지는 앱이 **두 길로만** 다시 읽었다.

1. 앱이 앞으로 옴 · 연결이 돌아옴(`contentSyncOpportunity`) → **열린 방만**(`refreshOpenRoom`).
2. 앱이 앞에 있을 때 받은 채팅 푸시(`pushNotificationReceived`) → 그 인물의 방(`pullRoom`).

그래서 다음 경우에 목록 줄(미리보기 · 안 읽음 · 순서)이 낡은 채로 남았다.

- 반응 · 선톡 푸시가 꺼졌거나, 알림 권한이 없거나, 서버 푸시 게이트에서 건너뛴 경우(앞에 있어도 2번 길이 없음).
- 앱이 뒤에 있을 때 받아 시스템 알림으로 들어오거나 그냥 앞으로 온 경우(목록이면 열린 방이 없음).
- 알림을 눌러 이미 한 번 읽은 방으로 들어온 경우 — 그 방은 열 때 기록을 다시 읽지 않고(`loadRoom`은 `loaded`면 건너뜀), 앞으로 옴 신호는
  방이 열리기 전에 와서 열린 방이 없다.
- 내 스토리 보기에서 새 답을 본 경우 — 보기는 30초마다 다시 읽어 답을 세우지만, 그 답(반응 메시지)이 든 방 · 목록 줄은 그대로였다.

선톡(proactive)도 같은 원인이다. 운영 확인(SELECT, 2026-11-27): 선톡 · 스토리 반응을 넣을 때 서버는 대화의 `last_message_at`을 바꾼다(최근
3일 선톡 464건 · 반응 9건 모두 10분 안). 값은 작업 시작 시각(`p_now`)이라 메시지 `created_at`보다 조금 이를 수 있다 — 그래서 시각 비교가
아니라 **값이 바뀌었는지**로 본다.

## 결정

### D1. 목록 요약 — 이미 있는 `companion_list_characters`의 `lastMessageAt`
- 새 서버 RPC는 만들지 않는다. `companion_list_characters()`는 인물마다 그 대화의 `lastMessageAt`을 이미 준다(운영 함수에 있음 확인).
- 앱 포트 `ChatRemote.lastMessages()` → 인물 id → `lastMessageAt | null`(`companion-activity-parse.ts`). 못 읽으면 null, 던지지 않는다.

### D2. 목록 맞추기 `server.syncRooms()` — 바뀐 방만 다시 읽는다
- 열린 방은 **요약을 기다리지 않고** 지금처럼 바로 다시 읽는다(`refreshOpenRoom`).
- 요약을 한 번 읽고, 닫힌 방 가운데 요약 값이 **마지막으로 맞춘 값과 다른** 방만 `pullRoom`과 같은 길로 다시 읽는다 — 새 인물 말이면
  안 읽음 하나(토스트의 원천과 같은 규칙), 같은 메시지(id)는 한 줄.
- 다시 읽어 합쳤을 때만 그 값을 맞춘 것으로 둔다 — 못 읽었거나 답을 기다리는 중이면 다음 맞추기에서 다시 본다.
- 요약을 읽는 사이 열린 방(누른 알림이 연 방)도 요약에서 바뀌었으면 다시 읽는다.
- 겹친 맞추기(앞으로 옴 + 목록 들어옴)는 요약 읽기 하나로 묶는다.
- 비용: 앞으로 올 때 · 목록에 들어올 때 요약 1회 + 바뀐 방 수만큼 기록 읽기. 인물 9명을 모두 다시 읽는 것보다 가볍다.

### D3. 언제 — 폴링 없이
- 앱이 앞으로 옴 · 연결이 돌아옴(`use-messenger-refresh.ts`, 앞의 `refreshOpenRoom` 자리).
- 목록 화면에 들어옴(`MessengerListScreen` 마운트 한 번 — 다시 그려도 부르지 않음).
- 내 스토리를 다시 읽었는데 답이 늘었음(`my-stories-wiring.ts` `onReplies` — 계정의 첫 읽기는 기준). 보기를 연 동안 30초 읽기는
  ADR-0194의 것이고 새 주기를 더하지 않는다.
- 앞에서 받은 푸시는 지금처럼 그 방만(`pullRoom`).
- 목록 화면에 **가만히 있는 동안** 푸시가 없으면 여전히 서지 않는다 — ADR-0200 D1 「폴링 없음」을 지킨다(남음 표 참고).

### D4. 처음 켤 때 — 요약으로 미리 읽을 방을 고른다
- 다시 켠 뒤 목록 미리보기(`previewRemoteRooms`)는 요약을 먼저 읽고 **대화가 있는 방만** 기록을 읽는다(대화 없는 방은 첫 인사 줄 그대로).
  읽은 요약 값이 맞추기의 기준이 된다. 요약을 못 읽으면 예전처럼 모든 방을 미리 읽는다. 미리 읽기는 안 읽음을 올리지 않는다(예전과 같음).

- **탭 배지**: 메신저 탭은 안 읽음 합을 보이지 않는다 — 처음 방문 · 새 친구 NEW만(2026-11-13 결정, `messengerTabBadge`). 설계대로.
- **스토리 줄 고리**: 친구 스토리 고리는 본 스토리 기록, 「Your story」는 내 스토리 읽기라 안 읽음과 겹치지 않는다.
- **스토리 반응 미리보기**: 목록 줄은 평소 글 미리보기(ADR-0178 D3 개정 2 — 목록 줄에 스토리 표시를 띄우지 않음). 방 안의 인용 카드 ·
  썸네일은 ADR-0191 그대로.

## 남음(이 ADR 밖)

- **앱을 끈 사이 온 선톡 · 반응의 안 읽음**: 안 읽음은 실행 중 메모리 값이고, 서버에는 읽음 기록이 없다. 켤 때 미리 읽기는 안 읽음을 올리지
  않는다. 고치려면 (가) 서버가 대화마다 읽은 시각 · 인물 마지막 메시지 id를 주거나 (나) 기기에 방마다 「본 마지막 인물 메시지 id」를 두어야
  한다. 시각 비교는 `last_message_at`(작업 시작)과 `created_at`(넣은 순간)이 어긋나 틀린다. **사용자 결정 필요.**
- **다른 기기에서 읽음**: 서버 읽음 기록이 없어 맞출 수 없다 — 위와 같은 결정에 묶인다.
- **목록에 가만히 있는 동안(푸시 없음)**: 폴링을 넣지 않는다(ADR-0200 D1).
- **시스템 푸시가 오는지 · 누르면 그 방**: 실기기에서만 본다(사용자 실기기 확인 목록). 서버 푸시 게이트 · 반응 허용은 PR #674(머지됨, 서버 20270119)가 다뤘다.
