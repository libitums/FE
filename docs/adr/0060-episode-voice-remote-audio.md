# ADR-0060 — 에피소드 음성: 공개 버킷의 `audio/<id>.m4a`를 재생 모듈이 https로 받고, 카탈로그 컷 · 최종 테스트가 자동으로 들려준다

- 상태: **채택 — 클라이언트 쪽.** 사용자 결정(2026-10-14)은 넷이다 — 음성은 **버킷에서 재생**한다 · 최종 테스트는 **상대 줄 자동 + 내 줄은 맞힌 뒤** ·
  **다시 듣기 조작을 두지 않는다** · 범위는 **앱 재생까지**(학습 문항은 넣지 않는다 — 「일반 학습은 바뀔 것 같아서」). 그 밖(id 규약 검사의 자리 · 네이티브 원격 판정 ·
  정지 시점 · 대화 줄 찾기 규칙 · 내장 version)은 계약 단계가 정했다. 음성 파일 14개(u01 6 · u02 4 · u03 4)는 사용자가 버킷에 올렸다.
  ⚠ **실제 소리를 귀로 확인하지 않았다.** iOS 시뮬레이터에서 앱이 버킷 주소로 요청을 내고 받아 간 것(Supabase `edge_logs` — `AppleCoreMedia`의 206 응답)까지 봤고,
  들리는지 · 효과음과 어떻게 겹치는지 · 오프라인 무음 진행 · Android는 보지 못했다([에피소드 음성 e2e](../e2e/episode-audio.md) 「미확인」).
  ⚠ **3초 넘는 컷 음성 여섯에 소리만 멈추는 수단이 없다** — WCAG 1.4.2 엄격 해석 미충족을 알고 받아들였다(D8 — 다시 듣기 · 재생 조작을 두지 않는 사용자 결정의 대가).
- 날짜: 2026-10-14.
- 다루는 축: **에피소드 음성** — 파일이 어디 있는가(출처) · 콘텐츠의 id를 재생 주소로 바꾸는 자리와 규약 · 재생 모듈이 원격 주소를 받는 조건 ·
  카탈로그 컷과 최종 테스트에서 언제 나고 언제 멈추는가 · 실패했을 때 · 내장 에피소드의 version.
  **다루지 않는 것**: 학습 문항(듣기 · 받아쓰기)의 오디오 연결(ADR README 보류 표 「학습 문항 오디오의 연결」), 튜토리얼의 판정용 번들 자산(그대로 번들에서 난다),
  콘텐츠가 앱에 오는 길([ADR-0056](0056-episode-content-delivery.md)), 카탈로그 화면 자체([ADR-0058](0058-catalog-learning-session.md)), 효과음([iOS 효과음 계약](../specs/ios-sound-effects.md)).
- 부분 대체:
  - [ADR-0017](0017-host-native-capabilities-and-audio.md) D3의 **「`source`가 무엇을 가리키는지는 정하지 않았다」** 한 문장 — 답이 아래 D1 · D3이다. **메서드 표면(`play` · `stop` · `pause` · `resume`)과
    D3의 제외 목록은 그대로 산다.**
  - [ADR-0058](0058-catalog-learning-session.md) D3의 **「3c는 오디오를 연결하지 않는다」 가운데 컷 · 최종 테스트 몫** — 학습 문항 몫(오디오 없는 듣기는 건너뜀 · 받아쓰기의 꺼진 재생 조작)은 그대로다.
- 이어받는 결정: [ADR-0056](0056-episode-content-delivery.md) D2(같은 id는 version이 높은 쪽) · D8(원격 기준 · 상대 경로 거부 규칙 — 아래 D2가 `audio/`를 더한다) · D10(짝 텍스트는 계속 필수),
  [ADR-0045](0045-android-host-audio-assets.md)(Android 번들 자산 결선 — 재검토 조건 「오디오 자산이 원격에서 오게 되면」이 발동했다), [ADR-0016](0016-assistive-technology-semantics.md)(낭독 단위 — 바꾸지 않는다).
  각 ADR에는 적용 기록이 붙었다.

**왜 새 번호인가** — ADR-0017 D3은 이미 실체화돼 있다(번들 해석 · 메서드 · 두 호스트 구현). 그 위에서 출처 · id 검사의 자리 · 네이티브 판정 · 재생 시점 · 실패 처리 ·
내장 version이 **한꺼번에** 정해지므로 새 번호로 묶는다(ADR-0010 D10 둘째 줄).

근거 표시: **[코드]** 저장소 코드 · **[데이터]** `apps/mobile/content/episodes/*.json` 실측 · **[실측]** 버킷 응답 · 빌드 크기 · **[실기]** iOS 시뮬레이터 관찰 · **[추론]** 관찰 없이 이어 붙인 것.
계약의 정본은 저장소 밖 작업 폴더의 spec(개정 A 포함)이고 이 문서는 그중 **결정**만 옮긴다. 시그니처는 코드가 진다.

## 맥락

1. **재생 모듈은 있었고 번들 id만 풀었다** [코드]. iOS `AudioPlaybackModule.resolve(_:)`는 번들 `audio/<source>.m4a` 조회 하나였고, Android `AudioAssetPath`는 조각 하나짜리 id만 받는다(`/` 거부).
   재생 수단은 이미 원격을 받을 수 있었다 — iOS는 `AVPlayer`, Android `MediaPlayer`는 이미 `prepareAsync`로 비동기 준비한다.
2. **콘텐츠는 이미 id로 말한다** [데이터]. 대화 `dialogue[].audio_url`은 필수 키였고(모두 빈 값), 제작 목록의 id 규약은 `<episode_id>/<kind>-<n>`이다
   ([콘텐츠 계약](../specs/episode-content-json-contract.md) 부록 C). 컷에는 오디오 키가 없었다.
3. **버킷 기준 상대 경로를 절대 URL로 푸는 자리가 이미 있다** [코드]. `EpisodeContent.imageUrlOf`(내부 `resolveContentUrlSafe`)가 빈 값 · 선두 `/` · `..` · `://`를 거부하고,
   Supabase 설정이 없으면 `null`이다. 이름은 그림용이지만 그림 전용 로직이 없다.
4. **앱은 음성의 길이를 모른다** [코드]. 재생 모듈에 길이 · 상태 조회가 없다(ADR-0017 D3의 제외).
5. **버킷에 음성 14개가 올라갔다** [실측]. 공개 URL 14개가 전부 200이고 정리본과 바이트가 같다. `content-type: audio/x-m4a`, 바이트 범위 요청에 206을 준다 —
   `AVPlayer` 원격 재생의 전제가 선다.
6. **iOS 번들 해석에 기존 결함이 있었다** [실기 — HostTests]. 빈 이름을 `Bundle.url(forResource:)`가 폴더의 **아무 파일**로 풀었다(`ordering-1`이 나왔다).
   원격 분기를 시험하는 새 테스트가 처음 드러냈다.

## 결정

### D1. 출처는 공개 버킷 `content`의 `audio/<id>.m4a`다 — 앱 번들에 묶지 않는다

- 파일은 `${PUBLIC_SUPABASE_URL}/storage/v1/object/public/content/audio/<id>.m4a`에 있다. 형식은 부록 C 그대로(m4a AAC · 모노 · 44.1 kHz).
  **매니페스트에 등록하지 않는 정적 파일이다** — 에피소드 JSON이 id를 들고, 파일은 그 id로 찾는다. 해시 · 바이트 검사가 없다.
- **받아 두지 않는다.** JS가 받지 않고 네이티브 재생기가 URL을 직접 스트리밍한다. 캐시 · 프리로드가 없다(ADR-0017 D3의 「재생목록 · 프리로드 · 캐시」 제외 그대로).
  그래서 오프라인에서는 소리가 나지 않는다(D7).
- 버린 대안: **앱 번들에 묶기**(튜토리얼 자산처럼 `apps/ios/Host/audio/`에) — 에피소드는 이후 서버로 오는데(ADR-0056) 음성만 앱 출시에 묶이고, 두 호스트의 번들 자산 검사
  (ADR-0045 D1 · D2)가 에피소드마다 바뀐다. 음성 한 줄을 고치는 데 출시가 필요해진다.
  **네이티브가 id를 받아 「번들에 없으면 원격」**(부록 C의 원래 문장) — 네이티브 둘이 버킷 주소와 앱 설정을 알아야 하고, 주소를 정하는 자리가 셋으로 흩어진다.

### D2. id → 주소는 JS 순수 함수 한 자리이고, 기준은 기존 콘텐츠 해석기다

- `lib/content-audio.ts`가 진다(import 없음 — 두 스레드에 실려도 된다). id 규약은
  `^[a-z0-9]+(?:-[a-z0-9]+)*(?:\/[a-z0-9]+(?:-[a-z0-9]+)*)*$` — 소문자 · 숫자 · 하이픈 조각을 `/`로 잇는다.
  빈 값 · 선두/끝/연속 `/` · `.`(따라서 `..`와 확장자) · `:`(스킴) · 대문자 · 공백 · `\`는 거부한다. URL 인코딩이 필요 없는 글자만 남는다.
- 규약에 맞으면 `audio/<id>.m4a`를 만들어 **기존 `EpisodeContent.imageUrlOf`에 넘긴다** — 이제 그 함수는 「버킷 기준 상대 경로(컷 그림 · 음성) → 절대 URL」이다.
  해석기를 하나 더 두지 않고 `EpisodeContent` 모양도 바꾸지 않았다.
- **재생하지 않는 경우**: id가 없거나 빈 값 · 규약 밖 · 그 줄의 원문 `ko`에 `{…}` 자리표시자가 있음(`{이름}` 줄은 녹음하지 않는다 — 부록 C) · Supabase 설정 없음.
  앞의 셋에서는 해석기를 부르지도 않는다.
- **호스트 제한은 이 한 자리에 있다.** 주소를 만드는 곳이 여기뿐이고 기준이 앱 설정의 Supabase URL이다. 네이티브는 그 설정을 모른다(D3).
- 버린 대안: `EpisodeContent`에 `audioSourceOf`를 더하기(같은 해석기가 한 겹 늘고 픽스처가 바뀐다) · `imageUrlOf` → `contentUrlOf` 개명(20여 파일 — 별도 작업, 「대가」 6).

### D3. 재생 모듈은 `https` 스킴에 호스트가 있는 절대 URL만 원격으로 연다 — ADR-0017 D3 개정, 메서드 표면 불변

- **판정 규칙(두 플랫폼 같음)**: `source`가 URL로 파싱되고 스킴이 `https`(대소문자 무시)이며 호스트가 비어 있지 않으면 그 URL을 재생한다.
  파싱 실패 · 다른 스킴(`http` · `file` · `content` · `data` …) · 호스트 없음은 **원격이 아니다** — 지금의 번들 해석으로 가서 거기서 걸러지고 `done`이 한 번 불린다.
- **`source`는 이제 둘 중 하나다** — 번들 id(튜토리얼 판정용 자산, 확장자 · 경로 없음) 또는 https URL(에피소드 음성). ADR-0017 D3이 비워 둔 자리의 답이다.
- **네이티브는 스킴만 본다.** 호스트 목록을 네이티브에 두면 JS 빌드 변수인 Supabase 설정이 두 벌이 된다. 네이티브의 몫은 「평문 · 로컬 파일 · 임의 스킴을 원격으로 열지 않는다」까지다.
- 구현: iOS `AudioPlaybackModule.resolve(_:)`의 첫 분기(`remoteURL`) — 나머지(`AVPlayer` · 관찰자 · `done` 한 번)는 그대로이고 원격 로드 실패도 기존 `.failed` 관찰이 `done` 한 번으로 모은다.
  테스트를 위해 `resolve`가 `private`에서 `internal`이 됐다. Android는 순수 클래스 `AudioRemoteSource.forSource`(JVM unit)가 판정하고, `AudioPlaybackController.play`가
  원격이면 `setDataSource(url)`, 아니면 지금의 자산 경로로 간다 — 리스너 · `prepareAsync` · 오류의 `done` 한 번은 같은 길이다.
- **바뀌지 않는 것**: 메서드 넷과 시그니처 · `done`은 끝/실패에 한 번 · 새 `play`가 이전 것을 대체 · 세션 카테고리 · 오디오 포커스 · 전경 전용 · 프리로드/캐시 없음.
  `lib/audio.ts`의 코드는 한 줄도 바뀌지 않았다.

### D4. iOS 번들 해석은 빈 이름 · `/` · `..`을 거부한다 — 기존 결함의 수정

번들 id는 경로 조각 하나다. iOS `resolve`가 번들을 찾기 전에 빈 값 · `/`가 든 값 · `..`이 든 값을 `nil`로 돌린다 — Android `AudioAssetPath`와 같은 경계다.
결정이 바뀐 것이 아니라 **실체화가 결정을 만족하지 않던 것**을 고쳤다(맥락 6). 튜토리얼 자산 id는 전부 조각 하나라 동작이 같다.

### D5. 컷 — 컷이 서면 그 컷의 소리가 한 번 난다. 다음 컷 · 나가기 · 화면을 떠날 때 멈춘다

- 콘텐츠의 컷(`pre_cuts[]` · `post_cuts[]`)에 **선택** 키 `audio_url`이 생겼다(대화와 같은 이름, 값은 id). 없음 · 빈 문자열은 소리 없음이다. 모르는 키를 버리는 옛 앱은 그대로 디코드한다.
- 카탈로그 표지 컷과 통과 뒤 컷 화면에서 **컷이 서는 순간** 그 컷의 소리를 한 번 재생한다. 내레이션 · 대사 · 독백 모두 같다. 지문(`aside`)은 소리와 무관하다.
- **멈추는 때**: 다음 컷으로 넘어갈 때 · 나가기 버튼 · 시스템 뒤로 · 마지막 컷 버튼 뒤 배너로 넘어감 · 화면을 떠남. 나가기 · 시스템 뒤로는 **즉시** 멈춘다.
  **`Next`는 탭 수가 설정에 따라 갈린다** — 타자기가 도는 동안의 첫 탭은 글을 끝까지 보일 뿐 컷이 그대로라 **소리도 계속 난다.** 두 번째 탭이 컷을 넘기며 멈춘다.
  동작 줄이기에서는 타자기가 즉시 완성이라 첫 탭이 컷을 넘기고 바로 멈춘다.
  같은 컷 안의 재렌더(타자기 완성 탭 · 번역 토글)는 소리를 건드리지 않는다.
- **소리가 끝나도 넘기지 않는다** — 타자기 · 버튼 · 토글 · 자동 넘김 없음은 그대로다. 표지 화면 · 건너뛰기 모달 · 배너에는 소리가 없다.
- 같은 문장은 한 번만 녹음한다(부록 C) — 컷 대사가 대화 줄과 같으면 그 줄의 id를 다시 쓴다(u01 pre-6 · u02 pre-5 · u03 pre-4 → 각 `d-01`).

### D6. 최종 테스트 — 상대 줄은 턴이 서면, 내 줄은 맞힌 직후. 오답에는 아무것도 바꾸지 않는다. 다시 듣기는 없다

- 턴이 서면 **상대 줄**이 난다. **정답 판정 직후** 내 줄(플레이어 줄)이 상대 줄을 끊고 난다 — 정답 효과음과 거의 동시에 시작해 **겹친다**(수용 — 지연 타이머를 두지 않는다).
  **오답이면 아무것도 바꾸지 않는다** — 상대 줄이 아직 나고 있으면 그대로 둔다. 다음 턴 · 나가기 · `See results`(화면을 떠남)에서 멈춘다.
- **다시 듣기 · 재생 · 일시정지 조작과 재생 중 표시를 두지 않는다 — 사용자 결정.** 소리는 화면에 늘 서 있는 대사(한국어 줄 + 번역 줄)의 보조 채널이라 못 들어도 잃는 정보가 없다.
- **대화 줄 찾기**: 문항의 `roleplay.line_id`가 `D<n>`(n ≥ 1)이고, `dialogue`에서 `seq = n` 줄이 `player` · `seq = n-1` 줄이 `counterpart`일 때만 두 줄의 소리를 쓴다.
  하나라도 어긋나면 그 턴 전체가 무음이다. 세 에피소드의 RP 13턴은 모두 이 모양이다 [데이터].
- 문항의 `stimulus.audio_url`은 읽지 않는다 — 녹음의 정본은 대화 줄이다. 학습 문항 오디오는 이 결정 밖이다.
- 결과 [데이터]: u01은 세 턴 모두 상대 줄이 나고, 내 줄은 1 · 2턴만 난다(3턴의 플레이어 줄 `d-06`은 녹음이 없다). u02 · u03은 첫 턴의 상대 줄(`d-01`)만 난다.

### D7. 실패는 무음이다 — 흐름은 소리의 결과를 읽지 않는다

- 재생의 시작 결과와 완료 콜백을 화면 · 흐름 · 결선 어디도 읽지 않는다. 오프라인 · 404 · 형식 오류 · 모듈 없음(Explorer · 테스트) 모두 화면과 진행이 소리 없는 때와 같다.
- 오류 표시 · 토스트 · 빈 상태 · 낭독을 만들지 않는다.
- 재생을 지는 것은 훅 하나(`lib/use-audio-cue.ts`)다 — 「지금 나야 할 소리」의 key가 바뀔 때만 이전 것을 멈추고 새 것을 한 번 재생하고, 화면이 사라지면 멈춘다.
  화면이 그 key를 순수 함수로 계산한다(컷 번호 · 턴 번호 + 판정). 소리 상태를 들고 있는 곳이 없다 — ADR-0017 D3의 「재생 상태 조회 없음」 그대로다.

### D8. 3초를 넘는 자동 재생 음성 — WCAG 1.4.2를 엄격 해석으로는 충족하지 못하는 것을 알고 받아들인다

u01 음성 6개는 모두 3초 미만이다(1.09 ~ 2.30 s). u02 · u03의 `d-01`(2.41 s · 2.58 s)도 미만이라 **최종 테스트의 자동 재생은 전부 3초 미만이다.**
3초를 넘는 것은 **컷 음성 여섯**이다 [실측 — ffprobe]:

| 음성 | 길이 | 자리 |
|---|---|---|
| `u02-checkin/post-1` | 6.76 s | 통과 뒤 컷 1 |
| `u03-mina/pre-2` | 6.50 s | 표지 컷 2 |
| `u03-mina/post-3` | 4.69 s | 통과 뒤 컷 3 |
| `u03-mina/post-1` | 4.50 s | 통과 뒤 컷 1 |
| `u02-checkin/pre-3` | 3.88 s | 표지 컷 3 |
| `u02-checkin/pre-1` | 3.51 s | 표지 컷 1 |

- WCAG 1.4.2(Audio Control)는 3초 넘게 자동 재생되는 소리를 **멈추는 수단**을 요구한다. 이 앱에서 소리를 멈추는 것은 **다음 컷으로 넘어가기 · 나가기 · 시스템 뒤로**뿐이다(D5) —
  셋 다 「내용을 진행하거나 떠나는」 부수효과가 붙은 조작이고, 타자기 도중의 `Next`는 첫 탭에 소리를 멈추지 않는다. **화면을 떠나지 않고 소리만 멈추는 수단이 없으므로
  엄격 해석으로는 1.4.2 미충족이다.** 「충족」이라고 적지 않는다.
- **알고 받아들인다.** 재생 · 멈춤 · 다시 듣기 조작을 두지 않는 것은 사용자 결정이다(D6, 2026-10-14). 대가는 VoiceOver 사용자가 진다 — 기본 세션 카테고리라 녹음과
  VoiceOver 낭독(같은 한국어 줄 + 번역 줄)이 섞여 난다. 정보 손실은 없다(대사는 늘 화면 글자로 서고 낭독된다).
- 앱은 음성의 길이를 모른다(맥락 4). 길이 상한(3초 — 효과음 포함 권장)은 콘텐츠 쪽의 몫이다([콘텐츠 계약](../specs/episode-content-json-contract.md) 부록 C).
- 재검토 조건 4 — 컷에 재생/멈춤 조작을 두거나, 위 여섯을 3초 미만으로 다시 편집하면 이 수용을 걷는다.

### D9. 내장 에피소드 셋의 version을 `2026-10-14.1`로 올린다

- 내장 JSON 셋에 id를 채웠다 — u01 대화 1 ~ 5 · 컷 pre-3 · pre-6, u02 대화 1 · 컷 pre-1 · pre-3 · pre-5 · post-1, u03 대화 1 · 컷 pre-2 · pre-4 · post-1 · post-3.
  내장 매니페스트의 `version` · `sha256` · `bytes`를 다시 적었다.
- version을 올리지 않아도 새 빌드는 내장본을 쓴다(같으면 내장 — ADR-0056 D2). 그래도 올리는 이유: 버킷에 같은 바이트를 같은 version으로 올리면 **옛 빌드도** 새 본문을 받는다 —
  옛 디코더는 컷의 모르는 키를 버리고 대화 `audio_url`은 읽기만 하므로 무해하다(재생은 하지 않는다). 「내용이 바뀌면 version이 바뀐다」는 매니페스트 규약과도 맞는다.
- 버킷의 에피소드 · 매니페스트 갱신은 사용자 손 작업이다(음성 → 에피소드 → 매니페스트 순서 — 매니페스트를 마지막에 올려야 그 전에 받은 기기가 옛 version을 유지한다).
- ⟨2026-10-16⟩ **`2026-10-14.1`은 그때의 내장 version이다** — 내장 셋이 새 형식으로 바뀌어 `2026-10-15.1`이 됐고, 위 id 배치는 새 본문에 같은 자리로 다시 붙었다(끝의 「적용 기록」).

### 측정

없다. 이벤트 · 속성 추가 0. 재생 성공/실패를 가를 신호가 모듈에 없다(`done`이 끝과 실패를 구분하지 않는다 — ADR-0017 D3).

## 버린 대안

1. **앱 번들에 묶기** — D1.
2. **네이티브가 id를 받아 「번들에 없으면 원격」** — D1.
3. **네이티브에 허용 호스트 목록** — D3. 설정이 두 벌이 된다.
4. **다시 듣기 버튼 · 재생 중 표시** — 사용자 결정으로 두지 않는다(D6). 학습 문항이 들어올 때 다시 본다.
5. **소리가 끝나면 다음 컷으로 자동 넘김** — 진행이 소리(와 네트워크)에 묶인다. 실패가 무음인데 넘김만 늦어지는 길이 생긴다.
6. **내 줄을 정답 효과음 뒤로 미루기(지연 타이머)** — 타이머가 하나 늘고 그 사이 다음 턴으로 가면 취소 규칙이 필요하다. 겹침을 수용했다(D6).

## 대가

1. **번들 +3,758 bytes**(1,913,545 → 1,917,303, +0.20 %) [실측 — 문서 단계 로컬 빌드]. 상한 1,915,000을 넘는다 — 올린 값과 근거는 `devtools/bundle-size/budget.json` note와
   [성능 보고서](../performance/reports/episode-audio-iphone-17-pro-simulator-01.md)가 진다. 음원은 번들에 넣지 않았다.
2. **오프라인 · 느린 네트워크에서는 소리가 없거나 늦다.** 컷의 첫 프레임보다 소리가 늦게 날 수 있다 — 프리로드를 하지 않는 대가다(ADR-0017 D3). 지연은 재지 않았다.
3. **정답 효과음과 내 줄이 겹친다**(D6).
4. **놓친 소리를 다시 들을 수 없다**(D6). 같은 문장은 화면에 있다.
5. **옛 빌드는 새 본문을 받지만 소리를 내지 않는다**(D9) — 의도된 무해.
6. **`EpisodeContent.imageUrlOf`의 이름이 좁다** — 그림과 음성을 함께 푼다. 개명은 별도 작업이다.
7. **네이티브는 호스트를 가리지 않는다**(D3) — JS가 다른 https 주소를 넘기면 재생한다. 지금 그 주소를 만드는 자리는 D2의 함수 하나뿐이다.
8. **WCAG 1.4.2 엄격 해석 미충족을 받아들였다**(D8) — 3초 넘는 컷 음성 여섯을 소리만 멈출 수단이 없다.
9. **iOS는 기본 세션 카테고리를 그대로 쓴다**(ADR-0017 D3의 제외 — 카테고리를 조작하지 않는다). 그래서 **무음 스위치를 켜면 음성이 나지 않는다** — 대사 글자로 그대로 진행되고
   실패 무음(D7)과 같은 결과다. 그리고 **자동 재생이 다른 앱의 오디오(음악 · 팟캐스트)를 끊는다** — 듣기 문항은 사용자가 누른 재생이었는데, 컷과 최종 테스트는 누르지 않아도 끊는다.
   VoiceOver 낭독 자체는 막히지 않는다. 사용자 보고가 생기면 ADR-0017의 세션 카테고리 재검토로 올린다.
10. **Android에서는 TalkBack 낭독마다 음성이 멈췄다 이어진다**(기존 동작 — [효과음 계약](../specs/ios-sound-effects.md) 접근성 4). 6초대 음성은 훑는 동안 문장 중간에서 조각날 수 있다. 실기로 듣지 않았다.

## 미확인 · 후속

1. **실제 청음** — 시뮬레이터에서 요청이 나가고 받아 간 것까지 봤다(최종 테스트 u01 세 턴: `d-01` → 정답 뒤 `d-02` → `d-03` → 정답 뒤 `d-04` → `d-05`, 표지 컷 3 `pre-3` · 컷 6 `d-01`).
   소리가 들리는지 · 겹침의 체감 · 끊김은 사용자가 귀로 확인해야 한다. 최종 테스트에 닿으려고 레슨 판정을 무조건 통과로 바꾼 **커밋하지 않은 빌드**를 썼다.
2. **관찰 하나** — 첫 시도에서 2턴 `d-03` 요청이 로그에 없었다. 같은 조작을 두 번 다시 했을 때는 재현되지 않았다. 원인은 모른다(로그 수집 누락인지 재생이 안 된 것인지 가르지 못했다).
3. **오프라인 무음 진행 · 나가기로 즉시 멈춤 · 배너 동안 무음 · 튜토리얼 소리 회귀 · u02 · u03 경로 · VoiceOver(덕킹 켬/끔)와의 겹침 · 무음 스위치** — 기기에서 보지 않았다.
4. **Android** — JVM unit(`AudioRemoteSourceTest`)은 통과했고, 계측 둘(닿지 않는 https의 `done` 한 번 · 준비 중 `stop`의 `done` 0회)과 에뮬레이터 청음은 실행하지 않았다
   ([Android 오디오 재생 검증](../e2e/android-audio-playback.md)).
5. **콘텐츠 쪽 길이 검사**(D8) — 버킷 업로드 준비 단계에서 음성 길이를 재 3초 이상이면 막고, 예외는 별도 허용 목록으로만 통과시키기를 권한다. 앱의 일이 아니다.
6. **동작 줄이기 쪽 회귀 고정이 없다** — 「타자기 도중 `Next` 첫 탭은 소리를 멈추지 않는다」는 ui 테스트(UCA2)가 고정하지만, 「동작 줄이기에서는 첫 탭이 멈춘다」(D5)는 고정되지 않았다. 그쪽 동작이 바뀌면 이 문서가 조용히 틀린다.

## 재검토 조건

1. **학습 문항(듣기 · 받아쓰기)에 오디오를 연결할 때**(보류 표 「학습 문항 오디오의 연결」) — 같은 D2 · D3 위에 서고, 다시 듣기 조작(D6)과 문항 `stimulus.audio_url`을 다시 본다.
   ⟨2026-10-22⟩ **발동했고 처리했다** — [ADR-0080](0080-item-audio-and-slow-playback.md). 끝의 「적용 기록」 ⟨2026-10-22⟩.
2. **음성을 다른 호스트(CDN 등)에서 내게 되면** — D2의 기준 주소와 D3의 「네이티브는 스킴만」을 다시 본다.
3. **첫 소리 지연이나 오프라인 무음이 문제로 보고되면** — D1의 「받아 두지 않는다」와 ADR-0017 D3의 프리로드 제외를 함께 연다.
4. **D8의 1.4.2 미충족 수용을 걷는 때** — 컷에 재생/멈춤 조작을 들이거나(듣기 문항의 `듣기`/`멈춤` 선례), 3초 넘는 컷 음성 여섯을 3초 미만으로 다시 편집해 올릴 때.
   3초 넘는 음성이 새로 늘거나 불편 · 자동 재생을 끄는 설정 요구가 보고될 때도 이 조건으로 다시 본다.
   ⟨2026-10-22⟩ **학습 문항 자동 재생이 늘어 이 조건으로 다시 봤다** — D8의 컷 수용은 그대로 두고, 문항 쪽은 [ADR-0080](0080-item-audio-and-slow-playback.md) D12가 따로 정했다(아래 적용 기록).
5. **콘텐츠가 플레이어 줄 전체를 녹음하거나 `line_id` 모양을 바꾸면** — D6의 대화 줄 찾기 규칙.

## 적용 기록

### 2026-10-16 — 새 에피소드 형식: 내장 본문이 바뀌어 음성 id 14개를 다시 붙였다

결정을 바꾸지 않는다. 형식의 결정은 [ADR-0065](0065-episode-format-additions.md)이 진다. 이 문서에 닿는 자리만 적는다.

- **콘텐츠 원본에는 음성 id가 없다** — 새 형식 원본(버킷에 있던 것도)은 이 문서 이전의 본문이라 컷에 `audio_url`이 없고 대화 `audio_url`이 빈 값이다. 그래서 내장본을 만들 때
  **문장 대조로 다시 붙였다** — 컷은 옛 내장본과 `ko`(대사 또는 내레이션) · 화자가 같은 컷에 `audio_url`을 `image_url` 바로 뒤에 더하고, 대화는 `text.ko` · `role`이 같은 줄의 값을 채웠다.
  **14 id 모두 쓰였고 사라진 문장은 0**이다. 손으로 고치지 않았다 — 같은 절차를 다시 돌리면 같은 바이트가 나온다(내장 매니페스트의 `sha256` · `bytes`가 그 값이다).
- **D9의 id 배치는 그대로다** — u01 대화 1 ~ 5 · 컷 pre-3 · pre-6, u02 대화 1 · 컷 pre-1 · pre-3 · pre-5 · post-1, u03 대화 1 · 컷 pre-2 · pre-4 · post-1 · post-3. 컷 수 · 순서가 같다.
- **u01 대화가 9줄이 됐다** — seq 7에 「감사합니다. 안녕히 가세요.」(상대)가 끼어 옛 seq 7 · 8이 8 · 9로 밀렸다. 새 줄은 녹음이 없어 빈 값이다. id가 붙은 줄(seq 1 ~ 5)은 밀리지 않아 id 이름(`d-0n`)과 seq가 계속 같다.
  로마자만 고쳐진 줄(ㅇ 받침 표기 등)도 `ko`가 같아 같은 음성을 쓴다 — 녹음은 한국어 문장이다.
- **D6의 `line_id` 규칙이 새 대화에서도 성립한다** [데이터] — 최종 테스트 13턴 모두 `D<n>` = 플레이어 줄 seq n, 상대 줄 seq n−1이다. u01의 세 턴은 seq 7보다 앞이라 끼어든 줄의 영향이 없다 —
  최종 테스트에서 나는 소리(u01 상대 `d-01` · `d-03` · `d-05`, 정답 뒤 `d-02` · `d-04`)는 **지금과 같다.** 재생 기대를 단언하는 integration 테스트는 진행 씨앗만 새 단계 id로 바꿨고 재생 배열은 그대로 통과한다.
- **내장 version `2026-10-14.1` → `2026-10-15.1`**(D9). 버킷의 에피소드는 **이 내장본과 같은 바이트**로 다시 올린다 — 음성 id 없는 원본을 올리면 원격본이 이길 때 컷 · 최종 테스트 소리가 사라진다(ADR-0065 D12 · Q7).
- ⟨2026-10-16 오후 갱신⟩ 같은 날 11:45 버킷 판으로 내장 셋을 한 번 더 바꿨다 — version `2026-10-16.1`. 바뀐 것: 제목이 짧아짐(`물 사기` · `체크인` · `미나 만나기`) · 최상위 `title_en`(앱은 버림) · 그림 경로가 `content/images/…` 꼴(앱이 선두 `content/`를 뗀다) · 모든 소리 자리에 빈 `audio_url` · u03 통과 뒤 컷 1 문장(`백반집` → `식당`). 음성 id는 같은 문장 자리에 다시 붙여 **13개**다 — u03 통과 뒤 컷 1(`u03-mina/post-1`)은 문장이 바뀌어 녹음과 맞는지 확인 전이라 비웠다.
- ⚠ 이 회차의 기기 확인에서 **최종 테스트 소리는 보지 않았다**([새 에피소드 형식 e2e](../e2e/episode-format.md)). 음성의 기기 확인은 여전히 [에피소드 음성 e2e](../e2e/episode-audio.md)의 요청 확인 회차뿐이다.

### 2026-10-19 — 음성 길이 맞춤 타이핑: 컷 타자기가 음성 정보 파일의 길이에 맞춰 쓴다

결정을 바꾸지 않는다. 타이핑 속도의 결정은 [ADR-0074](0074-voice-synced-typing.md)가 진다. 이 문서에 닿는 자리만 적는다.

- **D5의 컷에서 소리와 함께 서는 타자기의 속도가 소리를 따른다** — 버킷의 음성 정보 파일(`audio/manifest.json`)에 그 컷 음성 id의 길이가 있으면 글자 간격 = 맞출 길이 ÷ 글자 수([35, 300] ms),
  항목이 없거나 정보 파일이 없으면 지금처럼 35ms다. 정보 파일은 2026-10-19 사용자가 버킷에 올렸다.
- **D5의 탭 · 정지 · 「소리가 끝나도 넘기지 않는다」는 그대로다** — 쓰는 중 첫 `Next`는 글을 마저 보이고 소리는 계속 나며, 동작 줄이기는 즉시 완성이다. 소리가 나고 멈추는 때는 바뀌지 않았다.
- D1(스트리밍 · 받아 둔 파일 먼저) · D3(재생 모듈 메서드)는 그대로다 — 길이는 재생 모듈이 아니라 미리 잰 콘텐츠 데이터에서 온다.

### 2026-10-22 — 학습 문항 음성 · 「천천히」: 재검토 조건 1이 발동했다

결정은 [ADR-0080](0080-item-audio-and-slow-playback.md)이 진다. 이 문서의 결정 문장은 바뀌지 않는다 — 닿는 자리만 적는다.

- **재검토 조건 1** — 학습 문항의 `stimulus.audio_url`을 같은 D2(주소 규약 · 자리표시자) · D3(네이티브는 스킴만) · D7(실패는 무음) 위에서 재생한다. 머리 「다루지 않는 것」의 학습 문항 오디오와 맥락 끝의 「문항의 `stimulus.audio_url`은 읽지 않는다」는 그때의 상태다.
- **D6(다시 듣기 조작을 두지 않는다)은 컷 · 대화 · 최종 테스트에서 그대로다** — 다시 듣기 · 「천천히」는 학습 듣기 문항에만 선다. 최종 테스트의 플레이어 줄을 「듣기 버튼으로만」 내는 예외도 두지 않았다(사용자 결정 2026-10-21 「원래 하던대로」).
- **D5(컷의 재생 · 정지 시점)와 재생 속도는 그대로 1.0이다** — 컷 · 최종은 `play(source, done)` 인자 둘로 간다. 버린 대안 4(「다시 듣기 버튼 · 재생 중 표시 — 학습 문항이 들어올 때 다시 본다」)는 학습 문항에서 다시 봤고 그쪽에만 섰다.
- **재검토 조건 4(1.4.2)** — 레슨 문항의 자동 재생이 늘었다. 문항이 서는 자동 재생은 화면 안에서 멈출 수 있게 했고(듣기 3열 일시정지 · 간이 줄 재생 중 `Stop`), 판정 뒤 한 번 재생(1.0)은 멈춤 조작 없이 엄격 해석 미충족을 알고 받아들였다(ADR-0080 D12). **D8의 컷 음성 여섯 수용은 그대로다.**
- 측정: 이 문서의 「측정 — 없다」는 컷 · 최종 몫으로 그대로다. 학습 듣기 문항은 `episode_listen_item_answered` 하나가 생겼다(ADR-0080 「측정」).
