## 결정

### D1. 원천 — 대화 출처의 안 읽음 오름(새 서버 호출 없음)
- 출처(`ChatSource`)는 **닫힌 방**에 인물의 답(한 턴 — 서버 SSE의 첫 말풍선) · 끊긴 답 채우기 · 해금 첫 인사가 설 때 안 읽음을 **하나** 올린다.
  열린 방 · 내 글 · 안내 줄(엽전 부족 · 오류 · 고지) · 기록 미리 읽기는 올리지 않는다.
- 그래서 「답 하나에 토스트 하나」가 출처에서 이미 성립한다. 스트리밍 조각 · 말 여러 줄 · 사진+말은 같은 턴이라 카드 하나이고, 카드의
  미리보기는 그 방의 **마지막 미리보기 줄**을 매번 다시 읽어 조각마다 자란다.
- 처음 읽은 스냅숏(앱 시작 · 로그인 직후 기록)은 기준일 뿐 도착으로 세지 않는다. 판정은 `replyArrivals(prev, next)`(`app/reply-toast.ts`).
- `kind`: 오르기 직전 미리보기 줄이 **내 글**이면 `reply`, 아니면 `proactive`(첫 인사 · 끊긴 답 채우기 중 인물이 먼저 · 스토리 반응).
- **주기 확인(폴링)은 두지 않는다** — 사용자 요청의 중심(보기에서 보낸 답장)은 SSE로 이미 출처에 온다. 서버 호출 비용 · 배터리를 늘리지 않는다.

### D2. 어디서 — 지금 화면으로 정한다(`replyToastPlaceOf`)
| 화면 | 처리 |
| --- | --- |
| 채팅 목록(`messenger-list`) | 버림(목록이 안 읽음 숫자로 보임). 단 목록 위에 친구 스토리 보기가 떠 있으면 띄움(내 스토리 보기 · 만들기 위에서는 목록과 같이 버림) |
| 그 인물의 방 | 버림(출처가 안 읽음을 올리지 않음). **다른 인물의 방이면 띄움** |
| 레슨 · 막간 이야기 · 표지 · 최종 테스트 · 에필로그 · 롤플레이 말하기 | **미룸** — 레슨 밖 화면으로 돌아오면 최신 하나 + 「+N」으로 한 번 |
| 레슨 끝 화면 · 다른 탭 · 설정 · 상점 시트 위 · 그 밖 | 띄움 |
| 진입 흐름(스플래시 ~ 여정 입장) · 메신저를 못 여는 계정(손님 · 로그인 전) | 버림 |

- 미룬 사이 목록으로 가면 미룬 것을 **다** 버리고, 어떤 인물의 방으로 가면 **그 인물 것만** 버리고 나머지를 띄운다.
- 떠 있는 카드는 목록 · 그 방 · 레슨으로 들어가면 사라진다.
- **앱이 뒤에 있을 때 온 것은 띄우지 않는다**: 호스트가 배경으로 가는 신호를 보내지 않으므로, 앞으로 돌아오는 신호
  (`contentSyncOpportunity`) 뒤 **3초** 안의 도착은 뒤에 있는 동안 온 것으로 보고 버린다(그동안은 시스템 푸시가 이미 알렸다).

### D3. 몰릴 때 · 상한
- 떠 있는 카드와 **같은 인물**이면 내용만 바꿔 끼우고(4초를 새로 셈, 「+N」 그대로), **다른 인물**이면 최신으로 바꾸고 「+N」을 하나 올린다.
- **1분에 새 카드 3번**까지. 넘으면 띄우지 않고 목록의 안 읽음 숫자로만 남는다. 같은 인물의 바꿔 끼움은 세지 않는다.
- 판정은 리듀서 `replyToastReducer`(순수).

### D4. 모양 · 움직임 · 접근성
- 화면 위 안전 영역 아래 8pt, 좌우 12pt. 짙은 면(gray-900) · 얼굴 32 · 이름(흰 15/700) · 「+N」(브랜드 알약) · 미리보기 한 줄(gray-400
  13, 말줄임). 말은 한국어 본문(목록 미리보기와 같음), 사진 · 음성은 「Sent a photo」 · 「Sent a voice message」(알약 문구 재사용).
- 위에서 내려오고(d6 · enter) 4초 뒤 올라간다(d4 · exit). **위로 24pt 이상 밀면** 닫힌다. 움직임 줄이기면 페이드(d4). 새 토큰 없음.
- 카드 전체 = 그 방으로 가는 단추(낭독 「New message from {이름}: {미리보기}. {N} more」), 오른쪽 × = 닫기만(44 × 44, 「Dismiss」).
  뜰 때 · 바꿔 낄 때 한 번 낭독 알림(`announce`). 카드 밖은 비어 아래 화면 입력을 가로채지 않는다.
- 소리 없음. 진동 설정이 켜져 있으면 새 카드에 가벼운 진동(`key`) 한 번. 레슨 중에는 미루므로 소리 · 진동이 날 일이 없다.
- 문구 여덟 언어(`messengerChat.replyToast` — `dismiss` · `more` · `spoken`).

### D5. 누르면
- 선톡 푸시를 누른 것과 같은 이동(`companionPushActions`) — 메신저 탭을 루트로 접고 그 방을 쌓는다. 열 수 없는 방이면 목록 + 안내.
- 앱 전역 시트(상점)가 떠 있으면 닫는다. 화면 안 시트 · 키보드는 화면이 바뀌며 함께 내려간다.

### D6. 스토리 보기
- 토스트는 보기의 막대 · 머리 위를 가리므로 **떠 있는 동안 스토리 진행만 멈추고**(`StoryViewer`가 토스트 상태를 스스로 읽음) 사라지면 이어 간다. `covered`와
  달리 키보드 · 쓰던 답장 · 낭독은 건드리지 않는다.
- 보기 ↔ 토스트는 모듈 하나(`reply-toast-presence.ts`)로 서로를 안다 — 보기가 마운트되면 「열림」을 알리고 토스트 상태를 구독한다 — 화면 props를 늘리지 않는다.

### D7. 이벤트(PostHog만, Airbridge 매핑 없음)
- `chat_reply_toast_shown { characterId, kind: reply | proactive, more, deferred: true | false, screen }` — 새 카드가 섬(같은 인물
  바꿔 끼움은 내지 않음). `screen` = 그때 화면 이름.
- `chat_reply_toast_opened { characterId, kind }` — 카드를 눌러 방으로 감.
- 공통 `surface: chat` · `daysSinceFirstOpen`. 메시지 본문은 싣지 않는다. 이름 126 → 128(AN1), Airbridge 표 88 → 90 · 이름 96 → 98(AB3).

## 못 지키는 것 · 한계
- **선톡 · 스토리 반응이 앱이 앞에 있을 때 푸시로만 오는 경우**: 출처가 그 메시지를 모른다(서버가 앱에 따로 알리지 않음) → 앱 토스트는
  서지 않고, 지금처럼 **시스템 배너**가 뜬다(iOS `willPresent`가 `.banner`, Android `postForegroundNotification`). 같은 메시지가
  토스트 · 배너 둘 다 뜨는 일은 생기지 않는다(토스트의 원천은 SSE · 기록 채우기뿐). 선톡도 앱 토스트로 받으려면 호스트가 앞에서 받은 푸시를
  JS로 넘기고(그 종류만 배너를 끔) 출처가 그 방 기록을 다시 읽는 변경이 필요하다 — 이번 범위 밖.
- **스크린리더가 켜져 있으면 8초**: 호스트가 스크린리더 상태를 넘기지 않아 늘 4초다. 호스트 globalProps 키가 생기면 더한다.
- **숨긴 · 차단한 인물**: 앱에 그런 기능이 아직 없다(잠긴 방은 띄우지 않음).
- 앞으로 돌아온 3초 안에 새로 온 진짜 답도 함께 버려진다(드묾 — 목록의 안 읽음 숫자로 남는다).

## 버린 대안
- **앱이 앞에 있을 때만 30초마다 목록 다시 읽기** — 선톡까지 잡지만 서버 호출이 사용자 × 2번/분 늘고, 원천(SSE)이 이미 있는 중심 경우에는 필요
  없다.
- **레슨 중에도 띄우되 조용히** — 시안 4. 사용자가 「미룸」으로 정했다(문제 풀이를 가리지 않게).
- **카드를 쌓아 여러 장** — 화면 위를 오래 덮는다. 최신 하나 + 「+N」.
